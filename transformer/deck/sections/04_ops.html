행렬곱과 그 역전파

모든 층의 뼈대 — 세 겹 루프와 두 개의 전치

행렬곱 — 모양부터 맞춥니다

이 덱은 입력을 행 벡터로 둡니다(SPEC §2). 토큰 n 개의 폭 m 표현은 X ∈ ℝn×m 이고, 선형층은 오른쪽에 가중치를 곱합니다.

정의 — 행렬곱
Y = XW,   Yij = m∑k=1XikWkj
X 가 n×m, W 가 m×p 이면 Y 는 n×p 입니다. 안쪽 두 수가 같아야 곱할 수 있습니다.
  • 행 하나가 토큰 하나이므로, 층을 지나도 "행 = 토큰" 이 유지됩니다.
  • 저장은 행 우선입니다. (r, c) 칸은 1차원 리스트의 r·열수 + c 번째입니다.
  • 앞에 배치 축이 더 붙어도(B×n×m) 마지막 두 축끼리만 곱합니다.
설명용

손으로 셀 수 있는 크기에서 먼저 확인

3×2 와 2×3 을 곱하면 3×3 입니다. 첫 행은 [1, 2] 와 둘째 행렬의 두 행을 각각 1배·2배 해서 더한 것 — 행렬곱의 "행 읽기" 입니다.

행 읽기로 보면 Y 의 i 행은 W 의 행들을 X 의 i 행 값으로 가중해 더한 것입니다. 곧 볼 i-k-j 루프가 정확히 이 읽기를 따릅니다.

실행 검증

tensor.matmul — 순전파

  • ma·mb 는 배치 번호 t 가 두 입력의 몇 번째 행렬을 읽을지 적은 표입니다. 한쪽이 2차원이면 모든 t 가 같은 행렬을 가리킵니다.
  • MULTS 는 실제로 한 곱셈 수를 셉니다. 7부의 FLOPs 식이 이 계수기와 맞는지 시험합니다.
  • 가장 안쪽 줄 O[ro + j] += aik * B[rb + j] 가 행렬곱의 전부입니다.
실행 검증

루프 차례가 왜 중요한가 — i-j-k 와 i-k-j

세 겹 루프의 차례를 바꿔도 Yij 에 더해지는 항은 같습니다. 다른 것은 메모리를 읽는 순서입니다.

차례가장 안쪽 루프가 도는 것B 를 읽는 모양
i-j-k (교과서)k — A 의 행 하나와 B 의 열 하나 행 우선 배열에서 열을 읽으면 한 번에 p 칸씩 건너뜁니다
i-k-j (이 덱)j — B 의 행 하나와 출력의 행 하나 B 와 출력을 둘 다 앞에서부터 한 칸씩 읽고 씁니다

CPU 캐시는 방금 읽은 주소의 이웃을 함께 올려 둡니다. 그래서 한 칸씩 나란히 읽는 i-k-j 가 캐시를 덜 놓칩니다. 답은 같고 걸리는 시간만 다릅니다.

얼마나 빨라지나 — 기계마다 다릅니다. 이 덱은 그 숫자를 9부의 벤치 표 한 곳에만 둡니다.
설명용

C 에서 두 차례를 나란히

i-k-j 판은 출력에 더해 쌓기 때문에 먼저 memset 으로 0 을 채웁니다. i-j-k 판은 지역 변수 s 에 쌓아 한 번에 씁니다. bk 는 B 의 k 행 첫 칸을 가리키는 포인터라, 안쪽 루프가 곱셈 한 번과 덧셈 한 번만 합니다.

실행 검증

세 차례의 답은 비트까지 같다

부동소수 덧셈은 결합법칙이 성립하지 않습니다. 그래도 세 판은 한 칸 (i, j) 에 k 를 작은 것부터 더한다는 점이 같습니다. 그래서 반올림까지 똑같이 일어납니다.

모양을 일부러 어긋나게(67×45 · 45×53) 잡아 행과 열을 헷갈린 구현이 통과하지 못하게 했습니다. 블록 크기도 1 부터 넷씩 곱해 가며 봅니다.

행렬곱의 역전파 — 첨자로 유도

손실 ℓ 이 스칼라이고 윗기울기 G = ∂ℓ/∂Y (n×p) 를 받았다고 합시다.

정리 — 행렬곱의 기울기
∂ℓ/∂A = GB⊤,   ∂ℓ/∂B = A⊤G
증명

Yij = ∑k AikBkj 에서 Aik 는 i 행의 모든 j 칸에 Bkj 배로 들어갑니다. 연쇄법칙으로 모으면 ∂ℓ/∂Aik = ∑j GijBkj = (GB⊤)ik. 같은 방법으로 ∂ℓ/∂Bkj = ∑i AikGij = (A⊤G)kj.

모양으로 검산합니다: n×p 곱하기 p×m 은 n×m — A 의 모양입니다.

설명용

tensor.matmul — 역전파

  • s 는 ∑j GijBkj — 앞 장의 첫 식을 한 칸씩 계산한 것입니다.
  • gb[rb + j] += aik * g[ro + j] 는 둘째 식입니다. 전치 행렬을 따로 만들지 않습니다.
  • 모두 += 입니다. 같은 텐서가 그래프의 두 곳에 쓰이면 두 몫이 더해져야 하기 때문입니다(3부).
  • 입력이 기울기를 원하지 않으면(None) 그 쪽 루프를 건너뜁니다.
실행 검증

배치 행렬곱 — 퍼진 축의 기울기는 더한다

(2, 3, 4) 와 (4, 5) 를 곱하면 뒤의 행렬 하나를 배치 두 개가 함께 씁니다. 그러면 그 행렬의 기울기는 두 배치에서 온 몫의 합이어야 합니다.

순전파 코드에서 mb[t] 가 모든 t 에 대해 같은 자리를 가리키므로, 역전파의 gb[...] += 가 따로 손대지 않아도 배치를 따라 더해 줍니다. 브로드캐스팅의 역전파가 "늘어난 축으로 더하기" 인 까닭은 3부에서 보았습니다.

실행 검증

곱셈 수로 세는 비용

행렬곱 한 번은 곱셈을 정확히 n·m·p 번(배치가 있으면 그 곱) 합니다. 역전파는 두 입력의 기울기를 각각 같은 수만큼 계산하므로 순전파의 두 배입니다.

왜 세는가 — 모델 크기에서 학습 비용을 어림하는 "토큰당 약 6N" 규칙은 순전파 2N + 역전파 4N 에서 나옵니다. 역전파가 순전파의 두 배라는 비율이 바로 위에서 센 "기울기 둘" 입니다. 7부가 이 계수기로 식을 확인합니다.

안정한 소프트맥스

로짓을 확률로 — 넘치지 않게, 야코비안은 만들지 않고

소프트맥스 — 정의와 성질

정의 — 소프트맥스
pi = ezi∑j ezj
  • 모든 pi 가 양수이고 합이 1 — 확률 분포입니다.
  • 순서를 지킵니다. 로짓이 큰 칸이 확률도 큽니다.
  • 모든 로짓에 같은 수를 더해도 결과가 같습니다. 안정한 계산이 이 성질 하나에 기댑니다.
  • 행마다 따로 계산합니다. 텐서의 마지막 축이 한 행입니다.

소프트맥스와 로그합지수의 수학은 2부에서 준비했습니다. 여기서는 코드와 기울기입니다.

설명용

그냥 exp 하면 넘친다

세 행의 로짓은 간격이 같으므로 확률도 같아야 합니다. 위 표의 셋째 행에서 "그냥 exp" 는 double 의 범위를 넘어 계산을 못 했고, 최댓값을 뺀 판은 첫 행과 같은 답을 냈습니다.

학습 중의 로짓은 대개 크지 않지만, 한 번이라도 넘치면 inf/inf = nan 이 되어 그 뒤의 모든 가중치를 망칩니다. 그래서 늘 빼고 계산합니다.

실행 검증

최댓값을 빼도 되는 까닭

증명 — 이동 불변

아무 상수 c 에 대해

ezi − c∑j ezj − c = e−c ezie−c ∑j ezj = pi

분자·분모의 e−c 가 약분됩니다.

c = max z 로 잡으면 모든 지수가 0 이하가 되어 각 항이 (0, 1] 안에 들고, 가장 큰 항은 정확히 1 입니다. 분모는 1 이상 n 이하 — 넘칠 수가 없습니다. 아주 작은 항이 0 으로 내려앉는 것은 괜찮습니다. 그 칸의 참 확률도 그만큼 작기 때문입니다.

설명용

_softmax_row — 한 행의 소프트맥스

  • math.fsum 은 반올림 오차 없이 더하는 합입니다. 참조 구현은 가능한 한 정확해야 C 와의 차이가 C 쪽 오차로만 읽힙니다.
  • 행 전체가 −∞ 이면 확률을 정의할 수 없으므로 조용히 nan 을 내지 않고 멈춥니다.
  • off 와 n 을 받는 모양이라, 인과 마스크(6장)가 같은 함수를 행의 앞부분에만 쓸 수 있습니다.
실행 검증

소프트맥스의 야코비안

정리
∂pi∂zj = pi(δij − pj),   곧   J = diag(p) − p⊤p
증명

S = ∑k ezk 라 두면 pi = ezi/S 이고 ∂S/∂zj = ezj 입니다. 몫의 미분법으로

∂pi∂zj = δijeziS − eziezjS2 = piδij − pipj

야코비안은 대칭입니다. 대각은 pi(1 − pi) 로 양수, 나머지는 음수 — 한 칸이 오르면 다른 칸들이 내려가야 합이 1 로 남습니다.

설명용

야코비안을 만들지 않는 역전파

역전파는 야코비안 전체가 아니라 윗기울기와의 곱만 필요합니다. g = ∂ℓ/∂p 를 받으면

∂ℓ∂zj = ∑i gipi(δij − pj) = pj(gj − ⟨g, p⟩)
  • 내적 ⟨g, p⟩ 한 번과 칸마다 곱셈 한 번 — 시간 O(n), 추가 공간 O(1).
  • n×n 야코비안을 만들면 O(n2) 입니다. 어휘 크기의 로짓에서는 감당할 수 없습니다.
  • 결과를 모두 더하면 ∑pjgj − ⟨g,p⟩·∑pj = 0 입니다. 모든 로짓을 같이 올리는 방향으로는 기울기가 없다 — 이동 불변과 같은 이야기입니다.
설명용

ops.softmax — 순전파와 역전파

역전파가 쓰는 것은 순전파에서 계산해 둔 P 뿐입니다. 입력 로짓은 다시 보지 않습니다. back 안의 두 줄이 앞 장의 식 pj(gj − ⟨g, p⟩) 그대로입니다.

실행 검증

증인 — 야코비안을 차분과 견준다

입력 한 칸을 ±h 로 흔들어 출력 전체가 얼마나 움직이는지 재면 야코비안의 한 열이 나옵니다. 네 열을 모두 재서 닫힌 식과 소수 여덟째 자리까지 맞는지 봅니다.

실행 검증

로그소프트맥스 — 로그를 나중에 씌우지 않는다

log pi = zi − lse(z) 로 바로 계산합니다. 확률이 아주 작아 0 으로 내려앉으면 log 0 = −∞ 가 되지만, 이 식은 유한한 값을 줍니다.

역전파: ∂ log pi/∂zj = δij − pj 이므로 ∂ℓ/∂zj = gj − pj∑igi. test_log_softmax_matches_log_of_softmax 가 두 계산이 1e-14 안에서 같음을, test_backward 가 기울기를 차분과 견줍니다.

2장 퀴즈

Q. 소프트맥스 역전파의 결과 벡터 ∂ℓ/∂z 는 원소의 합이 늘 0 입니다. 이것이 "로짓 전체에 같은 수를 더해도 확률이 같다" 는 성질과 어떻게 이어지나요? 그리고 i-k-j 행렬곱이 i-j-k 와 비트까지 같은 답을 내는 까닭은?

A. 모든 로짓을 같은 양만큼 움직이는 방향은 벡터 (1, 1, …, 1) 입니다. 그 방향으로 가도 손실이 안 변하므로, 기울기와 그 방향의 내적 — 곧 기울기 원소의 합 — 은 0 이어야 합니다. 행렬곱은 두 차례 모두 한 칸 (i, j) 에 k 를 작은 것부터 더합니다. 덧셈의 순서가 같으니 반올림도 같이 일어나 비트까지 같습니다.
설명용

직접 해 보기 — 온도와 소프트맥스

로짓을 온도로 나눈 뒤 소프트맥스를 겁니다. 온도를 낮추면 가장 큰 칸으로 쏠리고, 높이면 고르게 퍼집니다. 온도 0 은 나눗셈 대신 argmax 로 처리합니다 — 10부 1장의 greedy 가 이것입니다.

소프트맥스
식은 py/transformerlib/ops.py 의 _softmax_row 와 같습니다(최댓값을 빼고 exp). 같은 값이 나오는지는 deck/check_deck.js 가 파이썬이 낸 값으로 검사합니다.

교차엔트로피를 한 몸으로

로그소프트맥스와 합치면 로짓 기울기가 (p − y)/N 한 줄이 된다

교차엔트로피 손실

정의 — 평균 음의 로그 가능도
ℓ = −1N N∑r=1 log pr, tr
N 은 (배치, 위치) 행의 수(파라미터 수가 아닙니다), r 행의 정답이 tr 이고, pr,· 는 그 행의 로짓에 소프트맥스를 한 것입니다.
  • 언어 모델에서 한 "행" 은 (배치, 위치) 하나입니다. SPEC §3.3 은 모든 (배치, 위치) 의 평균으로 정합니다.
  • 정답 확률이 1 이면 0, 작아질수록 끝없이 커집니다.
  • 정답을 원-핫 벡터 y 로 쓰면 한 행의 손실은 −∑j yj log pj — 교차엔트로피라는 이름의 뿌리입니다(2부).
설명용

유도 — 로짓 기울기는 p − y

정리 — 교차엔트로피의 로짓 기울기
∂ℓ∂zrj = prj − yrjN
증명

한 행만 봅니다. −log pt = −zt + lse(z) 이고, lse(z) = log ∑k ezk 의 미분은

∂ lse∂zj = ezj∑k ezk = pj

입니다. −zt 의 미분은 j = t 일 때만 −1, 곧 −yj 입니다. 더하면 pj − yj, 행 N 개의 평균이므로 1/N 이 붙습니다.

설명용

왜 두 연산을 합치나

소프트맥스 → log → 정답 칸 고르기를 따로 짜도 기울기는 같습니다. 하지만 길을 돌아갑니다.

따로 짠 사슬합친 연산
log 의 역전파정답 칸에 −1/(N·pt) — pt 가 작으면 거대한 수없음
소프트맥스 역전파그 거대한 수에 다시 p 를 곱해 상쇄없음
로짓 기울기상쇄 뒤에 (p − y)/N처음부터 (p − y)/N
순전파 값log(pt) — pt 가 0 으로 내려앉으면 −∞lse − zt — 늘 유한

큰 수로 나눴다가 다시 곱하는 길은 반올림 오차가 커지고, pt = 0 이면 0 으로 나누게 됩니다. 합친 연산에는 나눗셈이 없습니다. C 커널도 같은 모양이라 두 구현을 한 줄씩 맞대어 볼 수 있습니다.

처음 손실은 ln V

쓸모 — 초기화가 작으면 로짓이 0 근처에 모이므로 학습 첫 스텝의 손실은 ln V 가까이 나와야 합니다. 훨씬 크면 초기화가 너무 크거나 무언가 틀렸습니다. 8부 7·8장 학습 기록의 스텝 1 손실을 이 값과 견줘 보십시오.
실행 검증

p − y 가 학습에 좋은 까닭

  • 크기가 스스로 조절됩니다. 정답 칸의 기울기는 pt − 1 — 틀렸을수록(pt → 0) −1 에 가깝고, 맞힐수록 0 에 가깝습니다.
  • 유계입니다. 모든 칸이 −1 과 1 사이라, 한 토큰이 기울기를 폭주시키지 못합니다.
  • 합이 0 입니다. 확률은 늘 합이 1 이므로 한쪽을 올리면 다른 쪽을 내리는 몫만 전달됩니다.
  • 1/N 이 붙습니다. 손실이 평균이므로 배치나 문맥을 늘려도 기울기의 크기는 비슷하게 남습니다.

반면 소프트맥스 뒤에 제곱오차를 쓰면 기울기에 p(1 − p) 꼴이 곱해져, 확신하며 틀린 칸에서 기울기가 거의 0 이 됩니다.

레이어놈

순전파 세 줄, 역전파 유도 한 쪽

레이어놈 — 토큰 하나의 폭 방향으로 정규화

정의 — LayerNorm (SPEC §3.3)
μ = 1n∑j xj,   σ = √1n∑j(xj − μ)2 + ε
x̂j = (xj − μ)/σ,   yj = gjx̂j + bj
ε = 1e-5 이고, g·b 는 폭 n 짜리 학습 파라미터입니다. 이 장에서 n 은 토큰 수가 아니라 한 행의 폭(모델에서는 d)입니다.

한 층의 모든 단위가 같은 μ·σ 를 나눠 쓰고, 훈련 사례(여기서는 토큰)마다 그 값이 따로 계산됩니다 . 배치 안의 다른 토큰을 보지 않으므로 배치 크기와 상관없이, 학습과 생성에서 똑같이 동작합니다.

논문 근거

ops.layernorm — 순전파

  • XH(정규화된 값)와 SIG(행마다의 σ)를 저장합니다. 역전파가 이 둘만으로 끝나도록 유도할 것입니다.
  • 평균과 분산도 fsum 으로 쌓습니다 — 참조 구현은 반올림을 아낍니다.
  • 시간 O(행 수 · n), 저장은 입력과 같은 크기 하나 더.
실행 검증

출력은 평균 0, 분산 거의 1

첫 행은 한 칸만 크게 튀었는데도 출력이 평균 0 근처로 모였습니다. 분산이 1 보다 아주 조금 작은 것은 정의가 σ2 = 분산 + ε 으로 나누기 때문입니다. 출력 분산은 정확히 분산/(분산 + ε) 입니다.

실행 검증

ε 가 막는 것 — 모든 칸이 같은 행

위 캡처의 둘째 행처럼 모든 값이 같으면 분산이 0 입니다. ε 가 없으면 0/0 이 되어 nan 이 나옵니다. ε 가 있으면 x̂ = 0/√ε = 0 이고, 출력은 편향 b 그대로입니다.

트랜스포머의 입력에서 이런 행이 나올 일은 드뭅니다. 그래도 한 번 나오면 그 스텝의 모든 기울기가 nan 이 되므로 분모를 보호합니다.

4장 퀴즈

Q. 어휘 512 인 모델을 막 초기화해 첫 스텝을 돌렸더니 손실이 12 근처로 나왔습니다. 무엇을 의심해야 하나요? 그리고 교차엔트로피를 소프트맥스·log 로 나눠 짰을 때 정답 확률이 0 으로 내려앉으면 무슨 일이 생기나요?

A. 로짓이 고르면 손실은 ln 512, 3장의 표에서 본 대로 6 남짓이어야 합니다. 그 두 배 가까이 나왔다면 로짓이 이미 크게 벌어져 확신하며 틀리고 있다는 뜻 — 초기화 크기나 출력층 연결을 의심합니다. 나눠 짠 경우 log 0 = −∞ 로 손실이 무한대가 되고, log 의 역전파 −1/p 가 0 으로 나누기가 되어 nan 이 퍼집니다. 합친 연산은 lse − z[정답] 을 계산하므로 유한합니다.
설명용

역전파 (1) — g 와 b 는 쉽다

yj = gjx̂j + bj 에서 윗기울기 dyj = ∂ℓ/∂yj 를 받으면:

∂ℓ/∂gj = ∑행 dyjx̂j,   ∂ℓ/∂bj = ∑행 dyj

g·b 는 모든 행(토큰)이 함께 쓰므로 행을 따라 더합니다 — 배치 행렬곱에서 본 "퍼진 축은 더한다" 와 같습니다.

이름 하나 정하기 — dj = dyjgj = ∂ℓ/∂x̂j. 어려운 부분은 이 d 를 x 까지 내리는 것입니다. μ 와 σ 가 행의 모든 칸에 기대기 때문입니다.
설명용

역전파 (2) — μ 와 σ 의 미분

보조정리
∂μ/∂xi = 1n,   ∂σ/∂xi = x̂in
증명

첫 식은 평균의 정의에서 바로 나옵니다. 분산 v = (1/n)∑j(xj − μ)2 을 미분하면

∂v/∂xi = 2n∑j(xj − μ)(δij − 1n) = 2n(xi − μ)

편차의 합 ∑(xj − μ) 이 0 이라 1/n 항이 사라집니다. σ = √(v + ε) 이므로 ∂σ/∂xi = (1/(2σ))·(2/n)(xi − μ) = x̂i/n.

ε 는 상수라 미분에서 사라지지만 σ 안에는 남습니다. 그래서 아래 결과는 근사가 아니라 정확한 식입니다.

설명용

역전파 (3) — x̂ 한 칸이 x 한 칸에 얼마나 기대나

x̂j = (xj − μ)/σ 를 몫의 미분법으로 풀고 보조정리를 넣습니다.

∂x̂j∂xi = δij − 1/nσ − xj − μσ2·x̂in
= 1σ (δij − 1n − x̂ix̂jn)
  • δij — 자기 자신을 직접 통과하는 길
  • −1/n — 평균 μ 를 거쳐 모든 칸으로 새는 길
  • −x̂ix̂j/n — 표준편차 σ 를 거쳐 새는 길
설명용

역전파 (4) — 한 줄로 모으기

정리 — 레이어놈의 입력 기울기
dxi = 1σ ( di − mean(d) − x̂i · mean(d ⊙ x̂) )
증명

연쇄법칙 dxi = ∑j dj ∂x̂j/∂xi 에 앞 장의 식을 넣고 항별로 더합니다. δij 항은 di, −1/n 항은 −(1/n)∑dj = −mean(d), 마지막 항은 −x̂i(1/n)∑djx̂j 입니다. 모두 1/σ 로 나눕니다.

필요한 것은 행마다 평균 두 개(mean d, mean(d⊙x̂))와 저장해 둔 x̂·σ 뿐입니다. n×n 야코비안은 여기서도 만들지 않습니다 — O(n).

설명용

식이 말해 주는 것 — 무엇에 둔감한가

  • ∑i dxi = 0 은 언제나 성립합니다. ∑x̂i = 0 이기 때문입니다. 입력 전체에 같은 수를 더해도 μ 가 흡수해 출력이 그대로이니, 그 방향의 기울기가 없어야 맞습니다.
  • ∑i dxix̂i 는 ε 만큼만 0 이 아닙니다. 계산하면 n·mean(d⊙x̂)·ε / ((v + ε)σ) 입니다. ε 가 0 이면 입력을 몇 배로 키워도 출력이 같다는 "크기 불변" 이 정확히 성립하고, ε 가 그것을 아주 조금 깹니다.

둘째 식의 유도: ∑x̂i2 = n·v/(v + ε) 을 넣으면 됩니다(v 는 분산).

설명용

ops.layernorm — 역전파 코드

md 가 mean(d), mdx 가 mean(d⊙x̂) 이고, gx 줄이 정리의 식을 그대로 옮긴 것입니다. gg·gb 는 (1)에서 본 행 합입니다.

  • 기댓값: E[yk] = (1 − p)·xk/(1 − p) = xk. 학습 때 미리 키워 두므로 생성할 때는 아무것도 곱하지 않고 끄기만 하면 됩니다. "뒤집힌" 이라는 이름이 여기서 옵니다.
  • 역전파: dxk = mkdyk/(1 − p) — 순전파와 같은 마스크를 써야 합니다.
  • 원 트랜스포머는 각 부층의 출력과 임베딩 합에 드롭아웃을 걸었습니다 .
논문 근거

ops.dropout

마스크 M 에 0 또는 1/(1−p) 를 담아 두고 역전파가 그대로 다시 씁니다. 칸마다 uniform() 을 정확히 한 번씩, 앞에서부터 뽑습니다.

첫 시험은 0 의 비율과 평균을 통계 허용치로 보되, 모든 값이 0 아니면 1/(1 − p) 인지는 정확히 봅니다. 둘째 시험은 출력이 0 인 칸에서만 기울기가 0 인지 봅니다.

실행 검증

p = 0 이면 난수를 하나도 뽑지 않는다

SPEC §1.5 는 드롭아웃에 씨앗 seed + 2 의 생성기를 주고, "기록 실행은 p = 0 이라 한 번도 안 뽑는다" 고 적습니다. C 구현에는 드롭아웃이 아예 없습니다. p = 0 인 파이썬이 연산 자체를 건너뛰어야 두 구현이 같은 계산을 합니다.

  • assertIs — 1 을 곱한 새 텐서가 아니라 같은 객체입니다. 계산 그래프에 마디도 생기지 않습니다.
  • 생성기의 다음 값이 새 생성기의 첫 값과 같다 — 난수를 소비하지 않았다는 증거입니다.
실행 검증

인과 마스크 — 미래 칸을 지운다

언어 모델은 한 줄의 모든 위치를 한 번에 학습합니다. 위치 i 가 다음 토큰을 맞히는데 i 뒤의 토큰을 볼 수 있으면 답을 베끼게 됩니다. 그래서 점수 행렬의 j > i 칸을 소프트맥스 전에 −∞ 로 만듭니다. e−∞ = 0 이므로 그 칸의 확률은 정확히 0 입니다. 어텐션 안에서의 쓰임은 6부에서 다룹니다.

실행 검증

ops.causal_softmax — −∞ 를 더하지 않고 건너뛴다

  • 평평한 배열의 r 번째 행이 몇 번째 질의인지는 r % n 입니다. 앞의 배치·헤드 축은 신경 쓰지 않아도 됩니다.
  • 행의 앞 i + 1 칸만 _softmax_row 에 넘기고 나머지는 처음 채운 0 으로 둡니다.
  • 무한대를 실제로 더하지 않으니 inf 산술이 없고, C 에서는 계산할 칸 수도 줄어듭니다.
  • 역전파는 소프트맥스와 같은 식을 같은 i + 1 칸에서만 — 지운 칸의 기울기는 0 입니다.
실행 검증

증인 — 건너뛰기는 −∞ 마스크와 같다

비교 대상은 -math.inf 를 실제로 채워 넣고 보통 소프트맥스를 부른 결과입니다. 최댓값은 늘 대각 칸이라 유한하고, exp(−∞ − m) 은 파이썬에서 정확히 0.0 입니다. 두 결과가 1e-15 안에서 같고, 지운 칸은 근삿값이 아니라 정확히 0 입니다.

6장 퀴즈

Q. (1) 임베딩 행렬의 어떤 행이 한 배치 내내 기울기 0 을 받는다면 그 까닭은? (2) 인과 소프트맥스의 첫 행(i = 0)은 무엇이 되고, 그 행의 입력 기울기는?

A. (1) 그 배치에 그 토큰이 한 번도 안 나왔기 때문입니다. 조회의 역전파는 뽑힌 행에만 더합니다(가중치를 출력층과 묶으면 출력층 쪽 기울기는 따로 들어옵니다). (2) 첫 행은 자기 자신 한 칸만 소프트맥스하므로 [1, 0, 0, …] 입니다(test_causal_row0_attends_only_to_itself). p = [1] 이면 p(g − ⟨g, p⟩) = g − g = 0 이라, 그 행의 입력 기울기는 0 입니다 — 확률이 이미 1 로 고정돼 점수를 바꿔도 달라질 것이 없습니다.

검증, 그리고 C 로

모든 역전파를 차분과 견주고, 같은 식을 float32 로 다시 짠다

역전파를 무엇과 견주나 — 중심 차분

  • 중심 차분 (f(x+h) − f(x−h))/2h 의 오차는 O(h2) — 한쪽 차분의 O(h) 보다 훨씬 작습니다.
  • 출력이 텐서인 연산은 고정된 무작위 가중치 w 를 곱해 더한 스칼라 ∑ w·f(x) 로 만들어 잽니다. 그러면 야코비안의 모든 칸이 한 번에 섞여 시험됩니다(test_tensor.check).
  • 오차는 칸마다가 아니라 벡터 전체의 크기에 견줍니다. 0 근처 칸의 차분 잡음이 부풀지 않게 하려는 것입니다.
실행 검증

연산마다 역전파 대 차분 — 한 표로

행렬곱·소프트맥스·교차엔트로피·레이어놈·GELU·인과 소프트맥스가 이 부에서 다룬 연산입니다. 위 표의 오차는 모두 차분 간격 h 가 만드는 반올림 수준에 머뭅니다. 유도에서 항 하나만 빠져도 오차는 이 크기가 아니라 기울기 자체의 크기가 됩니다 — 그래서 이 표는 "맞다" 와 "틀리다" 를 가르기에 충분합니다.

실행 검증

C 의 원칙 — 값은 float32, 합은 double

  • 값을 float32 로 드는 까닭 — 메모리가 절반이라 캐시에 두 배가 들고, 체크포인트도 float32 입니다(SPEC §2·§4).
  • 합을 double 로 쌓는 까닭 — 한 행의 분모·평균·내적은 수백 항을 더합니다. float32 로 쌓으면 덧셈마다의 반올림이 쌓여 fsum 을 쓰는 파이썬과 멀어집니다. 원소 하나를 담기에는 float32 로 충분합니다.
  • 허용 오차는 이 차이를 전제로 SPEC §9 가 정합니다 — 순전파는 상대 1e-4, 기울기는 칸 크기에 견준 기준.
실행 검증

C 의 교차엔트로피 — 손실은 double 로 돌려준다

한 행의 손실은 로그합지수까지 double 로 계산해 돌려줍니다. 모델(c/model.c)은 그것을 행마다 담아 두었다가 행 차례로 더해 평균을 냅니다. 역전파의 scale 은 모델에서 1/N — 파이썬의 g0 / rows 에서 윗기울기 g0 가 1 인 경우입니다.

실행 검증

C 의 레이어놈 역전파 — 식은 파이썬과 한 줄씩 같다

  • 순전파가 sinv = 1/σ 를 저장해 두므로 역전파는 나눗셈 대신 곱셈을 합니다.
  • 행 안의 평균 md·mdx 는 double 로 쌓습니다.
  • dg·db 는 여러 행을 거쳐 float32 로 더해 갑니다. 머리말의 "합은 double" 원칙에서 벗어난 자리지만, C 시험이 파이썬과의 차이를 허용 오차 안에서 확인합니다.
실행 검증

C 시험 — 파이썬이 남긴 입력과 답으로

파이썬이 무작위 입력과 그 출력·기울기를 파일(ckpt/parity/ops.tfx)에 적고, C 가 같은 입력으로 계산해 견줍니다. 로짓을 일부러 크게 잡아 최댓값 빼기를 잊은 구현이 넘치게 했습니다. 같은 파일의 뒷부분이 레이어놈·GELU(원점의 기울기 ½ 포함)·인과 소프트맥스를 봅니다. C 쪽을 모아 보는 일은 9부의 몫입니다.

실행 검증

순수 파이썬의 속도 — 느림이 알려 주는 비용

파이썬의 O[ro + j] += aik * B[rb + j] 한 줄은 기계어 곱셈 한 번이 아닙니다.

  • 리스트 두 번 조회(범위 검사 포함), 덧셈으로 색인 계산, float 객체 꺼내기
  • 곱셈 결과로 새 float 객체 만들기, 덧셈 결과로 또 하나, 리스트 칸에 다시 넣기
  • 그 사이사이 바이트코드 해석기의 분기

C 의 같은 줄은 나란히 놓인 float32 두 개를 곱해 더하는 명령 몇 개입니다. 그래서 두 구현의 곱셈 수는 같고(1장의 계수기), 곱셈 하나의 값만 몇 자릿수 다릅니다. 비용 모형은 "곱셈 수 × 곱셈 하나의 값" 이고, 앞의 인수는 모델이 정하고 뒤의 인수는 구현이 정합니다.

그래서 파이썬 참조는 설명과 정답지를 맡고 작은 모델만 학습시킵니다. 실제 학습은 C 가 합니다. 숫자로 된 비교는 9부의 벤치 표에만 있습니다.

7장 퀴즈

Q. C 의 소프트맥스 분모를 float32 변수로 쌓도록 바꾸면 무엇이 달라지나요? 그리고 역전파를 한쪽 차분 (f(x+h) − f(x))/h 과 견주면 왜 판정이 흐려지나요?

A. 덧셈마다 float32 의 유효 자릿수에서 반올림이 일어나고 그것이 행 길이만큼 쌓여, fsum 으로 정확히 더한 파이썬과의 차이가 커집니다. 결과가 조금 흐려질 뿐 틀리지는 않지만, 파이썬과의 대조가 허용 오차 가장자리로 밀려 진짜 버그와 반올림을 구별하기 어려워집니다. 한쪽 차분은 오차가 O(h) 라 참 기울기와 이미 눈에 띄게 다릅니다. 그러면 "역전파가 틀렸다" 와 "차분이 거칠다" 를 같은 크기로 보게 되어 판정 기준을 느슨하게 잡아야 합니다. 중심 차분의 O(h²) 가 기준을 조일 수 있게 해 줍니다.
