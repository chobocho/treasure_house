1장

잔차 스트림

블록은 x 를 바꾸지 않고 더한다

모델 전체가 한 화면에 들어갑니다

임베딩, 블록 L 개, 마지막 정규화, 출력 사영. GPT 형 디코더의 순전파는 이것이 전부입니다.

실행 검증

잔차 — 더하기만 하는 길

블록 안의 두 줄 x = T.add(x, o), x = T.add(x, f) 가 이 구조의 요점입니다. 어텐션도 FFN 도 x 를 바꾸지 않고, 자기 결과를 x 에 더합니다.

xl+1 = xl + Fl(xl)

그래서 마지막 층의 표현은 임베딩에 블록마다의 기여를 차례로 더한 합입니다.

xL = x0 + L−1Σl=0 Fl(xl)

이 합의 흐름을 흔히 잔차 스트림(residual stream)이라 부릅니다. 한 F(x) + x 를 두는 생각은 잔차 학습에서 왔습니다 .

논문 근거

덧셈은 기울기를 그대로 통과시킵니다

3부에서 본 규칙 — 덧셈 노드의 역전파는 받은 기울기를 두 입력에 그대로 나눠 줍니다. 그러므로

∂ℓ∂xl = ∂ℓ∂xl+1 + ∂ℓ∂xl+1 ∂Fl∂xl

첫 항은 곱해지는 것이 없습니다. 블록을 몇 개 쌓든 출력의 기울기가 임베딩까지 곱셈 없이 이어지는 길이 하나 남습니다. 깊은 망에서 기울기가 사라지거나 터지는 문제를 이 길이 막습니다.

식은 유도이고 수를 내지 않으므로 설명용입니다. 덧셈의 역전파가 정말 그렇게 도는지는 test_tensor.py 의 차분 시험이 봅니다.
설명용

그림으로 — 굵은 선에는 연산이 없습니다

설명용

폭이 끝까지 같아야 하는 까닭

더하려면 모양이 같아야 합니다. 그래서 잔차 스트림의 폭 d 는 임베딩에서 마지막 정규화까지 한 번도 바뀌지 않습니다.

  • 어텐션은 d → 3d 로 사영했다가(q·k·v) 다시 d 로 돌아옵니다 (Wo).
  • FFN 은 d → dff 로 넓혔다가 d 로 좁힙니다 (W2).
  • 곁가지 안에서는 무엇을 해도 되지만, 스트림으로 돌아올 때는 늘 폭 d 입니다.

2장

pre-LN 과 post-LN

정규화를 어디에 두느냐가 기울기 길을 바꾼다

원래 트랜스포머는 더한 뒤에 정규화했습니다

두 배치를 식으로 나란히 놓으면 차이가 한눈에 보입니다.

post-LN:   xl+1 = LN(xl + F(xl))
pre-LN:    xl+1 = xl + F(LN(xl))

post-LN 에서는 잔차 길 위에 정규화가 앉아 있습니다. 1장의 "곱셈 없는 길" 이 블록마다 LN 의 야코비안을 한 번씩 지나게 됩니다.

설명용

GPT-2 는 정규화를 입력 쪽으로 옮겼습니다

GPT-2 보고서는 레이어 정규화를 각 하위 블록의 입력으로 옮기고, 마지막 어텐션 블록 뒤에 정규화를 하나 더 두었다고 적습니다 . 이 덱의 모델이 그 배치입니다 — forward 의 ln1·ln2 가 곁가지 입구에, lnf 가 맨 끝에 있습니다.

실행 검증

배치와 워밍업

Xiong 외는 초기화 시점의 기울기 크기를 분석해, post-LN 은 출력 가까운 층의 기울기가 커서 학습률 워밍업이 사실상 필수이고 pre-LN 은 기울기가 잘 행동해 워밍업을 뺄 수도 있다고 보였습니다 .

  • 이 덱은 그래도 워밍업을 씁니다(8부) — 작은 모델에서도 첫 몇 스텝의 큰 갱신을 누그러뜨리는 값싼 안전장치이기 때문입니다.
  • 분석의 증명은 이 덱의 범위를 넘습니다. 결론만 인용합니다.
논문 근거

마지막 LN 은 왜 필요한가

pre-LN 에서는 스트림 자체가 한 번도 정규화되지 않습니다. 블록이 더할수록 x 의 크기는 커질 수 있습니다. 출력 사영(로짓) 직전에 한 번 정규화해야 로짓의 크기가 깊이에 휘둘리지 않습니다.

그래서 GPT-2 가 덧붙인 "마지막 블록 뒤의 정규화" 가 pre-LN 과 한 쌍으로 옵니다. 코드에서는 lnf_g·lnf_b 두 텐서, 파라미터 2d 개입니다.

설명용

3장

FFN

토큰마다 따로 도는 두 층짜리 MLP

넓혔다가 좁힌다

FFN(x) = GELU(xW1 + b1) W2 + b2

W1 은 [d, dff], W2 는 [dff, d] 입니다(SPEC §2 — 행 벡터). 원래 트랜스포머는 d = 512 에 dff = 2048, 곧 네 배를 썼고 , GPT 계열도 대개 4배입니다.

논문 근거

토큰끼리 섞지 않습니다

행렬곱 x W1 에서 x 는 (B, n, d) 이고 W1 은 2차원입니다. 4부에서 본 대로 배치 축은 퍼지기만 합니다 — 행 i 의 출력은 행 i 의 입력에만 기댑니다.

  • 그래서 FFN 은 "위치마다 같은 MLP" 입니다(논문의 이름 position-wise).
  • 토큰 사이에 정보를 옮기는 곳은 어텐션뿐입니다. FFN 은 옮겨 온 정보를 그 자리에서 가공합니다.
  • C 에서는 이 성질 덕에 행마다 나눠 스레드로 돌려도 결과가 같습니다(9부).
설명용

파라미터 대부분은 FFN 에 삽니다

d_ff = 4d 이면 블록 하나의 FFN 은 4d² + 4d + 4d² + d = 8d² + 5d, 어텐션은 4d² + 4d 입니다. 두 배 차이입니다.

1~3장 퀴즈

Q. 어떤 사람이 "pre-LN 이면 스트림이 정규화되지 않으니, 블록 출력 F(LN(x)) 도 정규화해서 더하자" 고 제안합니다. 곧 x + LN(F(LN(x))) 입니다. 1장의 기울기 길 관점에서 이 제안은 무엇을 해치고, 무엇은 해치지 않습니까?

A. 잔차 길은 해치지 않습니다. 덧셈의 한쪽이 여전히 x 그대로라 ∂ℓ/∂xl+1 이 곱셈 없이 내려가는 길은 남습니다.
해치는 것은 곁가지의 크기 조절입니다. 곁가지 출력을 늘 분산 1 로 맞추면, 블록이 "이번에는 조금만 보태자" 고 출력을 작게 낼 수 없습니다. 블록마다 같은 크기로 더해져 스트림이 깊이에 비례해 커지고, 그만큼 뒤 블록의 기여가 상대적으로 작아집니다. post-LN 이 잔차 길 위에 LN 을 올려 기울기를 해쳤다면, 이 제안은 길은 두되 곁가지의 표현력을 해칩니다.

선형 이동 성질

삼각함수의 덧셈정리에서 바로 나옵니다.

sin(a+b) = sin a cos b + cos a sin b

학습한 위치 임베딩

표를 정하지 않고 위치마다 벡터를 배웁니다. GPT-2 가 이것이고, 이 덱의 기본값도 이것입니다. 초기화는 토큰 임베딩과 같은 normal·0.02 입니다(SPEC §3.5).

원래 트랜스포머 논문은 둘을 견주어 거의 같은 결과를 얻었고, 학습 때보다 긴 줄로 외삽할 수 있으리라는 가설 때문에 사인을 골랐다고 적습니다 .

대가 — 학습한 위치는 T 보다 긴 위치를 모릅니다. 표에 그 행이 없습니다. 10부에서 문맥이 차면 뒤쪽 절반만 남겨 다시 채우는 규칙이 필요한 까닭입니다.
논문 근거

RoPE — 더하지 않고 돌린다

Su 외의 RoPE 는 위치 정보를 x 에 더하지 않고, 어텐션 직전에 q 와 k 를 위치만큼 회전시킵니다 .

(a, b) ↦ (a cos θ − b sin θ,  a sin θ + b cos θ),   θ = m·10000−2i/dk

회전은 내적을 보존하는 변환이라 RmᵀRn = Rn−m 입니다. 그래서

⟨Rmq, Rnk⟩ = ⟨q, Rn−mk⟩

점수가 절대 위치가 아니라 거리에만 달립니다.

묶인 출력 사영

마지막 정규화를 지난 h 에서 로짓을 만드는 줄은 이것 하나입니다.

로짓 = h · Wte⊤

토큰 t 의 로짓은 h 와 "토큰 t 의 임베딩 행" 의 내적입니다. 들어올 때 토큰을 벡터로 바꾼 표를, 나갈 때는 벡터가 어느 토큰과 닮았는지 재는 자로 씁니다. 입력·출력 임베딩을 묶자는 제안은 Press·Wolf 에게서 왔고 , 원래 트랜스포머도 두 임베딩과 소프트맥스 앞 사영이 행렬을 나눠 썼습니다 .

논문 근거

묶으면 기울기가 두 곳에서 옵니다

wte 는 그래프에서 두 번 쓰입니다 — 맨 앞의 조회와 맨 끝의 행렬곱. 3부의 규칙대로 기울기는 두 길의 합입니다.

  • 끝에서: ∂ℓ/∂Wte = Gᵀh — 모든 위치·모든 토큰 행에 조금씩.
  • 앞에서: 입력에 나온 토큰 행에만, 그 위치의 기울기를 더해서(scatter-add).
  • C 는 이 둘을 파이썬과 같은 차례로 더합니다 — 끝의 몫을 먼저, 조회의 몫을 나중에. 차례가 달라도 수학은 같지만 float32 의 반올림은 달라집니다(9부).

실행 검증

초기화 — 잔차로 들어가는 사영만 작게

행렬은 normal·0.02, 잔차 스트림으로 돌아오는 두 사영 Wo·W2 만 0.02/√(2L) 입니다. 블록마다 스트림에 두 번 더하므로 더해지는 곳이 2L 개이고, 그 합의 분산이 깊이에 비례해 커지지 않게 줄입니다.

GPT-2 보고서는 잔차 층의 가중치를 1/√N(N 은 잔차 층 수)배 한다고 적습니다 . 편향과 LN 은 난수를 뽑지 않습니다 — 뽑는 차례가 C 와 맞아야 하기 때문입니다.

기울기가 정확히 0 인 파라미터

키의 편향 bk 을 조금 바꿔 봅시다. 모든 키에 같은 벡터가 더해지므로 질의 i 의 점수는 모두 qi·bk/√dk 만큼 같이 옮겨 갑니다. 소프트맥스는 한 행에 같은 수를 더해도 그대로입니다.

그러니 ∂ℓ/∂bk = 0 — 이 파라미터는 배우지 못합니다. RoPE 는 위치마다 bk 를 다르게 돌려 이 대칭을 깹니다.

4~5장 퀴즈

Q. 키 편향의 기울기가 0 이라면, 값(value) 의 편향 bv 은 어떻습니까? 모든 값 벡터에 같은 bv 를 더했을 때 어텐션 출력이 어떻게 바뀌는지로 답해 보십시오.

A. 0 이 아닙니다. 출력은 Σj wij(vj + bv) = Σj wijvj + bv·Σj wij 이고, 가중치의 합은 1 이라 출력에 bv 가 그대로 더해집니다. 키의 편향은 소프트맥스 안에서 행 전체를 옮겨 사라지지만, 값의 편향은 소프트맥스 밖에서 출력으로 흘러 나갑니다. 그래서 bv 는 배우고, 뒤의 Wo 를 지나 스트림에 상수 벡터를 보탭니다.

FLOPs ≈ 6N

학습 비용을 곱셈 수로 어림한다

곱셈 수로 센다

행렬곱 [m, p] 한 번을 행 하나에 적용하면 곱셈 m·p 번과 덧셈 m·p 번이 듭니다. 곱셈과 덧셈을 하나씩 FLOP 로 치면 파라미터 하나당 FLOP 2개입니다.

  • 순전파: 토큰당 약 2N.
  • 역전파: 입력 쪽 기울기(dX = dY Wᵀ)와 가중치 쪽 기울기(dW = Xᵀ dY)가 각각 순전파만큼 — 약 4N.
  • 합이 약 6N. Kaplan 외는 학습 계산량을 C ≈ 6NBS 로 적습니다 .
논문 근거

곱셈 수를 정확히 세는 식

어림이 아니라 정확한 수입니다. 우리 tensor.matmul 이 실제로 한 곱셈을 계수기(tensor.MULTS)로 세어 식과 견줍니다.

논문 근거

디코더 전용 — 이 덱의 모델

교차 어텐션을 떼고 인과 마스크를 둔 블록만 쌓으면 "앞 토큰들에서 다음 토큰" 을 맞히는 언어 모델이 됩니다. GPT 계열의 모양입니다 .

  • 학습 신호가 모든 위치에서 나옵니다 — 길이 n 인 줄 하나가 예측 n 개입니다.
  • 생성이 곧 학습과 같은 일입니다 — 다음 토큰을 뽑아 뒤에 붙이고 되풀이합니다(10부).
  • 번역 같은 과제도 "원문 → 구분자 → 번역" 을 한 줄로 이어 붙여 풀 수 있습니다. 이 덱의 덧셈 과제가 그 꼴입니다(123+456= 다음을 맞힌다).

인과 마스크를 떼면 모든 토큰이 앞뒤를 다 봅니다. 그러면 "다음 토큰 맞히기" 는 답을 보고 푸는 일이 되므로, BERT 는 토큰 일부를 가리고 가린 자리를 맞히게 학습했습니다 . 이 덱은 11부에서 같은 블록으로 그 손실을 구현합니다.

6~8장 퀴즈

Q. 어휘를 50257 에서 100000 으로 늘리면 GPT-2 small 의 파라미터 수와 토큰당 학습 FLOPs 는 어떻게 바뀝니까? 묶인 출력 사영을 염두에 두고 답하십시오.

A. 파라미터는 V·d 한 번만 늡니다 — (100000 − 50257)·768 = 38,202,624 개. 출력 사영이 wte 와 묶여 있어 두 번 늘지 않습니다.
FLOPs 는 출력 사영의 곱셈 n·d·V 가 늘어 토큰당 곱셈이 약 3,820만 개 늡니다. 반면 입력 쪽 임베딩은 "조회" 라 곱셈이 없습니다. 그래서 파라미터로 보면 어휘 표가 임베딩과 출력에 한 번 들어 있지만, 계산으로 보면 출력 쪽에서만 비용이 듭니다 — 6N 어림이 임베딩을 N 에서 빼는 까닭이기도 합니다.
