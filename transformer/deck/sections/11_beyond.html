1장

온라인 소프트맥스

가중치 n 개를 한꺼번에 들지 않고 조각씩 읽는다

무엇이 문제였나

6부에서 어텐션 가중치는 (B, h, n, n) 모양이라 문맥 길이의 제곱으로 메모리를 먹는다고 했습니다 (6부 6장).

그런데 한 질의 i 의 출력은 가중합 하나뿐입니다.

oi = Σj softmax(x)j vj,   xj = qi·kj/√dk

가중치 n 개를 전부 적어 두지 않고, 키를 몇 개씩(조각, 타일) 읽으며 몇 개의 수만 고쳐 나가도 같은 가중합에 닿을 수 있을까요? 이 장의 답은 "수 셋이면 된다" 입니다.

설명용

들고 다니는 수 셋

소프트맥스는 모든 점수에서 같은 수를 빼도 바뀌지 않습니다 (2부 3장). 그래서 지금까지 본 점수의 최댓값을 빼 두면 지수가 늘 0 이하라 넘치지 않습니다.

정의 — 앞부분 P 를 읽은 뒤의 상태
m = maxj∈P xj
s = Σj∈P exj−m
o = 1s Σj∈P exj−m vj
o 는 "P 만 있었다면 나왔을 어텐션 출력" 입니다. 처음에는 m = −∞, s = 0, o = 0 으로 둡니다.
설명용

조각 하나를 읽을 때의 갱신

정리 — 조각 C 를 더 읽으면
m′ = max(m, maxj∈C xj)
s옛 = s · em−m′,   ej = exj−m′ (j ∈ C)
s′ = s옛 + Σj∈C ej
o′ = o · s옛 + Σj∈C ej vjs′
그러면 (m′, s′, o′) 은 P∪C 의 상태입니다.

새 최댓값이 오면 옛 합을 em−m′ ≤ 1 로 줄여서 새 기준에 맞춥니다. 곱하는 수가 1 이하라 여기서도 넘침이 없습니다.

설명용

왜 맞는가

증명 s 의 정의에 em−m′ 을 곱하면 지수의 기준만 바뀝니다.
s옛 = Σj∈P exj−m′
그러므로 s′ = Σj∈P∪C exj−m′ 입니다. 같은 방법으로 o·s = ΣP exj−mvj 에 em−m′ 을 곱하면
o · s옛 = Σj∈P exj−m′ vj
이므로 o′ 의 분자는 P∪C 전체의 가중합, 분모는 P∪C 전체의 정규화 합입니다. 분자·분모에 같은 em′ 이 빠져 있으니 소프트맥스 가중합과 같습니다. 조각 수에 대한 귀납법으로 마지막 상태의 o 가 전체 출력이고, 덤으로 logsumexp(x) = m + ln s 입니다. ∎
설명용

그림으로 — 조각 셋, 상태 셋

한 번에 손에 드는 것은 조각 하나 분량의 ej 와 수 셋뿐입니다. 조각 크기를 1 로 하면 원소 하나씩, n 으로 하면 보통의 소프트맥스가 됩니다.

설명용

식을 그대로 옮긴 코드

m2·old·s2 가 앞 장의 m′·s옛·s′ 입니다. s > 0 검사는 첫 조각에서 −∞ − m′ 을 지수에 넣지 않으려는 것입니다.

어텐션 한 층에 끼우기

인과 마스크는 j ≤ i 까지만 점수를 만드는 것으로 대신합니다. 시험은 6부의 scaled_dot_product 와 조각 크기 1·2·4 에서 견줍니다 (test_tiled_attention_matches_sdpa).

정직하게 적으면 — 이 함수는 한 행의 점수 xs 를 먼저 다 만든 뒤 조각으로 읽습니다. 그래서 동시에 드는 것은 n×n 이 아니라 한 행의 n 개입니다. 점수도 조각 안에서만 만들면 조각 크기까지 줄지만, 여기서는 갱신 식을 보이는 데 집중했습니다.
실행 검증

원조 — 한 번 훑어 정규화 합 구하기

Milakov·Gimelshein 은 최댓값 m 과 정규화 항 d 를 원소 하나씩 읽으며 함께 갱신하는 알고리즘을 "Online Softmax" 라 불렀습니다. 새 최댓값이 오면 옛 항을 새 기준에 맞춘 뒤 새 값을 더한다는 설명이 앞 장의 갱신과 같습니다 .

  • 우리 코드에서 조각 크기를 1 로 두고 o 를 빼면 그 알고리즘입니다.
  • 논문의 동기는 메모리 접근 횟수였습니다 — 원소마다 메모리 접근이 네 번에서 세 번으로 줄어듭니다.
  • 우리가 덧붙인 o 의 갱신이 "소프트맥스 값" 대신 "어텐션 출력" 을 바로 쌓게 해 줍니다.
논문 근거

플래시 어텐션과의 관계

FlashAttention 은 N×N 어텐션 행렬을 느린 메모리에 만들지 않으려고 두 기법을 씁니다. 하나는 타일링 — 블록마다 소프트맥스를 계산하고, m(x) 와 합 ℓ(x) 를 들고 다니며 이어 붙인 벡터의 소프트맥스를 크기 조정으로 분해합니다. 다른 하나는 재계산 — 역전파 때 가중치를 다시 만듭니다 .

  • 타일링의 식은 이 장의 (m, s) 갱신과 같은 생각입니다.
  • 재계산은 6부 5~6장 퀴즈에서 본 거래입니다 (6부 6장).
  • 빠르기의 원천인 GPU 메모리 계층(칩 위 작은 메모리와 큰 메모리 사이의 읽기·쓰기)과 커널 합치기는 이 덱이 다루지 않습니다. 순수 파이썬 구현은 오히려 느립니다.
논문 근거

1장 퀴즈

Q. 갱신에서 s옛 = s·em−m′ 대신 기준을 바꾸지 않고 s′ = s + Σ exj−m 로 쌓으면 (첫 조각의 m 을 끝까지 쓰면) 무엇이 문제입니까? 수학적으로 틀립니까?

A. 수학적으로는 맞습니다 — 기준은 아무 상수나 빼도 소프트맥스가 같기 때문입니다. 문제는 수치입니다. 뒤 조각에 첫 기준보다 훨씬 큰 점수가 오면 ex−m 의 지수가 양수로 커져 double 이 넘칠 수 있습니다. 최댓값을 따라 기준을 옮기면 모든 지수가 0 이하, 곱하는 em−m′ 도 1 이하라 넘침이 원천적으로 없습니다. 대신 아주 작은 값이 0 으로 떨어지는(언더플로) 일은 생길 수 있지만, 그런 항은 가중치로도 무시해도 될 만큼 작습니다.

MQA 와 GQA

질의 헤드는 그대로, 키·값 헤드만 나눠 쓴다

생성할 때의 병목은 계산이 아니라 메모리

10부의 KV 캐시는 토큰마다 키·값을 쌓아 두고 새 위치의 질의·키·값만 계산합니다(10부). 곱셈은 크게 줄지만, 한 토큰을 낼 때마다 쌓인 키·값을 전부 다시 읽어야 합니다.

Shazeer 는 한 토큰씩 늘려 가는 멀티헤드 어텐션을 분석해, 메모리 접근 대 산술 연산의 비가 n/d + 1/b 꼴이라고 적습니다(b 는 배치). 1/b 는 배치를 키워 줄일 수 있지만, n/d 는 쌓인 K·V 를 매 스텝 다시 불러오는 비용이라 줄이기 어렵다고 봅니다 .

논문 근거

MQA — 키·값 한 벌을 모든 헤드가

멀티쿼리 어텐션은 멀티헤드와 같되 헤드들이 키와 값 한 벌을 함께 쓰는 변형입니다. 질의 쪽의 헤드 차원은 남기고, K·V 의 헤드 차원만 없앱니다 .

  • 질의 헤드는 여전히 h 개라, 헤드마다 다른 곳을 보는 능력은 질의 사영이 맡습니다.
  • 같은 분석에서 앞 장의 n/d 항이 h 배 줄어듭니다 .
  • 대가는 표현력입니다 — 키·값 부분공간이 하나뿐입니다.

GQA — MHA 와 MQA 사이

Ainslie 외의 그룹쿼리 어텐션은 질의 헤드를 G 개 그룹으로 나누고, 그룹마다 키·값 헤드를 하나씩 둡니다. GQA-1 은 MQA 와 같고, 그룹 수가 헤드 수와 같은 GQA-H 는 MHA 와 같습니다 .

MHAhj
GQAh 의 약수⌊j / (h/g)⌋

논문은 MHA 에서 MQA 로 가면 키·값 캐시가 헤드 수 배 준다고 적고, 중간 그룹 수가 품질과 속도 사이의 좋은 절충이라고 봅니다.

논문 근거

모양 — 사영을 둘로 나눈다

우리 모델은 q·k·v 를 Wqkv [d, 3d] 한 행렬로 사영합니다(SPEC §3). GQA 에서는 키·값 폭이 2·g·dk 로 줄어 질의와 모양이 달라지므로 Wq [d, d] 와 Wkv [d, 2g·dk] 로 나눕니다.

repeat_heads 는 새로 곱하는 것이 없는 모음(gather)입니다. 질의 헤드 hh 가 키 헤드 hh // rep 의 칸을 그대로 가리킵니다.

GQA 한 층

되풀이한 뒤에는 6부의 scaled_dot_product 를 그대로 부릅니다. 어텐션 자체는 한 글자도 바뀌지 않았고, 달라진 것은 k·v 를 몇 벌 만드느냐뿐입니다.

2장 퀴즈

Q. h = 12, g = 4 인 GQA 층의 파라미터 수를 d = 768 인 MHA 층(Wqkv·bqkv·Wo·bo)과 견주면 얼마나 줄어듭니까? 질의 헤드 7 은 어느 키 헤드를 씁니까?

A. dk = 64 라 키·값 폭은 2·4·64 = 512 입니다. MHA 의 사영은 Wqkv [768, 2304] 와 bqkv 2304 개인데, GQA 는 Wq [768, 768]·bq 768 과 Wkv [768, 512]·bkv 512 입니다. 합치면 2304 열이 768 + 512 = 1280 열이 되어 가중치 768 × 1024 = 786,432 개와 편향 1024 개, 모두 787,456 개가 줄어듭니다. Wo·bo 는 같습니다.
rep = 12/4 = 3 이므로 질의 헤드 7 은 키 헤드 ⌊7/3⌋ = 2 를 씁니다.

  • 원래 트랜스포머 논문도 사인 인코딩을 고른 까닭을 외삽할 수 있으리라는 가설로 적었습니다 .
  • RoFormer 저자들은 한계 절에서, 긴 글에서 더 나은 성능을 보였지만 그에 대한 믿을 만한 설명은 아직 없다고 적습니다 .
  • 이 덱의 모델은 짧은 문맥만 배웠고 외삽을 실험하지 않았습니다. 그래서 문맥이 차면 SPEC §7 의 규칙대로 뒤쪽 절반만 남기고 다시 채웁니다.
논문 근거

4장

LoRA

얼린 가중치 옆에 낮은 계수의 갱신을 붙인다

미세조정의 갱신은 계수가 낮다는 가설

Hu 외는 사전학습한 가중치 W0 ∈ ℝd×k 를 얼리고, 갱신을 두 작은 행렬의 곱으로 제한합니다 .

h = W0x + αr BAx,   B ∈ ℝd×r, A ∈ ℝr×k, r ≪ min(d, k)
  • 근거는 가설입니다 — 적응할 때의 가중치 변화가 낮은 "내재 계수" 를 가지리라는 것.
  • A 는 무작위 가우스, B 는 0 으로 시작해 처음에는 ΔW = BA = 0 입니다.
  • α/r 배는 r 을 바꿀 때 하이퍼파라미터를 다시 맞출 일을 줄이려는 것이라고 적습니다.
논문 근거

논문의 열 벡터를 우리의 행 벡터로

논문은 입력을 열 벡터로 씁니다(W0x). 이 덱은 행 벡터입니다(SPEC §2).

y = xW + b + αr (xA)B,   A [din, r], B [r, dout]
입력 쪽(먼저 곱함)출력 쪽
논문A — 무작위B — 0 에서 시작
이 덱A — 무작위B — 0 에서 시작

곱하는 순서가 뒤집혀 보여도 역할은 같게 이름을 맞췄습니다. 입력을 먼저 r 차원으로 누르는 것이 A, 다시 넓히는 것이 B 입니다.

설명용

설명용

코드 — 곱 세 번과 덧셈 한 번

xA 가 [n, r] 로 좁으므로, r 이 작으면 곁가지의 곱셈은 n·r·(din + dout) 번으로 원래 층의 n·din·dout 보다 훨씬 적습니다.

실행 검증

기울기를 유도하면

z = xA, c = α/r, 출력 쪽 기울기를 g = ∂ℓ/∂y 라 하면 행렬곱의 역전파(3부 6장)를 두 번 쓰면 됩니다.

∂ℓ/∂B = c · z⊤g = c · (xA)⊤g
∂ℓ/∂A = c · x⊤(gB⊤)
B = 0 이면 ∂ℓ/∂A 는 정확히 0 이고, ∂ℓ/∂B 는 A 가 무작위라 보통 0 이 아닙니다. 첫 스텝에서 배우는 것은 B 뿐입니다.

A 까지 0 으로 두면 두 기울기가 모두 0 이라 영영 움직이지 않습니다. 논문이 한쪽만 0 으로 두는 까닭이 이 식에 보입니다.

설명용

계획서의 증인은 틀렸습니다

이 덱의 작업 계획서(PLAN.md §3.1)는 LoRA 의 증인을 "B = 0 이면 출력이 그대로이고, 그 기울기가 A 에 닿는다" 로 적었습니다. 앞 장의 식이 보이듯 뒷부분은 거짓입니다.

계획서의 규칙은 "증인이 거짓으로 드러나면 참인 성질로 시험을 고쳐 쓰고 까닭을 docstring 에 적는다" 입니다. 그래서 시험은 참인 성질 — B 가 먼저 기울기를 받고 A 는 받지 않는다 — 을 봅니다.

실행 검증

B 가 한 번 움직이면 A 도 배운다

B 에 작은 값을 넣으면 A 의 기울기가 0 이 아니게 되고, 그 값은 유한차분과 맞습니다 (check 가 두 입력 모두를 봅니다). 실제 학습에서는 첫 갱신 뒤부터 둘 다 움직입니다.

실행 검증

실행 결과 — 숫자로 본 두 성질과 파라미터 수

첫 표의 A 기울기 줄이 앞 장의 식 그대로 0 입니다. 둘째 표는 정사각 층 하나에 붙인 LoRA 의 파라미터 r(din + dout) 을 원래 din·dout 과 견줍니다 — 폭이 클수록 비율이 작아집니다.

실행 검증

W′ = W + αr AB

논문은 합친 가중치로 추론하면 지연이 전혀 늘지 않는다고 적고 , 대신 합쳐 두면 서로 다른 과제의 A·B 를 한 배치에 섞기 어렵다는 한계도 적습니다 .

실행 검증

어느 행렬에 붙이나

논문은 어텐션의 가중치 행렬에만 LoRA 를 붙이고 MLP 는 얼린 채로 연구했습니다. GPT-3 175B 에서 r = 4 로 질의·값 사영에만 붙이면 체크포인트가 350GB 에서 35MB 로 약 10,000배 줄고, Adam 으로 학습할 때 VRAM 을 최대 2/3 줄인다고 적습니다 .

이 덱의 범위 — lora_linear 는 선형층 하나입니다. 우리 모델은 q·k·v 를 Wqkv 한 행렬로 사영하므로, "질의에만" 붙이려면 앞 d 열에만 갱신을 더해야 합니다. 그 배선과 미세조정 실험은 하지 않았습니다.
논문 근거

3~4장 퀴즈

Q. B 를 무작위로, A 를 0 으로 시작하면 어떻게 됩니까? 처음 출력은 여전히 원래 모델과 같습니까? 첫 스텝에서 누가 기울기를 받습니까?

A. xA = 0 이라 곁가지 출력 (xA)B 도 0 — 처음 출력은 같습니다. 기울기는 역할이 뒤바뀝니다. ∂ℓ/∂B = c·(xA)ᵀg 는 xA = 0 이라 0 이고, ∂ℓ/∂A = c·xᵀ(gBᵀ) 는 B 가 무작위라 0 이 아닙니다. 그러니 첫 스텝에는 A 만 배우고, A 가 움직인 다음부터 B 도 배웁니다. 수학적으로는 대칭입니다 — "한쪽은 0, 다른 쪽은 무작위" 이면 어느 쪽이든 출발점이 원래 모델과 같고 학습이 막히지 않습니다.

인코더 변형 — MLM

마스크를 떼고, 가린 토큰을 맞힌다

양방향이면 왜 "다음 토큰" 을 못 쓰나

인과 마스크를 떼면 모든 토큰이 앞뒤를 다 봅니다(7부 8장). 그러면 여러 층을 거치는 동안 각 단어가 간접적으로 "자기 자신을 보게" 되어, 맞힐 단어를 너무 쉽게 맞힐 수 있습니다. BERT 는 그래서 입력 토큰의 일부를 무작위로 가리고 가린 토큰만 맞히게 했습니다 .

  • 우리 코드에서 달라지는 것은 model.forward(…, causal=False) 와 손실을 세는 자리뿐입니다.
  • 블록·어텐션·FFN 은 디코더와 같은 코드를 씁니다.
논문 근거

15% 를 고르고, 80·10·10 으로 바꾼다

BERT 는 토큰 위치의 15% 를 무작위로 골라 예측 대상으로 삼고, 고른 토큰을 80% 는 [MASK] 로, 10% 는 무작위 토큰으로, 10% 는 그대로 둡니다 .

바꾸는 방법논문이 든 까닭
[MASK] 로무엇을 맞힐지 가린다
무작위 토큰으로[MASK] 는 미세조정 때 나오지 않아 사전학습과 어긋난다 — 늘 [MASK] 만 쓰지 않는다
그대로표현을 실제로 관찰한 단어 쪽으로 치우치게 한다

부록은 무작위 치환이 전체 토큰의 1.5%(15% 의 10%)에만 일어나 언어 이해를 해치지 않는 것으로 보인다고 덧붙입니다 .

읽을 때 주의 — 이 구현은 자리마다 따로 동전을 던지므로 고른 수가 줄마다 흔들립니다. 논문 문장만으로는 정확히 15% 개를 뽑는지 자리마다 뽑는지 정해지지 않습니다. 또 "아무 토큰" 은 원래 토큰이나 mask_id 자체가 뽑힐 수도 있어, 시험의 "그대로" 비율에는 작은 몫이 섞입니다.
실행 검증

손실 — 가린 자리의 행만 모은다

정답은 바꾼 입력 inp 가 아니라 원래 ids 입니다. "그대로" 둔 자리도 정답을 맞혀야 하므로 손실에 들어갑니다.

실행 검증

대가 — 줄 하나에서 얻는 신호가 적다

디코더는 길이 n 인 줄 하나에서 예측 n 개를 얻습니다(7부 8장). MLM 은 배치마다 토큰의 15% 만 예측하므로 수렴에 사전학습 스텝이 더 필요할 수 있다고 논문이 적습니다 . 부록 실험(미세조정한 MNLI 정확도)은 왼쪽→오른쪽 모델보다 조금 늦게 수렴하지만, 절대 정확도로는 거의 곧바로 앞선다고 답합니다 .

이 덱의 범위 — BERT 의 두 번째 사전학습 과제인 다음 문장 예측(NSP)과 문장 종류 임베딩은 구현하지 않았습니다. 파라미터 수만 7부에서 셌습니다.

혼합 정밀도 — 기법 셋

Micikevicius 외는 가중치·활성값·기울기를 반정밀도(FP16)로 두면서 FP32 학습의 정확도를 지키는 세 기법을 제안합니다 .

  • FP32 주 사본 — 옵티마이저는 단정밀도 가중치를 고치고, 순전파·역전파에는 그 반정밀도 사본을 씁니다. 학습률을 곱한 갱신이 너무 작으면 FP16 에서 0 이 되기 때문입니다 — 논문은 크기가 2−24 보다 작은 값이 FP16 에서 0 이 된다고 적습니다 .
  • 손실 스케일링 — 다음 장.
  • FP16 곱을 FP32 로 쌓기 — 합을 모으는 자리만 단정밀도로 둡니다 .
논문 근거

손실 스케일링 — 연쇄법칙을 빌린다

기울기 값은 대개 아주 작아 FP16 이 표현하는 범위 아래로 떨어집니다. 역전파 전에 손실에 상수를 곱하면 연쇄법칙 때문에 모든 기울기가 같은 배수로 커집니다. 가중치를 고치기 전에 다시 나누되, 기울기 자르기 같은 다른 처리보다 먼저 나누라고 권합니다 .

  • 배수는 곱한 최대 기울기가 FP16 의 최댓값 65,504 를 넘지 않게 고릅니다.
  • 논문이 학습한 여러 망에서는 8 부터 32K 까지의 배수를 썼습니다.
  • 넘침이 생기면 그 스텝의 갱신을 건너뛰면 됩니다.

이 덱의 기울기 자르기(SPEC §6.3)도 "나눈 뒤에 자른다" 는 차례를 따라야 문턱값 1.0 을 바꾸지 않아도 됩니다.

스케일링 법칙 (1) — Kaplan 외

Kaplan 외는 손실이 임베딩을 뺀 파라미터 수 N, 데이터 D, 계산량 C 각각에 대해 거듭제곱 법칙을 따른다고 적합했습니다 .

L(N) = (Nc/N)αN,   αN ≈ 0.076,   Nc ≈ 8.8×1013
  • 데이터에 대해서는 αD ≈ 0.095, Dc ≈ 5.4×1013 토큰, 최소 계산량에 대해서는 지수 약 0.050 입니다.

스케일링 법칙 (2) — Chinchilla

Hoffmann 외는 세 가지 방법으로 다시 추정해, 계산 예산이 늘 때 모델 크기와 학습 토큰 수를 대략 같은 비율로 늘려야 한다고 결론 냈습니다. N 의 지수가 방법마다 약 0.50·0.49·0.46 으로, Kaplan 의 0.73 과 다릅니다 .

Chinchilla 의 손실 적합식 읽기

L(N, D) = E + AN0.34 + BD0.28

적합값은 E = 1.69, A = 406.4, B = 410.7 입니다 .

거듭제곱 법칙은 여러 자릿수에 걸친 N·D·C 에서 점을 찍어야 보입니다. 이 덱의 모델은 접는 폰 한 대에서 몇 분 안에 끝나는 크기라, 한두 자릿수 안에서 찍은 점으로 지수를 말하면 오해를 부릅니다.

  • 그래서 이 장의 수는 전부 논문에서 옮긴 것이고, 출처는 deck/claims.md 에 있습니다.
  • 이 덱이 직접 확인한 것은 그 법칙의 재료입니다 — 파라미터 수와 6N 어림(7부).

5~6장 퀴즈

Q. 손실 스케일링에서 배수 S 를 곱한 채로 기울기 자르기(문턱 1.0)를 먼저 하고, 그다음 S 로 나누면 무엇이 달라집니까?

A. 자르기는 기울기 노름 n 이 문턱을 넘는지를 봅니다. S 배 된 기울기의 노름은 S·n 이라, 원래는 잘리지 않았을 기울기(n ≤ 1)도 S·n > 1 이면 잘립니다. 자른 뒤 S 로 나누면 노름이 1/S 가 되어 갱신이 거의 사라집니다. 결국 문턱을 S 배로 고쳐야 하는데, S 를 동적으로 바꾸면 문턱도 따라 바꿔야 합니다. 그래서 논문은 역전파 직후, 자르기 같은 다른 처리보다 먼저 나누라고 권합니다 — 그러면 다른 하이퍼파라미터를 건드릴 필요가 없습니다.
