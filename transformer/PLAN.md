# Transformer From Scratch (밑바닥부터_만드는_트랜스포머.html) — Work Plan for the Building Agent

> Audience of this file: the agent (Opus) that builds the deck. Written in English per the global
> language policy. The deck body itself is Korean (합니다체 in prose, as in the wireless deck).
> Progress log goes at the END of this file (append one entry per commit; never rewrite old entries).
>
> Output: `밑바닥부터_만드는_트랜스포머.html` at the repo root — a single-file slide deck cut from
> `template.html`. Hard cap **2000 slides** (user decision 2026-09-16); target band **1,400–1,800**.
> Lineage: `keycloak_ad/` → `compress/` → `wireless/` (assembler, checks, Makefile, svgkit, claims) and
> `optim/` (CSS math kit, pure-stdlib numerics). **Copy, don't reinvent.** Read `wireless/PLAN.md` §0–§2
> and the last three entries of its progress log once before starting: every rule below that looks
> pedantic was paid for there or in the compression deck.
>
> What "from scratch" means here: **no numpy, no torch, no library that hides a loop.** The reader sees
> every multiply. A pure-Python reference (`py/transformerlib/`) explains; a C99 rewrite (`c/`) trains
> real (small) models in minutes; the two check each other through a shared checkpoint format.

## 0. Non-negotiables (read twice)

1. **The deck HTML is a build artifact.** Never edit it by hand. Edit `transformer/deck/sections/*.html`
   or the sources they cite, then `make all`.
2. **No hand-written code, numbers or captures in the deck.** Every `<pre><code>` is a
   `<!--CODE file=… lines=A-B|sym=…-->` directive filled from a real file under `transformer/`. Every
   terminal capture is `<!--OUT file=…-->` from `transformer/out/`. Every table of measured numbers
   (loss, accuracy, perplexity, parameter counts, speed) is `<!--TABLE file=…-->` generated by
   `run_all.py`. `verify_deck.py` re-checks deck ↔ source on every build.
3. **Every formula has a witness.** A formula that yields a number or a gradient (softmax Jacobian,
   cross-entropy gradient, layer-norm backward, attention backward, Adam bias correction, the 1/√d
   variance argument, the KV-cache and online-softmax equivalences, parameter-count and FLOP formulas)
   must have a unit test in `py/transformerlib/tests/` that evaluates the code against the closed form
   or against central finite differences at a stated tolerance. Purely structural formulas
   (definitions, derivation steps) are exempt but must be marked `ill` (§6). No formula is typed twice:
   the deck cites the same symbol the test checks.
4. **Every fact has a source.** Dates, paper ids, model sizes, hyper-parameters quoted from papers
   (d_model 512, warmup 4000, BLEU 28.4, 124M…) go in `deck/claims.md` as
   `claim | source | verified-how | date` **before** they appear on a slide. Sources in order of
   preference: the paper itself (arXiv id + section/table, text fetched into `papers/` with
   `tools/paper_text.py` and quoted from there — see §2), an official model card or repository README,
   then a Wikipedia article **with its own citation followed**. A claim that cannot be sourced is
   either dropped or marked `<span class="unv">미확인</span>`.
5. **Knowledge-cutoff discipline.** Anything dated 2025 or later (newest models, parameter counts,
   context lengths, "state of the art") must be re-verified with WebSearch at build time and written
   with an explicit "2026-09 기준" stamp. Part 1's "오늘" slides are the only place such things belong;
   the rest of the deck teaches the 2017–2023 canon that does not move.
6. **Tests before code (RED → GREEN)** for every module in `py/` and every kernel in `c/`. Never loosen
   a tolerance to pass. If a stated witness turns out to be false (the wireless deck hit three), rewrite
   the test to state the property that *is* true and say why in its docstring.
7. **This machine is a Galaxy Fold under Termux/proot with ~600 MB free RAM and a full swap.** At most
   **2 subagents**, no JVM, **no numpy/scipy/torch** (pip could install numpy — do not; §9 decision 2).
   C training runs are sized to finish in ≤ 3 min each, `run_all.py` in ≤ 25 min total, and run
   strictly sequentially. Check `free -m` before heavy steps. Checkpoint everything to disk; assume
   the session can be killed any moment. Long runs go in the background with a Monitor.
8. **Foldable layout.** `<pre>` ≤ 45 lines and ≤ 72 columns (Korean counts as 2), captures ≤ 108
   columns, `<li>` ≤ 14 per list, no box-drawing characters in prose, no `①②③` inside monospace,
   formulas set with the CSS math kit (§4) — never as ASCII art, never as images of text.
   SVG figures use `viewBox` width 340 so they fit 374 px. The assembler errors on all of these.
9. **Determinism is evidence.** Every number in `out/` must be identical across three runs
   (`tools/record.sh --check`, md5). Both implementations use the PRNG specified in `SPEC.md`
   (xoshiro256** seeded by splitmix64; Gaussian by Box–Muller in a fixed order). C is compiled with
   `-O2 -std=c99 -ffp-contract=off -fno-fast-math`; if threads are used, work is statically
   partitioned so each output element is computed by exactly one thread in a fixed order, and a test
   proves the 1-thread and N-thread checkpoints are byte-identical. No wall-clock numbers anywhere in
   prose; speed tables are cited from `out/` and the prose points at the table.
10. **Corpus is public domain and committed.** Korean texts come from ko.wikisource.org works whose
    authors died before 1956 (김소월 1934 · 한용운 1944 · 윤동주 1945 · 현진건 1943 · 이상 1937 ·
    김유정 1937), each with page URL + revision id in `corpus/SOURCES.tsv`. Synthetic tasks are
    generated by a seeded script. No web-scraped modern text, no model-generated text as training data.
11. **Commit granularity:** one module, one kernel batch, one figure batch, or one deck part per commit;
    split "source commit" from "deck-body commit". Korean, no-prefix commit subject (repo convention),
    `Co-Authored-By` trailer per the session reminder. Never `git push` unless asked.
12. Keep Korean comments in code (UTF-8, no BOM), 72 columns. Identifiers in English. Do not touch
    other decks. Big writes are ≤ 250 lines each (append for more); the deck must open at every commit.

## 3. What gets written

### 3.0 `SPEC.md` — the contract between Python and C (write first, tests cite it)

- **RNG:** splitmix64(seed) → 4 × u64 state → xoshiro256**; `uniform()` = top 53 bits / 2⁵³;
  `normal()` = Box–Muller using two uniforms in a fixed order, both outputs consumed (no caching
  differences between the two languages). Python implements it with masked ints. Test: first 8
  outputs for seed 42 are pinned in both test suites (same constants in `tests/test_rng.py` and
  `c/tests/test_rng.c`).
- **Checkpoint `.ckpt`:** magic `TFS1`, header of little-endian int32s (vocab, ctx, d_model, n_layer,
  n_head, d_ff, flags: tied-embedding, pos-encoding kind), then float32 arrays in a fixed order
  (wte, wpe, per block: ln1_g ln1_b Wqkv bqkv Wo bo ln2_g ln2_b W1 b1 W2 b2, then lnf_g lnf_b).
  Row-major, weights stored as `[in, out]`. Optimizer state (`m`, `v`, step) in a separate `.opt`.
- **Vocab `.vocab`:** line-based, `id<TAB>hex-bytes`; merges `.merges`: `left<TAB>right` in rank
  order. Byte-level BPE with a **specified** pre-tokenizer (split into runs of: whitespace with the
  following word, letters, digits, other — using explicit byte/char classes, no regex properties).
- **Tokens `.bin`:** uint16 little-endian ids. Python and C must produce byte-identical `.bin` for the
  whole corpus (integer artifact — exact match, like the compression deck's golden files).
- **Model:** GPT-style decoder: token + position embedding (learned; sinusoidal and RoPE as options
  behind `flags`), pre-LN blocks, causal multi-head attention, GELU (tanh approximation, exact
  constants pinned) FFN ×4, final LN, tied output projection. Dropout exists in Python and is tested,
  but every recorded run uses p = 0 so parity holds.
- **Training step:** cross-entropy over all positions, AdamW (β1 0.9, β2 0.95, ε 1e-8, wd 0.1 on
  matrices only), gradient-norm clipping 1.0, warmup + cosine schedule. Batches are drawn with the
  shared RNG so both implementations see the same data.
- **Parity tolerances (float64 Python vs float32 C):** logits ≤ 1e-4 relative, gradients ≤ 1e-3
  relative, loss after 20 identical steps ≤ 1e-3 absolute. Longer runs are compared by *trend* only.

### 3.1 `py/transformerlib/` — pure Python, in this order (one commit each, tests first)

| # | Module | Content | Witness test (formula ↔ code) |
|---|---|---|---|

| 4 | `ops` | softmax (stable), log-softmax, cross-entropy (fused), layernorm, gelu (tanh), embedding lookup, dropout(rng), causal mask | softmax Jacobian `diag(p) − ppᵀ`; CE gradient = `p − y` exactly; layernorm backward vs FD; gelu'(0) = 0.5 |
| 5 | `tokenizer` | char-level, byte-level, BPE train/encode/decode per SPEC | round-trip on every corpus file; merges deterministic; Korean syllable = 3 bytes; `.bin` equals C's |

## 4. Formula policy (senior-undergraduate level)

Derive, don't decorate. Each of the following gets a short derivation box (`.thm`/`.proof`), the
symbols defined once on the notation slide in part 0, and a witness in §3.1:

chain rule and Jacobian-vector products (why backward multiplies from the left) · softmax and its
Jacobian · log-sum-exp stability shift · cross-entropy gradient `p − y` · layer-norm backward ·
matmul backward `dW = Xᵀ dY`, `dX = dY Wᵀ` · broadcasting backward = sum over broadcast axes · the
1/√d scaling (variance of a dot product of d independent unit-variance terms) · causal masking as
−∞ before softmax · multi-head as a block-diagonal projection · sinusoidal encoding and its linear
shift property · RoPE relative-position property · residual stream as a sum of block outputs · pre-LN
vs post-LN gradient path · parameter count `12·L·d² + …` and the GPT-2 124M reconstruction · FLOPs
≈ 6·N per token (forward 2N, backward 4N) · attention cost `O(n²·d)` vs FFN `O(n·d²)` and the
crossover · Adam update and bias correction · AdamW decoupling · gradient clipping · warmup-cosine ·
perplexity = exp(mean NLL) · KV-cache equivalence · online softmax (running max and rescaled sum) ·
LoRA rank-r update · top-p as a prefix of the sorted CDF.

Level check: linear algebra, multivariable calculus and basic probability at 4th-year CS/EE; no
measure theory, no convergence proofs for Adam (say so, cite). Every formula is set with the CSS math
kit; a formula longer than the 374 px fold is split across lines with `.eq` blocks, never scrolled.

  `out/parity_tokens.txt`), committed before any C kernel beyond rng, so each C test was RED on
  values. TFX1 = named float64 arrays (binary; C reads with fread). Model fixtures are computed from
  the float32 values re-read from the checkpoint C will load. The greedy fixture first used a seed
  whose continuation was all zeros — a witness that checks nothing; switched to seed 9.
- C tests use `c/tests/check.h` (counts failures, never aborts). `make test` = `test-py` + `test-c`;
  `test-c` builds `c/tfs` first. **8 C test files, 561 checks.**
- Results: rng bit-identical to Python (incl. `normal()` via glibc); matmul ijk/ikj/blocked agree to
  the bit (each (i, j) adds k in increasing order) — the bench table compares only time; tokenizer
  `.bin` byte-identical for all 45 corpus files on the first run; model logits/loss ≤ 1e-4 and
  1-thread vs 3-thread gradients bit-identical for learned/sin/rope; train: 20-step loss within
  1e-3 of Python, `lr_schedule` equal with `==`, 1 vs 4 threads bit-identical weights; sample: KV
  logits ≤ 1e-5 of batch forward, greedy continuation equal to Python token-for-token.
- **SPEC §9 corrected** after the first C model run failed 8 gradient checks. Not a backward bug:
  (a) the key-bias gradient is exactly 0 in theory (a common shift of every key moves a whole score
  row; softmax is invariant; RoPE breaks it) — Python 1e-16 vs C 1e-7 float32 noise; (b) cells built
  from cancelling O(1) terms carry ~3e-6 absolute float32 roundoff. New per-cell criterion:
  `|a−b| ≤ 1e-3·|b| + 1e-5·max|b|`. A pure tensor-scale metric was rejected because it would let a
  small cell be entirely wrong. New Python witness: key-bias gradient ≈ 0 for learned/sin, not rope.
- Deviations from §3.2's file list: `c/pool.c` (persistent pthread pool, static partition
  `[n·t/P, n·(t+1)/P)`, chunk 0 on the caller) so every kernel shares one partition rule; checkpoint
  read/write lives in `model.c` (the model test loads checkpoints before train.c exists).
- Probe for step 7: `tfs train` on add (V 13, T 16, d 48, L 2, h 4, B 32, 8 threads) runs 50 steps in
  about 3 s on this machine (not a deck number; recorded here only to size runs).
