이 책은 무엇인가

최적화는 “가장 좋은 것을 고르는 일”을 수학으로 옮긴 분야다. 학습률을 정하는 일도, 배송 경로를 짜는 일도, 공정의 병목을 찾는 일도 결국 같은 문제의 다른 얼굴이다.

✔ 이 책이 하는 것
  • 정리를 끝까지 증명한다 — “알려져 있다”로 넘어가지 않는다
  • 모든 알고리즘을 순수 파이썬으로 처음부터 만든다
  • 수렴 속도를 실제로 측정해 이론과 대조한다
  • 실패하는 경우를 일부러 만들어 왜 실패하는지 본다
✘ 이 책이 하지 않는 것
  • 솔버 API 사용법 나열 — 그건 문서를 보면 된다
  • 검증하지 않은 의사코드
  • “직관적으로 자명하다”로 끝내는 설명
  • 측정 없이 “빠르다”고 주장하기
한 줄 요약 — 이 책은 최적화 알고리즘을 스스로 만들어 낼 수 있게 하는 것이 목표다. 고르는 법이 아니라 만드는 법이다.

누구를 위한 책인가

컴퓨터공학 4학년, 혹은 그 정도의 배경을 가진 개발자를 상정했다. 구체적으로는 이런 사람이다.

가정하지 않는 것 — 실해석학, 측도론, 함수해석, 볼록해석 강의를 들었을 필요가 없다. 필요한 도구는 그때그때 세워서 쓴다. 라그랑주 승수를 “배운 적 있는 공식”이 아니라 유도해서 얻는 것으로 다룬다.

이 책이 답하는 질문들

  1. 경사하강법은 왜 수렴하는가? 얼마나 빨리? 그 속도를 무엇이 결정하는가?
  2. 학습률을 크게 잡으면 왜 발산하는가? 안전한 상한은 정확히 얼마인가?
  3. 모멘텀은 왜 빠른가? “관성” 말고 수식으로 설명할 수 있는가?
  4. 볼록이면 왜 국소 최소가 전역 최소인가?
  5. 라그랑주 승수는 어디서 나온 물건인가? 그 값은 무엇을 뜻하는가?
  6. 쌍대 문제는 왜 항상 볼록인가? 언제 원문제와 값이 같아지는가?
  7. 심플렉스법은 왜 꼭짓점만 봐도 되는가?
  8. 정수 제약 하나가 왜 문제를 NP-난해로 만드는가?
  9. SGD 는 잡음이 있는데 왜 답에 가까워지는가?
  10. Adam 은 무엇을 적응시키는가? 언제 실패하는가?
  11. 라쏘는 왜 계수를 정확히 0 으로 만드는가?
  12. 이벤트 로그에서 프로세스 모델을 어떻게 뽑아내는가?
  13. “이 로그가 이 모델에 얼마나 맞는가”를 재는 일이 왜 최적화 문제인가?
  14. 공정의 병목을 데이터만으로 어떻게 찾아내는가?
  15. 내 문제를 어떤 종류의 최적화 문제로 정식화해야 하는가?

읽는 법 — 세 겹으로 되어 있다

① 수식과 증명

정리는 보라색 상자, 증명은 회색 상자에 들어 있다. 증명의 각 줄에는 무엇을 근거로 그 줄이 나왔는지가 적혀 있다.

② 코드

모든 코드는 optim/py/ 안의 실제 파일에서 그대로 읽어 온 것이다. 손으로 옮겨 적은 코드는 이 책에 한 줄도 없다.

③ 실행 결과

검은 터미널 화면은 실제로 그 명령을 돌려서 나온 출력이다. 숫자를 지어내지 않았다.

상자 색의 뜻 정리·명제는 증명이 뒤따르는 주장 · 보조정리·따름정리는 다른 증명의 부품 · 정의는 용어를 세우는 곳 · 참고는 흔한 오해를 바로잡는 곳이다.
증명을 건너뛰어도 좋다 — 처음 읽을 때는 정리의 진술과 코드만 따라가도 된다. 다만 “왜 이 조건이 붙어 있지?”가 궁금해지는 순간이 오는데, 그 답은 대부분 증명 안에 있다.

코드 규약 — 왜 numpy 를 쓰지 않는가

이 책의 예제는 파이썬 표준 라이브러리만 쓴다. 행렬은 리스트의 리스트, 벡터는 리스트다.

✔ 그래서 얻는 것
  • LU 의 피벗팅이 왜 필요한지가 코드에 그대로 보인다
  • 촐레스키가 어디서 실패하는지를 직접 만난다
  • 설치 없이 어떤 파이썬에서도 돌아간다
  • 알고리즘의 비용이 눈에 보인다 — 숨은 C 루프가 없다
✘ 그래서 잃는 것
  • 속도. 실무에서 n이 10⁴ 이 넘으면 numpy·BLAS 를 써야 한다
  • 희소행렬 자료구조의 정교함
  • 검증된 LAPACK 루틴의 수치 안정성

14부에서 “언제 직접 짜고 언제 솔버를 부를 것인가”를 따로 다룬다.

예제를 돌려 보는 법

$ cd optim $ PYTHONPATH=. python3 py/demo_linalg.py $ python3 -m unittest discover -s tests -t . -v # 덱 다시 만들기 (소스를 고쳤다면) $ python3 run_all.py && python3 deck/build_deck.py

이 책의 코드가 진짜라는 증거

교재의 코드가 실제로 돌아가지 않는 일은 너무 흔하다. 그래서 이 책은 구조적으로 그럴 수 없게 만들었다.

최적화 한 장 요약

이 책에 나오는 거의 모든 알고리즘은 아래 골격의 변주다. 어디가 달라지는지만 보면 된다.

반복형 최적화의 공통 골격
  1. 시작: 초기점 x0 를 고른다
  2. 반복 k = 0, 1, 2, …
    1. 방향 dk 를 정한다  — 여기가 알고리즘의 정체다
    2. 보폭 αk > 0 을 정한다  — 고정 / 라인서치 / 신뢰영역
    3. 이동: xk+1 = xk + αkdk
  3. 종료: ‖∇f(xk)‖ ≤ ε 이거나 더 나아지지 않을 때
알고리즘방향 dk드는 정보부
경사하강−∇f기울기3
뉴턴−(∇²f)−1∇f기울기 + 헤세3
준뉴턴(BFGS)−Bk−1∇f기울기 이력3
켤레기울기−∇f + βkdk−1기울기3
SGD−∇fi (표본 하나)기울기 일부8
근접경사경사 후 prox 투영기울기 + 근접연산자8
심플렉스인접 꼭짓점으로의 모서리기저 교환6

프로세스 마이닝은 왜 이 책에 있는가

프로세스 마이닝은 “실제로 무슨 일이 어떤 순서로 일어났는가”를 기록(이벤트 로그)에서 되짚어 내는 분야다. 언뜻 최적화와 무관해 보이지만, 핵심 계산이 전부 최적화 문제다.

프로세스 마이닝의 질문실제로 푸는 최적화 문제이 책의 어디
로그와 모델이 얼마나 맞는가 (적합도)최소비용 정렬 — A* 최단경로 / ILP11부 · 7부의 분지한정
어떤 모델이 로그를 가장 잘 설명하는가구조 제약 아래의 조합 탐색10부 · 7부
어디가 병목인가대기시간 최대화 구간 탐색 · 큐 모형12부
자원을 어떻게 배치해야 하는가할당 문제 — 헝가리안 / 최소비용흐름12부 · 7부
케이스를 어떤 순서로 처리할 것인가스케줄링 — 정수계획13부
이 책의 논지 — 프로세스 마이닝은 “로그 분석 도구 모음”이 아니라, 이산 최적화가 현실 데이터를 만나는 자리다. 그래서 1~9부를 읽은 사람에게는 10~12부가 새로운 응용으로 읽힌다.
