민지의 문제

민지는 4학년 인턴이다. 학교 IT팀에서 학식 예약 앱을 하나 맡았다. 쿠버네티스에는 이미 올라가 있다. 그런데 팀장이 이렇게 말한다.

“회원가입 화면은 지우세요. 학교 계정으로 로그인하게 하면 됩니다.”

민지는 여기서 막힌다. 학교 계정은 어디에 있나? 그걸 어떻게 물어보나? 비밀번호를 우리 앱이 받아도 되나? 로그아웃은 어디서 하나? 그리고 이 모든 게 쿠버네티스 안에서 어떻게 돌아가나?

이 덱이 하는 일 — 그 질문 전부에 답한다. 답은 Keycloak이라는 이름의 통역사 하나와, 그 통역사가 학교의 계정 창고인 Active Directory와 나누는 대화다. 그 대화를 바이트 단위까지 열어 본다.

전체 그림은 다음 장에 있다. 지금 다 이해할 필요는 없다.

전체 그림 — 상자 여섯 개

이 덱이 끝날 때 민지가 손으로 그릴 수 있어야 하는 그림이다. 부(部)마다 이 그림이 다시 나오고, 그 부에서 새로 등장한 상자에 색이 켜진다.

세 개의 세션 — 이 덱에서 가장 헷갈리는 것

“로그아웃했는데 왜 아직 로그인돼 있죠?” 라는 질문의 답은 전부 여기 있다. 로그인 상태는 하나가 아니라 셋이다. 이름과 색을 지금 정해 두고 끝까지 그대로 쓴다.

이름누구와 누구 사이실제 물건
A브라우저 ↔ Keycloak민지와 프런트 Keycloak 이 심은 쿠키(KEYCLOAK_IDENTITY)
B브라우저 ↔ 앱민지와 학식 예약 앱이 심은 자기 쿠키
C앱 ↔ Keycloak학식 예약과 프런트 토큰(ID·액세스·리프레시)
왜 셋인가 — 앱에서 로그아웃해도 A 가 살아 있으면, 다시 로그인 단추를 눌렀을 때 Keycloak 이 비밀번호를 다시 묻지 않고 바로 통과시킨다. 그게 SSO(한 번 로그인하면 여러 앱이 통과)의 정체이자, 동시에 가장 흔한 민원의 정체다. 셋을 각각 어떻게 끊는지는 8부와 10부에서 다룬다.

이 덱이 쓰는 비유 — 끝까지 바뀌지 않는다

새 용어가 나올 때마다 비유 → 그림 → 진짜 바이트 순서로 간다. 비유는 여기 적은 것만 쓴다. 중간에 다른 비유로 갈아타지 않는다.

비유진짜기억할 한 가지
기숙사 출입 신청서 · 답변HTTP 요청 · 응답한 번 주고받으면 끝. 서로를 기억하지 않는다

세 가지 물건(열쇠 🔑 비밀번호 · 카드키 💳 토큰 · 손목밴드 🎗 쿠키)은 서로 다른 것이다. 이 셋을 섞지 않는 것이 4부의 핵심이다.

인증과 인가 — 소리는 비슷하고 뜻은 다르다

인증 (認證, authentication)

네가 누구인지 확인하는 일.
“민지 맞습니까?”

호텔 프런트에서 신분증을 보이는 순간.
이 덱에서는 AD 가 답한다.

인가 (認可, authorization)

무엇을 해도 되는지 정하는 일.
“민지가 관리자 화면을 봐도 됩니까?”

카드키가 어느 층을 여는가.
이 덱에서는 AD 그룹이 답한다.

영문 약자 주의 — 둘 다 auth 로 줄여 쓴다. 그래서 authn(인증)과 authz(인가)로 구분해 적는 관례가 있다. 이 덱은 본문에서는 항상 한국어로 인증·인가라고 쓰고, 설정 파일에 나오는 영문은 그때마다 어느 쪽인지 밝힌다.

순서도 정해져 있다. 인증이 먼저, 인가가 나중이다. 누구인지 모르는 사람에게 무엇을 허용할지 정할 수는 없다. 1~7부가 인증 이야기고, 9부가 인가 이야기다.

근거 등급 — 이 덱의 정직성 계약

기술 문서가 사람을 가장 크게 배신하는 순간은 돌려 보지 않은 코드를 돌려 본 것처럼 적어 놓았을 때다. 그래서 코드나 출력이 실린 화면마다 배지를 하나씩 달아, 우리가 어디까지 확인했는지 밝힌다.

배지뜻믿어도 되는 정도
실행 검증 이 기계에서 실제로 돌렸고, 그 출력을 out/ 에 남겼다 그대로 복사해 써도 된다
구문 검증 여기엔 쿠버네티스 클러스터가 없어 돌리지는 못했다. 대신 진짜 도구 (kubectl·kubeconform)가 문법과 스키마를 통과시켰다 문법은 맞다. 값은 당신 환경에 맞춰야 한다
문서 근거 돌려 보지 못했다. 제품 공식 문서나 RFC 에서 읽은 것이며, 출처 URL 이 deck/claims.md 에 있다 참고만. 반드시 당신 환경에서 확인할 것
예제용 화면에 보이는 비밀번호·인증서·시크릿이 가짜라는 표시 절대 실제로 쓰지 말 것
C 등급은 10%를 넘지 않는다 — 그리고 “당신이 복사해 붙여 넣을 것”에는 절대 붙이지 않는다. C 등급이 붙는 자리는 화면 캡처를 대신한 설명, 다른 제품과의 비교, 우리가 흉내 내지 않은 기능 같은 것들이다.

등장인물과 이름 — 전부 지어낸 것이다

실제 회사·학교·사람 이름은 한 번도 나오지 않는다. 대신 아래 이름을 끝까지 쓴다. 직접 따라 할 때는 campus.example 자리에 당신의 도메인을 넣으면 된다.

것이 덱에서의 이름

화면에 나오는 조각의 종류

  • 파일 이름 + 줄 번호가 붙은 코드 — 이 저장소의 진짜 파일에서 잘라 온 것이다. 손으로 옮겨 적은 코드는 이 덱에 하나도 없다.
  • 검은 바탕 출력 — 실제로 돌려서 받은 출력 그대로다.
  • 노란 테두리 상자 — 직접 만져 보는 데모다. 브라우저 안에서 돈다.
  • 보라 테두리 상자 — 용어 카드. 새 낱말이 처음 나올 때 붙는다.
  • 초록 접힌 상자 — 퀴즈. 답 보기를 누르기 전에 먼저 생각해 볼 것.
덮어 놓고 순서대로 — 앞 장이 유일한 준비물이다. JSON·base64·해시·공개키 서명·YAML 처럼 필요한 도구는 전부 1부에 한 장씩 있다. 아는 부분은 건너뛰어도 되지만, 모르는 것이 나오면 앞으로 돌아가면 된다.

시작하기 전에 — 준비물

덱을 읽기만 한다면 준비물은 없다. 코드를 따라 돌려 보려면 아래가 필요하다. 없어도 괜찮다 — 모든 출력은 이미 캡처돼 실려 있다.

1부

웹이 돌아가는 법

주소 한 줄을 치면 무슨 일이 일어나는가 — HTTP·쿠키·리다이렉트·TLS, 그리고 도구 상자

1부에서는 브라우저 하나만 켜진다

이 부에서 다루는 것

  • URL 과 DNS — 이름이 주소가 되는 과정
  • HTTP 요청과 응답을 한 줄씩 읽기
  • 상태 코드 · 리다이렉트 · 폼 전송
  • 쿠키와 세션 — 서버가 나를 기억하는 법
  • TLS/HTTPS — 남이 못 읽게 하는 것과 상대를 확인하는 것
  • 도구 상자: JSON · base64url · 해시 · 공개키 서명 · YAML
끝나면 — curl -v 기록을 읽고, 쿠키 하나가 어떻게 로그인 상태가 되는지 설명한다.
여기서 만드는 것 — 웹 서버 넷을 Go 표준 라이브러리만으로 직접 짠다. 01_hello(가장 작은 서버) → 02_form_cookie(로그인) → 03_redirect(옮겨 다니기) → 04_tls(자물쇠). 4부의 Keycloak 이 하는 일이 이 넷의 조합이다.

기억하지 않는다(stateless) — 이 한 가지가 이 덱 전체의 출발점이다. 서버는 방금 온 사람과 지금 온 사람이 같은 사람인지 모른다. 그래서 6장에서 손목밴드(쿠키)를 채우게 되고, 4부에서는 그 손목밴드를 남의 건물(Keycloak)에서 받아 오게 된다.

이름을 번호로 — DNS

컴퓨터끼리는 이름이 아니라 번호로 찾아간다. sso.campus.example 같은 이름을 10.1.2.3 같은 번호로 바꿔 주는 것이 DNS(Domain Name System)다.

DNS — 전화번호부다. "김민지" 를 대면 번호를 알려 준다. 브라우저는 요청을 보내기 전에 반드시 한 번 물어본다.
이 덱에서 DNS 가 문제가 되는 곳어디서

클러스터 안에서는 keycloak.sso.svc.cluster.local 같은 이름이 따로 있다2부·6부
실습에서는 DNS 없이 curl --resolve 이름:포트:번호 로 대신한다7장
왜 이름을 쓰나 — 번호는 바뀐다. 서버를 옮기면 번호가 바뀌지만 이름은 그대로 둘 수 있다. 그리고 인증서는 이름에 발급된다(7장) — 번호로 접속하면 자물쇠가 깨지는 이유가 그것이다.

1장 퀴즈

Q. https://sso.campus.example/auth 로 접속했는데 "인증서가 유효하지 않습니다" 가 떴다. 서버를 https://10.1.2.3/auth 로 번호를 직접 쳐서 들어가면 이 오류가 사라질까?

A. 아니다. 오히려 더 확실히 실패한다. 인증서는 이름에 발급된다. 번호로 접속하면 브라우저는 "내가 부른 이름이 10.1.2.3 인데 인증서에는 sso.campus.example 이라고 적혀 있다" 며 거절한다. 7장에서 이 실패를 실제로 만들어 본다.

요청 한 통의 생김새

HTTP 요청은 글자다. 암호도 이진수도 아니다. 줄 몇 개를 순서대로 늘어놓은 것이 전부다.

// logging 은 들어온 요청 한 줄을 터미널에 남긴다. 이렇게 다른 처리기를
// 감싸는 것을 미들웨어라고 부른다 — 8부에서 이 자리에 "로그인했는지
// 확인" 을 끼워 넣게 된다. 지금은 그 자리만 만들어 둔다.
func logging(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter,
		r *http.Request) {
		log.Printf("%s %s", r.Method, r.URL.RequestURI())
		next.ServeHTTP(w, r)
	})
}
실행 검증

// requestDump 는 요청 하나를 사람이 읽는 여러 줄로 옮긴다.
//
// 헤더는 지도(map)라 Go 가 돌 때마다 순서를 바꾼다. 그대로 찍으면 같은
// 요청도 매번 다르게 보여서, 캡처를 두 번 떠 비교하는 검사를 통과할 수
// 없다. 그래서 이름순으로 정렬한다. 시간 O(n log n), 공간 O(n) — n 은
// 헤더 수.
func requestDump(r *http.Request) string {
	var b strings.Builder

	// 첫 줄은 요청 줄(request line): 방법 · 주소 · 규약 판번호
	fmt.Fprintf(&b, "%s %s %s\n", r.Method, r.URL.RequestURI(), r.Proto)

	// Host 는 헤더인데도 Go 가 r.Header 에서 빼서 r.Host 에 따로 담아
	// 둔다. 다시 넣어 주지 않으면 캡처에서 Host 줄만 통째로 사라진다.
	fmt.Fprintf(&b, "Host: %s\n", r.Host)

	names := make([]string, 0, len(r.Header))
	for name := range r.Header {
		names = append(names, name)
	}
	sort.Strings(names)
	for _, name := range names {
		for _, v := range r.Header[name] {
			fmt.Fprintf(&b, "%s: %s\n", name, v)
		}
	}
	return b.String()
}
왜 정렬하나 — 헤더는 지도(map)라 Go 가 돌 때마다 순서를 바꾼다. 그대로 찍으면 같은 요청도 매번 다르게 보여서, "두 번 돌려 같은지" 로 캡처를 검사하는 이 덱의 규칙을 통과할 수 없다.

Host 는 왜 따로 있는가

헤더인데도 Go 는 Host 만 따로 빼서 다른 자리에 담는다. 초심자가 가장 자주 걸려 넘어지는 자리다.

설명용
가상 호스트 — 컴퓨터 하나에 사이트가 여럿 있을 수 있다. 번호는 하나인데 이름이 여럿인 것이다. 그래서 요청은 "나는 어느 이름으로 왔다" 를 Host 헤더로 알린다.
6부의 복선 — Keycloak 이 자기 주소를 만들 때 이 Host 를 본다. 클러스터 안에서 keycloak:8080 으로 불리는데 바깥 사용자에게는 sso.campus.example 로 답해야 하므로, KC_HOSTNAME 과 프록시 헤더 설정이 필요해진다. "로그인 눌렀더니 내부 주소로 튕겼다" 는 민원의 정체가 이것이다.

3장 퀴즈

Q. 학식 예약 앱이 갑자기 502 Bad Gateway 를 낸다. 사용자에게 "로그인을 다시 해 보세요" 라고 안내하는 것이 맞을까?

web/03_redirect/main.go24–50movable 과 redirectCode
// 옮기라는 뜻으로 쓸 수 있는 번호는 이 다섯뿐이다.
//
//	301 Moved Permanently   아주 바뀌었다. 브라우저가 기억해 버린다
//	302 Found               지금만 저기다. 가장 흔하다
//	303 See Other           "그 결과는 저기 있으니 GET 으로 가라"
//	307 Temporary Redirect  302 인데, 방법과 본문을 그대로 들고 간다
//	308 Permanent Redirect  301 인데, 방법과 본문을 그대로 들고 간다
//
// 300(여러 후보)과 304(안 바뀌었다)는 3으로 시작하지만 옮기라는 뜻이
// 아니다.
var movable = map[int]bool{
	301: true, 302: true, 303: true, 307: true, 308: true,
}

// redirectCode 는 ?code= 값을 검사한다. 아무 번호나 그대로 내보내면
// 브라우저마다 다르게 굴어서 무엇을 배우는 화면인지 알 수 없게 된다.
func redirectCode(s string) (int, bool) {
	if s == "" {
		return http.StatusFound, true // 안 적으면 302
	}
	n, err := strconv.Atoi(s)
	if err != nil || !movable[n] {
		return 0, false
	}
	return n, true
}

func readAndCount(r *http.Request) (int, error) {
	if r.Body == nil {
		return 0, nil
	}
	defer r.Body.Close()
	buf := make([]byte, 4096)
	total := 0
	for {
		n, err := r.Body.Read(buf)
		total += n
		if err != nil {
			return total, nil
		}
	}
}

// 있게 열 번째에 멈춘다. 진짜 무한 고리였다면 curl 은 --max-redirs 로,
// 브라우저는 "너무 많이 이동했습니다" 로 스스로 끊는다.
func handleLoop(w http.ResponseWriter, r *http.Request) {
	n, _ := strconv.Atoi(r.URL.Query().Get("n"))
	if n >= 10 {
		w.Header().Set("Content-Type", "text/plain; charset=utf-8")
		fmt.Fprintf(w, "%d번 돌고 멈췄습니다.\n", n)
		return
	}
	next := fmt.Sprintf("/loop?n=%d", n+1)
	http.Redirect(w, r, next, http.StatusFound)
}

// checkPassword 는 아이디와 비밀번호를 맞춰 본다.
//
// subtle.ConstantTimeCompare 를 쓰는 이유: 보통의 == 는 글자가 처음
// 어긋나는 자리에서 바로 끝난다. 그래서 "앞 세 글자가 맞았을 때"가 "첫
// 글자부터 틀렸을 때"보다 아주 조금 더 오래 걸린다. 그 차이를 수만 번
// 재면 비밀번호를 한 글자씩 알아낼 수 있다. 이 함수는 길이가 같으면
// 언제나 끝까지 다 본다.
func checkPassword(user, pass string) bool {
	want, ok := demoUsers[user]
	if !ok {
		// 없는 아이디여도 시간을 비슷하게 쓴다 — 아이디가 있는지
		// 없는지가 응답 속도로 새어 나가지 않게.
		subtle.ConstantTimeCompare([]byte(pass), []byte(pass))
		return false
	}
	return subtle.ConstantTimeCompare([]byte(pass), []byte(want)) == 1
}

왜 == 로 비교하면 안 되나 — 보통의 문자열 비교는 글자가 처음 어긋나는 자리에서 바로 끝난다. 그래서 "앞 세 글자가 맞았을 때" 가 "첫 글자부터 틀렸을 때" 보다 아주 조금 더 오래 걸린다. 그 차이를 수만 번 재면 비밀번호를 한 글자씩 알아낼 수 있다. subtle.ConstantTimeCompare 는 길이가 같으면 언제나 끝까지 다 본다.

web/02_form_cookie/main.go67–88newSessionID 와 create
// newSessionID 는 아무도 찍어 맞힐 수 없는 번호를 만든다.
//
// crypto/rand 다. math/rand 가 아니다 — 그쪽은 씨앗을 알면 다음 값을
// 계산할 수 있어서, 남의 세션 번호를 만들어 낼 수 있다. 16바이트를
// 16진수로 적으면 32글자가 되고, 경우의 수는 2^128 이다.
func newSessionID() string {
	b := make([]byte, 16)
	if _, err := rand.Read(b); err != nil {
		// 운영체제의 난수원이 죽었다면 더 할 수 있는 일이 없다
		panic(err)
	}
	return hex.EncodeToString(b)
}

func (s *store) create(user string) string {
	id := newSessionID()
	s.mu.Lock()
	defer s.mu.Unlock()
	s.rows[id] = session{user: user, dies: s.now().Add(s.life)}
	return id
}
실행 검증
math/rand 를 쓰면 안 된다 — 그쪽은 씨앗(seed)을 알면 다음 값을 계산할 수 있다. 남의 세션 번호를 만들어 낼 수 있다는 뜻이다. crypto/rand 는 운영체제의 난수원에서 가져온다.
16바이트 = 32글자 = 2128 가지 — 찍어서 맞힐 수 있는 수가 아니다. 4부의 state·nonce· 인가 코드도 전부 같은 방식으로 만든다.

수명이 지난 밴드

web/02_form_cookie/main.go89–110get 과 remove — 살아 있는 것만 돌려준다
// get 은 살아 있는 세션만 돌려준다. 시간이 지난 줄은 지도에 남아 있어도
// 없는 것으로 친다 — 그리고 지나는 김에 치운다.
func (s *store) get(id string) (session, bool) {
	s.mu.Lock()
	defer s.mu.Unlock()
	row, ok := s.rows[id]
	if !ok {
		return session{}, false
	}
	if !s.now().Before(row.dies) {
		delete(s.rows, id)
		return session{}, false
	}
	return row, true
}

func (s *store) remove(id string) {
	s.mu.Lock()
	defer s.mu.Unlock()
	delete(s.rows, id)
}
실행 검증

공인 CA 와 사내 CA — 인터넷 사이트는 기기에 미리 들어 있는 공인 CA 가 서명한다. 회사·학교의 도메인 컨트롤러는 대개 사내 CA 가 서명하는데, 그 CA 는 아무 기기에도 미리 들어 있지 않다. 그래서 "이 CA 를 믿어라" 고 따로 알려 줘야 한다 — 7부의 truststore 가 하는 일이 정확히 이것이다.

server_cert() {
  name="$1"; host="$2"; extra="$3"
  [ -f "$name.crt" ] && return 0
  openssl req -newkey rsa:2048 -nodes -sha256 \
    -keyout "$name.key" -out "$name.csr" \
    -subj "$SUBJ_BASE/CN=$host" 2>/dev/null
  openssl x509 -req -in "$name.csr" -CA demo-ca.crt -CAkey demo-ca.key \

keyUsage=critical,digitalSignature,keyEncipherment
extendedKeyUsage=serverAuth

func tlsSummary(cs *tls.ConnectionState) string {
	if cs == nil {
		return "평문(HTTP) — 중간에서 누구나 읽고 고칠 수 있습니다"
	}
	ver, ok := versionNames[cs.Version]

	name := cs.ServerName
	if name == "" {

		ver, tls.CipherSuiteName(cs.CipherSuite), name)
}

// redirectToHTTPS 는 평문으로 온 요청을 같은 주소의 https 로 보낸다.
//
// 301(영구)을 쓰는 이유: 브라우저가 기억해 둬서 다음부터는 평문으로
// 나가지도 않는다. 평문 요청이 한 번이라도 나가면 그 한 번에 쿠키가
// 실려 나갈 수 있다.
func redirectToHTTPS(tlsAddr string) http.Handler {
	_, port, err := net.SplitHostPort(tlsAddr)
	if err != nil {
		port = "443"
	}
	return http.HandlerFunc(func(w http.ResponseWriter,
		r *http.Request) {
		host := r.Host
		if h, _, err := net.SplitHostPort(host); err == nil {
			host = h // 들어온 쪽 포트는 버리고 https 쪽 포트를 붙인다
		}
		target := "https://" + host
		if port != "443" {
			target += ":" + port
		}
		target += r.URL.RequestURI()
		http.Redirect(w, r, target, http.StatusMovedPermanently)
	})
}
