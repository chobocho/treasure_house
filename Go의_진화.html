왜 Go 를 역사로 읽는가

Go 는 거의 모든 코드가 오래전 문법 그대로 컴파일되는 언어입니다. 그래서 "요즘 Go" 와 "옛날 Go" 의 차이가 눈에 잘 띄지 않고, 무엇이 언제 왜 바뀌었는지를 따로 배울 기회도 적습니다.

이 덱은 그 차이를 릴리스 하나하나 따라갑니다. 기능마다 같은 차례로 읽습니다 — 왜 생겼나 → 문법 → 실행 예제 → 함정 → 근거. 가장 최근의 세 릴리스(1.25–1.27)는 두 배의 분량으로 다룹니다.

호환성 약속 — Go 1 의 명세대로 쓴 프로그램은 그 명세가 살아 있는 동안 고치지 않고 계속 컴파일되고 돌아가야 한다는 약속입니다. 이 덱의 많은 장이 "그 약속을 지키면서 어떻게 바꿨나" 의 이야기입니다. Go 1 호환성 문서 §Introduction

같은 리듬의 형제 덱: 파이썬의 진화 · 자바의 진화 · 모던 C++의 진화

문서 근거

심판은 둘 — 설치된 go 와 공식 문서

이 덱에서 "Go 는 이렇게 한다" 는 문장의 근거는 사람의 기억이 아닙니다.

무엇을누가 판정하나
돌려 볼 수 있는 것 — 문법, 출력, 컴파일 오류, 벤치마크의 할당 수 이 기계에 설치된 go. 캡처는 스크립트가 돌려 남긴 것이고 세 번 돌려 바이트까지 같은 것만 씁니다
돌려 볼 수 없는 것 — 날짜, "몇 버전에 들어왔나", 설계자의 말 받아 둔 공식 문서 — 릴리스 기록, 릴리스 노트, 버전마다의 API 목록, 명세, 블로그
ex/00/machine · go 1.27이 덱의 첫째 심판
$ go version
go version go1.27.1 android/arm64

버전 표기 하나하나는 빌드가 릴리스 기록·API 목록과 대조합니다. 기억으로 적은 버전은 빌드를 통과하지 못합니다.

실행 검증

옛 Go 없이 '전과 후' 를 보이는 법

이 기계(안드로이드 arm64)에는 옛 Go 툴체인을 받을 수 없습니다. 모듈 프록시에 이 플랫폼용 판이 없습니다.

ex/00/machine · go 1.27옛 툴체인 받기는 실패한다
$ GOPROXY=https://proxy.golang.org GOTOOLCHAIN=go1.26.0 go version
go: downloading go1.26.0 (android/arm64)
go: download go1.26.0 for android/arm64: toolchain not available
[exit 1]

그래서 이 덱은 옛 출력을 흉내 내지 않고, 지금의 go 가 스스로 보여 주는 네 가지 증거만 씁니다. 지금의 컴파일러는 go.mod 에 적힌 언어 버전을 지키고, 옛 동작을 GODEBUG 로 되살릴 수 있고, 사라진 문법은 오류로 거절합니다. 그 셋으로 보일 수 없는 것은 "1.27.1 에서의 동작" 이라고 밝히고 역사는 문서 배지로 댑니다.

증거의 네 가지 꼴

꼴어떻게무엇이 증거인가
언어 버전 지시자같은 소스를 go.mod 의 go 1.N 만 바꿔 컴파일 "requires go1.22 or later" 같은 컴파일러의 거절 메시지
GODEBUG옛 동작을 켜는 설정으로 같은 프로그램을 다시 실행 두 실행의 출력 차이
GOEXPERIMENT1.27 에 실험으로 들어 있는 기능을 켜고 끄기 켰을 때만 되는 것
사라진 문법Go 1 이전 문법을 그대로 컴파일 지금 컴파일러의 오류 메시지

GODEBUG 의 기본값도 go.mod 의 go 줄을 따릅니다. 그래서 go 줄만 바꿔도 옛 동작이 돌아오는 설정이 있습니다(다음다음 장). GODEBUG 문서 §Default GODEBUG Values

문서 근거

꼴 (1) — go 줄이 언어 버전을 정한다

정수에 대한 range 는 1.22 에서 생긴 문법입니다. 같은 파일을 두 번 컴파일합니다.

ex/00/langdir/main.go1–11정수 range
// 슬라이드 p0-lang — go.mod 의 go 줄이 언어 버전을 정한다, Go 1.22
package main

import "fmt"

func main() {
	for i := range 3 {
		fmt.Print(i)
	}
	fmt.Println()
}
ex/00/langdir · go 1.22go.mod 가 go 1.22
$ go run .
012
ex/00/langdir · go 1.21사본의 go.mod 만 go 1.21 로
$ go run .
# ex/00/langdir
./main.go:7:17: cannot range over 3 (untyped int constant): requires go1.22 or later (-lang was set to go1.21; check go.mod)
[exit 1]

메시지 끝의 "-lang was set to go1.21; check go.mod" 가 요점입니다. 컴파일러는 모듈이 선언한 언어 버전보다 새 문법을 거절합니다. Go 툴체인 문서 §Module and workspace configuration

꼴 (2) — 옛 동작은 GODEBUG 로 돌아온다

1.21 부터 panic(nil) 은 런타임 오류가 되었습니다. 같은 프로그램을 세 번 돌립니다.

ex/00/panicnil/main.go1–12panic(nil) 을 recover 로 받는다
// 슬라이드 p0-godebug — GODEBUG 기본값도 go 줄을 따른다, Go 1.21
package main

import "fmt"

func main() {
	defer func() {
		r := recover()
		fmt.Printf("recover() = %v (%T)\n", r, r)
	}()
	panic(nil)
}
ex/00/panicnil · go 1.21go 1.21 — 새 동작
$ go run .
recover() = runtime error: panic called with nil argument (*runtime.PanicNilError)
ex/00/panicnil · go 1.20go 줄만 1.20 으로 — 옛 동작
$ go run .
recover() = <nil> (<nil>)
ex/00/panicnil · go 1.21go 1.21 그대로, 설정으로 옛 동작
$ GODEBUG=panicnil=1 go run .
recover() = <nil> (<nil>)

이 덱을 읽는 법

  • 1부·2부는 역사입니다 — 왜 만들었고, 공개에서 Go 1 까지 무엇이 굳었나.
  • 3부부터 8부까지가 릴리스 순서의 본문입니다. 릴리스마다 첫 장은 개관 장입니다 — 개관 장만 넘겨도 전체 흐름이 보입니다.
  • 8부(1.25–1.27)가 이 덱의 주인공이고, 9부는 아직 나오지 않은 1.28 의 초안입니다.
  • 10부는 같은 이야기를 갈래(언어·런타임·도구·라이브러리)별로 다시 엮습니다.
  • 코드 블록 위 회색 줄은 어느 파일 몇 번째 줄인지를 말합니다. 옮겨 적은 코드가 아닙니다.
  • 어두운 블록은 진짜로 돌린 출력이고 첫 줄이 그 명령입니다. 이름표의 "go 1.N" 은 그때의 go.mod 입니다.
  • 장마다 퀴즈가 하나씩 있습니다. 답은 단추를 누르면 펼쳐집니다.

캡처에서 지운 것

캡처가 그 실행의 우연에 기대면 세 번 돌렸을 때 달라집니다. 달라지는 조각만 지우고, 지운 것은 여기 전부 밝힙니다.

tools/gover.py106–130캡처 정규화 — 이 함수가 전부다
def normalise(text, work, scratch):
    """이 실행의 우연을 지운다 — 무엇을 지웠는지는 덱 0부가 밝힌다.

    경로(작업 사본 → /work, scratch → /scratch, GOROOT → $GOROOT),
    고루틴 번호, 힙 주소·명령 주소, 임시 빌드 디렉터리, 벤치마크의 반복
    횟수와 ns/op, 시험 소요 시간. allocs/op·B/op 는 결정적이라 남긴다.
    프로그램이 찍은 짧은 16진 값(0xff)은 증거라 남긴다. O(길이)."""
    text = text.replace('\r\n', '\n')
    text = text.replace(GOROOT, '$GOROOT')
    # 경로는 경계까지 맞춰 바꾼다 — '/s' 가 '/src' 의 앞머리를
    # 먹으면 안 된다
    for path, name in ((work, '/work'), (scratch, '/scratch')):
        text = re.sub(re.escape(path) + r'(?![\w.-])', name, text)
    text = re.sub(r'\bgoroutine \d+\b', 'goroutine N', text)
    text = re.sub(r'\b0xc[0-9a-f]{9,}\b', '0xc…', text)
    text = re.sub(r'\+0x[0-9a-f]+\b', '+0x…', text)
    text = re.sub(r'\b(pc|sp|fp|lr)=0x[0-9a-f]+\b', r'\1=0x…', text)
    text = re.sub(r'/go-build\d+', '/go-buildN', text)
    text = re.sub(r'^(Benchmark\S*[ ]*\t)[ ]*\d+\t[ ]*[\d.]+ ns/op',
                  r'\1…\t… ns/op', text, flags=re.M)
    text = re.sub(r'^(--- (?:PASS|FAIL|SKIP): .*\()[\d.]+s\)',
                  r'\1…s)', text, flags=re.M)
    text = re.sub(r'^((?:ok|FAIL)\s+\S+\s+)[\d.]+s\b', r'\1…s', text,
                  flags=re.M)
    return text
