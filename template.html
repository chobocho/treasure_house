슬라이드 덱 템플릿

PPT형 단일 HTML 덱 — 이 파일을 복사해 본문만 갈아 끼우면 됩니다

← → 방향키·스와이프로 넘기기 · ☰ 목차 · 🏰 보물창고

이 템플릿의 사용법

  1. template.html을 새 이름으로 복사합니다 — 저장소 루트에 한국어 파일명으로.
  2. <title>, <meta name="description">, 상단 바의 .brand를 바꿉니다.
  3. :root의 색 변수만 고쳐 테마를 바꿉니다. 그 아래 CSS는 건드릴 필요가 없습니다.
  4. <main> 안의 예시 슬라이드를 지우고 내용을 채웁니다.
  5. 상단 바 <select id="nav">의 option 목록을 실제 부·장 id에 맞춥니다.
  6. 완성하면 python3 tools/embed_mono_font.py 이파일.html을 돌려 고정폭 글꼴(DeckMono)을 갱신합니다.
  7. index.html의 해당 섹션에 카드를 추가합니다.
손대지 않아도 되는 것 — 페이지 번호, 목차 오버레이, 진행 막대, 코드 하이라이팅, 방향키·게임패드 입력, 책갈피(이어보기)는 전부 자동입니다.

지켜야 할 규칙

id는 반드시 붙인다 — 주소 해시(#slide-rules), 목차 점프, 책갈피 복원이 전부 id로 동작합니다. 없으면 그 슬라이드로 돌아올 수 없습니다.
페이지 번호를 손으로 쓰지 않는다 — .pno는 엔진이 자동으로 넣습니다. 슬라이드를 중간에 넣거나 빼도 번호가 어긋나지 않습니다.
박스 문자 도식(┌ ─ │ └) 금지 — 폴드7의 폰트에서 폭이 어긋나 도식이 깨집니다. 3부의 CSS 도식이나 표로 대체하세요.
슬라이드 하나에 한 가지 이야기 — 세로 스크롤은 되지만, 한 화면을 넘기면 넘길수록 PPT의 이점이 사라집니다.

콜아웃 네 종류

note — 중립적인 보충 설명. 파란색.
tip — 잘하는 방법, 권장 사항. 초록색.
warn — 함정, 실수하기 쉬운 곳. 주황색.

머리말은 <b>로 — 콜아웃마다 b의 색이 자동으로 맞춰집니다.

코드 블록

data-lang만 붙이면 하이라이터가 런타임에 색을 입힙니다. 손으로 <span>을 붙이지 마세요.

example.py

# 파일명 라벨은 <p class="fname"> 를 pre 바로 앞에 둔다
def fib(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b   # 튜플 대입
    return a

print(fib(10))  # 55

원시 < >는 반드시 이스케이프 — &lt;/&gt;로 쓰지 않으면 Promise<string>이나 </button>이 태그로 파싱돼 문서 구조가 통째로 깨집니다.

고정폭 글꼴과 아스키 표

코드·표·터미널 캡처는 "한글 2칸, 나머지 1칸"이라는 칸 규칙 위의 그림입니다. 폰·태블릿에는 그 규칙을 지키는 글꼴이 없어서 한글은 비례폭으로, 박스 문자는 다른 글꼴로 와 열이 어긋납니다. 그래서 이 템플릿은 D2Coding 서브셋을 DeckMono로 <style> 앞머리에 싣고, 모든 고정폭 글꼴 목록이 그것을 먼저 봅니다.

┌────────┬──────┬────────┐
│ 이름   │ 크기 │ 비고   │
├────────┼──────┼────────┤
│ main.c │ 12KB │ 진입점 │
│ util.h │  2KB │ 헤더   │
└────────┴──────┴────────┘
$ python3 tools/embed_mono_font.py 이파일.html # 고정폭 요소의 글자만 D2Coding 에서 잘라 @font-face 를 제자리 교체 — 덱마다 수십 KB $ python3 tools/embed_mono_font.py --check 이파일.html # 글꼴 1개 · woff2 · 목록 순서 · 글자 누락을 검사만 한다
코드·표에 새 한글을 넣었으면 스크립트를 다시 돌립니다 — 서브셋에 없는 글자는 기기 글꼴로 빠져 그 줄만 어긋납니다. --check가 누락 글자를 알려 줍니다.

인라인 코드와 칩

문장 안의 identifier는 <code>로 감쌉니다. 짧은 식별자에는 class="nb"를 붙이세요 — 낱말 중간에서 갈라지는 것을 막습니다.

왜 필요한가 — 좁은 화면에서 getmetatable이 getmeta/table로 쪼개집니다. 특히 따옴표·괄호·하이픈 뒤는 유니코드 규정상 정식 줄바꿈 지점이라 op-print-using 같은 이름이 잘 끊깁니다.
기준 — 18자 이하에만 nb를 붙입니다. 전부 붙이면 반대로 긴 칩이 카드 밖으로 넘칩니다. 칩을 ·나 /로 붙여 쓴 자리에는 폭 0 공백(U+200B)을 넣으세요.

값을 나열할 때는 칩을 씁니다: 0x1F NULL 3.14

데모 만들기

HTML — data-demo가 등록 이름

<div class="demo" data-demo="sample">
  <h5>제목</h5>
  <div class="row">
    <input type="number" data-n value="10">
    <button data-run>계산</button>
  </div>
  <div class="out"></div>   <!-- 출력은 반드시 .out -->
</div>

JS — 슬라이드가 처음 보일 때 자동 배선된다

__demo('sample', function (host, api) {
  var inp = host.querySelector('[data-n]');
  host.querySelector('[data-run]').onclick = function () {
    var n = +inp.value, a = 0, b = 1;
    for (var i = 0; i < n; i++) { var t = a + b; a = b; b = t; }
    api.w(host, 'fib(' + n + ') = ' + a, 'ok');   // w=쓰기, add=덧붙이기
  };
});
api — w(host,html,cls) 덮어쓰기 · add 한 줄 추가 · esc 이스케이프 · show 값 표시. 클래스는 ok/bad/dim.

데모에서 주의할 것

방향키를 쓰는 데모는 e.preventDefault()를 반드시 호출 — 입력 셸이 defaultPrevented를 보고 슬라이드 이동을 양보합니다. 빠뜨리면 게임을 조작할 때마다 슬라이드가 넘어갑니다.
스와이프는 자동으로 막힙니다 — pre·.tblwrap·.demo 위에서 시작한 터치는 페이지 넘김으로 해석하지 않습니다.
데모는 슬라이드가 처음 열릴 때 한 번만 배선됩니다 — 무거운 초기화를 해도 첫 진입에서만 비용을 냅니다.

퀴즈

Q. 슬라이드 id를 빠뜨리면 무엇이 깨지는가?

A. 주소 해시 이동, 목차 점프, 그리고 책갈피 복원. 이어보기가 그 슬라이드를 찾지 못합니다.

여기서 걸리는 것이 실제로 신고된 버그들이다

내보내기 전 점검

  1. 태그 균형 — <code> 안의 원시 </>가 전부 이스케이프됐는지. 파서로 검증하면 확실합니다.
  2. 가로 오버플로 0 — 360 / 412 / 884 / 1280px에서 가로 스크롤바가 생기지 않는지.
  3. 제목 겹침 — 페이지 번호가 세 자리(218 / 500)가 돼도 제목과 겹치지 않는지.
  4. 데모 전수 실행 — 모든 [data-run]을 눌러 .out에 오류가 없는지.
  5. 키·게임패드 — ← → 페이지, ↑ ↓ 스크롤이 동작하는지.
  6. 책갈피 — 중간 슬라이드에서 새로 고쳤을 때 이어보기 안내가 뜨는지.
  7. 인쇄 미리보기 — 모든 슬라이드가 한 장씩 펼쳐지는지.
  8. 고정폭 글꼴 — tools/embed_mono_font.py --check가 통과하는지. 누락 글자가 있으면 --check 없이 한 번 더 돌려 갱신.
실제 브라우저로 검증하세요 — Playwright로 띄워 슬라이드 수, 목차 링크 수, 데모 출력, 오버플로를 한 번에 확인하는 것이 가장 빠릅니다.
