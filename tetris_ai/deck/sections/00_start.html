01유전 알고리즘 AI와 1:1 대전

C++ WASM 테트리스 2편 — 판을 읽는 법, 수를 고르는 법, 그리고 그 판단 기준을 진화로 찾아내는 법.

왼쪽은 5세대까지만 배운 AI, 오른쪽은 50세대를 마친 AI다. 둘 다 이 문서 안의 wasm 인스턴스이고, 지운 줄은 서로의 필드로 넘어간다.

02무엇을 만드는가

1 · 판을 읽는 눈

보드를 숫자 8개로 압축한다. 높이·구멍·요철·우물·전이·착지 높이. 이 8개가 AI가 세상을 보는 전부다.

2 · 수를 고르는 손

가능한 착수 ~80가지를 보드 사본 위에서 전부 두어 보고, 점수가 가장 높은 자리를 고른다.

3 · 기준을 만드는 진화

8개 숫자에 곱할 가중치를 유전 알고리즘으로 찾는다. 개체 32, 세대 50, 실제로 45초 돌렸고 그 로그가 이 덱에 그대로 실린다.

4 · 1:1 대전

wasm 인스턴스 두 개, 심판 하나. 지운 줄이 상대 바닥에서 솟아오른다. 상쇄·B2B·콤보·T스핀까지 전부 C++ 안에.

모든 코드는 이 기계에서 실제로 컴파일·실행해 검증했다. 이 덱에는 전체 소스가 한 줄도 빠짐없이 실려 있다 — 슬라이드의 코드 블록은 실제 파일에서 잘라 온 것이고, 빌드 스크립트가 커버리지를 검사한다.

031편과 무엇이 다른가

1편은 규칙을 만들었다. 2편은 그 규칙 위에서 판단과 대결을 만든다.

주제1편2편
탐색고스트로 40번 찔러 보는 어트랙트 봇 — 진행 중인 판을 직접 움직여 본다board 240바이트 사본 위에서 ~80수를 시뮬레이션
평가줄·구멍·높이 3가지, 상수는 손으로 찍음특징 8가지, 가중치는 GA가 찾음
홀드고려하지 않음홀드를 쓰는 수까지 후보에 포함
인스턴스슬라이드마다 1개같은 모듈에서 2개 — 서로 다른 판
규칙싱글플레이공격 표·가비지·상쇄·승패까지 C++ 안에
wasm 크기7,340 바이트14,294 바이트 (AI 포함)
1편을 안 읽었어도 된다1편 코어의 전체 소스가 1부에 그대로 실려 있다. 다만 SRS 월킥이나 락딜레이가 왜 그렇게 생겼는지는 1편에서 설명한다.

14,294 바이트

~80 후보 / 0.05 ms

한 수를 고르는 데 드는 시간. 60fps 프레임(16.7ms)의 0.3%.

05필요한 준비물

  • clang++ 15 이상 — --target=wasm32 를 지원하면 된다. emscripten은 쓰지 않는다.
  • Node 18 이상 — GA 학습과 테스트를 돌린다. 브라우저 없이 wasm을 그대로 실행한다.
  • g++ (선택) — 같은 소스를 네이티브로 빌드해 AddressSanitizer로 검사한다.
  • 브라우저 — 대전을 눈으로 보려면. 파일을 더블클릭하면 열린다. 서버 필요 없음.

이 덱을 쓴 기계에서 실제로 확인한 버전:

확인한 툴체인shell · 3줄
clang version 21.1.8      # wasm32 타깃 내장, wasm-ld 포함
node v24.19.0             # WebAssembly.compile / instantiate
g++ (clang 호환) + ASan   # -fsanitize=address,undefined
읽는 순서2·3·4부가 AI의 본체다. 5·6부가 학습, 8·9부가 대전이다. 코드만 훑고 싶으면 각 부의 마지막 코드 슬라이드들만 봐도 파일 전체가 모인다.
