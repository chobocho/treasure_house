{{N}}브라우저 없이 wasm 돌리기

학습에 필요한 건 화면이 아니라 초당 수만 판이다. Node가 WebAssembly 를 그대로 갖고 있으니 브라우저는 필요 없다.

core.mjs Node용 최소 로더

파일에서 wasm을 읽고 → 인스턴스 → 선형 메모리 위에 Uint8Array·Int32Array·Float32Array 창을 낸다. 브라우저 쪽 battle.js 와 하는 일이 같고, atob 대신 fs 를 쓰는 것만 다르다.

같은 로더를 ga.mjs(학습)와 test_ai.mjs(검증)가 함께 쓴다
터미널shell · 4줄
$ make            # clang++ --target=wasm32 → tetris_ai.wasm (14,294 bytes)
$ make test       # node test_ai.mjs      → 98 passed, 0 failed
$ make train      # node ga.mjs           → weights.json, ga_log.json
$ make native     # g++ -fsanitize=address,undefined

{{N}}core.mjs — 메모리 창

포인터는 그냥 “선형 메모리 배열의 인덱스”다. 그 위에 TypedArray 창을 내면 복사 없이 C++의 배열을 JS에서 읽고 쓴다.

detach 함정memory.grow() 가 일어나면 ArrayBuffer 가 분리되어 기존 창이 전부 무효가 된다. 우리 모듈은 힙이 없어 자라지 않지만, 습관적으로 byteLength === 0 을 확인하고 다시 만든다.

{{N}}core.mjs — 테스트용 도구

테스트가 “특정 상황”을 만들려면 판을 직접 심어야 한다. ts_board() 가 준 주소에 그림을 그려 넣는 게 전부다.

boardHash 는 FNV-1a 32비트. “두 경로가 정말 같은 판을 만들었나”를 정수 하나로 비교하기 위한 것이다.

{{N}}첫 실험 — 줄 수를 목표로

가장 자연스러운 목표부터 시작했다. “400조각에서 몇 줄을 지우는가.”

터미널shell · 1줄
$ node ga.mjs --pop 32 --gen 30 --lines

{{N}}천장에 닿았다

400조각 × 4칸 = 1,600칸. 한 줄이 10칸이니 이론상 최대 160줄이다.

1세대 157.7 → 30세대 159.3

1세대의 무작위 개체가 이미 만점의 98.6%를 받았다. 8세대부터는 집단 전원이 157줄을 넘긴다. 이 지점에서 GA는 누가 더 나은지 구별할 수 없다 — 선택 압력이 사라지고, 남은 40세대는 잡음 위를 표류한다.

진단알고리즘이 잘못된 게 아니다. 자로 잰 것이 잘못됐다. 특징 8개 + 1수 탐색은 이 과제에 너무 강해서, 이 자로는 실력 차가 안 보인다.

실패한 시도로 하나 더: ai_play_hard() 로 N조각마다 가비지 1줄을 뿌려 난이도를 올려 봤다. 결과는 정반대였다 — 가비지 줄은 10칸 중 9칸이 이미 차 있어서, 지우기가 오히려 쉬워졌다. 6조각마다 뿌려도 학습된 AI는 600조각을 죽지 않고 버텼다.

이 덱은 대전 덱이다. 그렇다면 물어야 할 것은 “몇 줄을 지웠나”가 아니라 “상대에게 몇 줄을 보냈나”다.

위 숫자는 학습에 쓰지 않은 시드 5개(7·8·9·10·11)의 평균이다. 학습 시드에서 127.3, 미학습 시드에서 96.2 — 떨어지긴 했지만 무너지지 않았다. 시드 3개로 학습한 것 치고는 일반화가 잘 된 편이다.
