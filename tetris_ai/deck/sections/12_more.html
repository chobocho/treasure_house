{{N}}2수 탐색과 빔서치

1수 전탐색은 후보 80개다. 2수는 80 × 80 = 6,400 — 4 ms. 실시간은 가능하지만 GA 학습이 80배 느려진다.

해법은 빔서치다. 1수째의 상위 K개만 남기고 그 각각에서 2수째를 본다.

빔서치 뼈대C++ · 12줄
// 1수째: 후보 전부를 평가해 상위 K개만 남긴다
Cand beam[K];
enumerate(board, cur_piece, [&](int rot, int x, u8* after, float s) {
  insert_top_k(beam, K, {rot, x, s, after});
});
// 2수째: 각 빔에서 next_q[0] 을 놓아 본다 (조각을 알고 있다!)
float best = -1e30f; int best_first = -1;
for (int i = 0; i < K; i++)
  enumerate(beam[i].after, next_q[0], [&](int r2, int x2, u8* b2, float s2) {
    if (s2 > best) { best = s2; best_first = beam[i].packed; }
  });
return best_first;   // 두 수를 보고 고른 "첫 수"

K = 8 이면 후보가 80 + 8×80 = 720, 즉 1수의 9배다. 0.45 ms — 실시간에도, 학습에도 감당 가능하다.

공짜로 얻는 것2수째에는 next_q[0] 을 알고 두므로, “다음이 I니까 우물을 판다” 같은 판단이 생긴다. 특징을 하나도 안 늘리고 NEXT 큐를 활용하는 방법이다.

{{N}}적합도를 자가 대전으로

지금의 적합도는 “혼자 400조각을 두고 보낸 줄 수”다. 대전 실력을 재는 더 정직한 자는 실제로 싸워 보는 것이다.

자가 대전 적합도JavaScript · 11줄
function duelFitness(genome, champion, seeds) {
  let wins = 0;
  for (const s of seeds) {
    setWeights(coreA, genome); setWeights(coreB, champion);
    coreA.e.ts_init(s); coreB.e.ts_init(s);       // 같은 조각 순서
    while (alive(coreA) && alive(coreB)) {
      coreA.e.ai_step(); coreB.e.ai_step();
      route(coreA, coreB);                            // 심판을 그대로 재사용
    }
    if (alive(coreA)) wins++;
  }
  return wins / seeds.length;                          // 승률
}

좋은 점

목적 함수가 곧 목표다. 상쇄 타이밍처럼 대전에만 있는 기술이 학습된다.

어려운 점

적합도가 상대에 의존한다 → 순환(가위바위보)이 생겨 수렴이 안 될 수 있다. 챔피언 풀을 두고 과거 세대와도 싸우게 하는 게 표준 처방이다.

{{N}}신경망으로 가면

선형 평가를 작은 신경망으로 바꿀 수 있다. 유전자는 여전히 “실수의 배열”이므로 GA 코드는 한 줄도 안 바뀐다 — DIM 만 커진다.

선형 (지금)8→8→1 MLP
유전자 길이88×8 + 8 + 8 + 1 = 81
평가 비용곱셈 8곱셈 72 + tanh 8
필요한 세대50수백~수천
표현력“구멍이 많으면 나쁘다”“구멍이 있으면서 동시에 높으면 훨씬 나쁘다”

차원이 10배가 되면 GA만으로는 벅차다. 이 지점부터는 CMA-ES나 진화 전략(ES), 또는 강화학습이 낫다.

tanh 는 libm 이 필요하다-nostdlib 프리스탠딩에서는 tanhf 가 없다. 다항식 근사나 x / (1 + |x|) 같은 소프트사인으로 대체해야 한다. 1편의 pow() 를 표로 바꾼 것과 같은 종류의 문제다.

{{N}}네트워크 대전

지금은 두 인스턴스가 한 탭 안에 있다. 원격 대전으로 넓히면 무엇이 필요한가.

  1. 결정론이 이미 있다 — 같은 시드 + 같은 입력열 = 같은 판. 이건 이미 테스트로 보장된다(T6).
  2. 입력만 보낸다 — 판 상태(240바이트)가 아니라 (프레임 번호, 액션) 쌍만. 한 조각당 10바이트 남짓.
  3. 롤백 — 상대 입력이 늦게 오면, 예측으로 진행한 뒤 도착 시점으로 되감아 다시 시뮬레이션한다.
  4. 되감기가 싸다 — 상태 전체가 board + stats + 전역 몇 개 = 1 KB 미만이다. 프레임마다 스냅숏을 떠도 부담이 없다.

전역 상태를 한 블록에 모아 둔 1편의 설계가 여기서 값을 한다. ts_snapshot(ptr) / ts_restore(ptr) 두 익스포트면 롤백 넷코드의 토대가 끝난다.

{{N}}더 빠르게

워커 병렬

GA는 개체 평가가 서로 독립이라 병렬화가 거의 공짜다. 코어 8개면 45초 → 6초.

wasm SIMD

-msimd128 로 특징 계산의 열 스캔을 v128로. 240칸을 16칸씩 처리한다.

비트보드

한 줄을 u16 하나로. 충돌 검사가 & 한 번, 줄 완성 검사가 == 0x3FF 한 번이 된다. 10~30배 빨라진다.

증분 평가

조각 하나가 바꾸는 열은 최대 4개다. 높이·구멍·전이를 전체 재계산하지 말고 그 4열만 갱신한다.

다만 이 덱의 목적에서는 셋 다 불필요했다. 45초면 충분했고, 그 대신 코드가 읽히는 상태로 남았다. 최적화는 필요할 때 하는 것이다.

{{N}}배운 것

  1. 탐색은 사본 위에서 — 240바이트를 복사할 수 있느냐가 AI의 모든 것을 갈랐다.
  2. 평가는 선형으로도 충분하다 — 특징만 잘 고르면. 곱셈 8번이면 된다.
  3. 자를 잘못 대면 GA는 아무것도 못 배운다 — 줄 수를 목표로 하면 1세대에 천장에 닿는다.
  4. 목표가 곧 성격이다 — 공격을 목표로 삼자 AI가 스스로 “참는 법”과 “우물 파기”를 찾아냈다.
  5. 상식은 절반만 맞다 — 높이 총합에 +0.065, 요철에 +0.21. 사람은 이 부호를 못 찍는다.
  6. 규칙은 한 곳에 — C++ 안에 두었더니 사람·AI·테스트·대전이 전부 같은 규칙을 쓴다.
  7. 인스턴스 분리가 대전이다 — 모듈 1개, 상태 2벌. 코드 한 줄도 안 고치고 1:1이 됐다.
  8. 결정론은 기능이다 — 시드를 고정했기에 로그를 덱에 실을 수 있었고, 실수로 덮어써도 복구됐다.
