Go 1.27

제네릭 메서드 · encoding/json/v2 · crypto/mldsa · uuid · simd(실험) · · 2026-09 기준 최신판

Go 1.27 한눈에

노트는 변화 대부분이 툴체인·런타임·라이브러리의 구현에 있다고 소개하지만, 발표 글은 언어 명세의 눈에 띄는 변화 셋을 맨 앞에 둡니다. 이 기계의 go 가 바로 1.27.1 이라, 이 장의 거의 모든 항목을 실제로 돌려 봅니다.

문서 근거

왜 이제야 제네릭 메서드인가

1.18 의 제네릭 제안은 메서드에 타입 매개변수를 허락하지 않았습니다. 제네릭 인터페이스 메서드는 효율적으로 구현하기 어렵고, 메서드는 주로 인터페이스를 구현하는 수단이라고 보았기 때문입니다. 1.27 은 관점을 바꿉니다 — 메서드는 타입 둘레에 기능을 모으는 정리 도구이기도 하다는 것입니다.

  • 함수로 쓰면 이름이 패키지 범위에 쌓이고, 이어 부르기가 안에서 밖으로(MapList(MapList(l, f), g)) 읽힙니다.
  • 메서드로 쓰면 왼쪽에서 오른쪽으로(l.Map(f).Map(g)) 읽힙니다.
역사 근거

제네릭 메서드 (generic methods) 1.27

왜 — 메서드 선언이 자기만의 타입 매개변수를 가질 수 있습니다. 받는 타입의 매개변수(E)와 별개로 결과 타입(R)을 메서드가 정합니다.

실행 검증

제네릭 메서드는 인터페이스를 채우지 못한다

인터페이스 메서드는 타입 매개변수를 선언할 수 없고, 제네릭 메서드로 인터페이스 메서드를 구현할 수도 없습니다. T.M[int] 의 모양이 func M() 과 같아도 T 는 I 를 구현하지 않습니다 — 구현은 타입의 성질이지 특정 인스턴스의 성질이 아니기 때문입니다.

왜 막았나 — 인터페이스 값의 메서드 호출은 패키지 경계를 넘어 어느 구체 메서드로 갈지 컴파일 때 알 수 없습니다. 제네릭 인터페이스 메서드라면 어떤 인스턴스의 코드를 미리 만들어 둘지 정할 수 없다는 것이 글의 설명입니다.
실행 검증

표준 라이브러리의 첫 제네릭 메서드 — (*Rand).N 1.27

왜 — 전에는 정수 타입마다 메서드(Int32N·Int64N·IntN …)를 두거나 패키지 함수 rand.N 을 써야 했습니다. 이제 *Rand 에도 어떤 정수 타입이든 받는 N 이 있습니다.

함정 — go 줄을 1.26 으로 낮춰도 이 파일은 컴파일됩니다. 제네릭 메서드를 선언한 것은 표준 라이브러리이고, 부르는 쪽은 새 문법을 쓰지 않았기 때문입니다. 너무 새 API 를 잡는 것은 컴파일러가 아니라 vet 의 stdversion 검사이고, 1.27 부터는 go test 가 그것을 기본으로 돌립니다.

Go 1.27 퀴즈

Q. go.mod 가 go 1.26 인 모듈에서 r.N(int64(10))(1.27 의 제네릭 메서드)을 부르면 컴파일러가 거절합니까? 무엇이 알려 줍니까?

A. 컴파일러는 거절하지 않습니다 — 부르는 쪽은 새 문법을 쓰지 않았기 때문입니다. vet 의 stdversion 검사가 "rand.(*Rand).N requires go1.27 or later (module is go1.26)" 라고 짚고, 1.27 부터는 go test 가 그 검사를 기본으로 돌려 시험 전에 멈춥니다.
