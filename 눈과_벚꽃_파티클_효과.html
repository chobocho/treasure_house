파티클 시스템이란?

  • 작은 그림 조각(파티클) 수십~수천 개를 각각 간단한 규칙으로 움직여, 전체로는 복잡해 보이는 현상을 만드는 기법.
  • 눈, 비, 벚꽃, 불꽃, 연기, 먼지 — 게임과 웹의 배경 효과 대부분이 이 방식이다.
  • 핵심 발상: 개별 파티클은 바보처럼 단순하게, 대신 많이 + 서로 다르게(랜덤).
  • 이 자료의 눈송이는 속성 7개, 갱신 규칙 3줄이 전부다. 그런데도 화면은 진짜 눈처럼 보인다.

전체 구조: 상태 → 갱신 → 그리기

  • 상태(state): 파티클 배열 + 환경(바람, 바닥에 쌓인 높이).
  • 갱신(step): 매 프레임 dt초만큼 물리를 진행 — 위치, 바람, 착지, 녹음.
  • 그리기(draw): 화면을 지우고 상태를 처음부터 다시 그린다 (즉시 모드 렌더링).
  • 루프: requestAnimationFrame → step(dt) → draw() → 반복.
  • 이 4단 구조는 눈이든 벚꽃이든 완전히 동일하다. 달라지는 것은 step과 draw의 내용물뿐.

캔버스 준비와 DPR 대응

고해상도(레티나) 화면에서 흐릿하지 않게: 내부 버퍼는 DPR배로, 좌표계는 CSS px로.

const cv  = document.getElementById("sky");
const ctx = cv.getContext("2d");
let W, H;                                // CSS px 기준 크기

function resize() {
  const dpr = Math.min(devicePixelRatio || 1, 2);  // 2 초과는 낭비
  W = innerWidth;  H = innerHeight;
  cv.width  = Math.round(W * dpr);       // 실제 픽셀 버퍼
  cv.height = Math.round(H * dpr);
  ctx.setTransform(dpr, 0, 0, dpr, 0, 0); // 이후 좌표는 CSS px 그대로
}
addEventListener("resize", resize);
resize();

게임 루프와 delta time

dt(초)를 곱해 움직이면 60Hz든 120Hz든 같은 속도로 내린다. 탭 복귀 시 폭주를 막는 상한도 필수.

let last = performance.now();

function loop(now) {
  const dt = Math.min(0.05, (now - last) / 1000);  // 최대 50ms로 클램프
  last = now;
  step(dt);      // 물리 갱신
  draw();        // 전부 다시 그리기
  requestAnimationFrame(loop);
}
requestAnimationFrame(loop);
  • 백그라운드 탭에서는 rAF가 저절로 멈춘다. 복귀하면 now−last가 수십 초일 수 있으므로 dt 상한(0.05s)이 없으면 눈이 순간이동한다.

파티클 재활용 — 풀링

  • 눈송이가 화면 밖으로 나가면 삭제하고 새로 만들까? — 아니다. 같은 객체를 초기화해 재사용한다.
  • 매 프레임 객체를 생성/삭제하면 가비지 컬렉션이 발생해 모바일에서 프레임이 튄다.
  • 패턴: newFlake(f)는 새 객체를 만드는 게 아니라, 받은 객체 f의 속성을 덮어써서 "환생"시킨다.
  • 배열 길이는 시작할 때 정해지고 이후 변하지 않는다 — 개수 = 밀도 조절 다이얼.
  • 예외: 벚꽃 돌풍처럼 개수가 일시적으로 변하는 경우는 8장에서 상한선과 함께 다룬다.

rand 유틸과 파라미터 감각

모든 파티클 효과의 비밀은 "모든 속성에 범위 랜덤"이다. 전부 같은 값이면 군대 행진처럼 보인다.

const rand = (a, b) => a + Math.random() * (b - a);

rand(1, 3.2)      // 눈송이 반지름: 작은 것~큰 것 섞기
rand(20, 40)      // 기본 낙하 속도(px/초)
rand(0, Math.PI * 2)  // 흔들림 위상: 제각각 다른 타이밍
  • 파라미터 튜닝 요령: 먼저 최소=최대로 두고 동작을 확인한 뒤, 범위를 서서히 벌린다.
  • 이 자료의 모든 수치는 "px/초" 단위다. dt를 곱하는 순간 프레임레이트 독립이 된다.

1장 요약

  • 파티클 = 단순한 규칙 × 많은 개수 × 범위 랜덤.
  • 구조는 항상 상태 → step(dt) → draw() → rAF 루프.
  • DPR 대응: 버퍼는 크게, setTransform으로 좌표계는 CSS px 유지.
  • dt에 상한을 걸고, 객체는 삭제 대신 재활용한다.
  • 다음 장: 이 뼈대에 눈송이를 얹는다.

눈송이의 속성 설계

  • x, y — 위치 (CSS px).
  • r — 반지름 1~3.2px. 크기이자 "카메라와의 거리".
  • vy — 낙하 속도(px/초). r에 비례시켜 원근감을 만든다.
  • phase — 좌우 흔들림의 현재 위상(라디안). 눈송이마다 다르게 시작.
  • sway — 흔들림 속도 진폭(px/초). 8~24.
  • spd — 위상이 도는 속도(라디안/초). 흔들림의 빠르기.
  • 속성 7개가 전부다. 벚꽃잎은 여기에 회전·뒤집힘이 추가되어 12개가 된다(7장).

원근감 트릭: 크기 ∝ 속도

  • 실제 눈은 거의 같은 속도로 내리지만, 가까운 눈송이는 화면(각도)상 더 빨리 움직여 보인다.
  • 그래서 "큰 눈송이 = 가까운 눈송이 = 빠르게"로 묶으면 공짜로 깊이감이 생긴다.
  • 공식: vy = rand(20, 40) + r × 18 — 기본 속도에 반지름 비례항을 더한다.
  • 3장에서 바람 반응도 r에 비례시킨다 — 가까운 것이 더 크게 밀려 보여야 자연스럽다.
  • 투명도도 살짝: 작은(먼) 눈송이를 더 흐리게 그리면 깊이감이 배가된다.

눈송이 생성 코드

두 번째 인자 anywhere: 최초 1회는 화면 전체에 뿌려 "이미 내리던 중"처럼 시작한다.

const flakes = [];

function newFlake(f = {}, anywhere = false) {
  const r = rand(1, 3.2);
  f.x = rand(-20, W + 20);              // 좌우 여유 20px
  f.y = anywhere ? rand(-H, H) : rand(-40, -10);  // 평소엔 화면 위에서
  f.r = r;
  f.vy = rand(20, 40) + r * 18;         // 클수록 빨리 = 원근감
  f.phase = rand(0, Math.PI * 2);
  f.sway = rand(8, 24);
  f.spd = rand(1, 3);
  return f;
}
for (let i = 0; i < 220; i++) flakes.push(newFlake({}, true));

낙하와 좌우 흔들림

y ← y + vy · dt
x ← x + sin(phase) · sway · dt,   phase ← phase + spd · dt
  • 낙하는 등속으로 충분하다 — 눈송이는 공기저항 때문에 이미 종단 속도로 내려온다. 중력 가속 코드가 필요 없다.
  • 흔들림은 sin 곡선을 속도에 더한다. phase가 제각각이라 전체로는 무질서하게 보인다.
  • sway는 진폭이 아니라 "좌우 속도의 최대값(px/초)"이다. 위치가 아니라 속도에 더하므로 바람과 자연스럽게 합성된다(3장).

갱신 코드와 랩어라운드

좌우로 나가면 반대편에서 재등장(랩), 아래로 나가면 위에서 환생(재활용).

function step(dt) {
  for (const f of flakes) {
    f.phase += f.spd * dt;
    f.x += Math.sin(f.phase) * f.sway * dt;
    f.y += f.vy * dt;
    // 좌우: 바람에 밀려 나가도 반대편에서 들어와 밀도 유지
    if (f.x < -30) f.x += W + 60;
    else if (f.x > W + 30) f.x -= W + 60;
    // 아래로 사라지면 위에서 재활용
    if (f.y - f.r > H) newFlake(f);
  }
}

눈송이 그리기 — 한 패스에 모아서

220개를 각각 beginPath/fill 하면 느리다. 하나의 경로에 원 220개를 담아 fill은 1번만.

function draw() {
  ctx.clearRect(0, 0, W, H);
  ctx.fillStyle = "#fff";
  ctx.globalAlpha = 0.9;
  ctx.beginPath();
  for (const f of flakes) {
    ctx.moveTo(f.x + f.r, f.y);   // moveTo가 없으면 원끼리 선으로 이어진다
    ctx.arc(f.x, f.y, f.r, 0, Math.PI * 2);
  }
  ctx.fill();                     // 드로우 콜 1번
  ctx.globalAlpha = 1;
}
  • moveTo(f.x + f.r, f.y)는 arc의 시작점(3시 방향)으로 펜을 미리 옮기는 관용구다.

[데모] 기본 눈 내리기

바람 없이 낙하 + sin 흔들림만. 큰 눈송이가 더 빨리 떨어지는 원근감을 관찰해 보라.

2장 요약

  • 눈송이 = 속성 7개(위치, 반지름, 낙하 속도, 위상, 흔들림 진폭/속도).
  • 크기 ∝ 낙하 속도로 원근감을 공짜로 얻는다.
  • 낙하는 등속(종단 속도), 흔들림은 sin을 속도에 더한다.
  • 좌우는 랩어라운드, 아래는 재활용. 그리기는 한 패스에 모아 드로우 콜 1번.
  • 그럴듯하지만 아직 심심하다 — 눈보라의 영혼, 바람이 없기 때문이다.

상수 바람은 왜 어색한가

  • wind = 50을 그냥 더하면? 모든 눈이 같은 각도로 평행하게 내린다 — 벽지 무늬처럼 보인다.
  • 진짜 바람의 특징 세 가지:
  • ① 잔잔하다가 갑자기 세게 분다 (돌풍, gust)
  • ② 세기가 끊임없이 미세하게 흔들린다 (난류, turbulence)
  • ③ 파티클마다 반응이 다르다 (가벼운 것이 더 밀린다)
  • 이 셋을 각각 상태 기계, 노이즈 함수, 크기 비례 계수로 구현한다.

바람의 3층 구조

wind = base + gust + turb
  • base — 기본풍. 항상 부는 약한 바람. 눈은 0, 벚꽃은 12 정도로 둔다.
  • gust — 돌풍. 평소 0이다가 몇 초마다 랜덤하게 치솟았다 잦아든다. 방향(부호)도 랜덤.
  • turb — 난류. 노이즈 함수로 만드는 ±40 범위의 잔떨림.
  • 단위는 전부 px/초. 셋을 더한 wind.value 하나만 파티클이 읽어가면 된다.
  • 이 바람 객체는 눈과 벚꽃이 완전히 동일하게 재사용한다.

돌풍의 생애: idle → attack → decay

  • idle — 돌풍 없음. 타이머(3~8초 랜덤)가 다 되면 attack으로.
  • attack — 목표 세기(±70~170, 방향 랜덤)를 향해 지수적으로 상승. 목표 근처에 오면 decay로.
  • decay — 반감기 0.9초로 지수 감쇠. 거의 0이 되면 idle로 돌아가 타이머를 다시 뽑는다.
  • 지수 상승/감쇠를 쓰는 이유: 직선 보간보다 "훅 불었다가 스르르 잦아드는" 느낌이 난다.
attack: gust ← gust + (target − gust) · min(1, 3·dt)
decay:  gust ← gust · 0.5^(dt / 0.9)

돌풍 상태 기계 코드

const wind = {
  base: 0, gust: 0, target: 0, turb: 0,
  state: "idle", timer: rand(2, 6),
  t: 0, seed: Math.random() * 1000,

  update(dt) {
    this.t += dt;  this.timer -= dt;
    if (this.state === "idle" && this.timer <= 0) {
      this.state = "attack";      // 돌풍 시작! 세기·방향 랜덤
      this.target = rand(70, 170) * (Math.random() < 0.5 ? -1 : 1);
    }
    if (this.state === "attack") {
      this.gust += (this.target - this.gust) * Math.min(1, dt * 3);
      if (Math.abs(this.target - this.gust) < 5) this.state = "decay";
    } else if (this.state === "decay") {
      this.gust *= Math.pow(0.5, dt / 0.9);     // 반감기 0.9초
      if (Math.abs(this.gust) < 2) {
        this.gust = 0; this.state = "idle"; this.timer = rand(3, 8);
      }
    }
    this.turb = this.noise(this.t * 0.7) * 40;  // 난류는 다음 슬라이드
  },
  get value() { return this.base + this.gust + this.turb; }
};

난류: 1D 밸류 노이즈

  • Math.random()을 매 프레임 더하면 지글지글 떨리기만 한다 — 부드럽게 "변하는" 랜덤이 필요하다.
  • 밸류 노이즈: 정수 지점마다 고정된 랜덤값을 두고, 그 사이를 부드럽게 보간한다.
  • 고정 랜덤값은 sin 해시로 만든다 — 같은 n에는 항상 같은 값이 나오는 유사 난수.
  • 보간은 smoothstep 곡선을 쓴다. 직선 보간은 꼭짓점에서 꺾여 바람이 "덜컹"거린다.
u = f² · (3 − 2f)  (smoothstep)
noise(t) = hash(⌊t⌋) · (1−u) + hash(⌊t⌋+1) · u

노이즈 코드

wind 객체에 두 메서드를 추가한다. 반환 범위는 대략 −0.5 ~ +0.5.

hash(n) {   // n → 항상 같은 유사 난수 (셰이더에서 빌려온 고전 기법)
  const s = Math.sin((n + this.seed) * 127.1) * 43758.5453;
  return s - Math.floor(s) - 0.5;
},

noise(t) {  // 정수 격자 사이를 smoothstep으로 보간
  const i = Math.floor(t), f = t - i;
  const u = f * f * (3 - 2 * f);
  return this.hash(i) * (1 - u) + this.hash(i + 1) * u;
}
  • this.noise(this.t * 0.7) — 0.7은 난류가 변하는 속도. 키우면 신경질적인 바람이 된다.
  • seed 덕분에 새로고침할 때마다 다른 바람 패턴이 나온다.

  }

[데모] 바람 부는 눈

위쪽 금색 게이지가 현재 바람 세기다. 자동 돌풍을 기다리거나 버튼으로 즉시 불러 보라.

3장 요약

  • 바람 = base(상수) + gust(상태 기계) + turb(노이즈).

  • 파티클은 wind.value 하나만 읽고, 크기에 비례해 반응한다.

하이트맵: 화면을 세로 기둥으로

  • 쌓인 눈을 파티클 수만 개로 유지하면 금방 느려진다 — 착지한 눈은 높이 숫자로 압축한다.
  • 화면 가로를 COL(4px) 폭의 기둥으로 나누고, 기둥마다 쌓인 높이 하나만 기억한다.
  • ground[i] = i번째 기둥에 쌓인 눈의 높이(px). 배열 하나가 설경 전체다.
  • 기둥 폭 4px는 "지형의 해상도"다. 좁으면 뾰족뾰족, 넓으면 뭉툭해진다.
  • 같은 구조를 벚꽃 더미(8장)도 쓴다 — 거기선 개별 꽃잎 그림을 얹는 점만 다르다.

초기화와 리사이즈

기둥 개수는 화면 폭에 달려 있으므로 resize에서 함께 만든다.

const COL = 4;          // 기둥 폭 (px)
let ground;             // Float32Array — 기둥별 눈 높이

// x좌표 → 기둥 번호 (범위 밖 클램프)
const colOf = x =>
  Math.max(0, Math.min(ground.length - 1, Math.round(x / COL)));
  • Float32Array: 소수점 높이를 다루면서 일반 배열보다 가볍고 빠르다.
  • 리사이즈하면 쌓인 눈이 사라진다 — 새 화면 폭에 맞춰 다시 쌓이게 두는 게 가장 단순하고 안전하다.

착지 판정

착지 조건: y + r ≥ H − ground[col]
  • 바닥은 이제 화면 끝(H)이 아니라 "H에서 그 기둥의 눈 높이를 뺀 곳"이다.
  • 즉 눈이 쌓일수록 다음 눈은 더 높은 곳에 착지한다 — 이 재귀 덕분에 언덕이 자란다.
  • 착지하면: ① 그 기둥 높이를 올리고 ② 눈송이는 위에서 재활용.
  • 더하는 두께는 r × 0.55 — 큰 눈송이가 더 두껍게 쌓인다. 0.55는 화면을 채우는 속도를 정하는 튜닝값.
  • 상한 H × 0.6을 두어 화면의 6할 이상은 쌓이지 않게 막는다.

착지 코드

function step(dt) {
  wind.update(dt);
  for (const f of flakes) {
    // ... 2~3장의 위치 갱신 ...
    const col = colOf(f.x);
    if (f.y + f.r >= H - ground[col]) {   // 눈 표면에 닿았다
      if (ground[col] < H * 0.6)
        ground[col] += f.r * 0.55;        // 쌓임!
      newFlake(f);                        // 눈송이는 위에서 환생
    } else if (f.y - f.r > H) {

흘러내림 — 단차 완화

  • 착지만 구현하면 랜덤 편차가 누적되어 빗살무늬 스파이크가 생긴다. 진짜 눈은 옆으로 흘러내려 완만한 능선을 만든다.
  • 모래 더미 알고리즘의 1차원판: 이웃 기둥과의 단차가 문턱(5px)을 넘으면 차이의 15%를 옆으로 옮긴다.
  • 매 프레임 2회 반복이면 충분히 부드럽다. 문턱을 낮추면 평평하게, 높이면 뾰족하게 쌓인다 — "눈의 점도" 다이얼.
d = h[i] − h[i+1]
|d| > 5 이면  h[i] ← h[i] − 0.15d,  h[i+1] ← h[i+1] + 0.15d

흘러내림 코드

d의 부호가 이동 방향을 알아서 정한다 — 높은 쪽에서 낮은 쪽으로.

function relax() {
  for (let k = 0; k < 2; k++)               // 프레임당 2패스
    for (let i = 0; i < ground.length - 1; i++) {
      const d = ground[i] - ground[i + 1];
      if (Math.abs(d) > 5) {                // 안식각을 넘는 단차만
        ground[i]     -= d * 0.15;
        ground[i + 1] += d * 0.15;
      }
    }
}
  • 총량이 보존된다(빼준 만큼 더한다) — 눈이 새거나 불어나지 않는다.
  • 왼쪽→오른쪽 순회라 미세한 방향 편향이 있지만 눈으로는 구분되지 않는다.

녹음 모델: 상수항 + 비례항

h ← max(0, h − (0.4 + 0.03·h) · melt · dt)
  • 상수항 0.4 — 두께와 무관한 기본 녹음. 얇게 남은 눈을 확실히 지워 지저분한 잔설을 없앤다.
  • 비례항 0.03·h — 두꺼운 곳이 더 빨리 줄어든다. 높은 언덕부터 낮아져 시각적으로 자연스럽다.
  • melt — 온도 다이얼(px/초 스케일). 0이면 한겨울, 4면 봄볕.
  • max(0, …)를 빼먹으면 높이가 음수가 되어 능선이 화면 아래로 뚫고 내려간다 — 필수.
  • relax()는 녹는 중에도 계속 돌린다 — 녹아서 생긴 단차도 흘러내려 능선이 계속 매끈하다.

녹음 코드

step() 끝에 서너 줄 추가가 전부다.

let melt = 1.2;    // 온도 다이얼: 0 = 안 녹음, 4 = 봄볕

function meltStep(dt) {
  for (let i = 0; i < ground.length; i++)
    ground[i] = Math.max(0,
      ground[i] - (0.4 + ground[i] * 0.03) * melt * dt);
}

function step(dt) {
  // ... 낙하 · 착지 · relax ...
  meltStep(dt);
}
  • 모든 항에 dt가 곱해져 있으므로 프레임레이트와 무관하게 같은 속도로 녹는다.

내림과 녹음의 평형

  • 눈이 내리면서 동시에 녹으면, 쌓이는 속도 = 녹는 속도가 되는 높이에서 저절로 멈춘다.
  • 유입은 일정한데 유출(비례항)은 높이에 비례하니, 어느 높이에서 반드시 균형이 맞는다
  • 이 평형이 실전에서 대단히 유용하다: 몇 시간 켜 두는 배경 화면이 화면을 다 덮어버리지 않는다.
  • 온도를 올리면 평형 높이가 낮아지고, 0으로 내리면 상한(H×0.6)까지 계속 쌓인다.
  • 다음 데모에서 슬라이더로 직접 평형점을 움직여 보라.

확장: 젖은 바닥과 물웅덩이

  • 더 욕심을 내면 — 녹은 양을 버리지 않고 두 번째 하이트맵 water[]에 적립한다.
  • water는 relax의 문턱을 0으로(물은 완전히 평평해질 때까지 흐른다), 이동 비율을 크게(점도 낮음).
  • 그리기는 반투명한 어두운 파랑 — 쌓인 눈 아래에 얇게 깔면 젖은 아스팔트 느낌이 난다.
  • 증발까지: water에도 작은 감쇠를 걸면 웅덩이가 서서히 마른다.
  • 이 자료의 완성 코드에는 넣지 않았다 — 구조가 같으므로 연습 과제로 남긴다.

미리 쌓아 둔 언덕이 녹는다. 온도를 조절해 "내림 vs 녹음"의 평형 높이가 변하는 것을 확인해 보라.

      this.gust *= Math.pow(0.5, dt / 0.9);
      if (Math.abs(this.gust) < 2) {
        this.gust = 0; this.state = "idle"; this.timer = rand(3, 8);
      }
    }
    this.turb = this.noise(this.t * 0.7) * 40;
  },
  get value() { return this.base + this.gust + this.turb; }
};

눈 vs 꽃잎: 낙하 물리의 차이

  • 눈송이는 거의 점이다: 똑바로, 조금 흔들리며 내린다.
  • 꽃잎은 납작한 판이다: 공기를 받는 면적이 방향에 따라 크게 달라진다.
  • 수평에 가까울 때 — 낙하산처럼 천천히, 옆으로 미끄러지며
  • 수직에 가까울 때 — 칼날처럼 쑥 떨어진다
  • 그래서 꽃잎은 "그네 타듯" 좌우로 크게 왕복하며(진자), 동시에 몸을 뒤집는다(텀블링).
  • 유체역학을 풀 필요는 없다 — 결과로 보이는 세 가지 운동(진자·뒤집힘·속도 변조)만 삼각함수로 흉내 낸다.

'하늘하늘'의 정체 — 세 개의 위상

  • swayPhase — 좌우 진자. cos을 속도에 더해 크게 왕복한다 (진폭 20~45px/초).
  • tumble — 공중 뒤집힘. 그리기의 납작함(squash)과 낙하 속도를 함께 흔든다.
  • rot — 꽃잎 자체의 회전(빙글빙글). 순수하게 시각용.
  • 세 위상이 서로 다른 주기로 돌기 때문에 움직임이 절대 반복처럼 보이지 않는다.
x ← x + [cos(swayPhase)·A + wind·0.9 + vx] · dt
y ← y + vy · (0.6 + 0.4·|cos(tumble)|) · dt

낙하 속도 변조

  • y 공식의 (0.6 + 0.4·|cos(tumble)|) 항이 "낙하산 ↔ 칼날" 전환이다.
  • cos(tumble) = ±1 (꽃잎이 세로로 선 순간) → 계수 1.0, 빠르게 낙하
  • cos(tumble) = 0 (꽃잎이 수평으로 누운 순간) → 계수 0.6, 천천히 낙하
  • 그리기의 납작함도 같은 tumble을 쓰므로 "납작하게 보일 때 = 느리게 떨어질 때"가 저절로 일치한다.
  • 기본 낙하 속도 vy는 18~34px/초 — 눈(20~97)보다 확연히 느리다. 꽃잎은 가볍고 넓적하니까.
  • vx는 돌풍에 튕겨나갈 때 쓰는 수평 관성(8장). 평소엔 0이다.

  p.y = anywhere ? rand(-H, 0) : rand(-40, -10);
  p.vx = 0;                          // 돌풍 관성 (8장)

  p.swayPhase = rand(0, Math.PI * 2);
  p.swayFreq  = rand(1.2, 2.4);      // 진자 주기: 2.6~5.2초에 1왕복
  p.swayAmp   = rand(20, 45);

  p.rot    = rand(0, Math.PI * 2);
  p.rotSpd = rand(-1.5, 1.5);        // 시계/반시계 반반
  p.size = rand(5, 9);

function step(dt) {
  wind.update(dt);
  for (const p of petals) {
    p.swayPhase += p.swayFreq  * dt;
    p.tumble    += p.tumbleSpd * dt;
    p.rot       += p.rotSpd    * dt;
    p.vx *= Math.pow(0.25, dt);              // 돌풍 관성 감쇠 (8장)
    p.vyCur += (p.vy - p.vyCur) * 1.8 * dt;  // 종단 속도로 복귀 (8장)

    const sway = Math.cos(p.swayPhase) * p.swayAmp;
    p.x += (sway + wind.value * 0.9 + p.vx) * dt;
    p.y += p.vyCur * (0.6 + 0.4 * Math.abs(Math.cos(p.tumble))) * dt;

    if (p.x < -40) p.x += W + 80;
    else if (p.x > W + 40) p.x -= W + 80;
    if (p.y > H + 40) newPetal(p);   // 착지는 8장에서 교체
  }
}

function drawPetal(x, y, rot, size, tint, squash) {
  ctx.save();
  ctx.translate(x, y);
  ctx.rotate(rot);
  ctx.scale(1, squash);              // 뒤집힘 — 다음 슬라이드

                + (86 - tint * 9) + "%)";
  ctx.beginPath();
  ctx.moveTo(0, s);                                  // 밑동
  ctx.bezierCurveTo(-s*0.9, s*0.6,  -s*0.85, -s*0.5,
                    -s*0.18, -s*0.95);               // 왼쪽 → 홈 왼끝
  ctx.quadraticCurveTo(0, -s*0.6,  s*0.18, -s*0.95); // V자 홈
  ctx.bezierCurveTo( s*0.85, -s*0.5,  s*0.9, s*0.6,
                     0, s);                          // 오른쪽 → 밑동
  ctx.fill();
  ctx.restore();
}

착지 꽃잎 저장: 하이트맵 + 스프라이트

  • 눈은 착지하면 "높이 숫자"로 녹아들었다. 꽃잎은 개별 형태가 보여야 하므로 그대로는 안 된다.

  • landed[] — 그리기용 스프라이트 목록 {x, y, rot, size, tint}

돌풍 이벤트 — 눈의 wind 재사용

  • 새로 만들 것이 없다. 3장의 wind 상태 기계가 이미 "랜덤 시점에, 랜덤 세기·방향으로" 돌풍을 만들어 준다.
  • 날리는 꽃잎은 wind.value를 통해 이미 돌풍에 반응한다.
  • 남은 문제: 쌓인 꽃잎이다 — 돌풍이 충분히 강할 때(|gust| > 45) 더미에서 꽃잎을 뽑아 다시 하늘로 던진다.
  • 뽑는 수량을 돌풍 세기에 비례시키면, 약한 돌풍은 몇 장만 굴리고 강한 돌풍은 더미를 쓸어간다.
  • 이것이 요구사항 "랜덤하게 바람이 불어 흩날리면서 쌓인 게 줄어드는" 효과의 전부다.

흩날림(scatter): 더미에서 하늘로

function scatter(dt) {
  const power = Math.abs(wind.gust);
  if (power < 45 || landed.length === 0) return;

  let n = Math.min(landed.length,
                   Math.ceil(power * dt * 0.35));  // 세기 비례 수량
  while (n-- > 0) {
    const i = Math.floor(Math.random() * landed.length);
    const L = landed.splice(i, 1)[0];      // 더미에서 제거
    const c = colOf(L.x);
    ground[c] = Math.max(0, ground[c] - THICK);  // 더미 높이 감소!

    const p = newPetal({});
    p.x = L.x;  p.y = L.y;
    p.size = L.size;  p.tint = L.tint;     // 같은 꽃잎이 날아오른다
    p.vx = Math.sign(wind.value) * rand(60, 160); // 바람 방향으로 튕김
    p.vyCur = -rand(30, 90);               // 위로 떠오름
    petals.push(p);
  }
}

재이륙 후의 물리

  • 7장 step에 미리 심어 둔 두 줄이 여기서 빛을 발한다:
  • p.vx *= 0.25^dt — 튕겨나간 수평 관성이 약 1초 만에 잦아든다
  • p.vyCur += (p.vy − p.vyCur)·1.8·dt — 음수(상승)로 시작한 수직 속도가 종단 낙하 속도로 부드럽게 복귀
  • 결과: 확 날아올랐다가 → 호를 그리며 감속 → 다시 하늘하늘 낙하 → 재착지. 별도 분기 없이 같은 공식이 전 과정을 처리한다.
  • 개수 관리: scatter가 petals를 늘리므로, 착지 시 petals.length가 기준(90)을 넘으면 환생 대신 제거해 서서히 원래 개수로 돌아간다.
vx ← vx · 0.25^dt    vyCur ← vyCur + (vy − vyCur)·1.8·dt

[데모] 돌풍에 흩날리는 꽃잎 더미

꽃잎이 쌓이길 기다렸다가 돌풍 버튼을 눌러 보라 — 더미가 흩날리며 줄어들고, 날아간 꽃잎은 다시 쌓인다.

8장 요약

  • 쌓인 꽃잎 = 하이트맵(충돌) + 스프라이트 목록(그리기)의 이중 구조. 항상 둘을 같이 갱신한다.
  • 돌풍은 3장 상태 기계 재사용. |gust| > 45일 때 세기에 비례한 수량을 더미에서 뽑는다.
  • 뽑힌 꽃잎: 하이트맵 높이를 빼고(더미 감소), 바람 방향 관성 + 상승 속도로 재이륙.
  • 관성 감쇠와 종단 속도 복귀 두 줄이 재이륙~재착지 전 과정을 자동 처리한다.

const petals = [];
const BASE_COUNT = 90;

function newPetal(p = {}, anywhere = false) {
  p.x = rand(-20, W + 20);
  p.y = anywhere ? rand(-H, 0) : rand(-40, -10);
  p.vx = 0;
  p.vy = rand(18, 34);
  p.vyCur = p.vy;
  p.swayPhase = rand(0, Math.PI * 2);
  p.swayFreq  = rand(1.2, 2.4);
  p.swayAmp   = rand(20, 45);
  p.tumble    = rand(0, Math.PI * 2);
  p.tumbleSpd = rand(1.5, 3.5);
  p.rot    = rand(0, Math.PI * 2);
  p.rotSpd = rand(-1.5, 1.5);
  p.size = rand(5, 9);
  p.tint = Math.random();
  return p;
}
for (let i = 0; i < BASE_COUNT; i++) petals.push(newPetal({}, true));

전체 코드 4/8 — 돌풍 흩날림

function scatter(dt) {
  const power = Math.abs(wind.gust);
  if (power < 45 || landed.length === 0) return;
  let n = Math.min(landed.length, Math.ceil(power * dt * 0.35));
  while (n-- > 0) {
    const i = Math.floor(Math.random() * landed.length);
    const L = landed.splice(i, 1)[0];
    const c = colOf(L.x);
    ground[c] = Math.max(0, ground[c] - THICK);
    const p = newPetal({});
    p.x = L.x;  p.y = L.y;
    p.size = L.size;  p.tint = L.tint;
    p.vx = Math.sign(wind.value) * rand(60, 160);
    p.vyCur = -rand(30, 90);
    petals.push(p);
  }
}

전체 코드 5/8 — step: 플러터

function step(dt) {
  wind.update(dt);
  scatter(dt);
  for (let i = petals.length - 1; i >= 0; i--) {
    const p = petals[i];
    p.swayPhase += p.swayFreq  * dt;
    p.tumble    += p.tumbleSpd * dt;
    p.rot       += p.rotSpd    * dt;
    p.vx *= Math.pow(0.25, dt);
    p.vyCur += (p.vy - p.vyCur) * 1.8 * dt;

    const sway = Math.cos(p.swayPhase) * p.swayAmp;
    p.x += (sway + wind.value * 0.9 + p.vx) * dt;
    p.y += p.vyCur * (0.6 + 0.4 * Math.abs(Math.cos(p.tumble))) * dt;

    if (p.x < -40) p.x += W + 80;
    else if (p.x > W + 40) p.x -= W + 80;

전체 코드 7/8 — 꽃잎 모양

function drawPetal(x, y, rot, size, tint, squash) {
  ctx.save();
  ctx.translate(x, y);
  ctx.rotate(rot);
  ctx.scale(1, squash);
  const s = size;
  ctx.fillStyle = "hsl(" + (338 + tint * 14) + ", 85%, "
                + (86 - tint * 9) + "%)";
  ctx.beginPath();
  ctx.moveTo(0, s);
  ctx.bezierCurveTo(-s*0.9, s*0.6, -s*0.85, -s*0.5, -s*0.18, -s*0.95);
  ctx.quadraticCurveTo(0, -s*0.6, s*0.18, -s*0.95);
  ctx.bezierCurveTo( s*0.85, -s*0.5,  s*0.9, s*0.6, 0, s);
  ctx.fill();
  ctx.restore();
}

전체 코드 8/8 — draw와 루프

function draw() {
  ctx.clearRect(0, 0, W, H);
  for (const L of landed)
    drawPetal(L.x, L.y, L.rot, L.size, L.tint, 0.45);
  for (const p of petals) {
    const squash = 0.35 + 0.65 * Math.abs(Math.sin(p.tumble));
    drawPetal(p.x, p.y, p.rot + Math.sin(p.swayPhase) * 0.5,
              p.size, p.tint, squash);
  }
}

let last = performance.now();
function loop(now) {
  const dt = Math.min(0.05, (now - last) / 1000);
  last = now;
  step(dt);  draw();
  requestAnimationFrame(loop);
}
requestAnimationFrame(loop);

모바일 대응과 마무리

갤럭시 폴드7에서 매끄럽게 — 그리고 다음 아이디어

갤럭시 폴드7 대응 체크리스트

  • 뷰포트: meta viewport + viewport-fit=cover, 높이는 100dvh — 주소창이 숨을 때 레이아웃 점프 방지.
  • 안전 영역: env(safe-area-inset-*) 패딩 — 펀치홀·제스처 바에 UI가 가리지 않게.
  • DPR: Math.min(devicePixelRatio, 2) — 폴드7 내부 화면은 DPR이 높다. 2로 캡해도 눈으로 차이가 없고 픽셀 수는 절반 이하.
  • 접힘 전환: 커버 ↔ 메인 화면 전환 시 resize 이벤트가 온다 — 이 자료의 resize()가 버퍼·하이트맵을 다시 만들므로 그대로 대응된다.
  • 폴더블 힌지: @media (horizontal-viewport-segments: 2)로 힌지에 걸리는 다단 레이아웃을 1단으로.
  • 터치: 캔버스에 touch-action: pan-y — 데모를 만져도 세로 스크롤이 막히지 않는다.

성능 최적화 팁

  • 파티클 수를 화면 넓이에 비례시켜라: count = W × H / 4000 정도. 커버 화면(좁음)에서는 저절로 줄어든다.
  • 드로우 콜 병합: 같은 색 파티클은 한 beginPath에 모아 fill 1번 (2장). 눈 220개 = 드로우 콜 1개.
  • shadowBlur 금지: 파티클마다 그림자는 모바일 GPU 킬러다. 흐림은 globalAlpha나 그라디언트로.
  • save/restore는 벚꽃처럼 변환이 필요한 곳에만. 눈처럼 원만 찍을 땐 쓰지 않는다.
  • 보이지 않을 때 멈추기: rAF는 백그라운드 탭에서 자동 정지하지만, 스크롤 밖 캔버스는 IntersectionObserver로 직접 멈춰야 한다.
  • prefers-reduced-motion 사용자에게는 파티클 수를 줄이거나 정지 화면을 제공하는 배려도 좋다.

확장 아이디어

  • 🌧️ 비: 눈에서 sway를 0으로, vy를 400~700으로, 원 대신 짧은 세로 선. 착지 시 파문 원 2~3프레임.
  • 🍂 낙엽: 벚꽃 코드에서 색만 갈색·주황 계열로, size를 키우고 tumbleSpd를 줄이면 끝.
  • 🌫️ 깊이 레이어: 파티클을 2~3층으로 나눠 뒷층은 작고 흐리고 느리게 — 시차(parallax)가 생긴다.
  • 💧 물웅덩이: 5장의 확장 — 녹은 눈을 두 번째 하이트맵에 적립.
  • 🌀 2D 바람장: wind.value를 위치의 함수 noise(x, t)로 바꾸면 화면 곳곳이 다르게 분다.
  • ✨ 반딧불: 낙하 대신 노이즈 2개로 x·y를 각각 표류시키고 밝기를 sin으로 깜빡이면 된다.
