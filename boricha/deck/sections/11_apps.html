func (m Model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg := msg.(type) {
    case tea.WindowSizeMsg:            // ① 크기가 오면 부품 크기를 다시 잡는다
        m.w, m.h = msg.Width, msg.Height
        return m.resize(), nil

    case tea.ColorProfileMsg:          // ② 색 수준이 오면 스타일에 심는다
        m.prof = msg.Profile
        m.help = m.help.Profile(msg.Profile)
        return m, nil

    case 앱마다_다른_사건:             // ③ 명령이 돌려준 결과
        ...

    case tea.KeyMsg:                   // ④ 키
        ...
    }

    var cmd tea.Cmd                    // ⑤ 나머지는 초점이 있는 부품에게
    m.부품, cmd = m.부품.Update(msg)
    return m, cmd
}

세 앱이 다른 것은 ③과 ④뿐이다. 나머지 넷은 어떤 보리차 앱이든 같다. 이 뼈대를 외워 두면 새 앱을 시작할 때 빈 화면 앞에서 멈추지 않는다.

CPU 사용률은 한 번 읽어서는 알 수 없다

세 앱이 공통으로 보이는 것

  1. 순수하지 않은 일은 전부 명령으로. 파일 쓰기도, /proc 읽기도, 시계도 Update 밖에 있다.
  2. 상태의 출처는 하나. 할 일은 tasks, 모니터는 cur, 전시장은 tab. 부품에 담긴 것은 그 하나에서 나온 사본이다.
  3. 슬라이스·맵은 손수 복사. 할 일과 전시장에 append(append([]T{}, old...), new) 꼴이, 모니터의 push 에는 새 슬라이스를 만드는 같은 조심이 나온다. 값 의미론의 대가다.
  4. 시간을 바꿀 수 있게. SetInterval·SetSpinner 는 시험과 기록을 위한 문이고, 그것이 없으면 이 앱들의 시험이 20초를 먹는다.
