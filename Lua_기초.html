이 덱은 무엇인가

《Lua로 만드는 GW-BASIC 인터프리터》는 약 3,000줄의 Lua 코드를 처음부터 끝까지 읽어 나가는 책입니다. 그런데 그 책의 3장 제목은 “Lua를 빠르게 복습하기”입니다. 복습이라는 말이 붙었다는 건, 이미 안다고 가정한다는 뜻입니다.

이 덱은 그 빈칸을 메웁니다. 목표는 딱 하나입니다.

목표 — 그 책에 나오는 Lua 코드를 막힘없이 읽을 수 있게 만드는 것.

그래서 Lua의 모든 것을 다루지 않습니다. 그 책에 실제로 나오는 문법만 골라, 필요한 순서대로 배웁니다.

기준 — 오른쪽 항목들은 그 책의 코드에 한 번도 나오지 않습니다. 나중에 필요해지면 그때 배워도 늦지 않습니다.

전제로 하는 것

프로그래밍을 한 번이라도 해 봤다면 충분합니다. 변수, if, 반복문, 함수라는 말이 낯설지 않으면 됩니다. C, Python, JavaScript, 심지어 BASIC이라도 좋습니다.

Lua는 문법이 대단히 작은 언어입니다. 예약어가 22개뿐이고, 자료구조는 테이블 하나뿐입니다. 그래서 “언어를 배우는” 시간이 짧고, 대신 관용구를 익히는 시간이 깁니다. 이 덱은 뒤쪽에 무게를 둡니다.

팁 — 터미널에 lua만 치면 대화형 셸이 뜹니다. 이 덱의 예제는 거의 전부 거기 그대로 붙여 넣어 확인할 수 있습니다.

이 덱을 끝내면 읽히는 코드

아래는 그 책 6장에 나오는 진짜 코드입니다. 지금은 절반쯤 외계어로 보여도 정상입니다.

function Lexer:peek(off)
  off = off or 0
  return self.src:sub(self.pos + off, self.pos + off)
end

function Lexer:advance()
  local c = self:peek()
  self.pos = self.pos + 1
  if c == "\n" then self.line = self.line + 1 end
  return c
end

여기 들어 있는 개념은 메서드 정의 :, self, or 기본값 관용구, 문자열 메서드 호출 s:sub(), 1부터 시작하는 인덱스, 그리고 테이블 필드입니다. 전부 이 덱에서 다룹니다.

Lua라는 도구

어떤 언어이고, 어디서 왔고, 어떻게 돌리는가

1장

Lua란 무엇인가

“작다”는 것이 이 언어의 설계 목표이자 정체성입니다.

1.1 한 문단 요약

Lua는 브라질 리우데자네이루 가톨릭대학교(PUC-Rio)에서 1993년에 만들어진 스크립트 언어입니다. 이름은 포르투갈어로 “달”이라는 뜻이고, 약자가 아니므로 LUA가 아니라 Lua로 씁니다.

목적다른 프로그램에 끼워 넣기 위한 언어. 처음부터 “호스트 애플리케이션의 설정·확장 언어”로 설계되었습니다.
크기표준 배포판 전체가 C 소스 3만 줄 남짓. 빌드된 인터프리터가 수백 KB 수준입니다.
구현ANSI C로 작성. C 컴파일러만 있으면 어디서든 빌드됩니다.
라이선스MIT 라이선스. 상용 제품에 그대로 넣을 수 있습니다.
실행 방식소스를 바이트코드로 컴파일한 뒤 레지스터 기반 VM에서 실행합니다.
재미있는 우연 — 우리가 만들 GW-BASIC 인터프리터도 “소스를 바이트코드로 컴파일해 VM에서 실행”합니다. Lua 자신이 하는 일을, Lua로 한 겹 더 하는 셈입니다.

1.2 어디에 쓰이나

“임베디드 스크립트 언어”라는 자리를 사실상 독점하고 있습니다.

  • 게임 — 로블록스, 월드 오브 워크래프트 UI, 앵그리버드, 그리고 수많은 게임 엔진의 스크립트 계층
  • 네트워크 — Nginx의 OpenResty 모듈, HAProxy, Wireshark 프로토콜 분석기
  • 편집기/도구 — Neovim의 설정·플러그인 언어, Redis 서버 사이드 스크립트
  • 임베디드 — NodeMCU 같은 마이크로컨트롤러 펌웨어

공통점이 보입니다. 이미 C/C++로 짜인 큰 프로그램이 있고, 그 위에 “사용자가 고쳐 쓸 수 있는 얇은 층”이 필요할 때 Lua가 들어갑니다.

그래서 — Lua는 “혼자 쓰는 언어”로 설계되지 않았습니다. 표준 라이브러리가 작은 것도 그 때문입니다. 파일 I/O와 문자열, 수학, 그리고 끝입니다. HTTP도, JSON도, 정규식도 기본으로는 없습니다.

1.3 버전 지도

Lua는 버전 간 호환성을 과감히 깹니다. 5.1과 5.4는 사실상 사촌 언어에 가깝습니다. 어떤 버전을 쓰는지 항상 의식해야 합니다.

5.1 2006가장 오래 쓰인 판. LuaJIT이 이 버전과 호환됩니다. 로블록스·WoW·많은 게임이 여기 머물러 있습니다.
5.2 2011goto 추가, _ENV 도입, module() 함수 폐지.
5.3 2015정수 타입 분리(가장 큰 변화), 비트 연산자 & | ~ << >>, 정수 나눗셈 //.
5.4 2020~새 GC 모드, <const>​/​<close> 속성. 현재 최신 계열(5.4.8).
이 책의 선택 — 《Lua로 만드는 GW-BASIC 인터프리터》는 5.1을 최저선으로 잡습니다. 즉 goto도, //도, 비트 연산자도 쓰지 않고, 그 대신 math.floor(a/b)와 직접 만든 band​/​bor 함수를 씁니다. 5.4에서도 그대로 돕니다.

1.4 왜 인터프리터를 Lua로 짜는가

인터프리터 구현 교재는 보통 C, Java, Python, TypeScript로 쓰입니다. Lua는 흔한 선택이 아닙니다. 그런데 잘 맞는 이유가 있습니다.

테이블 하나면 끝토큰, AST 노드, 명령어, 환경, 호출 스택이 전부 테이블입니다. 클래스 선언도, 구조체 정의도 필요 없습니다.
디스패치가 공짜명령어 이름 → 함수 테이블이 곧 VM의 디스패치 표입니다. self.handlers[op.op](self, op) 한 줄.
빌드 단계 없음고치고 저장하고 lua main.lua. 컴파일 대기 시간이 0입니다.
스스로가 좋은 예시Lua 자체가 “렉서 → 파서 → 바이트코드 → VM” 구조입니다. 우리가 만들 것과 같은 모양입니다.
단점도 분명합니다 — 타입 검사가 없어 오타가 런타임까지 살아남고, nil이 조용히 퍼집니다. 그래서 이 덱은 Lua에서 실수하기 쉬운 지점을 반복해서 짚습니다.

1.5 첫인상 — 문법 한눈에

설명은 뒤로 미루고, 모양만 봅니다. 대부분 짐작이 갈 것입니다.

-- 주석은 하이픈 두 개
local name = "GW-BASIC"        -- 지역 변수
local nums = {10, 20, 30}      -- 테이블(배열처럼)

for i = 1, #nums do            -- 1부터 nums의 길이까지
  print(i, nums[i])            -- 인덱스는 1부터!
end

local function greet(who)
  return "Hello, " .. who      -- .. 이 문자열 연결
end

if #name > 3 and name ~= "" then   -- ~= 이 "같지 않다"
  print(greet(name))
end

다른 언어에서 온 사람이 가장 자주 걸려 넘어지는 세 가지를 미리 못 박아 둡니다.

~=“같지 않다”. !=는 문법 오류입니다.
..문자열 연결. +는 숫자 덧셈 전용입니다.
nums[1]배열의 첫 칸은 1번입니다. 0번이 아닙니다.

1.6 Lua에 없는 것들

다른 언어를 하다 온 사람에게는 “없다”는 사실 자체가 정보입니다. 찾다가 시간을 버리지 않도록 미리 나열합니다.

클래스없습니다. 테이블 + 메타테이블로 흉내냅니다 (37장).
배열/딕셔너리 구분없습니다. 둘 다 테이블입니다 (14장).
정규식없습니다. 훨씬 작은 패턴이라는 자체 문법이 있습니다 (31장).
continue없습니다. 5.2+의 goto continue나 if 뒤집기로 우회합니다.
++, +=없습니다. i = i + 1이라고 다 씁니다.
삼항 연산자없습니다. cond and a or b 관용구를 씁니다 (함정 있음 — 6장).
예외 try/catch없습니다. pcall(f)이 그 역할입니다 (41장).
정수 타입 5.15.1에는 없습니다. 모든 숫자가 double입니다 (7장).
switch없습니다. elseif 사슬이나 함수 테이블로 대신합니다 — 이 책의 VM이 후자를 씁니다.

1.7 예약어 전부

Lua 5.1의 예약어는 21개, 5.2에서 goto가 더해져 22개입니다. 이게 전부입니다. 한 화면에 다 들어갑니다.

and       break     do        else      elseif
end       false     for       function  goto
if        in        local     nil       not
or        repeat    return    then      true
until     while
여기 없는 것들에 주목하세요. class, new, try, switch, import, var, const, public — 전부 예약어가 아닙니다. print, type, pairs도 예약어가 아니라 그냥 전역 변수에 담긴 함수입니다. 덮어쓸 수도 있습니다(권하지는 않습니다).
goto는 5.1에서 예약어가 아닙니다. 그래서 5.1용 코드에서는 goto를 변수 이름으로 쓸 수 있고, 5.2+에서는 그 코드가 깨집니다. 이 책이 goto를 안 쓰는 이유이기도 합니다.

2.2 세 가지 실행 방법

  1. 파일 실행 — lua hello.lua. 인터프리터가 파일을 컴파일하고 즉시 실행한 뒤 종료합니다.
  2. 대화형 셸(REPL) — 인자 없이 lua. 한 줄씩 쳐 보며 실험합니다.
  3. 한 줄 실행 — lua -e 'print(1+1)'. 스크립트를 만들지 않고 표현식만 확인할 때.
$ lua -e 'print(1+1)' 2 $ lua Lua 5.4.8 Copyright (C) 1994-2025 Lua.org, PUC-Rio > print("hi") hi > 1 + 1 -- 5.3+ REPL은 식만 써도 값을 보여 준다 2 > os.exit() -- 또는 Ctrl-D
5.1의 REPL에서는 1 + 1만 치면 문법 오류입니다. =1+1처럼 등호를 앞에 붙이거나 print(1+1)이라고 써야 합니다.

그 책에는 별도의 빌드 단계가 없습니다. 소스를 그대로 실행합니다.

2.4 첫 프로그램

hello.lua라는 파일을 만들고 아래를 넣습니다.

hello.lua

local name = "world"
print("Hello, " .. name .. "!")
print("길이:", #name)
$ lua hello.lua Hello, world! 길이: 5

여기서 벌써 몇 가지가 드러납니다.

  • print는 인자를 탭 문자로 구분해 출력하고 줄바꿈을 붙입니다. 서식이 필요하면 string.format이나 io.write를 씁니다 (30·44장).
  • 문장 끝에 세미콜론이 필요 없습니다. 써도 되지만 아무도 쓰지 않습니다.
  • #name은 문자열의 바이트 수입니다. 문자 수가 아닙니다 (8장).

2.5 주석

한 줄 주석은 하이픈 둘, 여러 줄 주석은 대괄호 둘을 씁니다.

-- 한 줄 주석

--[[
  여러 줄 주석.
  대괄호 둘로 닫습니다.
]]

--[==[
  안에 ]] 가 들어가야 한다면 등호를 끼워 단계를 올립니다.
  이 줄의 ]] 는 이 주석을 닫지 못합니다.
]==]
관용구 — 블록 주석의 여는 쪽을 ---[[로 만들면(하이픈 셋) 그 줄 전체가 한 줄 주석이 되어 블록이 열리지 않습니다. 앞의 하이픈 하나만 지웠다 붙였다 하며 코드 뭉치를 켜고 끌 수 있습니다.
---[[  -- 하이픈 하나를 빼면 아래가 주석 처리됨
print("이 줄은 실행된다")
--]]

2.6 에러 메시지 읽는 법

Lua의 에러 메시지는 짧습니다. 형식만 익혀 두면 됩니다.

lua: hello.lua:2: attempt to concatenate a nil value (global 'nmae') stack traceback: hello.lua:2: in main chunk [C]: in ?

attempt to …무슨 연산을 시도했는지. concatenate(..), index(t.x), call(f()), perform arithmetic(+) 넷이 거의 전부입니다.

3장

여덟 가지 타입

타입은 변수가 아니라 값에 붙어 있습니다.

3.1 전부 여덟 개

type(v)가 돌려줄 수 있는 문자열은 정확히 여덟 가지입니다.

print(type(nil))       --> nil
print(type(true))      --> boolean
print(type(42))        --> number
print(type("hi"))      --> string
print(type({}))        --> table
print(type(print))     --> function
print(type(io.stdout)) --> userdata
print(type(co))        --> thread
매일 쓰는 것nil · boolean · number · string · table · function — 이 여섯이 사실상 전부입니다.
거의 안 쓰는 것userdata는 C 쪽에서 만든 값(파일 핸들 등), thread는 코루틴입니다. 그 책에는 둘 다 나오지 않습니다.
타입은 값에 붙습니다 — 변수에는 타입이 없습니다. 같은 변수에 숫자를 넣었다가 문자열을 넣어도 아무 문제가 없습니다. 그래서 “이 변수에 뭐가 들었더라?”를 컴파일러가 알려 주지 못합니다.

3.2 nil — “값이 없음”

nil은 값이 하나뿐인 타입입니다. 그 자체가 “아무것도 아님”을 뜻합니다.

local x                -- 초기화하지 않으면 nil
print(x)               --> nil

local t = {}
print(t.missing)       --> nil   (없는 필드는 에러가 아니라 nil)
print(undefinedGlobal) --> nil   (선언 안 한 전역도 nil)

t.k = 1
t.k = nil              -- nil을 넣는 것이 곧 "지우기"
Lua에서 nil은 “없음”과 완전히 같은 말입니다. 테이블에 nil을 넣는 것과 키를 지우는 것은 구분되지 않습니다. 그래서 “값이 nil인 항목”은 존재할 수 없습니다.
이것이 대부분의 런타임 에러의 씨앗입니다 — 오타 난 변수도 nil, 빠뜨린 필드도 nil, 반환값을 안 준 함수도 nil. 그 nil이 흘러 흘러 nil에 .field를 붙이는 순간에야 터집니다. 터진 곳과 원인이 멀리 떨어져 있습니다.

3.3 boolean — true와 false

값이 둘뿐인 타입입니다. 특별할 게 없어 보이지만, Lua에서 “거짓”인 값은 false와 nil 둘뿐이라는 규칙이 언어 전체의 성격을 결정합니다.

다른 언어라면 거짓
0        -- Lua에서는 참!
""       -- Lua에서는 참!
{}       -- 참
"false"  -- 참 (문자열이니까)
Lua에서 거짓인 것 전부
false
nil
-- 끝.
C·Python·JavaScript에서 온 사람이 가장 많이 데는 곳입니다. if n ~= 0 then이라고 써야 할 자리에 if n then이라고 쓰면, n이 0이어도 참이 됩니다.

이 규칙은 5장에서 and​/​or 관용구와 함께 자세히 다룹니다.

값을 하나 넣어 보면 type, 참/거짓, tostring, tonumber가 어떻게 나오는지 한눈에 보입니다.

값 하나를 넣어 보세요

3.5 number — 미리 보는 요약

숫자는 6장에서 제대로 다루지만, 지금 알아 둘 것이 하나 있습니다.

5.1 / 5.2숫자는 double 하나뿐입니다. 1과 1.0이 같은 값이고, print(1)은 1을 찍습니다.
5.3 / 5.4integer와 float가 분리됩니다. print(1)은 1, print(1.0)은 1.0입니다. 값으로는 1 == 1.0이 참입니다.
-- Lua 5.4
print(1, 1.0, 10/2)     --> 1    1.0    5.0
print(1 == 1.0)         --> true
print(math.type(1))     --> integer
print(math.type(10/2))  --> float

-- Lua 5.1: 같은 코드가
--> 1    1    5
--  (math.type 자체가 없음)
이 차이가 출력에 새어 나옵니다. GW-BASIC 인터프리터에서 PRINT 10/2가 5여야 하는데 5.4에서 5.0이 나오면 그건 이 문제입니다. 책의 runtime.lua가 숫자를 찍기 전에 정수 여부를 따로 확인하는 이유입니다.

3.6 string — 미리 보는 요약

문자열은 7장에서 다루지만, 성격 두 가지만 먼저 못 박습니다.

  1. 불변(immutable)입니다. 한 글자만 바꾸는 연산은 없습니다. 항상 새 문자열을 만듭니다.
  2. 인터닝(interning)됩니다. 같은 내용의 문자열은 메모리에 하나만 존재하므로, == 비교가 내용 비교이면서도 빠릅니다.
local a = "hello"
local b = "hel" .. "lo"
print(a == b)     --> true   (내용이 같으면 같은 값)

-- a[1] = "H"  같은 문법은 아예 없습니다.
local c = "H" .. a:sub(2)   -- 새로 만드는 수밖에
왜 중요한가 — 어휘 분석기는 문자열을 한 글자씩 훑으며 토큰을 모읍니다. 불변이라서 buf = buf .. c를 반복하면 매번 새 문자열이 생겨 O(n²)가 됩니다. 그래서 책의 lex_string은 local buf = {}에 모았다가 table.concat(buf)을 한 번 부릅니다 (38장).

3.7 table — 유일한 자료구조

Lua에는 배열도, 리스트도, 딕셔너리도, 집합도, 객체도, 클래스도, 구조체도 없습니다. 테이블 하나가 그 전부를 합니다.

local arr  = {1, 2, 3}                 -- 배열처럼
local rec  = {name = "A", age = 10}    -- 레코드처럼
local set  = {apple = true, pear = true}  -- 집합처럼
local dual = {1, 2, 3, name = "A"}     -- 둘을 섞어도 됨

print(#arr, rec.name, dual[2], set.apple)
--> 3    A    2    true

이 사실 하나가 Lua 코드의 모양을 결정합니다. 12장부터 17장까지 여섯 장을 테이블에 쓰는 이유입니다.

책에서는 — 토큰도 테이블 {kind="NUMBER", text="10", line=1}, AST 노드도 테이블 {tag="Binary", op="+", ...}, 바이트코드 명령도 테이블 {op="PUSH", value=10}, VM의 스택도 테이블, 변수 환경도 테이블입니다.

3.8 function — 값으로서의 함수

함수는 일급 값입니다. 변수에 담고, 인자로 넘기고, 테이블에 넣고, 반환할 수 있습니다.

local function add(a, b) return a + b end

local f = add                 -- 변수에 담기
local t = { plus = add }      -- 테이블에 넣기
print(f(1, 2), t.plus(3, 4))  --> 3    7

-- 이름 없는 함수도 그냥 값
local ops = {
  ADD = function(a, b) return a + b end,
  SUB = function(a, b) return a - b end,
}
print(ops["ADD"](10, 5))      --> 15
마지막 모양을 기억해 두세요. “문자열 → 함수” 테이블. 이것이 책의 VM이 명령어를 실행하는 방식입니다. switch문이 없는 대신 이 관용구를 씁니다.

3.9 값의 같음 — ==의 규칙

타입이 다르면 무조건 같지 않습니다. 자동 변환이 일어나지 않습니다.

print(1 == "1")     --> false   (number ≠ string, 변환 없음)
print(1 == 1.0)     --> true    (둘 다 number)
print("a" == "a")   --> true    (내용 비교)

local t1, t2 = {}, {}
print(t1 == t2)     --> false   (내용이 같아도 다른 테이블)
print(t1 == t1)     --> true    (같은 객체일 때만 참)
값 타입nil​·​boolean​·​number​·​string은 내용으로 비교합니다.
참조 타입table​·​function은 동일성으로 비교합니다. 두 테이블의 내용이 같은지 알고 싶으면 직접 순회해 비교하는 함수를 짜야 합니다.
예외 — 메타테이블에 __eq를 달면 테이블끼리의 ==를 바꿀 수 있습니다 (32장). 그 책은 쓰지 않습니다.

4장

변수와 스코프

local을 빠뜨리면 전역이 됩니다 — 이 언어에서 가장 비싼 실수입니다.

4.1 local이 기본이 아니다

Lua에서 선언 없이 이름에 대입하면 전역 변수가 만들어집니다. 경고도, 에러도 없습니다.

✘ 전역 (사고의 근원)
function tokenize(src)
  pos = 1          -- 전역!
  while pos <= #src do
    ...
  end
end

다른 함수가 pos를 쓰면 서로 짓밟습니다. 재귀 호출은 즉시 깨집니다.

✔ 지역
local function tokenize(src)
  local pos = 1
  while pos <= #src do
    ...
  end
end

호출마다 새로 생기고, 함수를 벗어나면 사라집니다.

책의 규칙 — 그 책은 전역을 하나도 만들지 않습니다. 모든 함수는 local이거나 모듈 테이블의 필드입니다. 이건 취향이 아니라 인터프리터를 여러 번 돌려도 상태가 새지 않게 하기 위한 요구 사항입니다.

4.2 전역 변수의 정체

전역 변수는 사실 특별한 것이 아닙니다. _G라는 보통 테이블의 필드입니다.

x = 5
print(_G.x)          --> 5
print(_G["print"] == print)  --> true

-- 즉, 이 셋은 같은 말입니다
x = 5
_G.x = 5
_G["x"] = 5

그래서 print, type, pairs 같은 “내장 함수”도 그냥 _G에 담긴 값이고, 덮어쓸 수 있습니다.

local realPrint = print
print = function(...) realPrint("[LOG]", ...) end
print("hi")     --> [LOG]	hi
전역 조회는 느립니다. 지역 변수는 VM의 레지스터를 바로 읽지만, 전역은 매번 _G 테이블을 해시 조회합니다. 루프 안에서 math.floor를 수백만 번 부른다면 local floor = math.floor로 한 번 받아 두는 것이 정석입니다 (38장).

4.3 스코프의 범위

local의 유효 범위는 선언한 줄부터 그 블록의 끝까지입니다. 블록은 do…end, 함수 본문, if​/​while​/​for의 몸통입니다.

local a = 1
do
  local b = 2
  print(a, b)   --> 1    2
end
print(a, b)     --> 1    nil   (b는 이미 사라짐)

if true then
  local c = 3
end
print(c)        --> nil
do…end은 그냥 “블록 만들기”입니다. 임시 변수의 수명을 좁히고 싶을 때 씁니다. 조건도 반복도 아닙니다.
선언한 줄부터라는 점이 중요합니다. local x = x는 “바깥의 x를 받아 같은 이름의 지역 변수를 만든다”는 뜻입니다. 오른쪽 x는 아직 바깥 것을 가리킵니다.

4.4 가리기(shadowing)

같은 이름을 다시 local로 선언하면 새 변수가 만들어지고 이전 것을 가립니다. 에러가 아닙니다.

local x = 1
local x = x + 1     -- 새 x. 오른쪽 x는 옛 x(=1)
print(x)            --> 2

for i = 1, 3 do
  local i = i * 10  -- 루프 변수 i를 가림
  io.write(i, " ")
end                 --> 10 20 30
print()
디버깅 함정 — 함수 안에서 실수로 local self = ... 같은 이름을 다시 선언하면, 바깥 값이 조용히 가려집니다. 에러가 안 나므로 찾기 어렵습니다. 이름을 재사용할 때는 의도적으로 하세요.

4.5 여러 개를 한 번에

Lua는 다중 대입을 지원합니다. 오른쪽이 먼저 전부 평가된 뒤 왼쪽에 배분됩니다.

local a, b, c = 1, 2, 3
local x, y = 1              -- y는 nil (모자라면 nil로 채움)
local p = 1, 2, 3           -- 2, 3은 버려짐

a, b = b, a                 -- 교환. 임시 변수가 필요 없음
print(a, b)                 --> 2    1
a, b = b, a 는 오른쪽 b, a를 먼저 다 읽어 둔 뒤 대입하므로 진짜 교환이 됩니다. 파서에서 두 상태를 맞바꿀 때 자주 나옵니다.

이 “모자라면 nil, 남으면 버림” 규칙은 함수의 다중 반환값에도 똑같이 적용됩니다. 19장의 핵심 주제입니다.

4.6 알아 둘 제약

이름 규칙영문자·숫자·밑줄. 숫자로 시작 불가. 대소문자 구분. 예약어 22개는 쓸 수 없습니다.
_ 관용구버릴 값에는 관례적으로 _를 씁니다. local _, v = pcall(f) 처럼. 특별한 문법이 아니라 그냥 이름입니다.
지역 변수 개수한 함수 안에 최대 200개. 넘으면 컴파일 에러가 납니다. 실제로 걸릴 일은 거의 없습니다.
upvalue 개수한 클로저가 붙잡을 수 있는 바깥 지역 변수는 최대 255개(5.2+ 기준).
<const> 5.4local N <const> = 10 처럼 상수 선언이 가능합니다. 5.1 호환 코드에서는 쓰지 않습니다.
밑줄로 시작하는 대문자 이름(_G, _VERSION, _ENV)은 Lua가 예약해 둔 영역입니다. 직접 만들지 마세요.

4.7 확인 문제

아래 코드의 출력은?

local n = 0
local function bump()
  n = n + 1
  local n = 100
  return n
end
print(bump(), n)

100    1

n = n + 1은 바깥의 n을 1로 만듭니다. 그다음 줄의 local n = 100은 그때부터 유효한 새 변수이고, return n은 그 새 변수를 돌려줍니다. 바깥 n은 여전히 1입니다.

인자 평가 순서 때문에 bump()가 먼저 실행되고, 그 뒤에 n이 읽혀 1이 됩니다.

5장

참과 거짓, 그리고 and​/​or

Lua에 삼항 연산자도 ??도 없는 이유는, 이 둘이 그 일을 하기 때문입니다.

5.1 규칙은 한 줄

false와 nil만 거짓입니다. 나머지 전부가 참입니다.
if 0 then print("0은 참") end          --> 0은 참
if "" then print("빈 문자열도 참") end  --> 빈 문자열도 참
if {} then print("빈 테이블도 참") end  --> 빈 테이블도 참

local n = 0
if n then print("여기 옴") end          -- n이 0이어도 통과
if n ~= 0 then print("여긴 안 옴") end  -- 이렇게 써야 의도대로

이 규칙 덕분에 “값이 있는가”와 “값이 참인가”가 같은 말이 됩니다. 테이블 조회 결과가 nil이면 거짓, 뭐라도 있으면 참. 그래서 아래 관용구가 자연스럽습니다.

local KEYWORDS = { PRINT = true, GOTO = true, IF = true }

if KEYWORDS[word] then
  -- 키워드다
else
  -- 식별자다     (없으면 nil → 거짓)
end
책의 lexer.lua가 정확히 이 모양입니다. 키워드 집합을 테이블로 두고, 조회 결과의 참/거짓만 봅니다.

5.2 비교 연산자

== ~=같다 / 같지 않다. !=는 없습니다.
< <= > >=숫자끼리, 또는 문자열끼리만 가능합니다.
print("a" < "b")      --> true    (사전순 = 바이트순)
print("Z" < "a")      --> true    (대문자가 앞. ASCII 코드 순서)
print(10 < 9)         --> false

print(1 < "2")        --> 에러!
-- attempt to compare number with string
<는 타입이 섞이면 에러지만 ==는 그냥 false입니다. 비교 연산자 중에서 ==​/​~=만 예외적으로 타입이 달라도 에러를 안 냅니다.
문자열 비교는 로케일 영향을 받습니다. 표준 C 라이브러리의 strcoll을 쓰기 때문입니다. 한글이 섞이면 “사전순”이 기대와 다를 수 있습니다. 어휘 분석기에서는 < 대신 패턴 매칭(%a, %d)을 쓰는 편이 안전합니다.

5.3 and​/​or는 값을 돌려준다

Lua의 and와 or는 true​/​false가 아니라 피연산자 중 하나를 그대로 돌려줍니다. 그리고 단축 평가합니다.

a and ba가 거짓이면 a를 돌려주고 b는 평가하지 않습니다. 참이면 b를 돌려줍니다.
a or ba가 참이면 a를 돌려주고 b는 평가하지 않습니다. 거짓이면 b를 돌려줍니다.
not a이것만은 언제나 true​/​false입니다.
print(1 and 2)        --> 2
print(nil and 2)      --> nil
print(false or "기본") --> 기본
print("x" or "기본")   --> x
print(not nil)        --> true
print(not 0)          --> false

5.4 기본값 관용구 x = x or 기본값

Lua에 ??가 없어도 되는 이유입니다. 이 한 줄이 “인자를 안 주면 기본값”을 처리합니다.

function Lexer:peek(off)
  off = off or 0                -- off를 안 주면 0
  return self.src:sub(self.pos + off, self.pos + off)
end

책의 코드에서 그대로 가져온 것입니다. lx:peek()로 부르면 off가 nil이므로 0이 됩니다.

유일한 함정 — 기본값이 false여도 되는 인자에는 쓸 수 없습니다. 
function setup(verbose)
  verbose = verbose or true   -- ✘ false를 넘겨도 true가 됨!
end

이때는 if verbose == nil then verbose = true end이라고 명시적으로 써야 합니다.

5.5 삼항 연산자 흉내 c and a or b

다른 언어의 c ? a : b에 해당하는 관용구입니다. 동작 원리는 앞 슬라이드에서 전부 설명됩니다.

local sign = (n < 0) and "-" or "+"
local kind = KEYWORDS[w] and "KEYWORD" or "IDENT"
  1. c가 참 → c and a는 a. 그다음 a or b에서 a가 참이면 a.
  2. c가 거짓 → c and a는 거짓. 그다음 거짓 or b는 b.
깨지는 경우 — a 자리의 값이 false나 nil이면, c가 참인데도 b가 나옵니다. 2번 규칙에 걸리기 때문입니다. 
local x = true and false or "기본"
print(x)   --> 기본   (false가 아니라!)
진짜 삼항 연산자가 아니라 두 연산자의 조합일 뿐임을 늘 기억하세요.

5.7 단축 평가를 안전장치로

and가 오른쪽을 평가하지 않는다는 성질은 nil 방어에 그대로 쓰입니다.

-- t가 nil일 수 있을 때

-- 함수 존재 확인
if vm.onStep then vm.onStep(pc) end
다른 언어의 ?.(옵셔널 체이닝)에 해당하는 것이 and 사슬입니다. 조금 길지만 규칙은 하나뿐이라 헷갈리지 않습니다.
연산자 우선순위: not > 비교 > and > or. 그래서 a < b and c < d는 괄호 없이도 의도대로 읽힙니다. 자세한 표는 11장에 있습니다.

6.3 산술 연산자

+ - * /기본 사칙연산. /는 언제나 실수 나눗셈입니다. 10/2가 5.3+에서 5.0인 이유입니다.
^거듭제곱. 언제나 float를 돌려줍니다. 2^2는 5.4에서 4.0입니다.
%나머지. floor 기준입니다 — a % b == a - math.floor(a/b)*b.
// 5.3+정수 나눗셈(내림). 5.1에서는 문법 에러입니다.
단항 -부호 반전. ^보다 약하게 묶입니다 — -2^2는 -4입니다.
print(7 % 3)     --> 1
print(-7 % 3)    --> 2      C나 JS라면 -1
print(-7 // 3)   --> -3     내림(floor)이므로 -2가 아님
print(math.fmod(-7, 3))  --> -1     C 방식이 필요하면 이것
음수 나머지가 다릅니다. Lua의 %는 결과 부호가 제수를 따릅니다. C·Java·JavaScript는 피제수를 따릅니다. BASIC의 MOD를 구현할 때 반드시 확인해야 하는 지점입니다.

6.5 부동소수점의 함정

Lua의 실수는 IEEE 754 double입니다. 다른 언어와 똑같은 문제를 겪습니다.

print(0.1 + 0.2)            --> 0.3        (보기엔 멀쩡)
print(0.1 + 0.2 == 0.3)     --> false      (실제로는 다름)
print(string.format("%.17g", 0.1 + 0.2))
--> 0.30000000000000004
print가 속입니다. Lua는 실수를 찍을 때 %.14g 서식을 씁니다. 유효숫자 14자리까지만 보여 주므로 오차가 가려집니다. 진짜 값이 보고 싶으면 string.format("%.17g", x)를 쓰세요.
무한대1/0 → inf, -1/0 → -inf. 에러가 아닙니다. math.huge가 같은 값입니다.
NaN0/0 → nan (플랫폼에 따라 -nan). nan ~= nan이므로 x ~= x가 NaN 판정법입니다.
정수 정확도double은 2^53까지만 정수를 정확히 담습니다. 5.1에서 큰 라인 번호를 다룰 때 알아 둘 한계입니다.

6.6 정수의 경계 5.3+

print(math.maxinteger)              --> 9223372036854775807
print(math.mininteger)              --> -9223372036854775808
print(math.maxinteger + 1 == math.mininteger)   --> true  (감쌈)

print(math.tointeger(3.0))          --> 3
print(math.tointeger(3.5))          --> nil  (정수로 못 바꿈)
print(math.type(3), math.type(3.0)) --> integer   float
integer 오버플로는 조용히 감깁니다(wrap around). 예외가 나지 않습니다. 반면 float은 inf로 갑니다.
GW-BASIC 쪽 이야기 — BASIC의 % 접미어 정수는 16비트 부호 있는 정수(-32768~32767)입니다. Lua의 64비트 정수와 전혀 다릅니다. 그래서 인터프리터가 그 범위를 직접 검사해 ?Overflow 에러를 내야 합니다. 언어가 대신 해 주지 않습니다.

local function num_to_str(v)
  if v == math.floor(v) and math.abs(v) < 1e15 then
    return string.format("%d", v)     -- 정수처럼 찍기
  end
  return tostring(v)
end
v == math.floor(v) 는 5.1에서도 5.4에서도 “정수인가”를 묻는 안전한 방법입니다. math.type은 5.3+에만 있습니다.

6.8 확인 문제

Lua 5.4에서 아래의 출력은?

print(-2^2, 2^3^2, 7 // 2, 7.0 // 2, -7 % 3)

-4.0  512.0  3  3.0  2

  • -2^2 — ^가 단항 -보다 강하므로 -(2^2). ^는 언제나 float이라 -4.0.
  • 2^3^2 — ^는 우결합이므로 2^(3^2) = 2^9 = 512.0.
  • 7 // 2 — 정수끼리면 결과도 integer라 3.
  • 7.0 // 2 — 한쪽이 float이면 결과도 float이라 3.0.
  • -7 % 3 — floor 기준이라 2. C라면 -1.

7.3 문자열은 바이트 열이다

print(#"hello")   --> 5
print(#"héllo")   --> 6    (é가 UTF-8로 2바이트)
print(#"한글")    --> 6    (한 글자당 3바이트)
장점이진 데이터를 그대로 담을 수 있습니다. \0이 들어가도 잘리지 않습니다.
단점s:sub(1,1)이 한글의 첫 바이트만 잘라 냅니다. #s도 문자 수가 아닙니다.

이 책에는 문제가 되지 않습니다. GW-BASIC 소스는 ASCII이고, 어휘 분석기가 다루는 것도 ASCII 범위의 바이트뿐입니다. 다만 PRINT "안녕"처럼 문자열 리터럴 안에 한글이 오면 그건 그냥 바이트로 통과시키면 됩니다.

7.5 ..의 비용

문자열이 불변이므로 ..는 언제나 새 문자열을 만듭니다. 루프 안에서 반복하면 O(n²)가 됩니다.

✘ O(n²)
local buf = ""
for i = 1, 100000 do
  buf = buf .. i .. ","
end
✔ O(n)
local buf = {}
for i = 1, 100000 do
  buf[#buf + 1] = i
end
local s = table.concat(buf, ",")
실제로 얼마나 차이 나는지
책의 lex_string이 정확히 오른쪽 방식입니다. 문자열 리터럴 안의 글자를 buf 테이블에 하나씩 넣었다가 마지막에 table.concat(buf)을 한 번 부릅니다.

7.6 인덱스는 1부터, 음수는 뒤에서부터

local s = "Hello"
print(s:sub(1, 1))    --> H     첫 글자
print(s:sub(2, 3))    --> el
print(s:sub(-3))      --> llo   뒤에서 3번째부터 끝까지
print(s:sub(-1))      --> o     마지막 글자
print(s:sub(2))       --> ello  두 번째부터 끝까지
1부터첫 글자가 1번입니다. 0번은 없습니다.
양끝 포함sub(i, j)는 i번째와 j번째를 모두 포함합니다. 길이는 j - i + 1.
음수-1이 마지막, -2가 그 앞. #s + 1 + 음수로 계산됩니다.
범위 밖에러가 아니라 잘린 결과나 빈 문자열을 돌려줍니다. 이 관대함이 어휘 분석기에서 아주 유용합니다.
범위 밖이 에러가 아니라는 점이 책의 peek을 단순하게 만듭니다. 문자열 끝을 지나도 s:sub(n, n)은 ""를 돌려주므로, 별도의 “끝인가?” 검사 없이 if c == "" then break end 한 줄로 끝납니다.

7.8 s:upper()는 어떻게 되는가

문자열에 콜론을 붙여 메서드처럼 부를 수 있습니다. 이건 특별한 문법이 아니라 메타테이블 덕분입니다 (28장에서 정식으로 다룹니다).

local s = "abc"
print(s:upper())          --> ABC
print(string.upper(s))    --> ABC     완전히 같은 호출
print(("abc"):upper())    --> ABC     리터럴에는 괄호가 필요
모든 문자열은 string 테이블을 __index로 갖는 메타테이블을 공유합니다. 그래서 s:upper()는 string.upper(s)로 풀립니다. 숫자·불리언·테이블에는 이런 기본 메타테이블이 없습니다.

print(#({1,2,3}))  --> 3     테이블의 "길이"
print(#t + 1)      -- # 가 + 보다 강하므로 괄호 불필요
테이블의 #는 생각보다 까다롭습니다. 중간에 nil이 있으면 결과가 정해져 있지 않습니다. 13장에서 자세히 다룹니다. 문자열의 #는 언제나 정확합니다.

가장 많이 쓰는 관용구는 배열 끝에 추가입니다.

t[#t + 1] = v          -- table.insert(t, v) 와 같은 뜻, 조금 더 빠름

11.5 확인 문제

아래 두 줄의 값은?

local a = "n=" .. 1 + 2
local b = not nil == true

a는 "n=3", b는 true.

  • +(9)가 ..(8)보다 강하므로 "n=" .. (1+2) → "n=3"입니다.
  • 단항 not(11)이 ==(3)보다 강하므로 (not nil) == true → true == true → true입니다. not (nil == true)로 읽었다면 우연히 답은 같지만 이유가 다릅니다.

두 경우 모두, 헷갈릴 것 같으면 괄호를 쓰는 편이 읽는 사람에게 친절합니다.

제4부

테이블

Lua의 유일한 자료구조. 여섯 장을 쓸 값어치가 있습니다

12장

테이블이 전부다

배열도 딕셔너리도 객체도 모듈도, 전부 이것 하나입니다.

12.1 테이블이란

테이블은 키 → 값의 연관 배열입니다. 키로는 nil과 NaN을 뺀 아무 값이나 쓸 수 있습니다.

local t = {}
t[1] = "첫째"        -- 숫자 키
t["name"] = "렉서"   -- 문자열 키
t.name = "렉서"      -- 위와 완전히 같은 말
t[true] = "참"       -- 불리언 키도 됨
t[print] = "함수도"  -- 함수도 키가 됨(주소로 구분)

local other = {}
t[other] = "테이블도" -- 테이블도 키가 됨
t.name은 t["name"]의 문법 설탕입니다. 완전히 같습니다. 점 표기는 키가 식별자 모양일 때만 쓸 수 있고, t["a b"]나 t["+"]는 대괄호 표기가 필요합니다.
키로 쓸 수 없는 것 — nil은 “없음”이라 키가 될 수 없고(table index is nil 에러), NaN도 자기 자신과 같지 않아 키가 될 수 없습니다.

12.2 테이블 생성자

local a = {}                       -- 빈 테이블
local b = {10, 20, 30}             -- 1, 2, 3번 키에 자동 배정
local c = {x = 1, y = 2}           -- 문자열 키
local d = {["a b"] = 1, [2 + 1] = 2}  -- 계산된 키/특이한 키
local e = {10, 20, x = 1}          -- 섞어도 됨
local f = {
  {type = "NUMBER", value = 10},    -- 중첩
  {type = "PLUS",   value = "+"},
}
구분자쉼표 ,와 세미콜론 ;을 섞어 쓸 수 있습니다. 마지막 항목 뒤의 쉼표(trailing comma)도 허용됩니다.
배열 부분키 없이 나열한 값은 1부터 차례로 배정됩니다.
계산된 키[expr] = value 형태. 변수도 식도 올 수 있습니다.
책에서는 — AST 노드를 만들 때마다 {tag = "BinOp", op = op, left = l, right = r} 같은 생성자가 나옵니다. 구조체 선언이 없으니 이 리터럴 자체가 스키마입니다.

12.3 하나의 테이블, 여섯 가지 역할

배열{1, 2, 3} — 1부터 연속된 정수 키
레코드{type = "NUMBER", value = 10, line = 3} — 고정된 이름의 필드
딕셔너리{["PRINT"] = fn} — 임의의 키 → 값
집합{PRINT = true, GOTO = true} — 값은 true만 쓰고 키의 존재만 봅니다
객체{src = s, pos = 1} + 메타테이블로 메서드를 붙임 (31장)
모듈local M = {} … return M — 파일이 돌려주는 이름공간 (33장)
이 여섯이 전부 같은 것이라는 점이 Lua의 힘이자 함정입니다. 힘인 이유는 배울 게 하나뿐이라서, 함정인 이유는 어떤 역할로 쓰고 있는지 코드에 안 적혀 있어서입니다. 그래서 “이 테이블은 순수 배열”, “이 테이블은 순수 레코드”라고 스스로 규율을 정해 지키는 것이 중요합니다.
책의 규율 — 토큰 목록·바이트코드·스택은 순수 배열로, 토큰·AST 노드·명령은 순수 레코드로 씁니다. 섞지 않습니다.

12.4 중첩과 접근

local prog = {
  lines = {
    {number = 10, stmts = {{tag = "Print", items = {}}}},
    {number = 20, stmts = {{tag = "Goto",  target = 10}}},
  },
}

print(prog.lines[2].stmts[1].target)   --> 10
print(#prog.lines)                     --> 2

점과 대괄호를 자유롭게 섞을 수 있습니다. prog.lines[2]는 prog["lines"][2]와 같습니다.

중간에 nil이 있으면 그 지점에서 터집니다. 
print(prog.line[2])
-- attempt to index a nil value (field 'line')
에러 메시지의 (field 'line')이 어느 단계에서 nil이었는지를 알려 줍니다. 오타 하나를 찾는 데 이 괄호가 결정적입니다.

12.5 테이블은 참조다

local a = {1, 2, 3}
local b = a              -- 복사가 아니라 같은 테이블을 가리킴
b[1] = 99
print(a[1])              --> 99   a도 바뀜!

print(a == b)            --> true  같은 객체
print(a == {1, 2, 3})    --> false 내용이 같아도 다른 객체

얕은 복사가 필요하면 직접 만들어야 합니다. Lua에는 내장 복사 함수가 없습니다.

local function shallow_copy(t)
  local r = {}
  for k, v in pairs(t) do r[k] = v end
  return r
end
인터프리터에서 중요한 지점 — BASIC의 배열 변수를 함수에 넘길 때, Lua 테이블을 그대로 넘기면 참조가 전달됩니다. 값 의미론이 필요하면 명시적으로 복사해야 합니다. 17장에서 다시 다룹니다.

13장

1부터 시작하는 인덱스와 #

Lua에서 가장 자주 사고가 나는 곳입니다.

13.1 왜 1부터인가

local t = {"a", "b", "c"}
print(t[1], t[3])     --> a    c
print(t[0])           --> nil  (에러가 아니라 그냥 없음)

0-기반 언어에서 오면 반드시 한 번은 실수합니다. 대신 규칙은 단순해집니다.

배열 순회for i = 1, #t do — 시작과 끝이 둘 다 자연스럽습니다.
마지막 원소t[#t]
끝에 추가t[#t + 1] = v
문자열도 동일s:sub(1, 1)이 첫 글자. 문자열과 테이블의 규칙이 일치합니다.
변환할 때 주의 — GW-BASIC의 배열은 기본이 0부터입니다. DIM A(10)은 A(0)부터 A(10)까지 11칸입니다. Lua 테이블에 담을 때 인덱스를 그대로 쓰면 t[0]이 생겨 #t가 무의미해집니다. 책은 오프셋을 더해 1-기반으로 맞춥니다.

13.2 #는 “경계”를 돌려준다

#t의 정의는 “길이”가 아니라 경계(border)입니다. 즉 t[n] ~= nil이고 t[n+1] == nil인 어떤 n입니다.

구멍이 없는 배열에는 그런 n이 하나뿐이라 결과가 확정됩니다. 구멍이 있으면 경계가 여러 개가 되고, Lua는 그중 아무거나 돌려줘도 됩니다.
-- 같은 "구멍 뚫린 테이블"인데 결과가 다릅니다 (Lua 5.4)
local a = {1, nil, 3}
print(#a)        --> 3

local b = {}
b[1] = 1
b[3] = 3
print(#b)        --> 1

둘 다 “1번과 3번에 값이 있고 2번이 nil”인데 답이 다릅니다. 생성자로 만들면 내부 배열부가 3칸으로 잡히고, 하나씩 넣으면 그렇지 않기 때문입니다. 이건 버그가 아니라 명세대로입니다.

결론 — 구멍 뚫린 테이블에 #를 쓰지 마세요. 길이를 알아야 한다면 따로 세어 두거나, 애초에 구멍을 만들지 않아야 합니다.

13.3 구멍을 직접 만들어 보기

#, ipairs, pairs가 서로 다른 답을 하는 순간

형식은 키=값을 쉼표로 나열. 시도해 볼 것: 1=a, 2=b, 3=c (구멍 없음) → 1=a, 3=c (구멍) → 2=b, 3=c (1번이 없음)

1번이 없으면 #t는 0이고 ipairs는 한 번도 돌지 않습니다. “값을 분명히 넣었는데 루프가 안 돈다”는 증상의 정체가 이것입니다.

13.4 구멍을 만들지 않는 습관

✘ 구멍이 생기는 코드
for i = 1, #toks do
  if toks[i].type == "SPACE" then
    toks[i] = nil        -- 중간에 구멍!
  end
end
✔ 새 배열로 걸러내기
local out = {}
for i = 1, #toks do
  if toks[i].type ~= "SPACE" then
    out[#out + 1] = toks[i]
  end
end
toks = out

제자리에서 지워야 한다면 table.remove를 쓰되 뒤에서부터 순회합니다.

for i = #toks, 1, -1 do
  if toks[i].type == "SPACE" then
    table.remove(toks, i)      -- 뒤에서부터면 인덱스가 밀리지 않음
  end
end
앞에서부터 지우면 지운 자리로 뒤 원소가 당겨져 한 칸씩 건너뛰게 됩니다. 어느 언어에서나 나는 실수지만, Lua는 에러도 경고도 없이 조용히 틀립니다.

14장

table 라이브러리

함수가 다섯 개뿐입니다. 그중 셋만 자주 씁니다.

14.1 table.insert / table.remove

local t = {"a", "b", "c"}

table.insert(t, "d")        -- 끝에 추가 → a b c d
table.insert(t, 1, "z")     -- 1번 자리에 끼워 넣기 → z a b c d
                            --   (뒤 원소들이 한 칸씩 밀림)

print(table.remove(t))      --> d    마지막을 빼서 돌려줌
print(table.remove(t, 1))   --> z    1번을 빼고 나머지를 당김
print(#t)                   --> 3
끝에 추가table.insert(t, v) 또는 t[#t + 1] = v. 후자가 조금 더 빠릅니다(함수 호출이 없어서).
중간 삽입/삭제뒤 원소를 전부 옮기므로 O(n)입니다. 큰 배열의 앞쪽을 반복해서 건드리면 느려집니다.
반환값remove는 빼낸 값을 돌려줍니다. insert는 아무것도 안 돌려줍니다.
책의 vm.lua는 스택을 다룰 때 table.insert 대신 stack[#stack + 1] = v / stack[#stack] = nil을 씁니다. 명령마다 수십만 번 도는 자리라서 함수 호출 비용이 눈에 보입니다.

14.2 table.concat

local t = {"a", "b", "c"}
print(table.concat(t))            --> abc
print(table.concat(t, ", "))      --> a, b, c
print(table.concat(t, "-", 2, 3)) --> b-c     범위 지정
문자열과 숫자만 됩니다. nil​·불리언·테이블이 섞여 있으면 invalid value (at index 2) in table for 'concat' 에러가 납니다. 넣기 전에 tostring을 거치세요.
가장 중요한 용도는 문자열 버퍼입니다 (7.5절). 어휘 분석기의 lex_string, PRINT 출력 조립, LIST 명령의 프로그램 재구성 — 문자열을 조각조각 모으는 곳마다 이 함수가 나옵니다.
local buf = {}
while true do
  local c = self:peek()
  if c == '"' then break end
  buf[#buf + 1] = c
  self:advance()
end
local text = table.concat(buf)

14.3 table.sort

local t = {3, 1, 2}
table.sort(t)
print(table.concat(t, ","))       --> 1,2,3

table.sort(t, function(a, b) return a > b end)   -- 내림차순
print(table.concat(t, ","))       --> 3,2,1

-- 레코드 배열 정렬
table.sort(lines, function(a, b) return a.no < b.no end)
제자리 정렬원본을 바꿉니다. 반환값은 없습니다.
비교 함수a가 b보다 앞이면 true. C의 -1/0/1이 아닙니다.
불안정같은 값의 상대 순서가 보장되지 않습니다.
비교 함수가 일관되지 않으면 에러가 납니다 — invalid order function for sorting. a <= b처럼 “같을 때도 true”를 돌려주면 이 함정에 빠집니다. 반드시 엄격한 부등호를 쓰세요.
책에서는 BASIC 프로그램의 줄 번호를 정렬할 때 씁니다. 10 20 100을 문자열로 정렬하면 10 100 20이 되므로, 반드시 숫자로 비교해야 합니다.

14.4 unpack — 이름이 바뀐 함수

local t = {1, 2, 3}
print(table.unpack(t))     -- 5.2+ :  1  2  3
print(unpack(t))           -- 5.1  :  1  2  3
5.1에서는 전역 unpack, 5.2+에서는 table.unpack입니다. 5.1에는 table.unpack이 없고, 5.4에는 전역 unpack이 없습니다. 양쪽에서 돌려야 한다면 이렇게 씁니다.
local unpack = table.unpack or unpack     -- 5.1~5.4 공통

unpack은 배열을 여러 개의 값으로 펼칩니다. 19장의 다중 반환값과 짝을 이루는 기능입니다.

local args = {10, 20}
print(math.max(unpack(args)))    --> 20   math.max(10, 20) 과 같음

14.5 나머지와, 없는 것들

table.pack(...) 5.2+인자들을 배열로 묶고 n 필드에 개수를 넣습니다. 20장에서 씁니다.
table.move 5.3+범위를 다른 위치(또는 다른 테이블)로 옮깁니다. 5.1 호환 코드에서는 못 씁니다.
next(t, k)테이블의 다음 키/값 쌍. pairs의 밑바닥입니다. next(t) == nil이 “테이블이 비었는가”를 묻는 관용구입니다.
print(next({}))        --> nil        비었음
print(next({5}))       --> 1    5     첫 쌍
if next(t) == nil then print("비었다") end
#t == 0으로 “비었는지”를 판단하면 안 됩니다. {x = 1}은 #t가 0이지만 비어 있지 않습니다. 해시 부분만 있는 테이블에 #는 0을 돌려줍니다.

없는 것도 알아 둡시다. 복사, 병합, 뒤집기, 찾기, 필터, 맵 — 전부 없습니다. 필요하면 for 루프로 직접 씁니다. 대여섯 줄이면 됩니다.

14.6 확인 문제

아래 코드가 찍는 값은?

local t = {}
t[1] = "a"
t[2] = "b"
t[4] = "d"
local n = 0
for _, v in ipairs(t) do n = n + 1 end
local m = 0
for _ in pairs(t) do m = m + 1 end
print(n, m, #t)

2  3  4 — 세 숫자가 전부 다릅니다. (5.1과 5.4 모두 이 값)

  • ipairs는 1, 2를 돌고 3번이 nil이라 멈춥니다 → 2
  • pairs는 존재하는 키 세 개를 전부 돕니다 → 3
  • #t는 어떤 경계든 돌려주면 됩니다. 여기서는 t[2]~=nil, t[3]==nil인 2도, t[4]~=nil, t[5]==nil인 4도 유효한 경계입니다. 실제로는 4가 나옵니다.

“4번에 넣은 d가 사라졌다”가 아니라, 세는 방법마다 답이 다르다는 것이 요점입니다. 그리고 #t의 값은 보장된 것이 아니므로 구멍 있는 테이블에서 절대 믿으면 안 됩니다.

15장

순회 — pairs와 ipairs

둘 중 무엇을 쓸지는 “테이블을 무슨 역할로 쓰는가”가 정합니다.

15.1 둘의 차이

ipairs(t)t[1]부터 1씩 늘려가며 nil을 만날 때까지. 순서가 보장됩니다. 배열용.
pairs(t)테이블에 실제로 존재하는 모든 키를. 순서는 보장되지 않습니다. 레코드·딕셔너리용.
local t = {"a", "b", "c", name = "렉서"}

for i, v in ipairs(t) do print(i, v) end
--> 1  a
--> 2  b
--> 3  c          (name은 안 나옴)

for k, v in pairs(t) do print(k, v) end
--> 1  a
--> 2  b
--> 3  c
--> name  렉서    (순서는 실행마다 다를 수 있음)
ipairs는 배열 부분만, pairs는 전부. 그리고 ipairs는 첫 nil에서 멈춥니다 — 뒤에 값이 더 있어도 못 봅니다.

15.2 pairs의 순서는 정말 무작위다

local t = {x = 1, y = 2, z = 3, a = 4, b = 5}
for k in pairs(t) do io.write(k, " ") end
-- Lua 5.4 x z y b a -- Lua 5.1 (같은 코드, 다른 순서) y x z b a
순서에 의존하는 코드를 쓰면 안 됩니다. 해시 테이블의 내부 배치에 따라 정해지므로, 버전·플랫폼·심지어 삽입 순서에 따라 달라집니다. 테스트에서는 우연히 통과하고 배포 후에 깨지는 전형적인 사례입니다.

순서가 필요하면 키를 모아 정렬합니다.

local keys = {}
for k in pairs(t) do keys[#keys + 1] = k end
table.sort(keys)
for _, k in ipairs(keys) do print(k, t[k]) end
책에서는 LIST 명령이 이 패턴을 씁니다. 프로그램 줄이 lines[번호] 테이블에 들어 있어 순서가 없으므로, 줄 번호를 모아 숫자로 정렬한 뒤 출력합니다.

15.3 순회 중 수정

값 바꾸기안전합니다. 이미 있는 키에 새 값을 대입하는 것은 허용됩니다.
키 지우기t[k] = nil도 허용됩니다(현재 키를 지우는 것).
키 추가정의되지 않은 동작입니다. 새 키를 넣으면 순회가 건너뛰거나 무한 반복할 수 있습니다.
-- ✔ 안전
for k, v in pairs(t) do
  if v == 0 then t[k] = nil end
end

-- ✘ 하면 안 됨
for k, v in pairs(t) do
  t[k .. "_copy"] = v      -- 새 키 추가. 결과 예측 불가
end
ipairs는 조금 다릅니다. 단순히 t[1], t[2], …를 읽는 것뿐이라 “테이블 내부 상태”에 얽매이지 않습니다. 순회 중 뒤쪽에 값을 추가하면 그 값까지 읽습니다. 예측 가능한 만큼, 의도치 않은 무한 루프도 만들 수 있습니다.

15.4 _로 버리기

for _, tok in ipairs(tokens) do      -- 인덱스는 안 씀
  print(tok.type)
end

for k, _ in pairs(t) do ... end      -- 값은 안 씀
for k in pairs(t) do ... end         -- 아예 안 받아도 됨

_는 특별한 문법이 아니라 그냥 변수 이름입니다. “안 쓴다”는 표시로 관례적으로 씁니다.

제네릭 for는 값이 남으면 버립니다. 반복자가 두 값을 주는데 하나만 받으면 두 번째는 조용히 버려집니다. 다중 대입과 같은 규칙입니다(4.5절).

15.5 반복자는 그냥 함수다

for … in의 in 뒤에는 “부를 때마다 다음 값을 주고, 끝나면 nil을 주는 함수”가 옵니다. pairs​·​ipairs는 그런 함수를 만들어 주는 도우미일 뿐입니다.

-- 직접 만든 반복자: 문자열을 한 글자씩
local function chars(s)
  local i = 0
  return function()
    i = i + 1
    if i <= #s then return i, s:sub(i, i) end
  end
end

for i, c in chars("Lua") do print(i, c) end
--> 1  L
--> 2  u
--> 3  a
클로저(21장)로 상태 i를 붙잡아 두는 것이 요령입니다. s:gmatch(패턴)도 정확히 이런 반복자 함수를 돌려줍니다 (26장).
책에서는 직접 만든 반복자가 나오지 않습니다. ipairs, pairs, 그리고 gmatch 셋으로 충분합니다. 다만 gmatch가 “왜 for에 그냥 들어가는지”를 이해하려면 이 슬라이드가 필요합니다.

16.1 레코드

구조체가 없으니 테이블에 이름 붙은 필드를 넣습니다. 이 책의 모든 데이터가 이 모양입니다.

-- 토큰
local tok = { type = "NUMBER", value = 10, line = 1 }

-- AST 노드
local node = { tag = "BinOp", op = "+", left = a, right = b }

-- 바이트코드 명령
local ins = { op = "PUSH", arg = 10 }
type​/​tag​/​op 같은 “종류” 필드가 핵심입니다. Lua에는 타입이 없으니 값 자신이 자기가 무엇인지 말해야 합니다. 이 문자열 하나로 파서와 컴파일러와 VM이 분기합니다.
오타에 무방비합니다. tok.tpye는 에러 없이 nil입니다. 그래서 필드 이름은 짧고 일관되게 정하고, 생성은 한 군데 함수에 모으는 것이 방어책입니다. 책의 ast.lua가 정확히 그 역할입니다.
-- ast.lua : 노드 생성을 한 곳에 모음
function M.NumLit(v)       return { tag = "NumLit", value = v } end
function M.BinOp(op, l, r) return { tag = "BinOp", op = op, left = l, right = r } end

16.2 집합

값은 true만 넣고 키의 존재만 확인하는 관용구입니다.

local KEYWORDS = {
  PRINT = true, INPUT = true, IF = true, THEN = true, ELSE = true,
  FOR = true, TO = true, STEP = true, NEXT = true, GOTO = true,
  GOSUB = true, RETURN = true, END = true, REM = true,
}

if KEYWORDS[word] then
  return { type = "KEYWORD", value = word }
else
  return { type = "IDENT", value = word }
end
조회해시 조회 O(1). 키워드가 100개가 되어도 속도가 같습니다.
elseif 사슬 대비비교 100번 → 조회 1번. 게다가 목록이 데이터로 분리돼 읽기 쉽습니다.
주의없는 키는 nil(거짓)이지, false가 아닙니다. 값을 false로 넣으면 “있지만 거짓”이 되어 헷갈립니다.
키워드 목록을 문자열로 관리하는 법도 흔합니다. for w in ("PRINT INPUT IF"):gmatch("%S+") do KEYWORDS[w] = true end — 목록을 한 줄로 유지할 수 있습니다.

16.3 다차원 배열 ① 중첩 테이블

Lua에 2차원 배열은 없습니다. 테이블의 테이블로 만듭니다.

local grid = {}
for i = 1, 3 do
  grid[i] = {}                 -- 행마다 새 테이블을 만들어야 함!
  for j = 1, 4 do
    grid[i][j] = 0
  end
end

print(grid[2][3])   --> 0
가장 흔한 실수 — grid[i] = {}를 빠뜨리는 것입니다. 그러면 grid[i]가 nil이라 grid[i][j]에서 attempt to index a nil value가 납니다.
희소 배열이라면 필요할 때 만드는 방식이 낫습니다. 
local row = grid[i]
if row == nil then row = {}; grid[i] = row end
row[j] = v

16.4 다차원 배열 ② 인덱스 평탄화

차원 수가 실행 중에 정해진다면(DIM A(3,4,5)) 중첩보다 1차원으로 펴는 편이 간단합니다.

-- dims = {3, 4}  →  3×4 배열
local function offset(dims, idx)
  local off = 0
  for k = 1, #dims do
    off = off * dims[k] + (idx[k] - 1)      -- 각 차원은 1부터
  end
  return off + 1                            -- Lua는 1-기반
end

local a = {}
a[offset({3,4}, {2,3})] = 99                -- A(2,3) = 99
이것이 책의 20장(배열·DIM·다차원 인덱스)이 하는 일입니다. GW-BASIC의 DIM A(2,3)은 각 차원이 0부터라 실제 크기가 3×4이고, 그걸 한 줄짜리 Lua 테이블에 담습니다. 인덱스 계산을 한 함수에 가둬 두면 차원 수가 몇이든 같은 코드로 처리됩니다.
왜 중첩이 아닌가 — 차원이 셋 이상이면 a[i][j][k]를 만들기 위해 중간 테이블을 전부 만들어야 하고, 빈 칸이 많으면 메모리를 크게 낭비합니다. 평탄화하면 테이블 하나로 끝납니다.

16.5 “없으면 기본값” 처리

BASIC에서 초기화 안 한 변수는 숫자면 0, 문자열이면 ""입니다. Lua 테이블은 nil을 주므로 그 자리를 메워야 합니다.

① 조회할 때마다
local function get(vars, name)
  local v = vars[name]
  if v == nil then
    return name:sub(-1) == "$" and "" or 0
  end
  return v
end
② 메타테이블로 (29장)
setmetatable(vars, {
  __index = function(t, k)
    return k:sub(-1) == "$" and "" or 0
  end
})
print(vars.X)   --> 0
어느 쪽이 나은가 — ②는 코드가 짧지만 “진짜 없는 것”과 “0이 들어 있는 것”을 구분할 수 없게 됩니다. DIM이 선언됐는지 확인해야 하는 상황에서는 ①이 안전합니다. 책은 ①을 씁니다.

17.1 토큰 목록

함수의 기본

18.1 다섯 가지 정의 형태

-- ① 전역 함수 (쓰지 말 것)
function tokenize(src) ... end

-- ② 지역 함수 ← 가장 많이 씀
local function tokenize(src) ... end

-- ③ 익명 함수를 변수에 대입
local tokenize = function(src) ... end

-- ④ 테이블 필드
function M.tokenize(src) ... end        -- M.tokenize = function(src)…

-- ⑤ 메서드 (self가 숨어 있음)
function Lexer:tokenize() ... end       -- Lexer.tokenize = function(self)…
②와 ③의 차이 — local function f는 local f; f = function과 같습니다. 즉 함수 몸통 안에서 자기 이름을 볼 수 있습니다. ③은 대입이 끝나야 f가 생기므로 재귀가 안 됩니다.
local function fact(n)              -- ✔ 재귀 가능
  if n <= 1 then return 1 end
  return n * fact(n - 1)
end

local fact2 = function(n)           -- ✘ fact2가 아직 nil
  return n * fact2(n - 1)           -- attempt to call a nil value
end
①은 전역을 만듭니다. 4.1절에서 말한 대로 이 책은 쓰지 않습니다. function f()라고 쓰면 그 순간 _G.f가 생깁니다.

18.2 인자 개수는 맞지 않아도 된다

local function f(a, b, c)
  print(a, b, c)
end

f(1)           --> 1    nil  nil     모자라면 nil
f(1, 2, 3, 4)  --> 1    2    3       남으면 버림
인자 개수 실수를 언어가 잡아 주지 않습니다. emit(kind)라고 써야 할 자리에 emit()이라고 쓰면 kind가 nil인 채로 진행되어, 한참 뒤에 이상한 곳에서 터집니다. 이것이 Lua로 큰 프로그램을 짤 때 가장 큰 비용입니다.

방어책은 명시적 검사입니다.

local function emit(kind, text)
  assert(kind, "emit: kind가 없습니다")     -- 즉시 터뜨리기
  ...
end
assert는 값이 참이면 그대로 돌려주고, 거짓이면 에러를 냅니다. local f = assert(io.open(path))처럼 반환값을 그대로 쓰는 관용구가 흔합니다 (34장).

18.3 괄호를 생략하는 두 경우

인자가 문자열 리터럴 하나이거나 테이블 생성자 하나일 때는 괄호를 생략할 수 있습니다.

print "hello"          -- print("hello")
require "lexer"        -- require("lexer")
f{1, 2, 3}             -- f({1, 2, 3})

-- 아래 두 줄은 완전히 같은 코드
local ast = node{tag = "Num", value = 10}
local ast = node({tag = "Num", value = 10})
왜 이런 문법이 있나 — 설정을 넘길 때 widget{width = 10, height = 20}처럼 이름 있는 인자처럼 보이게 하려는 것입니다. 사실상 “테이블 하나를 넘기는 것”인데 문법 설탕으로 예쁘게 보입니다.
혼동 주의 — f "a"는 함수 호출이고, f, "a"는 전혀 다른 것입니다. 그리고 print (x)처럼 띄어 써도 호출이므로, 줄이 (로 시작하면 앞줄의 마지막 값을 호출하려 든다고 오해할 수 있습니다. Lua가 ambiguous syntax 경고를 내던 시절도 있었습니다.

아래 네 줄이 각각 찍는 것은?

클로저

함수가 바깥 지역 변수를 붙잡아 함께 살아남습니다.

21.1 upvalue

함수 안에서 바깥 함수의 지역 변수를 참조하면, 그 변수를 upvalue라고 부릅니다. 바깥 함수가 끝나도 upvalue는 사라지지 않습니다.

local function counter()
  local n = 0                      -- upvalue
  return function()
    n = n + 1                      -- 바깥의 n을 읽고 씀
    return n
  end
end

local c = counter()
print(c(), c(), c())    --> 1  2  3
-- counter는 이미 끝났는데 n은 살아 있습니다
복사가 아니라 공유입니다. 클로저는 값을 복사해 가는 것이 아니라, 그 변수 자체를 계속 가리킵니다. 그래서 읽기도 쓰기도 됩니다.

21.2 같은 변수를 나눠 갖기

local function makeCounter()
  local n = 0
  local function inc() n = n + 1 end
  local function get() return n end
  return inc, get
end

local inc, get = makeCounter()
inc(); inc()
print(get())      --> 2   같은 n을 봅니다

반면 makeCounter()를 두 번 부르면 n도 두 개가 생깁니다.

두 클로저는 각자의 n을 갖는다
이것이 객체의 원형입니다. 상태(n)와 그 상태를 다루는 함수들을 묶은 것 — 메타테이블 없이도 “객체 비슷한 것”을 만들 수 있습니다. 다만 이 책은 메서드가 많아 31장의 테이블 방식을 씁니다.

21.3 루프 안의 클로저

local fs = {}
for i = 1, 3 do
  fs[i] = function() return i end
end
print(fs[1](), fs[2](), fs[3]())   --> 1  2  3
Lua에서는 이게 “당연히” 됩니다. for의 루프 변수는 매 회차마다 새로 만들어지는 지역 변수이기 때문입니다. JavaScript의 var나 Python에서는 같은 코드가 3 3 3을 찍습니다 — 그 언어들은 변수 하나를 공유하니까요.
단, while은 다릅니다. 직접 선언한 변수는 회차마다 새로 만들어지지 않습니다. 
local fs, i = {}, 1
while i <= 3 do
  fs[i] = function() return i end   -- 전부 같은 i를 붙잡음
  i = i + 1
end
print(fs[1]())   --> 4    (루프가 끝났을 때의 값)
회차마다 값을 고정하려면 몸통 안에서 local j = i처럼 새 지역 변수를 만드세요.

재귀와 꼬리 호출

파서는 재귀로 짜입니다. 스택 한계도 알아 둬야 합니다.

22.1 재귀 하강 파서의 모양

책의 파서는 문법 규칙 하나당 함수 하나입니다. 규칙이 서로를 참조하니 함수도 서로를 부릅니다.

function Parser:parse_binop(min_prec)
  local left = self:parse_unary()
  while true do
    local op, prec = self:peek_binop()
    if not op or prec < min_prec then break end
    self:advance()
    local next_min = is_left(op) and (prec + 1) or prec
    local right = self:parse_binop(next_min)   -- 재귀!
    left = AST.BinOp(op, left, right)
  end
  return left
end
중첩 괄호의 깊이만큼 재귀가 깊어집니다. ((((1))))는 네 겹입니다. 사람이 짠 BASIC 프로그램에서 실제로 문제가 되는 일은 없지만, 기계가 생성한 입력이라면 한계에 닿을 수 있습니다.

22.2 상호 재귀는 미리 선언

local function a는 자기 이름은 볼 수 있지만 아직 정의되지 않은 다른 함수는 못 봅니다.

✘ nil을 부르게 됨
local function parseStmt()
  return parseExpr()      -- 아직 nil!
end
local function parseExpr()
  ...
end
✔ 먼저 선언
local parseExpr           -- 선언만

local function parseStmt()
  return parseExpr()      -- upvalue로 붙잡힘
end

function parseExpr()      -- local 없이 대입
  ...
end
오른쪽 아래에서 local을 빼먹으면 안 됩니다. local function parseExpr()이라고 쓰면 새 지역 변수가 생겨 위에서 붙잡은 것과 달라집니다. 이미 선언된 이름에 대입할 때는 function parseExpr()(local 없이)이라고 써야 합니다.
이 미묘함 때문에, 책의 파서는 모든 규칙 함수를 Parser 테이블의 메서드로 만듭니다. self:parse_expr()은 호출 시점에 조회되므로 선언 순서를 신경 쓸 필요가 없습니다.

22.3 스택 한계

local function bad(n)
  if n == 0 then return 0 end
  return 1 + bad(n - 1)        -- 더하기 때문에 꼬리 호출이 아님
end
print(pcall(bad, 1000000))
--> false    stack overflow
lua: c.lua:9: stack overflow stack traceback: c.lua:9: in function 'bad' c.lua:9: in function 'bad' ... (skipping 199990 levels)

재귀 깊이는 대략 20만 단계에서 막힙니다(빌드에 따라 다름). 다행히 pcall로 잡히므로 프로그램이 죽지는 않습니다.

인터프리터에서의 함의 — BASIC의 GOSUB은 Lua 함수 호출로 구현하지 않습니다. 복귀 주소를 vm.calls 배열에 직접 쌓습니다. 그래야 BASIC 쪽 재귀 깊이가 Lua의 스택 한계와 무관해지고, RETURN 없이 GOTO로 빠져나가는 BASIC 특유의 코드도 처리할 수 있습니다.

22.4 꼬리 호출은 스택을 쓰지 않는다

return f(...) 형태로 다른 일을 전혀 남기지 않고 호출하면, Lua는 현재 스택 프레임을 재사용합니다. 이를 적정 꼬리 호출(proper tail call)이라고 하며, 언어 명세가 보장합니다.

local function loop(n)
  if n == 0 then return "끝" end
  return loop(n - 1)          -- 꼬리 호출
end
print(loop(3000000))          --> 끝    (300만 단계도 문제없음)
꼬리 호출 ✔return f(x)
꼬리 호출 ✘return 1 + f(x) — 돌아와서 더해야 함
꼬리 호출 ✘return (f(x)) — 괄호가 값을 하나로 조정하는 일을 남김
꼬리 호출 ✘local r = f(x); return r — 대입이 끼어듦
대가 — 스택 프레임이 사라지므로 에러 트레이스백에서 그 호출이 안 보입니다. (...tail calls...)라고만 표시됩니다. 디버깅이 어려워지는 것과 무한 깊이를 맞바꾸는 셈입니다.

22.5 재귀를 루프로 바꾸기

VM의 실행 루프처럼 수백만 번 도는 자리에서는 재귀 대신 while이 낫습니다.

재귀
local function run(vm)
  local op = vm.ops[vm.ip]
  if vm.halted then return end
  vm.ip = vm.ip + 1
  vm:exec(op)
  return run(vm)          -- 꼬리 호출
end
루프
function VM:run()
  while not self.halted and self.ip <= #self.ops do
    local op = self.ops[self.ip]
    self.ip = self.ip + 1     -- 꺼낸 직후에 올린다
    self:exec(op)
  end
end
꼬리 호출이라 둘 다 스택은 안전합니다. 그래도 루프가 더 빠르고 읽기도 쉽습니다. 책의 VM은 오른쪽입니다. 재귀는 구조가 재귀적인 파서에 어울리고, 반복은 구조가 평평한 VM에 어울립니다.
self.ip = self.ip + 1의 위치가 규칙의 전부입니다. 핸들러를 부르기 전에 올려 두면, JMP 핸들러는 vm.ip = op.arg라고 덮어쓰기만 하면 되고, GOSUB은 vm.ip를 그대로 복귀 주소로 저장하면 됩니다(이미 다음 명령을 가리키므로). 순서를 바꾸면 모든 점프가 한 칸씩 어긋납니다.

22.6 확인 문제

아래 코드는 무엇을 찍을까요? 그리고 왜?

local fs = {}
local i = 1
while i <= 3 do
  local j = i
  fs[i] = function() return i, j end
  i = i + 1
end
print(fs[1]())

4    1

  • i는 루프 바깥에 선언된 변수 하나뿐입니다. 세 클로저가 같은 i를 붙잡고 있고, 루프가 끝났을 때 그 값은 4입니다.
  • j는 루프 몸통 안의 local이라 회차마다 새로 만들어집니다. 첫 회차의 j는 1로 고정됩니다.

수치 for의 루프 변수는 j처럼 동작합니다(회차마다 새 변수). 그래서 21.3절의 예가 1 2 3을 찍은 것입니다.

string.format

C의 printf를 거의 그대로 가져왔습니다.

24.1 기본 사용

print(string.format("pc=%d op=%s", 12, "PUSH"))
--> pc=12 op=PUSH

-- 메서드 형태로도 (자주 쓰는 관용구)
print(("%s=%d"):format("x", 5))
--> x=5
%d %i정수. 소수부가 있으면 에러입니다(5.3+).
%f고정 소수점. 기본 6자리 → 3.141590
%g짧은 쪽 자동 선택. Lua의 tostring이 쓰는 방식(%.14g)
%e지수 표기 → 1.234568e+04

24.2 폭과 정밀도

print(string.format("[%5d]",   42))       --> [   42]   오른쪽 정렬
print(string.format("[%-5d]",  42))       --> [42   ]   왼쪽 정렬
print(string.format("[%05d]",  42))       --> [00042]   0 채우기
print(string.format("[%8.3f]", 3.14159))  --> [   3.142] 소수 3자리
print(string.format("[%.3s]",  "abcdef")) --> [abc]     문자열도 자름
print(string.format("[%+d]",   42))       --> [+42]     부호 항상
%숫자는 최소 폭, .숫자는 정밀도입니다. 숫자에서는 소수 자릿수, 문자열에서는 최대 길이를 뜻합니다.
GW-BASIC의 PRINT USING이 이것과 비슷한 일을 합니다. PRINT USING "###.##"; X는 %6.2f에 가깝지만 규칙이 달라서, 책에서는 string.format으로 바로 매핑하지 않고 직접 자리를 세어 만듭니다.

24.3 함정 세 가지

  1. %d에 실수를 넘기면 에러입니다(5.3+). 
    string.format("%d", 3.5)
-- bad argument #2 to 'format'
--   (number has no integer representation)
    3.0은 통과하지만 3.5는 안 됩니다. 계산 결과를 찍을 때는 math.floor를 거치거나 %g를 쓰세요.
  2. 5.1의 %s는 테이블을 못 받습니다. 
    -- 5.4: OK, "table: 0x..." 출력
-- 5.1: bad argument #2 to 'format' (string expected, got table)
string.format("%s", {})
    tostring()을 직접 감싸면 양쪽에서 안전합니다.
  3. 인자가 모자라면 에러입니다. string.format("%d %d", 1) → bad argument #3 to 'format' (no value).
에러 메시지를 만들 때는 string.format보다 ..가 안전할 때가 있습니다. 값이 nil일 가능성이 있는 자리에는 tostring(v)을 씌우는 습관을 들이세요 — 에러 처리 코드가 에러를 내면 원인 추적이 두 배로 어려워집니다.

24.4 %q — 디버깅에 유용

local s = 'a"b\nc'
print(s)                          --> a"b
                                  --> c
print(string.format("%q", s))     --> "a\"b\
                                  --> c"

%q는 결과를 Lua 소스로 다시 읽을 수 있게 만듭니다. 눈에 안 보이는 문자(줄바꿈, 탭, 널)가 그대로 드러나므로, 토큰의 실제 내용을 확인할 때 특히 유용합니다.

-- 어휘 분석기 디버그 출력
for _, t in ipairs(tokens) do
  print(string.format("%-8s %q", t.type, tostring(t.value)))
end
NUMBER "10" KEYWORD "PRINT" STRING "HI" EOL "\ "
왜 print(t.text)로는 부족한가 — 공백이나 줄바꿈이 섞이면 출력에서 구분이 안 됩니다. “토큰 텍스트가 "PRINT "인지 "PRINT"인지”가 버그의 원인일 때, %q가 즉시 답을 줍니다.

24.5 확인 문제

GW-BASIC의 PRINT는 양수 앞에 공백 하나를 붙이고 뒤에도 공백을 하나 붙입니다(PRINT 42 →  42 ). 음수는 -가 그 앞 공백 자리를 차지합니다. string.format으로 어떻게 만들까요?

서식 하나로는 안 됩니다. 부호를 직접 판정해야 합니다.

local function basic_num(v)
  local s
  if v == math.floor(v) and math.abs(v) < 1e15 then
    s = string.format("%d", v)
  else
    s = tostring(v)
  end
  if v >= 0 then s = " " .. s end   -- 양수는 앞에 공백
  return s .. " "                    -- 뒤에는 언제나 공백
end

print("[" .. basic_num(42)  .. "]")   --> [ 42 ]
print("[" .. basic_num(-42) .. "]")   --> [-42 ]

%+d는 +42가 되어 버리니 쓸 수 없습니다. “언어의 서식이 있어도 결국 직접 짜야 한다”는 것이, 남의 언어를 흉내 내는 인터프리터 작업의 일상입니다.

25장

패턴 문법

정규식이 아닙니다. 더 작고, 규칙이 스무 개도 안 됩니다.

25.1 왜 정규식이 아닌가

정규식 엔진은 그 자체로 수천 줄짜리 프로그램입니다. “작은 것”을 목표로 하는 Lua는 그 대신 200줄짜리 패턴 매처를 표준 라이브러리에 넣었습니다.

있는 것문자 클래스, 문자 집합, 앵커, 수량자 4종, 캡처, 균형 매칭 %b, 경계 %f
없는 것선택 |, 그룹 반복 (ab)+, {n,m} 횟수 지정, 전방/후방 탐색, 비탐욕 +?(대신 -가 있음), 백트래킹 제어
가장 아쉬운 것은 |입니다. “A 또는 B”를 한 패턴으로 못 씁니다. 그래서 Lua에서는 패턴 하나로 욕심내지 말고 여러 번 시도하거나, 손으로 분기합니다. 이 책의 어휘 분석기가 elseif 사슬인 이유이기도 합니다.

25.2 문자 클래스

.아무 글자 (줄바꿈 포함)
%a알파벳 [A-Za-z]
%d숫자 [0-9]
%l / %u소문자 / 대문자
%s공백류 (스페이스·탭·줄바꿈)
%w영숫자 [A-Za-z0-9] — 밑줄은 포함되지 않습니다
%p구두점
%c제어 문자
%x16진 숫자
%A %D %S %W …대문자면 여집합. %S는 “공백이 아닌 것”
%w에 밑줄이 없다는 점이 자주 문제입니다. 프로그래밍 언어의 식별자를 잡으려면 [%w_]라고 써야 합니다. 책의 어휘 분석기도 c:match("[%a_]")로 시작 글자를, [%w_]로 이어지는 글자를 판정합니다.

25.3 문자 집합과 마법 문자

[abc]        -- a 또는 b 또는 c
[a-z]        -- 범위
[%a%d_]      -- 클래스도 넣을 수 있음
[^%s]        -- 여집합 (%S와 같음)
[%]]         -- ] 자체를 넣으려면 % 로 escape
마법 문자 11개 — ^ $ ( ) % . [ ] * + - ?
이 글자들을 글자 그대로 찾으려면 앞에 %를 붙입니다. 정규식의 \가 아니라 %입니다.
print(("a.b"):match("a%.b"))    --> a.b     진짜 점
print(("a.b"):match("a.b"))     --> a.b     아무 글자 (여기선 우연히 같음)
print(("axb"):match("a%.b"))    --> nil
print(("100%"):gsub("%%", ""))  --> 100  1  퍼센트 기호 제거
문자열을 그대로 찾고 싶을 때는 find의 네 번째 인자에 true를 주면 패턴 해석을 아예 끕니다: s:find(".", 1, true). match와 gsub에는 이 옵션이 없습니다.

25.4 수량자 네 개

*0회 이상, 탐욕적 (최대한 많이)
+1회 이상, 탐욕적
-0회 이상, 비탐욕적 (최대한 적게)
?0회 또는 1회
-가 비탐욕 *입니다. 정규식의 *?에 해당합니다. +의 비탐욕 버전은 없습니다.
local s = '"abc" tail "def"'
print(s:match('"(.*)"'))    --> abc" tail "def    탐욕 — 마지막 따옴표까지
print(s:match('"(.-)"'))    --> abc               비탐욕 — 첫 따옴표까지
수량자는 한 글자에만 붙습니다. 클래스·집합·글자 하나에만 적용되고, (ab)+처럼 그룹에는 못 붙입니다. 이게 정규식과의 가장 큰 실용적 차이입니다.

25.5 앵커와 캡처

^abc      -- 문자열 시작
abc$      -- 문자열 끝
^abc$     -- 전체가 정확히 abc
^는 패턴 맨 앞에서만, $는 맨 뒤에서만 앵커입니다. 다른 자리에 있으면 그냥 글자입니다. 정규식과 달리 “줄 단위” 앵커가 아니라 문자열 전체 기준입니다.

캡처는 괄호로 감싼 부분입니다. 매칭에 성공하면 그 부분들이 반환됩니다.

print(("key = val"):match("(%w+)%s*=%s*(%w+)"))
--> key    val

print(("2026-08-12"):match("(%d+)-(%d+)-(%d+)"))
--> 2026   08   12
캡처가 없으면match는 매칭된 전체를 돌려줍니다.
캡처가 있으면전체 대신 캡처들만 순서대로 돌려줍니다.
%1 %2패턴 안에서 “앞서 캡처한 것과 같은 문자열”을 뜻합니다.
() 빈 캡처위치를 캡처합니다. 숫자가 반환됩니다.

25.6 특수 항목 %b와 %f

-- %bxy : x로 시작해 짝이 맞는 y까지 (중첩 고려)
print(("(a(b)c)rest"):match("%b()"))
--> (a(b)c)

-- %f[집합] : "경계" — 앞 글자는 집합 밖, 현재 글자는 집합 안
print(("THE (quick) fox"):match("%f[%a]%a+%f[%A]"))
--> THE
%b()는 정규식으로는 아예 불가능한 일을 합니다. 중첩된 괄호의 짝을 세어 맞추기 때문입니다. 표현식 안의 괄호 덩어리를 통째로 떼어낼 때 유용합니다.
%f는 단어 경계(정규식의 \b)에 해당합니다. 5.1부터 있지만 매뉴얼에 늦게 문서화되어 잘 알려지지 않았습니다. 이 책에는 나오지 않습니다.

26장

패턴 함수 4종

find · match · gmatch · gsub

26.1 무엇을 쓸지 고르는 법

s:find(p [, init [, plain]])위치를 알고 싶을 때. 시작, 끝을 돌려주고, 캡처가 있으면 그 뒤에 덧붙입니다. 없으면 nil.
s:match(p [, init])내용을 뽑고 싶을 때. 캡처들(없으면 전체)을 돌려줍니다. 없으면 nil.
s:gmatch(p)전부 훑고 싶을 때. for에 넣는 반복자를 돌려줍니다.
s:gsub(p, r [, n])바꾸고 싶을 때. 바뀐 문자열, 바뀐 횟수 두 값을 돌려줍니다.
print(("hello world"):find("o w"))   --> 5   7
print(("hello"):find("l+"))          --> 3   4
print(("hello"):match("l+"))         --> ll
print(("a.b"):find(".", 1, true))    --> 2   2   패턴 해석 끄기
find는 “있는가/어디에”, match는 “무엇이”를 묻습니다. 존재만 확인할 때는 if s:find(p) then이 관용적입니다.

26.2 직접 돌려 보기

아래 데모는 Lua의 패턴 매처(lstrlib.c)를 그대로 옮긴 것이라, 진짜 Lua와 결과가 같습니다.

패턴 실험실

26.3 gmatch — 없는 split 만들기

-- 공백으로 나누기
for w in ("A B  C"):gmatch("%S+") do io.write(w, "|") end
--> A|B|C|

-- 캡처가 둘이면 두 값을 받습니다
for k, v in ("a=1,b=2"):gmatch("(%w+)=(%w+)") do
  print(k, v)
end
--> a  1
--> b  2

표준 split이 없으니 이렇게 만듭니다.

local function split(s, sep)
  local out = {}
  for piece in s:gmatch("([^" .. sep .. "]+)") do
    out[#out + 1] = piece
  end
  return out
end
print(#split("10,20,30", ","))    --> 3
이 split은 빈 필드를 건너뜁니다. "a,,b"는 두 조각이 됩니다. 빈 칸까지 보존하려면 gmatch 대신 find로 구분자 위치를 하나씩 찾아가야 합니다. “대충 되는 split”과 “정확한 split”은 다릅니다 — BASIC의 DATA 문을 파싱할 때 실제로 걸리는 문제입니다.

26.4 gsub의 세 가지 치환 방식

-- ① 문자열: %1 %2 로 캡처 참조, %0 은 전체
print(("hello"):gsub("l", "L"))            --> heLLo   2
print(("hello"):gsub("l", "L", 1))         --> heLlo   1   횟수 제한
print(("a-b"):gsub("(%w)-(%w)", "%2-%1"))  --> b-a     1

-- ② 테이블: 캡처를 키로 조회
print(("$name"):gsub("%$(%w+)", {name = "Lua"}))   --> Lua   1

-- ③ 함수: 캡처를 인자로 받아 반환값으로 치환
print(("abc"):gsub("%a", function(c) return c:upper() end))
--> ABC   3
반환값 두 개바뀐 문자열, 바뀐 횟수. 두 번째를 잊고 print(s:gsub(...))하면 숫자가 하나 더 찍힙니다.
함수/테이블이 nil이나 false를 주면치환하지 않고 원래 문자열을 남깁니다. 조건부 치환에 유용합니다.
치환 문자열 안의 %%%로 escape해야 합니다. 사용자 입력을 치환값으로 쓸 때 사고가 납니다.

27.3 확인 문제

사용자가 입력한 문자열 needle이 haystack에 들어 있는지 확인하려고 haystack:find(needle)이라고 썼습니다. 무엇이 잘못됐고, 어떻게 고쳐야 할까요?

needle이 패턴으로 해석됩니다. 사용자가 a.b나 100%를 입력하면 의도와 다르게 동작하거나, %로 끝나면 malformed pattern (ends with '%') 에러까지 납니다.

두 가지 해법이 있습니다.

-- ① plain 모드 (가장 간단)
haystack:find(needle, 1, true)

-- ② 마법 문자를 escape
local function esc(s) return (s:gsub("(%W)", "%%%1")) end
haystack:find(esc(needle))

②의 "%%%1"은 “퍼센트 기호 하나 + 첫 캡처”라는 뜻입니다. 그리고 바깥 괄호는 gsub의 두 번째 반환값(횟수)을 잘라내기 위한 것입니다 — 19장의 조정 규칙이 여기서 쓰입니다.

28.1 개념

테이블에 메타테이블을 붙이면, 그 테이블에 대한 특정 연산이 일어날 때 Lua가 메타테이블의 약속된 필드를 찾아 대신 실행합니다. 그 필드를 메타메서드라고 합니다.

local mt = {
  __index = function(t, k) return "없음:" .. k end
}
local t = setmetatable({}, mt)

print(t.x)              --> 없음:x
print(rawget(t, "x"))   --> nil     메타테이블을 건너뛴 진짜 값
setmetatable(t, mt)메타테이블을 붙이고 t를 돌려줍니다. 그래서 return setmetatable({}, mt)가 관용구입니다.
getmetatable(t)붙은 메타테이블을 돌려줍니다.
rawget / rawset메타메서드를 거치지 않고 읽고 씁니다.
setmetatable(t, nil)떼어 냅니다.
메타테이블은 “있으면 참고하는 규칙집”입니다. 테이블 자체는 여전히 평범한 테이블이고, 값이 실제로 있으면 메타테이블은 아예 쳐다보지도 않습니다.

28.2 이미 쓰고 있었다 — 문자열

print(getmetatable("").__index == string)   --> true

모든 문자열은 같은 메타테이블 하나를 공유하고, 그 __index가 string 테이블입니다. 그래서 s:upper()가 string.upper(s)로 풀립니다.

  1. s:upper() — s에서 upper를 찾는다. 문자열에는 필드가 없으니 실패.
  2. 메타테이블의 __index를 본다 → string 테이블.
  3. string.upper를 찾는다. 있다.
  4. : 문법이므로 s를 첫 인자로 넣어 string.upper(s)를 호출한다.
숫자·불리언·​nil에는 기본 메타테이블이 없습니다. (5):foo()가 안 되는 이유이고, #42가 에러인 이유입니다. 테이블에도 기본 메타테이블은 없습니다 — 직접 붙여야 합니다.

__index와 조회 체인

상속처럼 보이는 것의 정체.

29.1 두 가지 형태

__index가 테이블일 때
local Base = { greet = function() return "hi" end }
local t = setmetatable({}, { __index = Base })
print(t.greet())     --> hi

그 테이블에서 같은 키를 다시 찾습니다. 상속에 씁니다.

__index가 함수일 때
local t = setmetatable({}, {
  __index = function(t, k)
    return 0            -- 기본값
  end
})
print(t.anything)    --> 0

호출해서 결과를 씁니다. 기본값·가상 필드에 씁니다.

rawget과의 차이를 기억하세요. __index가 있으면 “없는 키”와 “nil인 키”를 구분할 수 없게 됩니다. 진짜로 있는지 알아야 할 때는 rawget(t, k) ~= nil을 쓰세요.

29.2 조회 순서

  1. t 자신에 키가 있으면 그 값을 돌려주고 끝. 메타테이블은 보지도 않습니다.
  2. 없으면 t의 메타테이블에 __index가 있는지 봅니다. 없으면 nil.
  3. __index가 함수면 호출해 결과를 돌려줍니다.
  4. __index가 테이블이면 그 테이블에 대해 1번부터 다시 — 즉 재귀적으로 체인을 탑니다.
3단 체인에서 키를 찾아보기

시도해 볼 키: name(obj에 있음) · kind(중간에 있음) · greet(맨 위에 있음) · zzz(어디에도 없음)

29.3 __newindex — 쓰기를 가로채기

-- 읽기 전용 테이블 만들기
local function readonly(t)
  return setmetatable({}, {
    __index = t,
    __newindex = function() error("읽기 전용입니다", 2) end,
  })
end

local C = readonly{ MAX_LINE = 65529 }
print(C.MAX_LINE)     --> 65529
C.MAX_LINE = 1        --> 에러: 읽기 전용입니다
__newindex도 “없는 키에 쓸 때”만 발동합니다. 이미 그 키가 있으면 그냥 덮어씁니다. 그래서 위 예처럼 빈 껍데기 테이블을 만들고 실제 값은 __index 쪽에 두는 것입니다.
error(msg, 2)의 2는 “에러 위치를 한 단계 위(=호출한 쪽)로 보고하라”는 뜻입니다. 그래야 사용자에게 이 함수 안이 아니라 잘못 쓴 줄이 표시됩니다 (34장).

29.4 인터프리터에서의 쓸모

BASIC 변수 환경에 기본값을 주는 데 쓸 수 있습니다 (16.5절에서 예고한 ②번 방식).

local vars = setmetatable({}, {
  __index = function(t, name)
    return name:sub(-1) == "$" and "" or 0
  end
})
print(vars.X)        --> 0
print(vars["A$"])    --> ""
그런데 책은 이 방식을 쓰지 않습니다. 이유가 있습니다.
  • DIM으로 선언됐는지를 구분할 수 없게 됩니다 — 모든 이름이 값을 갖는 것처럼 보입니다.
  • pairs(vars)로 실제 정의된 변수만 나열하는 LIST 계열 기능이 어긋납니다.
  • 디버깅할 때 “왜 0이 나오지?”의 원인이 코드에서 멀어집니다.
명시적인 get_var() 함수가 길지만 거짓말을 하지 않습니다.

:와 . — self의 정체

문법 설탕 하나가 전부입니다.

30.1 규칙 두 줄

정의: function T:m(a) 는 function T.m(self, a) 의 줄임말.

호출: o:m(x) 는 o.m(o, x) 의 줄임말.

-- 이 네 줄은 완전히 같은 일을 합니다
function Lexer:peek()      return self.src:sub(self.pos, self.pos) end
function Lexer.peek(self)  return self.src:sub(self.pos, self.pos) end

lx:peek()
lx.peek(lx)
self는 예약어가 아닙니다. :로 정의할 때 컴파일러가 몰래 넣어 주는 첫 번째 매개변수의 이름일 뿐입니다. .로 정의하면서 첫 인자 이름을 me라고 지어도 됩니다.

30.2 짝이 안 맞으면

정의와 호출의 네 가지 조합
실수 유형은 하나뿐입니다 — :로 정의하고 .로 부르는 것. 그러면 self가 nil이 되어 attempt to index a nil value (local 'self')가 납니다. 에러 메시지에 'self'가 보이면 십중팔구 이것입니다.
.로 정의하고 :로 부르면 인자가 한 칸씩 밀립니다. 에러가 안 날 수도 있어서 더 나쁩니다.

30.3 메서드를 콜백으로 넘길 때

-- ✘ self가 사라집니다
setCallback(vm.step)

-- ✔ 클로저로 감싸기
setCallback(function() vm:step() end)

-- ✔ 또는 명시적으로 넘기기
setCallback(vm.step, vm)
vm.step은 그냥 함수 값입니다. vm과의 연결은 :로 호출하는 순간에만 생깁니다. 함수를 꺼내서 넘기면 그 연결이 끊깁니다.
다른 언어의 “바운드 메서드”가 없다고 생각하면 됩니다. Python의 obj.method는 self를 기억하지만, Lua의 obj.method는 기억하지 않습니다.

30.4 메서드 체이닝

-- 문자열은 매번 새 문자열을 돌려주므로 자연스럽게 이어집니다
text:gsub("[dD]", "e"):gsub("[%%!#]$", "")

-- 우리 객체에서도 self를 돌려주면 체이닝이 됩니다
function Buf:add(s) self.parts[#self.parts + 1] = s; return self end
function Buf:done()  return table.concat(self.parts) end

print(Buf.new():add("A"):add("B"):done())   --> AB
gsub 체이닝의 함정 — gsub은 두 값을 돌려주지만 :는 첫 값에만 붙습니다. 그래서 체이닝은 잘 되지만, 맨 마지막 결과도 두 값이라는 점은 그대로입니다. 
local t = { text:gsub("a", "b") }
print(#t)                              --> 2   (문자열, 횟수)

local text = text:gsub("a", "b")       -- 변수 하나면 횟수는 버려짐 ✔
return (text:gsub("a", "b"))           -- 괄호로 잘라내기 ✔

30.5 확인 문제

아래 코드는 왜 에러가 날까요?

local Stack = {}
Stack.__index = Stack

function Stack.new()
  return setmetatable({items = {}}, Stack)
end

function Stack:push(v)
  self.items[#self.items + 1] = v
end

local s = Stack.new()
local push = s.push
push("x")
lua: q11.lua:4: attempt to get length of a nil value (field 'items')

local push = s.push는 함수 값만 꺼내 옵니다. push("x")로 부르면 self 자리에 "x"가 들어가고 v는 nil이 됩니다.

  1. self.items — self는 문자열입니다. 문자열에는 메타테이블이 있으므로(28.2절) 이건 에러가 아니라 string.items 조회이고, 결과는 nil입니다.
  2. #nil — 여기서 터집니다. 그래서 메시지가 index가 아니라 get length of이고, 범인이 (field 'items')로 지목됩니다.

고치는 법:

push(s, "x")                      -- 명시적으로 self 전달
-- 또는
local push = function(v) s:push(v) end
push("x")
교훈 — 에러 메시지가 self를 직접 지목하지 않을 수도 있습니다. “nil이 어디서 왔는가”를 한 단계 거슬러 올라가는 습관이 필요합니다.

end

local lx = Lexer.new("10 PRINT")
print(lx:peek())     --> 1
  1. Lexer는 그냥 테이블입니다. 여기에 메서드들이 담깁니다.
  2. Lexer.__index = Lexer — “나를 메타테이블로 쓰는 객체가 없는 키를 찾으면, 나에게서 찾아라”.
  3. Lexer.new는 인스턴스 상태만 담은 새 테이블을 만들고 Lexer를 메타테이블로 붙입니다.
  4. lx:peek() — lx에 peek이 없으므로 __index를 타고 Lexer.peek을 찾아 lx를 self로 호출합니다.
Lexer.__index = Lexer가 없으면 인스턴스는 메서드를 하나도 못 찾습니다. attempt to call a nil value (method 'peek'). 이 한 줄 빠뜨리는 것이 가장 흔한 실수입니다.

31.2 왜 이렇게 하는가

메서드를 인스턴스에 직접 넣으면
function Lexer.new(src)
  local self = {src = src, pos = 1}
  self.peek = function() ... end
  self.advance = function() ... end
  return self
end

객체 하나마다 클로저가 여러 개 새로 만들어집니다. 메모리도, 생성 시간도 낭비입니다.

메타테이블 방식
local Lexer = {}
Lexer.__index = Lexer
function Lexer:peek() ... end

메서드는 프로그램 전체에 하나씩만 존재합니다. 인스턴스는 상태만 담습니다.

인스턴스가 하나뿐이라면 굳이 이 구조가 필요 없습니다. 그냥 모듈 테이블에 함수를 넣고 상태도 그 안에 두면 됩니다. 이 책이 Lexer​·​Parser​·​VM을 클래스로 만든 이유는 REPL에서 여러 번, 그리고 테스트에서 동시에 만들어 쓰기 때문입니다.

31.3 상속

local Base = {}
Base.__index = Base
function Base.new(n)  return setmetatable({n = n}, Base) end
function Base:show()  return "Base:" .. self.n end
function Base:kind()  return "base" end

local Derived = setmetatable({}, { __index = Base })   -- ← 클래스끼리 연결
Derived.__index = Derived
function Derived.new(n) return setmetatable({n = n}, Derived) end
function Derived:kind() return "derived" end           -- 재정의

local d = Derived.new(1)
print(d:kind())    --> derived     Derived에서 찾음
print(d:show())    --> Base:1      Derived에 없어 Base까지 올라감
두 개의 __index가 필요합니다. ① 인스턴스 → 클래스, ② 클래스 → 부모 클래스. 첫 번째는 Derived.__index = Derived, 두 번째는 setmetatable(Derived, {__index = Base})입니다. 이 둘을 헷갈리면 조회가 엉뚱한 곳에서 끊깁니다.
이 책에는 상속이 나오지 않습니다. Lexer​·​Parser​·​Compiler​·​VM은 서로 상속 관계가 아니라 파이프라인의 단계이기 때문입니다. 다만 남의 Lua 코드에는 자주 나오므로 모양은 알아 둘 값어치가 있습니다.

31.4 부모 메서드 부르기

function Derived:show()
  return "[" .. Base.show(self) .. "]"    -- 콜론이 아니라 점 + self 명시
end
Base:show()라고 쓰면 안 됩니다. 그러면 self가 Base(클래스 자신)가 되어 인스턴스의 상태를 못 봅니다. super 키워드가 없으니 부모 테이블 이름을 직접 적고 self를 손으로 넘겨야 합니다.
생성자에서도 마찬가지입니다. 
function Derived.new(n, extra)
  local self = Base.new(n)                -- 부모 생성자
  self.extra = extra
  return setmetatable(self, Derived)      -- 메타테이블만 바꿔치기
end
부모가 만든 테이블을 받아 필드를 더하고, 메타테이블만 자식 것으로 교체하는 방식입니다.

메서드: peek, advance, emit, lex_number, lex_string, lex_ident, tokenize
Parser상태: toks, pos
메서드: cur, advance, check, accept, expect, parse_binop, peek_binop, parse_stmt, parse_line
Compiler상태: ops, line_map, 백패치 목록

advance가 Lexer와 Parser 양쪽에 있습니다. 이름은 같지만 다루는 것이 다릅니다 — 하나는 문자, 하나는 토큰(그래서 “현재 것 보기”도 Lexer:peek / Parser:cur로 이름이 갈립니다). 상속으로 묶고 싶은 유혹이 들지만, 공통 부분이 두 줄뿐이라 그대로 두는 편이 읽기 쉽습니다. “구조가 비슷하다”가 “상속해야 한다”는 뜻은 아닙니다.

32.1 __tostring — 디버깅에 가장 유용

local Token = {}
Token.__index = Token
Token.__tostring = function(t)
  return string.format("<%s %q @%d>", t.type, tostring(t.value), t.line)
end

local tk = setmetatable({type = "NUMBER", value = 10, line = 1}, Token)
print(tk)              --> <NUMBER "10" @1>
print(tostring(tk))    --> 같은 결과
print(t)가 table: 0x...만 찍는 답답함을 없애 줍니다. 토큰·AST 노드·명령처럼 눈으로 확인할 일이 많은 자료구조에 붙여 두면 디버깅 속도가 확 달라집니다.
..에는 적용되지 않습니다. "tok: " .. tk는 여전히 에러입니다. 연결에는 __concat이 따로 있습니다. tostring(tk)을 명시적으로 감싸는 습관이 안전합니다.

32.2 __call — 테이블을 함수처럼

local ast = setmetatable({}, {
  __call = function(self, tag, fields)
    fields = fields or {}
    fields.tag = tag
    return fields
  end
})

local node = ast("Num", {value = 10})
print(node.tag, node.value)     --> Num    10
쓸모 — “주 기능이 하나인데 부가 함수도 있는” 모듈에 어울립니다. M(x)로 주 기능을, M.helper(x)로 부가 기능을 부를 수 있습니다. 다만 코드를 읽는 사람이 테이블인데 왜 호출되지? 하고 멈추게 되므로, 남발하지 않는 편이 좋습니다.

32.3 연산자 오버로딩

local Vec = {}
Vec.__index = Vec
Vec.__add = function(a, b) return Vec.new(a.x + b.x, a.y + b.y) end
Vec.__eq  = function(a, b) return a.x == b.x and a.y == b.y end
Vec.__lt  = function(a, b) return a.x < b.x end
Vec.__tostring = function(v) return "(" .. v.x .. "," .. v.y .. ")" end
function Vec.new(x, y) return setmetatable({x = x, y = y}, Vec) end

print(Vec.new(1,2) + Vec.new(3,4))     --> (4,6)
print(Vec.new(1,2) == Vec.new(1,2))    --> true
__eq의 제약두 피연산자가 모두 테이블이고, 서로 다른 객체일 때만 호출됩니다. 타입이 다르면 그냥 false입니다.
__lt만 정의하면5.4에서는 >가 피연산자를 뒤집어 __lt를 씁니다. __le는 따로 정의해야 합니다.
어느 쪽 메타테이블?왼쪽 피연산자의 것을 먼저 보고, 없으면 오른쪽을 봅니다.
이 책은 연산자 오버로딩을 쓰지 않습니다. BASIC의 값은 그냥 Lua의 숫자와 문자열이고, 연산은 VM 명령이 명시적으로 수행합니다. 오버로딩을 쓰면 “어디서 무슨 일이 일어나는지”가 코드에서 사라져, 인터프리터를 배우는 목적에 어긋납니다.

32.4 __len과 __index의 버전 차이

local t = setmetatable({}, {__len = function() return 42 end})
print(#t)
-- 5.4: 42
-- 5.1: 0     ← 테이블에는 __len이 안 통합니다
__len5.1에서는 userdata에만 적용됩니다. 테이블에 붙여도 무시됩니다.
__pairs5.2에서 추가. 5.1에는 없습니다.
__gc5.1에서는 userdata만. 테이블은 5.2+부터.
__ipairs5.2에서 추가되고 5.3에서 제거되었습니다. 쓰지 마세요.

32.5 확인 문제

아래 코드에서 print(v.x)는 무엇을 찍고, print(rawget(v, "x"))는 무엇을 찍을까요?

local defaults = { x = 0, y = 0 }
local v = setmetatable({ y = 5 }, { __index = defaults })
print(v.x, v.y)
print(rawget(v, "x"), rawget(v, "y"))
v.x = 9
print(v.x, defaults.x)
--> 0    5
--> nil  5
--> 9    0
  • v.x → v에 없으니 __index를 타고 defaults.x = 0.
  • v.y → v에 있으니 메타테이블을 보지도 않고 5.
  • rawget(v, "x") → 메타테이블을 건너뛰므로 nil. “진짜로 이 테이블에 있는가”를 묻는 방법입니다.
  • v.x = 9 → __newindex가 없으므로 v 자신에 x = 9가 생깁니다. defaults는 바뀌지 않습니다(여전히 0).
이 “읽기는 위로 올라가고, 쓰기는 제자리에” 하는 성질이 프로토타입 상속의 핵심입니다. JavaScript의 프로토타입 체인과 같은 규칙입니다.

33장

모듈과 require

규칙은 “테이블 하나를 돌려준다”가 전부입니다.

33.1 모듈의 모양

runtime.lua

local M = {}

M.EPSILON = 1e-9

function M.abs(x) return x < 0 and -x or x end

local function helper(x)        -- 밖에서 안 보이는 내부 함수
  return x * 2
end

function M.double(x) return helper(x) end

return M                        -- ← 이 줄이 핵심

vm.lua

local runtime = require("runtime")
print(runtime.abs(-3))     --> 3
print(runtime.helper)      --> nil     내부 함수는 안 보임
파일은 곧 함수입니다. Lua는 파일 전체를 하나의 함수(“청크”)로 컴파일해 실행하고, return한 값을 require의 결과로 줍니다. local로 선언한 것은 그 함수의 지역 변수이므로 밖에서 보이지 않습니다 — 이것이 Lua의 유일한 은닉 수단입니다.

33.2 require가 하는 일

  1. package.loaded["이름"]에 이미 있으면 그것을 그대로 돌려주고 끝냅니다.
  2. 없으면 package.path의 패턴들에서 ?를 이름으로 바꿔 가며 파일을 찾습니다.
  3. 찾으면 그 파일을 한 번 실행하고, 반환값을 package.loaded["이름"]에 저장합니다.
  4. 파일이 아무것도 return하지 않으면 true가 저장됩니다.
local m1 = require("m")
local m2 = require("m")
print(m1 == m2)                       --> true    같은 테이블
print(package.loaded["m"] == m1)      --> true
-- m.lua 안의 print는 딱 한 번만 실행됩니다 [m.lua 실행됨] true hi from m
캐싱은 실행 단위입니다. 모듈이 내부 상태(전역 카운터 등)를 갖고 있으면 프로그램 전체가 그것을 공유합니다. REPL에서 인터프리터를 여러 번 만드는 이 책이 모듈에 상태를 두지 않고 클래스 인스턴스에 두는 이유입니다.

33.3 package.path

$ lua -e 'print(package.path)' /usr/share/lua/5.4/?.lua; /usr/share/lua/5.4/?/init.lua; /usr/lib/lua/5.4/?.lua; ./?.lua; ./?/init.lua
?모듈 이름으로 치환됩니다. require("lexer") → ./lexer.lua
. → /require("src.lexer")는 ./src/lexer.lua를 찾습니다
현재 디렉터리./?.lua 항목 덕분입니다. 그래서 책의 실행법이 cd src 후 lua main.lua입니다
환경 변수LUA_PATH로 바꿀 수 있습니다. ;;는 “기본 경로를 여기 끼워 넣으라”는 뜻
-- 실행 중에 경로 추가하기
package.path = package.path .. ";../lib/?.lua"
못 찾으면 긴 에러가 납니다 — module 'xxx' not found: 뒤에 시도한 경로가 전부 나열됩니다. 겁먹지 말고 어디를 찾았는지 읽으면 문제가 바로 보입니다. 대개 실행 디렉터리가 다른 것입니다.

33.4 순환 의존

a.lua가 b를 부르고 b.lua가 다시 a를 부르면, a는 아직 return하지 않았으므로 package.loaded["a"]가 비어 있습니다. 부분적으로 초기화된 값이나 nil을 받게 됩니다.

이 책의 대책은 “애초에 만들지 않는 것”입니다. 의존 방향이 한쪽으로만 흐르도록 설계했습니다.
main.lua
  ├── lexer.lua
  ├── parser.lua  ── ast.lua
  ├── compiler.lua ── ast.lua
  │                ── runtime.lua
  └── vm.lua      ── runtime.lua

runtime.lua와 ast.lua는 아무것도 require하지 않습니다. 잎사귀 모듈을 의존성 없이 유지하는 것이 순환을 막는 가장 확실한 방법입니다.

피할 수 없다면 파일 맨 위가 아니라 함수 안에서 require하세요. 그러면 실제로 필요한 시점에는 상대 모듈이 완전히 로드돼 있습니다.

33.5 옛날 방식 module()

-- 5.1 시절 코드에서 보게 되는 것
module("mymod", package.seeall)
function foo() end          -- 전역처럼 보이지만 mymod.foo
module()은 5.2에서 폐지되었습니다. 전역 환경을 몰래 바꾸는 방식이라 부작용이 많았습니다. 오래된 Lua 코드나 튜토리얼에서 보이면 낡은 것이라고 판단하면 됩니다. 지금은 local M = {} … return M이 유일한 관례입니다.
다른 언어와 비교 — Lua에는 import x from y 같은 이름 단위 가져오기가 없습니다. 테이블을 통째로 받아 필드로 쓰거나, 필요한 것만 지역 변수로 꺼내 씁니다. 
local ast = require("ast")
local binary, number = ast.binary, ast.number     -- 자주 쓰는 것만 꺼내기
꺼내 쓰면 조회가 빨라지는 부수 효과도 있습니다 (38장).

34장

error와 pcall

예외가 없는 대신 이 둘이 있습니다.

34.1 error

error("문제 발생")           -- 위치가 자동으로 붙음
--> (command line):1: 문제 발생

error("문제 발생", 0)        -- 위치를 붙이지 않음
--> 문제 발생

error("문제 발생", 2)        -- 호출한 쪽의 위치를 붙임
두 번째 인자 = level1(기본): error를 부른 위치. 2: 그 함수를 호출한 위치. 0: 위치 없음.
왜 2가 필요한가인자 검증 함수에서 “네 잘못은 여기 있다”를 사용자 코드 줄로 가리키기 위해서입니다.
왜 0이 필요한가BASIC의 ?Syntax error처럼 우리가 만든 언어의 에러 메시지에 Lua 파일 이름과 줄 번호가 섞이면 안 되기 때문입니다.
이 책은 error(msg, 0)을 씁니다. BASIC 사용자에게 vm.lua:412: ?Type mismatch를 보여 줄 수는 없으니까요. 대신 BASIC 쪽 줄 번호를 직접 메시지에 넣습니다.

34.2 에러 값은 문자열이 아니어도 된다

error({ code = "TYPE_MISMATCH", line = 20 })

local ok, e = pcall(f)
print(type(e), e.code)      --> table    TYPE_MISMATCH
테이블을 던지면 구조화된 정보를 실을 수 있습니다. BASIC의 ON ERROR GOTO를 구현하려면 “몇 번 에러가 몇 번째 줄에서 났는가”가 필요합니다 — 문자열을 다시 파싱하는 것보다 테이블이 훨씬 낫습니다.
-- 책의 스타일
local function basic_error(code, msg, line)
  error({ basic = true, code = code, msg = msg, line = line }, 0)
end

basic_error(13, "Type mismatch", 20)
테이블 에러는 위치가 안 붙습니다. level 인자는 문자열일 때만 적용됩니다. 그리고 처리되지 않은 채 밖으로 나가면 lua: input:1: ? 같은 쓸모없는 메시지가 되므로, 반드시 pcall로 받아 직접 출력해야 합니다.

34.3 pcall

local ok, result = pcall(compile, src)
if ok then
  print("성공")
else
  print("실패: " .. tostring(result))
end

-- 익명 함수로 감싸면 인자를 자유롭게
local ok, a, b = pcall(function() return divmod(17, 5) end)
print(ok, a, b)     --> true  3  2
성공true 뒤에 함수의 모든 반환값
실패false 뒤에 에러 값 하나
인자 전달pcall(f, a, b)처럼 뒤에 붙이면 f(a, b)로 호출됩니다
잡히는 것error()는 물론 런타임 에러 전부(nil 인덱싱, 스택 오버플로 등)
pcall은 공짜가 아닙니다. 호출마다 보호 프레임이 하나 생깁니다. VM의 명령 실행 루프처럼 수백만 번 도는 안쪽에 두지 말고, 가장 바깥에 한 번 두는 것이 정석입니다.

34.4 xpcall과 트레이스백

  return debug.traceback(msg, 2)      -- 에러가 난 그 자리에서 스택을 뜬다
end)

pcall과의 차이 — pcall은 스택이 이미 풀린 뒤에 값을 돌려주므로 어디서 났는지를 알 수 없습니다. xpcall의 핸들러는 스택이 살아 있는 상태에서 호출되므로 트레이스백을 뜰 수 있습니다.
5.1의 xpcall은 인자를 전달하지 못합니다. xpcall(f, handler, a, b)의 a, b가 5.1에서는 그냥 무시됩니다 — 에러도 안 납니다. 5.1 호환 코드에서는 클로저로 감싸세요. 
xpcall(function() return f(a, b) end, handler)   -- 5.1~5.4 공통

관용구local x = assert(f()) — 실패를 무시하지 않겠다는 선언이자 코드 한 줄 절약

34.6 인터프리터의 에러 계층

인터프리터를 만들면 에러가 두 층이 됩니다. 이 둘을 섞지 않는 것이 설계의 핵심입니다.

BASIC 프로그램의 에러?Syntax error in 20, ?Division by zero — 정상 동작입니다. 사용자에게 보여 주고 REPL로 돌아가야 합니다.
인터프리터 자신의 버그vm.lua:412: attempt to index a nil value — 우리 잘못입니다. 트레이스백을 그대로 보여 주는 편이 낫습니다.

  if type(err) == "table" and err.basic then
    io.write("?", err.msg, " in ", tostring(err.line), "\n")   -- BASIC 에러

34.7 확인 문제

아래 두 코드의 출력 차이는?

37.1 문제

GW-BASIC의 AND​·​OR​·​XOR​·​NOT은 논리 연산이 아니라 비트 연산입니다. 16비트 정수로 계산합니다.

10 PRINT 12 AND 10      ' 8   (1100 AND 1010 = 1000)
20 PRINT 12 OR 10       ' 14
30 PRINT NOT 0          ' -1  (16비트 보수)
5.3+a & b, a | b, a ~ b, ~a, <<, >> 연산자가 있습니다.
5.1 / 5.2아무것도 없습니다. 5.2에 bit32 라이브러리가 잠깐 있었지만 5.3에서 폐기되었습니다.
LuaJITbit 라이브러리가 따로 있습니다. 표준이 아닙니다.
5.3+의 연산자는 문법이라 조건부로 쓸 수 없습니다. if VERSION >= 53 then return a & b end이라고 써도, 5.1은 그 파일을 컴파일하는 순간 문법 오류를 냅니다. 실행 여부와 무관합니다. 그래서 “양쪽에서 도는 하나의 파일”을 원하면 연산자를 아예 쓰지 않는 수밖에 없습니다.

37.2 직접 구현

-- vm.lua : 16비트 비트 연산 (5.1~5.4 공통)
local function band(a, b)
  local r, bit = 0, 1
  a, b = a % 65536, b % 65536
  while a > 0 and b > 0 do
    if a % 2 == 1 and b % 2 == 1 then r = r + bit end
    a = math.floor(a / 2)
    b = math.floor(b / 2)
    bit = bit * 2
  end
  return r
end

print(band(12, 10))     --> 8
  1. % 2로 최하위 비트를 꺼냅니다 (& 1 대신).
  2. math.floor(x / 2)로 오른쪽 시프트합니다 (>> 1 대신).
  3. 자리값 bit를 2배씩 올리며 결과를 더합니다.
bor​·​bxor도 3번 줄의 조건만 바꾸면 됩니다. bnot(a)는 16비트라면 65535 - a이고, BASIC의 NOT은 부호 있는 결과라 -(a + 1)입니다.
느립니다. 16비트면 최대 16번 반복합니다. 하지만 BASIC 프로그램에서 비트 연산은 드물게 나오므로 실측상 문제가 되지 않습니다. “느린 코드”와 “느린 프로그램”은 다릅니다 — 어디가 뜨거운지 재고 나서 최적화하세요.

-- A
local function isDigit(c) return c:match("%d") ~= nil end

-- B
local function isDigit(c) return c >= "0" and c <= "9" end

B가 빠릅니다. A는 호출마다 패턴 매처를 돌리고(문자열 메서드 조회 + 패턴 컴파일 없이 매칭), B는 비교 두 번입니다.

하지만 의미가 있는지는 “몇 번 부르는가”에 달렸습니다.

  • 어휘 분석기는 소스의 글자 수만큼 부릅니다. 수백 줄짜리 BASIC 프로그램이면 수천 번 — 차이가 안 보입니다.
  • 같은 함수를 VM 루프 안에서 부른다면 수백만 번이 되어 보입니다.

그리고 B에는 함정이 있습니다. 문자열 비교는 로케일 영향을 받고(5.2절), c가 빈 문자열이면 "" >= "0"은 false라 우연히 맞지만, 두 글자 이상이면 의도와 다르게 동작합니다.

책은 A를 씁니다 — 어휘 분석기는 뜨거운 곳이 아니고, c:match("%d")가 의도를 그대로 말해 주기 때문입니다. “빠른 코드”가 아니라 “맞는 자리에 쓴 코드”가 목표입니다.
