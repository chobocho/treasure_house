문제 : 자꾸 바뀌는 배열의 구간 합

숫자가 계속 변하는데, 매번 "1번~5번 합 알려줘!" 라고 물어본다면?

😵 단순 방법

  • 구간 합을 물을 때마다 하나씩 더한다 → 한 번에 O(N)
  • 값 하나 바꾸기는 빠름 → O(1)
  • 질문이 많아지면 너무 느려요 😢

😎 펜윅 트리

  • 구간 합 질문 → O(log N)
  • 값 하나 수정 → O(log N)
  • 코드도 짧고, 메모리도 배열 하나면 끝!

💡 핵심 한 줄 : 각 숫자를 적당한 크기의 "묶음"으로 미리 더해두면, 구간 합도 수정도 모두 log N 번의 점프로 끝납니다.

핵심 아이디어

비밀은 2진수의 마지막 1

lowbit(i) = i & (-i) : i를 2진수로 봤을 때, 가장 오른쪽 1이 가진 값

펜윅 트리의 tree[i] 칸은 "원래 배열에서 lowbit(i)개의 숫자"를 묶어서 더해 둡니다.

tree[i] = A[i-lowbit(i)+1] + ... + A[i]

즉 i번 칸이 담당하는 길이 = lowbit(i) 예요. 그래서 비트만 보면 누가 무엇을 담당하는지 바로 알 수 있죠!

숫자를 넣어 lowbit을 직접 확인 →

tree[8]은 8칸 전부를, tree[4]는 4칸을, tree[6]은 2칸, tree[5]·tree[7]은 1칸만 담당해요. 길이는 모두 lowbit 값과 똑같죠! 🌤️

동작 1 · 수정

update : 위로 점프하며 더하기

A[i]에 값을 더하면, i를 담당하는 모든 칸을 갱신해야 해요 → i += lowbit(i)

위치 i 더할 값
tree[] 배열
지금 갱신 중인 칸 이미 갱신한 칸
동작 2 · 합 구하기

query : 아래로 점프하며 더하기

"1번 ~ i번 합" 은, 겹치지 않는 묶음들을 주워 담으면 끝 → i -= lowbit(i)

1번부터 i번까지 합
tree[] 배열 (왼쪽 update 데모와 값 공유)
합에 더해지는 묶음

두 위치의 합을 빼면 어떤 구간 합도 OK : sum(l..r) = query(r) − query(l−1)
