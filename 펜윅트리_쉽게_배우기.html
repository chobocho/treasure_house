왜 필요할까?

문제 : 자꾸 바뀌는 배열의 구간 합

예) 배열 A = [3, 2, 5, 1, 4, 6, 2, 7] 에서 "3번~6번 합은?" → 5+1+4+6 = 16. 그런데 값이 자꾸 바뀌고, 이런 질문이 수십만 번 들어온다면?

😵 ① 그냥 더하기

  • 물을 때마다 l부터 r까지 하나씩 더함
  • 구간 합 → O(N) (느림)
  • 값 수정 → O(1) (빠름)

🤔 ② 누적합 배열

  • S[i] = A[1]+…+A[i] 를 미리 저장
  • 구간 합 → O(1) (아주 빠름!)
  • 값 하나만 바뀌어도 뒤를 전부 다시 계산 → 수정 O(N) 😢

😎 ③ 펜윅 트리

  • 구간 합 질문 → O(log N)
  • 값 하나 수정 → O(log N)
  • 둘 다 빠른 균형점! 배열 하나면 끝

💡 핵심 한 줄 : 누적합은 "수정"에 약하고, 그냥 더하기는 "질문"에 약해요. 펜윅 트리는 각 숫자를 적당한 크기의 "묶음"으로 미리 더해두어, 구간 합도 수정도 모두 log N 번의 점프로 해결합니다.

핵심 아이디어

비밀은 2진수의 마지막 1

lowbit(i) = i & (-i) : i를 2진수로 봤을 때, 가장 오른쪽에 있는 1 하나가 나타내는 값

예를 들어 12 = 1100₂ 의 가장 오른쪽 1은 세 번째 자리(값 4)예요. 그래서 lowbit(12) = 4.

여기서 핵심 약속: tree[i] 는 A[i] 하나가 아니라, i번에서 왼쪽으로 lowbit(i)칸만큼의 원소를 미리 더해 둔 부분합이에요.

tree[i] = A[i−lowbit(i)+1] + ⋯ + A[i]

그래서 tree[12] 는 lowbit이 4니까 12에서 왼쪽 4칸 → A[9]+A[10]+A[11]+A[12] 를 담아 둡니다. (A[12] 하나가 아니라 4칸의 합!)

i2진수lowbittree[i]가 담는 칸
51011A[5]
61102A[5]+A[6]
810008A[1]+…+A[8]
1211004A[9]+…+A[12]

정리하면 i번 칸이 담당하는 길이 = lowbit(i), 끝나는 위치는 항상 i예요. 비트만 보면 누가 어디까지 담는지 바로 알 수 있죠! 🌤️

숫자를 넣어 lowbit을 직접 확인 →
2진수의 1 가장 오른쪽 1 (lowbit)

🔍 왜 하필 i & (-i) 일까?

컴퓨터는 음수를 2의 보수로 저장해요. -i 는 "i의 모든 비트를 뒤집고 1을 더한 값"입니다. 그러면 신기하게도 i 와 -i 는 가장 오른쪽 1에서만 둘 다 1이 되고, 그보다 왼쪽 자리는 전부 어긋나요. 그래서 i & (-i) 를 하면 그 1 하나만 살아남습니다.

  12 = 0000 1100
−12 = 1111 0100  (비트 뒤집고 +1)
───────────────── AND
   4 = 0000 0100  ← lowbit!

tree[8]은 8칸 전부를, tree[4]는 4칸을, tree[6]은 2칸, tree[5]·tree[7]은 1칸만 담당해요. 길이는 모두 lowbit 값과 똑같죠! 🌤️

진짜 '트리' 모양

배열은 사실 트리였다

왜 이름이 '펜윅 트리'일까? 배열 인덱스를 선으로 이으면 진짜 트리가 나타나요. 규칙은 단 하나: 부모(i) = i + lowbit(i)

위로 올라갈수록(부모로 갈수록) 담당하는 구간이 더 넓어져요. 자식의 구간은 항상 부모 구간 안에 쏙 들어갑니다.

  • update(i) = 이 트리에서 나 → 부모 → 부모… 로 올라가기. (i += lowbit(i))
  • query(i) = i에서 왼쪽으로 건너뛰며 묶음 줍기. (i −= lowbit(i))
  • 그래서 트리 높이가 곧 점프 횟수 = O(log N)

※ 일반 트리처럼 노드 객체·포인터가 따로 있는 게 아니라, 이 부모-자식 관계가 인덱스 계산만으로 표현되는 게 펜윅 트리의 묘미예요. 배열 하나로 트리를 흉내 냅니다.

원리 · 가장 중요한 슬라이드

왜 점프가 통할까?

규칙을 외우기 전에, "왜 이렇게 하면 답이 맞는지"를 숫자로 끝까지 따라가 봐요.

🔽 query : 아래로 (i −= lowbit)

"1번~7번 합"을 구해 봅시다. 7을 2진수로 쪼개면 7 = 4 + 2 + 1 이에요. 펜윅은 이 묶음들을 그대로 주워 담습니다.

  • i=7 → tree[7] = A[7..7] 더함. 다음 7−1=6
  • i=6 → tree[6] = A[5..6] 더함. 다음 6−2=4
  • i=4 → tree[4] = A[1..4] 더함. 다음 4−4=0 → 끝

주운 구간: [1..4] + [5..6] + [7..7] = 빈틈없이 딱 1~7! 🎯
i −= lowbit(i) 는 "방금 더한 묶음의 바로 왼쪽"으로 점프해요. 묶음 길이가 곧 lowbit이라서, 정확히 그만큼만 건너뛰면 겹치지도 빠지지도 않습니다.

🔼 update : 위로 (i += lowbit)

이번엔 A[3] 을 고쳐 봅시다. 그러면 3번을 품고 있는 모든 칸을 같이 고쳐야 해요. 누가 3번을 품고 있을까요?

  • tree[3] = A[3..3] ✅   3+lowbit(3)=3+1=4
  • tree[4] = A[1..4] ✅   4+lowbit(4)=4+4=8
  • tree[8] = A[1..8] ✅   8+lowbit(8)=8+8=16 > N → 끝

고친 칸: 3 → 4 → 8. 모두 3번을 포함하죠!
i += lowbit(i) 는 "지금 칸을 통째로 삼키는 더 큰 묶음"으로 점프해요. 그래서 나를 포함하는 칸들만 정확히 따라 올라갑니다.

✨ 한마디로: query는 합을 "겹치지 않는 묶음들의 합"으로 분해하며 내려가고, update는 "나를 포함하는 묶음들"을 찾아 올라갑니다. 두 점프 모두 한 번에 적어도 2배씩 뛰므로 최대 log₂N 번이면 끝나요.

증명 · 왜 항상 맞을까

비트로 엄밀하게 증명하기

"예시는 맞던데 항상 맞나?" → 2진수 비트로 query·update가 빠짐도 겹침도 없음을 보입니다.

🔽 query 증명 — 빈틈도 겹침도 없다

정의상 tree[i] 는 구간 (i−lowbit(i), i] 의 합이에요. query에서 i 다음 값은 i' = i − lowbit(i).

  • 이번 묶음의 시작점 = i−lowbit(i)+1 = i'+1
  • 다음 묶음의 끝점 = i' (= 새 i)
  • → 두 묶음이 딱 맞붙음: …i', i'+1… (겹치지 않고, 사이에 빈칸도 없음)

i가 0이 될 때까지 반복하면 구간들이 망원경처럼 이어져 (0, i] = [1..i] 전체를 정확히 덮습니다. ∎

🔼 update 증명 — 정확히 그 칸들만

A[i]는 i ∈ (j−lowbit(j), j] 인 칸 tree[j] 에만 들어갑니다. 그런 j 전체가 바로 i, i+lowbit(i), … 임을 보이면 돼요.

  • j = i 는 당연히 포함 (i ≤ i)
  • i를 품은 j 중 i 다음으로 작은 것은? → i의 가장 낮은 0 자리를 1로 바꾼 값 = i + lowbit(i)
  • 그 칸도 i를 품고, 같은 논리로 또 +lowbit → 반복

즉 i를 포함하는 칸은 +lowbit 경로 위에만 있고, 그게 전부예요. 하나도 빠뜨리지 않습니다. ∎

📐 왜 O(log N)? lowbit을 더하거나 빼면 2진수에서 가장 낮은 1이 더 높은 자리로 이동(또는 소멸)해요. 비트는 최대 log₂N 개뿐이라, 점프도 최대 그만큼입니다.

query : 아래로 점프하며 더하기

"1번 ~ i번 합" 은, 겹치지 않는 묶음들을 주워 담으면 끝 → i -= lowbit(i)

1번부터 i번까지 합

합에 더해지는 묶음

두 위치의 합을 빼면 어떤 구간 합도 OK : sum(l..r) = query(r) − query(l−1)

처음 만들기

빈 트리에 처음 값 채우기

이미 A = [3,2,5,1,…] 가 있을 때, tree[] 를 어떻게 만들까? 두 가지 방법이 있어요.

방법 ① 그냥 update 반복

tree[]를 0으로 두고, 모든 i에 대해 update(i, A[i]) 호출.

for i in 1..N:
  update(i, A[i])

간단하지만 update가 한 번에 O(log N) → 전체 O(N log N). 대부분의 경우 이걸로 충분해요. 👍

방법 ② 부모에게 넘겨주기 — O(N)

먼저 tree[i] = A[i] 로 채운 뒤, 각 칸의 합을 부모 칸으로 한 번씩 흘려보냅니다.

for i in 1..N:
  tree[i] += A[i]
  j = i + lowbit(i)
  if j ≤ N: tree[j] += tree[i]

i를 작은 쪽부터 처리하면, tree[i]가 완성된 순간 그 합이 부모 tree[j]로 더해져요. 각 칸을 딱 한 번씩 → O(N)! ⚡

💡 왜 ②가 맞을까? 부모 j = i+lowbit(i) 의 담당 구간은 i의 구간을 완전히 포함해요 (트리 구조 슬라이드 그대로!). 그래서 자식의 부분합을 부모에 더하면, 모든 묶음 합이 자연스럽게 채워집니다.
