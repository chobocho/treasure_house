{{N}}한 PC 에 두 명 — 실제로 필요한 것

❶ 겹치지 않는 키맵 두 벌

이게 전부인 것 같지만, 한 글자라도 겹치면 한 사람의 입력이 두 판에 동시에 들어간다. 겪어 보기 전에는 안 믿긴다.

❷ 좌석과 슬롯의 구분

서버는 좌석 번호(0~7)를 안다. 이 PC 는 슬롯(1P/2P)을 안다. 둘을 잇는 표가 필요하다.

❸ 게임패드 두 개

navigator.getGamepads() 의 0번·1번을 각각 슬롯에 붙인다. 브라우저는 이벤트를 주지 않으므로 매 프레임 훑어야 한다.

❹ 포커스 관리

이 문서 안에서 돌 때 ←→ 가 슬라이드를 넘겨 버리면 안 된다. 데모 영역이 키를 붙잡아 멈춰야 한다.

2P 키를 왼손 영역에 모은 이유: 한 키보드에 두 사람이 앉으면 물리적으로 자리를 나눠야 한다. 2P 가 왼쪽, 1P 가 오른쪽(방향키·Space)이면 팔이 안 겹친다.

{{N}}한 리스너가 두 좌석을 나눠 맡는다

ev.repeat 를 거르는 이유키를 누르고 있으면 OS 가 자동 반복 keydown 을 계속 보낸다. 그걸 그대로 ng_press 로 넘기면 OS 의 반복 속도가 게임의 DAS/ARR 을 덮어쓴다. 반복은 tetris.cpp 안의 DAS(170ms)/ARR(40ms)이 담당해야 한다.

{{N}}게임패드 — 매 프레임 훑는다

이전 프레임 상태를 들고 있다가 엣지(눌림→안눌림, 안눌림→눌림)를 만들어 ng_press/ng_release 로 바꾼다. 키보드가 OS 에서 공짜로 받는 것을 패드는 직접 만들어야 한다.

임계값 0.5아날로그 스틱은 손을 떼도 0에 정확히 안 돌아온다(드리프트). 0.2 쯤으로 낮추면 가만히 있는데 조각이 계속 옆으로 간다. 0.5 는 확실히 기울여야 반응하는 값이다.

{{N}}직접 해 보기 — 한 PC 두 명

클릭(탭)해서 키를 넘긴 뒤, 1P 는 방향키·Space·C, 2P 는 A·D·S·W·Q·F·E. 두 판은 서로 가비지를 주고받는다 — 좌석 2석짜리 방이고, 서버는 이 페이지 안의 room.mjs 다. 한 판이 끝나면 잠시 뒤 다시 시작한다.
