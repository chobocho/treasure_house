asyncio.Lock 이 필요한 이유

싱글 스레드여도 await writer.drain() 에서 양보한다. 그 틈에 다른 코루틴이 프레임을 끼워 넣으면 연결이 통째로 망가진다. Go 의 뮤텍스와 같은 이유다.

ensure_ascii=False

기본값 True 면 "보라" 가 "\\ubcf4\\ub77c" 로 나간다. 12바이트가 될 것이 24바이트가 되고, 사람이 로그를 못 읽는다.

{{N}}핸드셰이크 — HTTP 를 손으로 읽는다

Go 와 갈리는 지점Go 는 net/http 가 요청을 다 파싱해 준 뒤 Hijack() 으로 소켓을 뺏는다. 파이썬에는 그런 것이 없으므로 readuntil(b'\r\n\r\n') 로 헤더를 직접 읽는다. 대신 업그레이드가 아닌 요청도 여기서 처리할 수 있어 정적 파일 서빙이 자연스럽게 붙는다.

{{N}}101 을 손으로 쓴다

업그레이드가 아니면 http(path) 로 넘기고, 그것도 None 이면 404 다. 이 한 갈래 덕분에 같은 포트에서 정적 파일과 웹소켓이 함께 서빙된다 — 브라우저가 file:// 가 아니라 http:// 로 페이지를 받아야 웹소켓을 열 수 있으므로 이게 필요하다.

{{N}}클라이언트 쪽

latin1 로 인코딩하는 게 맞다. HTTP 헤더는 정의상 바이트 단위 프로토콜이고, latin1 은 0~255 를 그대로 바이트로 옮긴다.
