{{N}}Makefile — 한 파일이 전부를 묶는다

tetris_net.wasm 의 의존성에 ../tetris_ai/ai.cpp 와 tetris.cpp 가 들어 있다. #include 로 삼킨 파일이라 그것들이 바뀌면 다시 빌드해야 한다 — make 는 그걸 스스로 알지 못한다.

{{N}}테스트와 실행

-node bot_client.mjs 의 앞 하이픈실패해도 계속하라는 뜻이다. 대전이 시간 안에 안 끝나 0이 아닌 값을 돌려줘도 서버를 죽이는 다음 줄은 실행돼야 한다. 안 그러면 포트를 물고 있는 프로세스가 남는다.

{{N}}브라우저 묶음과 덱

  sed 's/^export //' room.mjs > web/room.js

  이 한 줄이 "검증한 파일과 도는 파일이 갈리지 않는다"를 보장한다.
  덱 빌더도 정확히 같은 변환을 한다(build_deck.py).
  room.js 를 손으로 관리하면 언젠가 반드시 어긋난다.

{{N}}이 문서가 거짓말을 못 하는 장치

덱의 코드 블록은 손으로 옮겨 적은 것이 아니다. 빌드 스크립트가 실제 파일에서 줄 번호로 잘라 넣는다.

  슬라이드 조각에 이렇게 쓴다:
      <!--CODE file=server_go/room.go lines=318-361 cap="pickTarget()"-->

  build_deck.py 가 하는 일:
      ① 그 파일의 318~361 줄을 읽어 구문 강조해 넣는다
      ② 그 줄들에 "실렸음" 표시를 한다
      ③ 전부 조립한 뒤, 파일마다 모든 줄이 정확히 한 번씩 실렸는지 센다
      ④ 빠진 줄·중복된 줄·45줄 넘는 코드 블록이 있으면 경고한다

  이번 빌드의 결과:
      ── 소스 커버리지 (덱에 실린 줄 / 전체 줄)
        …
        ── 합계(로그 제외)     5831/5831

  소스를 고치고 줄 범위를 안 고치면 즉시 어긋난 게 드러난다.
  "문서가 코드보다 오래된" 상태가 원천적으로 불가능하다.
같은 장치를 1·2편에도 썼다그래서 3편이 tetris.cpp·ai.cpp 를 한 줄도 고칠 수 없었다. 고치는 순간 그 두 덱의 줄 범위가 전부 어긋나고 빌드가 경고를 쏟아낸다 — 제약이 설계를 이끈 사례다.

파이썬 판의 진짜 장점서버에 이미 파이썬이 있으면 빌드 단계가 없다. 규칙을 고치고 재시작하면 끝이다. 규칙을 자주 실험하는 동안에는 이쪽이 압도적으로 빠르다.

{{N}}배포 ③ nginx 앞단과 TLS

server {
    listen 443 ssl http2;
    server_name tetris.example.com;
    ssl_certificate     /etc/letsencrypt/live/tetris.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/tetris.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;

        # --- 이 세 줄이 없으면 웹소켓이 절대 안 된다 ---
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host       $host;

        # 기본 60초. 웹소켓은 오래 조용할 수 있으므로 늘린다.
        proxy_read_timeout  1h;
        proxy_send_timeout  1h;
    }
}

https:// 로 서비스하면 웹소켓도 wss:// 여야 한다 — 브라우저가 혼합 콘텐츠를 막는다. app.js 가 location.protocol 을 보고 자동으로 맞춘다.

이 Accept 값은 RFC 6455 의 예제 그대로다 — 서버가 규격을 지키고 있다는 한 줄짜리 증명이다.

{{N}}빈 방과 자원

방은 스스로 사라진다

마지막 PC 가 나가면 방 객체·채널·고루틴(또는 태스크)이 전부 없어진다. 청소 타이머가 없다 — 수명이 곧 참조다.

느린 클라이언트는 끊긴다

보낼 큐 64개가 차면 즉시 종료. 한 PC 때문에 방 전체가 멈추지 않는다.

메모리 상한

프레임 하나가 64KB 를 넘으면 연결을 끊는다(MaxPayload). 이 게임의 최대 메시지는 1KB 도 안 된다.

아직 없는 것

연결 수 제한, IP 당 방 생성 제한, 유휴 방 타임아웃. 공개 서비스로 낼 거라면 필요하다 — 27부에 목록이 있다.
