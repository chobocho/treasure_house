{{N}}8인 온라인 대전과 두 개의 서버

C++ WASM 테트리스 3편 — PC 1~8대, 한 PC 에 2명까지, 빈 자리는 유전 알고리즘 AI 가 채운다. 서버는 Go 와 파이썬으로 하나씩.

가상 PC 4대가 2석씩 쥔 8인 대전이다. 좌석 8개는 이 페이지 안의 wasm 인스턴스 8개이고, 가운데의 서버는 Go·파이썬과 같은 골든 벡터를 통과한 세 번째 구현이다.

{{N}}무엇을 만드는가

1 · 좌석이라는 추상

서버는 사람인지 AI인지, 브라우저인지 Node 인지 구분하지 않는다. 좌석 8개가 있고 각 좌석에 조종자가 하나 붙어 있을 뿐이다.

2 · PC 1대 = 좌석 2석

한 컴퓨터에 두 사람이 앉는다. 키맵 두 벌, 게임패드 두 개. 그래서 PC 4대로 8인이 된다.

3 · 서버 두 개

Go 와 파이썬. 둘 다 표준 라이브러리만 쓴다 — WebSocket(RFC 6455)부터 직접 구현한다.

4 · 골든 벡터

Go·파이썬·JS 세 구현이 같은 44스텝 표를 한 글자도 다르지 않게 재현한다. 이게 "서버가 두 개"라는 말의 증명이다.

모든 코드는 이 기계에서 실제로 빌드·실행·테스트했다. 이 덱에는 전체 소스 {{LINES:server_go/room.go}}줄짜리 room.go 를 포함해 5,400여 줄이 한 줄도 빠짐없이 실려 있다 — 슬라이드의 코드 블록은 실제 파일에서 잘라 온 것이고, 빌드 스크립트가 커버리지를 검사한다.

{{N}}완성물을 숫자로

17,360 바이트

코어 + AI + 멀티플레이 층 전체 wasm. 런타임·표준 라이브러리 0개, 임포트 0개.

0개

Go 서버와 파이썬 서버의 외부 의존성. go.mod 에 require 가 없고 pip install 이 필요 없다.

44스텝 × 3언어

골든 벡터. Go·파이썬·JS 가 같은 입력에 같은 출력을 낸다. 하나라도 어긋나면 빌드가 멈춘다.

13바이트

빈 판 하나를 남에게 보내는 데 드는 크기(런렝스). 8석 × 초당 10회 = 약 7 KB/s.

1.2 KB/s

실측. 8인 대전 중 PC 1대가 올려보내는 평균 대역폭. 내려받는 건 3.7 KB/s.

27.4초

실측. 진짜 웹소켓으로 붙은 8인 AI 대전 한 판이 끝나는 데 걸린 시간(Go 서버, 무작위 타겟팅).

{{N}}이 문서를 읽는 법

코드는 진짜다

슬라이드의 코드 블록은 tetris_net/ 의 실제 파일에서 줄 번호로 잘라 온 것이다. 손으로 옮겨 적은 코드가 한 줄도 없다.

빠진 줄이 없다

덱 빌드 스크립트가 파일마다 모든 줄이 정확히 한 번 실렸는지 센다. 빠지거나 겹치면 경고가 뜬다.

데모도 진짜다

이 문서 안의 8인 대전은 그림이 아니라 같은 wasm + 같은 room 엔진이 도는 것이다. 전송 계층만 루프백으로 바뀐다.

출력도 진짜다

실제 출력 딱지가 붙은 블록은 이 기계에서 명령을 돌려 나온 그대로다. 예쁘게 다듬지 않았다.

조작←→ 슬라이드 이동 · ↑↓ 슬라이드 안 스크롤 · T 목차 · 게임패드 지원. 게임 데모는 클릭(탭)하면 키 입력을 가져간다.

{{N}}지금 바로 돌려 보기

저장소를 받았다면 세 줄이면 8인 대전이 뜬다.

# 1) wasm 빌드 + 클라이언트 묶음
cd tetris_net && make web

# 2) 서버 — 둘 중 아무거나. 같은 프로토콜이라 클라이언트는 차이를 모른다
make run-go     # Go   : :8787
make run-py     # 파이썬: :8787

# 3) 각 PC 에서 브라우저로 접속 → 방 만들기 / 코드로 참가
http://<서버IP>:8787/

사람 없이 확인하고 싶으면 헤드리스 봇이 PC 4대를 흉내 낸다.

make match      # Go·파이썬 양쪽에 8인 대전을 붙여 실측까지 찍는다
make test       # wasm · room 3구현 · 브라우저 코드 전 계층

{{N}}차례

1~4부 · 바닥 깔기

물려받은 코어, 권위 모델 설계, C++ 멀티플레이 층, 화면을 13바이트로 접는 법.

5~6부 · 규격

프로토콜 v3 전문과, 세 구현을 묶는 골든 벡터.

7~11부 · Go 서버

RFC 6455 직접 구현, room 엔진, 방마다 고루틴 하나, 테스트 전부.

12~15부 · 파이썬 서버

같은 규격을 asyncio 로. 그리고 두 서버를 맞대어 본다.

16~21부 · 클라이언트

전송 갈아 끼우기, 한 판의 루프, 한 PC 두 명, AI 좌석, 8석 화면, 로비.

22~26부 · 증명과 마무리

헤드리스 봇 실측, 테스트 전부, 빌드·배포, 라이브 대전, 다음 걸음.
