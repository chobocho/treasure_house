안 되는 것

끊긴 자리로 복귀(그 좌석은 죽는다) · 리플레이 저장 · 관전자 전용 모드 UI · 터치 조작 · 부정행위 검증 · 방장 넘기기 · 유휴 방 정리

"안 되는 것"들은 구조적으로 막힌 게 아니라 아직 안 쓴 것이다. 아래에 각각 어디를 건드리면 되는지 적어 둔다.

{{N}}다음 걸음 ① 부정행위 검증

지금은 클라이언트가 "나 4줄 보냈다"고 하면 서버가 믿는다. 이 구조에서 검증까지 가는 길은 생각보다 짧다.

  ① 입력 로그를 같이 보낸다
     atk 에 "이번 락까지의 입력 기록(액션 + 시각)"을 붙인다.
     한 조각당 수십 바이트다.

  ② 서버가 같은 wasm 을 돌린다
     Go 라면 wazero, 파이썬이라면 wasmtime-py 로 tetris_net.wasm 을 그대로 실행.
     같은 시드 + 같은 입력 + 같은 가비지 → 같은 결과가 나와야 한다.

  ③ 안 맞으면 그 좌석을 무효 처리한다.

  비용:  좌석당 wasm 인스턴스 하나. 8인 방 하나에 8개.
         ai_plan 이 없으므로 CPU 는 사실상 무시할 만하다.
  얻는 것: 이 게임이 결정론적이라서 검증이 재실행 한 번으로 끝난다.
왜 지금 안 했나친구끼리 하는 8인 대전에 필요 없다. 그리고 이걸 넣는 순간 서버가 게임 규칙을 알아야 하므로, 2부에서 세운 "서버는 게임을 돌리지 않는다"가 깨진다 — 공개 서비스로 낼 때 치를 값이다.

{{N}}다음 걸음 ② 복귀와 리플레이

복귀(reconnect)

hello 에 재접속 토큰을 실어 보내고, room 이 peers 대신 토큰 → 좌석 표를 들면 된다. onBye 를 "즉시 죽이기"에서 "30초 유예 뒤 죽이기"로 바꾸고, 그동안의 grb 를 좌석 대기열에 쌓아 둔다.

리플레이

이미 거의 다 있다. 라운드 시드 + 모든 atk/grb/ko 를 시각과 함께 저장하면 재생이 된다. 화면 스냅샷(st)은 저장할 필요가 없다 — 다시 계산하면 나온다.

관전자 모드

좌석을 안 잡은 PC 도 이미 st 를 다 받는다. arena.js 에서 "내 좌석이 없으면 전체를 격자로" 배치하는 분기 하나만 추가하면 된다.

터치 조작

1편 덱에 화면 버튼 구현이 있다. seats.js 에 TouchPad 클래스를 하나 더 만들어 슬롯에 붙이면 끝난다 — 조종자 인터페이스가 이미 추상화돼 있다.

{{N}}다음 걸음 ③ 규모를 키우면

바꾸고 싶은 것어디를주의
좌석 99석 (배틀로열)cfg.max 상한, arena.js 배치st 중계가 O(n²) 가 된다. 관심 좌석만 구독하는 규칙이 필요하다

방 수천 개서버는 그대로Go 는 고루틴 수천 개가 문제없다. 파이썬은 프로세스를 나눠야 한다
서버 여러 대hub 층에 라우팅 추가room 은 순수 함수라 어느 서버로 옮겨도 된다 — 상태만 넘기면 된다
매치메이킹hub 층에 대기열room 을 건드릴 필요가 없다. 방을 만들어 사람을 넣는 것뿐

{{N}}이 프로젝트에서 얻은 것 다섯

  1. 층을 순수 함수로 떼어 내면 언어를 넘어 검증할 수 있다. room 에서 시계와 난수를 인자로 밀어낸 것 하나가 44스텝 골든 벡터를 가능하게 했다.
  2. 규격의 예제를 테스트로 박아 두라. RFC 6455 §1.3 의 한 줄이 GUID 오타를 잡았다. 그게 없었다면 "브라우저가 그냥 연결을 끊는다"를 몇 시간 들여다봤을 것이다.
  3. 같은 규격을 두 번 구현하면 규격의 구멍이 드러난다. 동률 처리, 봉투 타입 충돌, 무한정수 — 한 번만 썼으면 몰랐을 것들이다.
  4. 단위를 잘 고르면 요구사항이 특별 케이스가 아니게 된다. "좌석"을 단위로 잡은 덕에 1인용·2인 로컬·AI 혼합·8인 온라인이 전부 같은 코드 경로다.
  5. 사람 없이 전체를 돌릴 수단을 먼저 만들라. 헤드리스 봇이 없었다면 8인 대전을 한 번 시험하는 데 브라우저 8개와 손 16개가 필요했다.
