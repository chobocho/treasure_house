$ make web          # room.mjs 의 export 를 떼고, js·wasm·weights 를 web/ 에 모은다
$ make run-go       # 또는 make run-py

각 PC 에서:  http://<서버IP>:8787/

web/
  index.html            로비 + 대전 화면 (79줄)
  room.js               ← room.mjs 에서 `export ` 만 뗀 것
  netcore_browser.js    net_client.js    seats.js    arena.js    match.js

  tetris_net.wasm       17,360 바이트
  weights.json          2편의 GA 산출물
file:// 로는 안 된다브라우저는 file:// 페이지에서 웹소켓을 열지 못한다(그리고 fetch 도 막힌다). 그래서 서버가 정적 파일도 같이 내주게 만들었다 — 포트 하나로 끝난다.

{{N}}index.html — 로비

100dvh 를 쓴다. 모바일 브라우저의 주소창이 접히고 펴질 때 100vh 는 화면 밖으로 넘치는 값이 된다.

{{N}}스크립트 순서

일반 스크립트 7개를 순서대로 읽는다. 모듈이 아니라서 번들러가 필요 없고, 각 파일의 최상위 const/class 가 전역 렉시컬 스코프에 들어가 서로 보인다. 이 문서(덱)가 같은 파일들을 <script> 로 인라인하는 것과 정확히 같은 방식이다.

{{N}}app.js — 부팅

서버 주소 기본값을 location.host 에서 만든다. 페이지를 받아 온 그 서버가 웹소켓 서버이기도 하므로, 대부분의 경우 사용자가 주소를 만질 일이 없다.

{{N}}접속과 배선

ERR_KO 가 여기서 쓰인다서버는 {"t":"err","code":"full"} 만 보낸다. "이 PC 는 이미 2석을 쥐고 있습니다"라는 문장은 클라이언트 안에 있다 — 서버를 건드리지 않고 말투를 바꾸거나 언어를 추가할 수 있다.

{{N}}좌석표 — 클릭으로 앉고 선다

slot++ 가 한 PC 의 사람 좌석에 1P·2P 를 순서대로 배정한다. AI 좌석은 슬롯을 먹지 않는다 — 그래서 "사람 1명 + AI 1명"인 PC 에서 그 사람은 1P 키를 쓴다.

{{N}}1인용 — 서버 없이

  좌석 1석 방 + LoopbackHub → 서버가 필요 없다.
  그런데 코드 경로는 온라인과 완전히 같다:
      hello → create → seat → ready → start → (게임) → ko → end

  1인용 전용 코드가 0줄이다. 이게 "좌석"을 단위로 잡은 대가로 얻은 것이다.
