{{N}}첫 번째 질문 — 누가 규칙을 돌리나

온라인 게임의 설계는 이 한 줄에서 갈린다. 세 갈래가 있고, 셋 다 실제로 쓰인다.

서버 권위클라이언트 권위결정론 락스텝
규칙이 도는 곳서버각 클라이언트모든 곳(동일하게)
내 조작 반응왕복 지연만큼 늦거나, 예측 후 되감기0ms입력 지연만큼 늦음
부정행위막기 쉽다막기 어렵다어긋나면 즉시 들킨다
서버 부하인원수에 비례거의 없음거의 없음(중계만)
대표 사례FPS · MMOJstris · Tetris 99 계열RTS(스타크래프트·에이지)

이 프로젝트는 클라이언트 권위를 고른다. 테트리스는 프레임 단위 조작 감각이 전부인 게임이라 0ms 가 협상 불가능하고, 판끼리 주고받는 정보가 "줄 수 하나"뿐이라 클라이언트를 믿어도 게임이 성립한다.

{{N}}그래도 서버가 필요한 이유

"클라이언트 권위"라고 해서 서버가 우체국인 것은 아니다. 서버만 할 수 있는 판단이 있다.

타겟 선택

8인에서 내 공격을 누가 맞을지는 전역 정보다. 나는 남들의 상태를 다 알지 못하고, 알더라도 내가 고르면 담합이 된다.

구멍 위치

가비지 줄의 구멍은 모든 관전자가 같은 값을 봐야 한다. 서버의 난수 하나가 그걸 보장한다.

등수

"몇 등"은 죽는 순간의 전역 생존자 수다. 각자 세면 반드시 어긋난다.

라운드 시드

모두가 같은 조각 순서를 받아야 공평하다. 시드를 뿌리는 건 서버 몫이다.

서버가 하지 않는 것회전·월킥·락다운·점수·상쇄·레벨. 이 전부가 각 PC 의 wasm 안에 있다. 서버는 게임을 한 프레임도 돌리지 않는다.

{{N}}신뢰 경계를 그림으로

      MY PC                            SERVER                     OTHER PC
  +-----------------+                                     +-----------------+
  |  input -> wasm  |                                     |   their wasm    |
  |        |        |    atk {i,n}                        |        |        |
  |  attack N lines |-------------->  pick target         |        v        |
  |                 |                 pick hole           |                 |
  |  garbage queue  |<----  grb {i,n,from,hole}  ---------|                 |
  |        |        |                                     |                 |
  |        v        |    st {b,s}                         |    spectate     |
  |  my board rises |---->  relay as-is  ---------------->|        ^        |
  +-----------------+                                     +-----------------+

  MY PC 는 믿는다 · SERVER 가 판단한다 · OTHER PC 는 안 믿어도 된다

  경계를 넘는 것은 딱 셋:  공격 줄 수 · 화면 스냅샷 · 죽었다는 통보
  남의 PC 가 거짓말을 하면?  "저 사람이 강해 보인다"까지가 끝이다.
  내 판이 뒤집히려면 서버가 나에게 grb 를 보내야 하고, 그건 서버가 정한다.

부정행위를 완전히 막으려면 서버가 규칙을 다시 돌려야 한다(락스텝 검증). 26부에서 그 길을 다룬다 — 이 구조에서 그리 멀지 않다.

{{N}}좌석이라는 추상

설계에서 제일 값을 한 결정. "플레이어"가 아니라 "좌석"을 단위로 잡는다.

  peer (연결 = PC 1대)  --1..2-->  seat (좌석 0..7)  --1-->  controller
                                                              |
                                                              +-- 키보드 1P
                                                              +-- 키보드 2P
                                                              +-- 게임패드
                                                              +-- GA AI

  서버가 아는 것 :  좌석 번호 · 주인 pid · 이름 · kind(표시용) · 살았나 · 등수
  서버가 모르는 것:  그 좌석을 지금 사람이 누르고 있는지 AI 가 굴리고 있는지

얻는 것 ①

"한 PC 에 2명"이 특별 케이스가 아니게 된다. 그냥 그 pid 가 좌석을 두 개 쥔 것이다.

얻는 것 ②

AI 좌석이 서버 코드에 한 줄도 없다. 누군가의 PC 가 그 좌석을 대신 굴려 줄 뿐이다.

얻는 것 ③

1인용이 좌석 1석짜리 방이 된다. 코드 경로가 하나다.

대가

"이 좌석의 주인이 맞나"를 모든 메시지에서 확인해야 한다(err own).

{{N}}AI 좌석은 누구의 CPU 가 굴리나

방법장점단점선택
서버가 굴린다공평·일관서버에 wasm 런타임이 필요하고(Go·파이썬 둘 다에!), 인원수만큼 CPU 를 먹는다✕
방장 PC 가 굴린다서버가 단순해진다방장 PC 가 8석을 다 지면 부담이 몰린다△
좌석을 잡은 PC 가 굴린다부담이 자연스럽게 분산된다. 서버 코드 0줄그 PC 가 끊기면 그 AI 도 같이 죽는다(그게 맞다)◎

wasm 인스턴스 하나는 코드 17KB(공유) + 상태 몇 KB 다. 한 수 탐색은 후보 ~80개 × 240바이트 보드 복사라 0.05ms 쯤 걸린다. PC 한 대가 좌석 2개를 굴려도 60fps 프레임의 0.6% 다.

모듈과 인스턴스를 나누는 이유WebAssembly.compile 은 한 번, instantiate 는 좌석 수만큼. 코드는 한 벌만 메모리에 있고 상태만 늘어난다. 8석 대전이 성립하는 실질적인 이유다.

{{N}}타겟팅 4종

공격이 누구에게 가는가는 8인 대전의 성격을 통째로 바꾼다. 네 가지를 다 넣고 방마다 고르게 했다.

모드규칙난수판이 어떻게 되나
random 무작위살아 있는 상대 중 균등하게 하나1회가장 평범하다. 운이 크게 작용한다
even 분산지금까지 가장 덜 맞은 좌석. 동률이면 낮은 번호0회아무도 일찍 죽지 않는다. 판이 길어진다
attackers 반격최근 8초 안에 나를 때린 좌석 중 가장 최근. 없으면 무작위0 또는 1회둘씩 물고 늘어지는 싸움이 된다
ko 막타가장 높이 쌓인(=죽기 직전인) 좌석. 동률이면 낮은 번호0회잔인하다. 몰매가 몰린다 — 판이 빨리 끝난다

실측: 같은 8인 구성으로 random 은 27.4초, ko 는 52.8초가 걸렸다(23부). 직관과 반대인데, ko 는 높이가 낮은 좌석을 건드리지 않아서 강한 AI 가 오래 버틴다.

{{N}}가비지가 도착하는 시점

공격이 도착하자마자 줄이 솟으면 대전이 성립하지 않는다. 맞받아칠 틈이 있어야 한다.

  t=0     서버가 grb {n:4, hole:7} 을 배달 → 대기열 [4줄, 나이 0ms]
  t=250   조각을 놓아 2줄 지웠다 → 공격 1줄이 대기열을 깎는다 → [3줄]
  t=600   또 놓았는데 줄을 못 지웠다 → 솟아오른다 (cap 8줄까지)
  ---------------------------------------------------------------------
  규칙 두 줄:
    ① 줄을 못 지운 락에서 솟는다 — 상쇄할 기회를 준다
    ② 단, 대기열이 delay(900ms) 이상 묵었으면 지운 락에서도 솟는다
       — 끝없이 지우며 버티는 걸 막는다
어디서 지키나서버는 delay 를 설정값으로 알려 주기만 하고 세지 않는다. 시간을 재는 건 판을 돌리는 쪽, 즉 클라이언트다. 서버가 타이머를 들면 그 순간 서버가 게임을 돌리게 된다.

{{N}}등수는 언제 정해지나

규칙 한 줄: 죽는 순간 살아 있던 좌석 수가 그대로 등수다.

  좌석 8석, 전원 생존             alive = 8
  좌석 0 사망 → place 8           alive = 7
  좌석 7 사망 → place 7           alive = 6
  …
  좌석 5 사망 → place 2           alive = 1  ← 여기서 라운드가 끝난다
                                  남은 좌석 2 에게 place 1 을 주고 end 를 뿌린다

  1인용(좌석 1석)도 같은 길을 탄다:
  좌석 0 사망 → place 1 (그 순간 alive 는 1이었다) → alive 0 → 즉시 end

우승자는 ko 를 받지 않는다

죽지 않았으니 당연하다. 우승자의 등수는 end.order[0] 에만 있다 — 클라이언트가 이걸 잊으면 우승자만 "0등"으로 표시된다(실제로 겪었다, 22부).

막타 귀속

by = 최근 8초 안에 마지막으로 나를 때린 좌석. 없으면 -1(자멸).

{{N}}설계 요약 — 여덟 줄

  1. 규칙은 각 PC 의 wasm 안에서 돈다. 서버는 게임을 돌리지 않는다.
  2. 서버가 하는 판단은 타겟 · 구멍 · 등수 · 라운드 시드 넷뿐이다.
  3. 단위는 플레이어가 아니라 좌석이다. 한 연결이 최대 2석.
  4. AI 좌석은 그 좌석을 잡은 PC가 굴린다. 서버는 사람인지 AI인지 모른다.
  5. 가비지는 덩어리 목록이다 — 줄 수 · 보낸 좌석 · 구멍 · 나이.
  6. 구멍 위치는 서버가 뽑아 내려 준다. 관전 화면이 갈리지 않게.
  7. 화면은 런렝스 + base64 로 접어 초당 10번 보낸다.
  8. 규칙 층(room)은 순수 상태 기계다. 그래야 3언어를 같은 표로 검증한다.

이 여덟 줄이 나머지 24부의 전부다. 3부부터는 이걸 코드로 옮긴다.
