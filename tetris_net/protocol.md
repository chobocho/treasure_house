# 테트리스 온라인 프로토콜 v3

WebSocket **텍스트 프레임 1개 = JSON 객체 1개**. 모든 메시지는 `t` 필드로 종류를 구분한다.
바이너리 프레임은 쓰지 않는다 — 보드 스냅샷은 RLE 후 base64 로 접어 `b` 필드에 넣는다.

## 0. 용어

| 용어 | 뜻 |
|---|---|
| **peer** | WebSocket 연결 1개 = PC 1대. `pid` 로 식별한다 (1부터). |
| **seat** | 좌석 0‥7. 한 판에 최대 8석. 한 peer 는 **최대 2석**까지 가질 수 있다. |
| **hub** | 방 코드·라우팅을 맡는 층. `hello`/`create`/`join` 만 처리한다. |
| **room** | 게임 규칙을 맡는 순수 상태 기계. 시계(now)와 난수 시드를 주입받는다. |

hub 와 room 을 나눈 이유: room 을 **순수 함수**로 유지해야 Go·파이썬·JS 세 구현을
같은 골든 벡터로 검증할 수 있다. room 은 소켓도 시간도 직접 만지지 않는다.

## 1. room 엔진 계약

```
room.handle(pid, msg, now) -> [ {to, m}, ... ]
```

* `to == 0` 이면 방 전체 브로드캐스트, 그 외에는 해당 `pid` 에게만.
* `now` 는 밀리초 정수. 엔진은 절대 스스로 시계를 읽지 않는다.
* 난수는 방 생성 시 받은 `seed` 로 시작하는 **xorshift32** 하나뿐이다.

```
x ^= x << 13;  x ^= x >> 17;  x ^= x << 5;   // 전부 32비트 무부호
```

난수를 뽑는 지점은 **정확히 세 곳**이고 순서가 고정돼 있다.

1. 라운드 시드 (`start` 1회) — 이 값이 모든 클라이언트의 7-bag 시드가 된다
2. 타겟 선택 (`random` 으로 떨어질 때만 1회)
3. 가비지 구멍 위치 (`grb` 1개당 정확히 1회)

이 순서가 어긋나면 세 구현의 출력이 갈린다. 골든 벡터가 잡아내는 첫 번째 버그가 이것이다.

## 2. 방 설정 `cfg`

| 키 | 기본 | 뜻 |
|---|---|---|
| `max` | 8 | 좌석 수 (1‥8) |
| `perPeer` | 2 | PC 1대가 가질 수 있는 좌석 수 |
| `target` | `"random"` | 타겟팅 규칙 — `random` / `even` / `attackers` / `ko` |
| `delay` | 900 | 가비지가 대기열에서 필드로 솟기까지의 최대 유예(ms). **클라이언트가** 지킨다 |
| `cap` | 8 | 한 번의 락에서 올라올 수 있는 최대 줄 수 |
| `hitTTL` | 8000 | `attackers`/`ko` 판정에서 "최근 공격"으로 치는 시간(ms) |

## 3. 클라이언트 → 서버

| `t` | 필드 | 층 | 뜻 |
|---|---|---|---|
| `hello` | `v`, `name` | hub | 첫 메시지. `v != 3` 이면 `err ver` |
| `create` | `cfg` | hub | 방 생성 → 방장이 된다 |
| `join` | `room` | hub | 방 코드로 참가 |
| `seat` | `i`, `kind`, `name`, `lv` | room | 좌석 요청. `i = -1` 이면 빈 자리 자동 |
| `unseat` | `i` | room | 좌석 반납 |
| `ready` | `v` | room | 내가 가진 좌석 전부의 준비 상태 |
| `start` | — | room | 방장만. 사람 좌석이 전부 준비돼야 한다 |
| `atk` | `i`, `n` | room | 좌석 `i` 가 `n` 줄 공격을 보냈다 |
| `st` | `i`, `b`, `s` | room | 좌석 `i` 의 화면 상태 (초당 10회 권장) |
| `ko` | `i` | room | 좌석 `i` 가 죽었다 |
| `ping` | `c` | hub | 왕복 지연 측정 |

`kind` 는 `"human"` 또는 `"ai"`. 서버는 **둘을 구분하지 않는다** — AI 좌석도 사람 좌석과
똑같이 어느 PC 가 대신 굴려 주는 좌석일 뿐이다. `lv` 는 AI 난이도 프리셋 이름이며
서버는 로비 표시용으로 그대로 중계만 한다.

## 4. 서버 → 클라이언트

| `t` | 필드 | 뜻 |
|---|---|---|
| `hi` | `pid`, `v`, `code`, `cfg` | 접속·입장 승인 |
| `room` | `host`, `seats` | 로비 상태 (좌석이 바뀔 때마다). 방 코드와 `cfg` 는 hub 가 `hi` 에 실어 보낸다 |
| `err` | `code` | 거절. 사람이 읽을 문구는 클라이언트가 코드로 찾는다 |
| `start` | `seed`, `seats` | 라운드 시작. `seed` 로 모두가 같은 7-bag 을 쓴다 |
| `grb` | `i`, `n`, `from`, `hole` | 좌석 `i` 에게 `n` 줄, 보낸 좌석 `from`, 구멍 x = `hole` |
| `st` | `i`, `b`, `s` | 다른 좌석 화면 중계 |
| `ko` | `i`, `place`, `by` | 좌석 `i` 탈락. `place` 등수, `by` 막타 좌석(-1 = 자멸) |
| `end` | `order` | 라운드 종료. `order[0]` 이 1등 좌석 |
| `pong` | `c` | |

좌석 객체: `{"i":0,"pid":1,"name":"보라","kind":"human","lv":"","ready":false,"alive":true}`

## 5. 상태 배열 `s` — 고정 12칸

| 칸 | 뜻 | 칸 | 뜻 |
|---|---|---|---|
| 0 | state (0=진행 1=끝 2=일시정지) | 6 | 현재 조각 (0‥6) |
| 1 | score | 7 | 회전 (0‥3) |
| 2 | lines | 8 | x |
| 3 | pieces | 9 | y (보이는 필드 기준) |
| 4 | **height** — 가장 높은 열의 높이 | 10 | 고스트 y |
| 5 | pending — 대기 중인 가비지 줄 | 11 | hold (-1 = 없음) |

서버가 **읽는 칸은 `s[0]` 과 `s[4]` 뿐이다.** 나머지는 관전 화면을 그리라고 중계만 한다.
`ko`/`even` 타겟팅이 `s[4]` 를 쓴다.

## 6. 보드 스냅샷 `b`

보이는 필드 20×10 = 200칸을 위에서 아래로, 왼쪽에서 오른쪽으로 훑어 **런렝스**로 접는다.

```
바이트 = (런길이 - 1) << 4 | 칸값        런길이 1‥16, 칸값 0‥8
```

칸값 0 = 빈칸, 1‥7 = 조각 색, 8 = 가비지. 그 바이트열을 base64 로 만든 것이 `b` 다.
빈 판은 200칸 = 16×12 + 8 → 13바이트 → base64 20자. 꽉 찬 판도 100바이트를 넘지 않는다.
좌석 8석 × 초당 10회 × 약 90바이트 ≒ **7 KB/s** — 이게 이 게임의 전체 대역폭이다.

## 7. 타겟팅 4종

`atk {i, n}` 이 오면 살아 있는 **상대 좌석** 중에서 하나를 고른다. 후보가 없으면 아무 일도 없다.

| 모드 | 규칙 | 난수 |
|---|---|---|
| `random` | 후보 중 하나를 균등하게 | 1회 |
| `even` | 지금까지 받은 가비지(`recv`)가 **가장 적은** 좌석. 동률이면 낮은 번호 | 0회 |
| `attackers` | `hitTTL` 안에 나를 때린 좌석 중 **가장 최근**. 없으면 `random` 으로 | 없으면 1회 |
| `ko` | `height` 가 **가장 높은**(=죽기 직전인) 좌석. 동률이면 낮은 번호 | 0회 |

고른 뒤 구멍 x 를 난수 1회로 뽑아 `grb` 를 방 전체에 브로드캐스트한다.
피해자만 받게 하지 않는 이유는, 관전 화면이 "누가 누구를 때렸는지" 화살표로 그려야 하기 때문이다.

## 8. 등수

`ko {i}` 를 받으면 그 순간 **살아 있는 좌석 수**가 그대로 `place` 가 된다.
8석 중 첫 번째로 죽으면 8등. 살아남은 좌석이 1석이 되면 그 좌석이 1등이고
`end {order}` 로 라운드가 끝난다. 좌석이 1석뿐인 **1인용**도 같은 경로를 탄다 — 죽으면 1등, 즉시 `end`.

## 9. 오류 코드

| `code` | 언제 |
|---|---|
| `ver` | 프로토콜 버전 불일치 |
| `phase` | 로비에서만 되는 걸 게임 중에 했다 (또는 반대) |
| `seat` | 좌석 번호가 범위 밖이거나 이미 찼다 |
| `full` | 이 PC 가 이미 `perPeer` 석을 쥐고 있다 |
| `own` | 내 좌석이 아니다 |
| `host` | 방장만 할 수 있다 |
| `ready` | 준비 안 된 사람 좌석이 있다 |
| `nosuch` | 그런 방 코드가 없다 |
