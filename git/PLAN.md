# Git Encyclopedia (Git_대백과사전.html) — Work Plan for the Building Agent

> Audience of this file: the agent (Opus) that builds the deck. Written in English per the global
> language policy. The deck body itself is Korean (합니다체 in prose, as in the transformer deck).
> Progress log goes at the END of this file (append one entry per commit; never rewrite old entries).
>
> Output: `Git_대백과사전.html` at the repo root — a single-file slide deck cut from `template.html`.
> Hard cap **3000 slides** (user decision 2026-09-18); target band **2,000–2,700**.
> Lineage: `keycloak_ad/` → `compress/` → `wireless/` → `transformer/` (assembler, checks, Makefile,
> svgkit, claims, CITE badges). **Copy, don't reinvent.** Read `transformer/PLAN.md` §0–§2 and the last
> three entries of its progress log once before starting: every rule below that looks pedantic was paid
> for there or in the compression deck.
>
> What this deck is: **everything about Git** — its history (2005 → 2026-09), its principles (object
> store, refs, index, packs, diff/merge algorithms, transport), its limits (scale, binaries, encodings,
> SHA-1, security), and a scenario-driven usage guide. **Appendix A is "만들면서 배우는 Git"**: the same
> minimal Git (`mygit`) implemented in **Python, TypeScript, Go, Java and C++** from one spec, and every
> object it writes is byte-identical to what real `git 2.55.0` (installed here) writes. Real git is
> the oracle for the whole deck: every "principle" slide is backed by a captured experiment on a real
> repository, not by prose from memory.

## 0. Non-negotiables (read twice)

1. **The deck HTML is a build artifact.** Never edit it by hand. Edit `git/deck/sections/*.html` or the
   sources they cite, then `make all`.
2. **No hand-written code, numbers or captures in the deck.** Every `<pre><code>` is a
   `<!--CODE file=… lines=A-B|sym=…-->` directive filled from a real file under `git/`. Every terminal
   capture is `<!--OUT file=…-->` from `git/out/`, produced by `run_all.py` running **real git** or
   `mygit` in a scratch repo. Every table of measured numbers (object counts, pack sizes, delta ratios,
   timings expressed as ratios, line counts) is `<!--TABLE file=…-->` generated by `run_all.py`.
   `verify_deck.py` re-checks deck ↔ source on every build.
3. **Real git is the oracle.** Any statement of the form "git does X" that can be shown must be shown:
   a captured command in `out/`. Format claims (object header, index v2, pack v2, idx v2, pkt-line)
   are quoted from the official format documents (`gitformat-pack`, `gitformat-index`, `gitprotocol-pack`,
   `gitprotocol-v2`, `gitformat-signature`, `gitrepository-layout`) fetched into `docs/` (§2) and cited
   with `<!--CITE key=… sec=…-->`. `mygit` outputs are checked against real git with `git fsck --strict`,
   `git cat-file`, `git ls-tree`, `git verify-pack`, `git index-pack`, `git status`, `git log`.
4. **Every fact has a source.** Dates, version numbers, names, quotes, mailing-list events, CVE ids,
   company adoption claims go in `deck/claims.md` as `claim | source | verified-how | date` **before**
   they appear on a slide. Sources in order of preference: the git repository itself (a commit hash or
   tag — verified with `git log`/`git show` in the local mirror, §2), `Documentation/RelNotes/*.adoc`,
   lore.kernel.org message ids, git-scm.com docs, the Pro Git book (CC BY-NC-SA 3.0 — **cite and
   paraphrase, never copy passages**), then Wikipedia **with its own citation followed**. A claim that
   cannot be sourced is dropped or marked `<span class="unv">미확인</span>`.
5. **Knowledge-cutoff discipline.** Anything dated 2025 or later (latest git version, SHA-256
   interoperability status, reftable default, GitHub/GitLab feature changes, "current" CVEs) must be
   re-verified with WebSearch or the local git mirror at build time and written with an explicit
   "2026-09 기준" stamp. The installed `git 2.55.0` and its `RelNotes/2.55.0.adoc` are the anchor.
6. **Tests before code (RED → GREEN)** for every `mygit` module in every language. Parity fixtures
   (golden objects, hashes, index bytes, pack bytes) are produced by **real git** first (`golden/`), so
   every language's tests are RED for the right reason before a line of implementation exists. Never
   loosen an assertion to pass. If a stated property of git turns out to be false, fix the slide, not
   the oracle.
7. **This machine is a Galaxy Fold under Termux/proot with a few hundred MB free and a full swap.**
   At most **2 subagents**, **one JVM at a time** (`javac`/`java` through `flock` — copy the recipe from
   `compress/Makefile`), no `-j`. Never clone `git/git` in full (1+ GB); use the shallow/partial mirror
   recipe in §2. Recorded runs are sized to finish in ≤ 2 min each, `run_all.py` in ≤ 25 min total, and
   run strictly sequentially. Check `free -m` before heavy steps. Checkpoint everything to disk; assume
   the session can be killed any moment. Long runs go in the background with a Monitor.
8. **Foldable layout.** `<pre>` ≤ 45 lines and ≤ 72 columns (Korean counts as 2), captures ≤ 108
   columns, `<li>` ≤ 14 per list, no box-drawing characters in prose, no `①②③` inside monospace.
   DAG/graph figures are SVG generated by `deck/gen_figs.py` from real repositories (`git log --graph`
   is a capture, never a hand-drawn ASCII graph). SVG `viewBox` width 340 so it fits 374 px. The
   assembler errors on all of these.
9. **Determinism is evidence.** Every capture in `out/` must be identical across three runs
   (`tools/record.sh --check`, md5). Real-git sessions are made deterministic with
   `GIT_AUTHOR_NAME/EMAIL/DATE`, `GIT_COMMITTER_*` (fixed epoch `1700000000 +0900`), `TZ=UTC`, `LANG=C`,
   `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `HOME=$scratch`, `--no-pager`, and
   `init.defaultBranch=main` set explicitly. Pack contents are made deterministic with
   `pack.threads=1`, `pack.window=10`, `pack.depth=50` (quoted on the slide). Any command whose
   output legitimately varies (timestamps in reflog *display*, `git gc` progress) is captured with the
   varying column normalized by `run_all.py` and the normalization stated in the caption.
   No wall-clock numbers anywhere in prose; a speed comparison is a ratio table cited from `out/`.
10. **The five languages are equals, but Python leads.** The appendix narrative walks each step in
    Python (the shortest), then shows the *same* step in TS/Go/Java/C++ as a 4-up comparison
    (`<!--CODE sym=…-->` from each tree, same function name in every language — SPEC §naming). No
    language may skip a step; a step that is "left as an exercise" in one language does not exist.
    All five must pass the same `golden/` fixtures and the same real-git cross-checks.
11. **Commit granularity:** one module per language, one golden batch, one figure batch, or one deck
    part per commit. Korean, no-prefix commit subject (repo convention). Never `git push` unless asked.
    **Never run `git` commands from `run_all.py` against this repository** — every experiment runs in
    `scratch/repos/<name>/` created fresh by the script (`rm -rf` only under that path).
12. **Language:** deck prose in Korean 합니다체; identifiers, file names, commit subjects of the
    *example* repositories in English (so captures match what readers see in the wild); this file and
    subagent briefs in English.

## 3. What gets written

### 3.0 `SPEC.md` — the contract all five implementations share (write first; tests cite it)

- **Scope of `mygit`** (the same 14 commands in every language, same exit codes, same byte output):
  `init`, `hash-object [-w]`, `cat-file (-t|-s|-p)`, `add`, `rm --cached`, `status` (short form),
  `write-tree`, `commit-tree`, `commit -m`, `log` (`--oneline` and full), `branch`, `switch`/`checkout`,
  `tag [-a]`, `diff` (working tree vs index, index vs HEAD, commit vs commit), `merge` (fast-forward
  and 3-way with conflict markers), `merge-base`, `unpack-pack`/`read-pack` (read real git packs incl.
  OFS/REF deltas), `pack` (write a pack: first without deltas, then with a simple delta), `verify-pack`,
  `reflog` (write + show), `clone <local path>` (dumb: copy objects, resolve refs) and
  `fetch-pack <path>` over the **smart protocol v0/v2 pkt-line** against real `git-upload-pack` spawned as
  a child process. Everything else is out of scope and the deck says so on the appendix cover.
- **Repository layout produced**: `.git/{HEAD,config,objects/xx/…,refs/heads,refs/tags,index,logs/}`
  exactly as `gitrepository-layout` describes, so real git can open it.
- **Byte formats pinned with worked examples**: object header `"<type> <size>\0"`, tree entry
  `"<mode> <name>\0<20-byte sha>"` and the tree sort rule (directory names sort as if they ended in
  `/`), commit text with author/committer lines and `+0900` offsets, annotated tag text, index v2
  (header, entry with stat fields we do and do not fill, name flags, padding to 8, trailing SHA-1),
  pack v2 (header, varint size, OFS_DELTA/REF_DELTA encoding, delta copy/insert opcodes, trailer),
  idx v2 (fanout, sha list, crc32, offsets), pkt-line framing (`0000` flush, `0001` delim),
  `want/have/done`, `ref-prefix`, sideband-64k demux.
- **SHA-1** implemented by hand in every language (`sha1.<ext>`), verified against `hashlib`/`crypto`
  /`MessageDigest`/`crypto/sha1` in tests where a stdlib exists, and against `golden/sha1.tsv`
  (100 vectors incl. empty, 55/56/64/65-byte boundaries, 1 MB) everywhere. SHA-256 object format
  is **explained** (part 14) but `mygit` stays SHA-1 (decision 4).
- **zlib**: stdlib in py/ts/go/java; hand-written in C++ (`inflate.cpp` full RFC 1951 decoder,
  `deflate.cpp` stored blocks only + Adler-32). Tests: C++ inflates every object real git wrote;
  real git `cat-file` reads every stored-block object C++ wrote (`golden/stored_ok.txt`).
- **Diff**: Myers O((N+M)D) with the linear-space middle-snake refinement *optional* (decision 7);
  unified output identical to `git diff --no-index` for `golden/diff_*` pairs (`diff.algorithm=myers`,
  `-U3`, no color, `core.autocrlf=false`).
- **Merge**: 3-way file merge at line level (`diff3`-style, no rename detection) with conflict markers
  identical to `git merge` for `golden/merge_*` cases (`merge.conflictStyle=merge`).
- **Naming table**: the same command → function name in every language (`writeTree`, `write_tree`,
  `WriteTree`…, one row per language) so 4-up comparison slides can `sym=` each one.
- **Error contract**: exit 128 with the same first line as git for the five errors the deck shows
  (`fatal: not a git repository`, `fatal: Not a valid object name`, conflict exit 1, etc.).
- **Determinism**: author/committer taken from `GIT_*` env only (no config lookup), no wall clock ever.

### 3.1 The appendix steps (12 steps, identical in every language; one commit per step per language)

| Step | Title (Korean, as on the slides) | What each language delivers | Oracle check (real git) |
|---|---|---|---|
| 1 | SHA-1 을 손으로 | `sha1` module (80–120 lines) | `git hash-object --stdin` on 100 vectors = ours |
| 2 | zlib 과 느슨한 객체 | `zlib` wrapper (C++: inflate/deflate), `objects.write/read` | `git cat-file -p` reads ours; `git fsck --strict` clean |
| 3 | blob — hash-object · cat-file | `blob` CLI | sha equal for `golden/blobs/` |
| 4 | tree — 정렬 규칙이 전부다 | `tree` build/parse, sort rule | `git write-tree` sha equal for 12 fixture trees incl. `a`, `a-b`, `a/b`, `a.b` ordering trap |
| 5 | commit · refs · HEAD | `commit-tree`, `commit`, `refs`, `symbolic HEAD` | `git log` on our repo shows our commits; `git rev-parse HEAD` |
| 6 | index — 스테이징의 실체 | index v2 read/write, `add`, `rm --cached`, `status` | `git ls-files --stage` and `git status --porcelain` agree on our index; ours reads git's |
| 7 | log · DAG 순회 · merge-base | commit walk (date-ordered), LCA | `git merge-base` and `git log --topo-order` equal on the `golden/dag` repo (criss-cross case) |
| 8 | diff — Myers 알고리즘 | `myers`, unified diff, `diff` CLI | byte-equal to `git diff --no-index` on 30 pairs |
| 9 | checkout · switch — 작업 트리 쓰기 | tree → worktree, index refresh, `switch` | `git status` clean after our checkout of a git-made commit |
| 10 | merge — 3-way 와 충돌 | fast-forward, 3-way, conflict markers, `MERGE_HEAD` | byte-equal conflict files vs `git merge` on 10 cases; `git fsck` clean |
| 11 | packfile — 읽기, 그다음 쓰기 | pack/idx reader with deltas, pack writer (no delta → delta), `verify-pack` | we read every pack `git repack -adf` made; `git index-pack --strict` accepts ours; `git unpack-objects` round-trips |
| 12 | 전송 — pkt-line 으로 진짜 git 과 대화 | `clone <path>` (dumb) and `fetch-pack` v2 via child `git-upload-pack` | our clone passes `git fsck`; `git log` in our clone = origin's; transcript = `golden/pkt/*.txt` |

Per language line budget (estimate; the assembler prints actuals): py ≈ 1,300 · ts ≈ 1,600 ·
go ≈ 1,700 · java ≈ 2,000 · cpp ≈ 2,400 (hand zlib) → ≈ 9,000 lines → FULLSRC ≈ 200 slides.

### 3.2 Recorded experiments (`run_all.py` → `out/`, each ≤ 2 min, sequential)

Each experiment builds a fresh repo under `scratch/repos/<name>/` with `tools/gitenv.sh` (§0.9) and
captures commands with the exact command line as the first line. Planned set (≥ 60; ids are the
`<!--GIT repo=… -->` names):

- `hello` — init, first commit, the four object types dumped with `cat-file`, `find .git/objects`.
- `objects` — hand-make a blob with `printf | zlib | sha1` in Python and show git reading it;
  corrupt one byte → `fsck` output; header formats.
- `tree_sort` — the `a`, `a-b`, `a/b` ordering trap, `ls-tree`, `write-tree`.
- `refs` — `HEAD`, detached HEAD, `packed-refs` after `pack-refs`, `symbolic-ref`, `update-ref`,
  reflog entries, `reflog expire`.
- `index` — `ls-files --stage --debug`, `update-index --assume-unchanged`, `--skip-worktree`,
  racy-git demonstration (same-second mtime), `sparse-checkout` cone mode.
- `dag` — a criss-cross history, `merge-base --all`, `log --graph` capture, `rev-list --count`,
  `--ancestry-path`, `--first-parent`.
- `merge_*` — fast-forward, 3-way clean, conflict, `rerere`, `ort` vs `recursive` rename case,
  `-X ours`, octopus, squash, `merge --no-ff`.
- `rebase_*` — `rebase -i` scripted with `GIT_SEQUENCE_EDITOR`, `--autosquash`, `--onto`,
  `--update-refs`, cherry-pick with conflicts, revert of a merge (`-m 1`).
- `diff_*` — myers/patience/histogram/minimal on the same input, `--word-diff`, `-w`, `--stat`,
  `blame -w -M -C`, `log -S/-G`, `bisect run` with a script.
- `pack_*` — `count-objects -v` before/after `gc`, `verify-pack -v` (delta chains), `repack` window/depth
  effect table, `multi-pack-index`, `commit-graph write`, bitmap, `prune`, `unreachable` objects and
  `fsck --lost-found`.
- `proto_*` — `GIT_TRACE_PACKET=1` fetch over local path (v0 and `protocol.version=2`), dumb HTTP
  layout (`update-server-info`), `bundle create/verify`, shallow clone, partial clone
  (`--filter=blob:none`) + promisor, `push` to a bare repo with `receive.denyNonFastForwards`.
- `config_hooks` — three config levels, `includeIf`, `.gitattributes` (`eol`, `diff=…`, `merge=…`,
  `export-ignore`), `.gitignore` precedence, `pre-commit`/`commit-msg`/`pre-push` hooks firing,
  `worktree add`, `submodule` add/update, `subtree`, `credential` (no secrets: dummy helper),
  SSH signing with a throwaway key, `maintenance run`.
- `limits_*` — 10 MB binary churn vs text (pack growth table), 100k-file tree timing ratios,
  case-insensitive rename trap simulated with `core.ignorecase`, CRLF round trip, NFC/NFD filename
  bytes, empty directory disappearing, file mode 644/755/symlink in `ls-tree`, `--date` timezone
  display, SHA-256 repo `init --object-format=sha256` (object ids 64 hex) and its no-interop message.
- `recovery_*` — the 40 "사고" scenarios of part 16 each as a two-part capture: the mistake, the fix.
- `mygit_*` — the five implementations run the same script; `diff` of their `.git` trees and object
  lists; parity table (`out/tbl_parity.html`: step × language = ok).
- `cmdref_*` — every command in `data/commands.tsv` gets at least one capture (`git <cmd> -h` first
  line + one real invocation) for the command dictionary (part 17).
