RedPhone Clone · Build Spec

00 개요

2000년대 사내에서 쓰이던 LAN 메신저 X-PopUp(별명: 빨간전화기)의 현대식 Go 클론. 중앙 서버 없이 같은 네트워크의 PC들이 서로를 자동 발견하고 쪽지·파일을 주고받는다. UI는 네이티브 트레이 대신 로컬 웹 UI로 구현하고, 추가로 이미지/텍스트 파일을 로컬 웹서버 URL로 즉시 공유하는 기능을 넣는다.

자동 발견

UDP 브로드캐스트로 같은 서브넷의 피어를 서버 없이 탐지. 주기적 HELLO + TTL 만료.

쪽지 · 파일

쪽지는 fingerprint pinning된 HTTPS, 파일 본문은 토큰 기반 HTTP 스트림으로 직접 전송. 브라우저는 WebSocket으로 실시간 수신.

URL 공유

파일을 http://내IP:포트/s/<token>로 발행. 이미지는 인라인, 텍스트는 미리보기.

#설계 원칙

  • 의존성 최소화 — 표준 라이브러리 우선. 외부 패키지는 왜 필요한지 정당화될 때만.
  • 단일 실행 파일 — 원본처럼 redphone.exe 하나로 무설치 실행. 웹 자산은 embed.FS로 바이너리에 내장.
  • 서버리스 P2P — 중앙 서버 0대. 모든 인스턴스가 곧 서버이자 클라이언트.
  • 세 가지 종료 경로 — 콘솔에 exit 입력, 웹 UI의 종료 버튼, 그리고 SIGINT. 셋 다 graceful shutdown.
  • 성능 — goroutine + channel 기반, 락 경합 최소화, -race 통과를 DoD에 포함.

이 문서는 Claude Code 자율 실행용 작업 지시서다. CLAUDE.md + Todo.md를 Git에 두고, 이슈 1개 = 프롬프트 1개, 구현 전 테스트(TDD), 태스크마다 Git 체크포인트 규율을 따른다.

Dependencies

01 기술 스택

표준 라이브러리로 최대한 끝낸다. 외부 의존성은 WebSocket과 순수 Go SQLite 드라이버로 제한하며, 그 이유를 아래에 명시한다.

net (UDP) · 표준

피어 발견용 브로드캐스트 송수신. net.ListenPacket("udp4", ...)

WHY 발견은 단순 데이터그램이면 충분. 외부 라이브러리 불필요.

net/http · 표준

웹 UI 서빙 + REST API + 피어 간 HTTP/HTTPS 송수신 + URL 공유 엔드포인트 담당.

WHY UI·API·공유·파일 본문을 표준 HTTP 평면으로 통일하고, 메시지/파일 메타는 HTTPS로 보호.

embed · 표준

//go:embed static(internal/web 패키지 내부 기준)으로 HTML/CSS/JS를 바이너리에 내장.

WHY "실행 파일 하나" 원칙. 배포 시 자산 누락 없음.

context / os/signal / sync · 표준

생명주기·graceful shutdown·피어 레지스트리 동시성.

WHY exit/버튼/시그널 3개 종료 경로를 하나의 context 취소로 수렴.

#외부 의존성

github.com/coder/websocket

브라우저 ↔ Go 백엔드 실시간 푸시(피어 갱신, 수신 쪽지/파일 알림)용.

WHY 표준 라이브러리에 WS가 없음. coder/websocket은 API가 작고 컨텍스트 친화적이라 gorilla/websocket보다 종료 처리가 깔끔.

modernc.org/sqlite

채팅 히스토리를 redphone.db에 영속 저장하는 순수 Go SQLite 드라이버.

WHY 브라우저를 닫아도 기록을 유지하면서 cgo/Termux 제약을 피한다.

// 언어 비교 노트

Node였다면 ws + express를 깔았을 자리를, Go는 net/http 하나로 정적 서빙·REST·파일 업로드를 다 처리한다. Java로 치면 임베디드 Jetty를 띄우는 셈인데, Go는 그게 표준 라이브러리라 추가 프레임워크가 없다.

Go 1.22+ stdlib: net · net/http · embed · context · sync · os/signal · encoding/json dep: coder/websocket · modernc.org/sqlite

Components & Concurrency

02 아키텍처

하나의 프로세스 안에서 goroutine들이 context.Context 하나를 공유한다. 종료 신호는 어디서 오든 그 context를 취소해 전부 정리한다.

#동시성 모델

Goroutine역할종료 방식
udpListenHELLO/BYE 수신 → 레지스트리 upsert/removeconn close + ctx
udpBroadcast5초 ticker로 HELLO 송신ctx.Done()
peerSweep3초 ticker로 LastSeen 만료 피어 제거ctx.Done()
httpServe / httpsServeUI/API/공유/파일본문 + TLS inbox 서빙Shutdown(ctx)
wsHub.runregister/unregister/broadcast 채널 단일 소유ctx.Done()
stdinRead한 줄씩 읽어 exit 감지cancel() 호출
signalWatchSIGINT/SIGTERM 감지cancel() 호출
// 비교: Hub는 왜 락이 아니라 채널인가

WS 클라이언트 맵을 sync.Mutex로 보호하는 대신, 맵을 단 하나의 goroutine만 소유하고 register/unregister/broadcast를 채널로 보낸다. "메모리를 공유해 통신하지 말고, 통신해서 메모리를 공유하라"는 Go 관용구. Java의 synchronized 컬렉션이나 C++의 mutex 가드보다 데드락·경합 표면이 작다.

Wire Format

03 프로토콜 설계

발견은 UDP, UI·공유·파일 본문은 HTTP, 메시지와 파일 메타데이터는 fingerprint pinning된 HTTPS. 포트는 기본값 + 자동 폴백.

#포트

이름값용도
DISCOVERY_PORT17000/udp 고정브로드캐스트 송수신 (255.255.255.255). 같은 PC 다중 인스턴스 테스트를 위해 discovery 소켓은 SO_REUSEADDR를 bind 전에 설정
HTTP_PORT17080 우선, 사용 중이면 OS 자동(:0)웹 UI·REST API·공유 링크·파일 본문 스트림. 실제 포트를 HELLO에 실어 광고
HTTPS_PORT17443 우선, 사용 중이면 OS 자동(:0)피어 간 쪽지와 파일 announce. self-signed 인증서 fingerprint를 HELLO에 실어 pinning

#Discovery 메시지 (JSON over UDP)

udp-payload.json
// HELLO v2 — 5초마다 브로드캐스트. ip는 신뢰하지 않고 수신 패킷의 src addr를 사용한다.
{ "v":2, "type":"hello", "id":"<runtime-id>", "uid":"<stable-id>", "name":"chobocho", "httpPort":17080, "httpsPort":17443, "fp":"<leaf-cert-sha256>", "ts":1730000000000 }

// BYE — graceful shutdown 직전 1회 송신. 상대는 즉시 목록에서 제거.
{ "v":2, "type":"bye", "id":"<runtime-id>", "uid":"<stable-id>" }
// 보안/견고성 규칙

자기 자신의 브로드캐스트는 id로 필터링한다. 피어의 IP는 페이로드가 아니라 UDP 패킷의 출발지 주소에서 취한다(스푸핑 방지). v2 HELLO는 fp가 없으면 거부하고, LastSeen이 15초 넘으면 자동 만료.

메서드 · 경로설명

POST /inbox/file/announce피어→나: TLS-only 파일명·송신자 메타 수신 → 1회용 업로드 토큰 발급
PUT /inbox/file/{token}피어→나: 파일 본문 스트리밍 저장 → ./downloads/ 링크를 히스토리에 기록
GET /downloads/{name}수신 파일 열기. 경로 탈출 차단
POST /api/shutdown종료 버튼 → ctx 취소(graceful)

#종료 시퀀스 (3경로 → 1수렴)

shutdown-flow
  exit(stdin) ─┐
  종료(POST)  ─┼─▶ cancel(ctx) ─▶ ① BYE 브로드캐스트
  SIGINT      ─┘                  ② httpSrv/httpsSrv.Shutdown(timeout 3s)
                                  ③ ticker/hub 정지, ws 클라이언트 close
                                  ④ wg.Wait() (sync.WaitGroup) ─▶ exit(0)

Functional Spec

05 기능 명세

각 기능은 관찰 가능한 동작과 수용 기준(AC)으로 기술. AI가 테스트를 먼저 쓸 수 있도록 입력/출력을 구체화한다.

F1. 피어 자동 발견
  • 실행 즉시 HELLO 브로드캐스트 시작, 5초 주기.
  • 다른 인스턴스의 HELLO 수신 시 목록에 추가/갱신(이름·IP·httpPort·httpsPort·fingerprint·LastSeen).
  • 15초간 HELLO 없으면 오프라인 처리(목록에서 제거).
  • AC: 같은 LAN의 두 인스턴스가 ≤6초 내 서로를 목록에 표시. 한쪽 종료 시 ≤2초 내(BYE) 사라짐.
F2. 쪽지 송수신
  • 피어 선택 → 텍스트 입력 → 전송. 내 백엔드가 상대 HTTPS /inbox/message로 POST하고 fingerprint pinning으로 피어를 검증.
  • 수신 측은 WS로 브라우저에 즉시 푸시, 대화 히스토리는 SQLite(redphone.db)에 영속 저장.
  • 브라우저 새로고침 시 GET /api/history로 전체 히스토리를 복원하고, 필요한 경우 ?peerId=…로 특정 대화만 조회.
  • AC: A→B 전송 후 B 화면에 ≤1초 내 표시. 상대 오프라인이면 전송 실패를 UI에 명시.
F3. 파일 전송
  • 브라우저는 POST /api/sendfile multipart로 업로드. 백엔드는 상대 HTTPS /inbox/file/announce로 파일명·송신자 메타를 먼저 보내고, 받은 토큰으로 HTTP PUT /inbox/file/{token}에 본문을 스트리밍.
  • 수신 측은 ./downloads/에 저장하고 /downloads/{name} 링크를 SQLite 히스토리에 남긴다.
  • 파일명 충돌 시 name (2).ext 식으로 회피. 경로 탈출(../) 차단. 대용량(100MB) 전송 중 RSS 증가 ≤ 32MB (io.Copy 스트리밍, runtime.ReadMemStats로 측정).
  • AC: 임의 바이너리 왕복 후 SHA-256 동일. 100MB도 메모리 폭증 없이 스트리밍.
F4. URL 공유 신규 추가 기능

파일을 전송하지 않고 링크로 노출한다. 같은 LAN의 누구든 브라우저로 열 수 있다.

  • 업로드 → 랜덤 토큰(예: 22자 base62) 발급 → http://<myIP>:<port>/s/<token> 반환.
  • 이미지(png/jpg/gif/webp): <img>로 인라인 렌더. 텍스트(txt/md/log/csv/json/소스): 코드 미리보기. 그 외: 다운로드.
  • content-type은 확장자 + http.DetectContentType 둘 다로 판정.
  • 공유 목록 표시 + 개별 회수(DELETE). 토큰은 추측 불가해야 함.
  • AC: 이미지 토큰 GET → Content-Type: image/* + 인라인. 텍스트 토큰 → 이스케이프된 미리보기. 잘못된 토큰 → 404.
// 범위 한정

공유는 LAN 한정·휘발성(인스턴스 종료 시 소멸). 인증은 토큰 비밀성에 의존. 외부망 노출/영속화는 v2 과제로 분리.

F5. 웹 UI
  • 실행 시 기본 브라우저로 http://localhost:<port> 자동 오픈(OS별 분기).
  • 좌측 피어 목록(온라인 LED), 중앙 대화/입력, 파일 첨부, 공유 패널, 우상단 종료 버튼.
  • 반응형: 데스크톱·모바일·Galaxy Fold 펼침/접힘 모두 대응.
  • 자산은 embed.FS. 프레임워크 없이 바닐라 JS + WS.
F6. 종료 (exit / 버튼 / SIGINT)
  • 콘솔에 exit(개행 포함) 입력 → graceful shutdown.
  • 웹 UI 종료 버튼 → POST /api/shutdown → 동일 경로.
  • SIGINT/SIGTERM도 같은 root context 취소 경로로 수렴.
  • 셋 다 BYE 브로드캐스트 후 3초 타임아웃 내 HTTP·HTTPS 서버와 goroutine을 정리, exit code 0.
  • AC: 세 경로(exit·버튼·SIGINT) 모두 좀비 goroutine 없이 종료(go test -race 통과). 포트 즉시 해제.

CLAUDE.md
# RedPhone — 빨간전화기(X-PopUp) Go 클론

## 무엇 / 왜
중앙 서버 없이 같은 LAN의 PC들이 서로를 자동 발견하고 쪽지·파일을 주고받는
무설치 단일 바이너리 메신저. UI는 로컬 웹. 추가로 파일을 로컬 URL로 공유한다.
WHY: 사내/가정 LAN에서 "USB로 옮기기"를 대체. 외부 클라우드·서버 의존 0.

## 기술 제약 (지킬 것)
- Go 1.22+. stdlib 우선. 외부 의존성은 coder/websocket + modernc.org/sqlite로 제한.
  WHY: WS는 표준 라이브러리에 없고, SQLite는 cgo 없이 히스토리 영속화를 제공.
- 웹 자산은 //go:embed 로 내장 → 실행 파일 하나로 동작.
- 발견=UDP(17000), UI/API/공유/파일본문=HTTP(17080), 메시지/파일메타=HTTPS(17443). TCP 포트는 사용 중이면 OS 자동 폴백.
- 피어 IP는 UDP 패킷 src addr에서 취득(페이로드 신뢰 금지).
- HELLO v2는 HTTPS 포트와 leaf cert SHA-256 fingerprint를 광고하고, 피어 간 HTTPS 송신은 fingerprint pinning.
- 채팅 히스토리는 SQLite(redphone.db)에 영속 저장. 공유 파일은 인스턴스 종료 시 회수.
- 파일 저장 시 경로 탈출(../) 차단, 파일명 충돌 회피.

## 동시성 / 종료
- root context 하나를 모든 goroutine이 공유.
- 종료 경로 3개(stdin "exit" / POST /api/shutdown / SIGINT) → 모두 cancel(ctx).
- 종료 시: BYE 브로드캐스트 → httpSrv/httpsSrv.Shutdown(3s) → ticker/hub 정지 → Wait → exit 0.
- WS hub는 mutex 대신 channel로 클라이언트 맵을 단일 goroutine이 소유.

## 작업 규율
- 이슈 1개 = 프롬프트 1개. Todo.md의 한 항목만 처리.
- TDD: 실패하는 테스트(RED) 먼저 → 구현(GREEN) → 리팩터.
- 모든 동시성 코드는 `go test -race` 통과가 DoD.
- 태스크 완료마다 Git 체크포인트: feat(scope): ... / test(scope): ...
- 주석은 "왜"를 적는다(무엇은 코드가 말한다).

#프롬프트 골격

prompt-template
Todo.md의 #N 이슈만 처리해. 다른 이슈는 건드리지 마.

1) 먼저 실패하는 테스트를 작성(RED). 무엇을 검증하는지 주석으로.
2) 최소 구현으로 통과시켜(GREEN).
3) 리팩터: 중복 제거, 이름 정리. 동시성이면 `go test -race`.
4) `go vet ./...` 무경고 확인.
5) 끝나면 멈추고, 변경 요약 + 제안 커밋 메시지(feat/test(scope): ...)를 출력.

CLAUDE.md의 제약과 DoD를 반드시 지켜. 범위를 넘기면 안 돼.

// 검증 스모크 테스트

빌드 후 같은 PC에서 HTTP/HTTPS 포트를 바꿔 두 인스턴스를 띄워(--port 17080 --sport 17443, --port 17081 --sport 17444) 상호 발견·쪽지·공유 링크를 확인. UDP 17000은 고정 바인드지만 discovery 소켓이 SO_REUSEADDR를 설정하므로 같은 PC 다중 인스턴스 테스트가 가능해야 한다(§03 포트 표 참고). 그다음 다른 PC로 LAN 검증. 마지막에 exit, 종료 버튼, SIGINT 세 경로로 정상 종료를 확인한다.
