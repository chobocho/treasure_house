게임 — 상태 기계 하나

입력은 enum, 시간은 숫자 · 캡슐화 · 고정 지연 · 시험으로 규칙 못 박기

코어의 바깥 경계 — 함수 두 개

키·패드·터치→apply(Action)
시계→tick(dt_ms)
Game→게터 → 화면
시계를 주입한다 — Go 에서 time.Now 를 인터페이스로 빼는 것, Java 에서 Clock 을 넘기는 것과 같은 생각을 더 단순하게 했습니다. 코어는 "몇 ms 지났다"만 받으므로 시험이 1초를 기다릴 필요가 없습니다.

입력 — enum Action

프런트엔드무엇을 Action 으로 바꾸나
TUI (2부)crossterm KeyEvent
GUI (3부)minifb Key
WASM (4부)JS 가 넘긴 정수 0~7
키 배치는 바깥의 일이라 코어에는 "왼쪽 화살표"라는 말이 없습니다. 같은 Action 을 받으니 세 판의 동작이 정확히 같습니다.

struct Game — 전부 닫힌 필드

필드왜 따로 있나
hold_used조각 하나에 홀드는 한 번 — 무한 홀드로 시간 끌기 방지
fall_ms / lock_ms공중에서는 중력을, 바닥에서는 고정 지연을 센다
resets바닥에서 움직여 고정을 미룬 횟수. 15번까지
모두 비공개 — 바깥에서 score 를 고치거나 over 를 되돌릴 길이 없습니다. 288바이트, 힙에 있는 것은 봉지의 VecDeque 하나뿐입니다.

시작하기 — new 와 with_setup

필드를 하나도 빼먹을 수 없다 — 구조체 리터럴은 모든 필드를 적어야 컴파일됩니다. 필드를 하나 더하면 이 자리가 컴파일 오류로 알려 줍니다. Go 의 "빠진 필드는 0" 과 반대입니다.

중력 공식 — f64 한 번, 결과는 정수 ms

숫자 변환은 전부 명시적 — l as f64, as i32, as u32. Rust 는 u32 * f64 를 그냥 두지 않습니다. .max(1) 은 레벨 20 에서 0.46ms 가 0 으로 반올림되어 무한 루프에 빠지는 것을 막습니다(위 표의 20 이 그 1 입니다).

입력 처리 — apply

apply 읽기

코드설명
let ok = match a { ... };match 가 값을 낸다. 갈래마다 bool
Action::SoftDrop => { ...; ok }블록도 식 — 마지막 줄 ok 가 갈래의 값
return true; (HardDrop·Hold)고정 지연 초기화를 건너뛰고 바로 빠져나간다
unreachable!(...)"여기 오면 버그" — 위에서 이미 처리했지만 match 는 모든 갈래를 요구한다
2 * dist as u32그림자까지 거리 × 2점
_ => false 로 Pause 갈래를 뭉개지 않은 이유 — 그러면 나중에 Action 을 하나 더 넣어도 컴파일러가 이 match 를 짚어 주지 않습니다. 1장의 "빠짐없는 match" 를 스스로 버리는 셈입니다.

고정 지연 — 움직이면 미뤄 주되 15번까지

규칙의 경계를 시험이 정의한다 — 15번째 이동까지는 고정이 미뤄지고, 16번째는 이동만 되고 타이머는 안 돌아갑니다. "무한 회전으로 시간 끌기"를 막는 가이드라인 규칙입니다.

벽 킥 시험 — T 와 I

while g.apply(Action::Left) {} — 몸통이 빈 while. apply 가 false 를 낼 때(벽)까지 민다. 바뀌었으면 true 를 돌려주게 만든 덕에 시험이 짧습니다.

홀드 한 줄 — Option::replace

Python 으로 쓰면
old, self.hold = self.hold, self.cur.kind
nxt = old if old is not None else self.bag.draw()
Rust
let next = match self.hold.replace(self.cur.kind) {
    Some(k) => k,
    None => self.bag.draw(),
};

replace 는 새 값을 넣고 옛 값을 Option 으로 돌려줍니다. 옛 값이 없을 수 있다는 사실이 match 에 드러나 있어, "첫 홀드" 경우를 빠뜨릴 수 없습니다.

시험 도우미 — 판 그림 + 첫 조각

점수까지 손으로 셈한다 — I 를 세워 오른쪽 끝으로 민 뒤 하드 드롭: 16칸 × 2점 + 4줄 800점 × 레벨 1. 숫자가 맞지 않으면 규칙 어딘가가 틀린 것입니다.

4장 시험 결과 — 19개

clippy — 컴파일러 다음의 잔소리꾼

Bag 의 꺼내기 메서드에 처음엔 next 라고 이름을 붙였습니다. clippy 는 표준 Iterator::next 와 헷갈린다며 트레이트를 구현하거나 이름을 바꾸라고 합니다. 이 덱은 이름을 draw 로 바꿨습니다(봉지는 끝나지 않으니 Option 을 내는 Iterator 가 어색합니다).

-D warnings — 경고를 오류로. make lint 가 이것과 cargo fmt --check 를 함께 돌립니다. golangci-lint, ESLint 를 CI 에 거는 것과 같은 자리입니다.

1부 정리 — 코어에서 만난 Rust

장Rust 기능테트리스에서의 쓰임
1enum, match, derive, Copy, 구조체 갱신조각 일곱, 회전 넷, SRS 킥
2고정 배열, Option, ?, &self/&mut self, doctest판, 충돌, 줄 지우기
3wrapping_*, VecDeque, impl Iterator재현되는 난수, 7-bag
4캡슐화, 식으로서의 match, saturating_*, 클로저입력·중력·고정 지연·점수
빌림 검사기와 싸운 곳이 없다 — 판은 Game 혼자 갖고, 조각은 Copy 값이고, 바깥은 게터로 빌려 갈 뿐입니다. 소유 관계가 나무 모양이면 Rust 는 조용합니다. 2부부터는 이 코어를 바깥 세상에 붙입니다.
