일곱 조각 — enum Kind

Java
enum Kind { I, O, T, S, Z, J, L }
// 값 하나하나가 힙의 객체, 변수는 참조
Go
type Kind uint8
const ( I Kind = iota; O; T; S; Z; J; L )
// Kind(99) 도 만들어진다
Rust 의 enum 은 닫혀 있다 — Kind 값은 일곱 중 하나뿐이고 다른 정수를 끼워 넣을 수 없습니다. 크기는 1바이트(아래 "크기 재기" 슬라이드).

#[derive(...)] — 손으로 안 쓰는 구현들

트레이트얻는 것다른 언어의 자리
Clone.clone() 으로 명시적 복제Java clone()
Copy대입·인자 전달이 이동이 아니라 비트 복사Go 의 값 타입, Java 의 int
Debug{:?} 로 찍기 (Kind::T → T)Java toString(), Python __repr__
PartialEq, Eq== 비교Java equals(), Python __eq__
HashHashMap 키로 쓰기Java hashCode()
derive 는 매크로 — 컴파일 시점에 impl Clone for Kind { ... } 같은 코드를 만들어 붙입니다. 런타임 리플렉션이 아닙니다. Java 의 Lombok, Python 의 @dataclass 와 같은 일을 컴파일러가 합니다.

모양 표 — 상수 배열

타입읽는 법
(i32, i32)튜플 — 이름 없는 묶음. Python 튜플과 같지만 길이·타입이 고정
[(i32, i32); 4]길이 4 고정 배열 — 스택에 놓이고 할당이 없다

const 는 컴파일 시점 값 — 쓰는 자리마다 그대로 박힙니다. 주소가 하나인 전역이 필요하면 static 을 씁니다(4부에서 다시 나옵니다).

좌표계 — y 는 아래로

·0,0 T1,0 ·2,0
T0,1 T1,1 T2,1

T 의 스폰 모양 [(1,0), (0,1), (1,1), (2,1)] 을 3×3 상자에 놓은 그림입니다. 판도 같은 방향입니다. 맨 윗줄이 y=0, 바닥이 y=19 입니다.

SRS 문서는 y 가 위로 — 테트리스 위키의 킥 표는 수학 좌표(위가 +)입니다. 이 코드는 표를 위키 그대로 옮겨 두고, kicks() 한 곳에서만 y 부호를 뒤집습니다. 부호 실수를 한곳에 가두는 방법입니다.

match 는 빠짐없이 — 컴파일러가 센다

box_size 를 _ => 없이 쓰고 T 를 깜빡하면 이렇게 됩니다(실제 출력).

Go 의 switch 와 다른 점 — Go 는 빠진 case 를 조용히 넘어가고, Java 도 enum switch 문에서는 컴파일러가 막지 않습니다(식 형태 switch 만 강제). Rust 는 match 가 항상 식이라 모든 경우가 값을 내야 합니다. 조각이나 동작을 하나 더 넣으면 고칠 곳을 컴파일러가 전부 짚어 줍니다.

회전 상태 — enum Rot

R0·R1·R2·R3 은 SRS 문서의 0·R·2·L 입니다. 시계 방향은 +1, 반시계는 +3 (≡ −1 mod 4) — 음수 나머지를 피하는 흔한 요령입니다. const ORDER 처럼 impl 블록 안에 둔 상수를 연관 상수라고 부릅니다(Java 의 static final).

떨어지는 조각 — struct Piece

필드마다 pub — Rust 의 공개 범위는 필드 단위입니다. Piece 는 값 묶음이라 다 열었고, 2장의 Board·4장의 Game 은 필드를 닫고 메서드로만 다룹니다. Go 의 대문자/소문자, Java 의 public/private 와 같은 자리입니다.

impl Piece — 스폰 · 칸 계산 · 이동

Piece 읽기 — 회전 공식과 구조체 갱신

코드설명
Piece { kind, rot: Rot::R0, x, y: 0 }이름이 같은 변수는 kind 처럼 줄여 쓴다(JS 객체 단축 속성과 같다)
let mut out = ...변수는 기본 불변. 고칠 변수에만 mut
for c in out.iter_mut()배열 칸을 하나씩 고칠 수 있게 빌린다 — c 는 &mut (i32, i32)
*c = (n - 1 - c.1, c.0)* 로 빌린 자리에 쓴다. c.0·c.1 은 튜플의 첫째·둘째
Piece { x: ..., ..self }구조체 갱신 문법 — 나머지 필드는 self 에서. JS {...self, x}
회전 표를 따로 두지 않았다 — 상자 안에서 (x, y) → (n−1−y, x) 를 회전 횟수만큼 돌리면 SRS 의 네 상태가 정확히 나옵니다. I(4×4)·O(2×2)도 같은 공식입니다. 시험 t_and_i_states_match_srs 가 이것을 확인합니다.

moved(self) — 값으로 받고 새 값을 돌려준다

Go — 값 리시버
func (p Piece) Moved(dx, dy int) Piece {
    p.X += dx; p.Y += dy
    return p
}
Rust
pub fn moved(self, dx: i32, dy: i32) -> Piece {
    Piece { x: self.x + dx, y: self.y + dy, ..self }
}

Piece 는 12바이트짜리 Copy 라서 self 로 받아도 원본이 사라지지 않습니다. 시험 spawn_position_and_moved 가 moved 뒤에도 t.x == 3 인 것을 확인합니다.

Copy 를 붙이면 안 되는 것 — Vec·String 처럼 힙을 가진 타입은 Copy 가 될 수 없습니다(비트 복사로는 두 주인이 생긴다). 그래서 Board(200바이트 배열)는 Clone 만 붙였습니다. 크면 복사가 숨은 비용이 되기 때문입니다.

SRS 월킥 — 막히면 옆으로 밀어 본다

  1. 제자리에서 돌린다. 들어가면 끝.
  2. 안 들어가면 표의 2번째 이동(예: 왼쪽 1칸)을 더해 다시 시험.
  3. 3·4·5번째까지 차례로. 다섯 다 막히면 회전 실패 — 조각은 그대로.

이동값은 "어느 상태에서 어느 상태로"에 따라 다릅니다. J·L·S·T·Z 가 표 하나를 같이 쓰고, I 는 따로입니다. O 는 모양이 안 바뀌어 킥이 없습니다.

벽에 붙은 T 를 돌리면 — 시험 wall_kick_off_the_left_wall: R 상태로 왼쪽 벽에 붙인 T(x=−1)를 반시계로 돌리면 제자리는 벽에 걸리고, 2번째 이동 (+1, 0)으로 x=0 에 들어갑니다.

킥 표 — 위키 그대로 옮긴 상수

type Kicks = ... 는 타입 별칭입니다(Go 의 type X = Y, TS 의 type). 새 타입이 아니라 긴 이름의 줄임말입니다.
