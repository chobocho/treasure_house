판 한 칸 = 글자 두 개. 터미널 글자는 세로로 길쭉해서 두 개를 붙여야 정사각형에 가깝습니다. [] 는 하드 드롭하면 떨어질 자리(그림자)입니다.

왜 crossterm 인가

크레이트무엇이 덱에서
crosstermraw 모드·커서·색·키 이벤트. 윈도·맥·리눅스✔ 씀 — 저수준이라 Rust 가 잘 보인다
ratatuicrossterm 위의 위젯·레이아웃 프레임워크✘ — 위젯이 차분 그리기를 대신 해 줘서 배울 게 숨는다
termion유닉스 전용 저수준✘ — 윈도가 안 된다
crossterm = "0.29" 은 "0.29 이상 0.30 미만"입니다(캐럿 규칙. 0.x 에서는 둘째 자리가 주 버전). 정확한 버전은 Cargo.lock 에 고정되고, 그 파일을 커밋합니다 — 실행 파일이 있는 워크스페이스의 관례입니다.

오른쪽 패널 — NEXT · HOLD · 점수

패널 읽기 — 클로저가 &mut 를 받는 이유

코드설명
let label = |s: &mut Screen, y, t: &str| ...화면을 인자로 받는다. 클로저가 s 를 붙잡아 두면, 그동안 mini(s, ...) 가 s 를 빌릴 수 없다
if let Some(k) = game.hold()한 갈래만 보는 match. Swift·Kotlin 의 if let/?.let
stats.into_iter().enumerate()배열을 값으로 돌며 (i, (이름, 값)) — 중첩 튜플도 한 번에 푼다
&v.to_string()숫자 → String → &str 로 빌려 넘김
빌림 검사기를 처음 만나는 자리 — label 이 s 를 붙잡는 클로저(|y, t| s.put_str(...))였다면 label(...) 과 mini(s, ...) 를 번갈아 부르는 순간 "두 번 가변 빌림" 오류가 납니다. 고치는 법은 간단합니다: 붙잡지 말고 넘겨받는다.

터미널에 쓰기 — present

out: &mut impl Write — 어디에 쓰든

Go
func Present(out io.Writer, ...) error
Java
void present(OutputStream out, ...)
    throws IOException
코드설명
impl Write (인자 자리)"Write 를 구현한 어떤 타입" — 제네릭의 줄임. 호출마다 그 타입에 맞춘 사본이 컴파일된다(동적 호출 없음)
io::Result<()>성공이면 값 없음(()), 실패면 io::Error
queue!(out, ...)?escape 시퀀스를 버퍼에 쌓는 매크로. 실패하면 ? 가 바로 오류를 돌려준다 — Go 의 if err != nil { return err }
실행 파일은 BufWriter<Stdout>, 시험은 Vec<u8> — 같은 함수가 둘 다 받습니다. 목(mock) 프레임워크가 필요 없습니다.

차분이 아끼는 양 — 실제로 재기

전부 다시 그리면 프레임마다 2.3 KB, 바뀐 칸만 쓰면 0.2~0.5 KB. 초당 60프레임이면 140 KB/s 대 10~30 KB/s 차이이고, 아무 일도 없는 프레임은 거의 0입니다. SSH 너머에서 깜박임이 없는 이유입니다.

화면 시험 — 터미널 없이

"\x1b[2J" 는 "화면 전부 지우기" escape 시퀀스입니다. 첫 화면에는 있고 증분 화면에는 없어야 합니다. 바이트를 직접 보는 시험이라 crossterm 버전이 바뀌어 출력이 달라지면 바로 압니다.
