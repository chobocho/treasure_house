연습 문제

시험을 먼저 · 코어만 고치기 · 세 판에서 확인하기

연습의 순서 — 이 덱이 걸어온 길 그대로

  1. 시험 먼저 — core/tests/game.rs 에 from_rows 판 그림으로 상황을 만들고 기대 점수를 손으로 셈해 적는다.
  2. RED 확인 — cargo test -p tetris-core 가 그 시험에서 값이 달라서 실패하는지 본다(컴파일 오류는 RED 가 아니다).
  3. 코어만 고친다 — game.rs 의 lock_piece·rotate 근처. 프런트엔드는 건드리지 않는다.
  4. GREEN — make test lint.
  5. 세 판 확인 — make build wasm wasm-test. 표시가 필요하면 그때 render·tui 의 패널에 한 줄.
규칙을 바꿨는데 프런트엔드를 고칠 곳이 없다면 1부의 경계 설계가 제 일을 한 것입니다.

연습 1 — T-스핀 판정

할 일힌트
마지막 동작이 회전이었나 기억하기Game 에 bool 필드 하나. rotate 성공 시 켜고, 이동·낙하 성공 시 끈다. 구조체 리터럴(with_setup)이 빠진 필드를 컴파일 오류로 알려 준다
3-코너 규칙T 상자(3×3)의 네 모서리 중 셋 이상이 막혔나 — Board::is_free 를 네 번. 벽·바닥도 막힌 것으로 친다(이미 그렇게 동작한다)
점수T-스핀 싱글 800 · 더블 1200 · 트리플 1600 (× 레벨)
시험 그림 — 바닥에 T 하나 들어갈 홈을 판 판을 from_rows 로 그리고, queue: &[Kind::T] 로 T 를 받아 회전으로 밀어 넣습니다. 4장의 벽 킥 시험과 같은 방식입니다.

연습 2 — 콤보와 백투백

규칙뜻어디를
콤보연속으로 줄을 지울 때마다 50 × 콤보 수 × 레벨lock_piece — 0줄이면 콤보를 끊는다
백투백테트리스·T-스핀이 끊기지 않고 이어지면 1.5배LINE_SCORE 를 곱하는 줄
Rust 다운 표현 — "직전 지우기가 어려운 지우기였나"를 bool 둘로 두지 말고 enum LastClear { None, Normal, Difficult } 처럼 상태 하나로 두면, match 가 빠진 경우를 짚어 줍니다. 1장의 교훈 그대로입니다.

연습 3 — 효과음과 깜박임

판방법
공통코어에는 이미 last_clear() 가 있다. 고정이 일어났는지 알리는 "사건 번호"를 하나 더 두면 프런트엔드가 프레임마다 비교할 수 있다
TUI터미널 벨 \x07 을 present 뒤에 한 바이트
GUIrodio 크레이트(소리) — minifb 는 소리를 모른다
WASMRust 를 고치지 않는다. JS 글루의 onStats 에서 줄 수가 늘면 Web Audio 로 소리
WASM 에 첫 import 를 넣고 싶다면 — Rust 에 extern "C" 블록으로 JS 함수를 선언하고 instantiate(bytes, { env: { ... } }) 로 넘깁니다. 다만 "import 0개" 시험이 깨지는 것을 보고, 그 시험을 고칠지 설계를 지킬지 고르는 것까지가 연습입니다.

연습 4·5 — 최고 점수 · 더 넓은 판

연습생각할 거리
4. 최고 점수 저장TUI·GUI 는 std::fs 로 파일 하나, WASM 은 JS 의 localStorage. 코어는 저장을 몰라야 한다 — 어디까지가 코어인지 다시 긋는 연습
5. 판 크기를 바꾸기WIDTH·HEIGHT 가 const 라 타입([Row; HEIGHT])에 박혀 있다. 실행 중에 바꾸려면 Vec 으로 가거나, 상수 제네릭 Board<const W: usize, const H: usize> 으로 간다
연습 5 는 트레이드오프 연습 — 고정 배열은 할당 0·복사 싸고, Vec 은 유연합니다. 2장 sizes 예제를 다시 돌려 크기가 어떻게 바뀌는지 보세요.
