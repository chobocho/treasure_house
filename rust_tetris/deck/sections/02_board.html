struct Board — 200칸 한 덩어리

흔한 다른 언어 판
Kind[][] rows = new Kind[20][10];
// null 이면 빈 칸 — 깜빡하면 NPE
Rust
rows: [[Option<Kind>; 10]; 20]
// 빈 칸이 타입에 적혀 있다
필드가 pub 이 아니다 — 바깥에서는 rows 를 직접 못 고칩니다. 판을 바꾸는 길은 lock·clear_lines 둘뿐이라 "조각이 반쯤 찍힌 판" 같은 상태가 생기지 않습니다.

칸 묻기 — get · is_free · fits

? 연산자 — Option 에서도 된다

Go 로 풀어 쓰면
if x < 0 || y < 0 { return nil }
if y >= len(rows) { return nil }
if x >= len(rows[y]) { return nil }
return rows[y][x]
Rust
let (x, y) = (usize::try_from(x).ok()?,
              usize::try_from(y).ok()?);
*self.rows.get(y)?.get(x)?
조각뜻
usize::try_from(-1)음수면 Err. .ok() 로 Option 으로 바꾼다
...?None 이면 함수가 즉시 None 을 돌려준다
.get(y)범위 밖이면 패닉 대신 None. rows[y] 는 범위 밖에서 패닉
앞의 *&Option<Kind> 를 값으로 꺼낸다(Copy 라 가능)

판 위쪽은 비어 있다 — 설계 한 줄

is_free 는 y < 0 을 빈 칸으로 칩니다. 그래야 맨 위에서 돌린 I 가 킥으로 위로 밀려 올라갈 수 있습니다. 대신 벽은 위쪽에서도 벽입니다.

경계값마다 한 줄 — 0, 9(WIDTH−1), 10(WIDTH), −1, 19, 20. 주석 문자열("왼쪽 벽")은 실패 메시지에 같이 찍힙니다.

굳히기와 줄 지우기

clear_lines — 한 번 훑어 당겨 쓰기

바닥(y=19)부터 위로 읽으며, 꽉 차지 않은 줄만 write 자리에 복사합니다. 다 읽고 나면 write 위쪽이 지운 줄 수만큼 남고, 그 자리를 빈 줄로 채웁니다.

코드설명
(0..HEIGHT).rev()19, 18, … 0. 범위도 반복자
.all(Option::is_some)열 칸이 모두 Some 인가
self.rows[write] = self.rows[read]줄(10바이트 배열)이 Copy 라 그냥 대입
for row in &mut self.rows[..write]앞부분 슬라이스를 고칠 수 있게 빌려 돈다
복잡도 — O(WIDTH×HEIGHT) 시간, 추가 메모리 O(1). 지운 줄마다 위를 한 칸씩 내리는 흔한 구현(O(줄×HEIGHT×WIDTH))보다 단순하고, 떨어져 있는 줄 둘을 지울 때도 한 번에 끝납니다.

줄 지우기 시험 — 떨어진 두 줄

그림으로 쓰는 시험 — from_rows 덕분에 시험이 판 그림 그대로 읽힙니다. 4장 Game 시험들도 같은 방식입니다.

&self 와 &mut self — 빌림 규칙이 지키는 것

첫 원소를 빌려 둔 채 push 하면, 벡터가 더 큰 곳으로 옮겨 가면서 first 가 해제된 메모리를 가리킬 수 있습니다. C++ 에서는 실행 중의 버그, Java 라면 ConcurrentModificationException 감인 것을 Rust 는 컴파일 시점에 막습니다.

판에서는 — fits(&self) 는 몇 번이든 동시에 부를 수 있고, lock(&mut self) 이 도는 동안에는 아무도 판을 읽지 못합니다. "읽기 여럿 또는 쓰기 하나"가 타입에 적혀 있습니다.

패닉을 기대하는 시험

expected = "10칸" — 패닉 메시지에 이 글자가 들어 있어야 통과합니다. 엉뚱한 곳에서 패닉해도 통과해 버리는 실수를 막습니다. JUnit 의 assertThrows + 메시지 확인, pytest 의 raises(match=...).
