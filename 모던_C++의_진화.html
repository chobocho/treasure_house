이 덱을 읽는 법

  • 표준 순서대로 갑니다: C++11 C++14 C++17 C++20 C++23 — 최신인 C++23에 가장 많은 분량을 썼습니다.
  • 슬라이드 제목의 배지가 그 기능이 들어간 표준을 표시합니다.
  • 코드는 전부 그대로 컴파일되는 실물이거나, 파일명 라벨에 조각임을 밝힌 발췌입니다.

예제를 직접 돌려 보려면

$ g++ -std=c++23 -Wall -Wextra ex.cpp -o ex && ./ex # GCC 12 이하·Clang 16 이하는 -std=c++2b, MSVC는 /std:c++latest
버전 기준 — 이 덱의 C++23 예제는 GCC 14 / Clang 18 기준으로 씁니다. 일부 기능은 아직 컴파일러 지원이 늦다는 표시를 따로 달았습니다.

C++ 표준의 연대표

  • 1985C with Classes → C++ — Bjarne Stroustrup, 첫 상용 릴리스
  • 1998C++98 — 첫 ISO 표준. STL·템플릿·예외
  • 2003C++03 — 결함 수정판
  • 2011C++11 — 13년 만의 대개정. "새로운 언어처럼 느껴진다"(Stroustrup)
  • 2014C++14 — C++11 다듬기
  • 2017C++17 — 어휘 타입과 편의 기능
  • 2020C++20 — 콘셉트·레인지·코루틴·모듈의 4대 기능
  • 2023C++23 — 4대 기능을 실전에 잇는 완성판. 이 덱의 주인공
  • 2026C++26 — 진행 중 (리플렉션·컨트랙트 예정)
핵심 리듬 — C++11 이후 위원회는 3년마다 반드시 출시하는 "기차 시간표" 모델로 바뀌었습니다. 완성된 기능만 태우고, 기차는 제때 떠납니다.

표준은 누가, 어떻게 만드나

제안서 P####→ 스터디 그룹 SG→ EWG / LEWG→ CWG / LWG 문안→ 본회의 투표
  • ISO 산하 WG21 위원회. 언어(EWG)와 라이브러리(LEWG)로 나뉘어 심사합니다.

"모던 C++"이란 무엇인가

같은 일을 하는 코드가 어떻게 변했는지부터 보겠습니다 — 짝수만 골라 제곱해서 출력하기.

C++98
std::vector<int>::const_iterator it;
for (it = v.begin(); it != v.end(); ++it) {
    if (*it % 2 == 0) {
        std::cout << (*it) * (*it) << "\n";
    }
}
C++23
for (int x : v | std::views::filter(is_even)
               | std::views::transform(square))
    std::println("{}", x);
  • 타입은 컴파일러가 안다 — 장황한 이터레이터 선언이 사라졌습니다.
  • 의도를 말한다 — "골라서, 바꿔서, 출력한다"가 코드에 그대로 보입니다.
  • 자원은 스스로 정리된다 — new/​delete 대신 소유권을 타입으로 표현합니다.

여정의 지도

  1. 1부 C++11 — 타입 추론·람다·이동 의미론·스마트 포인터·동시성. 모던 C++의 뼈대.
  2. 2부 C++14 — C++11의 마감 처리. 제네릭 람다와 완화된 constexpr.
  3. 3부 C++17 — 구조적 바인딩, optional/variant, 컴파일 타임 분기.
  4. 4부 C++20 — 콘셉트·레인지·코루틴·모듈, 그리고 constexpr의 전면 확장.
  5. 5부 C++23 — 최신 표준 전체를 기능군별로 깊게. 분량 2배.
  6. 6부 정리 — 표준별 마이그레이션 전략과 C++26 전망.
필요한 배경 — C++98 수준의 문법(클래스·템플릿 기초·STL 컨테이너)을 안다고 가정합니다. 각 기능은 "왜 생겼나 → 문법 → 동작 예제 → 함정" 순서로 설명합니다.

auto — 선언의 혁명 C++11

초기화 식에서 타입을 추론합니다. C++98의 auto(자동 저장 기간)는 의미가 완전히 바뀌었습니다.

#include <iostream>
#include <map>
#include <string>
#include <vector>

int main() {
    auto i = 42;                  // int
    auto d = 3.14;                // double
    auto s = std::string("hi");   // std::string

    std::map<std::string, std::vector<int>> table;
    table["odd"] = {1, 3, 5};
    // C++98 이라면:
    // std::map<std::string, std::vector<int> >::iterator it = table.begin();
    for (auto it = table.begin(); it != table.end(); ++it)
        std::cout << it->first << " " << it->second.size() << "\n";
}   // 출력: odd 3
어디에 쓰나 — 이터레이터·긴 템플릿 타입·람다(이름 붙일 수 없는 타입)에는 필수. 반대로 auto n = f();처럼 타입이 문서 역할을 하는 곳에서는 과용을 피합니다.

auto의 추론 규칙과 함정 C++11

auto는 템플릿 인자 추론과 같은 규칙을 씁니다 — 참조와 최상위 const를 벗겨냅니다.

int x = 10;
int& r = x;
const int cx = 7;

auto a = r;    // int   — 참조가 아니다! a를 바꿔도 x는 그대로
auto b = cx;   // int   — const 탈락, b는 수정 가능
auto& c = r;   // int&  — 참조를 원하면 &를 직접 쓴다
const auto& d = x;   // const int&
vector<bool> 함정 — auto flag = v[0];은 bool이 아니라 프록시 객체를 받습니다. 벡터가 소멸한 뒤 flag를 읽으면 미정의 동작. bool flag = v[0];처럼 타입을 명시하면 안전합니다.
기억법 — 값이 필요하면 auto, 참조가 필요하면 auto&, 읽기만 하면 const auto&. (그대로 전달하는 auto&&는 5장에서.)

decltype — 식의 타입을 그대로 C++11

auto가 "값을 받으며" 추론한다면, decltype은 식의 선언 타입을 벗기지 않고 알려줍니다.

int x = 0;
int& ref = x;

decltype(x)   a = x;   // int
decltype(ref) b = x;   // int&  — 참조가 유지된다 (auto와 다른 점)
decltype((x)) c = x;   // int&  — 괄호를 치면 "lvalue 식"이 되어 참조!
decltype(x)와 decltype((x))는 다릅니다 — 이름 그대로면 선언된 타입, 괄호가 붙으면 식의 값 범주까지 반영합니다. 면접 단골이자 실전에서도 물리는 지점입니다.

제네릭 코드에서 "이 연산의 결과 타입"을 표현할 때 진가가 나옵니다.

template <class T, class U>
auto add(T a, U b) -> decltype(a + b) {   // int+double → double
    return a + b;
}

후행 반환 타입 C++11

반환 타입을 매개변수 뒤에 쓰는 문법입니다. 매개변수 이름을 반환 타입 계산에 쓸 수 있습니다.

✘ 불가능 — a, b가 아직 없다
template <class T, class U>
decltype(a + b) add(T a, U b);
// error: 'a' was not declared
✔ 후행 반환 타입
template <class T, class U>
auto add(T a, U b) -> decltype(a + b);
// 매개변수 선언 이후라 참조 가능
미리보기 — C++14부터는 -> 없이 auto add(T a, U b)만으로 본문에서 반환 타입을 추론합니다(12장). C++11에서 이 문법은 그 징검다리였고, 지금도 람다의 반환 타입 표기에 그대로 쓰입니다.

범위 기반 for C++11

#include <iostream>
#include <vector>

int main() {
    std::vector<int> v = {1, 2, 3, 4};

    for (int x : v)            // 값 복사
        std::cout << x;        // 1234
    for (int& x : v)           // 참조 — 원본 수정
        x *= 10;
    for (const auto& x : v)    // 읽기 전용 참조 (관용구)
        std::cout << x << " "; // 10 20 30 40
}

컴파일러는 이것을 begin(v)/​end(v)를 쓰는 일반 for문으로 펼칩니다. 그래서 배열, 모든 표준 컨테이너, begin/​end를 제공하는 어떤 타입에도 동작합니다.

순회 중 원본 변경 금지 — 펼쳐진 코드가 end()를 한 번만 계산하므로, 순회 중 push_back으로 재할당이 일어나면 미정의 동작입니다.

내 타입도 range-for에 태우기 C++11

#include <iostream>

struct Range {                       // [lo, hi) 정수 구간
    int lo, hi;
    struct It {
        int v;
        int operator*() const { return v; }
        It& operator++() { ++v; return *this; }
        bool operator!=(It o) const { return v != o.v; }
    };
    It begin() const { return It{lo}; }
    It end()   const { return It{hi}; }
};

int main() {
    for (int i : Range{1, 5})
        std::cout << i << " ";      // 1 2 3 4
    std::cout << "\n";
}
필요한 것은 셋뿐 — operator*, operator++, operator!=. 이 관례가 훗날 C++20 레인지 라이브러리(21장)의 토대가 됩니다.

초기화의 통일 C++11

중괄호 하나로 — 그리고 그 대가로 생긴 새로운 규칙들

중괄호 초기화 C++11

C++98에서는 초기화 문법이 대상마다 달랐습니다. C++11은 중괄호 {} 하나로 통일했습니다.

#include <map>
#include <string>
#include <vector>

struct Point { int x, y; };

int    n{42};
int    arr[]{1, 2, 3};
Point  p{10, 20};                       // 집합체 초기화
std::vector<int> v{1, 2, 3};            // 컨테이너에 원소 나열!
std::map<std::string, int> m{
    {"one", 1}, {"two", 2},
};
std::string* s = new std::string{"hi"}; // new 와도 결합
C++98에서 불가능했던 것 — 컨테이너를 원소 나열로 초기화하는 일. push_back을 반복하거나 배열을 만들어 복사해야 했습니다.

std::initializer_list C++11

중괄호 원소 나열을 받아주는 실체가 이 타입입니다. 내 클래스도 받을 수 있습니다.

#include <initializer_list>
#include <iostream>
#include <vector>

class IntBag {
    std::vector<int> data_;
public:
    IntBag(std::initializer_list<int> init)   // {1,2,3} 이 여기로
        : data_(init) {}
    std::size_t size() const { return data_.size(); }
};

int main() {
    IntBag bag = {1, 2, 3, 4};
    std::cout << bag.size() << "\n";   // 4
}
정체 — 컴파일러가 만든 임시 const 배열을 가리키는 가벼운 뷰(포인터+길이)입니다. 복사해도 배열은 복사되지 않고, 원소는 항상 읽기 전용입니다.

축소 변환 금지 C++11

중괄호 초기화의 두 번째 선물 — 정보를 잃는 변환은 컴파일 오류가 됩니다.

✘ () 와 = 는 조용히 자른다
int a = 3.7;    // a == 3, 경고뿐
char c(300);    // 오버플로, 통과
✔ {} 는 거부한다
int a{3.7};   // error: narrowing
char c{300};  // error: narrowing
int b{3};     // OK — 손실 없음
error: narrowing conversion of '3.7e+0' from 'double' to 'int' [-Wnarrowing]
실전 규칙 — 새 코드의 기본 초기화는 {}. 손실이 정말 의도라면 static_cast로 명시해 읽는 사람에게 알립니다.

중괄호의 함정 두 가지 C++11

함정 1 — initializer_list 생성자는 다른 생성자보다 우선합니다.

std::vector<int> a(10, 7);   // 원소 10개, 모두 7        → 크기 10
std::vector<int> b{10, 7};   // 원소 {10, 7} 두 개!       → 크기 2

함정 2 — auto와 만나면 initializer_list로 추론됩니다.

auto x = {1};    // std::initializer_list<int> — int가 아니다!
auto y{2};       // C++11/14: initializer_list, C++17부터: int
규칙이 표준 중간에 바뀐 유일한 지점 — auto y{2}의 의미가 C++17에서 int로 정정됐습니다(N3922). 그만큼 혼란이 컸다는 뜻입니다. auto와 중괄호는 함께 쓰지 않는 것이 안전합니다.

멤버 기본값 초기화 C++11

멤버 선언 자리에서 바로 기본값을 줍니다(NSDMI). 생성자가 여러 개여도 기본값은 한 곳에.

✘ C++98 — 생성자마다 반복
class Widget {
    int w, h; bool visible;
public:
    Widget() : w(100), h(50),
               visible(true) {}
    Widget(int w_) : w(w_), h(50),
               visible(true) {}
};
✔ C++11 — 선언에서 한 번
class Widget {
    int  w = 100;
    int  h = 50;
    bool visible = true;
public:
    Widget() = default;
    Widget(int w_) : w(w_) {}  // h, visible은 기본값
};
우선순위 — 생성자 초기화 목록이 있으면 그쪽이 이깁니다. 기본값은 "아무도 말하지 않았을 때"만 적용됩니다.

nullptr C++11

NULL은 사실 정수 0이었습니다. 그래서 오버로드가 엉뚱한 곳으로 갔습니다.

#include <iostream>

void take(int)   { std::cout << "int\n"; }
void take(char*) { std::cout << "char*\n"; }

int main() {
    take(0);         // "int" — 포인터를 준다고 생각했는데!
    // take(NULL);   // GCC: 모호성 "컴파일 오류" (NULL이 __null이라서)
                     // NULL이 0L인 구현에서는 조용히 int 오버로드로
    take(nullptr);   // "char*" — 항상 포인터 오버로드
}
  • nullptr의 타입은 std::nullptr_t — 모든 포인터 타입으로 변환되지만 정수로는 변환되지 않습니다.
  • 템플릿 인자 추론에서도 NULL은 int로, nullptr은 nullptr_t로 잡혀 의도가 보존됩니다.
규칙 — C++11 이후 코드에서 NULL과 0을 포인터로 쓰지 않습니다. 검색·치환이 가장 쉬운 현대화 작업이기도 합니다.

enum class C++11

기존 enum의 세 가지 문제 — 이름이 바깥으로 새고, 정수로 몰래 변환되고, 크기가 불명확 — 를 한 번에 해결합니다.

enum class Color : std::uint8_t { Red, Green, Blue };

이동 생성자 만들기 C++11

#include <algorithm>
#include <cstddef>
#include <utility>

class Buffer {
    char*       data_;
    std::size_t size_;
public:
    explicit Buffer(std::size_t n)
        : data_(new char[n]), size_(n) {}
    ~Buffer() { delete[] data_; }

    Buffer(const Buffer& o)                 // 복사: 새로 할당
        : data_(new char[o.size_]), size_(o.size_) {
        std::copy(o.data_, o.data_ + size_, data_);
    }
    Buffer(Buffer&& o) noexcept             // 이동: 포인터만 인수
        : data_(o.data_), size_(o.size_) {
        o.data_ = nullptr;                  // 원본을 비워 둔다
        o.size_ = 0;
    }
    Buffer& operator=(Buffer&& o) noexcept {
        if (this != &o) {
            delete[] data_;
            data_ = o.data_;  o.data_ = nullptr;
            size_ = o.size_;  o.size_ = 0;
            // C++14부터는 data_ = std::exchange(o.data_, nullptr); 로 한 줄 (14장)
        }
        return *this;
    }
};
noexcept가 성능 스위치 — vector는 재할당 때 이동 생성자가 noexcept일 때만 이동을 씁니다. 아니면 강한 예외 보장을 위해 복사로 후퇴합니다. 이동 연산에는 반드시 noexcept를 붙이세요.

완벽 전달 — 받은 그대로 넘기기 C++11

템플릿에서 T&&는 rvalue 참조가 아니라 전달 참조(forwarding reference) — lvalue든 rvalue든 다 받습니다.

#include <iostream>
#include <utility>

void sink(const std::string&) { std::cout << "copy\n"; }
void sink(std::string&&)      { std::cout << "move\n"; }

template <class T>
void relay(T&& arg) {                 // 전달 참조
    sink(std::forward<T>(arg));       // 받은 값 범주 그대로 전달
}

int main() {
    std::string s = "x";
    relay(s);                 // copy — lvalue는 lvalue로
    relay(std::string("t"));  // move — rvalue는 rvalue로
}
참조 붕괴 규칙 — T&&에 lvalue가 오면 T=string&이 되어 string& && → string&로 접힙니다. std::forward<T>는 이 정보를 되살리는 조건부 move입니다. emplace_back·​make_unique가 전부 이 원리 위에 서 있습니다.
구별법 — &&가 추론되는 T·​auto에 붙으면 전달 참조, 구체 타입(string&&)에 붙으면 진짜 rvalue 참조입니다.

    return std::unique_ptr<Widget>(new Widget);  // 반환 = 소유권 넘김
}

void consume(std::unique_ptr<Widget> w);         // 값 매개변수 = 인수

int main() {
    auto a = make_widget();       // 공장에서 받는다
    // auto b = a;                // error: 복사 금지
    auto b = std::move(a);        // 명시적 이동 — a는 nullptr
    consume(std::move(b));        // 넘겨준다 — b는 nullptr

weak_ptr — 순환을 끊는 관찰자 C++11

#include <iostream>
#include <memory>

struct Child;
struct Parent {
    std::shared_ptr<Child> child;
    ~Parent() { std::cout << "~Parent\n"; }
};
struct Child {
    std::weak_ptr<Parent> parent;   // shared_ptr이면 순환 → 영원한 누수
    ~Child() { std::cout << "~Child\n"; }
};

int main() {
    auto p = std::make_shared<Parent>();
    p->child = std::make_shared<Child>();
    p->child->parent = p;            // 약한 참조 — 계수를 올리지 않음

    if (auto sp = p->child->parent.lock())   // 사용할 땐 승격
        std::cout << "parent alive\n";
}   // parent alive / ~Parent / ~Child — 정상 파괴
lock()이 유일한 문 — weak_ptr은 역참조가 불가능합니다. lock()으로 shared_ptr을 얻어야 하며, 대상이 이미 죽었으면 빈 포인터가 옵니다. "있으면 쓰고 없으면 만다"가 자연스럽게 코드가 됩니다.

클래스의 새 문법 C++11

default · delete · override · final — 의도를 컴파일러에게 말하다

= default 와 = delete C++11

class Connection {
public:
    Connection() = default;              // "기본 생성자를 유지하라"

    Connection(const Connection&) = delete;             // 복사 금지
    Connection& operator=(const Connection&) = delete;

    Connection(Connection&&) noexcept = default;        // 이동은 허용
    Connection& operator=(Connection&&) noexcept = default;
};
  • = default — 다른 생성자를 정의해도 기본 생성자를 공짜 구현 그대로 되살립니다. 빈 몸통 {}보다 명확하고, 트리비얼 타입 자격도 유지합니다.
  • = delete — 그 함수를 선택하면 컴파일 오류. C++98의 "private으로 선언만 하고 정의 안 하기" 꼼수를 대체합니다.
delete는 멤버 전용이 아닙니다 — void f(double) = delete;를 두면 f(3.14)의 암묵 변환 호출을 막는 오버로드 차단기로도 씁니다.

override 와 final C++11

가상 함수 재정의는 시그니처가 한 글자만 달라도 조용히 새 함수가 됩니다. C++98의 유서 깊은 버그입니다.

struct Base {
    virtual void draw(int scale) const;
    virtual ~Base() = default;
};

struct Bad : Base {
    void draw(int scale);          // const 빠짐 — 재정의 아님! 조용히 통과
};

struct Good : Base {
    void draw(int scale) const override;   // 재정의 못 하면 컴파일 오류
};

struct Sealed final : Good {                  // 더는 상속 금지
    void draw(int scale) const final;         // 더는 재정의 금지
};
error: 'void Bad::draw(int)' marked 'override', but does not override
규칙 — 재정의하는 모든 가상 함수에 override. 비용은 0이고, 시그니처 불일치·부모 시그니처 변경을 전부 컴파일 오류로 바꿔 줍니다.

explicit 변환 연산자 C++11

C++98에서는 operator bool()을 정의하면 stream + 1 같은 엉뚱한 산술까지 허용됐습니다.

class Handle {
    int fd_ = -1;
public:
    explicit operator bool() const { return fd_ >= 0; }
};

Handle h;
if (h) { /* OK — 조건문은 "문맥상 bool 변환"이라 explicit여도 동작 */ }
// int n = h;        // error: 암묵 변환 금지
// bool b = h;       // error: 마찬가지
bool b = static_cast<bool>(h);   // 명시하면 허용

void relocate(T& a, T& b)
    noexcept(std::is_nothrow_move_constructible<T>::value);

constexpr — 컴파일 타임 함수 C++11

가변 인자 템플릿 C++11

타입을 몇 개든 받는 템플릿. C++98은 인자 수마다 오버로드를 복사해 붙였습니다(부스트에는 10개짜리가 흔했습니다).

#include <iostream>

void print() { std::cout << "\n"; }          // 재귀 종료

template <class First, class... Rest>         // Rest = 타입 팩
void print(First f, Rest... rest) {           // rest = 값 팩
    std::cout << f << " (남은 " << sizeof...(rest) << "개) ";
    print(rest...);                           // 팩 펼치기 — 하나 줄여 재귀
}

int main() {
    print(1, 2.5, "three");
    // 1 (남은 2개) 2.5 (남은 1개) three (남은 0개)
}
동작 원리 — print(1, 2.5, "three", 'x')는 First를 하나씩 벗기며 4단계 재귀로 펼쳐집니다. 각 단계가 다른 타입의 다른 함수로 인스턴스화됩니다.
미리보기 — 이 재귀 관용구는 C++17 접기 식(16장)으로 한 줄이 됩니다: ((std::cout << args << " "), ...)

가변 인자 + 완벽 전달 = emplace C++11

5장과 9장이 만나는 곳 — 표준 라이브러리의 핵심 패턴입니다.

#include <memory>
#include <utility>
#include <vector>

// make_unique의 원리 (C++14 표준 채택 전, C++11로 직접 구현)
template <class T, class... Args>
std::unique_ptr<T> make_unique_11(Args&&... args) {
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}

struct Point { int x, y; Point(int x_, int y_) : x(x_), y(y_) {} };

int main() {
    auto p = make_unique_11<Point>(3, 4);   // 인자를 그대로 T 생성자로

    std::vector<Point> v;
    v.emplace_back(1, 2);   // push_back(Point(1,2))와 달리
                            // 임시 없이 벡터 안에서 "직접 생성"
}
읽는 법 — Args&&...(전달 참조 팩)로 무엇이든 받아 std::forward<Args>(args)...로 값 범주를 보존한 채 넘깁니다. emplace_back·​make_shared·​thread 생성자가 전부 이 모양입니다.

SFINAE와 enable_if — 콘셉트 이전의 삶 C++11

"치환 실패는 오류가 아니다" — 템플릿 인자 치환이 실패하면 그 후보를 조용히 오버로드에서 제외하는 규칙을 이용해, 타입 조건별로 함수를 골라 태웁니다.

#include <iostream>
#include <type_traits>

template <class T,
          typename std::enable_if<std::is_integral<T>::value, int>::type = 0>
void describe(T) { std::cout << "integer\n"; }

template <class T,
          typename std::enable_if<std::is_floating_point<T>::value, int>::type = 0>
void describe(T) { std::cout << "float\n"; }

int main() {
    describe(42);     // integer
    describe(3.14);   // float
    // describe("x"); // error: 어느 오버로드도 남지 않음
}
읽기 어려운 게 정상입니다 — 이 문법의 난해함이야말로 C++20 콘셉트(20장)가 태어난 이유입니다. 새 코드가 C++20을 쓸 수 있다면 requires로 쓰세요. 다만 기존 코드베이스를 읽으려면 이 패턴을 알아봐야 합니다.

std::thread C++11

#include <iostream>
#include <thread>
#include <vector>

void worker(int id, int& out) {
    out = id * 10;
}

int main() {
    std::vector<int> results(4);
    std::vector<std::thread> pool;

    for (int i = 0; i < 4; ++i)
        pool.emplace_back(worker, i, std::ref(results[i]));
        // 인자는 "복사"가 기본 — 참조는 std::ref로 명시

    for (auto& t : pool) t.join();       // 반드시 join (또는 detach)

    for (int r : results) std::cout << r << " ";   // 0 10 20 30
}

atomic — 잠금 없는 공유 C++11

#include <atomic>
#include <iostream>
#include <thread>

std::atomic<bool> done{false};

    std::thread t([] {
        for (int i = 0; i < 100000; ++i)
            hits.fetch_add(1, std::memory_order_relaxed);
        done.store(true);                  // 기본: 순차 일관성
    });
    while (!done.load()) { /* spin */ }
    t.join();
    std::cout << hits.load() << "\n";      // 100000
}

#include <memory>
#include <utility>

if constexpr — 컴파일 타임 분기 C++17

조건이 거짓인 가지를 아예 인스턴스화하지 않습니다. 일반 if는 양쪽 다 컴파일되어야 하므로 템플릿에서는 불가능했던 코드가 됩니다.

#include <iostream>
#include <string>
#include <type_traits>

template <class T>
std::string stringify(const T& v) {
    if constexpr (std::is_same_v<T, std::string>)
        return v;                        // string이면 그대로
    else if constexpr (std::is_arithmetic_v<T>)
        return std::to_string(v);        // 숫자면 to_string
    else
        return v.to_string();            // 아니면 멤버에 위임
        // ← 일반 if라면 int에 .to_string()이 없어 "전체"가 컴파일 오류
}

int main() {
    std::cout << stringify(42) << " "
              << stringify(std::string("hi")) << "\n";   // 42 hi
}
무엇을 은퇴시켰나 — 9장의 enable_if 오버로드 더미와 태그 디스패치의 대부분. 조건별 코드가 한 함수 안에 순서대로 놓입니다.

    // 생성되지 않는다
}

접기 식 (fold expressions) C++17

template <class... Ts>
bool all(Ts... xs) { return (xs && ...); }       // 빈 팩이면 true

template <class... Ts>
void print(Ts... xs) {
    ((std::cout << xs << " "), ...);             // 쉼표 접기 — 순서대로 출력
    std::cout << "\n";
}

int main() {
    std::cout << sum(1, 2, 3, 4) << "\n";  // 10
    std::cout << all(true, 1, 2) << "\n";  // 1

}

보장된 복사 생략 C++17

임시(prvalue)로 초기화할 때 복사/이동이 선택 사항이 아니라 언어 규칙으로 없습니다.

#include <iostream>

struct Heavy {
    Heavy() { std::cout << "ctor\n"; }

    Heavy(Heavy&&) = delete;           // 이동조차 금지!
};

Heavy make() { return Heavy{}; }       // C++14: 이동 생성자 필요 → 오류

int main() {
    Heavy h = make();                  // 출력: ctor — 딱 한 번
}

평가 순서의 확정 C++17

C++14까지 한 식 안의 부분식 평가 순서는 대부분 미지정이었습니다.

std::map<int, int> m;
m[0] = m.size();     // C++14: 0일 수도 1일 수도 (컴파일러 마음)
                     // C++17: 우변 먼저 → m[0] = 0 확정

std::cout << f() << g();   // C++17: f가 먼저 "출력"됨은 원래 보장,
                           // 이제 f() 평가가 g()보다 먼저임도 보장

f(unique_ptr<T>(new T), g());   // C++14: new → g() 예외 → 누수 가능
                                // C++17: 인자 하나가 "끝난 뒤" 다음 인자
  • 확정된 것: 대입의 우변 먼저, a.b·​a->b·​a[b]·시프트·<< 체인은 왼쪽 먼저, 함수 인자끼리는 순서 미지정이되 겹침(interleaving) 금지.
  • 6장 make_shared 슬라이드의 예외 안전 문제가 언어 차원에서 봉인된 지점입니다.
여전히 f(i++, i++)처럼 인자 간 순서에 의존하는 코드는 이식성이 없습니다. 규칙이 좋아졌다고 곡예가 허용된 것은 아닙니다.

visit — variant를 분기하는 정석 C++17

#include <iostream>
#include <string>
#include <variant>

struct Circle { double r; };
struct Rect   { double w, h; };
using Shape = std::variant<Circle, Rect>;

// 람다 여러 개를 겹쳐 오버로드 집합 만들기 — 표준 관용구
template <class... Ts> struct overloaded : Ts... { using Ts::operator()...; };
template <class... Ts> overloaded(Ts...) -> overloaded<Ts...>;  // CTAD 지침

int main() {
    Shape s = Circle{2.0};
    double a = std::visit(overloaded{
        [](const Circle& c) { return 3.14159 * c.r * c.r; },
        [](const Rect& r)   { return r.w * r.h; },
    }, s);
    std::cout << a << "\n";   // 12.566…
}

제너레이터 직접 만들기 ① — 뼈대 C++20

C++20은 언어 장치만 주고 그릇(반환 타입)은 직접 만들게 했습니다. 최소 구현은 이렇습니다.

#include <coroutine>
#include <exception>

template <class T>
struct Gen {
    struct promise_type {                       // ← 이름 고정: 규약이다
        T value;
        Gen  get_return_object() {              // 호출자가 받을 그릇
            return Gen{std::coroutine_handle<promise_type>::from_promise(*this)};
        }
        std::suspend_always initial_suspend() { return {}; }  // 시작부터 일시정지
        std::suspend_always final_suspend() noexcept { return {}; }
        std::suspend_always yield_value(T v) {  // co_yield가 여기로 온다
            value = v; return {};
        }
        void return_void() {}
        void unhandled_exception() { std::terminate(); }
    };

    std::coroutine_handle<promise_type> h;
    explicit Gen(std::coroutine_handle<promise_type> h) : h(h) {}
    Gen(const Gen&) = delete;                   // 핸들 이중 파괴 방지
    ~Gen() { if (h) h.destroy(); }

    bool next()  { h.resume(); return !h.done(); }   // 다음 yield까지 실행
    T    value() const { return h.promise().value; }
};
promise_type은 코루틴과 바깥세상의 교환대입니다 — 언제 멈출지(initial/final_suspend), yield된 값을 어디 둘지, 예외를 어찌할지를 전부 이 타입이 결정합니다.

명시적 객체 매개변수 C++23

멤버 함수의 숨은 인자였던 this를 첫 매개변수로 직접 선언합니다.

struct Counter {
    int n = 0;

    // 기존 문법 — this는 암묵
    void up_old() { ++n; }

    // C++23 — "this Self self"가 객체 자신
    void up(this Counter& self) { ++self.n; }

    // 진가: 템플릿과 결합 — 객체의 "실제 타입·값 범주"가 추론된다
    template <class Self>
    void show(this Self&& self) {
        std::println("{}", self.n);
    }
};

Counter c;
c.up();        // self = c (Counter&)
c.show();      // Self = Counter&
Counter{}.show();   // Self = Counter — 임시로 불러도 구별된다
규칙 — 명시적 객체 매개변수는 반드시 첫 번째이고 이름은 관례상 self. 이런 함수 안에서 암묵 this·암묵 멤버 접근은 금지됩니다(self.n처럼 명시).

struct Node { int value; Node *left = nullptr, *right = nullptr; };

std::generator<int> in_order(const Node* n) {

    co_yield std::ranges::elements_of(in_order(n->left));   // 하위 트리 통째로 위임
    co_yield n->value;
    co_yield std::ranges::elements_of(in_order(n->right));
}

    for (int v : in_order(&root)) std::print("{} ", v);   // 1 2 3

// dextents<I, 2> = "동적 크기 2차원"의 지름길 표기

void matmul(Mat a, Mat b, Mat out) {
    for (std::size_t i = 0; i < out.extent(0); ++i)
        for (std::size_t j = 0; j < out.extent(1); ++j) {
            double s = 0;
            for (std::size_t k = 0; k < a.extent(1); ++k)
                s += a[i, k] * b[k, j];
            out[i, j] = s;
        }
}

    matmul(Mat(A.data(), 2, 2), Mat(B.data(), 2, 2), Mat(C.data(), 2, 2));
    std::println("{} {} {} {}", C[0], C[1], C[2], C[3]);   // 19 22 43 50
}

#include <string_view>

struct Level { std::string_view name; int value; };

constexpr std::array<Level, 3> parse_levels(std::string_view src) {
    std::array<Level, 3> out{};
    std::size_t i = 0;
    for (auto part : std::views::split(src, ';')) {         // 뷰도 constexpr!

        std::from_chars(num.data(), num.data() + num.size(), out[i].value);
        ++i;
    }
    return out;
}

종합 실습 ① — 1998년의 단어 빈도 세기

같은 프로그램을 두 시대의 문법으로 — 25년의 거리를 한눈에 봅니다.

// C++98: 표준 입력의 단어를 세어 빈도 내림차순 출력
#include <iostream>
#include <map>
#include <string>
#include <vector>
#include <algorithm>

bool by_count(const std::pair<std::string, int>& a,
              const std::pair<std::string, int>& b) {
    return a.second > b.second;
}

int main() {
    std::map<std::string, int> freq;
    std::string w;
    while (std::cin >> w) freq[w]++;

    std::vector<std::pair<std::string, int> > v(freq.begin(), freq.end());
    std::sort(v.begin(), v.end(), by_count);

    for (std::vector<std::pair<std::string, int> >::const_iterator
             it = v.begin(); it != v.end(); ++it)
        std::cout << it->first << ": " << it->second << "\n";
    return 0;
}
비교 함수는 쓰는 곳에서 멀리, 이터레이터 타입은 한 줄을 차지하고, > > 사이의 공백마저 문법이었습니다(C++11에서야 >> 허용).

종합 실습 ② — 2023년의 같은 프로그램

// C++23: 동일 동작
import std;

int main() {
    std::unordered_map<std::string, int> freq;               // 10장
    for (std::string w; std::cin >> w; )
        ++freq[w];

    auto v = freq | std::ranges::to<std::vector>();          // 32장
    std::ranges::sort(v, std::ranges::greater{},
                      &std::pair<const std::string, int>::second);  // 21장 프로젝션

    for (const auto& [word, count] : v)                      // 15장
        std::println("{}: {}", word, count);                 // 29장
}
  • 줄 수 절반 이하 — 그러나 진짜 이득은 줄 수가 아니라, 모든 줄이 의도를 말한다는 점입니다.
  • 덤으로 더 빠릅니다: 해시 맵(10장), 이동 기반 벡터 구축, print(29장).
이 두 슬라이드 사이에 이 덱의 42개 장이 놓여 있습니다.

부록 — 이 덱이 다루지 않은 것

  • ABI·바이너리 호환 — 표준이 침묵하는 영역이지만 실무 이주의 절반은 여기서 발목이 잡힙니다(std::string의 GCC dual ABI 등).
  • 프리스탠딩(freestanding) C++ — OS 없는 환경용 부분집합 규격. C++23에서 크게 정비됐지만 임베디드 독자용 별도 주제입니다.
  • Transactional Memory·Reflection TS 등 본선에 오르지 못한 실험들.
  • 컴파일러 확장 — __attribute__, #pragma, 인트린식. 표준의 국경 밖.
  • C++/CLI·Objective-C++ 같은 방언들.
이 덱은 ISO 표준의 변화만을 궤도로 삼았습니다 — 위 주제들은 각자 별도의 덱 하나 분량입니다.

끝 — 그리고 계속

  • C++14 그 언어를 다듬었다
  • C++17 일상의 어휘를 채웠다
  • C++20 추상의 지평을 넓혔다 — 4대 기능
  • C++23 그 모든 것에 손잡이를 달았다 — 완성판
