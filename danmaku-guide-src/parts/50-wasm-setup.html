작은 모듈을 직접 컴파일하고 네이티브·Node·오프라인 브라우저에서 같은 계산을 확인합니다.

도구와 실행 명령

g++는 네이티브 검사를, clang++와 wasm-ld는 wasm 생성을 맡습니다. 가이드 소스 디렉터리에서 명령을 실행하며 경로는 NATIVE_CXX·WASM_CXX·WASM_LD로 지정할 수 있습니다.

cpp-wasm/commands.sh

프리스탠딩 C++

설치 예제는 표준 라이브러리 없이 숫자를 계산합니다. 예외와 RTTI를 끄고 double 크기를 검사합니다. 이후 게임 상태도 명시적으로 초기화하는 방향으로 확장합니다.

cpp-wasm/setup.cpp

C ABI와 내보내기

extern C로 C++ 이름 장식을 피합니다. wasm 빌드에서 export_name으로 JS가 호출할 이름을 정하고 ABI 버전 함수로 로더와 모듈의 약속을 확인합니다.

cpp-wasm/setup.cpp

같은 소스의 네이티브 검사

같은 계산 소스를 g++로 실행해 먼저 확인합니다. 부동소수 연산의 융합을 막는 옵션을 두 빌드에 적용하여 앞으로 기준 기록과 비교할 때 계산 순서를 유지합니다.

cpp-wasm/build.mjs

wasm 오브젝트와 링크

clang++는 wasm32 오브젝트를 만들고 wasm-ld가 모듈로 연결합니다. no-entry는 main 진입점을 요구하지 않는다는 뜻이며 JS는 내보낸 함수를 직접 호출합니다.

Node에서 실제 실행

생성한 바이트를 인스턴스화하고 ABI 버전과 계산 결과를 확인합니다. 외부 가져오기가 없는 작은 모듈이므로 빈 객체를 전달하며 실행 실패는 빌드 실패로 처리합니다.

한 스텝의 위치 계산

속도는 초당 속도가 아닌 고정 스텝당 변위입니다. 위치 240과 변위 4를 전달하면 244를 돌려줍니다. 설치 예제에는 아직 플레이어 경계나 충돌 처리가 없습니다.

JS에서 wasm 불러오기

내장한 base64를 바이트 배열로 되돌린 뒤 인스턴스화를 기다립니다. ABI 버전이 다르면 호출을 계속하지 않고 오류를 냅니다. 반환한 exports로 C ABI 함수를 호출합니다.

오프라인 파일 만들기

빌드할 때 wasm과 로더를 한 HTML에 넣습니다. dist/wasm-setup.html을 직접 열면 서버나 CDN 없이 실행됩니다. 네트워크를 끈 Chromium에서도 실제 계산 결과를 검사합니다.

cpp-wasm/build.mjs

로딩 실패를 화면에 표시

정상 실행은 ABI 1과 계산 결과를 표시합니다. 바이트가 손상되거나 ABI 검사가 실패하면 오류를 화면에 남깁니다. 자동 검사는 손상된 바이트를 넣어 실패 표시까지 확인합니다.

설치와 첫 실행 · 이해 확인

no-entry로 링크한 모듈은 JS에서 사용할 수 없을까요?

시작용 main이 필요 없다는 뜻입니다. 인스턴스화를 기다린 뒤 내보낸 dm_abi_version과 dm_advance 함수를 JS에서 직접 호출할 수 있습니다.
