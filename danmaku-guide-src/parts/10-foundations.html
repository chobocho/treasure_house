벡터와 회전수

벡터와 회전수의 기준과 경계 조건을 익히고, 네 가지 구현에서 같은 뜻으로 사용할 약속을 확인합니다.

화면 좌표의 원점

논리 화면의 왼쪽 위를 원점으로 정합니다. 오른쪽이 양의 x 방향이고 아래쪽이 양의 y 방향이므로 위로 쏘는 탄환의 y 속도는 음수입니다.

위치와 변위

위치는 물체가 있는 곳이고 변위는 위치가 바뀐 양입니다. 같은 변위라도 출발 위치가 다르면 도착 위치도 달라지므로 두 역할을 혼동하지 않습니다.

위치(100, 200)
변위(4, -2)
다음 위치(104, 198)

그림: 화면 좌표와 변위

화면 좌표는 왼쪽 위가 원점이고 y가 커질수록 아래로 내려갑니다. 위치에 변위를 더하면 다음 위치가 되며, 수학 교과서의 좌표와 y축 방향이 반대라는 점을 먼저 기억합니다.

다음 위치 = 위치 + 변위
(100, 200) + (4, −2) = (104, 198)

스텝당 속도

이 가이드의 속도는 한 논리 스텝 동안 이동하는 픽셀 수입니다. 초당 속도를 사용할 때는 고정 스텝의 길이를 곱해야 단위가 맞습니다.

벡터 더하기

탄환의 다음 위치는 현재 위치에 속도 성분을 각각 더해 구합니다. x와 y를 같은 스텝에 갱신하면 방향이 다른 탄환도 같은 루프로 움직일 수 있습니다.

방향 벡터 만들기

목표 위치에서 출발 위치를 빼면 목표를 향하는 벡터를 얻습니다. 목표와 출발점이 같을 때는 방향을 정할 수 없으므로 별도 규칙이 필요합니다.

벡터 길이

두 성분의 제곱을 더한 뒤 제곱근을 취하면 벡터의 길이입니다. 성분이 3과 4인 벡터의 길이는 5이므로 정규화 결과는 0.6과 0.8입니다.

foundations/core.mjs

공식: 벡터 길이와 정규화

x와 y 성분을 직각삼각형의 두 변으로 보면 벡터 길이는 빗변입니다. 길이로 각 성분을 나누면 방향은 그대로이고 길이만 1인 단위 벡터가 됩니다.

|v| = √(x² + y²)
u = v / |v| (|v| = 0이면 (0, 0))

영벡터 정규화

길이가 0인 벡터를 나누면 유효한 방향을 얻을 수 없습니다. 일반 이동은 정지 벡터를 반환하고 조준 발사는 아래 방향처럼 명시한 대체 방향을 사용합니다.

foundations/core.mjs

대각선 이동 정규화

가로와 세로 입력을 각각 같은 속도로 더하면 대각선이 더 빨라집니다. 두 성분의 길이를 1로 맞춘 다음 이동 속도를 곱해 모든 방향의 속도 크기를 맞춥니다.

foundations/core.mjs

그림: 대각선이 빨라지는 이유

두 방향 키를 함께 누르면 입력 벡터 (1, −1)의 길이가 √2입니다. 그대로 속도를 곱하면 대각선만 약 1.414배 빨라지므로 먼저 정규화한 뒤 속도를 곱합니다.

|(1, −1)| = √2 ≈ 1.414
4 × (1, −1) / √2 = (2.828, −2.828)

길이·정규화·대각선 보정·영벡터 처리를 실제 함수로 계산한 출력입니다. 슬라이드에 적은 숫자는 이 실행 결과와 같습니다.

집중 이동 배율

입력 방향은 유지하면서 이동 크기를 4에서 1.6으로 바꿉니다. 방향 계산과 속도 선택을 분리하면 집중 이동이 탄환 패턴이나 충돌 계산을 바꾸지 않습니다.

라디안과 회전수

한 바퀴를 1로 나타내면 반 바퀴는 0.5, 사분의 일은 0.25입니다. 다항식 계산에 필요한 라디안으로 바꿀 때만 한 바퀴에 해당하는 상수를 곱합니다.

그림: 회전수와 라디안

이 덱은 한 바퀴를 1로 보는 회전수로 각도를 다룹니다. 라디안은 회전수에 2π를 곱한 값이고, 화면 y축이 아래라서 각도가 늘면 시계 방향으로 돕니다.

θ = 2π × t, t = θ / 2π
0.25바퀴 = π/2 = 화면 아래쪽

그림: 단위원의 사인과 코사인

반지름 1인 원 위의 점은 (cos θ, sin θ)입니다. 이 점에 탄속을 곱하면 어느 방향이든 같은 빠르기의 속도 벡터가 됩니다.

v = 탄속 × (cos θ, sin θ)
cos² θ + sin² θ = 1

한 바퀴의 나머지

회전수에서 내림한 정수를 빼면 결과는 0 이상 1 미만입니다. 음수 입력에도 같은 규칙을 적용하므로 음수 나머지 연산의 언어 차이를 피할 수 있습니다.

사분면 접기

사인의 대칭성을 이용하면 한 바퀴의 각도를 좁은 구간으로 접을 수 있습니다. 사분면마다 다른 삼각함수를 호출하지 않고 같은 다항식에 부호가 반영된 입력을 전달합니다.

foundations/core.mjs

그림: 사분면 접기의 대칭

사인 곡선은 0.25바퀴를 중심으로 좌우 대칭이고 0.75바퀴 뒤로는 한 바퀴 앞과 같습니다. 이 성질로 모든 입력을 −0.25~0.25바퀴로 옮겨 다항식이 정확한 구간에서만 계산하게 합니다.

sin(π − x) = sin x → t′ = 0.5 − t (0.25 < t ≤ 0.75)
sin(x − 2π) = sin x → t′ = t − 1 (t > 0.75)

사분파 다항식

작은 구간에서는 홀수 차수 다항식으로 사인을 근사할 수 있습니다. 입력을 먼저 사분파 구간에 접어야 바깥 각도에서 오차가 커지는 일을 막을 수 있습니다.

foundations/core.mjs

공식: 테일러 다항식

0 근처의 사인은 홀수 차수 항의 합으로 근사합니다. 항을 늘릴수록 곡선에 붙으며, 접은 구간 안에서는 13차까지 일곱 항으로 10억 분의 1 수준의 오차만 남습니다.

sin x ≈ x − x³/3! + x⁵/5! − x⁷/7! + x⁹/9! − x¹¹/11! + x¹³/13!
x = 2π × 접은 회전수

Horner 계산 순서

거듭제곱을 따로 여러 번 계산하지 않고 이전 결과에 제곱 값을 곱해 다음 계수를 더합니다. 같은 계수뿐 아니라 계산 순서도 맞춰야 언어 사이 반올림 차이를 줄일 수 있습니다.

foundations/core.mjs

공식: Horner 전개

z = x²로 두고 안쪽 괄호부터 곱하고 더하면 거듭제곱을 따로 계산하지 않습니다. 계산 순서를 하나로 고정해야 네 언어가 같은 반올림을 거쳐 같은 값을 냅니다.

sin x ≈ x(1 + z(−1/3! + z(1/5! + z(−1/7! + z(1/9! + z(−1/11! + z/13!))))))
z = x²를 구한 뒤 곱셈 7번과 덧셈 6번

실행 예: 회전수와 사인

회전수를 라디안으로 바꾼 값, 접은 회전수와 dsin 결과를 실제로 출력합니다. 0.4바퀴와 0.1바퀴의 사인이 같고 0.9바퀴는 부호만 바뀌는 것을 확인합니다.

코사인은 사인 이동

코사인은 사인에 사분의 일 회전을 더한 값으로 구합니다. 같은 사인 구현을 재사용하면 두 함수를 별도로 관리하다 계수나 경계 처리가 달라지는 일을 막습니다.

foundations/core.mjs

축 방향 속도

각도 0에서 x 속도는 양수이고 y 속도는 0에 가깝습니다. 사분의 일 회전에서는 아래로 향하므로 화면 좌표계의 방향을 먼저 확인합니다.

foundations/core.mjs

링의 각도 간격

탄환 n개를 한 바퀴에 균등 배치하면 각도 간격은 1을 n으로 나눈 값입니다. 마지막 각도를 1까지 포함하면 첫 방향과 겹치므로 인덱스는 n보다 작을 때까지만 사용합니다.

foundations/core.mjs

첫 탄환의 방향

링의 모든 각도에 같은 시작 회전수를 더하면 탄수와 간격을 유지하면서 전체를 회전할 수 있습니다. 다만 링은 1/n바퀴마다 같은 모양이 되므로 링 전체를 가끔 쏘며 시작값만 바꾸면 회전이 대칭에 묻힙니다. 그래서 나선만 짧은 주기로 이어 쏩니다.

foundations/core.mjs

그림: 링의 각도

링은 한 바퀴를 n등분한 방향으로 동시에 쏩니다. 모든 방향에 같은 시작 회전수를 더하면 모양은 그대로 두고 전체만 돌릴 수 있습니다.

θᵢ = t₀ + i / n (i = 0, 1, …, n − 1)

조준 벡터

조준에는 목표와 발사점 사이의 차이와 길이만 있으면 됩니다. 각도를 역삼각함수로 구했다 다시 방향으로 바꾸는 대신 정규화한 벡터를 그대로 사용합니다.

foundations/core.mjs

부채꼴의 기준 방향

부채꼴의 가운데 방향은 목표를 향하는 벡터입니다. 가운데 인덱스를 기준으로 양쪽에 같은 회전 간격을 더해 좌우 대칭으로 쏩니다. 탄수가 많으면 전체 폭이 반 바퀴를 넘어 겹치지 않도록 간격을 줄입니다.

foundations/core.mjs

그림: 부채꼴 간격과 상한

부채꼴은 목표 방향을 가운데에 두고 좌우로 같은 간격을 벌립니다. 탄수가 많으면 간격을 줄여 전체 폭을 반 바퀴 미만으로 묶습니다.

Δ = min(0.025, 0.5 / n)
θᵢ = 목표 방향 + (i − (n − 1) / 2) × Δ

회전 행렬

기준 방향에 작은 회전을 적용하면 부채꼴의 각 탄환 방향을 얻습니다. 두 성분을 함께 계산해야 방향이 회전하면서도 속도 크기를 유지합니다.

foundations/core.mjs

그림: 회전 행렬

벡터 (x, y)를 Δ만큼 돌리면 두 성분이 cos Δ와 sin Δ로 섞입니다. 길이를 바꾸지 않는 변환이라 정규화한 조준 벡터를 돌려도 탄속이 그대로입니다.

x′ = x·cos Δ − y·sin Δ
y′ = x·sin Δ + y·cos Δ

실행 예: 9° 회전

foundations/core.mjs

그림: 나선이 링으로 보이는 이유

n발 링은 1/n바퀴 돌리면 원래 모양과 같습니다. 그래서 보이는 회전은 발사 사이 회전량을 1/n로 나눈 나머지뿐이고, 몇 팔을 짧은 간격으로 이어 쏘아야 소용돌이가 됩니다.

보이는 회전 = (발사 간격 × ω) mod (1/n)
(60 × 0.007) mod (1/8) = 0.045, 6 × 0.007 = 0.042

파동의 주기

논리 틱을 주기 값으로 나눈 회전수를 사용하면 지정한 스텝 수마다 같은 방향으로 돌아옵니다. 주기가 짧을수록 방향이 빠르게 바뀌지만 탄환 자체의 속도는 별도로 정합니다.

그림: 파동 중심의 움직임

파동은 부채꼴 중심을 사인 곡선을 따라 좌우로 옮깁니다. 적이 60스텝마다 쏘면 주기 180스텝 동안 중심이 세 위치를 돌며 흔들립니다.

θᵢ(t) = 0.25 + 0.12 × sin(2π × t / 180) + (i − (n − 1) / 2) × 0.025

그림: 위상에 탄환 번호를 넣으면

번호 i를 위상에 더하면 한 번의 발사가 사인 한 주기를 모두 찍습니다. 시간이 바뀌어도 같은 호가 나오고 sin a = sin(π − a)인 두 탄환이 같은 방향으로 겹칩니다.

예전: θᵢ = 0.25 + 0.12 × sin(2π(t / 180 + i / n))
지금: 위상은 t / 180만, i는 부채꼴 간격으로

실행 예: 패턴 수치

링·부채꼴 각도, 64발 부채꼴 간격, 나선의 보이는 회전량과 파동 중심을 실제로 계산한 출력입니다. 파동 중심이 0.25를 기준으로 ±0.104만큼 오가는 것을 확인합니다.

foundations/core.mjs

그림: 렌더와 논리 스텝

렌더 간격과 논리 스텝 간격은 서로 다릅니다. 누적기에 실제 경과 시간을 더하고 한 스텝 길이 h가 찰 때마다 갱신하므로 30Hz 화면에서도 1초에 60번 갱신합니다.

누적 += Δt
누적 ≥ h인 동안: 갱신하고 누적 −= h (h = 1/60초)

보간 계수

남은 시간을 한 스텝 길이로 나눈 비율은 이전 상태와 현재 상태 사이를 그릴 때 쓸 수 있습니다. 보간한 위치를 다시 게임 상태에 저장하면 논리 결과가 렌더 빈도에 영향을 받습니다.

공식: 보간

남은 누적 시간을 h로 나눈 α는 0 이상 1 미만입니다. 이전 상태와 현재 상태 사이를 α 비율로 섞어 그리면 갱신 사이의 움직임이 부드러워집니다.

α = 누적 / h
표시 위치 = p₀ + (p₁ − p₀) × α

실행 예: 누적기와 α

30Hz로 1초를 렌더하면 정확히 60스텝, 40Hz로 세 번 렌더하면 네 스텝이 진행됩니다. 함수가 돌려준 남은 비율 α가 보간에 쓰이는 값입니다.

foundations/core.mjs

그림: 원 충돌 공식

두 원은 중심 사이 거리가 반지름 합 이하일 때 겹칩니다. 거리와 반지름 합이 모두 0 이상이라 제곱한 채 비교해도 결과가 같아 제곱근을 계산하지 않습니다.

dx = x₁ − x₂, dy = y₁ − y₂
겹침 ⇔ dx² + dy² ≤ (r₁ + r₂)²

그림: 피격과 그레이즈 구간

같은 적탄을 피격 원과 그레이즈 원에 각각 검사하면 거리가 세 구간으로 나뉩니다. 적탄 반지름 4를 더해 6.5 이하가 피격, 20 이하가 그레이즈입니다.

피격: d ≤ 2.5 + 4 = 6.5
그레이즈: 6.5 < d ≤ 16 + 4 = 20

시드와 상태

시드는 난수 생성기의 출발 상태입니다. 같은 시드에서 같은 횟수로 상태를 진행하면 같은 난수열을 얻지만 호출 순서가 달라지면 이후 게임도 달라집니다.

xorshift32의 세 연산

왼쪽 13비트, 오른쪽 17비트, 왼쪽 5비트 이동을 XOR와 함께 같은 순서로 적용합니다. 한 단계의 결과를 다음 단계의 입력으로 사용해야 정해진 수열을 재현합니다.

foundations/core.mjs

그림: xorshift32의 비트 이동

왼쪽 시프트는 비트를 위로 밀고 32비트를 넘친 비트를 버리며, 오른쪽 시프트는 아래로 밀고 위를 0으로 채웁니다. 원래 값과 배타적 논리합을 하면 비트가 섞입니다.

x ← x ⊕ (x ≪ 13)
x ← x ⊕ (x ≫ 17)
x ← x ⊕ (x ≪ 5) (모두 mod 2³²)

무부호 32비트 변환

JavaScript의 비트 연산은 부호 있는 정수로 동작할 수 있습니다. 각 단계에서 무부호로 되돌리고 Python과 C++에서도 같은 32비트 상태를 유지합니다.

영 시드의 고정점

xorshift32는 상태가 0이면 다음 상태도 0입니다. 테스트는 이 고정점을 드러내고 실제 게임은 공통 사양의 0이 아닌 시드를 사용합니다.

난수 호출 순서

입자 효과가 게임용 난수를 추가로 소비하면 적의 다음 탄막도 달라질 수 있습니다. 장식용 난수와 규칙용 난수의 소비 순서를 분리하거나 장식에 별도 생성기를 사용합니다.

공식: 나머지로 범위 줄이기

적의 x는 난수를 416으로 나눈 나머지에 32를 더해 32~447에서 고릅니다. 2³²이 416으로 나누어떨어지지 않아 작은 나머지가 아주 조금 더 자주 나오지만 차이는 약 천만 분의 일입니다.

x = 32 + (r mod 416) → 32 ≤ x ≤ 447
2³² = 416 × 10324440 + 256

에셋과 라이선스

에셋과 라이선스의 기준과 경계 조건을 익히고, 네 가지 구현에서 같은 뜻으로 사용할 약속을 확인합니다.

코드와 에셋의 출처

프로그램 코드의 라이선스와 함께 받은 이미지의 라이선스가 항상 같은 것은 아닙니다. 사용한 파일이 어느 출처의 어떤 조건을 따르는지 파일별로 기록합니다.

허용 라이선스 범위

이 프로젝트는 MIT, BSD, Apache-2.0과 CC0만 에셋에 허용합니다. 무료 다운로드라는 문구만으로 사용하지 않고 실제 라이선스와 적용 대상을 확인합니다.

이모지 렌더링의 차이

브라우저는 시스템 이모지를 그리므로 같은 문자도 기기별 모양이 다를 수 있습니다. 게임 규칙은 글자의 픽셀 모양 대신 공통 좌표와 반지름으로 계산합니다.

pygame 이미지의 출처

pygame용 Noto Emoji 이미지는 원본 저장소의 고정된 버전과 이미지 라이선스를 확인하여 보관합니다. 내려받은 파일의 이름만으로 출처를 추측하지 않습니다.

소리의 대체 경로

오디오 장치나 AudioContext를 만들 수 없어도 규칙과 테스트는 계속 실행되어야 합니다. 소리는 규칙이 만든 사건을 받아 재생하고 실패하면 조용히 비활성화합니다.

라이선스 목록의 열

파일 경로, 원본 URL, 버전, SHA-256, 라이선스와 라이선스 파일 위치를 한 행에 기록합니다. 라이선스가 불명확한 파일을 목록에 허용된 이름만 적어 통과시키지 않습니다.

파일 체크섬 검증

SHA-256은 받은 파일의 바이트가 기록한 것과 같은지 확인합니다. 같은 URL에서 내용이 바뀌어도 탐지할 수 있지만 해시 자체가 라이선스의 권한을 증명하지는 않습니다.

오프라인 자원 확인

덱은 외부 스크립트나 스타일시트 없이 열려야 합니다. 네트워크를 끈 브라우저에서 글꼴과 데모가 실행되는지 확인하고 필요한 코드는 빌드할 때 안에 포함합니다.

에셋과 라이선스 · 이해 확인

이미지가 무료라고 소개되어 있으면 파일 출처와 라이선스 기록을 생략해도 되나요?

생략할 수 없습니다. 허용된 라이선스인지 확인하고 원본 버전, 파일 체크섬과 라이선스 원문 위치를 기록합니다.
