배포·성능 측정

독립 HTML을 배포하고 로컬에서 실행하며 실제 측정 구간과 비교 한계를 기록합니다.

단일 HTML

최종 레벨은 코드와 스테이지를 한 HTML에 포함합니다. 배포 대상은 TypeScript 원본이 아니라 빌드된 독립 페이지입니다.

canvas-ts/tools.mjs

인라인 의존성

브라우저가 모듈 파일을 추가 요청하지 않도록 묶습니다. 오프라인 파일에서 실행되는지 실제 브라우저 검사로 확인했습니다.

canvas-ts/build.mjs

배포 파일 복사

완성된 HTML을 release/canvas.html로 복사합니다. 복사한 파일의 바이트가 원본과 같은지 테스트합니다.

canvas-ts/tools.mjs

로컬 HTTP

배포 파일을 로컬 HTTP로 열 수도 있습니다. 같은 파일을 제공하므로 오프라인 페이지와 게임 로직이 달라지지 않습니다.

canvas-ts/tools.mjs

로컬 바인딩

서버는 루프백 주소에만 바인딩합니다. 개발 중 확인하는 서버를 외부 네트워크 공개 서버로 오해하지 않게 합니다.

canvas-ts/tools.mjs

경로 제한

루트와 index.html만 제공합니다. 임의 경로 요청에는 404 응답을 보내며 프로젝트의 다른 파일을 노출하지 않습니다.

canvas-ts/tools.mjs

콘텐츠 형식

HTML과 UTF-8 콘텐츠 형식을 명시합니다. 한글 문서가 서버 기본 문자 인코딩에 따라 깨지지 않게 합니다.

canvas-ts/tools.mjs

서버 종료

터미널에서 종료 신호를 받으면 서버를 닫습니다. 실행 명령은 실제로 띄워 HTTP 응답과 정상 종료를 확인했습니다.

canvas-ts/commands.sh

오프라인과 출처

file URL과 HTTP URL은 저장소 출처가 다를 수 있습니다. 다른 실행 방식에서 최고 점수가 공유된다고 가정하지 않습니다.

canvas-ts/lv7/storage.ts

저장소 차이

저장소 접근을 차단한 환경에서는 기록을 영으로 시작하고 계속 플레이합니다. 저장 실패를 실행 실패로 처리하지 않습니다.

canvas-ts/lv7/storage.ts

측정 준비

모듈·스테이지·자동 입력을 읽고 측정 반복 수를 검사합니다. 이 로딩 시간은 로직 반복 측정과 분리합니다.

canvas-ts/tools.mjs

준비 실행

처음 두 번은 준비 실행으로 제외합니다. 실행기가 코드를 준비하는 비용과 반복 상태를 구분하여 측정 조건을 남깁니다.

canvas-ts/tools.mjs

반복 측정

같은 시드와 스테이지로 새 게임을 만들어 반복합니다. 이전 게임의 풀이나 점수를 재사용하여 부하를 바꾸지 않습니다.

canvas-ts/tools.mjs

중앙값

여러 표본을 정렬한 가운데 값을 함께 출력합니다. 모든 표본도 보관하여 한 숫자만 보고 변동을 놓치지 않게 합니다.

canvas-ts/tools.mjs

플레이 시간

activeSteps는 실제 전투가 진행된 스텝 수입니다. 지금의 기록 입력은 끝까지 살아남아 1800호출과 같지만, 게임 오버가 나면 전투가 멈추므로 두 값을 함께 기록합니다.

canvas-ts/tools.mjs

측정 구간

각 게임의 초기화 뒤부터 마지막 스텝까지 측정합니다. JSON 읽기·화면·소리·저장소는 이번 구간에 포함하지 않습니다.

canvas-ts/tools.mjs

다른 트랙 비교 제한

pygame의 cProfile 포함 측정과 이번 Node 측정은 도구 비용이 다릅니다. 수치만으로 언어 성능 순위를 정하지 않습니다.

canvas-ts/tools.mjs

렌더 비용 분리

빠른 로직 실행이 빠른 화면을 보장하지 않습니다. Canvas 그리기와 브라우저 프레임 비용은 별도 측정이 필요합니다.

canvas-ts/lv7/render.ts

실제 환경

Node 버전과 CPU 아키텍처를 표본에 함께 넣습니다. 다른 머신의 결과가 같은 시간이어야 한다고 기대하지 않습니다.

canvas-ts/tools.mjs

오류 재현

성능 수정 뒤에도 같은 입력으로 체크포인트를 비교합니다. 화면 예외와 논리 불일치는 각각 원인을 찾아 수정합니다.

canvas-ts/run.mjs
