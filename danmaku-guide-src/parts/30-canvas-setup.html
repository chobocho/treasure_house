3부 · Canvas+TypeScript

같은 게임 규칙을 브라우저의 이차원 그리기와 엄격한 타입으로 옮깁니다.

Canvas 설치와 실행

로컬 컴파일러와 번들러를 실행하고 브라우저에서 오프라인 화면을 확인합니다.

실행기 버전

Node와 TypeScript의 실제 버전을 출력합니다. 전역 설치에 기대지 않고 프로젝트에 고정한 실행기를 사용합니다.

canvas-ts/commands.sh

고정 의존성

타입 검사는 TypeScript, 번들은 esbuild가 담당합니다. 의존성은 설치된 정확한 버전을 유지하여 실행 조건을 고정합니다.

canvas-ts/build.mjs

플랫폼별 컴파일러

이 환경의 Node는 Android를 보고하지만 PRoot는 Linux 바이너리를 실행합니다. 같은 버전의 Linux ARM64 실행기로 검사했습니다.

엄격 타입 검사

strict 모드를 켜고 출력 파일 없이 검사합니다. 문법 변환이 성공하는 것과 타입이 맞는 것은 서로 다른 조건입니다.

canvas-ts/tsconfig.json

타입 오류 확인

검사 테스트는 문자열을 숫자 변수에 대입하여 실제 오류 번호를 확인합니다. 명령 실행 성공만으로 strict 설정을 믿지 않습니다.

DOM 타입

화면 코드에는 DOM 라이브러리를 허용합니다. 이후 게임 로직은 DOM을 사용하지 않는 순수 모듈로 분리합니다.

canvas-ts/tsconfig.json

esbuild 역할

타입 검사를 통과한 진입 파일과 의존 모듈을 하나로 묶습니다. 브라우저가 TypeScript 원문을 직접 실행하는 것은 아닙니다.

canvas-ts/build.mjs

HTML 인라인 실행

번들 스크립트를 HTML 안에 넣어 오프라인으로 엽니다. 외부 서버에서 스크립트나 글꼴을 받지 않아도 작동합니다.

canvas-ts/build.mjs

캔버스 논리 크기

width와 height는 실제 그리기 해상도를 정합니다. CSS 크기만 바꾸면 논리 좌표와 표시 크기가 어긋날 수 있습니다.

canvas-ts/setup.ts

화면 배율

최대 표시 폭을 부모에 맞추고 높이는 비율대로 둡니다. 게임 좌표는 표시 폭이 달라도 480×640입니다.

canvas-ts/setup.ts

컨텍스트 실패

getContext는 실패 시 null을 돌려줄 수 있습니다. 명시적으로 검사한 뒤에야 그리기 함수를 호출합니다.

canvas-ts/setup.ts

배경 지우기

매 화면마다 전체 배경을 다시 칠합니다. 이전 위치에 남은 픽셀과 현재 화면이 섞이지 않도록 합니다.

canvas-ts/setup.ts

이모지 폰트

운영체제의 이모지 글리프로 우주선을 그립니다. 별도 이미지 파일은 없으며 플랫폼마다 외형이 달라질 수 있습니다.

canvas-ts/setup.ts

텍스트 중심

textAlign과 textBaseline을 중심에 맞춰 좌표가 이미지 중심을 뜻하게 합니다. 충돌 규칙은 이모지 그림 크기와 별개입니다.

canvas-ts/setup.ts

프레임 계수

그린 횟수를 dataset에 기록하여 브라우저 검사에서 관찰합니다. 이 설치 예제의 계수는 아직 게임 논리 시간이 아닙니다.

canvas-ts/main.ts

오프라인 검사

로컬 파일을 열고 120프레임과 밝은 픽셀을 확인합니다. 자바스크립트 예외가 없는지도 함께 검사합니다.

게임 루프로 연결

다음 단계에서는 화면 갱신과 고정 논리 스텝을 분리합니다. 설치 확인 루프를 그대로 게임 이동 시간으로 사용하지 않습니다.
