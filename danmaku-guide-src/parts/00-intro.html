네 가지 구현 경로

익숙한 언어의 경로 하나를 먼저 완주한 다음, 같은 단계의 다른 구현을 비교하면 차이를 이해하기 쉽습니다.

경로기술화면을 그리는 방법

CThree.js + TypeScriptWebGL로 여러 탄환을 함께 그립니다.
DC++ → wasmC++ 상태를 JavaScript가 읽어 Canvas에 그립니다.

가이드를 읽는 순서

  1. 공통 기초에서 좌표, 충돌, 시간 간격의 뜻을 익힙니다.
  2. 선택한 경로의 설치 장에서 개발 환경을 준비합니다.
  3. Lv1부터 한 단계씩 실행하고, 새 동작과 상태를 확인합니다.
  4. 실행 결과가 같아진 뒤 다음 단계로 넘어갑니다.
각 단계는 독립된 폴더입니다. 이전 단계의 파일을 수동으로 합치지 않아도 해당 단계부터 실행할 수 있도록 구성합니다.

같은 규칙으로 비교하기

네 경로는 화면을 그리는 기술이 달라도 같은 입력에서 같은 게임 상태를 만들어야 합니다. 언어를 바꿀 때 규칙까지 바꾸면 구현 차이를 찾기 어렵습니다.

함께 맞추는 것

화면 크기, 이동 속도, 판정 반지름, 난수 시드와 입력 순서입니다.

경로마다 배우는 것

입력을 받는 방법, 화면을 그리는 방법, 소리를 재생하고 실행 파일을 배포하는 방법입니다.

화면과 조작의 기준

논리 화면은 가로 480, 세로 640픽셀입니다. 왼쪽 위가 원점이고 오른쪽과 아래쪽으로 갈수록 좌표가 커집니다.

일반 이동한 스텝에 4픽셀 이동합니다.
집중 이동한 스텝에 1.6픽셀로 천천히 이동합니다.
피격 반지름플레이어 중심에서 2.5픽셀입니다.
그레이즈 반지름중심에서 16픽셀 안의 아슬아슬한 회피를 판정합니다.
실제 키 배치와 발사·폭탄 조작은 각 경로의 실행 안내에서 확인합니다.

결과를 재현하는 기준

같은 난수 시드만 넣으면 서로 다른 구현의 게임 상태가 항상 같을까요?

아닙니다. 고정 시간 간격, 프레임별 입력, 난수 호출 순서와 계산 규칙도 같아야 합니다. 정해진 프레임의 상태를 기준 기록과 비교해서 확인합니다.
