작은 위치 배열로 주소·활성 구간·바이트 순서·뷰 수명을 실행하며 확인합니다.

선형 메모리와 바이트 주소

wasm의 포인터는 JS 객체가 아니라 선형 메모리 안의 바이트 위치입니다. 위치 배열의 시작 주소를 함수로 받아 메모리 버퍼의 해당 구간을 읽습니다. 주소 숫자를 좌표 값으로 해석하지 않습니다.

cpp-wasm/memory.cpp

레이아웃을 ABI로 약속하기

좌표 하나는 x와 y 두 개의 double로 구성되어 16바이트입니다. 용량은 네 개이며 배열은 8바이트에 정렬합니다. ABI 버전과 간격을 내보내 JS가 같은 형식으로 읽는지 확인합니다.

cpp-wasm/memory.cpp

명시적으로 초기화하기

새 게임이나 재시작 때 dm_init을 호출합니다. 활성 개수를 영으로 돌리고 좌표를 지웁니다. 모듈을 처음 로딩했을 때의 초기 상태만 믿으면 같은 인스턴스를 재사용하기 어렵습니다.

cpp-wasm/memory.cpp

용량과 활성 개수

할당한 공간은 좌표 네 개지만 유효한 좌표는 count개뿐입니다. 추가 함수는 가득 차면 영을 돌려주고 배열을 건드리지 않습니다. JS는 용량 전체를 그리지 않고 활성 구간만 읽습니다.

cpp-wasm/memory.cpp

C++가 갱신하고 JS가 표시하기

예제는 활성 좌표에 같은 변위를 더합니다. C++가 상태를 소유하고 JS는 갱신 후 결과를 읽는 순서를 유지합니다. 다음 게임 단계에서도 입력 전달·고정 스텝·표시의 경계를 이 방식으로 나눕니다.

cpp-wasm/memory.cpp

범위와 정렬 검사

주소를 무부호 값으로 바꾸고 정렬·용량·배열 끝 위치를 검사합니다. wasm 접근이 허용되는 메모리 범위 안이라고 해서 게임용 배열의 범위도 올바르다는 뜻은 아닙니다. 잘못된 메타데이터는 읽기 전에 거부합니다.

cpp-wasm/memory-glue.mjs

리틀 엔디언으로 읽기

DataView의 getFloat64에 true를 전달하여 바이트 순서를 명시합니다. 각 좌표의 x는 시작 위치, y는 8바이트 뒤에 있습니다. JS와 wasm 사이에 C++ 구조체 객체 자체를 넘기는 방식이 아닙니다.

cpp-wasm/memory-glue.mjs

공유 뷰와 독립 복사본

DataView는 wasm 버퍼를 공유하므로 C++가 갱신한 값이 다음 읽기에 보입니다. snapshot은 좌표를 새 배열로 복사하므로 이전 결과는 다음 이동에도 바뀌지 않습니다. 이 예제의 작은 용량에서는 검증하기 쉬운 복사를 사용합니다.

cpp-wasm/memory-glue.mjs

메모리 성장과 뷰 수명

이 모듈은 최대 메모리를 초기 크기와 같게 제한합니다. 일반적인 성장 가능한 모듈에서는 버퍼가 바뀔 수 있으므로 기존 뷰를 계속 쓰지 않아야 합니다. 연결한 버퍼와 현재 버퍼가 다르면 다시 연결하도록 오류를 냅니다.

메모리와 ABI · 이해 확인

배열 용량이 네 개이고 활성 개수가 한 개라면 몇 개를 읽어 표시할까요?

활성 좌표 한 개만 표시합니다. 용량은 메모리 범위 검사에 사용합니다. 주소·간격·개수를 함께 확인해야 유효한 좌표만 읽을 수 있습니다.
