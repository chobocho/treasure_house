Lv1 · 이동과 발사

순수 로직을 보존하고 Sprite와 Mesh로 같은 이동·발사 화면을 그립니다.

순수 로직 복사

Canvas 단계에서 검증한 로직을 독립 폴더에 복사합니다. Three.js 가져오기는 렌더러에만 두고 Node에서도 게임을 실행합니다.

three-ts/lv1/game.ts

입력 계약

같은 비트 번호와 입력 JSON을 사용합니다. 그리기 방식을 바꾸더라도 이동·발사 입력의 의미는 바뀌지 않습니다.

three-ts/lv1/game.ts

배정밀도 위치

게임 좌표는 number와 Float64Array를 유지합니다. GPU로 전달하는 표시 값 때문에 게임 상태의 정밀도를 줄이지 않습니다.

three-ts/lv1/game.ts

고정 풀

탄환은 미리 만든 열 배열의 활성 구간에 저장합니다. 렌더 객체 배열과 게임 풀은 역할과 수명이 서로 다릅니다.

three-ts/lv1/game.ts

용량

용량 영인 풀과 잘못된 용량을 구분합니다. 풀이 가득 찼을 때 동적 확장하지 않는 정책도 이전 트랙과 같습니다.

three-ts/lv1/game.ts

추가

마지막 활성 칸에 새 탄환 필드를 기록합니다. 렌더러에서 Mesh를 보이게 하는 일과 게임 탄환 생성은 별개입니다.

three-ts/lv1/game.ts

교환 삭제

모든 필드를 마지막 활성 칸과 함께 옮깁니다. 화면이 객체를 참조하더라도 게임 풀 인덱스는 삭제 후 바뀔 수 있습니다.

three-ts/lv1/game.ts

상태

플레이어·이전 위치·발사 대기·점수와 목숨을 Game이 보관합니다. 장면 객체를 게임 상태의 원본으로 사용하지 않습니다.

three-ts/lv1/game.ts

정규화

대각선 방향의 길이를 구해 같은 이동 거리를 만듭니다. Three 벡터의 normalize로 순서를 바꾸기보다 기존 계산을 보존합니다.

three-ts/lv1/game.ts

집중

집중 속도 일 점 육의 누적 순서를 유지합니다. 카메라나 화면 배율이 이동 속도에 섞이지 않도록 합니다.

three-ts/lv1/game.ts

발사 간격

첫 스텝부터 발사하고 이후 여덟 스텝 간격입니다. 화면을 여러 번 그려도 대기 시간은 로직에서만 감소합니다.

three-ts/lv1/game.ts

논리 순서

이동·발사·탄환 갱신을 마친 뒤 프레임을 증가시킵니다. 실제 Three 렌더 호출은 이 순서 밖에서 수행합니다.

three-ts/lv1/game.ts

체크섬

그림 결과와 별도로 탄환 좌표의 양자화 합을 비교합니다. 표준 floor와 무부호 변환 순서는 그대로 유지합니다.

three-ts/lv1/game.ts

좌표 경계

게임의 중심 좌표를 십이 픽셀 안쪽으로 제한합니다. Sprite의 크기를 변경해도 충돌과 이동 경계는 따로 유지합니다.

three-ts/lv1/game.ts

직교 투영

카메라 범위를 논리 화면 크기로 둡니다. 원근에 의한 크기 변화가 없어 평면 게임의 좌표와 표시를 대응시키기 쉽습니다.

three-ts/lv1/render.ts

y 변환

게임 y가 아래로 증가하고 장면 y는 위로 증가하므로 높이에서 뺍니다. 순수 로직의 좌표를 수정하지 않습니다.

three-ts/lv1/render.ts

렌더러

하나의 WebGLRenderer와 Scene을 만들고 계속 사용합니다. 매 프레임 새 장면이나 GPU 컨텍스트를 만들지 않습니다.

three-ts/lv1/render.ts

이모지 캔버스

시스템 이모지를 작은 이차원 캔버스에 한 번 그립니다. 이를 텍스처로 사용하므로 외부 그림 요청이 없습니다.

three-ts/lv1/render.ts

텍스처 색 공간

이모지 캔버스를 sRGB 텍스처로 표시합니다. 색 공간을 명시해 입력 이미지와 출력 색의 해석을 맞춥니다.

three-ts/lv1/render.ts

Sprite 재질

SpriteMaterial에 텍스처를 연결합니다. 투명 배경의 사각형을 화면을 향하는 물체로 표시할 수 있습니다.

three-ts/lv1/render.ts

우주선 크기

우주선 Sprite의 가로세로를 이십사 논리 단위로 맞춥니다. 원본 텍스처 해상도와 장면에서의 크기를 구분합니다.

three-ts/lv1/render.ts

피격 점

작은 원 Mesh를 플레이어 중심에 둡니다. 큰 이모지의 모양과 실제 중심 위치를 분리해 읽을 수 있게 합니다.

three-ts/lv1/render.ts

탄환 기하

반지름 일이 되는 원 기하를 공유합니다. 각 탄환의 반지름은 객체의 배율로 전달하여 기하를 계속 만들지 않습니다.

three-ts/lv1/render.ts

공유 재질

플레이어 탄환은 같은 재질을 공유합니다. 같은 색의 탄환마다 독립 재질을 만들면 리소스 관리가 늘어납니다.

three-ts/lv1/render.ts

Mesh 미리 생성

최대 탄환 용량만큼 Mesh를 초기화 때 만듭니다. 이번 단계의 기준 구현이며 다음 단계에서 인스턴싱으로 바꿉니다.

three-ts/lv1/render.ts

활성 표시

살아 있는 탄환 인덱스까지만 visible을 켭니다. 비활성 Mesh에 과거 좌표가 남아 있어도 그려지지 않습니다.

three-ts/lv1/render.ts

탄환 보간

현재 좌표와 속도로 이전 스텝 사이를 표시합니다. 보간된 값을 게임 풀에 다시 저장하면 다음 로직 결과가 달라집니다.

three-ts/lv1/render.ts

위치와 크기

각 Mesh의 위치와 배율을 갱신합니다. 행렬과 벡터는 이미 가진 객체를 수정하고 새 객체 생성을 피합니다.

three-ts/lv1/render.ts

렌더 호출

플레이어와 탄환의 표시 상태를 갱신한 뒤 장면을 렌더합니다. 화면을 그리는 도중 충돌이나 발사를 처리하지 않습니다.

three-ts/lv1/render.ts

통계

실제 그리기 호출 수를 dataset에 남깁니다. 활성 탄환 수와 호출 수의 관계를 다음 인스턴싱 단계와 비교할 수 있습니다.

three-ts/lv1/render.ts

키보드

키 이름을 비트에 매핑하고 눌린 상태를 읽습니다. 입력 어댑터는 Three 객체의 위치를 직접 변경하지 않습니다.

three-ts/lv1/input.ts

포커스

캔버스가 포커스를 잃으면 눌린 키를 비웁니다. 다른 창으로 이동한 뒤 돌아와도 이동 키가 고착되지 않게 합니다.

three-ts/lv1/input.ts

고정 스텝

실제 화면 시간을 누적하여 논리 갱신을 육십분의 일초씩 실행합니다. WebGL 화면 속도가 게임 속도를 결정하지 않습니다.

three-ts/lv1/main.ts

해제

텍스처·재질·기하·렌더러를 해제합니다. 공유 리소스는 한 번만 해제하고 같은 객체를 여러 번 독립 리소스처럼 다루지 않습니다.

three-ts/lv1/render.ts

독립 번들

각 레벨의 화면 페이지와 순수 로직 모듈을 별도로 만듭니다. 브라우저와 Node가 같은 game.ts를 사용합니다.

three-ts/build.mjs

기준 비교

pygame Lv1의 세 체크포인트와 모든 상태 필드를 비교합니다. Three 렌더러를 추가해도 기준 기록을 새로 만들지 않습니다.

three-ts/run.mjs

실제 화면

백이십 화면 뒤 이동·발사와 실제 WebGL 픽셀을 검사합니다. 호출 수가 양수인 것만 확인하고 화면 검사를 끝내지 않습니다.
