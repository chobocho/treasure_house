## 0. Non-negotiables (read twice)

1. **The deck HTML is a build artifact.** Never edit it by hand. Edit `compress/deck/sections/*.html`
   or the real source files they cite, then `make all`.
2. **No hand-written code in the deck.** Every `<pre><code>` is a `<!--CODE file=… lines=A-B|sym=…-->`
   directive that the assembler fills from a real file under `compress/`. Every terminal capture is
   `<!--OUT file=…-->` pointing at `compress/out/`. `verify_deck.py` re-checks deck ↔ source on every build.
3. **Tests before code (RED → GREEN).** Each algorithm gets its spec and failing tests first.
   Never loosen a test or a golden vector to make it pass.
4. **Five languages, one behaviour.** For **every** algorithm (Tier 1 and Tier 2) the Python, Go, C++,
   Java and TypeScript encoders must produce **byte-identical output** for every corpus file, and every
   decoder must round-trip every other language's output. Enforced by `golden/` SHA-256 files (§4).
   Decoder-only modules (bzip2dec, lzmadec) are gated by decoding the same real-tool files to the
   same SHA-256 in all five languages.
5. **Real-world interop is the strongest evidence.** Where a real format exists (gzip/zlib, bzip2,
   xz/LZMA, lz4, zstd, brotli — all CLIs are installed on this machine, and Python stdlib has
   zlib/bz2/lzma), our decoder must decode files made by the real tool, and where we have an encoder
   the real tool must decode ours. Capture both directions into `out/`.
6. **This machine is a Galaxy Fold under Termux/proot with ~200 MB free RAM.** At most **2 subagents**,
   **1 JVM at a time** (flock), Go with `-p=1`, benchmarks strictly sequential. Check `free -m` before
   heavy steps. Checkpoint everything to disk; assume the session can be killed at any moment.
7. **Foldable layout.** `<pre>` ≤ 45 lines and ≤ 72 columns (Korean counts as 2), captures ≤ 108
   columns, `<li>` ≤ 14 per list, no box-drawing characters in prose, no `①②③` inside monospace,
   no Korean at the *start* of a column in `<pre>` diagrams. The assembler errors on all of these.
8. **Commit granularity:** one algorithm (or one deck part) per commit, and split "source commit" from
   "deck-body commit". Korean, no-prefix commit subject (repo convention). Never `git push` unless asked.
9. Keep Korean comments in code (UTF-8, no BOM). Identifiers in English.

## 3. Algorithm catalogue and tiers

**All 17 modules below are implemented in all five languages** (user decision 2026-09-12). The tier
only orders the work: Tier 1 first (the foundations), Tier 2 on top of them.

**Tier 1 — foundations, byte-identical (golden vectors, §4).** Each has a bit-exact spec in
`SPEC.md` (container header, endianness, parse strategy, tie-breaking, window sizes, EOF handling).
Without the spec five implementations will never agree — write the spec before the Python reference.

| # | Module | Content | Spec pins |
|---|---|---|---|
| 1 | `bitio` | MSB-first and LSB-first bit writer/reader | flush padding = zero bits |
| 2 | `intcode` | varint(LEB128), zigzag, Elias γ/δ, Golomb/Rice(k) | unsigned 64-bit; Rice k in header |
| 3 | `rle` | byte RLE (PackBits-style) + zero-run RLE | run cap 128/255 exactly as PackBits |
| 4 | `mtf` | move-to-front + inverse | alphabet 256, initial identity |
| 5 | `huffman` | canonical Huffman, length-limited (≤15) via package-merge or the DEFLATE kraft fix-up | tie-break: (length, symbol) ascending; header = 256 code lengths, 4 bits each |
| 6 | `lzss` | LZ77 with 32 KiB window, min match 3, max 258, hash-chain greedy parse, flag-byte tokens | hash = 3 bytes, chain length 32, prefer longest then nearest |
| 7 | `lzw` | LZW 9→12-bit variable width, clear code 256, EOF 257, MSB-first (like `.Z`/GIF spec direction fixed in SPEC) | dictionary reset at 4096 |
| 8 | `rangecoder` | 32-bit range coder (LZMA-style carry propagation) + adaptive binary model + order-0 byte model | 11-bit probabilities, shift 5 |
| 9 | `bwt` | BWT via suffix doubling O(n log² n) + inverse via LF mapping; sentinel-free with primary index in header | block ≤ 64 KiB (900 KiB later in bzip2 chapter) |
| 10 | `deflate` | full DEFLATE: stored/fixed/dynamic blocks, inflate + deflate with lzss parse; zlib and gzip containers (Adler-32, CRC-32) | must round-trip with real zlib/gzip both ways |

**Tier 2 — advanced codecs, also all five languages, byte-identical.** Python reference first, then
C++ → Go → TS → Java exactly as in Tier 1. Each also needs a bit-exact section in `SPEC.md`
(rANS renormalisation, LZ4 parse choices, PPM escape/exclusion rules, CM mixer fixed-point math,
DCT integer approximation — floating point is **forbidden** in codecs so five languages agree bit-for-bit).

| # | Module | Content | Oracle |
|---|---|---|---|
| 11 | `ans` | rANS (32-bit, byte renorm) and tANS table build; explain FSE | self round-trip; entropy bound table |
| 12 | `lz4block` | LZ4 block format encoder/decoder + frame decoder | `lz4` CLI both directions |
| 13 | `bzip2dec` | real bzip2 decoder (RLE1, BWT, MTF, ZRLE, Huffman multi-table, CRC) | `bzip2` CLI → ours; py `bz2` |
| 14 | `lzmadec` | real LZMA(1)/xz-stream decoder (rc + lit/match/rep states) | `xz --format=lzma` → ours |
| 15 | `ppm` | PPM order-2 with escape method C, on top of `rangecoder` | self; ratio vs order-0 |
| 16 | `cm` | context mixing lpaq-lite: 2–3 predictors + logistic mixer + APM | self; ratio table |
| 17 | `lossy` | uniform/dead-zone quantiser, 8×8 DCT, JPEG-lite (DCT+quant+zigzag+RLE+Huffman on grayscale PGM), PNG filters (Sub/Up/Avg/Paeth) + zlib, IMA ADPCM | PSNR table; PNG output must open with py `zlib` inflate; ADPCM round-trip SNR |

**Tier 3 — concept-only chapters (no new code, cite Tier-1/2 code and real-tool captures):**
zstd (FSE + repeat offsets + dictionaries), brotli (static dictionary, context modelling),
7z/xz container, PNG/GIF/ZIP file formats, compression bombs, CRIME/BREACH, compressed
sensing is OUT of scope. Video motion compensation gets one conceptual sub-chapter, no code.

**Fixed-point rule (all tiers):** no `float`/`double` in any encoder or decoder path. Where a chapter
needs real numbers (entropy, PSNR, SNR) compute them in the bench/analysis scripts (Python only) and
cite the captured table; the codecs themselves use integer arithmetic so golden vectors are stable
across languages and platforms.

**TypeScript doubles as the in-deck demo layer.** The same `src/ts` modules are bundled
(`tools/bundle_web.mjs` pattern from tetris_ts) into `deck/demos.js` for `<div class="demo">`
widgets: entropy calculator, Huffman tree builder, LZ77 match viewer, arithmetic interval zoom,
BWT rotation table, "paste text → compress with 6 codecs" comparator. `check_deck.js` must run
each demo on the DOM stub with sample inputs (CASES table) and assert output nodes exist.

## 4. Golden-vector protocol (cross-language parity)

1. `corpus/gen_corpus.py` generates a deterministic corpus (seeded PRNG, committed outputs):
   `empty.bin` (0 B), `one.bin` (1 B), `zeros_64k.bin`, `random_64k.bin`, `abab_4k.txt`,
   `korean_utf8.txt` (~40 KB of Korean prose), `english.txt` (~60 KB), `source.go` (real file copied),
   `mixed_1m.bin` (1 MiB structured mix), `boundary_32768.bin`, `boundary_32769.bin`.
   Edge cases are deliberate: window boundary, max-match-length runs, all-256-symbol alphabet,
   single-symbol alphabet (Huffman must handle a 1-symbol tree), LZW dictionary wrap.
2. Python reference encodes every corpus file with every codec (Tier 1 and Tier 2) → `golden/<algo>/<file>.sha256`
   and `.size`. Regenerating goldens is a separate commit with a stated reason.
3. `make parity` runs every language's CLI (`cli/<lang>`) over every (algo, file), compares SHA-256
   to golden, then cross-decodes (each language decodes each other language's output) — 5×5 matrix
   per algorithm, all must equal the original. Output → `out/parity_<algo>.txt` (cited in the deck).
4. Round-trip property tests per language (random inputs, sizes 0..70000) in each language's own
   test runner. C++/Go/Java/TS tests may be smaller than Python's; the parity matrix is the real gate.
5. Bench (`bench/run_bench.py`): sequential, one process at a time, 3 runs each, reports min time and
   ratio per (lang, algo, file) → `out/bench_*.txt`. Never run in parallel (RAM). Java timing includes
   JVM warm-up note; C++ `-O2`; TS via node. The deck reports numbers only from these files.

## 10. Consequences of the decisions (planning notes for the builder)

- Source volume roughly doubles versus the original tiered plan: expect ~25k lines across
  `src/{py,go,cpp,java,ts}`. Keep every module ≤ ~350 lines per language so `FULLSRC` slices and
  `check_slices.py` stay manageable; split large codecs (deflate, lzmadec, cm, lossy) into 2–3 files.
- Java is the bottleneck (one JVM at a time). Batch-compile the whole `src/java` tree once per parity
  run rather than per module; run Java tests from one `main` dispatcher to avoid repeated JVM starts.
- Integer-only codecs (see §3 fixed-point rule) are what make five-language parity possible for
  ANS, CM and the lossy chapter. Specify every table (CM stretch/squash, DCT constants, ADPCM step
  table) as literal integer arrays in `SPEC.md` and generate them once from Python into all five
  languages via `tools/gen_tables.py` so they cannot drift.

### 3. Corpus (2026-09-12)

`corpus/gen_corpus.py` + 13 committed files + `corpus/MANIFEST.txt` + `corpus/README.md`.

Two deviations from §4.1, both deliberate:

- **13 files, not 11.** Added `runs.bin` (run lengths 127/128/129 and 257/258/259 — the
  PackBits control-byte cap and the LZSS max-match cap, plus 2-run/3-run threshold) and
  `alphabet.bin` (all 256 symbols, so the 128-byte Huffman header is fully populated).
  §4.1 asked for those edge cases in prose; they need their own files to be reachable.
- **`boundary_32768.bin` / `boundary_32769.bin` name the tested distance, not the file
  size.** Each is `mark(64) + filler + mark(64)` sized so the trailing mark sits at
  distance exactly 32768 / 32769. Files are 32832 / 32833 bytes. The filler is
  16-symbol low-entropy bytes, **not** random: random filler makes DEFLATE emit stored
  blocks, and a stored block has no matches at all, so the window boundary would never
  be exercised.

`korean_utf8.txt` (40 KB) and `english.txt` (61 KB) are extracted from real documents,
not synthesised — invented prose has a narrow vocabulary and compresses far better than
real text, which would put a false number in the deck. Korean comes from four finished
repo documents (prose only, code fences and tables stripped); English is this deck's own
`SPEC.md` plus `PLAN.md` up to the progress-log marker, which is why the marker is a
hard cut: everything after it changes every commit. `source.go` is
`keycloak_ad/ldap/ber/ber.go` verbatim.

`MANIFEST.txt` records the SHA-256 of every generated file **and of every external
source**, so a source document changing is a loud failure (`gen_corpus.py --check`)
rather than a silent corpus drift that invalidates every golden vector.

Sanity numbers (Python stdlib, informational only — the deck cites `out/` captures):
`random_64k.bin` grows under gzip, bzip2 and xz alike; `zeros_64k.bin` is 84 B under
gzip and 140 B under xz, because LZMA's fixed structure outweighs 64 KiB of nothing.

### 4. Python reference + golden vectors (2026-09-12)

All ten Tier-1 modules, tests first, one commit each. 153 tests green.
`golden/<algo>/<file>.{sha256,size}` for 10 algorithms × 13 corpus files = 130 pairs,
each regenerated only after the encoder's own output round-trips.

**The tests found four real defects, three of them in SPEC.md rather than in code:**

1. §0.3 claimed every codec's empty output is `00`. `bitio`'s three pad bits still
   need a byte. Fixed the spec (two exceptions: `bitio` `00 00`, `deflate` `03 00`)
   and later made the rule uniform — `huffman`, `lzw`, `rangecoder` and `bwt` all
   return after the header, so an empty input never gets framing it has no body for.
2. §2.5 capped Rice's unary run at 64. `Rice(k=0)` is plain unary, which is how the
   deck introduces unary coding, and 64 cannot express 100. Raised to 4096 — still
   bounded (a corrupt stream spins 4 Ki times per symbol at worst).
3. §10.6 said blocks are 65536 bytes. A stored block's `LEN` is 16 bits, so 65536
   can never be stored as one block and the type choice would stop being free at
   exactly that size. Now 65535.
4. A genuine code bug: BWT's suffix doubling packs its key as
   `rank[i] * (m + 1) + rank[i + k]`, and on the first round `rank` held **raw byte
   values** (up to 255), so the multiplier was far too small. `banana` produced
   `nanbaa`. Byte values are now rank-compressed to `0..distinct-1` first. The
   round trip still worked — only the textbook expectation caught it.

Two spec additions that the implementation forced:

- §6.1: the hash chain is indexed by **absolute position**, not `pos & 32767`.
  zlib's wrapped array is exactly why zlib's effective maximum distance is 32506.
  `corpus/boundary_32768.bin` now demonstrably finds a match at distance 32768 and
  `boundary_32769.bin` does not.
- §5.1/§5.3: a single-symbol Huffman table is necessarily incomplete (Kraft 1/2).
  `check_complete` accepts exactly that case; RFC 1951 has the same exception for a
  one-code distance table, which our inflate needs anyway.

Deviation from §1: `tools/gen_tables.py` is not written yet. Every Tier-1 table is
**derived** at import from a short authoritative array (`deflate_tables.py` builds
the length/distance code tables from the RFC's 29+30 `(extra, base)` pairs; the
CRC-32 table comes from the polynomial). A generator is needed only for Tier-2's
CM stretch/squash, DCT and ADPCM tables, which cannot be derived that cheaply.

Ratios on the whole corpus (1,367,107 bytes in): deflate 36.8 %, lzss 55.9 %,
rangecoder 60.4 %, lzw 75.6 %, rle 76.9 %, huffman 80.4 %, bwt/mtf/bitio ~100 %,
intcode 131.3 %. Our DEFLATE is within 1 % of `zlib -9` on every corpus file and
0.5 % *better* on `mixed_1m.bin`, and interoperates with real zlib and gzip in both
directions at every level.

### 6. Ports — C++, Go, TypeScript, Java (2026-09-12)

**All five languages now produce byte-identical output for all ten Tier-1 modules
on all thirteen corpus files, and the full 5×5 cross-decode matrix passes.**
That is §8's first bullet, done for Tier 1.

Every port matched the golden vectors **on the first run**. That is the return on
step 2: the spec pinned every choice that could differ (package–merge's sort key,
the `>` in the LZSS chain, LZW's one-step decoder lag, the stable sort in BWT,
DEFLATE's exact cost accounting), so there was nothing left to guess.

Deviations from §1, all deliberate:

- **Go is one package**, not one per algorithm. The modules call each other
  constantly (deflate needs huffman and bitio; everything needs varint), and one
  package per algorithm would scatter the appendix's full listing over ten
  directories for no benefit.
- **Java's CLI lives at `cli/java/Main.java` with `package compresslib;`.** javac
  does not require the directory to match when every file is named explicitly.
- **`build/` holds every language's output** (gitignored). The parity harness
  probes it to decide which languages are available.

Per-language notes worth keeping:

- **C++:** cast helpers (`u8` `u32` `sz` `i32` `ix`) instead of `static_cast<…>`.
  This is a readability decision forced by the deck: at 72 columns a line with two
  `static_cast<uint8_t>(…)` wraps three times. `CXX` is pinned to g++ — the
  environment has `CXX=clang++` and §2 verified g++ 15.2.
- **Go:** internal code panics via `fail()`; the exported `Encode`/`Decode` recover
  into an `error`. Threading `error` through every "cannot continue here" inside a
  decoder buries the algorithm, which is the opposite of what a teaching deck needs.
- **TypeScript:** `typescript@5`, not 6.x — TS 6 ships a per-platform native binary
  and there is no android-arm64 package, so `tsc` will not start at all. The range
  coder avoids bitwise operators entirely (`* 256 % 2**32`, `Math.floor(x / 2048)`);
  BWT's doubling key needs `Float64Array` because it reaches 2^32.
- **Java:** `Console.useUtf8()` is called from both mains. Java 18+ defaults
  `file.encoding` to UTF-8 but **not** the console encoding, which here is ASCII —
  every Korean message printed as `?`, including the test results.
  `Arrays.sort` on `int[]` is not stable, so BWT sorts `Integer[]`.

One tooling casualty worth recording: teaching `tools/rewrap.py` about javadoc made
it swallow the closing ` */` of twenty-one files in one run (it read the line as a
paragraph word `/`). Fixed in the tool, and the files were repaired mechanically.

Seven modules: `ans`, `lz4block`, `bzip2dec`, `lzmadec`, `ppm`, `cm`, `lossy`.

Whole-corpus ratios (1,367,107 bytes): cm 34.4 %, deflate 36.8 %, lossy 41.5 %,
ppm 42.9 %, lz4block 54.1 %, lzss 55.9 %, rangecoder 60.4 %, lzw 75.6 %,
rle 76.9 %, ans 79.6 %, huffman 80.4 %, bwt/mtf/bitio ~100 %, intcode 131.3 %.

Three findings worth keeping:

- **`cm` — the mixer's learning rate is the whole algorithm.** An update shift of
  10 (instead of lpaq's 16) swings a weight by 50,000 per step and the mix
  thrashes. Separately, lpaq1's APM multiplier of 23 leaves the top nine of 33
  interpolation slots unreachable, capping the output probability near 3200/4096;
  at 32 `english.txt` went 39.5 % → 35.6 %. **Round-trips were perfect the whole
  time** — only the compressed size showed either bug. A codec that round-trips is
  not a codec that works.
- **`lossy` — the only place anything is discarded is quantisation.** The DCT and
  the PNG filters are exactly invertible. The registered codec is the PNG one,
  because it is the only one that round-trips; putting a golden vector on a lossy
  encoder would pin the encoder, not the picture. jpeglite's decoder must *eat*
  the EOB byte even when all 64 coefficients were present (quality 100), or the
  next block reads that 255 as its own EOB — PSNR 8.4 dB instead of 55.1 dB.
- **Non-derivable tables are now generated, not typed.** `tools/gen_tables.py`
  emits SQUASH (33), DCT (64), JPEGQ (64), ADPCMSTEP (89), ADPCMINDEX (16) and
  `--check` finds each as a contiguous subsequence between `NAME-TABLE-BEGIN` /
  `NAME-TABLE-END` markers in all five languages. 25 places, 0 mismatches.

A process note: the cm/lossy sources landed in commit `cfb479c` rather than in
their own commits — a concurrent session working elsewhere in this repository ran
`git add -A` across the whole tree while these files were still unstaged. Nothing
