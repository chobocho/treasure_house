클로저와 반복자

이름 없는 함수 · 주변을 붙잡는 세 가지 방법 · next 하나로 도는 반복자 · 어댑터와 소비자

이 부에서 할 일

앞의 부들에서 |x| x + 1 이나 .iter().map(…) 을 "그런 것이 있다" 며 지나쳤습니다. 이 부가 그 둘을 정식으로 다룹니다. 클로저는 주변의 변수를 붙잡는 함수이고, 반복자는 값을 하나씩 내주는 것입니다. 둘은 늘 함께 쓰입니다.

  • 1장 — 클로저: 문법, 붙잡기(빌림·가변 빌림·이동), Fn · FnMut · FnOnce
  • 2장 — Iterator 트레이트: next, 세 가지 iter, 게으름
  • 3장 — 어댑터: map, filter, zip … 반복자를 받아 반복자를 내는 것
  • 4장 — 소비자: collect, sum, fold … 반복자를 끝까지 돌려 값을 내는 것
  • 5장 — 실전: 반복문을 반복자로, 정렬, 묶기

1장

클로저

문법 · 주변을 붙잡는다 · 빌림과 move · Fn · FnMut · FnOnce · 주고받기

클로저 — 이름 없는 함수

매개변수를 세로줄 | | 사이에 쓰고, 그 뒤에 본문을 씁니다. 타입은 대개 쓰지 않습니다 — 쓰이는 모습을 보고 컴파일러가 정합니다.

함수클로저
fn add_one(x: i32) -> i32 { x + 1 }|x| x + 1

클로저는 주변을 붙잡는다

함수와 가장 다른 점입니다. 클로저는 자기가 만들어진 자리의 변수를 그대로 쓸 수 있습니다. 5부에서 중첩 함수가 못 하던 일입니다(E0434).

붙잡기(capture) — 클로저 값 안에 rate 가(또는 그 참조가) 들어 있다고 생각하면 됩니다. "코드 + 붙잡은 것" 이 클로저입니다.

타입은 한 번 정해지면 끝이다 — E0308

클로저는 제네릭이 아닙니다. 처음 불린 모습으로 타입이 정해지고, 다른 타입으로 다시 부를 수 없습니다.

읽기만 하면 빌린다

클로저는 필요한 만큼만 붙잡습니다. 읽기만 하면 불변으로 빌립니다. 주인은 그동안에도 값을 읽을 수 있습니다.

고치면 가변으로 빌린다

주변 변수를 고치는 클로저는 그것을 가변으로 빌립니다. 부를 때마다 자기 상태가 바뀌므로 클로저를 담은 변수에도 mut 가 필요합니다.

빌림 규칙은 클로저에도 그대로 — E0502

클로저가 가변으로 빌리고 있는 동안에는 주인도 그 값을 읽을 수 없습니다. 클로저를 마지막으로 쓴 뒤에야 빌림이 끝납니다.

앞 장이 통과한 까닭 — 거기서는 add 를 다 쓴 뒤에 total 을 읽었습니다.

move — 가져가서 붙잡는다

클로저 앞에 move 를 쓰면 쓰는 변수를 빌리지 않고 가져옵니다. 클로저가 그 값의 주인이 됩니다. 클로저를 만든 함수보다 클로저가 오래 살아야 할 때 필요합니다.

가져간 뒤에는 밖에서 못 쓴다 — E0382

평소의 이동과 같습니다. 클로저로 옮겨 간 값은 원래 이름으로 더 쓸 수 없습니다.

스레드에서 본 것 — thread::spawn(move || …) 의 move 가 이것입니다 (15부).

세 가지 클로저 — Fn · FnMut · FnOnce

붙잡은 것을 어떻게 다루느냐에 따라 클로저는 세 트레이트 가운데 하나(이상)를 구현합니다. 컴파일러가 본문을 보고 정합니다.

트레이트붙잡은 것을부를 수 있는 횟수예
Fn읽기만 한다몇 번이든|| names.len()
FnMut고친다몇 번이든(혼자서)|n| total += n
FnOnce써 버린다(밖으로 내보낸다)한 번move || name
포함 관계 — Fn 인 것은 FnMut 이기도 하고, FnMut 인 것은 FnOnce 이기도 합니다. 받는 쪽은 필요한 만큼만 요구합니다. move 는 "어떻게 붙잡는가" 이고 이 셋은 "붙잡은 것으로 무엇을 하는가" 라서 서로 다른 축입니다.

클로저를 받는 함수

매개변수 타입에 impl Fn(i32) -> i32 라고 씁니다. 클로저도, 같은 모양의 보통 함수도 받습니다.

5부의 fn(i32) -> i32 와 다른 점 — 소문자 fn 은 함수 포인터 타입이라 주변을 붙잡은 클로저는 못 받습니다. Fn 트레이트는 둘 다 받습니다.

상태를 고치는 클로저를 받으려면 FnMut

넘겨받은 클로저가 자기 상태를 고칠 수 있게 하려면 FnMut 로 받고, 매개변수에 mut 를 붙입니다.

한 번만 부를 클로저는 FnOnce

붙잡은 값을 밖으로 내보내는 클로저는 한 번만 부를 수 있습니다. 그런 것까지 받으려면 FnOnce 로 받습니다 — 가장 너그러운 조건입니다.

FnOnce 를 두 번 부르면 — E0382

첫 호출에서 클로저가 통째로 소비됩니다. 붙잡은 name 이 이미 밖으로 나갔기 때문입니다.

읽는 법 — note: 가 까닭을 말합니다. "이 클로저는 name 을 자기 환경 밖으로 옮기므로 한 번 넘게 부를 수 없다".

클로저를 돌려주는 함수

반환 타입에도 impl Fn(…) 을 씁니다. 돌려주는 클로저가 함수의 지역 변수(n)를 쓴다면 move 로 가져가야 합니다 — 함수가 끝나면 n 은 사라지니까요.

클로저 여럿을 한 벡터에

클로저는 하나하나가 서로 다른 이름 없는 타입입니다. 한 벡터에 담으려면 트레이트 객체로 만듭니다 (10부, 14부).

퀴즈 — 클로저

Q. let mut add = |n| total += n; 을 받으려는 함수의 매개변수는 Fn, FnMut, FnOnce 가운데 무엇이어야 할까요?

A. FnMut(또는 더 너그러운 FnOnce)입니다. 붙잡은 total 을 고치므로 Fn 은 아닙니다(세 가지 클로저). 여러 번 부르려면 FnMut 로 받습니다.

2장

Iterator 트레이트

next 하나 · iter · iter_mut · into_iter · 게으르다 · 내 반복자 만들기

반복자는 next 하나로 움직인다

반복자(iterator)는 next() 를 부를 때마다 다음 값을 Some 으로, 다 떨어지면 None 을 주는 것입니다. 그것이 전부입니다.

let mut it — next 는 반복자의 자리를 한 칸 옮기므로 반복자는 가변이어야 합니다.

for 는 next 를 대신 불러 준다

for 반복문은 반복자를 만들고 None 이 나올 때까지 next 를 부르는 문법입니다. 손으로 풀어 쓰면 이렇습니다.

세 가지 반복 — 빌려서, 고치며, 가져가며

모음에서 반복자를 얻는 메서드는 셋이고, 소유권의 세 가지 모양과 그대로 맞습니다.

메서드원소의 타입for 로 쓰면끝난 뒤 모음은
iter()&Tfor x in &v그대로
iter_mut()&mut Tfor x in &mut v고쳐진 채로
into_iter()Tfor x in v없다(소비됨)

반복자는 게으르다

map 은 "이렇게 바꿀 것" 이라는 계획을 담은 새 반복자를 돌려줄 뿐, 아무것도 돌리지 않습니다. 누군가 next 를 불러야 일이 일어납니다.

소비해야 돈다

끝에 collect() 를 붙였습니다. collect 가 next 를 끝까지 부르고, 그제야 map 의 클로저가 원소마다 돕니다.

어댑터와 소비자 — map 처럼 반복자를 받아 반복자를 내는 것이 어댑터(3장), collect 처럼 끝까지 돌려 값을 내는 것이 소비자(4장)입니다. 사슬은 늘 소비자로 끝납니다.

내 타입을 반복자로 만든다

Iterator 트레이트는 next 하나만 구현하면 됩니다. 그러면 for 에 쓸 수 있고, map · filter · sum 같은 수십 개의 메서드가 따라옵니다.

기본 메서드 — 10부에서 본 "트레이트의 기본 구현" 입니다. 나머지 메서드는 전부 next 위에 지어져 있습니다.

반복자를 내주는 것들

범위, 문자열의 글자·줄·조각 — 표준 라이브러리 곳곳에서 반복자가 나옵니다. 전부 같은 방법으로 다룹니다.

퀴즈 — Iterator

Q. v.iter().map(|x| { println!("{x}"); x * 2 }); 는 무엇을 찍을까요?

A. 아무것도 찍지 않습니다. map 은 게을러서 소비자가 없으면 클로저가 한 번도 돌지 않습니다(반복자는 게으르다). 컴파일러도 "쓰지 않은 Map" 이라고 경고합니다.
