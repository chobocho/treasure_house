클로저와 반복자

이름 없는 함수 · 주변을 붙잡는 세 가지 방법 · next 하나로 도는 반복자 · 어댑터와 소비자

이 부에서 할 일

앞의 부들에서 |x| x + 1 이나 .iter().map(…) 을 "그런 것이 있다" 며 지나쳤습니다. 이 부가 그 둘을 정식으로 다룹니다. 클로저는 주변의 변수를 붙잡는 함수이고, 반복자는 값을 하나씩 내주는 것입니다. 둘은 늘 함께 쓰입니다.

  • 1장 — 클로저: 문법, 붙잡기(빌림·가변 빌림·이동), Fn · FnMut · FnOnce
  • 2장 — Iterator 트레이트: next, 세 가지 iter, 게으름
  • 3장 — 어댑터: map, filter, zip … 반복자를 받아 반복자를 내는 것
  • 4장 — 소비자: collect, sum, fold … 반복자를 끝까지 돌려 값을 내는 것
  • 5장 — 실전: 반복문을 반복자로, 정렬, 묶기

1장

클로저

문법 · 주변을 붙잡는다 · 빌림과 move · Fn · FnMut · FnOnce · 주고받기

클로저 — 이름 없는 함수

매개변수를 세로줄 | | 사이에 쓰고, 그 뒤에 본문을 씁니다. 타입은 대개 쓰지 않습니다 — 쓰이는 모습을 보고 컴파일러가 정합니다. 둘째 area 처럼 타입을 다 적을 수도 있고, 셋째 hello 처럼 매개변수가 없으면 || 만 씁니다.

함수클로저
fn add_one(x: i32) -> i32 { x + 1 }|x| x + 1

클로저는 주변을 붙잡는다

함수와 가장 다른 점입니다. 클로저는 자기가 만들어진 자리의 변수를 그대로 쓸 수 있습니다. 5부에서 중첩 함수가 못 하던 일입니다(E0434).

붙잡기(capture) — 클로저 값 안에 rate 가(또는 그 참조가) 들어 있다고 생각하면 됩니다. "코드 + 붙잡은 것" 이 클로저입니다.

타입은 한 번 정해지면 끝이다 — E0308

클로저는 제네릭이 아닙니다. 처음 불린 모습으로 타입이 정해지고, 다른 타입으로 다시 부를 수 없습니다.

읽는 법 — 오류는 4번 줄입니다: "정수를 기대했는데 &str 이 왔다". 첫 note: 가 까닭을 3번 줄에서 짚습니다 — 앞서 이 클로저를 {integer}(아직 폭이 정해지지 않은 정수) 인자로 불렀기 때문이라고. 둘째 note: 는 그 매개변수 x 가 적힌 2번 줄입니다. 여러 타입을 받아야 한다면 클로저가 아니라 제네릭 함수로 씁니다(10부 1장).

읽기만 하면 빌린다

클로저는 필요한 만큼만 붙잡습니다. 읽기만 하면 불변으로 빌립니다. 주인은 그동안에도 값을 읽을 수 있습니다.

고치면 가변으로 빌린다

주변 변수를 고치는 클로저는 그것을 가변으로 빌립니다. 부를 때마다 자기 상태가 바뀌므로 클로저를 담은 변수에도 mut 가 필요합니다.

빌림 규칙은 클로저에도 그대로 — E0502

클로저가 가변으로 빌리고 있는 동안에는 주인도 그 값을 읽을 수 없습니다. 클로저를 마지막으로 쓴 뒤에야 빌림이 끝납니다.

읽는 법 — 세 자리를 짚습니다. 3번 줄: 클로저가 total 을 쓰므로 여기서 가변 빌림이 시작된다. 6번 줄: 그런데 여기서 불변으로 빌리려 한다. 7번 줄: 가변 빌림은 여기서 또 쓰인다 (mutable borrow later used here) — 그래서 6번 줄은 아직 빌림 한가운데입니다.
앞 슬라이드가 통과한 까닭 — 거기서는 add 를 다 쓴 뒤에 total 을 읽었습니다.

move — 가져가서 붙잡는다

클로저 앞에 move 를 쓰면 쓰는 변수를 빌리지 않고 가져옵니다. 클로저가 그 값의 주인이 됩니다. 클로저를 만든 함수보다 클로저가 오래 살아야 할 때 필요합니다(클로저를 돌려주는 함수에서 씁니다).

두 번 불렀다 — move 는 붙잡는 방법만 바꿉니다. 이 클로저는 가져온 names 를 읽기만 하므로 몇 번이든 부를 수 있습니다.

가져간 뒤에는 밖에서 못 쓴다 — E0382

평소의 이동과 같습니다. 클로저로 옮겨 간 값은 원래 이름으로 더 쓸 수 없습니다.

읽는 법 — 2번 줄: names 의 타입은 Copy 가 아니라서 이동한다. 3번 줄: 클로저가 names 를 쓰므로 값이 클로저 안으로 옮겨 갔다(value moved into closure here). 6번 줄: 옮긴 뒤에 빌리려 한다. help: 는 밖에서도 써야 한다면 옮기기 전에 복제해 그 복제본을 클로저에 주라고 권합니다.
스레드에서 다시 본다 — thread::spawn(move || …) 의 move 가 이것입니다. 15부 1장에서 봅니다.

세 가지 클로저 — Fn · FnMut · FnOnce

클로저를 부르는 방법은 세 트레이트로 나뉩니다. 본문이 붙잡은 것을 어떻게 다루느냐를 보고 컴파일러가 그 클로저가 구현하는 트레이트를 정합니다. 예의 첫 둘은 앞에서 본 클로저이고, 셋째는 한 번만 부를 클로저에서 나옵니다.

본문이 붙잡은 것을구현하는 트레이트부를 수 있는 횟수예
읽기만 한다Fn · FnMut · FnOnce몇 번이든|| names.len()
고친다FnMut · FnOnce몇 번이든(mut 변수에 담아)|n: i32| total += n
밖으로 내보낸다(써 버린다)FnOnce 만한 번move || name
포함 관계 — 모든 클로저는 FnOnce 입니다(적어도 한 번은 부를 수 있습니다). 붙잡은 것을 밖으로 내보내지 않으면 FnMut 이기도 하고, 고치지도 않으면 Fn 이기도 합니다. move 는 "어떻게 붙잡는가" 이고 이 셋은 "붙잡은 것으로 무엇을 하는가" 라서 서로 다른 축입니다 — move 로 가져가도 읽기만 하면 Fn 입니다(move — 가져가서 붙잡는다). 이어지는 슬라이드들이 받는 쪽에서 하나씩 확인합니다.

클로저를 받는 함수

매개변수 타입에 impl Fn(i32) -> i32 라고 씁니다(impl 트레이트 는 10부 2장). 클로저도, 같은 모양의 보통 함수도 받습니다.

5부의 fn(i32) -> i32 와 다른 점 — 소문자 fn 은 함수 포인터라는 타입 하나이고, 대문자 Fn 은 트레이트입니다. Fn 으로 받으면 위처럼 주변(offset)을 붙잡은 클로저와 보통 함수 double 을 둘 다 받습니다 — (10 + 3) + 3 은 16, (10 * 2) * 2 는 40.

Fn 자리에 고치는 클로저를 넘기면 — E0594

Fn 으로 받겠다는 것은 "붙잡은 것을 읽기만 하는 클로저" 를 받겠다는 뜻입니다. 붙잡은 변수를 고치는 클로저는 거기에 맞지 않습니다.

읽는 법 — 9번 줄: Fn 클로저 안에서는 붙잡은 변수 calls(6번 줄, 클로저 밖에서 선언)에 대입할 수 없다. 8번 줄: many 가 FnMut 가 아니라 Fn 을 기대한다. 1번 줄의 꼬리표가 고칠 곳입니다 — "Fn 대신 FnMut 를 받도록 바꿔라". 다음 슬라이드가 그렇게 받습니다.

상태를 고치는 클로저를 받으려면 FnMut

넘겨받은 클로저가 자기 상태를 고칠 수 있게 하려면 FnMut 로 받고, 매개변수에 mut 를 붙입니다.

세 번 불렸다 — 부를 때마다 그때의 길이(0, 1, 2)에 10 을 곱한 값이 log 에 들어갔습니다. repeat 가 끝나 클로저가 사라진 뒤라 main 이 log 를 다시 읽을 수 있습니다.

한 번만 부를 클로저는 FnOnce

붙잡은 값을 밖으로 내보내는 클로저는 한 번만 부를 수 있습니다. 그런 것까지 받으려면 FnOnce 로 받습니다 — 가장 너그러운 조건입니다.

FnOnce 를 두 번 부르면 — E0382

첫 호출에서 클로저가 통째로 소비됩니다. 붙잡은 name 이 이미 밖으로 나갔기 때문입니다.

읽는 법 — 5번 줄의 호출에서 consume 이 옮겨 갔고, 6번 줄에서 그것을 다시 썼습니다. 첫 note: 가 까닭을 3번 줄에서 짚습니다 — "이 클로저는 name 을 자기 환경 밖으로 옮기므로 한 번 넘게 부를 수 없다". 둘째 note: 는 그 결과입니다 — "이 값은 FnOnce 를 구현하므로 부르면 값이 옮겨 간다".

읽기만 하는 클로저는 세 자리에 다 들어간다

표의 "구현하는 트레이트" 칸을 돌려서 확인합니다. 받는 쪽이 FnOnce · FnMut · Fn 인 함수 셋에 같은 모양의 클로저를 넘겨 봅니다.

출력 — 앞의 세 줄은 길이 2 를 두 번 불러 더한 4, 4 와 한 번 부른 2 입니다. 끝 줄은 calls 가 1, 2 로 올라 더한 3 과, 한 번 더 올라 3 이 된 값입니다.
받는 쪽은 필요한 만큼만 요구한다 — FnOnce 자리에는 읽는 것도, 고치는 것도, 내보내는 것 (앞에서)도 들어갑니다. FnMut 자리에는 읽는 것과 고치는 것이, Fn 자리에는 읽는 것만 들어갑니다. 그래서 한 번만 부를 함수는 FnOnce 로 받습니다.

클로저를 돌려주는 함수

반환 타입에도 impl Fn(…) 을 씁니다(10부 2장의 -> impl 트레이트). 돌려주는 클로저가 함수의 지역 변수(n)를 쓴다면 move 로 가져갑니다 — 함수가 끝나면 n 은 사라지니까요.

저마다 자기 n 을 갖는다 — add5 는 5 를, add100 은 100 을 가져가 붙잡고 있습니다. move 를 빼먹어 지역 변수를 빌린 채 내보내려 할 때의 오류(E0373)는 스레드에 클로저를 넘기는 15부 1장에서 봅니다.

클로저 여럿을 한 벡터에

클로저는 하나하나가 서로 다른 이름 없는 타입입니다. 한 벡터에 담으려면 트레이트 객체 Box<dyn Fn(i32) -> i32> 로 만듭니다. dyn 은 10부 5장에서 봤고, 값을 힙에 두는 Box 는 14부 1장에서 봅니다.

22 — 5 에 1 을 더해 6, 두 배 해서 12, bonus 10 을 더해 22 입니다. 셋째 클로저만 주변을 붙잡았지만 셋 다 같은 벡터에 들어갔습니다.

퀴즈 — 클로저

Q. let mut add = |n: i32| total += n; 을 받으려는 함수의 매개변수는 Fn, FnMut, FnOnce 가운데 무엇이어야 할까요?

A. FnMut(또는 더 너그러운 FnOnce)입니다. 붙잡은 total 을 고치므로 Fn 자리에는 들어가지 못합니다(E0594). 여러 번 부르려면 FnMut 로 받습니다(세 자리에 넘겨 보기).

2장

Iterator 트레이트

next 하나 · iter · iter_mut · into_iter · 게으르다 · 내 반복자 만들기

반복자는 next 하나로 움직인다

반복자(iterator)는 next() 를 부를 때마다 다음 값을 Some 으로, 다 떨어지면 None 을 주는 것입니다. 그것이 전부입니다.

iter() — 4부에서 미뤄 둔 그 메서드입니다. 벡터의 원소를 앞에서부터 차례로 빌려 주는 반복자를 만듭니다. next 는 반복자의 자리를 한 칸 옮기므로 반복자를 담은 변수는 가변 (let mut it)이어야 합니다.

for 는 next 를 대신 불러 준다

for 반복문은 반복자에서 None 이 나올 때까지 next 를 부르는 문법입니다. 같은 일을 for 로 한 번, 손으로 풀어 한 번 씁니다. 두 줄이 같게 찍힙니다.

while let — next() 가 Some 을 주는 동안 속을 꺼내 돌고, None 이 나오면 끝납니다(7부 5장).

세 가지 반복 — 빌려서, 고치며, 가져가며

모음에서 반복자를 얻는 메서드는 셋이고, 소유권의 세 가지 모양과 그대로 맞습니다.

메서드원소의 타입for 로 쓰면끝난 뒤 모음은
iter()&Tfor x in &v그대로
iter_mut()&mut Tfor x in &mut v고쳐진 채로
into_iter()Tfor x in v없다(소비됨)
출력 — 첫 줄의 3 3 은 iter() 로 읽은 길이이고, 그 뒤의 벡터는 iter_mut() 로 ! 를 붙인 뒤의 모습입니다. 둘째 줄은 into_iter() 가 내준 String 입니다.

반복자는 게으르다

map 은 "이렇게 바꿀 것" 이라는 계획을 담은 새 반복자를 돌려줄 뿐, 아무것도 돌리지 않습니다. 누군가 next 를 불러야 일이 일어납니다.

경고를 읽는다 — 오류가 아니라 경고라서 프로그램은 만들어졌고, 끝 만 찍혔습니다. 경고는 3–6번 줄의 Map 을 쓰지 않았다고 하고, note: 가 까닭을 말합니다 — "반복자는 게으르며 소비하지 않으면 아무 일도 하지 않는다". help: 의 let _ = 는 경고만 끄는 방법이라 여기서 바라는 것이 아닙니다. 다음 슬라이드처럼 소비자를 붙입니다.

소비해야 돈다

끝에 collect() 를 붙였습니다. collect 가 next 를 끝까지 부르고, 그제야 map 의 클로저가 원소마다 돕니다.

어댑터와 소비자 — map 처럼 반복자를 받아 반복자를 내는 것이 어댑터(3장), collect 처럼 끝까지 돌려 값을 내는 것이 소비자(4장)입니다. 사슬은 늘 소비자로 끝납니다.

내 타입을 반복자로 만든다

Iterator 트레이트는 내줄 값의 타입 Item 과 next 하나만 구현하면 됩니다. 그러면 for 에 쓸 수 있고, 구현하지 않은 filter 와 sum 도 부를 수 있습니다.

  • type Item = u32; — 이 반복자가 내주는 값의 타입입니다. 10부 6장의 연관 타입이고, next 는 Option<Self::Item> 을 돌려줍니다. impl Iterator<Item = u32> 의 Item 이 이것입니다.
  • 기본 메서드 — filter 와 sum 은 10부 2장에서 본 "트레이트의 기본 구현" 이라 따로 쓰지 않았습니다. 둘째 줄의 30 은 10 부터 1 까지에서 짝수만 더한 값입니다.

반복자를 내주는 것들

범위, 문자열의 글자·줄·조각 — 표준 라이브러리 곳곳에서 반복자가 나옵니다. 전부 같은 방법으로 다룹니다.

퀴즈 — Iterator

Q. v.iter().map(|x| { println!("{x}"); x * 2 }); 는 무엇을 찍을까요?

A. 아무것도 찍지 않습니다. map 은 게을러서 소비자가 없으면 클로저가 한 번도 돌지 않습니다(반복자는 게으르다). 컴파일러도 "쓰지 않은 Map" 이라고 경고합니다.
