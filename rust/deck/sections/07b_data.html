4장

match 전부

풀어 헤치기 · 겹친 패턴 · @ · 가드 · .. · 슬라이스 패턴 · 상수와 범위 · 이름의 함정 · 빌려서 가르기 · 고치면서 가르기

구조체를 풀어 헤친다

4부에서는 정수와 문자를 값 · 범위 · | 로 가르는 데까지 봤습니다. 패턴(pattern)은 값만이 아니라 값의 모양을 적는 문법이고, 이 장에서 그 나머지를 전부 봅니다. 먼저 구조체를 풀어 헤칩니다(destructuring). 어떤 필드는 값과 견주고, 어떤 필드는 이름으로 꺼냅니다.

읽는 법 — x: 0 은 필드를 0 과 견주고, y 한 글자는 y: y 를 줄인 것으로 필드의 값을 변수 y 로 받습니다. 원점은 네 패턴 모두에 맞지만, 4부에서 본 대로 위에서부터 처음 맞는 갈래 하나만 실행합니다.

튜플 패턴과 가드

4부에서 튜플을 값과 _ 로 갈랐습니다. 자리에 이름을 쓰면 그 값을 받습니다. 패턴만으로 못 적는 조건("둘 다 양수")은 4부에서 본 가드(guard), 곧 패턴 뒤의 if 조건 으로 붙입니다.

읽는 법 — (4, -4) 는 둘째 갈래의 패턴에는 맞지만 가드가 거짓이라 아래로 내려가고, 마지막 갈래에서 "그 밖" 이 됩니다. 가드가 거짓이면 그 갈래는 맞지 않은 것으로 칩니다.

겹친 것을 한 번에

패턴은 겹쳐 쓸 수 있습니다. 열거형 안의 구조체 안의 튜플까지 한 줄로 내려갑니다. match 를 여러 겹 쓰지 않아도 됩니다.

| 와 .. — | 는 4부에서 본 "이거나" 이고, 값뿐 아니라 모양 사이에도 씁니다. .. 은 나머지를 건너뛰며, 나머지는 상관없다에서 따로 봅니다. main 끝의 match 는 첫 도형에서 반지름만 꺼냅니다 — 한 변형만 볼 때의 더 짧은 문법은 5장에서 봅니다.

@ — 견주면서 이름도 붙인다

범위 패턴은 "맞았다" 는 것만 알려 주고 값에 이름을 붙이지 않습니다. 이름 @ 패턴 은 패턴에 맞는지 보면서 그 값을 이름에 담습니다.

가드 — 꺼낸 값에 조건을 건다

4부와 튜플 패턴에서는 수에 가드를 붙였습니다. 이번에는 변형으로 가른 뒤, 꺼낸 속의 값에 조건을 겁니다. t 를 빌려서 가르므로 c 와 f 는 참조이고, 견줄 때는 *c 로 값을 봅니다.

가드는 빠짐없음 검사에 들지 않는다 — E0004

양수·음수·영을 가드로 전부 적었습니다. 사람이 보기에는 빠진 것이 없지만, 컴파일러는 가드의 조건을 따져 보지 않습니다.

읽는 법 — 3장에서 본 E0004 인데, 빠졌다는 것이 i32::MIN..=i32::MAX, 곧 i32 전부입니다. 까닭은 마지막 note: 에 있습니다. 가드가 붙은 갈래는 빠짐없음 검사에 세지 않습니다.
고치면 — 마지막 갈래에서 가드를 떼고 _ => "영" 으로 씁니다. 튜플 패턴과 가드와 앞 슬라이드의 예제가 마지막 갈래를 가드 없이 둔 까닭입니다.

.. — 나머지는 상관없다

필드가 많은 구조체에서 몇 개만 꺼낼 때, 튜플의 처음과 끝만 필요할 때 .. 을 씁니다. 패턴은 let 의 왼쪽에도 씁니다 — 3부의 튜플 풀기가 그것이었고, 6장에서 정리합니다.

_ 와 .. — _ 는 자리 하나를, .. 은 남은 자리를 몇 개든 건너뜁니다. 16번 줄은 &c 를 풀었으므로 host 와 port 는 참조이고, c 에서 옮겨 간 것은 없습니다. 구조체 패턴에서 .. 없이 필드를 빼면 나는 오류는 26부의 .. 없이 필드 하나를 뺐다에서 봅니다.

슬라이스 패턴 — 길이와 양 끝으로 가른다

슬라이스는 원소의 개수와 자리로 가를 수 있습니다. [first, .., last] 는 "둘 이상, 처음과 끝" 이고, [head, tail @ ..] 는 "첫 원소와 나머지" 입니다.

tail @ .. — 앞에서 본 @ 로, .. 이 건너뛴 나머지에 이름을 붙였습니다. sum 은 머리를 하나씩 떼며 나머지로 자기를 다시 부르고, 빈 슬라이스에서 멈춥니다.

상수도 패턴이 된다 — 범위의 끝에도

리터럴뿐 아니라 이름 붙은 상수도 패턴이 됩니다. 범위의 끝에도 쓸 수 있습니다. 4부에서 쓴 a..=b 와 달리 1..MAX 는 끝(MAX)을 뺀 범위입니다.

함정 — 소문자 이름은 견주지 않고 받는다

변수 target 의 값과 견주려고 패턴에 target 을 썼습니다. 그런데 패턴 안의 변수 이름은 4부에서 본 "이름으로 받기" 입니다. 무엇이든 맞고, 그 값이 새 target 에 담깁니다.

읽는 법 — 출력 마지막 줄에서 바깥의 target 은 5 그대로입니다. 갈래 안의 target 은 바깥 것을 가린 새 변수입니다.
변수의 값과 견주려면 가드를 씁니다 — x if x == target => …. 앞 슬라이드의 MAX 가 견주는 패턴이 될 수 있었던 것은 let 변수가 아니라 const 로 선언한 상수였기 때문입니다.

값을 match 하면 속이 옮겨 간다 — E0382

지금까지의 예제는 대부분 참조를 받아 갈랐습니다. 값을 그대로 가르면, 갈래 Text(s) 가 속의 String 을 s 로 옮겨 받습니다. 그 뒤에 msg 는 온전하지 않습니다.

읽는 법 — 6부에서 본 부분 이동의 E0382 입니다. 11번 줄의 s 가 속의 String 을 옮겨 받았고(partially moved), 14번 줄이 msg 전체를 빌리려 했습니다. 새로 볼 것은 help: 입니다. ref s 로 옮기지 말고 빌려서 받으라고 권합니다. 다음 슬라이드는 같은 일을 & 하나로 합니다.

빌려서 가른다 — match &값

참조를 match 하면 패턴으로 꺼낸 것도 참조가 됩니다. 아무것도 옮겨 가지 않으므로 뒤에서 계속 쓸 수 있습니다. 3장부터 이 장의 예제 대부분이 써 온 모양입니다.

ref — 앞 슬라이드의 help: 가 권한 Text(ref s) 는 그 이름 하나만 빌려서 받는 문법입니다. 참조를 match 하면 꺼내는 이름 전부가 저절로 그렇게 됩니다. 다른 코드에서 ref 를 보면 이 뜻입니다.

고치면서 가른다 — match &mut 값

가변 참조를 match 하면 꺼낸 것이 &mut 입니다. 6부에서 본 대로 *balance 로 값에 닿아, 변형 속의 값을 제자리에서 고칩니다.

Option 둘도, 겹친 Option 도 한 번에 가른다

값 둘을 튜플로 묶어 조합을 한 번에 가릅니다. 겹친 Option 도 패턴으로 곧바로 내려갑니다.

_ 갈래가 없다 — 컴파일러는 겹친 패턴도 조합까지 따져 빠짐없는지 확인합니다. 네 조합과 세 경우를 다 적었으므로 두 match 모두 _ 없이 컴파일됐습니다.

패턴 문법 한눈에

왼쪽 모양이 오른쪽 값에 맞습니다. 위 다섯 줄은 대부분 4부에서 본 것이고, 그 아래가 이 장에서 더한 것입니다.

패턴맞는 것
5 · 'a' · MAX그 값
1..=9 · 'a'..='z'범위 안의 값
x무엇이든 — x 로 받는다
_무엇이든 — 받지 않는다
A | BA 이거나 B
(a, _, c) · [first, .., last]튜플 · 슬라이스의 자리
Point { x, y: 0 } · Point { x, .. }구조체의 필드
Some(n) · Shape::Circle(r)열거형의 변형과 그 속
n @ 1..=9범위에 맞으면 n 으로 받는다
패턴 if 조건패턴에 맞고 조건도 참

전부 4부와 이 부의 예제에서 돌려 본 것입니다.

퀴즈 — match

Q. match msg { Message::Text(s) => … } 뒤에도 msg 를 쓰려면 어떻게 고칠까요?

A. match &msg 로 빌려서 가릅니다. 그러면 s 는 &String 이 되고 아무것도 옮겨 가지 않습니다(빌려서 가른다).

5장

if let · let else · while let

한 가지 모양만 볼 때 · 안 맞으면 빠져나가기 · 맞는 동안 돌기 · matches! · let 사슬 · 무엇을 쓸까

if let — 한 가지 모양에만 관심이 있을 때

match 는 모든 경우를 적어야 합니다. 4장의 겹친 것을 한 번에에서도 한 변형만 보려고 빈 갈래 => {} 를 적었습니다. 한 경우만 다루고 나머지는 지나칠 때는 if let 패턴 = 값 이 짧습니다.

잃는 것 — 빠짐없음 검사입니다. 변형이 늘어도 if let 은 조용합니다.

안 맞으면 else, 다른 모양은 else if let

안 맞았을 때의 일은 else 에 씁니다. else if let 으로 다른 모양을 이어 볼 수도 있습니다. 세 갈래를 넘으면 match 가 낫습니다.

let else — 안 맞으면 빠져나간다

if let 은 꺼낸 값을 블록 안에서만 씁니다. 1부에서 먼저 본 let … else 는 맞으면 그 값을 아래에서 계속 쓰고, 안 맞으면 else 블록에서 함수를 떠납니다. 들여쓰기가 깊어지지 않습니다.

읽는 법 — "3 4" 는 쉼표가 없어 첫 else 에서, "3, 넷" 은 "넷" 이 수가 아니라 셋째 else 에서 None 을 돌려주고 떠났습니다.
처음 보는 것 둘 — split_once(',') 는 첫 쉼표에서 둘로 쪼개고, 쉼표가 없으면 None 을 줍니다(8부). parse 는 성공하면 Ok(값), 실패하면 Err(까닭) 을 줍니다(9부).

else 는 반드시 떠나야 한다 — E0308

else 블록이 떠나지 않고 끝나면 그 아래에서 n 은 무슨 값일까요? 정할 수 없습니다. 그래서 else 는 return · break · continue · panic! 처럼 돌아오지 않는 것으로 끝나야 합니다.

읽는 법 — 번호는 타입이 맞지 않을 때의 E0308 이고, 첫 줄이 "else 가 떠나지 않는다(does not diverge)" 입니다. ! 는 5부에서 본 "돌아오지 않음" 타입입니다. ! 를 기대했는데 () 를 찾았다고 하고, help: 는 return 이나 panic! 을 넣으라고 합니다.

while let — 맞는 동안 돈다

패턴이 맞는 동안 되풀이합니다. "꺼낼 것이 있는 동안" 을 그대로 적은 모양입니다.

pop() 은 벡터의 맨 끝 원소를 떼어 Some(값) 으로 주고, 비었으면 None 을 줍니다. 벡터는 8부에서 봅니다.

matches! — 이 모양인가

값을 꺼낼 필요 없이 "이 변형인가" 만 알고 싶을 때 matches! 가 bool 을 줍니다. 가드도 붙일 수 있습니다.

let 사슬 — if let 과 조건을 잇는다

if let 여럿과 보통 조건을 && 로 이어 씁니다. 앞에서 꺼낸 값을 뒤의 조건에서 쓸 수 있습니다. 예전에는 if let 을 겹쳐 써야 했습니다.

읽는 법 — "port=0" 은 두 let 에는 맞았지만 마지막 n > 0 에서, "port" 는 = 가 없어 첫 let 에서 끊겼습니다. 어느 고리에서 끊기든 else 로 갑니다.

let 사슬은 2024 에디션부터

같은 문법을 2021 에디션으로 컴파일하면 거절됩니다. 에디션이 문법을 가르는 예입니다 (1부 4장).

읽는 법 — 번호가 없는 오류이고, 메시지가 곧 까닭입니다. let 사슬은 2024 에디션부터 쓸 수 있다고 합니다. 명령 줄이 다른 예제와 달리 --edition 2021 입니다.

무엇을 쓸까

4장과 이 장에서 본 도구를 한 표에 놓습니다. 왼쪽에서 상황을 찾아 오른쪽을 씁니다.

상황쓸 것
모든 경우를 다룬다match
한 경우만 다루고 나머지는 지나친다if let
한 경우가 아니면 함수를 떠난다let … else
맞는 동안 되풀이한다while let
맞는지 여부만 필요하다matches!
모양과 조건을 함께 본다가드, let 사슬
열거형을 가를 때는 match 먼저 — 빠짐없음 검사를 받을 수 있기 때문입니다. 나머지는 그것이 번거로울 때의 지름길입니다.

퀴즈 — if let · let else

Q. let Ok(n) = s.parse::<i32>() else { println!("실패"); }; 는 왜 컴파일되지 않을까요?

A. else 블록이 떠나지 않고 끝나기 때문입니다. 그러면 아래에서 n 이 없는 채로 계속 가게 됩니다. else 는 return 이나 panic! 처럼 돌아오지 않는 것으로 끝나야 합니다 (E0308).

6장

패턴이 쓰이는 모든 자리

let · 매개변수 · for · 클로저 · 안 맞을 수 있는 패턴 · 상태 기계 · 이 부의 정리

let 의 왼쪽은 패턴이다

패턴은 match 와 if let 만의 것이 아닙니다. 지금까지 써 온 let x = … 의 x 가 가장 단순한 패턴이었고, 3부의 튜플 풀기도 패턴이었습니다. 튜플 · 배열 · 구조체를 그 자리에서 풀어 헤칩니다.

읽는 법 — 출력 마지막 줄은 16번 줄에서 1 과 9 를 맞바꾼 뒤 하나를 더하고 하나를 뺀 값입니다. let 없이 대입의 왼쪽에 쓴 (lo, hi) 도 풀어 헤치기입니다.

매개변수, for, 클로저의 자리도 패턴

함수의 매개변수, for 의 변수, 클로저의 매개변수 — 값을 받는 자리는 전부 패턴입니다. 받으면서 곧바로 풀어 헤칩니다.

클로저 — |매개변수| 식 은 이름 없는 함수입니다. 12부에서 봅니다. 여기서는 그 매개변수 자리도 패턴이라는 것만 봅니다. 출력 마지막 줄 끝의 3 이 그 클로저가 낸 값입니다.

안 맞을 수 있는 패턴은 let 에 못 쓴다 — E0005

let · 매개변수 · for 의 자리에는 조건이 하나 있습니다. 반드시 맞는 패턴이어야 합니다. let Some(n) = maybe; 는 maybe 가 None 이면 갈 곳이 없습니다.

읽는 법 — 빠진 것을 말하는 방식은 E0004 와 같습니다. None 이 다뤄지지 않았다고 합니다. 첫 note: 는 let 이 "반드시 맞는 패턴(irrefutable pattern)" 을 요구한다고 하고, help: 는 5장의 let … else 를 권합니다.
반드시 맞는 패턴(irrefutable)안 맞을 수 있는 패턴(refutable)
예x · (a, b) · Point { x, y }Some(n) · 5 · [a, b](슬라이스)
쓸 수 있는 곳어디서나 — let · 매개변수 · for 는 이것만 받는다match · if let · let else · while let

패턴의 두 종류와 그것을 받는 자리입니다. 이 오류를 고치는 길은 오른쪽 아래 칸의 문법들입니다. 같은 번호를 for 의 자리에서 만나면 26부의 for 의 자리에 Some(…) 패턴을 적었다에서 봅니다.

상태 기계 — 이 부의 전부를 한 예제로

문의 상태(열거형)와 일어난 일(열거형)을 튜플로 묶어 match 합니다. 변형 속의 데이터, 가드, "그 밖" 갈래가 한자리에 모입니다.

읽는 법 — Locked { code: 42 } 가 세 번 이어집니다. 잠근 직후, 잠긴 문을 민 뒤, 틀린 번호 7 을 넣은 뒤입니다. 뒤의 둘은 마지막 갈래 (door, _) => door 로 내려가 받은 상태를 그대로 돌려준 것입니다. 7 은 패턴에는 맞았지만 가드가 거짓이었습니다.
상태를 타입으로 — 잠긴 문에만 비밀번호가 있습니다. "열려 있는데 잠겨 있는" 상태는 표현할 수조차 없습니다.

상태마다 타입을 하나씩 두어 순서를 어긴 호출까지 막는 설계는 19부의 상태를 타입으로 옮기면에서 봅니다.

이 부를 세 줄로

  1. 구조체는 값들을 "그리고" 로 묶고, 열거형은 "또는" 으로 가른다. 둘을 겹쳐 자료의 실제 모양을 적고, impl 로 메서드를 붙인다.
  2. 패턴은 값의 모양을 적는 문법이고, 값을 받는 모든 자리에 쓰인다.
  3. match 는 빠짐없이 다뤘는지를 컴파일러가 확인한다. 경우를 더하면 고칠 곳을 알려 준다.
다음 — 8부는 문자열과 컬렉션입니다. Vec 의 pop 처럼 값이 없을 수 있는 메서드는 Option 을 돌려주고, 이 부의 패턴으로 그 속을 꺼냅니다. Option 과 Result 로 실패를 다루는 법은 9부, 타입에 공통된 능력을 붙이는 트레이트는 10부입니다.

퀴즈 — 패턴의 자리

Q. let (a, b) = pair; 는 되는데 let Some(n) = maybe; 는 왜 안 될까요?

A. 튜플 패턴은 어떤 튜플에도 맞지만, Some(n) 은 None 일 때 맞지 않습니다. let 은 반드시 맞는 패턴만 받습니다(E0005). if let 이나 let … else 를 씁니다.
