1장

첫 프로그램

파일 하나 · rustc · main 함수 · 주석 · 세미콜론 · 에디션

세 줄짜리 프로그램

Rust 프로그램은 main 이라는 함수에서 시작합니다. 소스 파일의 확장자는 .rs 입니다.

  • fn — 함수를 만드는 키워드. main 은 인자도 반환값도 없습니다.
  • println! — 한 줄을 찍고 줄을 바꿉니다. 끝의 ! 는 이것이 함수가 아니라 매크로라는 표시입니다.
  • 들여쓰기는 공백 네 칸이 관례입니다.

컴파일하고, 그다음에 돌린다

Rust 는 미리 컴파일하는 언어입니다. rustc 가 소스를 기계어 실행 파일로 바꾸고, 그 파일을 돌립니다. 인터프리터가 따로 없습니다.

hello.rs→ rustc→ hello (실행 파일)→ ./hello
실행 파일은 혼자 돕니다 — 만들어진 hello 는 Rust 가 설치되지 않은 같은 종류의 기계에 옮겨도 그대로 실행됩니다.

주석과 문장

컴파일러가 읽지 않는 글이 주석입니다. 문장(statement)은 세미콜론으로 끝납니다.

{name} — 중괄호 안에 변수 이름을 쓰면 그 값이 들어갑니다. 서식은 3장에서 자세히 봅니다.

세미콜론을 빼먹으면

첫 컴파일 오류를 일부러 내 봅니다. 2번 줄 끝에 세미콜론이 없습니다.

오류 읽는 법 — --> 뒤가 파일:줄:칸이고, ^ 가 문제의 자리를 가리킵니다. help: 는 고치는 법입니다. Rust 컴파일러는 대개 답을 같이 알려 줍니다.

느낌표를 빼먹으면 — E0423

println 이라는 함수는 없습니다. 있는 것은 매크로 println! 입니다.

오류 번호 — error[E0423] 같은 번호가 붙은 오류는 rustc --explain E0423 으로 긴 설명을 볼 수 있습니다. 문법 오류(앞 장)에는 번호가 없습니다.

에디션 — 같은 컴파일러, 다른 문법 판

Rust 는 옛 코드를 깨지 않으려고 문법의 판(에디션)을 나눕니다. 2015 에디션에서는 async 가 그냥 이름이라 변수로 쓸 수 있습니다.

rustc 의 기본값은 2015 — --edition 을 주지 않으면 가장 옛 판으로 컴파일합니다. 그래서 이 책의 명령에는 늘 --edition 2024 가 붙어 있습니다. cargo 로 만든 프로젝트는 설정 파일에 에디션이 적혀 있어 따로 줄 필요가 없습니다.

같은 코드를 2024 에디션으로

2018 에디션부터 async 는 키워드입니다. 같은 파일이 이제는 컴파일되지 않습니다.

에디션은 파일(크레이트)마다 고릅니다 — 옛 에디션으로 쓴 라이브러리와 새 에디션으로 쓴 프로그램을 한데 묶어 쓸 수 있습니다. 에디션의 역사는 1부에서 봅니다.
