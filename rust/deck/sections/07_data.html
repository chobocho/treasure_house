7부

구조체·열거형·패턴 매칭

이름 붙은 묶음 · 메서드 · 이것 또는 저것 · match 의 모든 것 · if let · let else

이 부에서 할 일

지금까지는 정수·문자열·튜플 같은 주어진 타입만 썼습니다. 이 부는 내 타입을 만드는 두 가지 방법을 봅니다. 구조체는 여러 값을 "그리고" 로 묶고, 열거형은 "또는" 으로 가릅니다. 그리고 그 속을 꺼내 보는 도구가 패턴 매칭입니다.

  • 1장 — 구조체: 정의, 만들기, 갱신 문법, 튜플 구조체
  • 2장 — 메서드: impl, &self · &mut self · self, 연관 함수
  • 3장 — 열거형: 데이터를 가진 변형, Option 의 정체
  • 4장 — match 전부: 풀어 헤치기, @, 가드, 슬라이스 패턴
  • 5장 — if let · let else · while let
  • 6장 — 패턴이 쓰이는 모든 자리

1장

구조체

정의와 만들기 · 통째로 가변 · 줄여 쓰기 · 갱신 문법 · 튜플 구조체 · 찍어 보기

구조체 — 이름 붙은 필드의 묶음

struct 로 타입을 정의하고, 이름 { 필드: 값, … } 으로 값을 만듭니다. 필드는 점으로 읽습니다. 타입 이름은 대문자로 시작합니다(UpperCamelCase).

필드를 빠뜨릴 수 없다 — E0063

값을 만들 때는 모든 필드를 채워야 합니다. "초기화되지 않은 필드" 라는 것이 없습니다.

고치려면 값 전체가 mut

가변은 변수에 붙는 성질입니다. 필드 하나만 가변으로 할 수는 없습니다. let mut 로 묶으면 모든 필드를 고칠 수 있습니다.

mut 가 없으면 필드도 못 고친다 — E0594

3부의 "기본은 불변" 이 구조체에도 그대로입니다.

이름이 같으면 한 번만 쓴다

변수 이름과 필드 이름이 같을 때 name: name 대신 name 만 씁니다. 생성 함수에서 자주 나옵니다.

갱신 문법 — 나머지는 저기서

..다른값 은 "적지 않은 필드는 이 값에서 가져온다" 입니다. 몇 개만 다른 값을 만들 때 씁니다.

가져온 필드는 옮겨 간다 — E0382

갱신 문법은 복사가 아니라 필드별 이동입니다. String 처럼 복사되지 않는 필드는 새 값으로 옮겨 가고, 원래 값의 그 필드는 쓸 수 없게 됩니다.

부분 이동 — 6부에서 튜플로 본 것과 같습니다. 오류는 14번 줄 하나뿐이고, 13번 줄의 base.port 는 걸리지 않았습니다. 원본을 남기려면 옮겨 갈 필드를 clone() 으로 복제해 직접 적습니다.

튜플 구조체 — 필드 이름 없이 타입 이름만

필드에 이름을 붙일 것까지는 없지만 타입은 구별하고 싶을 때 씁니다. 필드는 .0, .1 로 읽습니다.

속이 같아도 다른 타입이다 — E0308

Meters 와 Seconds 는 둘 다 f64 하나를 감쌌지만 서로 다른 타입입니다. 인자 순서를 바꾸면 컴파일러가 잡습니다. 그냥 f64 둘이었다면 조용히 틀린 답이 나왔을 것입니다.

타입으로 실수를 막는다 — 값 하나를 감싼 튜플 구조체(newtype)는 Rust 에서 흔한 관용구입니다 (10부에서 다시 봅니다).

구조체 찍어 보기 — derive(Debug)

구조체는 그냥은 찍을 수 없습니다. #[derive(Debug)] 를 붙이면 {:?} 로, {:#?} 로는 여러 줄로 펴서 찍습니다. 구조체 안에 구조체를 넣을 수도 있습니다.

derive 는 "이 기능을 이 타입에 맞게 만들어 달라" 는 부탁입니다. 무엇이 만들어지는지, Debug 말고 무엇을 부탁할 수 있는지는 10부에서 봅니다.

함수에 넘기기 — 빌려서

구조체도 다른 값과 같습니다. 읽기만 할 함수는 &Rect 로, 고칠 함수는 &mut Rect 로 받습니다(6부).

다음 장으로 — 이 함수들은 Rect 에 딸린 일입니다. 그런 것은 메서드로 만듭니다.

필드가 없는 구조체

값은 담지 않고 타입만 필요할 때 씁니다(10부의 트레이트를 구현할 자리 따위). 크기는 0 입니다.

퀴즈 — 구조체

Q. let secure = Config { port: 443, ..base }; 뒤에 base.port 와 base.host(String)를 쓸 수 있을까요?

A. base.port 는 됩니다(정수는 복사). base.host 는 안 됩니다 — secure 로 옮겨 갔습니다(가져온 필드는 옮겨 간다).

2장

메서드

impl · &self · &mut self · self · 연관 함수 · 이어 부르기

impl — 타입에 함수를 붙인다

impl 타입 { … } 안에 쓴 함수가 메서드입니다. 첫 매개변수 &self 가 "이 메서드를 부른 값" 입니다. 값.메서드() 로 부릅니다.

&self 는 self: &Rect 를 줄여 쓴 것입니다. 빌려서 읽기만 한다는 뜻입니다.

&mut self — 자기를 고치는 메서드

자기 필드를 고치려면 &mut self 로 받습니다. 부르는 쪽의 변수는 mut 여야 합니다.

불변 변수에서 &mut self 메서드를 부르면 — E0596

&mut self 메서드를 부르는 것은 가변 빌림입니다. c.hit() 은 c 를 가변으로 빌리려 하고, c 가 mut 가 아니면 빌릴 수 없습니다.

self — 자기를 가져가는 메서드

self 를 참조 없이 받으면 메서드가 그 값의 소유권을 가져갑니다. 값을 다른 것으로 바꿔 돌려주는 메서드에 씁니다 — 초안이 발행본이 되면 초안은 더 없습니다.

가져간 뒤에는 다시 부를 수 없다 — E0382

두 번 발행할 수 없다는 규칙이 타입에 적힌 셈입니다. 컴파일러가 지켜 줍니다.

읽는 법 — 15번 줄의 첫 호출에서 d 가 옮겨 갔고, 16번 줄이 그것을 다시 썼습니다. note: 는 까닭을 6번 줄에서 짚습니다 — publish 가 self 를 통째로 받기 때문입니다.

self 의 세 가지 모양

받는 모양뜻부른 뒤 원래 값은이럴 때
&self빌려서 읽는다그대로대부분의 메서드
&mut self빌려서 고친다고쳐진 채로상태를 바꿀 때
self가져간다없다다른 것으로 바꿔 낼 때
6부의 세 가지 그대로 — &T · &mut T · T 를 받는 함수와 같습니다. 메서드는 첫 인자를 점 앞에 쓰는 함수일 뿐입니다.

연관 함수 — self 가 없는 함수

impl 안에 self 없이 쓴 함수는 값이 아니라 타입에 딸립니다. 타입::함수() 로 부릅니다. 값을 만드는 new 가 대표입니다.

new 는 관례일 뿐 — 키워드가 아닙니다. Rust 에는 생성자 문법이 따로 없고, 값을 돌려주는 보통 함수를 씁니다. String::new() · Vec::new() 가 이것입니다.

이어 부르기

self 를 받아 고친 뒤 다시 돌려주는 메서드는 점으로 이어 쓸 수 있습니다. 설정이 많은 값을 만드는 흔한 모양입니다(빌더).

mut self — 가져온 값을 메서드 안에서 고치려고 붙였습니다. 5부에서 본 매개변수의 mut 와 같습니다. 부르는 쪽 변수는 mut 가 아니어도 됩니다.

점은 알아서 빌리고 따라간다

C · C++ 와 달리 . 과 -> 를 가려 쓰지 않습니다. 값이든, 참조든, Box 든 점 하나로 부릅니다. 메서드가 요구하는 모양에 맞게 컴파일러가 & 나 * 를 붙입니다.

Box 는 값을 힙에 두고 가리키는 포인터입니다(14부). 여기서는 "참조 말고 다른 포인터에서도 점 하나" 라는 것만 봅니다.

impl 블록은 여럿이어도 된다

한 타입의 impl 을 여러 블록으로 나눌 수 있습니다. 관련된 메서드끼리 묶을 때 씁니다. 10부의 트레이트 구현도 이렇게 따로 선 impl 블록입니다.

퀴즈 — 메서드

Q. fn publish(self) -> Published 를 부른 뒤, 그 값의 다른 메서드를 부를 수 있을까요?

A. 없습니다. self 로 받는 메서드는 값을 가져가므로 부른 뒤에는 그 변수를 쓸 수 없습니다 (E0382). 돌려받은 Published 를 쓰면 됩니다.

3장

열거형

이것들 가운데 하나 · 변형마다 다른 데이터 · 메서드 · 정수와 오가기 · Option 의 정체

열거형 — "이것들 가운데 하나"

enum 은 가능한 경우(변형, variant)를 늘어놓아 타입을 만듭니다. 값은 그 가운데 정확히 하나입니다. 타입::변형 으로 쓰고, match 로 가릅니다.

변형마다 다른 데이터를 가진다

C 의 enum 은 이름 붙은 정수일 뿐이지만, Rust 의 열거형은 변형마다 서로 다른 모양의 데이터를 담을 수 있습니다. match 가 변형을 가르면서 그 속을 꺼내 줍니다.

빌려서 갈랐다 — s 가 참조이므로 꺼낸 r · w · h 도 참조입니다. 4장의 빌려서 가른다에서 다시 봅니다.

열거형에도 메서드를 붙인다

구조체와 똑같이 impl 을 씁니다. 메서드 안에서 match self 로 변형을 가르는 모양을 자주 씁니다.

변형을 더하면 컴파일러가 빠진 곳을 찾아 준다 — E0004

동전에 50원을 더했습니다. 그것을 다루지 않은 match 는 전부 컴파일 오류가 됩니다. 고칠 곳을 찾아다닐 필요가 없습니다.

_ 를 아끼는 까닭 — _ => … 로 나머지를 뭉뚱그려 두면 이 도움을 받지 못합니다. 열거형을 가를 때는 변형을 전부 적는 편이 안전합니다.

변형 이름을 끌어와 짧게 쓴다

use 타입::{변형, …}; 으로 끌어오면 Light:: 를 붙이지 않아도 됩니다. Some · None · Ok · Err 를 그냥 써 온 것이 이 방식입니다.

정수로 바꾸기

데이터가 없는 열거형은 as 로 정수가 됩니다. 번호는 0 부터 차례로 붙고, 직접 줄 수도 있습니다.

정수에서 열거형으로는 as 가 안 된다 — E0605

반대 방향은 막혀 있습니다. 정수 9 에 해당하는 변형이 없을 수 있기 때문입니다.

직접 가르고, Option 으로 돌려준다

정수를 변형으로 바꾸는 함수를 match 로 씁니다. 맞는 것이 없으면 None 입니다.

Option 은 평범한 열거형이다

Option 은 언어에 박힌 것이 아니라 변형이 둘인 열거형입니다 — 값이 있는 Some(T) 와 없는 None. "없을 수 있다" 를 타입으로 적으므로 Rust 에는 null 이 필요 없습니다.

쓰는 법 전부는 9부에서 봅니다. 여기서는 "열거형 + match" 로 읽힌다는 것만 봅니다. <T> 는 "어떤 타입이든" 을 뜻하는 자리(제네릭)이고 10부에서 봅니다.

열거형의 크기

열거형 값은 가장 큰 변형이 들어갈 자리에, 어느 변형인지 적는 꼬리표를 더한 크기입니다.

  • 24 — 가장 큰 Rect 가 f64 둘로 16 바이트입니다. 꼬리표가 붙고, 전체 크기를 f64 의 8 바이트 단위에 맞추느라 8 이 늘었습니다.
  • 1 2 — Option<u8> 는 u8 한 바이트에 꼬리표 한 바이트입니다.
  • 8 8 — Option<&u8> 는 &u8 와 크기가 같습니다. 참조는 0 일 수 없으므로 None 을 0 으로 적으면 꼬리표가 필요 없습니다. "null 일 수 있는 포인터" 를 자리를 더 쓰지 않고 안전하게 쓰는 셈입니다.

"그리고" 는 구조체, "또는" 은 열거형

주문에는 물건 그리고 값 그리고 결제가 있습니다(구조체). 결제는 현금 또는 카드 또는 이체입니다(열거형). 둘을 겹쳐 실제 자료의 모양을 그대로 적습니다.

있을 수 없는 상태를 못 만들게 — 카드 결제에만 카드 번호가 있습니다. "현금인데 카드 번호가 있는" 값은 만들 수조차 없습니다.

퀴즈 — 열거형

Q. 열거형에 변형을 하나 더했습니다. 그 열거형을 _ 없이 가르던 match 들은 어떻게 될까요?

A. 전부 컴파일 오류(E0004)가 나서 새 변형을 다루라고 알려 줍니다 (빠진 곳을 찾아 준다). _ => 로 뭉뚱그린 match 는 조용히 그 갈래로 빠집니다.
