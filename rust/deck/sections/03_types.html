변수와 기본 타입

let 과 mut · 가리기 · 상수 · 정수와 넘침 · 실수·불·문자 · 형변환 · 튜플과 배열

이 부에서 할 일

값에 이름을 붙이는 법과, 그 값이 가질 수 있는 가장 기본적인 타입들을 익힙니다. Rust 는 모든 값의 타입을 컴파일할 때 정해 두고, 실행 중에는 바꾸지 않습니다.

  • 1장 변수 — let 과 mut, 가리기(shadowing), 스코프, const 와 static
  • 2장 정수 — 열두 가지 정수 타입, 리터럴, 넘침(overflow), 나눗셈과 나머지
  • 3장 실수·불·문자 — f32·f64, bool, char
  • 4장 형변환 — 타입이 다른 값을 섞는 법: as, From, TryFrom, parse
  • 5장 튜플·배열 — 값 여러 개를 하나로 묶는 두 가지 기본 타입
일부러 틀립니다 — 이 부에는 컴파일되지 않는 예제와 실행하다 멈추는 예제가 여럿 나옵니다. Rust 의 변수와 타입은 "무엇이 안 되는가"를 보아야 빨리 익습니다. 오류 화면도 모두 이 기계의 컴파일러가 낸 그대로입니다.

변수

let 은 값에 이름을 붙인다 — 타입은 컴파일러가 정한다

2부에서 이미 써 본 let 입니다. 변수마다 타입이 하나씩 정해지는데, 적지 않으면 컴파일러가 값을 보고 추론(type inference)합니다.

  • 타입을 적지 않은 정수는 i32, 소수점이 있는 수는 f64 가 됐습니다.
  • let count: i64 = 5; — 이름 뒤에 : 타입 을 적으면 그 타입이 됩니다. 이것을 타입 표기(type annotation)라고 합니다.
  • type_name_of_val 은 값의 타입 이름을 글자로 돌려주는 표준 함수입니다. 이 부에서 타입을 눈으로 확인할 때 씁니다( 부터). 앞에 붙인 & 는 6부에서 봅니다.

변수는 기본이 불변이다 — E0384

다른 언어에서는 변수에 값을 다시 넣는 것이 당연합니다. Rust 에서는 한 번 붙인 값을 바꿀 수 없는 것이 기본입니다. 이것을 불변(immutable)이라고 합니다.

오류 읽는 법 — 화면이 두 줄을 짚습니다. 2번 줄이 첫 대입(first assignment)이고, 4번 줄이 "불변 변수에 두 번 대입할 수 없다"는 자리입니다. help: 는 2번 줄의 어디에 무엇을 넣으면 되는지를 +++ 로 보여 줍니다 — mut 입니다.

바꿀 변수에는 mut 를 붙인다

컴파일러가 알려 준 대로 고칩니다. let mut 로 만든 변수는 가변(mutable)이라 값을 다시 넣을 수 있습니다.

왜 기본이 불변인가 — 선언에 mut 가 없으면 그 값은 끝까지 그대로라는 뜻입니다. 긴 함수를 읽을 때 mut 가 붙은 변수만 "어디서 바뀌는가"를 따라가면 됩니다. 바꿀 일이 생기면 그때 붙입니다.

같은 이름으로 다시 let 하면 앞의 변수를 가린다

mut 없이도 같은 이름을 다시 쓸 수 있습니다. let 을 한 번 더 쓰면 새 변수가 생기고, 앞의 변수는 그 이름으로 더는 보이지 않습니다. 이것이 가리기(shadowing)입니다.

  • let x = x + 1; — 오른쪽의 x 는 앞의 변수(5)이고, 왼쪽이 새 변수(6)입니다.
  • 중괄호로 묶은 블록 안에서 가린 것은 블록이 끝나면 풀립니다. 그래서 블록 밖의 x 는 12 가 아니라 6 입니다.
  • 값을 바꾼 것이 아니라 변수를 새로 만든 것입니다. 세 변수 모두 불변입니다.

mut 로는 타입을 바꿀 수 없다 — E0308

공백 문자열을 받아 두었다가, 같은 이름에 그 길이를 담고 싶습니다. mut 변수에 대입해 봅니다.

오류 읽는 법 — mismatched types 는 타입이 맞지 않는다는 뜻이고, Rust 에서 가장 자주 만나는 오류입니다. 4번 줄은 "&str 을 기대했는데 usize 가 왔다"이고, 2번 줄은 그렇게 기대한 까닭입니다 — 처음 넣은 값이 문자열이었습니다. mut 는 값을 바꾸게 해 줄 뿐, 타입은 그대로입니다.

가리기는 타입도 바꾼다

앞 장을 고친 것입니다. mut 를 떼고 let 을 한 번 더 썼습니다. 새 변수이므로 타입이 달라도 됩니다.

mut 에 대입let 으로 가리기
변수같은 변수의 값이 바뀐다새 변수가 생긴다
타입바꿀 수 없다바꿀 수 있다
블록 안에서 하면블록 밖에서도 바뀌어 있다블록이 끝나면 풀린다
언제 가리기를 쓰는가 — 같은 것을 다른 꼴로 바꿔 갈 때입니다. 읽은 줄 → 다듬은 글 → 수 처럼 단계마다 spaces_str · spaces_len 같은 이름을 새로 짓지 않아도 됩니다.

블록 안에서 만든 이름은 블록 밖에 없다 — E0425

변수는 자기가 선언된 블록의 닫는 중괄호까지만 삽니다. 이름이 보이는 이 범위를 스코프(scope)라고 합니다.

오류 읽는 법 — 7번 줄의 inner 를 "이 스코프에서 찾을 수 없다"고 합니다. help: 는 그 이름이 같은 함수의 다른 스코프(4번 줄)에 있다고 짚어 줍니다. outer 는 걸리지 않았습니다 — 바깥의 이름은 안쪽 블록에서 보이지만, 그 반대는 아닙니다. 블록 밖에서도 쓰려면 이름을 바깥에서 선언해야 합니다.

값을 넣기 전에는 읽을 수 없다 — E0381

이름을 바깥에서 선언하되 값은 아직 정하지 못했다면, 값 없이 이름만 선언할 수 있습니다. 그러나 그대로 읽으려 하면 컴파일되지 않습니다.

오류 읽는 법 — 2번 줄은 "선언했지만 초기화하지 않았다", 3번 줄은 "여기서 쓰는데 초기화되지 않았다"입니다. Rust 에는 값을 넣지 않은 변수에 저절로 들어가는 0 이나 쓰레기 값이 없습니다. help: 의 = 42 는 "아무 값이나 넣으라"는 예시일 뿐입니다.

선언은 먼저, 값은 나중에 — 읽기 전에만 넣으면 된다

앞의 두 오류를 함께 고친 것입니다. 이름은 바깥에서 선언하고, 값은 블록 안에서 계산해 넣습니다.

  • let total; — 타입도 값도 적지 않았습니다. 타입은 뒤에 오는 대입을 보고 추론합니다.
  • 값을 넣는 것이 한 번뿐이므로 mut 가 필요 없습니다. 첫 대입은 "바꾸기"가 아니라 초기화입니다.
  • 컴파일러는 읽는 자리마다 그 전에 값이 들어갔는지를 확인합니다. 실행해 보지 않고 압니다.

쓰지 않은 변수는 경고를 받는다

경고(warning)는 오류와 달리 컴파일을 멈추지 않습니다. 만들어 놓고 한 번도 읽지 않은 변수가 있으면 컴파일러가 알려 줍니다.

  • warning: 으로 시작하고, 그 아래에서 프로그램은 정상으로 돌았습니다.
  • help: — 일부러 안 쓰는 것이라면 이름 앞에 밑줄을 붙이라고 합니다. 같은 처지인 _depth 는 경고를 받지 않았습니다.
  • = note: 줄의 unused_variables 가 이 경고의 이름입니다. 기본으로 켜져 있다고 적혀 있습니다.
경고를 쌓아 두지 않습니다 — 안 쓰는 변수는 대개 지우다 만 코드이거나 잘못 쓴 이름입니다. 이 책의 예제는 경고를 보이려고 만든 것 말고는 모두 경고 없이 컴파일됩니다.

const — 컴파일할 때 정해지는, 이름 붙은 값

프로그램 내내 변하지 않고 실행 전에 이미 아는 값은 상수(constant)로 둡니다. 수 8 을 여기저기 적는 대신 이름을 붙이는 것입니다.

불변 변수와 다른 점 — let 으로 만든 불변 변수는 "한 번 정하면 못 바꾸는 값"이고, 그 값은 입력을 읽어 정해도 됩니다. const 는 실행하기 전에 이미 정해져 있어야 합니다.

static — 프로그램 내내 한 자리에 놓이는 값

const 와 닮은 것이 하나 더 있습니다. static 입니다. 적는 법은 같고, 값이 놓이는 방식이 다릅니다.

망설여지면 const — 읽기만 하는 값이라면 둘의 차이가 드러날 일이 거의 없습니다. "한 곳에 있어야 한다"는 까닭이 따로 없으면 const 를 씁니다. fn show() 같은 함수 정의는 5부에서 봅니다.

퀴즈 — 1장

Q. 다음 둘 가운데 컴파일되는 것은 어느 쪽입니까? 컴파일되지 않는 쪽은 무슨 오류입니까?
① let x = 5; x = x + 1;
② let x = 5; let x = x + 1;

A. ② 만 컴파일됩니다. ② 는 let 을 다시 써서 새 변수로 앞의 x 를 가린 것이고, 새 x 는 6 입니다. ① 은 불변 변수에 다시 대입한 것이라 E0384 (cannot assign twice to immutable variable)가 납니다. ① 을 살리려면 let mut x = 5; 로 선언합니다.

정수 타입은 크기와 부호로 고른다

Rust 에는 int 하나가 아니라 정수 타입이 열두 가지 있습니다. 이름이 곧 설명입니다 — i 는 부호 있는(signed) 정수, u 는 부호 없는(unsigned) 정수이고, 뒤의 수가 비트 수입니다.

비트부호 있음부호 없음
8i8u8
16i16u16
32i32u32
64i64u64
128i128u128
기계에 따라isizeusize
  • i 쪽은 음수도 담고, u 쪽은 0 이상만 담습니다. 비트 수가 같으면 u 쪽이 양수를 두 배쯤 더 멀리 담습니다.
  • isize · usize 는 그 기계의 주소 크기를 따릅니다. 이 장의 끝에서 다시 봅니다.
  • 무엇을 고를지 모르겠으면 i32 로 시작합니다. 컴파일러의 기본값도 그것입니다.

타입마다 담을 수 있는 범위가 정해져 있다

비트 수가 정해져 있으니 담을 수 있는 값에도 끝이 있습니다. 그 끝은 외우지 않아도 됩니다. 타입에 이름으로 들어 있습니다.

  • 부호 있는 쪽은 음수가 하나 더 많습니다. i8 은 -128 부터 127 까지입니다.
  • i32 는 ±21억쯤, i64 는 열아홉 자리 수까지 담습니다.
  • 이 기계에서 isize · usize 는 64비트입니다. 32비트 기계에서 컴파일하면 32비트가 됩니다.

정수 리터럴 — 밑줄 · 진법 · 접미사

소스에 직접 적은 값을 리터럴(literal)이라고 합니다. 정수 리터럴은 읽기 좋게, 또는 비트가 보이게 여러 꼴로 적을 수 있습니다.

꼴뜻값
1_000_000숫자 사이의 밑줄은 읽기 좋으라고 넣는 것 — 값은 그대로다1000000
0xff16진수255
0o178진수15
0b1010_00012진수161
b'a'바이트 리터럴 — 그 글자의 바이트 값, 타입은 u897
42u8 · 42_u8접미사 — 리터럴의 타입을 그 자리에서 정한다42
찍을 때의 진법은 서식으로 — 16진수로 적었어도 값은 그냥 수입니다. 16진수로 찍으려면 2부에서 본 {:x} · {:#b} 를 씁니다.

단서가 없으면 i32 — 추론은 뒤의 쓰임까지 본다

접미사도 타입 표기도 없는 정수 리터럴의 타입은 무엇일까요. 컴파일러는 그 값이 어디에 쓰이는지를 보고 정하고, 아무 단서가 없을 때 i32 로 합니다.

  • a — 단서가 없어 기본값 i32 가 됐습니다.
  • b — 접미사 u8 이 단서입니다.
  • c — 선언은 a 와 같지만 다음 줄에서 i64 변수에 넣었습니다. 그래서 c 도 i64 입니다.
리터럴 42 에는 미리 정해진 타입이 없습니다 — 쓰이는 자리에 맞는 정수 타입이 됩니다. 2부의 오류 화면에 나왔던 {integer} 가 "아직 정해지지 않은 정수"라는 뜻입니다.

범위를 넘는 리터럴은 컴파일되지 않는다

u8 은 255 까지입니다. 거기에 256 을 적으면 컴파일러가 실행하기 전에 잡아냅니다.

오류 읽는 법 — 첫 줄은 "u8 의 범위를 벗어난 리터럴"이고, 첫 = note: 가 까닭을 말합니다. 리터럴 256 은 범위가 0..=255(0 이상 255 이하)인 u8 에 들어가지 않습니다. 둘째 = note: 의 overflowing_literals 가 이 검사의 이름입니다. 1장의 안 쓴 변수 경고에는 #[warn(…)] 이, 여기에는 #[deny(…)] 가 적혀 있습니다. 같은 종류의 검사인데 이쪽은 기본이 오류라는 뜻입니다. 이 화면에는 error[E…] 번호가 없습니다.

계산하다 범위를 넘으면 패닉한다

리터럴은 컴파일러가 미리 볼 수 있지만, 실행 중에 들어온 값으로 한 셈은 그럴 수 없습니다. u8 값 250 에 10 을 더해 봅니다. 결과가 타입의 범위를 넘는 것을 넘침(overflow)이라고 합니다.

  • 지금: 250 까지 찍고 9번 줄에서 멈췄습니다 — attempt to add with overflow.
  • 이렇게 프로그램이 스스로 멈추는 것이 패닉(panic)이고, 그때의 종료 코드가 101 입니다. 패닉은 9부에서 봅니다.
  • 틀린 값을 들고 계속 가는 대신, 틀린 그 자리에서 멈춥니다.

같은 코드를 -O 로 컴파일하면 조용히 한 바퀴 돈다

앞 장의 패닉은 넘침 검사가 켜져 있어서 났습니다. 최적화 옵션 -O 를 주면 이 검사가 빠집니다. 소스는 한 글자도 바꾸지 않았습니다.

  • 260 은 u8 에 들어가지 않습니다. 256 에서 0 으로 돌아가 다시 세어 4 가 됐습니다(260 - 256).
  • 패닉도 경고도 없습니다. 같은 소스가 컴파일 옵션에 따라 다르게 움직입니다.
cargo 에서도 같습니다 — cargo build 는 넘침을 검사하고, 최적화를 켜는 cargo build --release 는 기본 설정에서 검사하지 않습니다. 개발할 때는 패닉하던 코드가 배포판에서는 틀린 값으로 계속 돌 수 있습니다. 넘칠 수 있는 셈은 다음 장처럼 뜻을 밝혀 적습니다.

넘칠 때 어떻게 할지를 메서드로 고른다

넘침이 일어날 수 있는 셈이라면 + 대신 메서드를 씁니다. 넘쳤을 때의 행동이 이름에 적혀 있고, 컴파일 옵션에 따라 달라지지 않습니다.

정수 나눗셈은 0 쪽으로 버리고, % 는 왼쪽의 부호를 따른다

정수끼리 나누면 결과도 정수입니다. 소수점 아래가 어느 쪽으로 사라지는지, 음수의 나머지가 무엇인지는 언어마다 다릅니다.

  • -7 / 2 는 -3 입니다. -3.5 에서 0 에 가까운 쪽으로 버립니다. -4 가 아닙니다.
  • % 의 결과는 나뉘는 수(왼쪽)의 부호를 따릅니다. -7 % 3 은 -1 이고 7 % -3 은 1 입니다.
  • 요일이나 시계처럼 늘 0 이상인 나머지가 필요하면 rem_euclid 를 씁니다. 짝이 되는 몫은 div_euclid 입니다 — (-3) × 3 + 2 = -7.

0 으로 나누면 패닉한다 — -O 로 컴파일해도

넘침 검사는 -O 에서 빠졌지만, 0 으로 나누는 것은 다릅니다. 이번에는 처음부터 -O 로 컴파일하고 나누는 수로 0 을 줍니다.

  • 8번 줄의 / 에서 패닉했습니다 — attempt to divide by zero. 종료 코드는 넘침 때와 같은 101 입니다.
  • 그 앞줄의 checked_div 는 패닉하지 않고 None 을 돌려줬습니다. 나누는 수가 바깥에서 들어온다면 이쪽을 씁니다.

정수끼리도 타입이 다르면 섞을 수 없다 — E0308

C 나 Java 에서는 작은 정수가 큰 정수와 만나면 저절로 큰 쪽으로 바뀝니다. Rust 는 저절로 바꾸지 않습니다. i64 와 i32 를 견주어 봅니다.

오류 읽는 법 — 1장에서 본 mismatched types 입니다. 왼쪽이 i64 이므로 오른쪽에도 i64 를 기대했는데 i32 가 왔다고 합니다. help: 는 i32 를 i64 로 바꿀 수 있다며 .into() 를 붙여 보입니다. 타입을 맞추는 방법들은 4장에서 봅니다.

길이와 위치는 usize 로 센다

정수 타입을 고를 일이 없는 자리가 하나 있습니다. 몇 개인지, 몇 번째인지를 나타내는 수는 언제나 usize 입니다.

  • len() 이 돌려준 값의 타입이 usize 로 찍혔습니다. 1장에서 spaces.len() 이 usize 라던 오류 화면과 같은 이야기입니다.
  • 대괄호 안에 넣어 몇 번째 값을 꺼낼 때도 usize 를 씁니다. 대괄호로 묶은 배열은 5장에서 봅니다.
  • 이 기계에서는 64비트입니다. 주소 크기와 같아서, 메모리에 놓을 수 있는 어떤 길이든 담습니다.
부호가 없습니다 — len() - 1 은 길이가 0 일 때 -1 이 아니라 넘침입니다. 앞에서 본 그대로, 검사가 켜져 있으면 패닉합니다.

자주 쓰는 셈은 정수의 메서드로 들어 있다

거듭제곱이나 절댓값을 구하려고 따로 수학 모듈을 불러올 필요가 없습니다. 값 뒤에 점을 찍고 부릅니다.

  • 2_i32.pow(10) — 리터럴에 바로 메서드를 부를 때는 접미사로 타입을 밝혀 줍니다.
  • abs_diff 는 두 수의 차이를 부호 없이 줍니다( 부터). isqrt 는 소수점 아래를 버린 정수 제곱근입니다( 부터).
  • count_ones · leading_zeros · trailing_zeros 는 비트를 셉니다. 0b0010_1100 에는 1 이 셋, 앞에 0 이 둘, 뒤에 0 이 둘입니다.

퀴즈 — 2장

Q. 실행할 때 받은 u8 값 250 에 + 10 을 하는 프로그램이 있습니다.
① rustc 로 그냥 컴파일해 돌리면 어떻게 됩니까?
② rustc -O 로 컴파일해 돌리면 어떻게 됩니까?
③ 어느 쪽으로 컴파일하든 255 가 나오게 하려면 무엇을 씁니까?

A. ① attempt to add with overflow 로 패닉하고 종료 코드 101 로 끝납니다. ② 패닉 없이 4 가 나옵니다 — 260 에서 256 을 뺀 값입니다. ③ level.saturating_add(10) 입니다. 끝값 255 에서 멈춥니다. 넘쳤는지를 알아야 한다면 checked_add 가 None 으로 알려 줍니다.
