HashMap 과 BTreeMap

키로 넣고 찾기 · entry · 도는 순서는 정해져 있지 않다 · 키와 값의 소유권 · BTreeMap

HashMap — 키로 넣고, 키로 찾는다

HashMap<K, V> 는 키와 값의 짝을 담습니다. 다른 언어의 사전(dict)·객체에 해당합니다. 벡터와 달리 프렐류드에 없어서 use 가 필요합니다.

get 은 Option — 없는 키일 수 있기 때문입니다. 없을 때의 기본값은 .copied().unwrap_or(0) 처럼 줍니다(9부).

[] 로 읽으면 없는 키에서 패닉한다

맵에도 map[key] 가 있습니다. 벡터와 같은 약속입니다 — 반드시 있다고 믿는 자리에만 쓰고, 없으면 패닉합니다.

같은 키에 다시 넣으면 덮어쓴다

insert 는 그 키에 있던 옛 값을 Option 으로 돌려줍니다. 처음이면 None, 덮어썼으면 옛 값입니다.

entry — 없으면 넣고, 있으면 그것을

"있는지 보고, 없으면 넣고, 그 값을 고친다" 를 한 번에 합니다. or_insert 는 그 자리의 값을 가리키는 가변 참조를 돌려줍니다.

낱말 세기 — entry 의 대표 쓰임새

낱말마다 entry(낱말).or_insert(0) 에 1 을 더합니다. 그리고 결과를 찍기 전에 벡터로 옮겨 정렬합니다.

HashMap 을 도는 순서는 정해져 있지 않다 — 넣은 순서도, 키 순서도 아니고 실행할 때마다 달라질 수 있습니다. 순서가 필요하면 정렬하거나 BTreeMap 을 씁니다. 이 책의 화면이 맵을 그대로 찍지 않는 까닭입니다.

넣은 키와 값은 맵의 것이 된다 — E0382

insert 는 키와 값의 소유권을 가져갑니다. String 을 넣은 뒤에는 원래 이름으로 쓸 수 없습니다.

남겨 두려면 clone() 해서 넣거나, 맵이 &str 을 키로 갖게 합니다(그러면 원본 문자열이 맵보다 오래 살아야 합니다 — 11부).

String 키를 &str 로 찾고, 값을 제자리에서 고친다

키가 String 이어도 찾을 때는 &str 을 넘깁니다 — 찾으려고 문자열을 새로 만들 필요가 없습니다. 값은 get_mut 이나 and_modify 로 고칩니다.

아무 타입이나 키가 될 수는 없다 — E0277

키는 Hash 와 Eq 를 구현해야 합니다(10부). 실수는 NaN 이 자기 자신과도 같지 않아서 Eq 가 아니고, 그래서 키가 될 수 없습니다.

짝의 반복자에서 맵 만들기

(키, 값) 짝을 내는 반복자는 collect 로 맵이 됩니다. keys() 와 values() 는 한쪽만 돕니다.

BTreeMap — 늘 키 순서로

쓰는 법은 HashMap 과 거의 같고, 키가 늘 정렬돼 있습니다. 순서대로 돌거나 범위로 찾을 수 있습니다. 키는 Hash 대신 Ord 가 필요합니다.

HashMapBTreeMap
도는 순서정해져 있지 않다키 순서

퀴즈 — 맵

Q. *counts.entry(word).or_insert(0) += 1; 은 word 가 처음 나왔을 때와 이미 있을 때 각각 무엇을 할까요?

A. 처음이면 0 을 넣고 그 자리를 1 로 올립니다. 이미 있으면 넣지 않고 있던 값을 1 올립니다 (entry). or_insert 가 돌려준 가변 참조에 * 로 닿아 고치는 것입니다.

그 밖의 컬렉션

집합 · 양쪽이 열린 줄 · 우선순위 큐 · 고르는 법

집합 — 겹치지 않는 값들

집합은 값만 있는 맵입니다. 같은 값은 한 번만 들어갑니다. BTreeSet 은 정렬돼 있고, HashSet 은 순서가 없습니다. 교집합·합집합·차집합이 있습니다.

"처음 본 것만" — insert 의 반환값 쓰기

집합의 insert 는 새로 들어갔으면 true 를 줍니다. filter 에 그대로 쓰면 순서를 지키면서 겹친 것을 지웁니다(2장의 dedup 은 정렬이 필요했습니다).

VecDeque — 양쪽 끝이 열린 줄

벡터는 앞에서 빼는 일이 느립니다(전부 한 칸씩 당겨야 합니다). 앞뒤 양쪽에서 넣고 빼야 하면 VecDeque 를 씁니다.

BinaryHeap — 큰 것부터 나온다

넣는 순서와 상관없이 pop 이 늘 가장 큰 값을 줍니다. 가장 급한 일부터 꺼내는 우선순위 큐에 씁니다.

퀴즈 — 컬렉션 고르기

Q. 일거리를 들어온 순서대로 처리하려 합니다. Vec 에 push 하고 remove(0) 으로 꺼내도 되지만, 더 알맞은 컬렉션은 무엇일까요?

A. VecDeque 입니다. push_back 으로 넣고 pop_front 로 꺼냅니다 (양쪽 끝이 열린 줄). 벡터의 remove(0) 은 꺼낼 때마다 나머지를 전부 한 칸씩 당깁니다.

문자열 실전

글자 다루기 · 바이트 · 날 문자열 · 넘겨주기 · 만들기 · 정렬 · 보이는 글자와 char

글자를 살펴보는 메서드

char 에는 종류를 묻는 메서드가 있습니다. 문자열을 한 글자씩 읽어 처리할 때 씁니다.

바이트로 보기

파일이나 네트워크에서 온 데이터는 바이트입니다. String 은 올바른 UTF-8 임이 보장되므로, 바이트에서 만들 때는 검사를 거칩니다 — 그래서 Result 가 나옵니다.

이스케이프와 날 문자열

역슬래시가 많은 글자(경로, 정규식, JSON)는 날 문자열 r"…" 로 씁니다. 안에 큰따옴표가 있으면 r#"…"# 로 감쌉니다.

넘겨주기 — String 을 받는 함수와 &str 을 받는 함수

&str 을 받는 함수에는 무엇이든 빌려줄 수 있습니다. String 을 받는 함수에는 넘겨줘야(또는 복사해 줘야) 합니다.

기본은 &str 로 받기 — 받는 쪽이 글자를 가져야 할 때만 String 으로 받습니다.

문자열 만들어 가기

조각을 이어 긴 문자열을 만드는 세 가지 방법입니다. 대개 join 이나 collect 가 손으로 쓴 반복문보다 짧고 실수가 없습니다.

문자열 정렬

그냥 sort() 는 바이트 순서라 대문자가 소문자보다 앞에 옵니다. 사람이 기대하는 순서는 기준을 줘서 만듭니다.

한글은 유니코드에서 가나다순으로 놓여 있어 그냥 정렬해도 가나다순이 됩니다.

Cow — 고칠 때만 복사한다

"대부분은 그대로 돌려주고, 가끔만 고친다" 는 함수는 Cow<str> 를 돌려줄 수 있습니다. 고칠 것이 없으면 빌린 채로, 있으면 새 String 으로 줍니다.

지금은 알아보기만 — 표준 라이브러리의 반환 타입에서 가끔 만납니다. Cow 는 &str 처럼 쓸 수 있습니다.

보이는 글자와 char 는 다를 수 있다

char 는 유니코드 코드 포인트 하나입니다. 화면의 "한 글자" 가 여러 코드 포인트로 이뤄질 수 있습니다 — 부호를 덧붙인 글자, 국기 이모지 같은 것입니다.

뒤집기와 글자 수 세기의 함정 — chars().rev() 와 chars().count() 는 코드 포인트 단위입니다. 사람이 보는 글자 단위로 다루려면 표준 라이브러리 밖의 크레이트가 필요합니다.

퀴즈 — 문자열 실전

Q. ["banana", "apple", "Cherry", "fig"] 를 sort() 하면 맨 앞에 오는 것은 무엇일까요?

A. "Cherry" 입니다. 바이트 순서에서는 대문자가 소문자보다 앞입니다. 대소문자를 가리지 않으려면 sort_by_key(|w| w.to_lowercase()) 를 씁니다(문자열 정렬).
