8부

문자열과 컬렉션

String 과 &str · UTF-8 · Vec · HashMap · 집합·덱·힙 · 문자열 실전

이 부에서 할 일

프로그램은 데이터를 흔히 문자열, 목록, 사전에 담습니다. Rust 에서 이것들을 담는 String, Vec, HashMap 은 언어에 박힌 것이 아니라 표준 라이브러리의 타입이고, 6부의 소유권 규칙을 그대로 따릅니다.

  • 1장 — String 과 &str: 만들기, 잇기, 왜 s[0] 이 안 되는가
  • 2장 — Vec<T>: 늘어나는 목록
  • 3장 — HashMap 과 BTreeMap: 키로 찾기
  • 4장 — 그 밖의 컬렉션: 집합, 덱, 힙
  • 5장 — 문자열 실전: 글자·바이트·날 문자열·정렬
사전처럼 쓰는 부 — 메서드가 많습니다. 외우기보다 "이런 것이 있다" 를 봐 두고 필요할 때 돌아오면 됩니다.
미리 쓰는 둘 — 예제에 collect() 와 |x| 식 꼴의 클로저가 가끔 나옵니다. collect 는 2부에서 명령 줄 인자를 모을 때 쓴 메서드로, 반복자가 차례로 내놓는 값을 받는 쪽 타입(Vec, String, 맵)으로 모읍니다(12부). 클로저는 7부에서 한 번 본 이름 없는 함수입니다(12부).

1장

String 과 &str

두 타입 · 만들기 · 잇기 · 인덱스가 없다 · UTF-8 · 글자와 바이트 · 자주 쓰는 메서드 · 값으로 바꾸기 · 견주기 · 자리

문자열 타입은 둘이다

6부에서 본 대로입니다. String 은 글자를 스스로 가진 값이고, &str 은 어딘가에 있는 글자를 빌려 보는 슬라이스입니다. 6부는 둘을 소유권을 보는 데 필요한 만큼만 썼고, 이 장은 둘을 만들고 잇고 자르는 법을 봅니다. 표는 그 전에 둘의 차이를 한 줄씩 견준 것입니다.

String&str
글자의 주인자기남(빌려 본다)
늘리고 고치기된다안 된다
리터럴 "…" 의 타입이쪽
함수 매개변수로값을 가질 때읽기만 할 때(대부분)
서로 바꾸기&s · s.as_str() →← to_string() · String::from

"함수 매개변수로" 줄은 6부에서 정한 그대로입니다 — 읽기만 하면 &str 로 받습니다.

String 을 만드는 길은 여럿이고 결과는 같다

리터럴에서 String 을 만드는 방법이 여럿입니다. 3번부터 6번 줄까지의 넷은 같은 일을 합니다 — 글자를 힙에 복사해 가진 값을 만듭니다.

무엇을 쓸까 — 취향입니다. 이 책은 String::from("…") 과 to_string() 을 주로 씁니다. 6번 줄의 into() 는 10부에서 봅니다.

덧붙이기 — push · push_str · +=

String 은 늘어납니다. 글자 하나는 push, 문자열은 push_str 이나 += 로 붙입니다. 가운데에 끼워 넣는 insert 도 있습니다.

+ 로 잇기 — 왼쪽은 가져가고 오른쪽은 빌린다

+ 의 왼쪽에는 String 이, 오른쪽에는 &str 이 옵니다. 왼쪽 문자열의 자리를 그대로 써서 뒤에 붙이기 때문입니다.

+ 의 왼쪽은 사라진다 — E0382

그래서 + 뒤에 왼쪽 문자열을 다시 쓰면 이동 오류입니다.

읽는 법 — 6부에서 본 E0382 와 같은 꼴이고, 옮긴 자리가 대입이 아니라 + 의 왼쪽이라는 점만 다릅니다. 5번 줄의 hello 아래에 value moved here, 6번 줄에 value borrowed here after move 가 붙었습니다. help 는 hello.clone() 을 권합니다. 복제하지 않고 잇는 방법은 다음 슬라이드에 있습니다.

여럿을 이을 때는 format! 과 join

2부에서 본 format! 은 아무것도 가져가지 않고 새 String 을 만듭니다. 조각이 목록에 들어 있으면 join 이 사이사이에 구분자를 넣어 잇습니다.

문자열에는 s[0] 이 없다 — E0277

다른 언어에서 하던 대로 첫 글자를 꺼내려 하면 컴파일되지 않습니다. 컴파일러가 까닭을 설명한 책의 장까지 알려 줍니다.

읽는 법 — 2부에서 본 E0277 과 같은 꼴입니다. 이번에 없다는 것은 정수를 str 의 인덱스로 쓰는 구현입니다. 3번 줄에 붙은 string indices are ranges of `usize` 는 문자열의 [] 안에는 수 하나가 아니라 범위가 온다는 말입니다. note 는 대신 .chars().nth() 나 .bytes().nth() 를 쓰라고 권합니다(n 번째 글자). 그 아래 help 묶음은 usize 하나를 인덱스로 쓸 수 있는 쪽이 슬라이스 [T] 같은 다른 타입이라는 말로, 지금은 넘어가도 됩니다.

까닭 — 글자마다 바이트 수가 다르다

Rust 의 문자열은 UTF-8 입니다. 영문자는 1바이트, 한글은 6부에서 본 대로 3바이트이고, 예제의 🦀 이모지는 4바이트입니다. len() 은 글자 수가 아니라 바이트 수입니다.

"0번째" 가 무엇인가 — 0번째 바이트인지 0번째 글자인지 모호하고, n번째 글자를 찾으려면 앞에서부터 세어야 합니다. 그래서 Rust 는 한 번에 되는 것처럼 보이는 s[n] 을 주지 않습니다.

글자로 볼지 바이트로 볼지 고른다

chars() 는 글자(char)를, bytes() 는 바이트(u8)를 하나씩 줍니다. char_indices() 는 글자와 함께 그 글자가 시작하는 바이트 자리를 줍니다.

글자 경계 — 출력 마지막 줄의 0 과 1 이 글자가 시작하는 자리입니다. 6부에서 &s[0..1] 이 패닉한 것은 이런 자리가 아닌 번호로 잘랐기 때문입니다.

n 번째 글자, 뒤집기, 글자 수로 자르기

글자 단위의 일은 chars() 반복자로 합니다(12부). nth 와 last 는 그런 글자가 없을 수 있으므로 Option 을 줍니다. collect() 는 반복자가 내놓는 글자를 다시 String 으로 모읍니다.

바이트 범위로 자르기 — &s[0..3] 은 6부에서 봤고, 글자 경계가 아닌 곳을 자르면 패닉합니다. 글자 수로 자를 때는 11번 줄처럼 chars().take(n) 을 씁니다.

자주 쓰는 메서드 ① — 다듬고, 찾고, 바꾸기

이 메서드들은 &str 의 것이라 String 에도, 리터럴에도 똑같이 씁니다. 원본을 고치지 않고 새 값이나 슬라이스를 돌려줍니다. trim 은 2부에서 읽은 줄을 다듬을 때 쓴 그것입니다.

find 의 답 — 찾은 자리를 글자 번호가 아니라 바이트 번호로 줍니다. 영문만 있는 첫 문자열에서는 둘이 같아 Some(7) 이지만, 마지막 줄의 "나" 는 둘째 글자인데 Some(3) 입니다. 없으면 None 입니다.

자주 쓰는 메서드 ② — 쪼개기

쪼개는 메서드들은 반복자를 돌려줍니다. for 로 돌거나, collect() 로 Vec<&str> 에 모읍니다. 조각은 원본을 빌린 &str 이라 글자를 복사하지 않습니다.

마지막 줄 — split(',') 은 구분자 사이가 비어 있으면 빈 문자열을 그대로 내줍니다. split_whitespace 는 이어진 공백을 하나로 봅니다.

자주 쓰는 메서드 ③ — 앞뒤 떼어 내기

strip_prefix 는 "이것으로 시작하면 그 뒤를" 줍니다. 시작하지 않으면 None 이라 검사와 자르기가 한 번에 됩니다.

parse 로 값이 되고 to_string 으로 문자열이 된다

문자열에서 값으로는 2부에서 쓴 parse 입니다. 받는 쪽의 타입 표기에 따라 정수뿐 아니라 실수·불·문자도 만듭니다. 값에서 문자열로는 to_string 이고, {} 로 찍을 수 있는 것은 전부 to_string 이 됩니다(10부).

unwrap() — parse 는 실패할 수 있어 Ok 나 Err 를 돌려줍니다. unwrap() 은 Ok 면 속의 값을 꺼내고 Err 면 패닉합니다. 2부의 expect 에서 남길 글만 뺀 것으로, 9부에서 봅니다.

== 는 바로 되고, 순서는 바이트 값을 따른다

String 과 &str 은 바로 == 로 견줍니다. 순서(<)는 글자의 바이트 값 순서입니다.

사전 순서가 아니다 — 대문자 Z 가 소문자 a 보다 앞입니다. 사람이 기대하는 정렬은 5장의 문자열 정렬에서 봅니다.

자리를 미리 잡아 둔다 — with_capacity

String 은 길이(len)와 따로 잡아 둔 자리(capacity)를 가집니다 (6부). 얼마나 커질지 알면 미리 잡아 둡니다.

읽는 법 — 잡아 둔 자리 안에서는 붙여도 자리를 다시 잡지 않습니다. 네 번 붙인 뒤에도 16 그대로입니다. 자리가 모자랄 때의 일은 2장의 벡터에서 봅니다.

퀴즈 — String 과 &str

Q. "가나다".len() 은 얼마일까요? 글자 수를 얻으려면 어떻게 할까요?

A. 9 입니다. len() 은 바이트 수이고 한글 한 글자는 UTF-8 로 3바이트입니다 (글자마다 바이트 수가 다르다). 글자 수는 .chars().count() 로 3 입니다.

2장

Vec

만들기 · push 와 pop · 인덱스와 get · 돌기 · 자리와 길이 · 끼우고 빼기 · 한꺼번에 다루기 · 잇기 · 슬라이스 · 원소 꺼내기 · 벡터의 벡터 · 떼어 내기

Vec — 늘어나는 목록

앞의 부들에서 vec![…] 로 여러 번 쓴 벡터를 이 장에서 제대로 봅니다. Vec<T> 는 같은 타입의 값을 차례로 담고, 실행 중에 늘어납니다. 배열과 달리 길이가 타입에 들어 있지 않습니다. 5번 줄처럼 범위나 다른 반복자를 collect() 로 모아 만들 수도 있습니다.

원소 타입을 알 수 없으면 — E0282

빈 벡터를 만들고 아무것도 넣지 않으면 컴파일러가 원소 타입을 정할 수 없습니다.

고치는 법 — help 의 Vec<T> 에서 T 자리에 원소 타입을 적습니다(앞 슬라이드의 Vec<i32>). 뒤에서 push 하면 그것을 보고 정해지므로 적지 않아도 됩니다. 다음 슬라이드의 Vec::new() 에 타입이 없는 까닭입니다.

push 로 끝에 넣고 pop 으로 끝에서 꺼낸다

끝에 넣고 끝에서 꺼내니 그대로 스택입니다. pop 은 비어 있을 수 있으므로 Option 을 돌려줍니다 — 7부에서 while let 으로 스택을 비울 때 본 그대로입니다.

[] 는 패닉하고 get 은 None 을 준다

3부의 배열과 같은 약속입니다. 범위 밖을 읽는 일이 버그라면 v[i] 로 읽어 패닉으로 알리고, 있을 수 있는 일이라면 v.get(i) 로 읽어 Option 으로 다룹니다.

읽는 법 — 패닉 메시지도 배열 때와 같은 index out of bounds 이고, 길이 3 과 읽으려던 번호 7 을 함께 알려 줍니다. first() 와 last() 도 벡터가 비어 있을 수 있어 Option 을 줍니다.

돌기 — 읽으며, 고치며

for x in &v 는 빌려서 읽고, for x in &mut v 는 빌려서 고칩니다. & 없이 for x in v 로 돌면 6부에서 본 대로 벡터를 통째로 옮겨 받으므로 그 뒤에는 v 를 쓸 수 없습니다. 셋을 나란히 견주는 것은 12부에서 봅니다.

자리가 모자라면 옮겨 간다

벡터는 원소를 힙의 이어진 자리에 둡니다. 잡아 둔 자리가 차면 더 큰 자리를 새로 잡고, 그때 원소들이 통째로 옮겨 갈 수 있습니다. 이 실행에서는 자리가 0 → 4 → 8 → 16 → 32 로 늘어, 스무 개를 넣는 동안 네 번만 바뀌었습니다.

참조가 무효가 되는 순간 — 옮겨 가면 원소의 주소가 바뀝니다. 6부에서 원소를 빌려 둔 채 push 하는 코드를 컴파일러가 E0502 로 막은 까닭이 이것입니다.

가운데에 끼우고 빼기

가운데를 건드리면 뒤의 원소들이 전부 한 칸씩 움직입니다. swap_remove 는 뒤를 당기지 않고 마지막 원소 하나를 빈자리로 옮깁니다 — 대신 순서가 바뀝니다.

한꺼번에 — 거르고, 정렬하고, 겹친 것 지우기

벡터를 제자리에서 고치는 메서드들입니다. retain 과 position 에는 원소를 받아 bool 을 내는 클로저 |x| 조건 을 넘깁니다(12부). 클로저가 받는 x 는 원소의 참조라서 *x 로 값에 닿습니다.

dedup 은 이웃만 본다 — 첫 dedup 뒤의 [5, 3, 8, 3, 8] 에서 붙어 있던 8 둘은 하나가 됐지만 떨어져 있는 3 둘은 그대로입니다. 정렬해서 같은 값을 모은 뒤에 부르면 전부 지워집니다 ([3, 5, 8]).

벡터끼리 잇기

extend 는 반복자의 원소를 덧붙이고, append 는 다른 벡터의 원소를 옮겨 옵니다. 그래서 append 뒤에 찍은 b 는 [] 입니다.

벡터의 일부를 빌린다

6부에서 본 대로, 함수를 &[T] 로 받게 만들면 벡터 전체도, 그 일부도, 배열도 받습니다. 여기서는 슬라이스에 쓰는 메서드 몇을 더 봅니다.

  • xs.iter().sum() 은 원소를 전부 더합니다. sum 같은 반복자 메서드는 12부에서 봅니다.
  • split_first 는 6부에서 본 대로 첫 원소와 나머지 슬라이스를 주고, chunks(2) 는 둘씩 끊은 슬라이스들을 줍니다. 남는 마지막 조각은 짧습니다.

복사되지 않는 원소 꺼내기

Vec<String> 에서 let s = names[0]; 은 안 됩니다 (6부에서 본 E0507). 그때 본 길 가운데 셋을 다시 씁니다 — 빌리거나, 복제하거나, 벡터에서 빼냅니다.

벡터의 벡터

2차원 자료는 벡터 안에 벡터를 둡니다. 줄마다 따로 힙에 놓이므로 길이가 달라도 됩니다.

떼어 내기 — drain 과 split_off

앞에서 몇 개를 한꺼번에 꺼내 처리할 때 drain 을 씁니다. 꺼낸 것은 반복자로 나오고(여기서는 collect() 로 새 벡터에 모았습니다) 원래 벡터에서는 사라집니다.

퀴즈 — Vec

Q. vec![5, 3, 8, 3] 에 바로 dedup() 을 부르면 3 이 하나로 줄까요?

A. 줄지 않습니다. dedup 은 이웃한 같은 값만 하나로 합칩니다. 두 3 사이에 8 이 있어 그대로 남습니다. 먼저 sort() 해서 같은 값을 모아야 합니다(한꺼번에의 두 dedup 뒤 출력).
