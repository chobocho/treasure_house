표준 트레이트 ②

From 과 Into · TryFrom · FromStr · AsRef · 연산자 오버로딩

From 과 Into — 타입을 바꾸는 표준 방법

"A 에서 B 를 만들 수 있다" 를 impl From<A> for B 로 적습니다. 그러면 반대 방향에서 부르는 a.into() 가 저절로 생깁니다.

이미 써 온 것 — String::from("…"), i64::from(x) (3부), 그리고 ? 가 오류를 바꿀 때 부르던 것(9부)이 전부 이 트레이트입니다.

impl Into<String> — 넘기는 쪽을 편하게

문자열을 받아 가질 함수는 매개변수를 impl Into<String> 으로 두면 &str 과 String 을 둘 다 받습니다. 부르는 쪽이 .to_string() 을 쓰지 않아도 됩니다.

TryFrom — 실패할 수 있는 변환

모든 값이 바뀔 수 있는 것은 아닐 때 TryFrom 을 구현합니다. Result 를 돌려주고, try_into() 가 따라옵니다. type Error = String; 은 실패했을 때 낼 오류의 타입을 적는 자리입니다(연관 타입, 6장).

값의 조건을 타입으로 — Percent 를 만드는 길이 이것뿐이라면, Percent 를 받는 함수는 범위를 다시 검사할 필요가 없습니다.

FromStr — parse 가 내 타입을 만들게 한다

"42".parse::<i32>() 의 parse 는 FromStr 트레이트를 부릅니다. 내 타입에 구현하면 문자열에서 바로 만들 수 있습니다. 오류의 타입은 앞 슬라이드처럼 type Err 에 적습니다.

AsRef — "그것으로 볼 수 있는 것"

값을 갖지 않고 읽기만 할 함수가 여러 문자열 타입을 받게 하려면 AsRef<str> 을 씁니다. 표준 라이브러리에서는 std::fs::read_to_string 같은 파일 함수가 경로를 AsRef<Path> 로 받습니다.

내 타입에는 + 가 없다 — E0369

3장의 == 처럼 + 도 트레이트입니다. 구현하지 않은 타입끼리는 더할 수 없습니다.

Add 를 구현하면 + 가 된다

a + b 는 a.add(b) 를 부르는 문법입니다. std::ops::Add 를 구현합니다. 결과의 타입은 type Output 에 적습니다(연관 타입, 6장).

다른 타입과의 연산, 단항 연산, +=

오른쪽 타입을 타입 인자로 바꿀 수 있고(Mul<f64>), 단항 - 는 Neg, += 는 AddAssign 입니다.

[] 도 트레이트다 — Index

색인 연산자는 Index 트레이트입니다. 색인의 타입도 정할 수 있어서, 문자열로 찾는 것도 만들 수 있습니다. index 는 값이 아니라 참조(&u32)를 돌려줍니다.

퀴즈 — 표준 트레이트 ②

Q. impl From<Celsius> for Fahrenheit 하나만 구현했습니다. let f: Fahrenheit = Celsius(0.0).into(); 는 컴파일될까요?

A. 됩니다. From 을 구현하면 반대쪽 Into 가 저절로 생깁니다 (From 과 Into). 6장의 포괄 구현이 그것을 해 줍니다.

5장

트레이트 객체

서로 다른 타입을 한 그릇에 · dyn Trait · 컴파일 때 고르기와 실행 중에 고르기

벡터에는 한 가지 타입만 들어간다 — E0308

원과 정사각형을 한 벡터에 넣으려 합니다. 벡터의 원소 타입은 하나여야 하므로 첫 원소를 보고 Circle 로 정해지고, 둘째에서 막힙니다.

dyn Trait — "이 트레이트를 구현한 무언가"

dyn Shape 는 "Shape 를 구현한 어떤 타입" 입니다. 실제 타입은 실행 중에 정해집니다. 크기를 미리 알 수 없으므로 Box 같은 포인터 뒤에 둡니다. 이것이 트레이트 객체(trait object)입니다. Box::new(값) 은 값을 힙에 두고 그것을 가리키는 포인터를 만듭니다(14부).

dyn 은 포인터 뒤에만 둘 수 있다 — E0277

dyn Shape 를 지역 변수에 직접 담으려 하면 크기를 알 수 없다고 합니다. 원일 수도, 더 큰 무엇일 수도 있기 때문입니다.

오류는 둘입니다 — 여기서 뺀 첫째는 E0308 로, Circle 과 dyn Shape 가 다른 타입이라는 말입니다. 위의 둘째에서 Sized 는 "크기가 컴파일할 때 정해진다" 는 트레이트이고, note: 는 지역 변수가 그래야 한다고 합니다.

&dyn Trait, 그리고 Box<dyn Trait> 를 돌려주기

빌려 쓸 때는 &dyn Shape 입니다. 그리고 2장에서 -> impl Shape 로는 못 하던 "경우에 따라 다른 타입을 돌려주기" 가 Box<dyn Shape> 로는 됩니다.

dyn 참조는 주소 둘이다

보통 참조는 주소 하나입니다. 트레이트 객체의 참조는 값의 주소에 더해 "그 타입의 메서드 표" 의 주소를 함께 들고 다닙니다. 메서드를 부를 때 그 표에서 찾아갑니다.

먼저 제네릭 — 타입이 컴파일할 때 정해지는 자리에서는 제네릭을 씁니다. "여러 종류를 한데 모은다", "실행 중에 고른다" 가 필요할 때 dyn 을 꺼냅니다.

모든 트레이트가 객체가 될 수는 없다 — E0038

Self 를 값으로 돌려주는 메서드가 있는 트레이트입니다. dyn 뒤에서는 실제 타입을 모르니 무엇을 돌려줄지 정할 수 없습니다. 이런 트레이트는 dyn 으로 쓸 수 없습니다.

읽는 법 — note: 의 vtable 이 앞에서 본 메서드 표입니다. 그 표를 만들 수 있어야 한다고 하고, 3번 줄의 반환 타입 Self 를 까닭으로 짚습니다. 이 조건을 예전에는 "객체 안전(object safety)" 이라고 불렀고, 오래된 글에서는 그 이름으로 나옵니다.

종류가 정해져 있으면 열거형도 답이다

도형의 종류가 몇 가지로 정해져 있다면 열거형 하나로 묶을 수 있습니다. Box 도 표도 없습니다(7부).

퀴즈 — 트레이트 객체

Q. 이 기계에서 size_of::<&Circle>() 는 8 인데 size_of::<&dyn Shape>() 는 왜 16 일까요?

A. 값의 주소에 더해 그 타입의 메서드 표를 가리키는 주소를 하나 더 들고 있기 때문입니다 (dyn 참조는 주소 둘). 실제 타입을 모르는 채로 메서드를 부르려면 그 표가 필요합니다.

연관 타입 — 구현하는 쪽이 정하는 타입

트레이트 안에 type Item; 이라고 적어 두면, 구현마다 그 자리에 올 타입을 정합니다. 연관 타입(associated type)이라고 합니다. 앞에서 쓴 Add 의 Output, TryFrom 의 Error, impl Iterator<Item = u32> 의 Item 이 이것입니다.

타입 인자와 연관 타입의 차이

타입 인자를 받는 트레이트는 한 타입에 여러 번 구현할 수 있습니다. 연관 타입은 구현 하나에 답이 하나입니다.

연관 상수

i32::MAX 나 u8::BITS 처럼 타입 이름 뒤에 :: 로 붙는 상수가 연관 상수(associated constant)입니다. 트레이트에 적어 두면 "타입마다 다른 상수" 를 약속하게 할 수 있습니다.

&'static str — 문자열 리터럴의 타입을 줄이지 않고 적은 것입니다. 'static 은 11부에서 봅니다.

상위 트레이트 — 이것을 하려면 저것도

trait Named: Display 는 "Named 를 구현하려면 Display 도 구현해야 한다" 입니다. Display 를 Named 의 상위 트레이트(supertrait)라고 합니다. 그 덕에 기본 구현 안에서 self 를 {} 로 찍을 수 있습니다.

상위 트레이트를 빼먹으면 — E0277

Display 없이 Named 만 구현했습니다.

읽는 법 — 오류가 난 곳은 9번 줄의 impl 이고, note: 가 그 조건이 온 곳으로 3번 줄의 : Display 를 짚습니다. 고친 모양이 앞 슬라이드입니다.

포괄 구현 — 조건에 맞는 모든 타입에 한꺼번에

impl<T: Display> Shout for T 는 "Display 인 모든 타입" 에 Shout 를 구현합니다(blanket implementation). 문자열에도, 정수에도, 문자에도 메서드가 생깁니다.

표준 라이브러리의 포괄 구현 — "Display 면 to_string() 이 있다", "From 을 구현하면 Into 가 있다" 가 이렇게 만들어져 있습니다. 위 10번 줄이 T: Display 라는 것만 알고 to_string() 을 부르는 것이 앞의 것을 쓰는 모습입니다.

확장 트레이트 — 남의 타입에 메서드 붙이기

내 트레이트를 남의 타입(str)에 구현하는 것은 고아 규칙에 걸리지 않습니다 — 트레이트가 내 것이니까요. 표준 타입에 메서드를 더한 것처럼 쓸 수 있습니다. 이렇게 쓰는 트레이트를 확장 트레이트(extension trait)라고 부릅니다.

둘째 줄 — str 에 구현했는데 String 에서도 불립니다. String 이 str 로 보이는 까닭은 14부(Deref)에서 봅니다.

const 제네릭 — 값을 인자로

타입이 아니라 값(주로 길이)을 인자로 받습니다. 길이가 타입에 적히므로 Grid<u8, 2> 와 Grid<u8, 3> 은 서로 다른 타입입니다 — 배열 [T; N] 의 길이가 타입의 일부였던 것(3부)과 같습니다. 이 기능이 들어온 이야기는 1부에 있습니다.

퀴즈 — 더 깊이

Q. Iterator 는 왜 Iterator<T> 가 아니라 연관 타입 type Item 을 쓸까요?

A. 한 반복자가 내주는 원소의 타입은 하나로 정해져 있기 때문입니다. 타입 인자였다면 같은 타입에 Iterator<i32> 와 Iterator<String> 을 둘 다 구현할 수 있게 되고, 쓰는 쪽이 매번 골라 줘야 합니다(타입 인자와 연관 타입).
