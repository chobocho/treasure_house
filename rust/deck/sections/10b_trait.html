4장

표준 트레이트 ②

From 과 Into · TryFrom · FromStr · AsRef · 연산자 오버로딩

From 과 Into — 타입을 바꾸는 표준 방법

3장의 트레이트는 대부분 derive 한 줄로 붙었습니다. 이 장의 것은 직접 구현합니다 — 타입을 바꾸는 트레이트와 연산자의 트레이트입니다. "A 에서 B 를 만들 수 있다" 는 impl From<A> for B 로 적습니다. 그러면 반대 방향에서 부르는 a.into() 가 저절로 생깁니다.

이미 써 온 것 — String::from("…"), i64::from(x) (3부), 그리고 ? 가 오류를 바꿀 때 부르던 것(9부)이 전부 이 트레이트입니다. 9부에서 모양대로 쓴 impl From<ParseIntError> for CalcError 가 위 8번 줄과 같은 꼴입니다.

impl Into<String> — 넘기는 쪽을 편하게

문자열을 받아 가질 함수는 매개변수를 impl Into<String> 으로 두면 &str 과 String 을 둘 다 받습니다. 8부에서는 가질 함수는 String 으로 받는다고 했는데, 이렇게 두면 부르는 쪽이 .to_string() 을 쓰지 않아도 됩니다.

TryFrom — 실패할 수 있는 변환

모든 값이 바뀔 수 있는 것은 아닐 때 TryFrom 을 구현합니다. 3부에서 정수끼리 써 본 try_from 을 내 타입에 붙이는 것입니다. Result 를 돌려주고, try_into() 가 따라옵니다.

미리 쓰는 문법 — type Error = String; 은 실패했을 때 낼 오류의 타입을 적는 자리입니다. 연관 타입이라고 하며 6장에서 봅니다.
값의 조건을 타입으로 — Percent 를 만드는 길이 이것뿐이라면, Percent 를 받는 함수는 범위를 다시 검사할 필요가 없습니다.

FromStr — parse 가 내 타입을 만들게 한다

2부부터 써 온 parse 는 FromStr 트레이트를 부릅니다. "42".parse::<i32>() 가 되는 것은 i32 에 그 구현이 있어서입니다. 내 타입에 구현하면 문자열에서 바로 만들 수 있습니다. 오류의 타입은 앞 슬라이드처럼 type Err 에 적습니다.

AsRef — "그것으로 볼 수 있는 것"

impl Into<String> 이 "가질 함수" 의 것이라면 이것은 "읽기만 할 함수" 의 것입니다. 그런 함수는 6부에서 &str 로 받았습니다. AsRef<str> 로 받으면 String 을 통째로 넘겨도 됩니다.

표준 라이브러리에서는 — std::fs::read_to_string 같은 파일 함수가 경로를 AsRef<Path> 로 받습니다.

내 타입에는 + 가 없다 — E0369

3장의 == 처럼 + 도 트레이트입니다. 구현하지 않은 타입끼리는 더할 수 없습니다.

읽는 법 — 3장의 E0369 와 같은 꼴이고, note: 가 대는 이름이 PartialEq 에서 Add 로 바뀌었습니다. 그때와 달리 derive 를 권하는 help: 가 없습니다. 다음 슬라이드에서 직접 구현합니다.

Add 를 구현하면 + 가 된다

a + b 는 a.add(b) 를 부르는 문법입니다. std::ops::Add 를 구현합니다. 결과의 타입은 type Output 에 적습니다. TryFrom 의 type Error 와 같은 자리입니다.

다른 타입과의 연산, 단항 연산, +=

오른쪽 타입을 타입 인자로 바꿀 수 있고(Mul<f64>), 단항 - 는 Neg, += 는 AddAssign 입니다.

[] 도 트레이트다 — Index

인덱스 연산자 [] 는 Index 트레이트입니다. 8부에서 s[0] 이 막힌 것은 정수 하나를 받는 구현이 str 에 없어서였습니다. 인덱스의 타입도 정할 수 있어서, 문자열로 찾는 것도 만들 수 있습니다. index 는 값이 아니라 참조(&u32)를 돌려줍니다.

연산자마다 트레이트가 있다

3장과 이 장에서 본 연산자를 한 표로 모읍니다. 내 타입에 쓰고 싶은 연산자를 찾고, 그 오른쪽 칸의 트레이트를 구현합니다.

뜻이 분명할 때만 — 벡터의 덧셈처럼 누구나 같은 뜻으로 읽을 때 구현합니다. 새 연산자를 만들 수는 없고, && · || · = 는 바꿀 수 없습니다.

퀴즈 — 표준 트레이트 ②

Q. impl From<Celsius> for Fahrenheit 하나만 구현했습니다. let f: Fahrenheit = Celsius(0.0).into(); 는 컴파일될까요?

A. 됩니다. From 을 구현하면 반대쪽 Into 가 저절로 생깁니다 (From 과 Into). 6장의 포괄 구현이 그것을 해 줍니다.

5장

트레이트 객체

서로 다른 타입을 한 그릇에 · dyn Trait · 포인터 뒤에만 · &dyn 과 Box<dyn> · 주소 둘 · 컴파일 때 고르기와 실행 중에 고르기 · dyn 이 안 되는 트레이트 · 열거형과 견주기

벡터에는 한 가지 타입만 들어간다 — E0308

원과 정사각형을 한 벡터에 넣으려 합니다. 벡터의 원소 타입은 하나여야 하므로 첫 원소를 보고 Circle 로 정해지고, 둘째에서 막힙니다. 2장에서 -> impl Shape 가 두 타입을 돌려주지 못한 것과 같은 벽입니다 — 한 자리에는 한 타입입니다.

dyn Trait — "이 트레이트를 구현한 무언가"

dyn Shape 는 "Shape 를 구현한 어떤 타입" 입니다. 실제 타입은 실행 중에 정해집니다. 크기를 미리 알 수 없으므로 Box 같은 포인터 뒤에 둡니다. 이것이 트레이트 객체(trait object)입니다.

미리 쓰는 문법 — Box::new(값) 은 값을 힙에 두고 그것을 가리키는 포인터를 만듭니다. 14부에서 봅니다. 9부에서 한 낱말처럼 읽은 Box<dyn Error> 가 이 모양입니다 — "Error 를 구현한 무언가" 를 Box 뒤에 둔 트레이트 객체입니다.

dyn 은 포인터 뒤에만 둘 수 있다 — E0277

dyn Shape 를 지역 변수에 직접 담으려 하면 크기를 알 수 없다고 합니다. 원일 수도, 더 큰 무엇일 수도 있기 때문입니다.

읽는 법 — 오류는 둘입니다. 여기서 뺀 첫째는 E0308 로, Circle 과 dyn Shape 가 다른 타입이라는 말입니다. 위의 둘째는 2장에서 읽은 E0277 그대로 타입 dyn Shape 와 트레이트 Sized 를 댑니다. Sized 는 "크기가 컴파일할 때 정해진다" 는 트레이트이고, note: 는 지역 변수가 그래야 한다고 합니다. 마지막 help: 가 권하는 &dyn Shape 가 다음 슬라이드입니다.

&dyn Trait, 그리고 Box<dyn Trait> 를 돌려주기

빌려 쓸 때는 &dyn Shape 입니다. 그리고 2장에서 -> impl Shape 로는 못 하던 "경우에 따라 다른 타입을 돌려주기" 가 Box<dyn Shape> 로는 됩니다.

dyn 참조는 주소 둘이다

보통 참조는 주소 하나입니다. 트레이트 객체의 참조는 값의 주소에 더해 "그 타입의 메서드 표" 의 주소를 함께 들고 다닙니다. 메서드를 부를 때 그 표에서 찾아갑니다.

컴파일 때 고르기, 실행 중에 고르기

제네릭과 dyn 은 같은 트레이트를 쓰는 두 길입니다. 갈리는 곳은 어느 타입의 메서드를 부를지를 언제 정하느냐입니다. 컴파일할 때 정하면 정적 디스패치(static dispatch), 실행 중에 표에서 찾으면 동적 디스패치(dynamic dispatch)입니다.

"타입마다 한 벌씩" 이 1장의 단형화, "표" 가 앞 슬라이드의 메서드 표입니다. 아래 두 줄은 앞에서 막혔다가 dyn 으로 푼 두 가지입니다.

먼저 제네릭 — 타입이 컴파일할 때 정해지는 자리에서는 제네릭을 씁니다. "여러 종류를 한데 모은다", "실행 중에 고른다" 가 필요할 때 dyn 을 꺼냅니다.

모든 트레이트가 객체가 될 수는 없다 — E0038

Self 를 값으로 돌려주는 메서드가 있는 트레이트입니다. dyn 뒤에서는 실제 타입을 모르니 무엇을 돌려줄지 정할 수 없습니다. 이런 트레이트는 dyn 으로 쓸 수 없습니다.

읽는 법 — note: 의 vtable 이 앞에서 본 메서드 표입니다. 그 표를 만들 수 있어야 한다고 하고, 3번 줄의 반환 타입 Self 를 까닭으로 짚습니다. 첫 help: 는 그 메서드를 다른 트레이트로 옮기라고 권합니다. 이 조건을 예전에는 "객체 안전(object safety)" 이라고 불렀고, 오래된 글에서는 그 이름으로 나옵니다.

종류가 정해져 있으면 열거형도 답이다

도형의 종류가 몇 가지로 정해져 있다면 7부에서 본 데이터를 가진 열거형 하나로 묶을 수 있습니다. Box 도 표도 없습니다.

앞으로 더할 일이 많은 쪽이 종류인지 동작인지를 보고 고릅니다.

퀴즈 — 트레이트 객체

Q. 이 기계에서 size_of::<&Circle>() 는 8 인데 size_of::<&dyn Shape>() 는 왜 16 일까요?

A. 값의 주소에 더해 그 타입의 메서드 표를 가리키는 주소를 하나 더 들고 있기 때문입니다 (dyn 참조는 주소 둘). 실제 타입을 모르는 채로 메서드를 부르려면 그 표가 필요합니다.

6장

더 깊이

연관 타입 · 연관 상수 · 상위 트레이트 · 포괄 구현 · 확장 트레이트 · const 제네릭

연관 타입 — 구현하는 쪽이 정하는 타입

4장에서 type Error = String; 과 type Output = Vec2; 를 뜻은 미루고 적었습니다. 트레이트가 "이 타입은 구현하는 쪽이 정한다" 고 비워 둔 자리이고, 연관 타입(associated type)이라고 합니다.

읽는 법 — 트레이트는 3번 줄에 type Item; 이라고 자리만 두고, 구현이 14번 줄에서 그 자리에 올 타입을 정합니다. 쓰는 쪽은 26번 줄처럼 C::Item 으로 적습니다. 2장의 impl Iterator<Item = u32> 의 Item 도 이것입니다.

타입 인자와 연관 타입의 차이

앞 슬라이드의 Container 를 Container<T> 로 써도 될 것 같습니다. 다른 점은 구현의 수입니다. 타입 인자를 받는 트레이트는 한 타입에 여러 번 구현할 수 있고, 연관 타입은 구현 하나에 답이 하나입니다.

연관 상수 — 타입마다 다른 상수

i32::MAX 나 u8::BITS 처럼 타입 이름 뒤에 :: 로 붙는 상수가 연관 상수(associated constant)입니다. 트레이트에 적어 두면 "타입마다 다른 상수" 를 약속하게 할 수 있습니다.

미리 쓰는 문법 — &'static str 은 문자열 리터럴의 타입을 줄이지 않고 적은 것입니다. 'static 은 11부에서 봅니다.

상위 트레이트 — 이것을 하려면 저것도

trait Named: Display 는 "Named 를 구현하려면 Display 도 구현해야 한다" 입니다. Display 를 Named 의 상위 트레이트(supertrait)라고 합니다. 그 덕에 기본 구현 안에서 self 를 {} 로 찍을 수 있습니다.

이미 써 온 것 — 9부에서 Error 를 구현하려면 Debug 도 있어야 했고, 3장에서 Copy 에는 Clone 이 함께 있어야 했습니다. 둘 다 이 관계입니다.

상위 트레이트를 빼먹으면 — E0277

Display 없이 Named 만 구현했습니다.

읽는 법 — E0277 이 대는 타입은 Port, 트레이트는 Display 입니다. 오류가 난 곳은 9번 줄의 impl 이고, note: 가 그 조건이 온 곳으로 3번 줄의 : Display 를 짚습니다. 고친 모양이 앞 슬라이드입니다.

포괄 구현 — 조건에 맞는 모든 타입에 한꺼번에

Display 를 구현하면 to_string() 이 따라왔고, From 을 구현하면 into() 가 저절로 생겼습니다. 그 "저절로" 를 만드는 것이 포괄 구현(blanket implementation)입니다. impl<T: Display> Shout for T 는 "Display 인 모든 타입" 에 Shout 를 구현합니다 — 문자열에도, 정수에도, 문자에도.

표준 라이브러리의 포괄 구현 — 위의 두 "저절로" 가 이렇게 만들어져 있습니다. 10번 줄이 T: Display 라는 것만 알고 to_string() 을 부르는 것이 첫째 것을 쓰는 모습입니다.

확장 트레이트 — 남의 타입에 메서드 붙이기

str 에 낱말 수를 세는 메서드가 있었으면 합니다. str 은 남의 타입이지만, 내 트레이트를 거기에 구현하는 것은 고아 규칙에 걸리지 않습니다. 트레이트가 내 것이기 때문입니다. 표준 타입에 메서드를 더한 것처럼 쓸 수 있고, 이렇게 쓰는 트레이트를 확장 트레이트(extension trait)라고 부릅니다.

출력 마지막 줄의 2 — str 에 구현했는데 String 에서도 불립니다. String 이 str 로 보이는 까닭은 14부(Deref)에서 봅니다. 부르는 쪽에서는 트레이트가 보여야 한다는 것도 그대로입니다.

const 제네릭 — 값을 인자로

3부에서 배열 [T; N] 의 길이는 타입의 일부였습니다. 내 타입에도 그런 N 을 둘 수 있습니다. 타입이 아니라 값(주로 길이)을 인자로 받는 const 제네릭입니다. 길이가 타입 이름에 적힙니다 — 예제의 Grid<u8, 2> 와 Grid<bool, 8> 이 그렇습니다.

역사 — 이 기능이 들어온 이야기는 1부에 있습니다.
