읽는 법 — 이 책의 증거 방식

슬라이드 한 장의 구조 · 어두운 상자는 진짜 출력 · 일부러 틀린 예제 · 손댄 곳 세 가지

이 책은 무엇인가

다른 언어를 하나쯤 써 본 사람이 Rust 의 문법을 처음부터 끝까지 한 번 훑도록 만든 슬라이드 책입니다. 한 장에 한 가지를, 돌아가는 예제 하나와 함께 봅니다.

  • 돌아가는 예제만 — 코드는 전부 실제 파일이고, 출력은 전부 실제로 돌려 받은 것입니다.
  • 틀린 코드도 돌린다 — 컴파일 오류가 곧 수업인 곳에서는 오류 메시지를 그대로 싣습니다.
  • 표준 라이브러리만 — 바깥 크레이트 없이, 설치 직후의 Rust 로 전부 따라 할 수 있습니다.
  • 역사 포함 — 문법이 왜 이렇게 생겼는지를 1부가 먼저 이야기합니다.

슬라이드 한 장은 이렇게 읽는다

밝은 상자가 소스 파일, 어두운 상자가 그 파일을 돌린 화면입니다. 둘은 늘 짝입니다.

  • 밝은 상자 위의 꼬리표는 파일 경로입니다. 이 책의 저장소 rust/ex/ 아래에 그대로 있습니다.
  • 어두운 상자의 첫 줄 $ 뒤가 입력한 명령, 그 아래가 화면에 나온 글자입니다.

손으로 쓴 출력은 한 줄도 없다

책을 만드는 도구가 이 약속을 강제합니다. 사람이 "아마 이렇게 나올 것" 이라고 적을 자리가 없습니다.

예제 파일→ rustc 로 컴파일·실행→ 화면을 파일로 저장→ 슬라이드에 실음
  • 예제를 고치고 다시 돌리지 않으면 책이 조립되지 않습니다(소스와 화면의 지문을 대조합니다).
  • 슬라이드에 실린 코드와 화면은 조립이 끝난 뒤 원본과 한 번 더 글자 단위로 맞춰 봅니다.
  • 기대와 다른 결과(뜻밖의 오류, 뜻밖의 종료 코드, 경고)가 나오면 저장 자체를 거부합니다.

이 기계

모든 화면은 한 대의 기계, 한 판의 컴파일러에서 나왔습니다. 안드로이드 폰(64비트 ARM) 위의 Rust 입니다.

여러분의 화면과 다를 수 있는 곳 — 컴파일러가 더 새 판이면 오류 메시지의 문구나 권하는 고침이 조금 다를 수 있습니다. 오류 번호(E0382 같은 것)와 뜻은 같습니다.

고백 하나 — 화면의 rustc 는 포장지다

이 기계에서는 링커를 따로 일러 줘야 실행 파일이 만들어집니다. 그래서 화면의 rustc 는 진짜 rustc 에 옵션 둘을 덧붙여 부르는 두 줄짜리 스크립트입니다.

  • -C linker=… — 어떤 링커를 쓸지. 기계 사정일 뿐, 프로그램의 뜻은 바뀌지 않습니다.
  • -C codegen-units=1 — 메모리를 아끼려고 한 번에 한 덩이씩 컴파일합니다.
여러분의 기계에서는 화면에 적힌 명령을 그대로 치면 됩니다.

명령에 늘 --edition 2024 가 붙는 까닭

rustc 를 그냥 부르면 가장 옛 문법 판으로 컴파일합니다. 이 책의 예제는 가장 새 판인 2024 에디션으로 썼으므로 명령마다 그렇게 적습니다.

화면의 명령뜻
rustc --edition 2024 a.rs && ./a컴파일이 성공하면 이어서 실행
rustc --edition 2024 a.rs 만컴파일에서 끝났다(오류가 났거나, 컴파일만 보는 예제)
rustc --edition 2024 --test a.rs시험 함수를 모아 돌리는 실행 파일을 만든다
cargo run -q프로젝트 디렉터리 예제 — 에디션은 설정 파일에 있다

에디션이 무엇인지는 1부 4장과 2부 1장에서 봅니다.

일부러 틀린 예제

제목이 "— E0308" 처럼 오류 번호로 끝나는 장은 컴파일되지 않는 코드를 보여 줍니다. 화면은 컴파일러가 실제로 한 말이고, 끝의 [종료 코드 1] 은 컴파일이 실패했다는 표시입니다.

틀린 예제 뒤에는 늘 고친 예제가 옵니다 — 같은 장이나 바로 다음 장에서 돌아가는 판을 보여 줍니다.

실행 중에 죽는 예제

컴파일은 되지만 돌다가 죽는(패닉) 예제도 있습니다. Rust 프로그램이 패닉으로 끝나면 종료 코드는 101 입니다.

(tid) — 원래 이 자리에는 실행할 때마다 달라지는 스레드 번호가 찍힙니다. 책에서는 tid 로 바꿔 적었습니다. 화면에 손댄 곳은 다음 장의 세 가지가 전부입니다.

화면에 손댄 곳은 세 가지뿐이다

같은 예제를 두 번 돌려 글자까지 같아야 책에 싣습니다. 그러려면 돌릴 때마다 달라지는 값만은 고정해야 합니다.

원래 화면책에서까닭
패닉 줄의 스레드 번호(tid)실행마다 다르다
시험·빌드에 걸린 시간0.00s실행마다 다르다
작업 디렉터리의 긴 경로/work기계마다 다르다

경고는 숨기지 않는다

이 책의 예제는 경고 없이 컴파일됩니다. 경고가 화면에 보인다면 그 경고가 수업이라는 뜻입니다.

  • 경고가 나도 실행 파일은 만들어집니다. 그래서 명령이 두 줄로 나뉘어 보입니다.
  • 컴파일러는 고치는 법도 말합니다 — 일부러 안 쓰는 이름은 _spare 처럼 밑줄로 시작합니다.

버전 배지와 출처

"이 문법은 언제부터" 와 "그 일은 언제" 는 기억으로 적기 쉬운 숫자입니다. 이 책은 그 숫자를 손으로 적지 않고 공식 릴리스 노트에서 가져옵니다.

표시뜻어디서 오나
이 문법이 안정판에 들어온 버전그 버전의 릴리스 노트에 해당 줄이 있어야 붙는다
그 버전이 나온 날릴리스 노트의 제목 줄
역사 주장의 근거받아 둔 원문에서 근거 문장을 찾아야 붙는다
배지가 없는 문법은 1.0 부터 있었거나, 버전을 따질 필요가 없을 만큼 오래된 것입니다.

직접 돌려 보기

읽기만 해서는 익지 않습니다. 예제는 전부 파일 하나로 돌아가니, 고쳐 가며 컴파일러와 이야기해 보세요.

  1. Rust 를 설치합니다. 공식 설치 도구 rustup 이 컴파일러 rustc 와 빌드 도구 cargo 를 함께 깝니다.
  2. 슬라이드의 밝은 상자를 이름.rs 파일로 저장합니다(꼬리표의 파일 이름 그대로).
  3. 어두운 상자 첫 줄의 명령을 그대로 칩니다.
  4. 한 군데를 고쳐 다시 컴파일합니다. 오류가 나면 help: 줄부터 읽습니다.
