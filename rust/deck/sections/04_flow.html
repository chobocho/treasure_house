4부

식과 제어 흐름

식과 문 · if 는 값을 낸다 · loop · while · for 와 범위 · 이름표 · match 맛보기

이 부에서 할 일

Rust 는 "식 중심" 언어입니다. if 도, 블록도, match 도 값을 냅니다. 이 한 가지를 알면 이 부의 나머지는 다른 언어에서 본 것과 크게 다르지 않습니다.

  • 1장 — 식과 문: 무엇이 값을 내고 무엇이 내지 않는가, 세미콜론의 뜻
  • 2장 — if: 조건은 반드시 bool, 그리고 if 는 식이다
  • 3장 — 반복: loop · while · for, 범위, break 와 이름표
  • 4장 — match 맛보기: 값으로 가르기, 빠짐없이 다뤄야 한다 (패턴 전체는 7부)

1장

식과 문

값을 내는 것과 내지 않는 것 · 블록의 값 · 세미콜론이 하는 일 · let 은 문 · 대입의 값

식은 값을 내고, 문은 내지 않는다

x + 1 처럼 계산하면 값이 나오는 것이 식(expression)입니다. let x = 5; 처럼 일을 하고 끝나는 것이 문(statement)으로, 2부에서 본 대로 세미콜론으로 끝납니다. 이 부의 if · 반복 · match 는 모두 이 구별 위에 서 있습니다.

거의 전부가 식이다 — 5번 줄의 println! 호출조차 값을 냅니다. 출력 마지막 줄의 () 가 그 값입니다. 쓸모는 없지만 3부에서 본 유닛, 곧 빈 튜플이라는 값입니다.

블록도 식이다

중괄호로 묶은 블록은 안의 문을 차례로 실행하고, 세미콜론 없는 마지막 식의 값을 자기 값으로 냅니다.

쓸모 — 중간 계산에만 쓰는 이름(w, h)을 블록 안에 가둘 수 있습니다. 블록이 끝나면 두 이름은 스코프를 벗어납니다.

세미콜론은 "값을 버려라" 다 — E0308

식 뒤에 세미콜론을 붙이면 값을 버리고 문이 됩니다. 앞 슬라이드의 마지막 식 w * h 에 붙이면 블록의 값은 () 가 됩니다.

처음에 자주 만나는 오류 — 3부에서 여러 번 본 E0308 입니다. 이번에는 "i32 를 기대했는데 () 를 찾았다" 입니다. 찾은 쪽이 () 이면 마지막 식 뒤의 세미콜론을 먼저 의심합니다. help: 도 5번 줄의 그 세미콜론을 지우라고 짚습니다.

let 은 식이 아니다

let 은 문이라 값을 내지 않습니다. 그래서 다른 식 안에 넣을 수 없습니다.

예외 하나 — note: 줄이 말하듯 if 와 while 의 조건 자리에는 let 이 올 수 있습니다. if let 이라는 문법으로, 7부에서 봅니다.

대입은 식이지만 값은 () 다

C 에서는 a = b = 5 로 둘에 한꺼번에 넣을 수 있습니다. Rust 에서 대입식 a = 5 의 값은 5 가 아니라 () 입니다.

덕분에 막히는 실수 — if a = 5 처럼 == 를 = 로 잘못 쓰면 조건이 bool 이 아니어서 컴파일되지 않습니다. 2장에서 직접 내 봅니다(== 를 = 로 잘못 쓰면).

무엇이 식이고 무엇이 문인가

값 칸이 "없음" 인 줄만 문이고, 나머지는 모두 식입니다. if · match · loop 줄은 이어지는 장에서 하나씩 확인합니다.

코드종류값
let x = 5;문없음
fn f() { } 같은 정의문없음
x + 1식계산한 값
{ …; 식 }식마지막 식의 값
if c { a } else { b }식고른 갈래의 값
match v { … }식맞은 갈래의 값
loop { break v; }식break 가 준 값
x = 5식()
식;문없음 — 식의 값을 버린다

퀴즈 — 식과 문

Q. let v = { let a = 2; a * 10 }; 에서 v 는 얼마이고, 블록 뒤에서 a 를 쓸 수 있을까요?

A. v 는 20 입니다 — 블록의 값은 세미콜론 없는 마지막 식 a * 10 의 값입니다(블록도 식이다). a 는 블록 안에서 만든 이름이라 블록이 끝나면 스코프를 벗어나 쓸 수 없습니다(3부).

2장

if

조건은 bool · if 는 식 · 갈래의 타입은 같아야 · else 없는 if · 논리 연산

if — 조건에 괄호는 없고, 중괄호는 꼭 쓴다

조건에 따라 할 일을 가르는 가장 기본 도구입니다. 다른 언어와 달리 조건에 괄호를 두르지 않습니다. 대신 본문의 중괄호는 한 줄이어도 반드시 씁니다.

조건은 bool 이어야 한다 — E0308

C·Python·JavaScript 는 조건 자리의 정수가 0 이 아니면 "참" 으로 봐 줍니다. Python·JavaScript 는 비지 않은 문자열도 그렇게 봅니다. Rust 는 그러지 않습니다.

읽는 법 — 1장의 세미콜론 오류와 같은 E0308 입니다. 이번에는 3번 줄의 조건 자리를 짚고 "bool 을 기대했는데 정수를 찾았다" 고 합니다. 고친 것은 무엇과 견주는지 직접 쓴다에 있습니다.

== 를 = 로 잘못 쓰면 — E0308

C 에서 악명 높은 실수입니다. 견주려다 대입을 써 버립니다. 1장에서 본 대로 대입식의 값은 () 이고, () 는 bool 이 아니므로 조건 자리에 올 수 없습니다.

무엇을 하려 했는지까지 — 앞 슬라이드와 같은 오류이고, 찾은 쪽만 정수에서 () 로 바뀌었습니다. help: 가 == 로 고친 줄을 보여 줍니다.

무엇과 견주는지 직접 쓴다

정수를 조건에 쓴 예제를 고친 것입니다. "참 같은 값" 이라는 개념이 없으므로 무엇과 견주는지를 코드에 적습니다. 코드가 조금 길어지는 대신 뜻이 하나로 정해집니다.

if 는 값을 낸다

if 가 식이므로 그 결과를 바로 변수에 담습니다. 그래서 Rust 에는 삼항 연산자 c ? a : b 가 없습니다.

값으로 쓸 때는 갈래도 블록이므로 마지막 식에 세미콜론을 붙이지 않습니다. 세미콜론은 let 문 전체의 끝에 하나만 붙입니다.

두 갈래의 타입은 같아야 한다 — E0308

변수의 타입은 하나입니다. if 의 값이 어떤 때는 문자열, 어떤 때는 정수일 수는 없습니다.

읽는 법 — 번호는 같은 E0308 이고, 첫 줄이 "if 와 else 의 타입이 맞지 않는다" 로 바뀌었습니다. 첫 갈래를 보고 &str 을 기대했는데 else 쪽에서 정수를 만났다고 두 자리를 함께 짚어 줍니다.

값으로 쓰려면 else 가 있어야 한다 — E0317

조건이 거짓일 때의 값이 없으면 변수에 넣을 것이 없습니다. else 없는 if 의 값은 () 입니다.

읽는 법 — = note: 가 "else 없는 if 식의 값은 () 다" 라고 적습니다. = help: 는 기대한 타입의 값을 내는 else 블록을 더하라고 합니다.

&& 와 || 는 필요한 만큼만 본다

조건 여럿을 묶는 논리 연산자는 &&(그리고), ||(또는), !(아님)입니다. 왼쪽만으로 답이 정해지면 오른쪽은 평가하지 않습니다.

단락 평가(short-circuit) — i < len && v[i] > 0 처럼 앞 조건이 뒤 조건의 안전을 지키는 코드가 이 성질에 기댑니다. check 처럼 매개변수와 반환 타입이 있는 함수를 만드는 법은 5부에서 봅니다.

퀴즈 — if

Q. let n = 3; if n { … } 는 왜 컴파일되지 않고, 어떻게 고칠까요?

A. 조건이 bool 이 아니라 정수라서 E0308 이 납니다 (조건은 bool). if n != 0 { … } 처럼 무엇과 견주는지 적습니다.

3장

반복

loop · break 로 값 내기 · while · for 와 범위 · C 식 for 와 ++ 는 없다 · continue · 이름표

loop — 멈추라고 할 때까지

Rust 의 반복문은 loop · while · for 셋입니다. 가장 단순한 loop 부터 봅니다. 조건 없이 돌고, break 를 만나야 끝납니다.

break 는 값을 들고 나올 수 있다

loop 도 식입니다. break 값; 이라고 쓰면 그 값이 loop 전체의 값이 됩니다. 앞 슬라이드의 예제에서 break 뒤에 n 을 적고, loop 전체를 let 으로 받았습니다.

"될 때까지 다시" 에 쓴다 — 입력이 올바를 때까지 다시 받거나, 조건을 채우는 첫 값을 찾는 코드가 이 모양입니다. 결과를 담을 가변 변수를 바깥에 따로 둘 필요가 없습니다.

while — 조건이 참인 동안

돌기 전에 조건을 봅니다. 처음부터 거짓이면 한 번도 돌지 않습니다.

6번 줄 — if 의 값을 그대로 n 에 넣었습니다. 짝수면 반, 홀수면 세 배에 1 을 더한 값입니다.

while true 대신 loop 를 쓰라고 한다

끝없이 도는 반복은 loop 로 쓰는 것이 Rust 의 관례이고, 컴파일러도 그렇게 권합니다.

까닭 — loop 는 "반드시 한 번은 돌고, break 로만 나온다" 는 것을 컴파일러가 압니다. 그래서 break 로 값을 들고 나올 수 있습니다. while true 는 그렇지 못합니다 — 다음 슬라이드에서 확인합니다.

while 에서는 break 로 값을 낼 수 없다 — E0571

break 로 값을 낸 loop 예제를 while true 로 바꿨습니다. 컴파일러는 앞 슬라이드의 경고에 이어 break n 을 거절합니다. while 은 조건이 거짓이 되어 끝날 수도 있고, 그때는 낼 값이 없기 때문입니다.

고치려면 — help: 는 값을 떼고 break; 만 쓰라고 합니다. 값이 필요한 것이라면 경고가 권한 대로 while true 를 loop 로 되돌립니다.

for — 범위의 값을 하나씩

정해진 횟수만큼 돌 때는 for 와 범위(range)를 씁니다. a..b 는 b 를 빼고, a..=b 는 b 까지 넣습니다.

거꾸로, 그리고 건너뛰며

범위에 rev() 를 붙이면 거꾸로, step_by(n) 을 붙이면 n 칸씩 갑니다. 범위에 메서드를 부를 때는 괄호로 감쌉니다.

거꾸로 쓴 범위는 비어 있다

5..1 은 "5 부터 거꾸로 1 까지" 가 아닙니다. 시작이 끝보다 크면 원소가 하나도 없는 범위입니다. 오류도 경고도 없이 한 번도 돌지 않습니다.

읽는 법 — for 본문은 아무것도 찍지 않았고, 출력 마지막 줄은 len() 으로 센 두 범위의 길이입니다. 5..1 은 0, 1..5 는 4 입니다.
거꾸로 세려면 앞 슬라이드처럼 (1..=5).rev() 라고 씁니다.

for 는 컬렉션의 원소를 하나씩 꺼낸다

for 뒤에는 범위뿐 아니라 배열 같은 컬렉션이 올 수 있습니다. 번호가 함께 필요하면 enumerate() 가 (번호, 원소) 짝을 주고, for 가 그 튜플을 3부에서 본 대로 풀어 받습니다.

iter() 가 무엇인지는 12부(반복자)에서 봅니다. 지금은 "차례로 꺼내 주는 것" 으로 충분합니다.

번호로 돌지 말고 원소로 돈다

C 에서 온 습관대로 번호를 돌려 scores[i] 로 꺼내도 되기는 합니다. 하지만 원소를 직접 받는 쪽이 짧고, 번호를 잘못 써서 배열의 범위를 넘을 일도 없습니다.

C 식의 for 는 없다

for (초기화; 조건; 증가) 꼴은 Rust 에 없습니다. 컴파일러는 for 바로 뒤를 반복 변수가 올 자리(패턴)로 읽으려다 막힙니다.

고치면 — for i in 0..3 { … }. 변수 선언, 끝 조건, 증가가 범위 하나에 들어 있습니다. 첫 오류의 help: 대로 let 만 지워서는 풀리지 않습니다 — 둘째 오류가 바로 그 뒤의 = 를 짚습니다.

++ 도 없다

증가·감소 연산자 ++ · -- 가 없습니다. 컴파일러는 다른 언어에서 온 사람이 무엇을 하려 했는지 알고 고칠 방법을 알려 줍니다.

고치면 — help: 대로 i += 1; 이라고 씁니다. 이 장의 예제가 n += 1 · steps += 1 로 써 온 꼴입니다.

continue — 이번 바퀴는 여기까지

continue 는 본문의 나머지를 건너뛰고 다음 바퀴로 갑니다.

break 는 가장 안쪽 반복문만 끝낸다

반복문이 겹쳐 있을 때 break 는 자기를 감싼 가장 안쪽 것 하나만 끝냅니다. 곱이 42 가 되는 짝을 "하나만" 찾으려 했는데, 바깥 반복은 계속 돌아 둘을 찾았습니다.

이름표를 붙여 바깥 반복문을 끝낸다

반복문 앞에 '이름: 을 붙이고 break '이름 이라고 쓰면 그 반복문을 끝냅니다. continue 에도 똑같이 쓸 수 있습니다.

작은따옴표로 시작하는 이름 — 반복문의 이름표와, 뒤에 나올 수명(11부)이 이 모양을 씁니다. 문자 'a' 와 달리 닫는 따옴표가 없습니다.

반복 변수는 반복문 밖에서 보이지 않는다 — E0425

반복문의 본문도 블록입니다. for 의 변수와 본문에서 만든 변수는 그 블록이 스코프이고, 반복문 뒤에서 쓰면 3부에서 본 E0425 가 그대로 납니다.

끝난 뒤에도 필요한 값은 반복문 앞에 let mut 로 만들어 두거나, loop 의 break 값 으로 받습니다.

어느 반복문을 쓸까

이 장에서 본 것을 상황별로 모았습니다. 왼쪽에서 상황을 찾아 오른쪽을 씁니다.

상황쓸 것
횟수가 정해져 있다 · 컬렉션의 원소마다for x in …
조건이 참인 동안while 조건
끝없이, 또는 가운데서 빠져나온다loop + break
반복의 결과로 값 하나가 필요하다loop + break 값
겹친 반복을 한꺼번에 끝낸다이름표 'outer:
대부분은 for 입니다. 번호를 손으로 올리는 while 을 쓰고 있다면 for 로 바꿀 수 있는지 먼저 봅니다.

퀴즈 — 반복

Q. for i in 5..1 { println!("{i}"); } 는 무엇을 찍을까요?

A. 아무것도 찍지 않습니다. 시작이 끝보다 큰 범위는 비어 있습니다 (거꾸로 쓴 범위). 5, 4, 3, 2 를 찍으려면 (2..=5).rev() 라고 씁니다.

4장

match 맛보기

값으로 가르기 · _ · 빠짐없이 · | 와 범위 · 블록 갈래 · 이름과 가드 · 갈래의 순서와 타입 · if 와 견주기

match — 값에 따라 갈래를 고른다

한 값이 여러 경우 가운데 무엇인지 가를 때는 else if 사슬 대신 match 를 씁니다. 값을 위에서부터 갈래(arm)의 패턴(pattern)과 견주어, 처음 맞는 갈래 하나를 실행합니다. => 왼쪽이 패턴이고, _ 는 "나머지 전부" 입니다.

switch 와 다른 점 — 갈래 끝에 break 가 없습니다. 맞은 갈래 하나만 실행하고 끝납니다. 그리고 match 도 식이라 값을 냅니다 — 예제도 그 값을 name 에 담았습니다.

빠뜨린 경우가 있으면 컴파일되지 않는다 — E0004

match 는 가능한 값을 빠짐없이 다뤄야 합니다. 앞 슬라이드에서 _ 갈래를 지우면 컴파일러가 빠진 값을 알려 줍니다.

읽는 법 — i32::MIN..=0_i32 와 4_i32..=i32::MAX, 곧 "0 이하와 4 이상이 빠졌다" 입니다. i32::MIN · i32::MAX 는 3부에서 본 양 끝 값이고, ..= 는 3장의 범위 표기입니다.
빠짐없음(exhaustiveness) — Rust 가 믿을 만한 까닭의 하나입니다. 나중에 경우를 하나 더 만들면(열거형, 7부), 그것을 다루지 않은 match 를 컴파일러가 전부 찾아 줍니다.

여러 값은 | 로, 이어진 값은 범위로

한 갈래에 패턴을 여럿 쓰려면 | 로 잇습니다. 이어진 값은 a..=b 범위로 씁니다. 문자에도 됩니다.

순서가 뜻을 만든다 — 'e' 는 둘째 갈래('a'..='z')에도 맞지만 첫 갈래에서 이미 걸립니다.
&'static str — 함수 kind 의 반환 타입입니다. 지금은 "문자열 리터럴의 타입" 으로 읽으면 됩니다. 'static 은 11부에서, 함수 정의는 5부에서 봅니다.

전부 다뤘으면 _ 는 필요 없다

bool 의 값은 둘뿐입니다. 둘을 다 썼으면 빠짐없이 다룬 것이므로 _ 갈래가 없어도 됩니다.

갈래가 길면 블록으로

=> 뒤에는 식 하나가 옵니다. 여러 줄이 필요하면 블록을 씁니다. 1장에서 본 대로 블록의 마지막 식이 그 갈래의 값이 됩니다.

String::from — format! 이 돌려주는 것은 String 이라, 첫 갈래도 문자열 리터럴을 String 으로 바꿔 두 갈래의 타입을 맞췄습니다. String 은 6부에서 봅니다.

이름으로 받고 조건 붙이기

패턴 자리에 이름을 쓰면 값이 그 이름에 묶입니다. 뒤에 if 조건 을 붙여 갈래를 더 좁힐 수 있습니다. 이 조건을 가드(guard)라고 합니다.

패턴의 나머지 — 구조를 풀어 헤치는 패턴, @ 묶기 같은 것은 7부에서 한꺼번에 봅니다. 가드도 거기서 다시 나옵니다.

닿을 수 없는 갈래는 경고한다

_ 를 맨 위에 두면 모든 값이 거기서 걸립니다. 아래 갈래는 영영 실행되지 않고, 컴파일러가 그것을 알려 줍니다.

_ 는 늘 마지막에 둡니다. 경고일 뿐이라 프로그램은 돌았고, 답은 "다섯" 이 아니라 "아무거나" 로 나왔습니다.

갈래의 타입도 같아야 한다 — E0308

if 의 두 갈래와 마찬가지입니다. match 가 값을 내려면 모든 갈래가 같은 타입의 값을 내야 합니다.

읽는 법 — if 때와 같은 E0308 이고, 첫 줄만 "match 갈래들의 타입이 맞지 않는다" 로 바뀌었습니다. 4번 줄에서 &str 로 정해졌는데 5번 줄에서 정수를 만났다고 짚습니다.

튜플로 묶어 한 번에 가르기

값 둘을 튜플로 묶으면 두 조건의 조합을 표처럼 적을 수 있습니다. _ 는 한 칸에서도 "아무거나" 로 쓰입니다.

if 와 match, 어느 쪽을 쓸까

이 부에서 본 가르는 도구 둘을 견줍니다. 왼쪽에서 상황을 찾아 오른쪽을 씁니다.

상황쓸 것
참·거짓 하나로 가른다if / else
서로 다른 조건을 차례로 본다else if 사슬
한 값이 여러 경우 가운데 무엇인가match
경우를 빠뜨리면 안 된다match — 컴파일러가 확인한다
값의 구조를 풀어 헤친다match (7부)
다음은 함수 — 블록 · if · match 가 값을 내는 것을 봤습니다. 5부에서는 함수의 반환값도 같은 규칙, 곧 "세미콜론 없는 마지막 식" 으로 정해진다는 것을 봅니다.

퀴즈 — match

Q. i32 값을 1, 2, 3 세 갈래로만 가른 match 는 왜 컴파일되지 않을까요?

A. i32 에는 그 셋 말고도 값이 있기 때문입니다. 컴파일러는 빠진 범위(0 이하와 4 이상)를 짚으며 E0004 를 냅니다(빠뜨린 경우). _ => … 갈래를 더하면 됩니다.
