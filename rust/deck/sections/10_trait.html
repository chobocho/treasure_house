10부

제네릭과 트레이트

타입을 인자로 · 할 수 있는 일로 묶기 · 표준 트레이트 · 연산자 · 트레이트 객체 · 연관 타입

이 부에서 할 일

같은 코드를 타입마다 다시 쓰지 않게 해 주는 것이 제네릭(generic)이고, "이 타입은 이런 일을 할 수 있다" 를 적는 것이 트레이트(trait)입니다. 둘은 한 쌍입니다 — 제네릭이 "어떤 타입이든" 이라고 하면, 트레이트가 "단, 이것을 할 수 있는" 이라고 조건을 답니다.

  • 1장 — 제네릭: 함수, 구조체, 열거형, impl
  • 2장 — 트레이트: 정의, 구현, 기본 메서드, 조건(바운드)
  • 3장 — 표준 트레이트 ①: Debug · Display · Clone · PartialEq · Ord · Hash · Default
  • 4장 — 표준 트레이트 ②: From · FromStr · 연산자 오버로딩
  • 5장 — 트레이트 객체: dyn Trait
  • 6장 — 더 깊이: 연관 타입, 상위 트레이트, 포괄 구현, const 제네릭

1장

제네릭

같은 코드를 두 번 쓰지 않기 · T · 조건이 필요하다 · 구조체와 열거형 · impl<T>

타입만 다른 함수 둘

가장 큰 값을 찾는 함수를 정수용과 실수용으로 따로 썼습니다. 본문은 글자까지 같습니다. 타입이 하나 더 필요해지면 또 복사해야 합니다.

타입을 T 로 바꾸면 — E0369

타입 자리에 이름 T 를 쓰고 함수 이름 뒤 <T> 에서 선언합니다. "어떤 타입이든" 이라는 뜻입니다. 그런데 컴파일되지 않습니다.

"어떤 타입이든" 은 너무 넓다 — > 로 견줄 수 없는 타입도 있습니다. Rust 는 제네릭 함수의 본문을 "모든 T 에 대해 옳은지" 미리 검사합니다. 부를 때 가서야 오류가 나는 C++ 템플릿과 다른 점입니다.

조건을 단다 — T: PartialOrd + Copy

컴파일러가 권한 대로 조건(트레이트 바운드)을 답니다. "견줄 수 있고(PartialOrd) 복사되는 (Copy) 타입이면 무엇이든". 이제 함수 하나가 정수·실수·문자에 다 됩니다.

트레이트가 조건의 낱말 — PartialOrd 와 Copy 가 트레이트입니다. 다음 장에서 직접 만들어 봅니다.

제네릭 구조체

구조체의 필드 타입도 인자로 받을 수 있습니다. 타입 인자를 둘 두면 필드마다 다른 타입을 담습니다.

같은 T 는 같은 타입이다 — E0308

Point<T> 의 두 필드는 둘 다 T 입니다. x 가 정수면 y 도 정수여야 합니다.

다르게 하려면 앞 장의 Pair<A, B> 처럼 타입 인자를 둘 둡니다.

제네릭 열거형 — Option 과 Result 의 정체

열거형도 타입 인자를 받습니다. 지금까지 써 온 Option<T> 와 Result<T, E> 가 바로 표준 라이브러리에 정의된 제네릭 열거형입니다.

impl<T> — 제네릭 타입의 메서드

impl<T> Point<T> 는 모든 T 에 대한 메서드를, impl Point<f64> 는 f64 일 때만 있는 메서드를 정의합니다.

그 타입에는 없는 메서드 — E0599

distance 는 Point<f64> 에만 정의했습니다. 정수 점에서 부르면 "그런 메서드가 없다" 고 합니다.

제네릭은 공짜다 — 타입마다 따로 컴파일된다

컴파일러는 쓰인 타입마다 제네릭 코드의 사본을 만듭니다(단형화, monomorphization). Wrapper<u8> 과 Wrapper<u64> 는 크기부터 다른 별개의 타입입니다.

실행할 때 치르는 값이 없다 — 손으로 타입마다 따로 쓴 것과 같은 코드가 나옵니다. 값은 컴파일 시간과 실행 파일 크기로 치릅니다.

타입 인자를 직접 적기 — ::<T>

대개는 인자를 보고 T 가 정해집니다. 인자에서 알 수 없을 때는 이름 뒤에 ::<타입> 을 붙이거나 받는 변수에 타입을 적습니다.

별명 — ::<> 의 생김새 때문에 "터보피시" 라고 부릅니다. parse::<u8>() 에서 이미 써 왔습니다.

퀴즈 — 제네릭

Q. fn largest<T>(xs: &[T]) -> T 의 본문에서 x > best 를 쓰면 왜 컴파일되지 않을까요?

A. T 가 "어떤 타입이든" 이라서, 견줄 수 없는 타입일 수도 있기 때문입니다(E0369). T: PartialOrd 라는 조건을 달아야 합니다(조건을 단다).

2장

트레이트

정의와 구현 · 기본 메서드 · impl Trait · 바운드와 where · 고아 규칙

트레이트 — 할 수 있는 일의 목록

trait 으로 메서드의 시그니처를 적고, impl 트레이트 for 타입 으로 타입마다 본문을 씁니다. 다른 언어의 인터페이스에 가깝습니다.

약속한 것은 전부 구현해야 한다 — E0046

트레이트에 메서드가 둘인데 하나만 구현했습니다. 컴파일러는 빠진 것의 이름을 말합니다.

기본 구현

트레이트 안에 본문까지 써 두면 기본 구현이 됩니다. 구현하는 쪽은 그대로 쓰거나 덮어씁니다. 기본 구현은 같은 트레이트의 다른 메서드(area)를 부를 수 있습니다.

이미 본 예 — Iterator 는 next 하나만 요구하고 나머지 수십 개가 기본 구현입니다(12부).

트레이트를 매개변수로 — impl Trait

매개변수 타입에 impl Shape 라고 쓰면 "Shape 를 구현한 타입이면 무엇이든" 입니다. 1장의 제네릭 바운드를 짧게 쓴 것이고, 두 모양은 뜻이 같습니다.

조건에 안 맞는 타입을 넘기면 — E0277

Shape 를 구현하지 않은 타입(실수)을 넘깁니다. Rust 에서 가장 자주 보게 될 오류 번호입니다 — "트레이트 바운드가 채워지지 않았다".

E0277 읽는 법 — "어떤 타입이 어떤 트레이트를 구현하지 않았는가" 두 가지만 찾으면 됩니다. 지금까지 본 E0277({} 로 못 찍는다, ? 를 못 쓴다, 스레드로 못 보낸다)이 전부 이 모양이었습니다.

조건이 여럿일 때 — + 와 where

조건은 + 로 잇습니다. 길어지면 where 절로 빼서 시그니처의 첫 줄을 읽기 쉽게 둡니다.

돌려주는 타입을 감춘다 — -> impl Trait

반환 타입에도 impl Trait 을 씁니다. 실제 타입은 길고 복잡해도(반복자 사슬, 클로저), 받는 쪽은 "반복자다" 만 알면 됩니다.

-> impl Trait 은 한 가지 타입만 돌려준다 — E0308

impl Shape 는 "어떤 한 타입" 입니다. 경우에 따라 Circle 이나 Square 를 돌려줄 수는 없습니다.

실행 중에 골라야 한다면 5장의 Box<dyn Shape> 가 답입니다.

트레이트의 메서드는 트레이트가 보여야 쓸 수 있다 — E0599

다른 모듈의 트레이트 메서드를 부르려면 그 트레이트를 use 로 끌어와야 합니다. 타입만 보여서는 부족합니다.

고치면 — use shapes::Shape; 한 줄. 표준 라이브러리에서도 use std::io::Read; 를 해야 read_to_string 이 보이는 것이 같은 까닭입니다.

self 가 없는 함수도 약속할 수 있다

트레이트에는 연관 함수도 넣을 수 있습니다. Self 는 "이 트레이트를 구현하는 바로 그 타입" 입니다. 제네릭 코드가 "어떤 타입이든 같은 방법으로 만든다" 를 쓸 수 있게 됩니다.

남의 트레이트를 남의 타입에 붙일 수는 없다 — E0117

Display 도 Vec 도 표준 라이브러리의 것입니다. 둘 다 내 것이 아니면 구현할 수 없습니다. 고아 규칙(orphan rule)이라고 합니다.

까닭 — 두 크레이트가 같은 타입에 같은 트레이트를 서로 다르게 구현하면 어느 쪽을 쓸지 정할 수 없기 때문입니다. 트레이트나 타입 가운데 하나는 내 것이어야 합니다.

한 겹 감싸서 내 타입으로 만든다

고아 규칙을 지나가는 관용구입니다. 필드 하나짜리 튜플 구조체로 감싸면 그것은 내 타입이고, 무엇이든 구현할 수 있습니다(newtype 패턴).

퀴즈 — 트레이트

Q. fn f(x: &impl Shape) 와 fn f<T: Shape>(x: &T) 는 무엇이 다를까요?

A. 뜻은 같습니다. 앞의 것이 뒤의 것을 짧게 쓴 모양입니다 (impl Trait). 같은 T 를 매개변수 둘에 써야 하거나 터보피시로 타입을 직접 적어야 할 때는 뒤의 모양을 씁니다.

3장

표준 트레이트 ①

Debug · Display · Clone · Copy · PartialEq · Ord · Hash · Default — 그리고 derive

Debug — {:?} 로 찍히려면 — E0277

{:?} 는 Debug 트레이트를 부릅니다. #[derive(Debug)] 를 붙이면 컴파일러가 구현을 만들어 주고, 붙이지 않은 타입은 찍을 수 없습니다.

Display — {} 는 직접 구현한다

사람에게 어떻게 보일지는 타입마다 다르므로 Display 는 derive 가 없습니다. fmt 메서드 하나를 씁니다.

  • Display 를 구현하면 to_string() 이 저절로 생깁니다.
  • 셋째 줄을 보세요. {m:>10} 의 폭이 먹지 않았습니다. write! 로 그냥 쓰면 폭·정렬 지시는 무시됩니다.

Clone 과 Copy

Clone 은 ".clone() 으로 복사할 수 있다", Copy 는 "대입만 해도 복사된다" 입니다(6부). 둘 다 derive 로 붙입니다. Copy 에는 Clone 이 함께 있어야 합니다.

힙을 가진 타입은 Copy 가 될 수 없다 — E0204

String 필드가 있는 구조체에 Copy 를 붙이려 합니다. String 이 Copy 가 아니므로 그것을 품은 구조체도 될 수 없습니다.

derive 의 규칙 — 모든 필드가 그 트레이트를 구현해야 붙일 수 있습니다. Debug 도 Clone 도 PartialEq 도 마찬가지입니다.

== 도 트레이트다 — E0369

내가 만든 구조체는 저절로 견줄 수 없습니다. == 는 PartialEq 트레이트를 부르는 연산자이기 때문입니다.

PartialEq · Eq · PartialOrd · Ord

같은지(==)와 순서(<, 정렬)를 주는 네 트레이트입니다. derive 하면 필드를 적은 순서대로 견줍니다.

트레이트주는 것f64 는?
PartialEq== · !=있다
Eq"자기 자신과는 늘 같다" 는 표시없다(NaN ≠ NaN)
PartialOrd< · >있다
Ord빠짐없는 순서 — sort · max없다

Hash — 해시 집합·맵의 키가 되려면

HashSet 과 HashMap 의 키는 Hash 와 Eq 를 구현해야 합니다. 둘 다 derive 로 붙습니다.

Default — 기본값

Default 를 derive 하면 필드마다 그 타입의 기본값으로 채운 값을 만들 수 있습니다. ..Default::default() 와 함께 쓰면 "몇 개만 정하고 나머지는 기본" 이 됩니다.

기본값을 직접 정한다

0 이나 빈 문자열이 알맞지 않으면 Default 를 직접 구현합니다. 5부에서 본 "기본 인자가 없다" 의 또 다른 답입니다.

derive 할 수 있는 것들

트레이트얻는 것붙이는 때
Debug{:?}거의 언제나
Clone.clone()복사가 뜻이 있을 때
Copy대입으로 복사작고 힙이 없는 값
PartialEq · Eq==견줄 일이 있을 때, 시험에서
PartialOrd · Ord< · 정렬순서가 뜻이 있을 때
Hash해시 키맵·집합의 키로 쓸 때
DefaultT::default()"빈 값" 이 뜻이 있을 때

Display 는 여기 없습니다 — 직접 구현합니다.

퀴즈 — 표준 트레이트 ①

Q. #[derive(PartialOrd, Ord, …)] struct Version { major: u32, minor: u32 } 에서 {1, 99} 와 {2, 0} 가운데 어느 쪽이 클까요?

A. {2, 0} 입니다. derive 한 순서는 필드를 적은 순서대로 견주므로 major 를 먼저 봅니다(PartialOrd · Ord). 필드 순서를 바꾸면 결과도 바뀝니다.
