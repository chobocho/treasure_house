키워드 ① — 쓰이는 낱말

레퍼런스가 "엄격한(strict) 키워드" 라 부르는 서른아홉 개로, 이름으로 쓸 수 없는 낱말입니다. 꼭 이름으로 써야 하면 대개 r# 를 붙여 쓸 수 있습니다(16부).

쓰임키워드
항목 정의fn struct enum trait impl type const static mod use extern crate
변수·값let mut ref move true false _
제어 흐름if else match loop while for in break continue return
타입·경로as dyn where self Self super pub
그 밖unsafe async await

낱말이 키워드인지, 어떤 쓰임인지 찾는 표입니다. 주로 배운 곳은 항목 정의가 5부 · 7부 · 10부 · 13부, 변수·값이 3부, 제어 흐름이 4부, 타입·경로가 7부 · 10부 · 13부, 그 밖이 16부이고, 문법마다 나온 장은 문법 찾아보기에 있습니다. async · await · dyn 은 2018 에디션에서 더해졌습니다 — 까닭은 1부 4장에서 봤고, async 는 2부에서 직접 돌려 봤습니다.

키워드 ② — 예약된 낱말과 약한 키워드

앞 표에는 없지만 이름을 지을 때 걸릴 수 있는 낱말입니다. 예약된 낱말은 앞 표의 키워드처럼 이름으로 쓸 수 없고, 약한 키워드는 정해진 자리 밖에서는 보통 이름입니다.

종류낱말뜻
예약abstract become box do final gen macro override priv try typeof unsized virtual yield아직 쓰이지 않지만 앞날을 위해 잡아 두었다. 이름으로 못 쓴다
약한 키워드'static macro_rules raw safe union정해진 자리에서만 키워드다. 다른 곳에서는 이름으로 쓸 수 있다

try 는 2018 에디션에서, gen 은 2024 에디션에서 예약됐습니다 — 1부에서 직접 돌려 본 둘입니다(try, gen). 약한 키워드 가운데 'static 은 11부에서, macro_rules · raw · union 은 16부에서 만났습니다.

연산자 우선순위 — 위가 먼저

괄호 없이 쓴 식에서 무엇이 먼저 묶이는지 찾는 표입니다. 위에 있는 줄이 먼저 묶이고, 같은 줄끼리는 오른쪽 칸의 방향으로 묶입니다. 연산자 하나하나는 3부의 나눗셈과 나머지, 4부의 && 와 ||, 10부의 연산자와 트레이트 표에서 봤습니다.

Rust 레퍼런스의 표를 줄 수와 차례 그대로 옮긴 것입니다. 한 줄이 한 단계이고, 묶이는 방향이 빈칸인 줄은 레퍼런스도 비워 둔 줄입니다.

우선순위에서 헷갈리기 쉬운 곳

앞 슬라이드의 표에서 눈여겨볼 다섯 군데를 돌려 봅니다. 3·5·7번 줄은 왼쪽이 괄호 없이 쓴 것, 오른쪽이 다르게 묶은 것입니다.

  • -2i32.pow(2) 는 -(2.pow(2)) 라서 -4, 10 as f64 / 4 as f64 는 둘 다 실수로 바꾼 뒤에 나눠서 2.5, 1 << 2 + 1 은 1 << 3 이라서 8 입니다.
  • 9번 줄은 (6 & 3) == 2 로 묶여 true, 11번 줄은 true || (false && false) 로 묶여 true 입니다. 11번 줄을 왼쪽부터 묶었다면 false 였을 것입니다.
C 와 다른 곳 — C 에서는 == 가 비트 & 보다 먼저라 6 & 3 == 2 가 6 & (3 == 2) 로 읽힙니다. Rust 는 (6 & 3) == 2 입니다.

비교 연산자는 이어 쓸 수 없다

수학처럼 1 < x < 10 이라고 쓰면 컴파일러가 막고, 둘로 나눠 쓰는 법을 알려 줍니다.

  • 오류 첫 줄 — "비교 연산자는 이어 쓸 수 없다". 번호가 없는 오류이고, 3번 줄의 < 둘을 짚습니다. 우선순위 표의 "이어 쓸 수 없다" 가 이것입니다.
  • help: — 비교를 둘로 나누라며 고친 줄을 보여 줍니다. ++++ 가 놓인 && x 가 더할 글자입니다.

서식 지정자 한눈에 보기

2부 3장의 서식을 한 화면에 모았습니다. 지정자는 {이름:채움 정렬 부호 # 0 폭 .정밀도 종류} 의 차례로 적습니다. 4번 줄부터 println! 마다 차례로 정수 · 실수 · 문자열 · 진법 · 디버그 · 변수로 준 폭과 정밀도 · 중괄호 글자와 자리 번호입니다.

  • 2부에서 본 대로 폭만 주면 수는 오른쪽에, 문자열은 왼쪽에 붙습니다 — 4번 줄의 {n:5} 가 찍은 [ 42] 와 6번 줄의 {s:8} 이 찍은 [rust ].
  • 7번 줄 끝의 {n:#010b} 는 #(0b 붙이기) · 0(0 으로 채움) · 폭 10 · b 를 함께 쓴 것입니다. 2부의 진법에서 본 대로 폭 10 에는 0b 두 글자도 들어갑니다.

타입의 크기 — 이 기계에서

64비트 기계에서 잰 바이트 수입니다. isize · usize 와 포인터류는 32비트 기계에서 절반이 됩니다. 찍는 데 쓴 show! 는 16부의 반복과 ty 로 만든 매크로입니다.

낱말 수로 읽기 — 주소 하나의 크기(이 기계에서 8바이트)를 낱말 하나로 치면, 참조와 Box 는 낱말 하나, 슬라이스 참조는 둘(주소 + 길이), String 과 Vec 은 셋(주소 + 길이 + 자리 — 6부의 그림, 8부의 자리)입니다.

() 는 0바이트, char 는 4바이트입니다. Option<Box<u8>> 는 Option 으로 감쌌는데도 Box<u8> 와 같은 8바이트입니다.

오류 번호 찾아보기 — 쓰는 법

이 책에서 실제로 내 본 컴파일 오류를 번호순으로 모았습니다. 컴파일러가 낸 번호를 여기서 찾으면, 같은 오류를 일부러 내고 고친 슬라이드로 갈 수 있습니다.

  • 번호가 없는 오류(문법 오류, 일부 금지 린트)는 여기에 없습니다.
  • 긴 설명이 필요하면 rustc --explain E0382 처럼 물어봅니다.
  • 이 책에 가장 여러 번 나온 셋 — E0308(타입이 맞지 않는다 — 0부), E0382(옮겨 간 값을 썼다 — 6부), E0277(그 타입이 그 트레이트를 구현하지 않았다 — 10부). 링크는 그 오류를 풀어 읽은 슬라이드입니다.

끝

문법은 여기까지입니다. 이제 컴파일러와 이야기하며 직접 써 볼 차례입니다 — 틀리면 무엇이 틀렸는지 말해 주고, 대개는 고치는 법도 함께 알려 줄 것입니다.
