소수점이 있는 수는 f64 가 기본이다

소수점 아래가 있는 수를 담는 실수(floating-point) 타입은 둘뿐입니다. 32비트인 f32 와 64비트인 f64 입니다. 정수에 기본값 i32 가 있었듯이 실수에도 기본값이 있습니다.

  • a — 단서가 없어 f64 가 됐습니다. b 는 타입 표기로, c 는 접미사로 f32 를 골랐습니다.
  • 같은 셈인데 f32 는 3 이 일곱 개, f64 는 열여섯 개 찍혔습니다. 비트가 많은 만큼 더 자세히 담습니다.
  • 담을 수 있는 크기도 다릅니다. f32 는 10 의 38 제곱쯤, f64 는 10 의 308 제곱쯤이 끝입니다.
망설여지면 f64 — 컴파일러의 기본값이고 더 자세합니다. f32 는 값이 아주 많아 메모리를 아껴야 할 때나, 그래픽처럼 상대가 f32 를 요구할 때 고릅니다.

0.1 + 0.2 는 0.3 이 아니다 — 실수는 == 로 견주지 않는다

실수는 2진수로 저장합니다. 10진수 0.1 은 2진수로 딱 떨어지지 않아서, 가장 가까운 값이 대신 들어갑니다. Rust 만의 일이 아니라 실수를 이렇게 저장하는 모든 언어에서 같습니다.

  • 합은 0.3 보다 아주 조금 큽니다. 그래서 == 는 거짓입니다.
  • 차이는 10 의 -17 제곱쯤입니다. 차이의 절댓값이 정해 둔 허용 오차(tolerance)보다 작으면 같다고 봅니다. 여기서는 1e-9 로 잡았고, 그 크기는 다루는 값의 크기에 맞추어 정합니다.
  • 0.5 · 0.25 · 0.75 처럼 2 의 거듭제곱으로 나타낼 수 있는 수는 어긋나지 않았습니다.
돈은 실수로 세지 않습니다 — 0.1 과 0.2 를 더한 값이 0.3 과 같지 않으면 장부가 맞지 않습니다. 금액은 가장 작은 단위를 정수로 셉니다.

정수끼리 나누면 정수, 실수끼리 나누면 실수다

/ 는 하나지만 양쪽의 타입에 따라 하는 일이 다릅니다. 평균을 내려다 소수점 아래를 잃는 것이 가장 흔한 잘못입니다.

  • 7 / 2 는 3 이고 7.0 / 2.0 은 3.5 입니다. 2장에서 본 대로 정수 나눗셈은 0 쪽으로 버리고, 실수 나눗셈은 버리지 않습니다.
  • total 을 가리기로 두 번 만들었습니다. 정수일 때 평균은 82, 실수일 때는 82.33… 입니다.
  • 찍을 때 자릿수를 정하는 {:.2} 는 2부에서 본 서식입니다. 값은 그대로이고 보이는 것만 줄입니다.
이미 정수인 값이라면 — 리터럴은 소수점을 붙이면 되지만, 정수 변수에 든 값은 그럴 수 없습니다. 정수를 실수로 바꾸는 법은 4장에서 봅니다.

실수를 0 으로 나누면 패닉 대신 무한대나 NaN 이 나온다

정수를 0 으로 나누면 패닉했습니다. 실수는 멈추지 않습니다. 대신 특별한 값 세 가지를 돌려줍니다.

  • inf 와 -inf 는 양과 음의 무한대(infinity)입니다. 1 을 더해도 그대로입니다.
  • NaN 은 "수가 아님(Not a Number)"입니다. 0.0 / 0.0 이나 inf - inf 처럼 답을 정할 수 없는 셈의 결과입니다.
  • NaN 은 무엇과 == · < · > 로 견주어도 거짓입니다. 자기 자신과 == 로 견주어도 거짓입니다. 그래서 is_nan() 으로 묻습니다.
조용히 지나갑니다 — 패닉도 경고도 없이 다음 줄로 갑니다. 바깥에서 들어온 값으로 나누었다면 결과를 is_finite() 로 확인합니다. 무한대와 NaN 모두 거짓이 나옵니다.

실수 배열은 sort() 로 정렬되지 않는다 — E0277

NaN 은 어떤 수보다 크지도 작지도 않습니다. 그러니 실수 전체를 한 줄로 세울 방법이 없습니다. 컴파일러는 이 사실을 타입으로 알고 있습니다.

읽는 법 — 2부에서 본 E0277 과 같은 꼴입니다. 그때는 Display 가, 이번에는 Ord 가 없다고 합니다. {float} 은 {integer} 처럼 "아직 정해지지 않은 실수"입니다. Ord 는 빠짐없이 줄을 세울 수 있는 타입에 붙는 이름이고, help: 가 보여 준 여덟 타입은 모두 정수입니다. 마지막 note: 는 sort 가 그 이름을 요구한다는 뜻입니다. 이런 이름을 트레이트(trait)라고 하며 10부에서 봅니다.
  • total_cmp 는 NaN 에도 자리를 정해 주는 순서입니다( 부터). 여기서는 NaN 이 맨 뒤로 갔습니다. 함수를 인자로 넘기는 것은 5부에서 봅니다.
  • max 와 min 은 한쪽이 NaN 이면 다른 쪽을 돌려줍니다. 둘 다 21.5 입니다.

소수점 아래를 없애는 방법은 넷이다

"반올림"이라고 뭉뚱그려 말하지만 어느 쪽으로 보내느냐에 따라 메서드가 다릅니다. 양수와 음수에 하나씩 불러 보면 차이가 보입니다.

메서드어느 쪽으로2.5-2.5
round가까운 정수로, 딱 절반이면 0 에서 먼 쪽3-3
floor작은 쪽으로2-3
ceil큰 쪽으로3-2
trunc0 쪽으로2-2
  • 결과는 정수처럼 보여도 실수입니다. {:?} 로 찍으면 3.0 입니다. 정수 타입으로 바꾸는 것은 4장의 일입니다.
  • sqrt 는 제곱근, powi 는 정수 지수의 거듭제곱입니다. 음수의 제곱근은 앞에서 본 NaN 입니다.
  • 보여 줄 때만 줄이려면 값을 바꾸지 말고 서식 {:.1} 을 씁니다.

bool 은 true 와 false 둘뿐이다

참과 거짓을 담는 타입이 불(boolean), 곧 bool 입니다. if 와 while 의 조건이 이 타입이고, 값을 견주는 식이 모두 이 타입의 값을 냅니다.

  • 82 >= 60 의 값을 그대로 변수에 담았습니다. 타입은 bool 이고 크기는 1바이트입니다.
  • ! 는 참과 거짓을 뒤집습니다. 둘을 잇는 && 와 || 는 4부에서 봅니다.
  • as i32 로 수로 바꾸면 true 는 1, false 는 0 입니다. 그래서 맞은 것의 개수를 더해서 셀 수 있습니다. as 는 4장에서 봅니다.
size_of — 타입이 차지하는 바이트 수를 돌려주는 표준 함수입니다. ::<bool> 처럼 타입을 넘기는 표기는 4장에서 봅니다. 앞에 std::mem:: 을 붙이지 않고 쓸 수 있는 것은 부터입니다.

char 는 유니코드 글자 하나다 — 언제나 4바이트

C 의 char 는 1바이트라 한글 한 글자를 담지 못합니다. Rust 의 char 는 유니코드 스칼라 값(Unicode scalar value) 하나를 담습니다. 작은따옴표로 적습니다.

  • 'a' 도 '가' 도 게 그림 글자도 char 하나이고, 어느 것이든 4바이트를 차지합니다.
  • 글자마다 유니코드 번호가 있습니다. as u32 로 꺼내고, '\u{1F980}' 처럼 번호로 글자를 적을 수도 있습니다.
  • '\n'(줄바꿈) · '\t'(탭) · '\''(작은따옴표) · '\\'(역슬래시)처럼 \ 로 시작하는 표기를 이스케이프(escape)라고 합니다. {:?} 로 찍으면 소스에 적은 꼴로 보입니다.
문자열은 따로 있습니다 — 글자 여러 개를 이은 문자열은 char 를 늘어놓은 것과 다른 방식으로 저장합니다. 8부에서 봅니다.

글자에게 묻고, 글자를 바꾸는 메서드

"이 글자가 숫자인가"를 알려고 번호를 직접 견줄 필요가 없습니다. char 에 메서드로 들어 있습니다.

  • is_alphabetic 은 한글에도 참입니다. 유니코드 전체를 봅니다.
  • 이름에 ascii 가 든 메서드는 영문자·숫자·기호가 있는 ASCII 범위만 봅니다. '가' 는 is_ascii_alphabetic 에 거짓이고, to_ascii_uppercase 를 거쳐도 그대로입니다.
  • to_digit(진법) 은 숫자 글자를 수로 바꿉니다. 'f' 는 16진법에서 15 이고, 10진법에서는 숫자가 아니라서 None 입니다.

'A' 와 "A" 는 타입이 다르다 — E0308

Python 이나 JavaScript 에서는 작은따옴표와 큰따옴표가 같은 것을 만듭니다. Rust 에서는 작은따옴표가 char, 큰따옴표가 문자열입니다.

읽는 법 — 이번에도 mismatched types 입니다. char 를 기대했는데 &str 이 왔다고 합니다. help: 는 "char 리터럴을 쓰려던 것이라면 작은따옴표를 쓰라"며 고친 줄을 - 와 + 로 나란히 보여 줍니다.

퀴즈 — 3장

Q. 다음 세 식의 값은 각각 무엇입니까?
① 0.1 + 0.2 == 0.3
② let x = 0.0_f64 / 0.0; 다음의 x == x
③ size_of::<char>()

A. ① false 입니다. 합이 0.30000000000000004 로 나옵니다. 차이의 절댓값을 허용 오차와 견주어야 합니다. ② false 입니다. x 는 NaN 이고, NaN 은 자기 자신과도 같지 않습니다. x.is_nan() 으로 묻습니다. ③ 4 입니다. 'a' 를 담든 '가' 를 담든 char 는 4바이트입니다.

형변환

as · 잘림과 멈춤 · From 과 Into · TryFrom · parse 와 터보피시 · 고르는 법

as 는 넓힐 때는 그대로 두고, 좁힐 때는 잘라 낸다

2장에서 i64 와 i32 를 견주지 못했습니다. Rust 는 타입을 저절로 바꾸지 않으므로 바꾸라고 적어야 합니다. 이것이 형변환(type conversion)이고, 가장 짧은 표기가 값 as 타입 입니다.

  • 넓은 타입으로 — 값이 그대로입니다. -1 은 -1 이고 200 은 200 입니다.
  • 좁은 타입으로 — 300 은 u8 에 들어가지 않습니다. 아래 8비트만 남아 44 가 됐습니다(300 - 256). 2장에서 본 "한 바퀴 돌기"와 같은 결과입니다.
  • 크기는 같고 부호만 다르게 — 비트는 그대로 두고 읽는 법만 바꿉니다. -1 은 u32 의 가장 큰 값이 되고, 200 은 -56 이 됩니다.
as 는 말이 없습니다 — 값이 달라져도 패닉하지 않고 경고도 없습니다. 좁히는 as 는 넘치지 않는다고 아는 자리, 또는 잘라 내는 것이 바로 하려는 일인 자리에서만 씁니다.

실수를 as 로 정수로 바꾸면 버리고, 넘치면 끝값에서 멈춘다

정수와 실수 사이도 as 로 오갑니다. 정수에서 실수로 가는 쪽이 3장에서 미뤄 둔 평균입니다. 반대쪽, 실수에서 정수로 갈 때는 규칙이 셋 있습니다.

실수의 값정수로 바꾸면위의 출력
소수점 아래가 있다0 쪽으로 버린다2.9 → 2, -2.9 → -2
그 타입의 범위 밖이다가까운 끝값에서 멈춘다300.7 → 255, -5.0 → 0, 1e20 과 inf → 2147483647
NaN 이다0 이 된다NaN → 0
정수끼리 좁힐 때와 다릅니다 — 300_i32 as u8 은 잘려서 44 였고, 300.7 as u8 은 멈춰서 255 입니다. 버리지 않고 반올림하려면 round() 를 먼저 부릅니다.

글자와 불도 as 로 수가 된다

3장에서 글자에 as u32 를, 불에 as i32 를 먼저 썼습니다. 글자와 수 사이를 오가는 길을 모아 봅니다.

  • char → 수 — 유니코드 번호가 나옵니다. 'A' 는 65 입니다.
  • u8 → char — 그 번호의 글자가 됩니다. b'a' 는 u8 값 97 이므로, 3 을 더해 글자로 되돌리면 d 입니다.
  • u32 → char — char::from_u32 를 부릅니다. 번호 가운데에는 글자가 아닌 것도 있어서, 결과가 Some 아니면 None 입니다.
  • bool → 수 — true 는 1, false 는 0 입니다.

잃을 것이 없는 변환은 From 과 Into 로 적는다

as 는 값이 달라져도 알려 주지 않았습니다. 값이 반드시 그대로 남는 변환에는 다른 표기가 있습니다. 타입::from(값) 과 값.into() 입니다.

  • i64::from(order) — 만들려는 타입을 앞에 적습니다.
  • order.into() — 무엇으로 바꿀지는 받는 쪽이 정합니다. b 에서는 타입 표기가, 그 아래 견주는 식에서는 왼쪽의 i64 가 정했습니다. 2장의 help: 가 권한 바로 그 표기입니다.
  • 정수에서 실수로, 글자에서 번호로, 불에서 수로 가는 것도 잃을 것이 없어 from 으로 적을 수 있습니다.
먼저 from 을 써 봅니다 — 컴파일되면 그 변환은 값을 잃지 않는다는 뜻입니다. 나중에 타입을 바꾸어 값을 잃을 수 있게 되면 그때는 컴파일되지 않습니다. 다음 슬라이드가 그 경우입니다.

값을 잃을 수 있는 방향에는 From 이 없다 — E0277

이번에는 거꾸로 갑니다. i64 에 든 50억을 i32 로 바꾸어 봅니다. i32 는 21억쯤까지만 담습니다.

읽는 법 — 3장의 Ord 오류와 같은 E0277 입니다. 이번에는 "i32 에는 From<i64> 가 구현되어 있지 않다"고 합니다. i64 에서 i32 를 만드는 from 이 없다는 뜻입니다. help: 는 있는 것을 늘어놓습니다 — bool · i16 · i8 · u16 · u8. 모두 i32 에 빠짐없이 들어가는 타입입니다. 값이 50억인지 3 인지는 보지 않고, 타입만 보고 컴파일할 때 막습니다. 고친 것은 다음 슬라이드입니다.

들어갈지 모르는 변환은 TryFrom — 답은 Ok 아니면 Err 다

i64 값이 i32 에 들어갈지는 실행해 보아야 압니다. try_from 은 변환을 해 보고, 됐는지 안 됐는지를 값으로 돌려줍니다.

  • 300 은 i32 에 들어가므로 Ok(300) 입니다. 50억은 i32 에, 300 은 u8 에 들어가지 않아 Err 입니다. 괄호 안이 까닭입니다 — 위로 넘쳤는지(PosOverflow) 아래로 넘쳤는지(NegOverflow).
  • into 의 짝은 try_into 입니다. 2부에서 쓴 expect 는 Ok 이면 안의 값을 꺼내고, Err 이면 패닉합니다.
  • unwrap_or(값) 은 Err 일 때 대신 쓸 값을 정합니다. 300 이 u8 에 들어가지 않아 255 가 됐습니다.
Ok 와 Err — 성공과 실패를 값으로 나타내는 Result 타입이며, 오류 처리와 함께 9부에서 봅니다.

parse 는 무엇으로 읽을지 알아야 한다 — E0284

글로 적힌 수를 수로 바꾸는 일은 parse 가 맡습니다. 2부에서는 늘 let n: i32 = … 처럼 타입을 적었습니다. 그 표기를 빼 봅니다.

읽는 법 — type annotations needed 는 "타입 표기가 필요하다"입니다. "42" 는 i32 로도 u8 로도 읽을 수 있으니, 컴파일러가 대신 고르지 않습니다. 3번 줄의 parse 아래에 "이 지점에서 타입이 정해져 있어야 한다"고 적혀 있습니다. help: 는 n 뒤에 : /* Type */ 를 넣어 보이며, 그 자리에 타입을 적으라고 합니다.

타입은 표기로, 또는 터보피시 ::<T> 로 알려 준다

앞 슬라이드를 고치는 방법은 둘입니다. 받는 변수에 타입을 적거나, parse 에 직접 타입을 넘깁니다.

  • parse::<u8>() 의 ::<타입> 을 터보피시(turbofish)라고 합니다. 3장의 size_of::<char>() 도 같은 표기였습니다. 변수에 담지 않고 바로 쓸 때 편합니다.
  • 같은 글 "42" 가 i32 로도 u8 로도 읽혔습니다. 실수와 불도 같은 메서드로 읽습니다.
  • 읽지 못하면 Err 입니다. 숫자가 아닌 글자가 끼었거나(InvalidDigit), 그 타입에 넘치거나(PosOverflow), 비어 있을 때(Empty)입니다.
앞의 공백도 "숫자가 아닌 글자"입니다 — " 42" 가 InvalidDigit 로 실패했습니다. 입력받은 줄은 2부에서처럼 trim() 을 거쳐 넘깁니다.

어떤 변환을 언제 쓰는가

이 장에서 본 네 가지를 한 표에 모읍니다. 위에서부터 차례로 맞는지 봅니다.

퀴즈 — 4장

Q. 300 을 u8 로 바꾸는 세 가지입니다. 각각 무엇이 나옵니까?
① 300_i32 as u8
② 300.7 as u8
③ u8::try_from(300_i64)

A. ① 44 입니다. 정수끼리 좁히면 아래 8비트만 남습니다(300 - 256). ② 255 입니다. 실수에서 정수로 갈 때는 범위를 넘으면 끝값에서 멈춥니다. ③ Err(TryFromIntError(PosOverflow)) 입니다. 들어가지 않는다는 것을 값으로 알려 줍니다. 같은 300 인데 결과가 셋 다 다릅니다. 무엇을 원하는지에 따라 변환을 고릅니다.

5장

튜플·배열

튜플과 () · [T; N] · 길이도 타입 · 없는 칸 · get · 복사와 견주기 · 2차원 · 슬라이스와 Vec

튜플은 타입이 다른 값을 묶는다 — 번호로 꺼내고, 한 번에 푼다

이름과 나이와 점수처럼 종류가 다른 값 몇 개를 한 덩어리로 다루고 싶을 때 튜플(tuple)을 씁니다. 괄호 안에 쉼표로 늘어놓습니다. 2부에서는 찍는 법만 봤습니다.

  • 튜플의 타입은 칸마다의 타입을 차례로 적은 것입니다 — (&str, i32, f64).
  • student.0 처럼 점 뒤에 번호를 적어 한 칸을 꺼냅니다. 번호는 0 부터 셉니다.
  • let (name, age, score) = student; — 왼쪽에 같은 꼴을 적으면 칸마다 이름이 붙습니다. 풀어 헤치기(destructuring)라고 하며, 7부에서 보는 패턴의 한 가지입니다. 두 값을 맞바꿀 때도 씁니다.
  • 칸이 하나도 없는 튜플 () 을 유닛(unit)이라고 합니다. 값도 (), 타입 이름도 () 입니다. "돌려줄 값이 없다"는 뜻으로 4부와 5부에서 다시 만납니다.

배열은 같은 타입의 값을 정해진 개수만큼 담는다

튜플이 종류가 다른 값 몇 개라면, 배열(array)은 같은 종류의 값 여러 개입니다. 대괄호 안에 쉼표로 늘어놓습니다.

  • 배열의 타입은 [칸의 타입; 길이] 입니다. 점수 셋은 [i32; 3] 입니다.
  • [0_u8; 5] — 값을 적는 자리에서는 [값; 개수] 로 같은 값을 채웁니다.
  • len() 이 길이이고, 대괄호 안의 번호는 0 부터 셉니다. 마지막 칸은 len() - 1 번입니다. 둘 다 2장에서 본 usize 입니다.
  • mut 배열은 칸의 값을 바꿀 수 있습니다. 바뀌는 것은 값이고, 칸의 개수는 타입에 적힌 그대로입니다.

배열의 길이는 타입의 일부다 — E0308

칸의 타입이 같아도 길이가 다르면 서로 다른 타입입니다. 세 칸짜리 배열을 네 칸짜리 자리에 넣어 봅니다.

읽는 법 — 이 부에서 네 번째 만나는 mismatched types 입니다. "크기 4 인 배열을 기대했는데 크기 3 인 배열이 왔다"고 합니다. help: 는 표기를 [u8; 3] 으로 바꾸라고 합니다. 컴파일러는 어느 쪽이 잘못인지 모르므로 가장 가까운 고침을 권할 뿐입니다.

없는 칸의 번호를 소스에 적으면 컴파일되지 않는다

길이가 타입에 적혀 있으니, 번호까지 소스에 적혀 있으면 컴파일러가 둘을 미리 견줄 수 있습니다.

읽는 법 — 첫 줄은 "이 연산은 실행하면 패닉한다"입니다. 그 아래가 까닭입니다 — 길이는 3 인데 번호가 3 입니다. 번호는 0 부터 세므로 마지막 칸은 2번입니다. 2장의 범위를 넘는 리터럴처럼 error[E…] 번호가 없고, #[deny(unconditional_panic)] 이 적혀 있습니다. 반드시 패닉할 코드를 찾는 검사이고 기본이 오류입니다.
번호가 소스에 없다면 — 실행 중에 정해지는 번호는 컴파일러가 미리 볼 수 없습니다. 다음 슬라이드에서 봅니다.

실행 중에 받은 번호가 범위를 넘으면 패닉한다 — get 은 None 을 준다

같은 배열, 같은 번호 3 입니다. 이번에는 번호를 실행할 때 인자로 받습니다. 컴파일은 됩니다.

  • 12번 줄의 scores[i] 에서 패닉했습니다 — 0부에서 패닉의 보기로 본 index out of bounds 입니다. 종료 코드는 101 이고, 그 아래 줄은 찍히지 않았습니다.
  • 배열 밖의 메모리를 읽어 엉뚱한 값을 내놓는 일은 없습니다. 번호를 쓸 때마다 길이와 견주고, 넘으면 그 자리에서 멈춥니다.
  • get(i) 는 패닉하지 않습니다. 칸이 있으면 Some(값), 없으면 None 입니다. 번호가 바깥에서 들어온다면 이쪽을 씁니다.
Some 과 None — 2장의 checked_add 가 돌려주던 것과 같은 Option 타입입니다. 안의 값을 꺼내 쓰는 법은 7부와 9부에서 봅니다.

정수 배열은 대입하면 통째로 복사되고, == 로 칸마다 견준다

배열을 다른 변수에 대입하면 무슨 일이 일어날까요. 두 변수가 같은 칸들을 함께 쓰는 언어도 있습니다. Rust 의 정수 배열은 그렇지 않습니다.

  • let mut b = a; 뒤에 b 의 첫 칸을 바꿨지만 a 는 그대로입니다. 칸이 모두 복사되어 둘은 따로 있습니다.
  • == 는 모든 칸이 같을 때 참입니다. 한 칸만 달라도 거짓입니다.
  • 배열도 튜플처럼 {:?} 로 통째로 찍습니다. 2부에서 본 그대로입니다.
칸이 정수라서 그렇습니다 — 대입한 뒤에도 a 를 그대로 쓸 수 있었습니다. 대입하면 원래 변수를 더 쓸 수 없게 되는 타입도 있으며, 그 이야기가 6부의 소유권입니다.

배열 안에 배열을 담으면 2차원이 된다

배열의 칸에는 어떤 타입이든 들어갑니다. 배열도 들어갑니다. 표나 격자처럼 행과 열이 있는 자료를 이렇게 담습니다.

  • 타입 [[i32; 3]; 2] 는 안쪽부터 읽습니다 — "i32 세 칸짜리 배열"이 두 개입니다.
  • grid[1][2] — 행을 먼저, 열을 다음에 적습니다. grid[0] 만 적으면 한 행, 곧 배열 하나입니다.
  • [[0_u8; 4]; 3] 은 12바이트입니다. 1바이트짜리 칸 열두 개가 빈틈없이 이어져 놓입니다. size_of_val 은 값이 차지하는 바이트 수를 돌려줍니다.

배열 · 슬라이스 · Vec — 길이를 언제 아는가

배열의 길이는 컴파일할 때 정해집니다. 길이를 실행 중에야 알거나, 실행 중에 늘려야 하는 자료에는 다른 타입을 씁니다. 여기서는 이름과 생김새만 봅니다.

배열 [T; N]슬라이스 &[T]Vec<T>
길이타입에 적혀 있다타입에 없다. 실행 중에 안다타입에 없다. 실행 중에 바뀐다
하는 일값을 직접 담는다다른 곳에 있는 칸들의 한 구간을 가리킨다늘어나고 줄어드는 목록을 담는다
배우는 곳이 장6부8부
길이가 정해져 있을 때만 배열 — 요일 일곱 개, 색의 세 성분처럼 개수가 바뀔 일이 없는 것에 배열을 씁니다. 몇 개가 될지 모르는 것은 Vec 에 담습니다. 출력의 alloc::vec::Vec<i32> 는 Vec<i32> 를 그것이 정의된 곳까지 붙여 적은 이름입니다.
여기까지 — 값에 이름을 붙이고, 정수·실수·불·문자와 튜플·배열에 담고, 타입 사이를 옮기는 법을 봤습니다. 4부에서는 이 값들로 식을 짜고, if 와 반복으로 흐름을 가릅니다.

퀴즈 — 5장

Q. let scores = [70, 85, 90]; 이 있습니다. 각각 어떻게 됩니까?
① 소스에 scores[3] 이라고 적는다
② 실행 중에 받은 번호 i 가 3 일 때 scores[i]
③ 같은 i 로 scores.get(i)

A. ① 컴파일되지 않습니다. this operation will panic at runtime 이라는 오류가 납니다. ② 컴파일은 되고, 실행하면 index out of bounds 로 패닉해 종료 코드 101 로 끝납니다. ③ 패닉하지 않고 None 을 돌려줍니다. 세 칸짜리 배열의 번호는 0 · 1 · 2 뿐입니다.
