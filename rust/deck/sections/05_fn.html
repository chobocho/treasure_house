이 부에서 할 일

지금까지는 거의 전부를 main 하나에 썼습니다. 이 부는 코드를 이름 붙은 조각으로 나누는 법을 봅니다. Rust 의 함수는 단순합니다 — 오버로딩도, 기본 인자도 없습니다. 그 대신 시그니처만 보면 무엇이 들어가고 나오는지 전부 알 수 있습니다.

  • 1장 — 함수 정의: 매개변수의 타입, 반환값, return
  • 2장 — 함수는 값이다: 함수 포인터, 중첩 함수, 재귀, 돌아오지 않는 함수 !
  • 3장 — 다듬기: 오버로딩과 기본 인자가 없을 때의 관용구, const fn, 문서 주석
다른 부에서 볼 것 — 인자를 넘길 때의 소유권은 6부, 제네릭 함수는 10부, 이름 없는 함수(클로저)는 12부입니다.

1장

함수 정의

fn · 매개변수에는 타입이 필수 · 마지막 식이 반환값 · return · ()

fn 이름(매개변수: 타입) -> 반환 타입

함수는 fn 으로 만듭니다. 이름은 소문자와 밑줄(snake_case)로 짓습니다.

  • 함수를 쓰는 곳보다 아래에 정의해도 됩니다. 파일 안의 순서는 상관없습니다.
  • greet 처럼 돌려줄 것이 없으면 -> 부분을 쓰지 않습니다.

매개변수의 타입은 생략할 수 없다

지역 변수는 타입을 추론해 주지만, 함수의 매개변수 타입은 반드시 적어야 합니다. 값을 돌려준다면 반환 타입도 마찬가지입니다.

일부러 그렇게 만들었다 — 시그니처가 함수의 계약서입니다. 본문을 읽지 않아도 무엇을 받고 무엇을 돌려주는지 알 수 있고, 컴파일러도 함수 하나를 고쳤을 때 다른 함수까지 다시 추론할 필요가 없습니다.

마지막 식이 반환값이다

함수 본문의 마지막에 세미콜론 없이 놓인 식이 그 함수의 값입니다. return 을 쓰지 않는 것이 보통입니다.

식(expression) — if … else … 도 값을 내는 식이라 그대로 반환값이 됩니다. 식과 문의 구별은 4부에서 봤습니다. 반환 타입 &'static str 은 문자열 리터럴의 타입입니다('static 은 11부).

마지막 줄에 세미콜론을 붙이면 — E0308

흔한 실수입니다. 세미콜론을 붙이면 식이 문이 되고, 값은 버려집니다. 함수는 () 를 돌려주게 됩니다.

읽는 법 — "u32 를 기대했는데 () 를 찾았다". () 는 본문에 마지막 식이 없을 때 함수가 돌려주는 빈 값입니다(유닛). help: 줄이 지울 세미콜론을 정확히 짚습니다.

return 은 중간에 빠져나갈 때 쓴다

함수 끝까지 가지 않고 돌아가야 할 때 return 값; 을 씁니다. 끝에서는 여전히 마지막 식을 씁니다.

먼저 걸러 내기 — 잘못된 입력을 함수 맨 위에서 돌려보내면 본문의 들여쓰기가 깊어지지 않습니다.

돌려줄 것이 없는 함수는 () 를 돌려준다

반환 타입을 쓰지 않은 함수도 값을 돌려주기는 합니다. 빈 튜플 () 입니다. "유닛(unit)" 이라고 부릅니다.

() 는 타입이기도 하고 그 타입의 하나뿐인 값이기도 합니다. 그래서 변수에 담을 수 있고, {:?} 로 찍을 수 있고, 서로 같습니다.

값을 여럿 돌려주려면 튜플로

반환값은 하나뿐입니다. 둘 이상을 돌려주고 싶으면 튜플로 묶어 하나로 만듭니다.

받는 쪽에서 바로 푼다 — let (q, r) = … 처럼 받으면 이름이 붙어 읽기 좋습니다. 값이 셋을 넘어가면 구조체(7부)가 낫습니다.

인자의 수가 맞지 않으면 — E0061

인자는 정의된 개수만큼 정확히 넘겨야 합니다. 빠뜨려도, 남아도 오류입니다.

읽는 법 — 컴파일러는 빠진 것이 "두 번째 인자, 타입 i32" 라고 말하고, note: 로 함수가 정의된 자리도 보여 줍니다.

인자의 타입이 맞지 않으면 — E0308

Rust 는 인자를 알아서 바꿔 주지 않습니다. i32 자리에 실수를 넘기면 오류입니다.

바꾸는 것은 호출하는 쪽의 일 — 형변환은 3부에서 본 대로 직접 적습니다.

퀴즈 — 함수 정의

Q. fn area(w: u32, h: u32) -> u32 { w * h; } 는 왜 컴파일되지 않을까요?

A. w * h; 의 세미콜론 때문에 곱한 값이 버려지고, 본문에 마지막 식이 없어 함수는 () 를 돌려주게 됩니다. 반환 타입 u32 와 맞지 않아 E0308 이 납니다 (마지막 줄에 세미콜론을 붙이면). 세미콜론을 지우면 됩니다.

2장

함수는 값이다

함수 포인터 · 함수를 인자로 · 중첩 함수 · 재귀 · 돌아오지 않는 함수

함수 이름은 값이고, 타입이 있다

함수를 변수에 담거나 배열에 넣을 수 있습니다. 그 타입은 fn(i32) -> i32 처럼 시그니처 모양 그대로 적습니다. 이것을 함수 포인터라고 합니다.

소문자 fn 이 타입 자리에 오면 함수 포인터 타입입니다. 대문자 Fn 은 클로저까지 받는 트레이트로, 12부에서 봅니다.

함수를 인자로 넘긴다

함수를 받는 함수를 만들 수 있습니다. 직접 만든 함수뿐 아니라 표준 라이브러리의 메서드 (i32::abs)도 같은 방식으로 넘깁니다.

i32::abs — 3부에서 a.abs() 로 부른 절댓값 메서드를, 타입 이름을 앞세워 값으로 가리킨 것입니다. 메서드를 만드는 법은 7부에서 봅니다.

함수 안의 함수

함수 안에서만 쓰는 도우미는 그 안에 정의할 수 있습니다. 바깥에서는 보이지 않습니다.

중첩 함수는 바깥 변수를 못 본다 — E0434

안쪽 fn 은 자리만 안에 있을 뿐 독립된 함수입니다. 바깥 함수의 지역 변수를 쓸 수 없습니다.

컴파일러의 권고 — help: 가 말하는 || { … } 꼴이 주변 변수를 붙잡을 수 있는 클로저입니다(12부). 지금은 값을 인자로 넘기면 됩니다. 뒤따르는 경고도 같은 말입니다 — 안쪽 함수가 factor 를 쓴 것으로 치지 않아 "쓰지 않은 변수" 라고 합니다.

재귀

함수는 자기 자신을 부를 수 있습니다. 끝나는 조건을 먼저 쓰는 것이 요령입니다.

깊이에는 끝이 있다 — 호출마다 스택을 씁니다. 아주 깊이 들어가는 일은 반복문으로 바꾸는 편이 안전합니다(4부).

돌아오지 않는 함수 — !

프로그램을 끝내거나 영원히 도는 함수는 돌아오지 않습니다. 그런 함수의 반환 타입은 ! (never 타입)입니다.

  • match 의 한 갈래는 i32 를, 다른 갈래는 ! 를 냅니다. ! 는 어떤 타입 자리에도 맞으므로 문제없습니다.
  • panic! 과 std::process::exit 가 대표적인 ! 입니다. 화면 끝의 종료 코드 2 는 exit(2) 가 낸 것입니다.
  • Ok 와 Err 는 parse 가 돌려주는 결과의 두 경우(성공·실패)입니다. 9부에서 봅니다.

퀴즈 — 함수는 값

Q. apply_twice(add_three, 10) 은 16 을 냈습니다. 같은 함수에 i32::abs 와 -4 를 넘기면 무엇이 나올까요?

A. 4 입니다. abs(-4) 는 4, abs(4) 도 4 입니다. 표준 라이브러리의 메서드도 fn(i32) -> i32 모양이면 직접 만든 함수와 똑같이 넘길 수 있습니다 (함수를 인자로).

3장

함수 다듬기

오버로딩이 없다 · 기본 인자가 없다 · 매개변수 고치기 · const fn · 문서 주석 · must_use

같은 이름의 함수를 둘 만들 수 없다 — E0428

C++ 나 Java 에서는 매개변수만 다르고 이름이 같은 함수를 여럿 만들 수 있습니다(오버로딩). Rust 에서는 그럴 수 없습니다.

한 이름에는 한 정의 — note: 가 말하듯 같은 이름은 한 번만 정의할 수 있습니다. 인자의 수나 타입으로 함수를 고르는 일이 없으므로, 이름만 보면 어느 함수인지 정해집니다.

대신 이름에 뜻을 담는다

Rust 의 관례는 다른 일에는 다른 이름을 주는 것입니다. 표준 라이브러리도 Vec::new 와 Vec::with_capacity 처럼 이름으로 가릅니다.

여러 타입을 한 함수로 받고 싶다면 그것은 제네릭의 일입니다(10부).

기본 인자도 없다 — Option 으로 받는다

"안 주면 기본값" 인 매개변수가 없습니다. 줄 수도 안 줄 수도 있는 값은 Option 으로 받고, 없을 때 쓸 값을 함수 안에서 정합니다.

Option 은 "있거나(Some) 없거나(None)" 를 나타내는 타입입니다. unwrap_or(값) 은 있으면 그것을, 없으면 괄호 안의 값을 냅니다. 7부와 9부에서 자세히 봅니다.

매개변수는 지역 변수다

매개변수도 변수이므로 기본은 불변입니다. mut 를 붙이면 함수 안에서 고칠 수 있습니다. 부른 쪽의 변수는 바뀌지 않습니다 — 정수는 넘길 때 복사됩니다.

부른 쪽의 값을 고치려면 가변 참조 &mut 가 필요합니다. 6부의 주제입니다.

매개변수를 같은 이름으로 다시 묶기

받은 값을 다듬어 쓸 때 새 이름을 짓는 대신 같은 이름으로 가립니다(shadowing). 타입이 바뀌어도 됩니다 — 아래에서 text 는 &str 에서 String 이 됩니다.

const fn — 컴파일하는 동안 부를 수 있는 함수

const 를 붙인 함수는 상수의 값이나 배열의 길이처럼 컴파일 때 정해져야 하는 자리에서 부를 수 있습니다. 실행 중에 부르는 것도 그대로 됩니다.

마지막 줄 — std::env::args().count() 는 명령 줄 인자의 수로, 실행해 봐야 아는 값입니다(여기서는 프로그램 이름 하나뿐이라 1). 그래서 이 호출은 실행 중에 일어납니다.

const 가 없으면 상수 자리에서 못 부른다 — E0015

같은 함수에서 const 만 뗐습니다. 본문은 똑같이 단순하지만, 컴파일러는 표시가 없는 함수를 컴파일 때 돌려 주지 않습니다.

const 는 약속이다 — "이 함수는 앞으로도 컴파일 때 돌릴 수 있게 유지하겠다" 는 표시입니다. 그래서 컴파일러가 알아서 판단하지 않고 쓴 사람이 붙입니다.

문서 주석 ///

슬래시 셋으로 시작하는 주석은 바로 아래 항목의 문서가 됩니다. 첫 줄은 한 문장 요약으로 씁니다.

그냥 주석과 다른 점 — 도구가 이것을 모아 문서 페이지를 만들고, 그 안의 예제 코드는 시험으로 돌려 주기까지 합니다. 13부에서 직접 해 봅니다.

반환값을 버리면 경고하게 만들기 — #[must_use]

결과를 쓰지 않으면 부른 의미가 없는 함수에는 #[must_use] 를 붙입니다. 부른 쪽이 값을 버리면 컴파일러가 경고합니다. 아래에서 세금을 더한 값은 버려졌고, price 는 1000 그대로입니다.

#[…] 는 속성(attribute)입니다. 바로 아래 항목에 대한 지시를 컴파일러에 전합니다. 13부에서 모아 봅니다.

퀴즈 — 함수 다듬기

Q. const BUFFER: usize = kib(4); 가 컴파일되려면 kib 는 어떻게 정의돼 있어야 할까요?

A. const fn kib(n: usize) -> usize 처럼 const fn 이어야 합니다. const 가 없으면 본문이 아무리 단순해도 E0015 가 납니다 (const 가 없으면 상수 자리에서 못 부른다).
