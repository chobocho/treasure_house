어댑터

map · filter · enumerate · zip · skip · take · chain · flat_map · filter_map · peekable

map 과 filter

가장 자주 쓰는 둘입니다. map 은 원소마다 바꾸고, filter 는 조건에 맞는 것만 남깁니다. 점으로 이어 붙여 사슬을 만듭니다.

**s — iter() 가 &i32 를 내주고, filter 는 그것을 다시 참조로 넘겨줍니다. 그래서 별이 둘입니다. 다음 두 장에서 풉니다.

filter 의 클로저는 참조의 참조를 받는다 — E0308

별을 빼먹으면 이렇게 됩니다. filter 는 원소를 넘겨받지 않고 빌려서 살펴보기만 하므로 &&i32 가 들어옵니다.

copied — 참조를 값으로 바꾼다

정수처럼 복사되는 원소라면 copied() 를 끼워 값의 반복자로 만듭니다. 별이 하나 줄고, 결과도 Vec<i32> 로 받을 수 있습니다. 패턴 |&&s| 로 벗기는 방법도 있습니다.

enumerate 와 zip

enumerate 는 번호를 붙이고, zip 은 두 반복자를 짝지어 튜플을 냅니다.

zip 은 짧은 쪽에서 끝난다 — 이름은 셋인데 점수가 둘이라 park 는 나오지 않았습니다. 오류도 경고도 없습니다.

건너뛰고, 자르고, 잇고, 뒤집고

반복자의 일부만 쓰거나 둘을 잇는 어댑터들입니다.

flat_map 과 flatten — 한 겹으로 편다

원소 하나가 여러 개로 늘어날 때 씁니다. 줄마다 낱말 여럿이 나오는 것을 낱말의 반복자 하나로 폅니다.

filter_map — 바꾸면서 거른다

클로저가 Option 을 돌려주면 Some 의 속만 남깁니다. "되는 것만 바꿔서 모으기" 가 한 줄입니다(9부에서 미리 썼습니다).

take_while 과 skip_while

조건이 처음 깨지는 자리를 기준으로 앞쪽만, 또는 뒤쪽만 씁니다. filter 와 달리 한 번 깨지면 그 뒤는 다시 보지 않습니다.

peekable — 다음 것을 엿본다

"다음이 숫자면 계속, 아니면 멈춤" 처럼 꺼내기 전에 살펴봐야 할 때 씁니다. 글자를 읽어 나가는 파서의 기본 도구입니다.

windows 와 chunks — 조각으로 돈다

이 둘은 반복자 어댑터가 아니라 슬라이스의 메서드지만 함께 자주 씁니다. 이웃한 원소를 견주거나 몇 개씩 끊어 처리할 때입니다.

사슬은 원소 하나씩 끝까지 흐른다

inspect 는 지나가는 원소를 엿보는 어댑터입니다. 찍힌 순서를 보면 사슬이 어떻게 도는지 보입니다 — 단계별로 전부 처리하는 것이 아니라, 원소 하나가 사슬 끝까지 간 뒤 다음 원소가 출발합니다.

중간 목록이 없다 — filter 뒤에 걸러진 목록이 따로 만들어지지 않습니다. 그래서 사슬이 길어져도 메모리를 더 쓰지 않습니다.

끝이 없는 반복자

게으르다는 것의 덤입니다. 끝없는 범위 (1..) 에서 시작해도, 필요한 만큼만 꺼내므로 끝납니다.

퀴즈 — 어댑터

Q. 이름 셋과 점수 둘을 zip 하면 짝이 몇 개 나올까요?

A. 둘입니다. zip 은 짧은 쪽이 끝나면 함께 끝납니다 (enumerate 와 zip).

4장

소비자

collect · sum · count · fold · min · max · any · all · find · for_each

collect — 받는 쪽의 타입이 정한다

collect 는 반복자의 값을 모아 모음을 만듭니다. 무엇을 만들지는 받는 변수의 타입을 보고 정합니다. 같은 반복자가 벡터도, 집합도, 문자열도, 맵도 됩니다.

타입을 안 알려 주면 — E0283

그래서 collect 에는 타입 표기가 필요합니다. 없으면 컴파일러가 무엇을 만들지 정하지 못합니다.

두 가지 표기 — let v: Vec<i32> = … .collect(); 또는 … .collect::<Vec<i32>>(). 원소 타입은 Vec<_> 로 맡겨도 됩니다.

세고, 더하고, 고른다

값 하나를 내는 소비자들입니다. min · max · last · nth 는 빈 반복자일 수 있으므로 Option 을 돌려줍니다.

fold — 하나로 접는다

가장 일반적인 소비자입니다. 처음 값에서 시작해, 원소마다 "지금까지의 값" 을 새 값으로 바꿔 갑니다. sum 도 count 도 fold 로 쓸 수 있습니다.

기준을 줘서 고른다 — max_by_key · max_by

"가장 긴 낱말" 처럼 원소 자체가 아니라 그 원소의 어떤 값으로 견줄 때 씁니다. 실수는 견주는 방법을 직접 줘야 합니다.

묻고 찾는다 — any · all · find · position

답이 정해지는 순간 멈춥니다. any 는 처음 맞는 원소에서, all 은 처음 어긋나는 원소에서 끝납니다.

for_each

사슬 끝에서 원소마다 무언가를 합니다. for 반복문과 같은 일이지만 사슬에 이어 쓸 수 있습니다.

어느 쪽을 쓸까 — 본문이 길거나 break 가 필요하면 for, 사슬 끝의 짧은 한 줄이면 for_each 입니다.

반복자는 한 번 쓰면 끝이다 — E0382

소비자는 반복자를 가져가서(self) 끝까지 돌립니다. 다 쓴 반복자를 다시 쓸 수 없습니다.

두 번 필요하면 모음에서 반복자를 다시 만들거나(v.iter() 는 값이 싸다), 먼저 collect 해 둡니다.

퀴즈 — 소비자

Q. let doubled = v.iter().map(|x| x * 2).collect(); 는 왜 컴파일되지 않을까요?

A. collect 가 무엇을 만들지 알 수 없어서입니다(E0283). 받는 쪽에 타입을 적습니다 — let doubled: Vec<i32> = …(타입을 안 알려 주면).

5장

실전

반복문을 반복자로 · 정렬 · 묶기 · 값을 만들어 내는 반복자

반복문을 반복자로 옮기기

같은 일을 두 가지로 씁니다. 반복문은 "어떻게" 를 한 걸음씩 적고, 반복자 사슬은 "무엇을" 을 단계 이름으로 적습니다.

느려질까 걱정하지 않아도 된다 — 반복자는 "비용 없는 추상화" 로 설계됐습니다. 사슬은 컴파일하면서 풀려 손으로 쓴 반복문에 가까운 코드가 됩니다. 읽기 좋은 쪽을 고르면 됩니다.

정렬 — sort_by_key 와 sort_by

정렬은 벡터의 메서드입니다. 기준이 하나면 sort_by_key, 견주는 법을 직접 쓰려면 sort_by 에 클로저를 줍니다.

안정 정렬 — 첫 줄에서 나이가 같은 kim 과 park 의 순서가 원래대로입니다. sort · sort_by · sort_by_key 는 같은 것끼리의 순서를 지킵니다(sort_unstable 계열은 지키지 않을 수 있습니다).

묶기 — 맵과 entry

"첫 글자별로 모으기" 같은 묶기는 맵의 entry 로 합니다. 없으면 빈 벡터를 만들고, 있으면 거기에 더합니다(8부).

값을 만들어 내는 반복자

모음이 없어도 반복자를 만들 수 있습니다. 앞의 값에서 다음 값을 내거나(successors), 부를 때마다 값을 내는 클로저로(from_fn) 만듭니다.

퀴즈 — 실전

Q. [1, 2, 3, 4].iter().inspect(A).filter(짝수).inspect(B).sum() 에서 A 와 B 가 찍는 순서는 "A 넷 다음에 B 둘" 일까요?

A. 아닙니다. 원소 하나가 사슬 끝까지 간 뒤 다음 원소가 출발하므로 A1, A2, B2, A3, A4, B4 순서입니다 (사슬은 원소 하나씩).
