11부

활용 II: 자동화와 서버

꺼지지 않고, 스스로 돌고, 부르면 답하게

폰은 늘 켜져 있고 늘 들고 다니는 컴퓨터입니다. 서버를 띄우고, 부팅 때 스크립트를 돌리고, 밖에서 들어오게 할 수 있습니다. 다만 8부의 벽(팬텀 프로세스·Doze·낮은 포트)이 그대로 따라옵니다.

이 덱은 서비스를 새로 켜거나 포트를 바깥에 열지 않았습니다. 서버 실험은 127.0.0.1 에서 한 번 묻고 끄는 것까지입니다.

1장

서비스 — termux-services 와 runit

설치(pkg install termux-services) 뒤 셸을 다시 열면 서비스 데몬이 뜹니다. 그다음은 runit 의 명령들:

하고 싶은 일명령
켜 두기(다음에도 자동)sv-enable <서비스>
이번만 띄우기sv up <서비스>
멈추기 · 끄기sv down · sv-disable
로그$PREFIX/var/log/sv/<서비스>/current

꺼진 서비스는 $PREFIX/var/service/<서비스>/down 파일이 있는 것 — sv-enable/sv-disable 은 이 파일을 지우고 만들 뿐입니다.

출처: termux-services README · 위키 Termux-services

문서

내 서비스 만들기

위키의 순서: $PREFIX/var/service/<이름>/log 를 만들고 로그 스크립트(svlogger)를 log/run 으로 링크한 뒤, 실행 가능한 run 스크립트를 $PREFIX/var/service/<이름>/run 에 둔다. runit 의 예제 스크립트들을 가져다 쓸 수 있다.

이 기기에는 termux-services 가 깔려 있지 않습니다 — 8부에서 본 sshd 는 사용자가 직접 띄운 데몬(부모 1)입니다.

2장

부팅 때 — Termux:Boot

README 의 사용법: ① 앱을 설치하고 ② 한 번 실행해 부팅 때 돌 수 있게 하고 ③ ~/.termux/boot/ 를 만들어 ④ 스크립트를 넣는다 — 여럿이면 이름 차례로. ⑤ 기기가 잠들지 않게 하려면 맨 먼저 termux-wake-lock.

README 의 두 예:

  • ~/.termux/boot/start-sshd — termux-wake-lock 다음 sshd
  • ~/.termux/boot/start-services — termux-wake-lock 다음 $PREFIX/etc/profile.d/start-services.sh 를 source — 1장의 서비스들을 부팅 때 켠다

출처: termux-boot README 1.2·1.2.1

문서

Boot 앱이 하는 일

부팅이 끝났다는 방송(BOOT_COMPLETED)을 받으면 디렉터리의 파일을 이름순으로 정렬하고, 파일마다 JobScheduler 작업 하나를 "3초 안에" 조건으로 예약합니다. 사용자가 실행 권한을 잊었으면 켜 줍니다.

이 기기 캡처

작업은 Termux 에게 넘긴다

Boot 앱은 스크립트를 스스로 돌리지 않습니다. 스크립트 경로를 com.termux.file 주소로 싸서, 백그라운드 실행 표시를 붙여 Termux 의 서비스에 보냅니다(Android 8 이상이면 전경 서비스로). 4부에서 본 sharedUserId 와 같은 서명이 이 부탁을 가능하게 합니다 — README 가 "같은 키로 서명되어야 스크립트 실행 권한이 있다" 고 적는 까닭입니다.

폰 위의 작은 웹 서버

파이썬 표준 라이브러리만으로 exp/ 디렉터리를 8080 에 내놓고 hello.c 를 한 번 받았습니다. 200 과 1048 바이트 — 파일 크기 그대로입니다. 80 이 아니라 8080 을 쓴 것은 8부의 포트 벽 때문입니다 — 이 기기에서는 80 도 열렸지만(8부 4장), 대개는 막혀 있습니다.

4장

밖에서 들어오기 — NAT 너머

위키 "Bypassing NAT": 통신사와 공유기는 여러 기기가 바깥 주소 하나를 나눠 쓰게 하므로(NAT), 기본으로는 인터넷에서 이 폰에 닿을 수 없다. 고정 IP 나 공유기의 포트 포워딩이 있다면 이 장은 필요 없다. 그렇지 않을 때의 길 셋:

방법위키의 설명
Tor 어니언 서비스가장 안전하고 효과적. 종단 간 암호화, root 없이 80 같은 가상 포트, 평범한 인터넷에는 안 보임
Ngrok닫힌 클라이언트 대신 OpenSSH 로 터널. 무료 계정은 TCP 포트가 무작위
Tmate터미널 공유. 쉽지만 손님이 끊으면 연결도 끝난다

문서

Tor 로 sshd 를 내놓는 설정

위키의 torrc 예는 두 줄이 핵심입니다: HiddenServiceDir …/home/.tor/hidden_ssh 와 HiddenServicePort 22 127.0.0.1:8022. 바깥에서는 22 번으로 보이고, 폰 안에서는 8022 의 sshd 로 이어집니다 — 8부의 낮은 포트 벽을 Tor 가 "가상 포트" 로 넘는 셈입니다.

11부 퀴즈

Q. ~/.termux/boot/10-sshd 와 ~/.termux/boot/2-lock 두 스크립트를 두었습니다. 부팅 때 어느 쪽이 먼저 예약되고, 그것이 의도와 맞습니까?

A. BootReceiver 는 이름을 문자열로 비교해 정렬하므로 10-sshd 가 2-lock 보다 먼저입니다 ("1" < "2"). wake lock 을 먼저 잡으려 했다면 의도와 다릅니다 — 01-lock·10-sshd 처럼 자리수를 맞추거나, README 의 예처럼 한 스크립트 안에서 termux-wake-lock 을 첫 줄에 둡니다.
