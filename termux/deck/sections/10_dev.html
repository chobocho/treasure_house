10부

활용 I: 개발 환경

폰 하나로 짜고, 돌리고, 올리기

이 덱의 도구·실험·빌드는 이 폰에서 돌았습니다. 이 부는 그 작업대를 한 칸씩 봅니다 — 무엇이 깔려 있고, 그것들이 자기가 어디서 돈다고 생각하는지, 그리고 PC 와 어떻게 잇는지.

Go·Rust 로 무언가를 지어 보지는 않았습니다 — 이 기기의 메모리로는 다른 작업과 함께 돌리기 어려워 판만 적습니다(PLAN.md 결정 10).

1장

작업대에 놓인 것

모두 pkg 로 설치한 Termux 패키지입니다 — 앱 안의 $PREFIX/bin 에 있고 bionic 에 링크됩니다(3부). rustc 의 날짜가 보여 주듯 저장소는 판을 계속 올립니다(2026-09 기준).

이 기기 캡처

없는 것

vim·nano·tmux·git·make·ssh·sshd 는 있고 rsync·emacs 는 이 기기에 깔려 있지 않습니다. 없는 것은 pkg install 한 줄이면 되지만, 이 덱은 사용자 기기에 패키지를 남기지 않았습니다(6부의 실험 .deb 는 깔았다 지웠습니다).

이 기기 캡처

위키가 꼽는 개발 환경

위키 "Development Environments" 는 31개 항목을 둡니다 — APK 만들기와 C/C++·Common Lisp·D·Dart·Elixir·Erlang·Forth· Go·Groovy·Haskell·Java·JavaScript·Kotlin·Lua·Nim·OCaml·Octave·Perl·PHP·Picolisp·Prolog·Python·Racket·Ruby·Rust·Scala· Scheme·Smalltalk·Swift·Tcl. 항목마다 패키지 이름과 홈페이지, 관련 이슈 링크가 붙어 있습니다.

2장

모두 자기가 안드로이드에 있다고 안다

Termux 의 파이썬은 sys.platform 을 android 로, 플랫폼 이름을 android-24-arm64_v8a 로 답합니다. 끝의 24 는 실험 1 의 hello 가 적은 "android api: 24" 와 같은 수입니다. Node.js 도 android 입니다.

이 기기 캡처

컴파일러의 대상

clang 은 aarch64-unknown-linux-android24, rustc 는 aarch64-linux-android, Go 는 GOOS=android. 세 도구 모두 "리눅스 커널 위의 안드로이드" 를 대상으로 코드를 냅니다 — glibc 가 아니라 bionic 을 부르는 코드입니다.

이 기기 캡처

같은 폰, proot 쪽은 linux

같은 커널 위인데 우분투의 도구들은 linux·aarch64-linux-gnu 입니다. 그리고 이 덱을 검사한 node(deck/check_deck.js)는 우분투의 것이 아니었습니다 — proot 세션의 PATH 끝에 붙은 $PREFIX/bin 에서 찾은 Termux 의 node 였습니다. proot-distro 는 로그인 때 환경을 새로 만들고, 마지막에 $PREFIX/bin 을 PATH 끝에 붙여 Termux 의 도구가 손에 닿게 합니다.

출처: 캡처 · proot-distro README 1.3.5.2 — 캡처는 tools/tmx.sh 가 우분투 기본 PATH 로 뜬 것이라 $PREFIX/bin 이 빠져 node·git 이 "없다" 로 나옵니다.

이 기기 캡처

1~2장 퀴즈

Q. proot 우분투에서 gcc 로 지은 실행 파일을 Termux 쪽 셸에서 바로 실행하면 어떻게 될까요? 반대로 Termux 의 clang 으로 지은 것을 우분투 쪽에서 실행하면?

A. 첫째는 대개 실패합니다 — 그 파일은 /lib/ld-linux-aarch64.so.1 을 인터프리터로 부르는데 Termux 쪽에는 그 경로가 없습니다(3부의 elf.py). 둘째는 /system/bin/linker64 를 부르는데 proot 가 /system 을 바인드해 두었으므로 이 세션에서는 돌 수 있습니다 — 실제로 이 덱의 bionic 실험 파일들이 그렇게 돌았습니다.
설명용

3장

파이썬

위키(Python)의 요점:

  • pkg install python 뒤 pip 가 생긴다. 네이티브 확장을 짓는 모듈이 있으니 build-essential 을 함께 두라.
  • numpy·matplotlib·cryptography·opencv 같은 것은 pip 보다 pkg install python-numpy 처럼 Termux 패키지로 — 컴파일 오류를 피한다.
  • 마이너 판이 오르면(3.8 → 3.9 처럼) 깔아 둔 모듈을 모두 다시 깔아야 한다. 저장소는 옛 판을 두지 않으니 개발자는 $PREFIX 를 백업해 두라.
  • termux-exec 가 살아 있어야 한다 — 아니면 모듈의 셔뱅을 일일이 고쳐야 한다(5부).

출처: 위키 Python 서두·1·2절

문서

Node.js

위키(Node.js): 현재판 nodejs 와 LTS nodejs-lts 중 하나만 깔 수 있다. 네이티브 확장을 짓는 패키지를 위해 build-essential 과 python 을 두라. 일부 모듈은 LLVM 도구(llvm-ar)를 못 찾아 binutils 가 필요하다. 표의 예로 브라우저에서 쓰는 VS Code(code-server)가 있다.

파이썬과 같은 경고도 있습니다 — 옛 판은 저장소에 없다.

4장

ssh — 폰과 PC 잇기

위키: Termux 의 기본 SSH 포트는 8022 입니다(8부 — 1024 미만은 대개 쓸 수 없다. 이 기기는 80·443 등 몇 개가 예외). init 이 없으니 서버는 명령줄에서 sshd 로 띄우고 pkill sshd 로 멈춥니다. 로그는 안드로이드 시스템 로그로 가서 logcat -s 'sshd:*' 로 봅니다.

출처: 위키 Remote Access 2.2.1

문서

이 기기의 sshd

호스트 키는 이미 만들어져 있고(ssh_host_*_key), 설정은 공개 키 목록을 ~/.ssh/authorized_keys 에서 읽습니다. Subsystem sftp 의 경로가 $PREFIX/libexec 인 것이 Termux 답습니다.

이 기기 캡처

비밀번호에서 키로

위키의 순서: ① 서버를 처음 띄울 때는 비밀번호 인증(기본으로 켜짐) — passwd 로 비밀번호를 정한다. ② PC 에서 키를 만들고 ssh-copy-id -p 8022 로 폰에 올린다. ③ PasswordAuthentication no 로 바꾸고 pkill sshd; sshd. 위키는 RSA 2048 비트를 "안전하다고 보는 최소" 로, 4096 을 넘기지 말라고 적습니다.

출처: 위키 Remote Access 2.2.1.2·2.2.1.3 · 8부의 캡처는 이 기기의 sshd 가 init 의 자식임을 보였습니다

5장

git 과 이 저장소

이 덱이 든 저장소는 사용자의 Termux 홈 아래에 있고, proot 에는 /root/github 로 바인드되어 있습니다(9부의 명령줄 끝의 사용자 바인드). 커밋은 proot 안에서 했지만 우분투 쪽에는 git 이 없어서, 2장의 node 처럼 PATH 끝의 Termux 의 git(2.55)이 쓰였습니다. 같은 저장소를 Termux 쪽 git 으로도, PC 로 밀어 올린 뒤 PC 의 git 으로도 다룰 수 있습니다.

git 자체는 이 저장소의 "Git 대백과사전" 덱이 다룹니다.

이 기기 캡처

6장

셸과 설정 파일

위키 "Shells" 가 꼽는 셸: BASH(기본 로그인 셸)·Busybox Ash·FISH·TCSH·ZSH, 그리고 IPython·Xonsh·Beanshell 같은 대화형 환경. 설정은 모두 $HOME 아래의 보통 도트파일입니다 — ~/.bashrc, ~/.profile.

Termux 앱 자신의 설정은 ~/.termux/ 에 있습니다. 이 기기에는 termux.properties 하나(4부의 키 목록). 도트파일을 git 저장소로 관리하면 폰과 PC 에서 같은 설정을 쓸 수 있지만, 경로가 다르다는 것(/usr 대신 $PREFIX)을 잊지 말아야 합니다.

3~6장 퀴즈

Q. pkg upgrade 뒤 파이썬이 3.14 에서 3.15 로 올랐고, 어제까지 되던 import requests 가 실패합니다. 왜이고, 무엇을 해야 합니까?

A. 모듈은 판별 디렉터리(lib/python3.14/site-packages)에 깔리므로 마이너 판이 바뀌면 새 파이썬은 옛 모듈을 보지 못합니다. 위키대로 모듈을 다시 깔아야 합니다. Termux 저장소는 옛 판을 두지 않으니, 되돌릴 길은 미리 떠 둔 $PREFIX 백업(8부)뿐입니다.
