CANNOT LINK EXECUTABLE

메시지CANNOT LINK EXECUTABLE "./use_gone": library "libgone.so" not found
원인bionic 의 동적 링커(linker64)가 DT_NEEDED 의 라이브러리를 RUNPATH 에서도 찾지 못했다. 대개 그 라이브러리의 패키지가 지워졌거나 판이 바뀌었다.
해결pkg install 로 빠진 패키지를 다시 깔거나(dpkg -S 로 주인 찾기, 6부), 실행 파일의 needed·runpath 를 py/elf.py 로 읽어 본다(5부).

스크립트가 "No such file or directory"

메시지#!/bin/sh 로 시작하는 스크립트를 실행했는데 파일이 없다고 한다
원인Termux 에는 /bin/sh 가 없다(FHS 를 따르지 않음). 커널이 셔뱅의 경로를 그대로 찾는다.
해결termux-fix-shebang 으로 첫 줄을 $PREFIX 경로로 고치거나, termux-exec 가 켜져 있는지(LD_PRELOAD) 확인한다(5부).

linker 경고 — unused DT entry

메시지WARNING: linker: …: unused DT entry: type …
원인실행 파일의 ELF 머리에 이 판의 안드로이드 링커가 모르는 항목(예: DT_FLAGS_1=0x8)이 있다. 위키: 경고는 안전하다.
해결pkg install termux-elf-cleaner 뒤 termux-elf-cleaner ./프로그램 — 공식 패키지는 빌드 때 이미 거친다(6부 massage).

[Process completed (signal 9)]

메시지[Process completed (signal 9) - press Enter] — 끝낸 적이 없는데
원인Android 12+ 의 팬텀 프로세스 킬러(32개 한도·과다 CPU) 가 SIGKILL 을 보냈다(8부).
해결14+: 개발자 옵션 "Disable child process restrictions". 12L·13: adb 로 settings put global settings_enable_monitor_phantom_procs false. 아니면 프로세스 수를 줄인다.

htop·netstat 이 안 된다 / Permission denied

메시지/proc/…: Permission denied, 또는 htop·netstat 이 비어 있음
원인위키 FAQ: 부채널로 정보가 새지 않도록 안드로이드가 /proc/net/*·/proc/loadavg·/proc/stat·/proc/uptime·/proc/version·/proc/vmstat 등을 막았다. 판이 오를수록 더 막힌다.
해결root 없이는 우회할 수 없다. proot-distro 는 바로 이 파일들을 가짜로 붙인다(9부 sysdata).

ps 에 내 프로세스만 보인다

메시지ps 에 안드로이드의 다른 프로세스가 없다 · pkill 이름 이 안 먹는 데몬
원인Android 7 부터 /proc 이 hidepid=2 로 붙어, 앱은 자기 프로세스만 본다. 위키: 그래서 ssh-agent·tor 같은 데몬이 ps 에 안 보여 pkill 로 못 죽이고 kill PID 만 되는 일이 있다.
해결root 셸이나 adb 에서만 더 보인다.

15부 퀴즈

Q. PC 에서 가져온 리눅스용 실행 파일을 Termux 에서 실행했더니 "No such file or directory" 가 납니다. 파일은 분명히 있습니다. 무엇부터 보겠습니까?

A. 파일이 아니라 인터프리터가 없는 것입니다. py/elf.py(또는 readelf -l)로 PT_INTERP 를 보면 /lib/ld-linux-aarch64.so.1 같은 glibc 링커일 텐데, Termux 에는 그 경로가 없습니다(5부). Termux 용으로 다시 짓거나(clang), proot 배포판 안에서 실행합니다(9부).
