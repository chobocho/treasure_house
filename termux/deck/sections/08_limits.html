8부

한계와 우회

막히는 곳마다 — 왜 막히나, 어떻게 돌아가나, 그 대가는

Termux 는 리눅스처럼 보이지만 안드로이드 앱입니다. 앞의 부들이 "어떻게 동작하나" 를 봤다면, 이 부는 "어디서 막히나" 를 모읍니다. 한계마다 무엇이 막나 · 이 기기에서 본 것 · 돌아가는 길 · 그 대가 순서로 적습니다.

돌아가는 길 중 adb·root 가 필요한 것은 이 덱이 실행하지 않았습니다(이 덱의 규칙 — 사용자 기기를 해치지 않는다). 문서에 적힌 방법을 옮겨 적고 출처를 붙입니다.

1장

root 가 없다 — 한 사용자짜리 리눅스

위키 "Differences from Linux" 의 넷째 절: 모든 것이 Termux 앱과 같은 uid 로 돌고, 사용자 이름은 uid 에서 나오므로 바꿀 수 없다. 그래서 패키지들은 다중 사용자·setuid/setgid 기능을 빼도록 패치되어 있고, 서버들의 기본 포트도 바꿨다 — ftpd 8021, httpd 8080, sshd 8022.

proot 의 uid=0 은 흉내였고(9부), 진짜 root 는 기기를 루팅해야만 생깁니다. 이 덱의 기기는 루팅되지 않았습니다.

출처: 위키 Differences from Linux(revid 6506) 4절

2장

팬텀 프로세스 — 32개가 넘으면 죽인다

Android 12 는 앱이 fork 한 자식 프로세스를 지켜보다가 기본 32개(모든 앱을 합친 수 — README NOTICE)가 넘으면 죽이는 장치를 넣었습니다. 백그라운드에서 CPU 를 너무 쓰는 프로세스도 죽입니다. Android-Docs(Termux 팀원 agnostic-apollo 의 문서)에 따르면 이 변경은 Android 12 변경 목록에도, 동작 변경 목록에도 없이 조용히 들어갔습니다.

출처: Android-Docs phantom-cached-and-empty-processes 2절

문서

팬텀 프로세스란

안드로이드가 보기에 앱의 주 프로세스에서 fork 된 모든 프로세스입니다. 만들어지는 길은 셋:

  • Runtime.exec() — 자바에서 자식을 띄운다. Termux 의 백그라운드 작업(RUN_COMMAND 등).
  • fork + execvp — 네이티브에서. Termux 의 터미널 세션(4부의 create_subprocess).
  • daemon() — 부모를 떠나 init(pid 1)의 자식이 된다. sshd·crond 같은 것. 앱 프로세스에 붙어 있지 않아 더 쉽게 죽는다.

문서의 결론: Termux 에서는 셸에서 돌리는 모든 명령이 대상입니다.

출처: Android-Docs 2.1·2.2

누구부터 죽이나

문서가 옮긴 PhantomProcessList.trimPhantomProcessesIfNecessary()(Android 12 r4)의 순서:

화면에 남는 것 — signal 9

README 의 경고문: 셸을 끝내지 않았는데 [Process completed (signal 9) - press Enter] 가 보일 수 있다. 9 는 SIGKILL 입니다. 셸은 시그널로 죽은 자식의 종료 상태를 128 + 번호로 적으므로 137 이 됩니다. 킬러를 일부러 부르지 않고, 우리 자식에게 직접 SIGKILL 을 보내 같은 모양을 만들었습니다(실험 9).

1~2장 퀴즈

Q. Android 13 폰에서 Termux 로 make -j8 빌드를 돌리고 화면을 껐더니 빌드가 signal 9 로 끊겼습니다. 가장 먼저 의심할 것과, root 없이 할 수 있는 일은?

A. 팬텀 프로세스 킬러입니다 — 컴파일러 여덟 개와 셸·make 가 더해져 32 에 가깝고, 백그라운드의 CPU 과다 사용도 걸립니다. root 없이도 adb(무선 디버깅)로 settings put global settings_enable_monitor_phantom_procs false 를 한 번 실행할 수 있습니다(12L·13 이상). 아니면 -j 를 줄이고 화면을 켜 둡니다.

3장

Doze — 잠든 폰은 wake lock 을 무시한다

개발자 문서: 전원에 꽂지 않은 채 한동안 움직이지 않고 화면이 꺼져 있으면 기기는 Doze 에 들어갑니다. 그동안

  • 네트워크 접근을 멈추고
  • wake lock 을 무시하며
  • 알람·작업(JobScheduler)·동기화를 다음 "유지 보수 창" 까지 미룹니다.

유지 보수 창은 시간이 갈수록 드물어집니다. 사용자가 기기를 움직이거나 화면을 켜거나 충전기를 꽂으면 풀립니다.

출처: developer.android.com Doze and App Standby 1.1·1.1.1

문서

그래서 Termux 는 배터리 최적화 해제를 요청한다

실험 4 는 127.0.0.1 의 포트 1~1100 에 하나씩 bind() 해 보고 곧바로 닫습니다. 같은 소스를 Termux 의 clang(bionic)과 proot 의 gcc(glibc)로 지어 양쪽에서 돌렸습니다.

5장

저장소 — 앱의 집과 공유 저장소

$PREFIX 와 $HOME 은 /data 파티션의 앱 전용 디렉터리에 있습니다(3부). 여기에 세 가지 한계가 붙습니다.

  • $PREFIX 는 옮길 수 없다 — 모든 프로그램이 그 경로를 박아 두고 있다.
  • $PREFIX 의 파일을 sdcard 에 둘 수 없다 — 그 파일 시스템은 유닉스 권한·심볼릭 링크·소켓을 지원하지 않는다.
  • 앱을 지우거나 데이터를 지우면 $PREFIX 와 $HOME 도 함께 지워진다.

7장

bionic 이 막는 이식

termux-packages 위키의 "Common porting problems" 가 적는 것 중 몇 가지:

  • bionic 에는 iconv·gettext 가 없다 → libandroid-support
  • <glob.h> 가 없다 → libandroid-glob
  • 커널이 System V 공유 메모리를 지원하지 않는다 → ashmem 위에 흉내 낸 libandroid-shmem
  • System V 세마포어도 없다 → libandroid-posix-semaphore
  • Android 8 부터 앱에 seccomp 가 걸려 일부 시스템 호출이 "Bad system call" 로 죽는다
  • Android 9 부터 setuid 계열 호출이 막힌다

출처: termux-packages.wiki Common-porting-problems.md(고정 커밋)

termux-backup 은 $HOME 을 싸지 않는다

termux-restore 는 풀기 전에 대상 트리를 지우므로(--recursive-unlink), 백업에 무엇이 들었는지 확실해야 합니다. 파이프 입력은 두 번 읽을 수 없으니 구성을 고정해야 했고, 그래서 $PREFIX 만 싼다 — $HOME 은 사용자 몫이다.

소스 발췌

9장

키보드와 화면

터치 키보드에는 Ctrl·Alt·Esc 가 없습니다. Termux 는 볼륨 아래를 Ctrl 로, 볼륨 위를 특수 키 접두로 씁니다: 볼륨 위+E → Esc, +T → Tab, +1 → F1, +W/A/S/D → 화살표, +L → |, +Q → 추가 키 줄 보이기.

이 덱의 조작(←/→ 넘기기, ↑/↓ 스크롤)을 폰에서 보는 것도 같은 문제를 푼 것입니다 — 화면 위 버튼과 게임패드.

출처: 위키 Touch Keyboard(revid 6554)

3~9장 퀴즈

Q. termux-backup ~/storage/shared/b.tar.gz 로 백업하고 앱을 지웠다 다시 깔아 termux-restore 로 풀었습니다. 무엇이 돌아오고 무엇이 사라졌을까요?

A. $PREFIX(설치한 패키지·설정)는 돌아오지만 $HOME(작업 파일·~/.termux·dotfile)은 사라졌습니다 — termux-backup 은 $PREFIX 만 쌉니다. $HOME 까지 지키려면 위키처럼 ./home ./usr 을 함께 tar 로 싸서, 앱 전용 디렉터리가 아닌 공유 저장소에 둡니다.
