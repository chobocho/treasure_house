설치에서 첫 패키지까지 — 막히지 않고 시작하기

처음 Termux 를 여는 사람을 위한 부입니다. 각 장은 짧게 "무엇을 하나" 만 적고, 왜 그렇게 되는지는 뒤의 원리 부 (3~9부)로 이어 둡니다.

1장

Termux 란

README 의 한 줄: "Termux 는 안드로이드용 터미널 앱이자 리눅스 환경이다." 위키는 덧붙입니다 — 가상 머신도 에뮬레이터도 아니다. 모든 패키지는 안드로이드 NDK 로 교차 컴파일되고 안드로이드에서 돌도록 호환 패치만 붙어 있다. 루팅이나 특별한 설정 없이 리눅스 명령줄을 쓰게 하는 것이 목표다.

그래서 이 폰 위의 bash 는 에뮬레이션이 아니라 이 폰의 CPU 에서 곧바로 도는 안드로이드 프로그램입니다(3·5부).

출처: termux-app README 서두 · 위키 Getting Started 서두·1절

문서

모든 것은 앱의 디렉터리 안에

위키가 "prefix" 라 부르는 /data/data/com.termux/files/usr($PREFIX)가 다른 배포판의 /usr 자리이고, $HOME 은 그 옆의 home 입니다. 이 경로는 모든 실행 파일에 박혀 있어 옮길 수 없습니다(5부).

3장

첫 실행 — 부트스트랩이 풀린다

README 가 말하는 "부트스트랩" 은 앱에 실려 오는 최소한의 패키지 묶음입니다. 처음 열면 앱이 이것을 $PREFIX 에 풀고 나서 셸을 띄웁니다. 풀리는 순서와 앱 안에 zip 이 어떻게 들어 있는지는 4부("부트스트랩" 장), 그 zip 을 누가 만드는지는 6부에 있습니다.

이 기기는 지금 170개 패키지로 자랐습니다.

4장

pkg 첫 명령

위키는 apt 를 직접 쓰기보다 pkg 를 강하게 권합니다 — 짧은 별칭(pkg in), 필요하면 설치 전에 apt update 를 알아서, 그리고 미러를 돌려 쓰며 부하를 나눈다.

하고 싶은 일명령
먼저 전부 올리기(주 1회 권장)pkg upgrade
설치 · 제거pkg install 이름 · pkg uninstall 이름
찾기 · 목록pkg search · pkg list-all · pkg list-installed
패키지의 파일pkg files 이름
캐시 비우기pkg clean · pkg autoclean

출처: 위키 Package Management 2절 · pkg 의 속은 6부

문서

pkg 가 하지 않는 것

위키의 제약 세 줄: 데비안·우분투 저장소의 패키지는 쓸 수 없다(5부 — 경로와 libc 가 다르다). 64비트와 32비트를 함께 깔 수 없다. 되돌리기(다운그레이드)가 없다 — 디스크를 아끼려고 옛 판을 두지 않는다. 그리고 root 로 apt 를 돌리는 것은 막혀 있다 (6·15부).

출처: 위키 Package Management 1절

5장

폰의 파일에 닿기

termux-setup-storage 한 번이면 권한을 묻고 ~/storage 에 다운로드·사진·음악 등으로 가는 링크를 만듭니다. 기본으로는 권한이 없고 앱이 시작할 때 묻지도 않습니다(8부).

이 기기 캡처

6장

키보드 — Ctrl 은 볼륨 아래

터치 키보드에는 Ctrl·Esc·Tab 이 없습니다. 볼륨 아래 + C 가 Ctrl+C, 볼륨 위 + E 가 Esc, 볼륨 위 + T 가 Tab, 볼륨 위 + W/A/S/D 가 화살표. 화면 아래의 추가 키 줄은 볼륨 위 + Q 로 켜고 끕니다. 설정 파일로 추가 키를 바꾸는 일은 4부(termux.properties)에.

출처: 위키 Touch Keyboard

7장

세션과 서랍, 그리고 비상구

화면 왼쪽에서 밀면 서랍이 열리고 "new session" 으로 셸을 여럿 띄웁니다. 그 버튼을 길게 누르면 "failsafe" — Termux 의 셸 대신 안드로이드의 /system/bin/sh 로 뜨는 비상 세션입니다. 도트파일을 잘못 고쳐 Termux 가 열리자마자 닫힐 때 쓰는 문입니다(15부).

출처: 위키 FAQ "How to open failsafe shell" · Recover a broken environment

1부 퀴즈

Q. F-Droid 에서 Termux 를 깔아 쓰던 사람이 GitHub 의 Termux:API APK 를 받아 설치하려 합니다. 무슨 일이 생기나요?

A. 설치가 실패합니다(App not installed 등). 두 앱이 같은 sharedUserId 를 쓰려면 같은 키로 서명되어야 하는데, F-Droid 판은 F-Droid 의 키, GitHub 판은 공개 테스트 키입니다. 플러그인도 F-Droid 에서 받아야 합니다.
