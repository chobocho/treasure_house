7부

Termux:API 와 플러그인

앱과 명령줄 사이를 잇는 다리

터미널 안의 프로그램은 안드로이드의 자바 API(배터리·센서·알림·카메라)를 부를 수 없습니다. 그 일을 대신 해 주는 것이 Termux:API 라는 별도의 앱과, 그 앱에 부탁을 전하는 명령줄 도구입니다. 같은 구조로 부팅·위젯·Tasker·떠 있는 창·배색·X11 을 맡는 플러그인들이 있습니다.

proot 안에서는 API 가 답하지 않았습니다(1장). 그래서 API 출력은 사용자가 네이티브에서 돌릴 스크립트에 맡겼고, 공개 시점에는 그 결과가 없어 출력 대신 소스에서 읽은 출력 모양을 싣습니다. 개인정보를 읽는 명령은 한 번도 실행하지 않았습니다.

1장

한 줄이 앱까지 가는 길

설명용

명령은 몇 줄짜리 셸 스크립트다

인자를 검사하고 마지막 줄에서 $PREFIX/libexec/termux-api 에 메서드 이름(BatteryStatus) 하나를 넘길 뿐입니다. 5부의 실험 7(exp/api_call.sh)은 설치된 스크립트에서 그 이름을 읽어 termux-api 를 직접 부르는 스크립트입니다.

이 기기 캡처

몇 개가 이 길을 쓰나

84개 중 54개가 termux-api 를 부릅니다. 나머지는 termux-tools·termux-core 등의 명령으로, 앱 없이 셸에서 끝납니다(6부의 주인 목록). 명령마다의 표는 3장에 있습니다.

이 기기 캡처

termux-api — 소켓이냐 am broadcast 냐

Android 14(API 34) 미만이면 먼저 유닉스 소켓으로 앱에 붙습니다. 14 이상에서는 앱 프로세스가 얼어 있을 때 소켓은 붙지만 답이 오지 않아 read() 가 한없이 기다릴 수 있어서, 앱을 깨우기도 하는 옛 방식 am broadcast 를 씁니다(주석이 가리키는 이슈 #638). 소켓 상대가 정말 플러그인인지는 SO_PEERCRED 로 uid 를 확인합니다(88–90행).

소스 발췌

proot 안에서는 답이 없다

종료 코드 124 는 timeout 이 끊었다는 뜻입니다. 이 덱은 그 까닭을 확인하지 못했습니다 (미확인) — 소켓 쪽의 uid 확인이나 am 경로가 proot 의 가짜 uid 0 과 어긋날 수는 있지만, 추측입니다. 그래서 API 의 실제 출력은 네이티브 캡처로 받습니다.

이 기기 캡처

앱 쪽 — 메서드 이름으로 가른다

인텐트의 api_method 로 45가지 경우를 가르고, 각각 apis/ 아래의 클래스 하나를 부릅니다. 카메라·통화 기록처럼 런타임 권한이 필요한 것은 부르기 전에 권한을 확인하고, 없으면 권한 창을 띄웁니다 (같은 파일의 checkAndRequestPermissions).

소스 발췌

BatteryStatus 가 돌려주는 칸

네이티브 캡처의 JSON 이 이 이름들로 나와야 합니다(0부 "이 기기"). 값이 없으면 넣지 않는 것 (…IfSet)도 코드에서 보입니다.

소스 발췌

2장

명령 84개의 색인

6부에서 dpkg -S 로 본 주인 패키지와, 스크립트가 termux-api 를 부르는지를 합쳐 표를 만들었습니다 (tools/api_table.py, 손으로 적지 않음). 전체 84줄은 17부 부록에 있고, 여기서는 두 부분만 봅니다.

설명용

표는 캡처에서 만든다

입력은 6부의 dpkg_stats 캡처(주인 패키지)와 1장의 api_mechanism 캡처(스크립트 안의 termux-api 호출)입니다. 캡처가 바뀌면 make tables 가 표를 다시 씁니다.

이 기기 캡처

이 덱이 실행하지 않은 명령 — 개인정보 16개

문자·통화 기록·연락처·위치·카메라·마이크·전화·알림 목록·지문·키 저장소·NFC·USB. 이 덱을 만든 도구 (tools/tmx.sh)는 이 이름들을 명령 자리에서 보면 실행하기 전에 거부합니다(2장 끝).

이 기기 캡처

거부 목록은 코드로 박혀 있다

시험(tools/tests/test_tmx.py)이 거부 목록의 명령 50가지를 하나씩 넣어 보고, 뒤에 붙인 touch 가 표지 파일을 만들지 못했음을 — 즉 실행되지 않았음을 — 확인합니다.

이 기기 캡처

실행하지 않고 출력 모양 알기 — termux-sms-list

위키는 "출력은 JSON" 과 옵션(-l 개수·-o 건너뛰기·-t 종류·-n 번호 보이기· -d 날짜)만 적습니다. 칸 이름은 앱 소스에 있습니다 — 보낸 사람(sender)·번호(number)· 본문(body). 이 명령이 무엇을 내놓는지 알면, 스크립트에 이 권한을 줄지 판단할 수 있습니다(14부).

출처: 위키 Termux-sms-list · 소스

소스 발췌

termux-location 의 칸

위키의 옵션: -p 제공자(gps·network·passive, 기본 gps), -r 요청 종류(once·last·updates). 위키는 GPS 가 건물 안에서는 잘 안 되고, 기기 시계가 맞아야 한다고 덧붙입니다.

출처: 위키 Termux-location · 소스

소스 발췌

3장

안전한 명령 — 네이티브에서 돌릴 것

화면이나 설정을 바꾸지 않고 읽기만 하는 명령 몇 개를 골라, 사용자가 네이티브 Termux 에서 한 번 돌릴 스크립트에 넣었습니다. 토스트·진동·알림처럼 사용자의 화면에 흔적을 남기는 것은 넣지 않았습니다.

이 기기 캡처

그 스크립트의 해당 부분

결과는 data/device.txt 에 모이고, 개인정보 검사(tools/scrub.py)를 거쳐 캡처 native_device 로 들어옵니다. Wi-Fi 이름·주소는 자리표시로 바뀝니다.

공개 시점(2026-09-18)에는 네이티브 결과가 오지 않아 표의 명령 출력은 싣지 못했습니다(0부 "이 기기").

설명용

1~3장 퀴즈

Q. 어떤 셸 스크립트가 termux-battery-status 만 부릅니다. Termux:API 앱을 지우면 명령은 어떻게 됩니까? termux-api 패키지를 지우면?

A. 앱을 지우면 스크립트와 libexec/termux-api 는 남아 있어 명령은 실행되지만, 요청을 받을 상대(TermuxApiReceiver)가 없으니 답이 오지 않습니다. 패키지를 지우면 termux-battery-status 스크립트 자체가 사라집니다 — 1장에서 본 두 조각(패키지와 앱)이 모두 있어야 합니다.
설명용

4장

플러그인 — 다른 입구들

Termux 에는 API 말고도 부가 앱이 있습니다. 모두 같은 sharedUserId 를 쓰므로(4부) 같은 곳에서 받은 것끼리만 함께 설치됩니다.

문서

스크립트를 두는 자리

Boot 는 ~/.termux/boot/ 의 스크립트를 이름 차례로 돌리고, 먼저 termux-wake-lock 을 부르라고 권합니다. Widget 은 ~/.shortcuts/ 를 전경 세션으로, ~/.shortcuts/tasks 를 백그라운드로 돌리며, 숨김 디렉터리·깨진 링크·밖을 가리키는 파일은 목록에 넣지 않습니다.

출처: termux-boot·termux-widget README

문서

Termux:Tasker 와 두 개의 문

Tasker 같은 자동화 앱이 Termux 명령을 부르려면 README 가 "필수" 로 적은 두 가지가 필요합니다.

  • 부르는 앱에 com.termux.permission.RUN_COMMAND 권한 — 0.5 이상. 없으면 FireReceiver 가 권한 오류를 냅니다.
  • ~/.termux/tasker/ 밖의 스크립트를 절대 경로로 부르려면 allow-external-apps=true.

README 는 경고합니다: 덜 믿는 앱에 RUN_COMMAND 권한을 줬다면 allow-external-apps 를 켜지 말라 — 그 앱이 사용자 모르게 백그라운드에서 아무 명령이나 돌릴 수 있다. 4부의 RUN_COMMAND 인텐트와 같은 문입니다.

출처: termux-tasker README 1.6.2·1.6.3·1.6.4

문서

Float 과 Styling

Termux:Float 은 터미널을 떠 있는 창으로 엽니다. Termux:Styling 은 터미널을 길게 눌러 More… → Style 에서 색 배합과 글꼴을 고르게 합니다. 이 덱의 배색(0부)은 Styling 이 아니라 앱 소스의 기본 색표(TerminalColorScheme)에서 왔습니다.

출처: termux-float·termux-styling README

문서

Termux:X11

NDK 로 지은 완전한 X 서버입니다. Android 8 이상이고, 앱과 Termux 쪽 패키지(x11-repo 의 termux-x11-nightly)가 둘 다 있어야 합니다(API 와 같은 두 조각 구조). GitHub 에 남은 릴리스는 nightly 하나뿐이라 첫 릴리스 날짜를 표에 적을 수 없었습니다. 12부에서 자세히 봅니다.

출처: termux-x11 README 1.1·1.4 · 릴리스 목록(2026-09 기준)

4장 퀴즈

Q. 부팅할 때 sshd 를 띄우고 싶습니다. Termux:Boot 로 할 때 스크립트 첫 줄 가까이에 무엇을 두라고 README 가 권합니까? 그리고 그 스크립트를 어디에 둡니까?

A. termux-wake-lock — 기기가 잠들어 프로세스가 멈추지 않게 합니다. 자리는 ~/.termux/boot/ 이고, 여러 개면 이름 차례로 돕니다.
