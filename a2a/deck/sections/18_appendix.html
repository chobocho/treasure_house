부록

부록 — 오류 코드표·필드 사전·용어집·찾아보기

오류 코드표, 메서드 대응표, proto 에서 뽑은 필드 사전, 용어집, 찾아보기, 출처와 퀴즈 모음

부록은 찾아보는 곳이다 — 새 실험 없이, 앞 부의 슬라이드로 가는 길만 모았다

0~17부가 돌려 보인 것을 표로 다시 묶었습니다. 표의 칸마다 그것을 보인 슬라이드로 가는 링크가 있고, 필드 사전과 찾아보기는 손으로 적지 않고 make deck 이 proto 와 조각에서 그때마다 새로 만듭니다.

장무엇을
1장오류 코드표 — JSON-RPC 표준 다섯, A2A 아홉, 세 바인딩의 그릇, 표 밖의 오류
2장메서드 대응표 — 열한 연산 × JSON-RPC·gRPC·HTTP+JSON, 세 SDK 클라이언트의 이름
3장필드 사전 — a2a.proto 의 메시지 마흔넷과 enum 둘
4장용어집 — 이 책이 고정한 번역과 부마다 들인 말
5장찾아보기 — 메서드·필드·enum 값·오류·머리글 이름에서 쪽 번호로
6장출처 목록과 퀴즈 모음
퀴즈는 없다 — 부록은 새로 가르치지 않으므로 장 끝 퀴즈를 두지 않았습니다. 대신 6장에 0~17부의 퀴즈 백스물셋을 부·장마다 모아 두었습니다.

3장

필드 사전

a2a.proto(v1.0.1)의 메시지 마흔넷과 enum 둘을 파일 차례대로 — 읽는 법 한 장, 그다음은 proto 에서 뽑은 표

사전 읽는 법 — 손으로 옮기지 않고 proto 에서 뽑았다

tools/appendix.py 가 docs/spec/specification/a2a.proto 를 읽어 deck/fields.tsv 를 만들고, 조립기의 FIELDS 지시자가 그것을 블록이 쪼개지지 않게 나눠 싣습니다. make deck 이 매번 먼저 돌리므로 proto 와 어긋날 수 없습니다.

칸읽는 법
머리 줄메시지·enum 이름과 proto 주석의 첫 문장. 이름의 링크는 그것을 가르친 슬라이드(deck/proto_where.tsv)
필드(JSON)와이어에 나오는 이름 — context_id → contextId(ProtoJSON). 필수 는 field_behavior = REQUIRED(예순하나), 폐기 는 deprecated = true(둘). oneof 에 든 필드는 그 이름을 밑에 적었다
타입repeated 는 배열, map<…> 은 객체, optional 은 "안 채움" 을 가르는 필드(7부). google.protobuf. 는 떼어 Struct·Value·Timestamp 로
#필드 번호(enum 은 값). gRPC 의 바이너리에서 쓰고 JSON 에는 나오지 않는다
뜻proto 주석의 첫 문장을 영어 그대로. 110자에서 자르고 Optional.·Required. 머리말은 뺐다
빠진 것 — service 의 rpc 열하나는 2장의 몫이라 여기 싣지 않았습니다. 필드는 백일흔여섯, enum 값은 열둘입니다.

4장

용어집

이 책이 고정한 번역과 부마다 새로 들인 말을 가나다순으로 — 용어를 누르면 그것을 처음 풀이한 슬라이드로 갑니다(영문 머리 말은 맨 앞)

5장

찾아보기

메서드·메시지·필드·enum 값·오류·reason·머리글 이름을 abc 차례로 — 숫자는 쪽 번호, 처음 나온 세 곳(가르친 슬라이드가 있으면 그것이 먼저)

6장

출처 목록과 퀴즈 모음

역사와 스펙의 출처 글(data/sources.tsv) → 0~17부의 장 끝 퀴즈를 부·장마다

책을 덮으며 — 카드 한 장에서 메시 하나까지, 모두 이 기계에서 돌았다

이 책은 에이전트 카드를 읽는 데서 시작해, 다섯 에이전트가 세 언어·세 바인딩으로 서로 일을 맡기는 메시를 짓고, 그것이 끊기고 죽을 때까지 보았습니다. 화면의 코드와 출력은 모두 저장소의 진짜 파일과 캡처입니다.

  • 무엇인가를 다시 찾을 때는 1~2장의 표, 이름을 알면 찾아보기, 말을 알면 용어집에서 시작하십시오.
  • 스펙이 바뀌면 make docs 로 proto 를 다시 받고 make deck 을 돌리면 필드 사전과 찾아보기가 따라 바뀝니다.
처음으로 — 여기가 마지막 슬라이드입니다. 다시 읽으려면 표지로, 읽는 길을 고르려면 0부 길잡이로 가십시오.
