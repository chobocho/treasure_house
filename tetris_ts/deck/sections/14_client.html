{{N}}이제 소켓을 붙인다

규칙(파트 10)도, 프로토콜(11)도, 웹소켓(12)도, 룸(13)도 다 있다. 남은 건 이것들을 이어 붙여 실제로 붙는 것이다 — 서버 한 대, 페이지 하나, 그리고 이 문서 안에서 도는 8인 대전.

PC 네 대가 이 페이지 안에서 허브에 붙어 좌석을 잡고 대전한다. 하늘색 이름이 1번 PC 의 좌석이고, 나머지 여섯은 초당 10회 올라오는 스냅샷을 풀어서 그린 남의 화면이다.

{{N}}아래로 갈수록 순수하다

  브라우저 페이지 (app.ts)          덱 데모 (net_view.ts)      봇 (bot_client.ts)
        │                                  │                        │
        └──────────── NetClient (client.ts) ────────────────────────┘
                             │ Transport
             ┌───────────────┴───────────────┐
        WebSocket                       LoopbackHub
             │                               │
        server.ts (소켓·파일)            같은 페이지 안
             └───────────────┬───────────────┘
                          Hub (hub.ts)      ← 방 코드·pid·라우팅
                             │
                          Room (room.ts)    ← 게임 규칙, 순수 상태 기계

전송 계층만 바꿔 끼우면 같은 코드가 세 곳에서 돈다. 덱 데모가 "그럴듯한 흉내"가 아닌 이유이자, 테스트가 소켓 없이 대전을 끝까지 돌릴 수 있는 이유다.

{{N}}방 코드와 pid

허브는 소켓을 모른다. handle() 이 받는 사람이 확정된 메시지 목록을 돌려주므로 바깥 층은 그대로 write 하기만 하면 된다.

0·O·1·I·L 을 뺀 이유방 코드는 사람이 전화로 불러 줘야 한다. 헷갈리는 글자를 빼면 31글자가 남고, 네 자리로 92만 가지다 — 동시에 열려 있을 방 수를 생각하면 충분하다.

{{N}}충돌하면 다시 뽑는다

fan 이 to: 0(방 전체)을 실제 pid 목록으로 풀어 준다. 이걸 아래층에서 하면 소켓 층이 방 구성을 알아야 하고, 그러면 층 나눔이 무너진다.

{{N}}허브가 직접 답하는 것

허브가 직접 처리하는 건 hello·create·join·ping 넷뿐이다. 나머지는 전부 방으로 넘긴다 — 방에 안 들어간 사람이 좌석을 요구하면 nosuch 로 막는다.

빈 방은 치운다마지막 사람이 나가면 방을 지운다. 안 그러면 방 코드가 영원히 쌓여 재사용도 안 되고 메모리도 샌다.

{{N}}이 층만 더럽다

시계·소켓·파일을 만지는 유일한 층이다. 그 아래는 전부 순수하므로, 여기서 버그가 나면 여기서만 난다.

.. 를 막지 않으면 파일 서버가 아니라 파일 유출기다safeJoin 이 정규화 뒤 루트 밖을 가리키면 거절한다. 널 바이트도 막는다 — 옛 라이브러리들이 이걸로 뚫렸다. 테스트가 ../../etc/passwd 류를 직접 넣어 본다.

{{N}}101 뒤로는 메시지만 오간다

연결 하나가 pid 하나다. 소켓이 끊기면 hub.disconnect 를 부르고, 그 결과로 나온 메시지(좌석 비움·탈락·종료)를 남은 사람들에게 배달한다.

{{N}}make run

$ make run
node dist/src/net/server.js --port 8787
서버 시작 — http://localhost:8787  (web/ + /ws)

정적 파일 루트는 web/ 이다. make web 이 만든 번들과 index.html 이 그 안에 있다.

{{N}}전송 계층은 밖에서 넣는다

이 파일은 자기가 소켓 위에 있는지 루프백 위에 있는지 구분하지 못한다. 그래서 "덱에서 도는 것과 서버에 붙는 것이 같은 코드"라는 말이 성립한다.

{{N}}구독자가 볼 때 이미 최신이어야 한다

메시지가 오면 방 상태를 먼저 갱신하고 그다음에 사건을 낸다. 순서를 바꾸면 콜백 안에서 client.seats 를 읽었을 때 한 박자 전 목록이 나온다 — 찾기 어려운 종류의 버그다.

깨진 JSON 은 조용히 버린다. 우리가 고칠 수 있는 게 없고, 던져 봐야 화면만 죽는다.

{{N}}소켓 없이 서버에 붙기

허브도 룸도 클라이언트도 그대로다. 바뀐 건 "보내면 어디로 가는가" 하나뿐이다. 지연(latency)을 주면 진짜 네트워크처럼 늦게 도착하는 상황도 재현할 수 있다.

onOpen 을 다음 틱에 부르는 이유생성자가 돌아가기 전에 부르면 구독자가 아직 없다. 진짜 WebSocket 도 마찬가지라, 이렇게 두면 두 전송 계층의 타이밍 성질까지 같아진다.

{{N}}내 좌석만 굴린다

클라이언트는 방에 대한 사실만 안다. 실제로 판을 굴리는 건 이 파일이고, 하는 일은 넷이다: AI 를 두게 하고, 굳을 때마다 공격을 보고하고, 화면을 주기적으로 올리고, 내려온 가비지를 유예 뒤에 얹는다.

시드는 start 로 내려온 하나를 전원이 공유한다. 그래서 여덟 판의 조각 순서가 같다 — 실력만 남는다.

{{N}}서버가 아니라 여기서

서버가 보낸 hole 은 쓰지 않는다코어의 pushRows 가 자기 난수로 구멍을 고르고, 관전 화면은 내가 보내는 스냅샷을 그대로 그린다. 그러니 어긋날 데가 없다 — hole 은 공격 연출용 정보다.

{{N}}두고 · 보고하고 · 올린다

이벤트 번호로 락을 감지하므로 같은 공격을 두 번 보내지 않는다(파트 10의 drain 과 같은 수법이다). 화면 상태는 초당 10회 — 규격 권장값이다.

{{N}}두 종류의 판

덱 데모의 화면에는 성격이 다른 판이 섞여 있다. 내 좌석은 내 프로세스가 굴리는 판이고, 남의 좌석은 스냅샷을 푼 결과다. 남의 판이 제대로 보인다는 건 런렝스·base64·스냅샷이 전부 맞는다는 뜻이다.

{{N}}페이지 안의 PC 넷

좌석 수는 PC 대수 × PC 당 좌석이다. 4×2 = 8석이 기본이고, 2×1 로 줄이면 1:1 이 된다 — 규격을 바꾸지 않고 숫자만 바꾼다.

{{N}}hi → create/join → seat → ready → start

1번 PC 만 방을 만들고 나머지는 그 코드로 들어간다. 좌석이 다 차면 방장이 start 를 누른다 — 사람이 로비에서 하는 일과 똑같은 순서다.

스냅샷을 푸는 건 1번 PC 시점뿐이다. 화면이 하나뿐이니 나머지 세 대는 받아서 버린다 — 진짜 8대라면 각자 자기 화면을 그린다.

{{N}}허브의 시계도 같이 민다

룸은 시계를 주입받는다(hitTTL 과 막타 판정이 그걸 본다). 데모에서는 프레임의 dt 를 그대로 밀어 준다 — 서버라면 Date.now() 가 들어갈 자리다.

{{N}}버퍼만 받는 격자

데이터가 어디서 왔는지는 그리는 쪽의 관심사가 아니다. 그래서 격자를 따로 뺐고, 덱 데모와 진짜 페이지가 같은 그림을 그린다.

{{N}}좌석 여덟을 격자로

고스트(오버레이 8~14)는 남의 화면에 그리지 않는다. 내 판에서만 쓸모 있는 정보이고, 스냅샷에도 들어가지 않는다.

{{N}}make run 으로 여는 그 화면

덱 데모와 다른 점은 전송 계층 하나다. 여기서는 진짜 WebSocket 이 들어오고, 방 코드를 사람이 입력한다.

전송 계층을 주입받게 둔 값테스트가 루프백을 넣어 소켓 없이 이 페이지를 끝까지 돌려 본다 — 방 만들기, 좌석 잡기, 시작, 조각 놓기까지.

{{N}}버튼 여섯과 캔버스 하나

{{N}}여섯 가지만 다루면 된다

방 코드는 사람이 읽고 전화로 불러 줘야 하므로 로그 줄에 그대로 띄운다. 다른 기기에서 같은 주소로 들어와 코드로 참가를 누르면 같은 방이다.

{{N}}키는 사람이 앉았을 때만

사람 좌석이 없으면 키를 아예 건드리지 않는다(관전 모드). 있으면 방향키를 가져간다 — 덱과 달리 이 페이지에는 넘길 슬라이드가 없으니 자동 포커스로 충분하다.

{{N}}index.html 은 46줄이다

스크립트 순서가 곧 의존 순서다. 모듈이 아니라 평범한 스크립트라, make web 이 만든 번들을 순서대로 넣으면 그만이다(파트 3에서 본 그 번들이다).

{{N}}서버 + 브라우저를 함께 띄운다

루프백 데모는 전송 계층을 바꿔치기한 것이라 "소켓까지 포함해서 도는가"는 증명하지 못한다. 마지막 칸은 이 도구가 채운다.

{{N}}make page-check

$ make page-check
✔ 페이지 — 방 XP2P, 좌석 2석(내 몫 2), 조각 64개, 칠해진 픽셀 11386,
  콘솔 오류 0건 (PC 1대 = 2석 상한)

좌석이 2석인 게 정답이다. 규격상 한 PC 는 두 자리까지 쥔다 — 도구는 일부러 세 번 눌러 세 번째가 full 로 막히는 것까지 확인한다.

{{N}}슬라이드 한 줄이면 붙는다

파트 10의 arena 와 화면은 비슷하지만 속은 완전히 다르다. 저쪽은 판 여덟을 한 프로세스가 직접 굴렸고, 이쪽은 좌석·공격·탈락이 전부 메시지로 오간다.
