01쿠키란 무엇인가?

쿠키(Cookie)는 웹사이트가 여러분의 브라우저에 저장해 두는 아주 작은 메모지입니다. 이름표가 붙은 이름=값 형태의 짧은 글이고, 보통 한 개에 4KB(약 4096자) 이하입니다.

🏷️ 비유: 옷 보관소의 번호표 옷 보관소에 외투를 맡기면 번호표를 줍니다. 나중에 그 번호표만 내밀면 직원이 "아, 7번 손님이군요" 하고 알아봅니다. 쿠키가 바로 이 번호표예요. 서버는 여러분에게 번호표(쿠키)를 쥐여주고, 여러분의 브라우저는 다음에 그 사이트에 갈 때마다 자동으로 그 번호표를 다시 보여줍니다. 그래서 서버가 "다시 온 그 사람"임을 알아봅니다.

핵심 성질

  • 브라우저에 저장된다 — 서버가 아니라 여러분 컴퓨터(브라우저)에 보관됩니다.
  • 도메인마다 따로 관리된다 — naver.com의 쿠키와 google.com의 쿠키는 서로 못 봅니다.
  • 같은 사이트로 가는 모든 요청에 자동으로 따라붙는다 — 이미지·API 호출까지 전부.
  • 작고(≤4KB), 개수도 도메인당 수십 개로 제한된다.
  • 만료 시간을 줄 수 있다 — 안 주면 브라우저를 닫을 때 사라진다(세션 쿠키).

02왜 쿠키가 필요할까?

웹의 기본 프로토콜인 HTTP는 "기억상실증"이 있습니다. 요청 하나하나가 완전히 독립적이라, 서버는 방금 요청한 사람과 지금 요청한 사람이 같은 사람인지 기본적으로 알 수 없습니다. 이걸 "무상태(stateless)"라고 합니다.

🤔 쿠키가 없다면? 로그인을 해도 다음 페이지로 넘어가는 순간 서버는 여러분을 잊어버립니다. 장바구니에 담아도 새로고침하면 텅 비고, 다크모드로 바꿔도 페이지를 옮기면 다시 밝아집니다. 매 클릭마다 다시 로그인해야 하는 웹을 상상해 보세요. 😱

쿠키는 이 무상태 HTTP 위에 "기억"을 얹는 가장 오래되고 보편적인 방법입니다. 대표적인 쓰임새:

  • 로그인 세션 유지 — "이 사람은 로그인한 7번 사용자" (가장 중요한 용도)
  • 장바구니 / 임시 선택 기억
  • 환경설정 — 언어, 다크모드, 글자 크기
  • 방문 분석 / 광고 — 며칠 만에 다시 온 방문자인지 식별

03기본: 만들고 · 읽고 · 지우기

브라우저의 자바스크립트에서 쿠키를 다루는 통로는 딱 하나, document.cookie 입니다. 그런데 이게 좀 특이하게 생겼습니다. 하나씩 보겠습니다.

🍪 쿠키 만들기 (쓰기)

document.cookie에 "이름=값" 문자열을 대입하면 쿠키 하나가 생기거나 갱신됩니다.

javascript
// "user=홍길동" 쿠키를 만든다 (한글 값은 인코딩 권장)
document.cookie = "user=" + encodeURIComponent("홍길동");

// 여러 개를 만들려면? 한 줄에 하나씩, 여러 번 대입한다.
document.cookie = "theme=dark";
document.cookie = "lang=ko";
⚠️ 가장 헷갈리는 함정 document.cookie = "theme=dark" 는 기존 쿠키를 덮어쓰지 않습니다. 변수에 값을 넣는 것처럼 보이지만, 실제로는 "이 쿠키 하나를 추가/갱신해줘"라는 명령입니다. 그래서 lang=ko를 또 대입해도 theme는 그대로 남아 있어요.

📖 쿠키 읽기

document.cookie를 그냥 읽으면 모든 쿠키가 "; "로 이어진 한 줄 문자열로 나옵니다.

javascript
console.log(document.cookie);
// → "user=%ED%99%8D%EA%B8%B8%EB%8F%99; theme=dark; lang=ko"

// 특정 쿠키 하나만 꺼내는 도우미 함수
function getCookie(name){
  const hit = document.cookie
    .split("; ")
    .find(row => row.startsWith(name + "="));
  return hit ? decodeURIComponent(hit.slice(name.length + 1)) : null;
}
getCookie("theme"); // → "dark"

읽을 때는 만료·Path 같은 속성은 보이지 않고 이름=값만 나옵니다. 그래서 "이 쿠키 언제 만료돼?"는 JS로 알 수 없어요.

🗑️ 쿠키 지우기

"삭제" 명령은 따로 없습니다. 과거의 만료일을 주면 브라우저가 알아서 버립니다.

javascript
// 만료일을 과거로 → 즉시 삭제됨. (만들 때와 같은 path를 줘야 확실히 지워짐)
document.cookie = "theme=; max-age=0; path=/";

05만료 시간 — 세션 쿠키 vs 영구 쿠키

쿠키의 수명은 만료 속성으로 정합니다. 두 가지 방법이 있어요.

속성의미예시
max-age지금부터 N초 뒤 만료 (요즘 권장)max-age=3600 → 1시간
expires특정 날짜/시각에 만료 (UTC 문자열)expires=Fri, 31 Dec 2027 23:59:59 GMT
(둘 다 없음)세션 쿠키 — 브라우저 닫으면 삭제document.cookie="x=1"
🕐 세션 쿠키 vs 영구(Persistent) 쿠키 세션 쿠키는 만료를 안 준 쿠키로, 브라우저를 닫으면 사라집니다 (탭이 아니라 브라우저 전체). 만료를 주면 영구 쿠키가 되어 디스크에 저장되고, 브라우저를 껐다 켜도 만료 전까지 살아남습니다. 로그인 "이 기기에서 로그인 유지"가 바로 영구 쿠키예요.
javascript
// 1) 세션 쿠키 — 브라우저 닫으면 사라짐
document.cookie = "cart=temp";

// 2) max-age로 7일짜리 영구 쿠키
document.cookie = "login=keep; max-age=" + (60 * 60 * 24 * 7);

// 3) expires로 특정 날짜까지
const d = new Date();
d.setFullYear(d.getFullYear() + 1);
document.cookie = "promo=seen; expires=" + d.toUTCString();

07중요한 속성들 — Path · Secure · SameSite · HttpOnly

쿠키는 이름=값 뒤에 ; 속성을 붙여 동작과 보안을 제어합니다. 실무에서 꼭 알아야 할 것들입니다.

속성하는 일예시 / 권장
Path 이 쿠키가 따라붙을 URL 경로 범위. path=/면 사이트 전체. path=/ (대부분 이걸 씀)
Domain 쿠키가 유효한 도메인. 지정하면 서브도메인까지 공유. domain=.example.com
Secure HTTPS 연결에서만 전송. 도청 방지. 로그인·민감 쿠키엔 필수
HttpOnly 자바스크립트가 못 읽게 막음 (document.cookie에 안 보임). XSS로 세션 탈취 방지. 서버만 설정 가능 · 세션 쿠키엔 필수
SameSite 다른 사이트에서 온 요청에 쿠키를 붙일지. CSRF 방어의 핵심. SameSite=Lax (기본 권장)
🔒 HttpOnly는 JS로 만들 수 없다 HttpOnly 쿠키는 오직 서버가 응답 헤더로만 설정할 수 있고, document.cookie로는 읽지도 만들지도 못합니다. 이게 핵심이에요 — 진짜 로그인 세션 쿠키는 JS에서 아예 보이지 않아야 악성 스크립트(XSS)가 훔쳐갈 수 없습니다. "쿠키를 JS로 읽어서 로그인 체크"하는 설계는 보안상 나쁜 패턴입니다.

SameSite 3가지 값

  • Strict — 다른 사이트에서 넘어온 요청엔 쿠키를 절대 안 붙임. 가장 안전하지만, 외부 링크로 들어오면 로그아웃처럼 보임.
  • Lax (현대 브라우저 기본값) — 평범한 링크 클릭(GET)엔 붙이고, 외부 사이트의 폼 전송(POST)·iframe엔 안 붙임. 균형점.
  • None — 어디서든 붙임. 단, 반드시 Secure와 함께여야 함. (외부 임베드·결제 위젯 등)
javascript — 클라이언트에서 줄 수 있는 속성 조합
document.cookie =
  "pref=ko" +
  "; max-age=" + (60*60*24*30) +   // 30일
  "; path=/" +                       // 사이트 전체
  "; SameSite=Lax" +                  // CSRF 완화
  "; Secure";                         // HTTPS에서만 (https 페이지일 때)

08서버는 쿠키를 어떻게 다룰까?

실무에서 로그인 쿠키는 거의 서버가 만듭니다. 흐름은 이렇습니다.

1
로그인 요청 — 브라우저가 아이디/비밀번호를 서버로 보냄
2
서버가 쿠키를 발급 — 응답에 Set-Cookie 헤더를 담아 보냄
3
브라우저가 저장 — 받은 쿠키를 자동으로 보관
4
이후 모든 요청 — 브라우저가 Cookie 헤더로 자동 첨부
5
서버가 알아봄 — "아, 7번 세션이네" 하고 로그인 상태로 처리
http — 서버 → 브라우저 (응답)
HTTP/1.1 200 OK
Set-Cookie: sessionId=a1b2c3d4e5; Max-Age=86400; Path=/; HttpOnly; Secure; SameSite=Lax
http — 브라우저 → 서버 (다음 요청마다 자동)
GET /my-page HTTP/1.1
Host: example.com
Cookie: sessionId=a1b2c3d4e5
node.js (express) — 서버에서 쿠키 발급 예
app.post("/login", (req, res) => {
  // ...비밀번호 확인 통과...
  res.cookie("sessionId", sessionId, {
    maxAge: 86400000,   // 1일 (밀리초)
    httpOnly: true,     // JS 접근 차단
    secure:   true,     // HTTPS에서만
    sameSite: "lax"
  });
  res.json({ ok: true });
});

즉, 설정 = 서버의 Set-Cookie 응답 헤더, 전송 = 브라우저의 Cookie 요청 헤더. JS의 document.cookie는 이 둘 중 클라이언트 쪽을 직접 만지는 도구일 뿐입니다.

09쿠키 vs localStorage vs sessionStorage

"브라우저에 값 저장"이 목적이라면 요즘은 선택지가 더 있습니다. 언제 무엇을 쓸지 정리합니다.

🍪 CookielocalStoragesessionStorage
용량~4KB~5–10MB~5MB
서버로 자동 전송예 (매 요청)아니오아니오
수명만료 지정 가능지울 때까지 영구탭 닫으면 삭제
JS 접근가능 (HttpOnly 제외)가능가능
주 용도인증/세션설정·캐시일회성 폼 데이터
🎯 고르는 기준 서버가 알아야 하는 정보(로그인 세션)는 쿠키. 서버는 몰라도 되고 브라우저에만 두면 되는 큰 설정/캐시는 localStorage. 매 요청에 따라붙는 쿠키에 큰 데이터를 넣으면 모든 요청이 무거워지니 주의하세요.

10주의사항 & 치트시트

  • 민감 정보를 값에 직접 넣지 말 것 — 비밀번호·주민번호 ❌. 쿠키는 사용자가 열어볼 수 있습니다.
  • 세션 쿠키엔 HttpOnly+Secure+SameSite를 반드시.
  • 한글·특수문자는 encodeURIComponent로 감싸기 (쿠키 값에 ; , 공백 금지).
  • 삭제할 땐 만들 때와 같은 path(와 domain)를 줘야 지워집니다.
  • 개수·용량 제한을 의식하기 — 큰 데이터는 localStorage나 서버 DB로.
  • EU·국내 쿠키 동의 — 분석/광고 쿠키는 법적으로 사용자 동의가 필요할 수 있습니다.
javascript — 복붙용 쿠키 도우미 3종
function setCookie(name, value, days){
  const maxAge = days ? "; max-age=" + (days*86400) : "";
  document.cookie = name + "=" + encodeURIComponent(value)
                  + maxAge + "; path=/; SameSite=Lax";
}
function getCookie(name){
  const hit = document.cookie.split("; ")
    .find(r => r.startsWith(name + "="));
  return hit ? decodeURIComponent(hit.slice(name.length+1)) : null;
}
function deleteCookie(name){
  document.cookie = name + "=; max-age=0; path=/";
}
