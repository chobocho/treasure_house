메뉴 — 화면을 바꿔 끼운다

Bubble Tea 에서 화면을 바꾸는 방법이 이 파일의 요점이다. 창을 새로 띄우지 않는다. Update 가 자기 자신이 아니라 다른 모델을 돌려주면, 그 순간부터 프로그램은 그 모델을 쓴다. 화면 전환이 곧 값의 교체다.

메뉴 항목과 조립

깃발(-mode)로 들어오든 메뉴에서 고르든 Build 를 지난다. 두 길이 갈라지면 "메뉴로 들어갈 때만 나는 버그"가 생긴다.

테스트가 이걸 지킨다 — 메뉴에 보이는 모든 항목이 실제로 만들어지는지, 그리고 항목 수와 이름 수가 같은지.

메뉴 조작

숫자 키로 바로 고르는 것도 넣었다 — 메뉴에 번호를 적어 뒀으니 눌리면 먹어야 한다. 적어 놓고 안 되는 것만큼 나쁜 것이 없다.

바꿔 낄 때 잊기 쉬운 두 가지

① 새 화면에 창 크기를 알려 줘야 한다 안 알려 주면 첫 프레임이 "창 크기를 기다리는 중"으로 뜨고, 다음 크기 변화가 올 때까지 그대로 있는다. 사용자는 창을 흔들어야 한다.
② 새 화면의 Init 을 직접 불러야 한다 Bubble Tea 는 프로그램이 시작할 때 한 번만 Init 을 부른다. 바꿔 낀 모델의 첫 틱은 우리가 예약해 줘야 한다. 이걸 빠뜨리면 게임에 들어갔는데 시간이 안 흐른다.

둘 다 테스트로 못 박았다 — Enter 를 눌렀을 때 돌아온 cmd 가 nil 이 아닌지.

메뉴 — 실제 화면

설치해서 쓰기

# 이 저장소를 받아서
$ cd tetris_tui
$ go build -o tetris ./cmd/tetris
$ ./tetris

# 또는 GOPATH/bin 에 설치
$ go install ./cmd/tetris
$ tetris -mode ai -level max

결과물은 단일 실행 파일이다. 가중치가 //go:embed 로 박혀 있어서 옆에 둘 파일이 없다.

다른 기계로GOOS=linux GOARCH=amd64 go build ./cmd/tetris
맥으로GOOS=darwin GOARCH=arm64 go build ./cmd/tetris
윈도로GOOS=windows GOARCH=amd64 go build ./cmd/tetris

Go 의 교차 컴파일은 C 라이브러리를 안 쓰면 이렇게 한 줄이다. 이 프로젝트는 cgo 를 안 쓴다.

다른 운영체제에서

macOSTerminal.app 은 24비트 색을 안 낸다(256색까지). Bubble Tea 가 알아서 낮춰 주므로 색만 조금 거칠어진다. iTerm2 를 쓰면 그대로 나온다
WindowsWindows Terminal 은 잘 된다. 옛 conhost 는 24비트 색과 일부 유니코드가 약하다. WSL 안에서 돌리는 편이 안전하다
Linux대부분 문제없다. TERM 이 dumb 면 색이 전부 빠진다 — 그래도 판은 보인다
모바일(Termux)이 덱을 만든 환경이다. 화면이 좁으면 "터미널을 키워 주세요"가 뜬다 — 가로로 돌리면 대개 들어간다
블록 문자 폭 █ 와 ░ 는 유니코드 상 "동아시아 애매" 폭이다. CJK 로케일에서 두 칸으로 그리는 터미널이 있다면 판이 두 배로 늘어난다. 실제로 겪은 적은 없지만, 겪는다면 ui/style.go 의 세 상수를 ASCII 로 바꾸는 것이 가장 빠른 해결이다.

더 해 볼 것 ① — bubbles 컴포넌트

같은 팀이 만든 charm.land/bubbles/v2 에는 이미 만들어진 부품이 있다.

list필터·페이지가 되는 목록. 메뉴를 이걸로 바꿔 볼 수 있다
viewport스크롤되는 영역. 긴 도움말이나 리플레이 로그에
textinput한 줄 입력. 시드를 직접 넣게 한다면
help키맵에서 도움말을 만들어 준다 — 우리가 손으로 한 그것
spinner · progress기다리는 동안
이 프로젝트는 안 썼다 의존성을 둘로 줄이고, 모든 코드를 이 덱 안에 싣기 위해서다. help 컴포넌트를 썼다면 ui/keys.go 의 절반이 없어졌을 것이다 — 그리고 그 절반이 이 덱에서 가르치려던 것이었다.

더 해 볼 것 ② — 게임 쪽

  1. 리플레이 — 기록 도구가 이미 절반을 해 놨다. 키와 틱을 파일로 남기고 다시 먹이면 그대로 재생된다. 결정론이 이미 보장되어 있다
  2. 2수 탐색 — 다음 조각을 알고 있으니 후보를 두 겹으로 펼칠 수 있다. 후보가 1만 개로 늘어나므로 가지치기가 필요해진다
  3. T스핀 노리는 AI — 도달 가능성 검사를 넓혀야 한다. "회전으로만 들어갈 수 있는 자리"를 후보에 넣는 것부터
  4. 마우스 — Bubble Tea v2 는 마우스 메시지도 준다. View.MouseMode 를 켜면 클릭으로 조각을 옮길 수 있다
  5. 색맹 배색 — 조각 색을 바꿔 끼울 수 있게 하면 된다. ui/style.go 의 배열 하나가 전부다

더 해 볼 것 ③ — 네트워크 대전

같은 저장소에 TypeScript 로 만든 8인 온라인 대전편이 있다. 거기서 다룬 것을 이 코드 위에 얹으면 그대로 된다.

이미 되어 있는 것

  • 규칙이 화면과 분리됨
  • 공격이 숫자 하나로 표현됨
  • 같은 시드 = 같은 조각
  • 모델이 값이라 상태 직렬화가 쉽다

더 필요한 것

  • 프로토콜(입장·시작·공격·이탈)
  • 지연 보정 — 공격이 늦게 도착하면?
  • 서버 권위 대 클라이언트 예측
  • 끊긴 상대 처리

Bubble Tea 쪽 준비는 이미 끝나 있다 — 소켓에서 온 메시지도 그냥 tea.Msg 하나다. Cmd 안에서 읽어서 돌려주면 된다.

대신 배워야 했던 것은 사고방식이다 — 상태를 한 곳에 두고, 사건을 메시지로 받고, 오래 걸리는 일을 밖으로 내보내는 것. 그게 이 덱의 절반이었다.

돌아보기 ② — 실제로 밟은 함정

2부모델을 안 돌려주면 화면이 안 변한다 (오류 없음)
2부tea.Tick 은 한 번만 보낸다 — 재예약을 잊으면 시계가 죽는다
3부lipgloss 의 Width 는 테두리를 포함한다
4부ClearLines 의 y++ — 테트리스가 두 줄만 지워진다
5부좌우를 안 놓으면 조각이 혼자 벽까지 간다 (DAS)
5부도움말이 창보다 길면 판의 윗줄이 잘려 나간다
5부제목이 길면 테두리에서 통째로 사라진다
6부FMA — float32(w*f) 없이는 1 ULP 가 어긋난다
7부모델은 값이지만 *core.Game 은 공유된다
7부락 이벤트 번호를 안 보면 같은 공격이 매 프레임 배달된다
8부기록기가 Cmd 를 안 돌리면 기록 속 AI 가 가만히 서 있다

전부 이 프로젝트를 만들면서 실제로 겪은 것이고, 대부분 테스트로 못 박아 두었다.

돌아보기 ③ — 무엇으로 증명했나

골든 트레이스

C++ 판과 9,000스텝 + 1,960경우 + 36라운드 + AI 1,421경우 + 실전 56판. 내가 생각 못 한 경우까지 잡는다.

구조 단위 테스트

"표가 표답게 생겼는가" — 킥 표의 대칭, 키 충돌, 글자 폭. 트레이스가 안 밟는 구석을 메운다.

변이 테스트

일부러 망가뜨려 보고 잡히는지 확인. 두 종류가 서로를 메운다는 것을 이걸로 알았다.

실제 실행

tmux 로 진짜 PTY 에서 다섯 화면. 기록으로 네 모드. 둘 다 필요하다 — 기록은 모델을, tmux 는 프로그램을 증명한다.

이 프로젝트가 못 하는 것 — 정직하게

키를 뗀 것모른다. 소프트드롭은 타임아웃으로 지어낸 것이고, 좌우는 OS 자동반복에 기댄다
동시 입력없다. 2인용에서 두 사람의 키가 순서대로 들어온다
AI 의 시야1수. T스핀도, 끼워 넣기도, 상대 판도 안 본다
레이스 검출이 기계에서 -race 를 못 돌렸다. 설계와 테스트로 대신했다
블록 문자 폭"동아시아 애매" 폭이라 이론상 두 칸이 될 수 있다. 테스트로 전제를 못 박고 넘어갔다
Kitty 프로토콜안 쓴다. 쓰면 나아지지만 "어떤 터미널에서만 되는 게임"이 된다

이 목록을 적는 이유가 있다. 안 적으면 읽는 사람이 스스로 발견해야 하고, 그때는 이미 시간을 쓴 뒤다.
