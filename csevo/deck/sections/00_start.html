왜 C# 을 역사로 읽는가

C# 의 공식 버전 기록에는 1.0 부터 14 까지 열여덟 개의 버전이 있습니다. 첫 버전은 자바를 많이 닮았지만, 지금의 C# 에는 제네릭, LINQ, async/await, 패턴, record, 확장 멤버가 차례로 쌓여 있습니다.

"요즘 C#" 만 배우면 그 층이 보이지 않습니다. 왜 var 와 익명 형식이 같은 버전에 들어왔는지, 왜 record 가 문맥 키워드인지는 생긴 순서를 따라가야 풀립니다. 이 덱은 버전 하나하나를 따라갑니다. 기능마다 같은 차례로 읽습니다 — 왜 생겼나 → 문법 → 실행 예제 → 함정 → 근거. 가장 최근의 세 버전(C# 12–14)은 1.5배의 분량으로 다룹니다.

공식 버전 기록의 첫 문장 — "C# version 1.0, released with Visual Studio .NET 2002, looked a lot like Java." 이 덱의 이야기는 거기서 시작해 C# 14 에서 끝납니다.

같은 리듬의 형제 덱: Go의 진화 · 파이썬의 진화 · 자바의 진화 · 모던 C++의 진화

문서 근거

심판은 둘 — 설치된 Roslyn 과 공식 문서

이 덱에서 "C# 은 이렇게 한다" 는 문장의 근거는 사람의 기억이 아닙니다.

무엇을누가 판정하나
돌려 볼 수 있는 것 — 문법, 출력, 컴파일 오류와 경고 이 기계에 설치된 .NET SDK. 캡처는 스크립트가 돌려 남긴 것이고, 세 번 돌려 바이트까지 같은 것만 씁니다
돌려 볼 수 없는 것 — 나온 달, "몇 버전에 들어왔나", 설계자의 말 받아 둔 공식 문서 — 버전 기록, 버전별 "What's new", csharplang 의 기능 명세, Roslyn 의 문서와 소스

버전 표기 하나하나는 빌드가 버전 표·컴파일러의 기능 게이트와 대조합니다. 기억으로 적은 버전은 빌드를 통과하지 못합니다.

실행 검증

"몇 버전에 들어왔나" — 컴파일러 자신의 답

Roslyn 은 언어 버전을 확인해야 하는 기능마다 "이 기능은 C# 몇부터" 를 소스 한 곳에 적어 둡니다. MessageID.cs 의 RequiredVersion() 입니다. 이 덱은 그 파일을 설치된 SDK 와 같은 커밋에서 받아 기능 183개의 버전을 표로 뽑았습니다.

C# 1.0 의 한 줄은 특이한 경우입니다. 소스 주석이 "Special C# 2 feature: only a warning in C# 1" 이라고 적은 특성 위치 지정자(module:)입니다.

실행 검증

게이트가 적은 버전 — C# 1.2 와 5.0

표를 다시 보면 C# 1.2 는 0, C# 5.0 은 1 입니다. 이 두 버전의 변화는 대부분 문법이 아니라 의미의 변화라, 컴파일러가 버전을 따져 거절할 거리가 없습니다. C# 1.2 의 변화는 foreach 가 열거자의 Dispose 를 부르게 된 것이고, C# 5.0 의 노력은 거의 전부 async 와 await 에 들어갔습니다.

그런 버전에서는 아래의 다른 증거 방식을 씁니다. 어느 방식을 썼는지는 장마다 밝힙니다.

문서 근거

옛 컴파일러 없이 '전과 후' 를 보이는 법

이 기계에는 Roslyn 5 하나뿐입니다. 그래서 옛 출력을 흉내 내지 않고, 지금의 컴파일러와 런타임이 스스로 보여 주는 것만 씁니다.

꼴어떻게무엇이 증거인가
(가) 언어 버전 짝같은 소스를 -langversion 만 바꿔 컴파일 "Feature 'X' is not available in C# N" 같은 컴파일러의 거절
(나) 버전에 묶인 동작컴파일러가 언어 버전에 따라 다르게 번역하는 것만 골라 두 번 두 실행의 출력 차이. 묶여 있지 않으면 옛 동작을 풀어 쓴 코드로 보이고 그렇다고 밝힙니다
(다) 런타임의 사실.NET 10 런타임에서 돌린 결과 "이 런타임은 이렇게 한다" 까지만. 역사는 문서 배지로
(라) 바뀐 문법옛 꼴을 그대로 지금 컴파일 지금 컴파일러의 오류·경고

넷 중 어느 것으로도 보일 수 없으면 "C# 14 / .NET 10 에서의 동작" 이라고 밝혀 지금의 동작만 보입니다.

설명용

꼴 (가) — 같은 소스, 언어 버전만 다르게

컬렉션 식([1, 2, 3])은 C# 12 의 문법입니다. 같은 파일을 두 번 컴파일합니다.

거절 문장이 기능의 이름('collection expressions')과 필요한 버전(12.0)까지 알려 줍니다. 기능 이름은 컴파일러의 자원 파일에 적힌 그대로이고, 이 덱의 게이트 표도 같은 이름을 씁니다.

실행 검증

언어 버전을 내려도 런타임은 그대로

-langversion 은 컴파일러가 받아들이는 문법만 바꿉니다. 라이브러리와 런타임은 여전히 .NET 10 입니다. C# 1 문법만 쓴 프로그램이 그것을 스스로 찍습니다.

그래서 조심할 것 — 이 덱의 캡처는 "C# 1 컴파일러의 출력" 이 아닙니다. "지금의 컴파일러가 C# 1 의 규칙으로 컴파일한 프로그램을 .NET 10 에서 돌린 출력" 입니다. 옛 .NET Framework 에서의 결과가 다를 수 있는 곳은 장마다 밝힙니다.
실행 검증

csrun — MSBuild 없이 컴파일하고 돌리기

예제는 ex.csproj 를 가진 진짜 프로젝트라 dotnet run 으로도 돌아갑니다. 이 덱의 캡처는 더 가벼운 길로 떴습니다 — Roslyn 의 csc.dll 을 직접 부르고 dotnet exec 로 실행하는 스크립트 하나입니다.

-pathmap 은 예외 스택 트레이스의 파일 경로를 /work 로 고정합니다. -deterministic 은 같은 입력에서 같은 어셈블리를 냅니다.

실행 검증

캡처에서 지운 것

캡처가 그 실행의 우연에 기대면 세 번 돌렸을 때 달라집니다. 달라지는 조각만 지우고, 지운 것은 여기 전부 밝힙니다.

예제는 처음부터 흔들리는 값을 찍지 않습니다 — 시각, Stopwatch, GUID, 스레드 번호, 문자열의 GetHashCode()(프로세스마다 씨앗이 다릅니다).

이 덱을 읽는 법

  • 1부는 C# 이 나오기 전의 이야기입니다.
  • 2부부터 15부까지가 버전 순서의 본문입니다. 버전마다 첫 장은 개관 장입니다 — 개관 장만 넘겨도 전체 흐름이 보입니다.
  • 13부–15부(C# 12–14)가 이 덱의 주인공입니다.
  • 16부는 같은 이야기를 갈래(언어·런타임·컴파일러·라이브러리)별로 다시 엮고, 다음 버전에서 진행 중인 제안을 짧게 봅니다.
  • 코드 블록 위 회색 줄은 어느 파일 몇 번째 줄인지를 말합니다. 옮겨 적은 코드가 아닙니다.
  • 어두운 블록은 진짜로 돌린 출력이고 첫 줄이 그 명령입니다. 이름표의 "C# N" 은 그때의 언어 버전입니다.
  • 단원(1장·2장 …)이 끝날 때마다 퀴즈가 하나씩 있습니다. 답은 단추를 누르면 펼쳐집니다.

이 덱이 아닌 것

이 덱은 역사와 "무엇이 바뀌었나" 를 다룹니다. C# 문법을 처음부터 가르치는 교재가 아니고, .NET 라이브러리를 둘러보는 안내서도 아닙니다. 기능은 바뀐 점을 보일 만큼만 가르칩니다.

라이브러리와 런타임은 언어 기능이 그것에 기대는 곳에서만 나옵니다 — async 와 Task, LINQ 와 System.Linq, Span 과 ref struct, 제네릭 수학과 INumber, 컬렉션 식과 컬렉션 빌더. 버전마다 "같이 온 런타임" 장이 하나씩 그 둘레를 짧게 봅니다.

언어 진화를 나란히 읽고 싶다면: 자바의 진화(C# 이 처음 닮았던 언어) · Go의 진화 · 파이썬의 진화
