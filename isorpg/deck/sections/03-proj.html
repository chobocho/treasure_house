3차원에서 시작하기

쿼터뷰 화면은 3차원 공간을 평면에 눌러 놓은 것입니다. 눌러 놓는 방법을 정하면 나머지는 전부 따라옵니다.

지면 위의 점 (X, Y, Z) 를 생각합시다. X 는 동쪽, Y 는 남쪽, Z 는 위쪽입니다. 카메라를 남동쪽 위에서 내려다보게 두면, 화면 좌표는 두 번의 회전으로 얻어집니다.

  1. 수직축 회전 45° — X 축과 Y 축이 화면에서 좌우 대칭이 되도록 돌립니다.
  2. 수평축 회전 φ — 위에서 내려다보도록 기울입니다. 등각이면 φ = arctan(1/√2) = 35.264°.
  3. Z 축 방향으로 정사영 — 깊이를 버리고 평면에 찍습니다.

두 회전을 합치면 화면 좌표는

sx = (X - Y) · cos 45°
sy = (X + Y) · cos 45° · sin φ  -  Z · cos φ

가 됩니다. 여기서 결정적인 관찰: 상수 cos 45° 와 cos 45°·sin φ 는 그저 가로·세로 축척일 뿐입니다. 게임은 이 둘을 각도로 정하지 않고 픽셀 수로 정합니다.

가로 축척을 TW/2 = 16, 세로 축척을 TH/2 = 8 로 고정하면 각도는 자동으로 정해집니다. 그리고 그 각도가 arctan(8/16) = arctan(1/2) = 26.565° 입니다. 도스 게임이 한 것이 바로 이것입니다 — 각도를 고르고 픽셀을 계산한 것이 아니라, 픽셀을 고르고 각도를 받아들였습니다.

정의 3.1 — 타일에서 화면으로

타일 (tx, ty) 의 마름모는 꼭대기 꼭짓점이 월드 픽셀

Vx(tx, ty) = (tx - ty) · TW/2 = 16 · (tx - ty)
Vy(tx, ty) = (tx + ty) · TH/2 =  8 · (tx + ty)

에 놓입니다. 높이 h 인 타일은 화면에서 h · TZ = 8h 픽셀만큼 위로 올라갑니다.

기준점을 마름모 중심이 아니라 꼭대기 꼭짓점으로 잡은 것은 편의가 아니라 필요입니다. 스프라이트를 그릴 때 왼쪽 위 모서리를 계산해야 하고, 꼭짓점 기준이면 그 계산에 상수가 하나도 안 들어갑니다.

중심이 필요할 때는 (Vx, Vy + 8) 입니다. 마름모의 세로 지름이 16 이니 반이 8 이죠.

기저 벡터

타일 좌표를 1 늘리면 화면이 얼마나 움직이는가 — 그것이 기저 벡터입니다.

e_x = 투영(1, 0) - 투영(0, 0) = ( 16, 8)
e_y = 투영(0, 1) - 투영(0, 0) = (-16, 8)

두 축의 길이가 같습니다(√(16²+8²) = 8√5). 그런데 높이 축은 8 이라 다릅니다. 세 축이 균등하게 단축되지 않았으므로 등각이 아니라 다이메트릭입니다 — 등각이라면 세 축의 길이가 같고 사잇각이 모두 120°여야 합니다.

축화면 벡터길이
tx (+1)(16, 8)8√5 ≈ 17.89
ty (+1)(-16, 8)8√5 ≈ 17.89
h (+1)(0, -8)8

높이 축만 짧습니다. 이 비율(8 : 8√5)이 화면의 "입체감"을 정합니다. 높이 축을 더 길게 하면 산이 더 높아 보이고, 짧게 하면 평평해 보입니다.

정리 3.1 — 행렬식이 2의 거듭제곱이다

두 기저 벡터를 열로 세우면 투영 행렬이 나옵니다.

      | 16  -16 |
  M = |  8    8 |          det M = 16·8 - (-16)·8 = 128 + 128 = 256 = 2^8

           1  |  8   16 |
  M^-1 = ---- | -8   16 |
          256 |         |

정리. M = [[w, -w], [h, h]](w = TW/2, h = TH/2) 에 대해, M^-1 · det M 의 성분이 전부 2의 거듭제곱일 필요충분조건은 w 와 h 가 각각 2의 거듭제곱인 것이다.

증명. det M = 2wh 이고 M^-1 · det M = [[h, w], [-h, w]] 입니다. 성분이 ±h 와 w 뿐이므로, 전부 2의 거듭제곱인 것과 w, h 가 각각 2의 거듭제곱인 것이 같은 말입니다. ∎

이 정리는 2:1 을 요구하지 않습니다. TW=64, TH=16(4:1)도 w=32, h=8 이라 조건을 만족합니다. 거꾸로 TW=48, TH=24 는 2:1 인데도 h=12 라 만족하지 않습니다 — 이 부 끝의 확인 문제 2 가 그 경우입니다. 2:1 은 이 정리에서 나오는 것이 아니라 2부의 픽셀 격자 이유에서 나옵니다. 이 정리가 말하는 것은 "그렇게 고른 뒤에도 산술이 공짜인가"입니다.
둘을 합치면 32×16 이 됩니다. 2부가 비율 2:1 을 정하고, 이 정리가 w=16, h=8 처럼 둘 다 2의 거듭제곱인 크기를 고르게 합니다. 30° 등각을 쓰면 w/h = √3 이라 애초에 정수로 맞출 수 없습니다.

다이아몬드 배치 vs 지그재그 배치

같은 마름모 타일이라도 저장 방식은 두 가지입니다.

다이아몬드 (이 문서)

배열 인덱스 (tx, ty) 를 그대로 투영합니다. 맵 전체가 화면에서 마름모 모양이 됩니다.

sx = 16(tx - ty)
sy =  8(tx + ty)

장점: 수식이 대칭이고 역행렬이 깔끔
단점: 직사각 화면에 마름모 맵 — 귀퉁이가 빈다

지그재그 (staggered)

홀수 행을 반 칸 밀어 저장합니다. 맵이 화면에서 직사각형이 됩니다.

sx = 32·tx + (ty odd ? 16 : 0)
sy =  8·ty

장점: 화면을 꽉 채운다
단점: 이웃 계산에 홀짝 분기가 붙는다

다이아몬드지그재그
이웃 (동)(tx+1, ty)(tx+1, ty)
이웃 (남동)(tx+1, ty+1)홀짝에 따라 다름
역투영나눗셈 두 번나눗셈 + 홀짝 보정
맵 모양마름모직사각
이 문서는 다이아몬드를 씁니다. 수식이 대칭이라 증명이 짧고, 4부의 모서리 마스크가 네 값으로 떨어지기 때문입니다. 지그재그였다면 마스크가 홀짝 두 벌 필요합니다.

높이 항

높이는 세로 좌표에서 빼기만 하면 됩니다. sy - h·TZ. 이 단순함에는 대가가 있습니다.

높이 h 인 타일은 (tx − h/2, ty − h/2) 위치의 높이 0 타일과 화면상 같은 자리에 옵니다(h 가 짝수일 때). 왜냐하면

투영(tx, ty, h) = (16(tx-ty),  8(tx+ty) - 8h)
투영(tx-k, ty-k, 0) = (16(tx-ty),  8(tx+ty) - 16k)

h = 2k 일 때 정확히 같습니다. 즉 높이 2 는 대각선 한 칸 뒤와 구별되지 않습니다. 실제로 tile_to_screen(5,3,2) 와 tile_to_screen(4,2,0) 은 둘 다 (32, 48) 입니다. 이것이 쿼터뷰의 근본적 모호함이고, 게임들이 절벽 옆면에 그림자와 무늬를 넣어 구별시키는 이유입니다.

픽킹에서 이 모호함이 문제가 됩니다 — 마우스가 가리킨 픽셀이 "높이 0 의 먼 타일"인지 "높이 2 의 가까운 타일"인지 화면만으로는 알 수 없습니다. 4부에서는 높이를 무시한 지면 픽킹을 다루고, 진짜 높이 픽킹은 7부의 정렬 결과를 역으로 훑어야 합니다.

기둥 그리기 — 큐브 한 장으로 어떤 높이든

스프라이트를 높이마다 따로 만들 필요가 없습니다. 큐브 한 장(윗면 마름모 + 아래로 8픽셀 옆면)을 k = 1..h 에 차례로 올리면 됩니다. 아래부터 올리므로 마지막에 올린 윗면이 맨 위에 남고, 옆면은 8h 픽셀만큼 이어 붙습니다.

스프라이트 뱅크에는 지형 16종의 마름모 16장과 큐브 16장이 들어 있습니다. 합쳐 32장으로 높이 0..12 의 모든 지형을 그립니다.

마름모는 L1 단위공이다

타일 중심을 원점으로 두면, 마름모 내부는

|u| / 16  +  |v| / 8  ≤  1        ⟺        |u| + 2|v| ≤ 16

입니다. 이것은 L1 노름의 단위공을 u 축으로 두 배 늘인 것입니다. 유클리드 원이 L2 공이듯, 마름모는 L1 공입니다.

이 관찰이 4부 전체를 끌고 갑니다. L1 공은 좌표를 45° 돌리면 정사각형이 되기 때문입니다 — 그리고 정사각형 안에 있는지 확인하는 것은 나눗셈 두 번이면 끝납니다.

넓이 확인 — 마름모 넓이는 대각선 곱의 반, 즉 32 × 16 / 2 = 256 픽셀입니다. 4부에서 실제로 세어 보면 정확히 256개가 나옵니다.

타일 사이에 있을 때 — 16.16 좌표

캐릭터는 타일 격자에 딱 맞춰 서 있지 않습니다. 타일 단위 16.16 고정소수점 좌표를 갖습니다.

정수 투영과 형태가 같고 마지막에 65,536 으로 내림 나눗셈만 붙습니다. 범위 확인이 중요합니다 — |fx|, |fy| < 48 × 65536 < 2²² 이므로 (fx+fy)·8 < 2²⁶ 로, 배정밀도 가수 53비트 안에 넉넉히 들어갑니다.

왜 범위를 따지는가 — 루아 5.1 과 자바스크립트에서 정수는 배정밀도 실수입니다. 253 을 넘으면 조용히 틀린 값이 나옵니다. 이 문서의 모든 곱셈에는 이런 범위 계산이 붙어 있습니다. 5부에서 본격적으로 다룹니다.

직접 해 보기 — 투영 실험실

타일 좌표와 높이를 바꿔 보세요

TW 와 TH 를 바꿔 보면 행렬식이 어떻게 변하는지 볼 수 있습니다. TW/2 와 TH/2 가 둘 다 2의 거듭제곱일 때만 역행렬 성분이 깔끔하게 떨어집니다 — 2:1 이라도 48×24 는 그렇지 않습니다(정리 3.1).

확인 문제

타일 (10, 4) 의 높이가 3 이라면 화면 좌표는? (카메라 오프셋 0)

Vx = 16 × (10 - 4) = 96
Vy = 8 × (10 + 4) - 3 × 8 = 112 - 24 = 88
답은 (96, 88).

확인: 높이가 0 이면 (96, 112) 이고, 높이 3 이 24픽셀만큼 들어 올립니다.

확인 문제 2

타일 크기를 TW=48, TH=24 로 바꾸면 행렬식은? 그리고 여전히 시프트만으로 역투영할 수 있는가?

w = 24, h = 12 이므로 det = 2wh = 576.

576 = 26 × 32 이라 2의 거듭제곱이 아닙니다. 역행렬 성분이 12/576 = 1/48, 24/576 = 1/24 이 되어 3 으로 나누는 연산이 필요합니다.

비율 2:1 은 지켜지므로 화면 각도는 그대로 26.565° 입니다. 하지만 산술은 더 이상 공짜가 아닙니다. 이것이 도스 게임의 타일 크기가 거의 언제나 32×16 이나 64×32 였던 이유입니다 — 둘 다 det = 28, 210 입니다.
