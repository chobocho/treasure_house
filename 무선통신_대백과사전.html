왜 무선인가

전선 없이 소식을 보내는 일은 마법이 아니다. 있는 것은 전자기파에 뜻을 실어 보내고, 잡음 속에서 그것을 되찾는 방법뿐이다. 그런데 "되찾을 수 있는 양" 에는 넘을 수 없는 벽이 있고, 벽이 어디인지는 식 한 줄로 정해진다.

휴대전화가 왜 셀(cell)로 쪼개져 있는지, CDMA 가 왜 모두가 동시에 떠들어도 되는지, LTE 가 왜 부반송파를 수천 개 쓰는지 — 전부 같은 이야기의 다른 장면이다. 남이 정리해 준 표를 외우는 대신 식을 세우고 코드로 확인하면 그 장면들이 하나로 이어진다.

이 덱의 약속 — 여기 실린 코드는 전부 실제로 돌아간다. 의사코드는 한 줄도 없다. 화면에 보이는 숫자는 전부 이 기계에서 진짜로 계산한 것이고, 규격을 인용한 자리에는 문서 번호와 조항이 배지로 붙어 있다.

이 덱이 다른 무선 교재와 다른 점

무선통신 책은 둘 중 하나로 갈린다. 식은 있는데 돌려 볼 수 없거나, 표는 많은데 그 표가 어디서 왔는지 알 수 없거나. 이 덱은 그 사이를 메우려고 한다.

흔한 방식이 덱
식을 적고 "이렇게 된다" 고 한다 같은 식을 파이썬으로 옮기고, 몬테카를로가 이론값에 맞는지를 시험으로 박아 둔다
규격 값을 표로 옮겨 적는다 규격 번호와 조항을 배지로 달고, 조항 제목이 진짜 원문에 있는지 빌드가 검사한다
세대별 특징을 나열한다 왜 그 선택을 했는지를 앞 세대의 한계에서 끌어낸다
사진을 아무 데서나 가져온다 자유 라이선스만 싣고 출처 줄을 기계가 붙인다. 없으면 그림을 그린다

이 책을 읽는 법

한 장에 한 가지만 담았다. 모르는 낱말이 나오면 15부 용어집을 보라 — 낱말마다 "처음 나온 자리" 로 가는 화살표가 붙어 있다.

  • 순서대로 읽는 것이 가장 빠르다. 뒤 장은 앞 장에서 세운 식을 그대로 쓴다.
  • 2·3·4부가 이 책의 수학 뼈대다. 세대 이야기(5부부터)는 그 뼈대를 계속 되부른다.
  • 코드 블록 위의 회색 줄은 어느 파일 몇 번째 줄인지를 말한다. 옮겨 적은 코드가 아니다.
  • 어두운 바탕의 블록은 실제로 돌린 출력이다. 사람이 꾸민 숫자가 아니다.
  • 동그란 배지(예: TS 38.211 §4.2)는 그 문장의 근거가 되는 규격 문서와 조항이다.
  • 장마다 오른쪽 아래에 근거 등급 배지가 있다 — 실행 검증 · 규격 근거 · 역사 근거 · 설명용.
  • 부마다 열다섯 장쯤에 퀴즈가 한 장씩 나온다. 답은 단추를 누르면 펼쳐진다.
  • 이 문서는 자기완결형이다 — 외부 스크립트·글꼴·이미지를 하나도 안 부른다. 내려받아 두면 인터넷 없이도 그대로 열린다.

수식은 이렇게 조판했다

이 덱은 수식 라이브러리를 부르지 않는다. 파일 하나로 열려야 하기 때문이다. 분수·큰 연산자·근호·경우 나눔은 전부 CSS 로 짰다. 좁은 화면에서는 식 블록만 가로로 밀린다.

정의 — 유도 상자 정의·정리·증명은 이렇게 색이 다른 상자에 들어간다. 정의는 초록, 정리는 보라, 증명은 회색이고 끝에 ∎ 가 붙는다.
정리 (섀넌–하틀리) 대역폭 B, 신호 대 잡음비 γ 인 AWGN 채널의 용량은
C = B log2(1 + γ)
이다. 2부에서 유도하고, py/wirelesslib/info.py 로 확인한다.

한국이라는 실 한 가닥

이 덱은 세대를 따라가지만, 그 사이에 한국 이야기를 실처럼 꿰어 둔다. 따로 떼어 한 부로 만들지 않은 것은, 그 이야기들이 각자의 세대 안에서만 뜻이 통하기 때문이다.

  • 7부 — CDMA 세계 최초 상용화. 왜 하필 아무도 안 하던 방식을 골랐는가.
  • 10부 — 와이브로와 WiMAX 의 패배. 기술이 좋으면 이기는 것이 아니다.
  • 11부 — 5G 세계 최초 상용화와 그 뒤의 논쟁.
  • 14부 — 통신사와 단말의 연표, 그리고 세대 비교표.

세계 최초라는 말은 누가 무엇을 최초라고 세느냐에 달려 있다. 그래서 이 덱은 그럴 때마다 무엇의 최초인지를 같이 적는다.

열여섯 부다. 2·3·4부가 수학 뼈대이고, 5부부터가 그 뼈대로 읽는 역사다.

  • 2부 · 물리계층 기초 · 3부 · 채널 부호화 · 4부 · 다중 접속과 셀룰러 개념
  • 5부 · 1G · 6부 · 2G GSM · 7부 · 2G CDMA
  • 8부 · 표준화 기구와 스펙 읽는 법
  • 9부 · 3G UMTS/WCDMA 와 HSPA · 10부 · 4G LTE · 11부 · 5G NR
  • 12부 · 위성통신과 NTN · 13부 · 6G
  • 14부 · 세대 비교와 실전 · 15부 · 부록
Wi-Fi 는 어디에 — 802.11 은 이 덱에서 다시 가르치지 않는다. Wi-Fi 완전 가이드 를 보라. 다만 OFDM·비터비·MIMO 는 셀룰러 쪽 변형이 달라서 여기서 다시 유도한다.

무엇을 보내고, 무엇을 받는가

무선으로 보내는 것은 무엇인가

안테나에서 나가는 것은 전압의 출렁임뿐이다. 그 출렁임의 모양에 뜻을 실어 보내고, 받는 쪽은 모양을 보고 뜻을 되찾는다. 무선통신의 모든 기술은 "어떤 모양으로 실을까" 와 "망가진 모양에서 어떻게 되찾을까" 두 물음의 답이다.

가장 단순한 모양은 정현파다.

s(t) = A cos(2πfct + φ)

손댈 수 있는 것은 셋뿐이다 — 크기 A, 주파수 fc, 위상 φ. 그래서 변조 방식도 결국 진폭 변조·주파수 변조·위상 변조, 그리고 그 조합뿐이다.

설명용

푸리에 — 시간과 주파수는 같은 것의 두 얼굴

아무리 복잡한 신호도 정현파의 합으로 쓸 수 있다. 그 '합의 성분표' 가 스펙트럼이다.

정의 — 푸리에 변환
S(f) = ∞∫−∞ s(t) e−j2πft dt

이 변환이 중요한 까닭은 하나다. 채널을 지나는 일이 시간 영역에서는 컨볼루션이고 주파수 영역에서는 곱셈이다. 곱셈이 훨씬 다루기 쉽다 — OFDM 이 왜 그렇게 생겼는지의 답도 결국 이 한 줄에 있다(10부).

실무의 푸리에 — 실제로 쓰는 것은 적분이 아니라 DFT 이고, 그것을 빠르게 하는 것이 FFT 다. 이 책의 모든 스펙트럼은 py/wirelesslib/dsp.py 의 FFT 로 구했다.
설명용

FFT — 빠른 것이 맞기도 한가

FFT 는 DFT 와 정확히 같은 값을 훨씬 적은 연산으로 구한다. "같다" 는 말을 믿지 말고 확인하자.

py/wirelesslib/dsp.py77–118제자리 반복형 radix-2 쿨리-튜키
def fft(x):
    """radix-2 쿨리-튜키 FFT (제자리 반복형).

    시간 O(N log N), 여분 공간 O(N).

    되부름 대신 반복으로 짠 이유: 파이썬의 되부름은 깊이 제한이 있고
    프레임 비용이 커서, N=4096 에서 눈에 띄게 느려진다.
    """
    n = len(x)
    if n == 0:
        return []
    if not is_pow2(n):
        raise ValueError('FFT 길이는 2의 거듭제곱이어야 한다: %d' % n)
    a = [complex(v) for v in x]

    # 1) 비트 뒤집기 순서로 자리를 바꾼다
    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j |= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    # 2) 나비 연산 — 길이 2 부터 두 배씩
    size = 2
    while size <= n:
        ang = -2j * math.pi / size
        step = cmath.exp(ang)
        half = size // 2
        for start in range(0, n, size):
            w = 1 + 0j
            for k in range(half):
                u = a[start + k]
                t = w * a[start + k + half]
                a[start + k] = u + t
                a[start + k + half] = u - t
                w *= step
        size *= 2
    return a

2 GHz 신호를 2 GHz 그대로 계산하면 표본이 초당 수십억 개 필요하다. 그런데 우리가 관심 있는 것은 반송파가 아니라 그 위에 실린 변화다. 그래서 반송파를 빼고 생각한다.

s(t) = Re{ s̃(t) ej2πfct }

s̃(t) 가 복소 기저대역 등가 신호다. 실수부를 I(동상), 허수부를 Q(직교)라 부른다. 이 책의 모든 코드는 복소수 리스트 하나로 신호를 다룬다 — 그것이 곧 I/Q 다.

역사 근거

왜 디지털로 갔는가

아날로그는 "약해진 신호를 되살릴 방법이 없다" 는 치명적인 약점이 있다. 한 번 잡음이 섞이면 영영 섞인 채다. 디지털은 다르다 — 판정을 하는 순간 잡음이 지워진다.

  • 재생 중계 — 비트를 되읽어 다시 보내면 잡음이 누적되지 않는다
  • 오류 정정 부호 — 아날로그 파형에는 걸 수 없다(3부)
  • 압축 — 음성을 13 kbit/s 로 줄여 채널을 나눠 쓴다
  • 암호 — 도청과 복제를 막는다. 1G 가 못 한 일이다
  • 같은 장비로 무엇이든 — 음성이든 문자든 사진이든 비트다
대가 — 아날로그 FM 은 신호가 약해지면 서서히 지직거리지만, 디지털은 어느 문턱을 넘는 순간 뚝 끊긴다. 이 절벽 효과가 디지털의 값이고, 3부의 부호와 9부의 HARQ 가 그 절벽을 최대한 멀리 밀어내려는 노력이다.
설명용

BPSK — 점 둘

가장 단순한 디지털 변조다. 위상을 0 또는 π 로 둔다.

s0 = +1,   s1 = −1

점 사이의 거리가 2 이고 평균 에너지가 1 이다. 이 최소 거리가 오류율을 정한다 — 잡음이 점 사이 거리의 절반을 넘어야 틀리기 때문이다.

심볼 하나에 1비트. 대역폭 효율은 가장 낮지만 잡음 내성은 가장 좋다. 위성·IoT 처럼 전력이 귀한 곳이 이것을 쓴다.
설명용

QPSK — 공짜로 두 배

I 축과 Q 축은 서로 직교한다. 그러니 BPSK 를 두 개 겹쳐 쓸 수 있다 — 하나는 I 에, 하나는 Q 에.

s = 1√2(±1 ± j)

심볼당 2비트인데, 비트 오류율은 BPSK 와 정확히 같다. 전력을 둘로 나눠 쓰지만 판정도 축마다 따로 하므로 손해가 없다.

따름정리 같은 Eb/N0 에서 BPSK 와 QPSK 의 BER 은 같다. QPSK 는 같은 오류율로 대역폭 효율만 두 배로 올린 것이다 — 이 책에서 몇 안 되는 '공짜' 다.
설명용

그레이 사상 — 이웃끼리는 비트 하나만

잡음이 심볼을 틀리게 만들 때, 대개는 바로 옆 점으로 간다. 그러니 옆 점끼리 비트가 하나만 다르게 라벨을 붙이면, 심볼이 하나 틀려도 비트는 하나만 틀린다.

BER ≈ SERk   (그레이 사상일 때)

라벨만 바꿔서 얻는 이득이라 공짜다. 그래서 오늘날 모든 규격이 그레이 사상을 쓴다.

실제로 물린 자리 자리에 붙는 라벨은 gray(자리) 여야 하므로, 라벨에서 자리를 찾을 때는 역함수 가 필요하다. 두 비트(QPSK·16QAM)에서는 gray 가 우연히 자기 역함수라 그냥 써도 맞아 보이는데, 세 비트부터 어긋난다. 이 책을 쓰며 그렇게 짰다가 64QAM 의 BER 이 이론보다 14 % 높게 나와 잡혔다.

def _ungray(g, k):
    """그레이 부호를 되돌린다 — _gray 의 역함수.

    자리(position)에 붙는 라벨이 _gray(자리) 여야 이웃한 자리끼리 비트가
    하나만 다르다. 그러니 라벨에서 자리를 찾으려면 이 역함수가 필요하다.

    **_gray 를 역함수 대신 쓰면 안 된다.** 두 비트짜리(16QAM·QPSK)에서는
    _gray 가 우연히 자기 역함수라서 맞아 보이지만, 세 비트부터는
    어긋난다. 실제로 그렇게 짰다가 64QAM 의 BER 이 이론보다 14 %
    높게 나왔다.
    """
    b = g
    sh = 1
    while sh < k:
        b ^= b >> sh
        sh <<= 1
    return b

QAM — 진폭과 위상을 함께

점을 더 넣으려면 원 위에만 둘 게 아니라 격자로 깔면 된다. 그것이 QAM 이다.

s = (a + jb) · √32(M−1),   a, b ∈ {±1, ±3, …}

배율 √(3/2(M−1)) 은 평균 에너지를 1 로 맞추는 값이다. 그래야 Es/N0 라는 표기가 뜻을 갖는다.

왜 사각 격자인가 — 같은 평균 전력에서 최소 거리를 가장 크게 만드는 배치가 육각 격자이지만, 사각 격자는 I 와 Q 를 따로 판정할 수 있어 수신기가 훨씬 싸다. 규격은 언제나 후자를 골랐다.

Q. QPSK 는 BPSK 와 같은 Eb/N0 에서 BER 이 같은데 비트는 두 배로 보낸다. 그러면 16QAM 은 왜 BPSK 보다 나쁜가? 같은 논리로 "I 와 Q 에 네 점씩" 이면 공짜가 아닌가?

A. QPSK 가 공짜인 것은 축마다 점이 둘뿐이기 때문이다. I 축에서 보면 그냥 BPSK 이고, Q 축에서도 그렇다. 두 축이 직교하니 서로 간섭하지 않는다.
16QAM 은 축마다 점이 넷이다. 같은 평균 전력에서 점을 넷으로 나누면 이웃 사이 거리가 좁아진다. 성상도 제원표를 보면 QPSK 의 최소 거리는 1.4142, 16QAM 은 0.6325 로 정확히 절반보다 조금 크다. 거리가 줄어든 만큼 오류율이 올라가고, 그것을 메우려면 전력이 더 든다.
정리하면 — 축을 늘리는 것은 공짜, 축 위의 점을 늘리는 것은 유료다.

펄스 성형과 나이퀴스트

심볼을 어떤 모양으로 보낼 것인가

사각 펄스를 쓰면 안 되는 이유

심볼마다 사각 펄스를 보내면 가장 간단하다. 그런데 사각 펄스의 스펙트럼은 sinc 이고, sinc 의 꼬리는 1/f 로만 떨어진다. 이웃 채널이 그 꼬리를 그대로 뒤집어쓴다.

200 kHz 간격으로 채널을 놓는 GSM 이 사각 펄스를 썼다면, 옆 채널이 −20 dB 수준의 간섭을 받는다. 그래서는 망이 서지 않는다.

맞바꿈 — 시간에서 좁으면 주파수에서 넓다. 펄스를 시간에서 길게 늘여 주파수에서 좁혀야 하는데, 길게 늘이면 이웃 심볼과 겹친다(ISI). 이 둘을 동시에 만족시키는 길이 나이퀴스트 기준이다.

정리 (나이퀴스트 ISI 기준) 펄스 h(t) 가
h(kT) =
1k = 0
0k ≠ 0
를 만족하면, 심볼이 서로 겹쳐 보내져도 심볼 순간에는 간섭이 없다.

제곱근을 나눠 갖는다 — RRC 와 정합 필터

잡음에 가장 강한 수신 필터는 보낸 펄스와 같은 모양이다 (정합 필터). 그런데 송신 필터가 이미 상승 코사인이면 수신에서 한 번 더 걸었을 때 전체가 상승 코사인의 제곱이 되어 나이퀴스트 조건이 깨진다.

그래서 제곱근을 양쪽이 나눠 갖는다. 송신에 RRC, 수신에 RRC. 둘을 이으면 정확히 상승 코사인이 되고, 동시에 정합 필터다.

def rrc(beta, sps, span):
    """상승 코사인의 제곱근(RRC). 에너지를 1 로 맞춰 돌려준다.

    송신기와 수신기가 이것을 하나씩 쓰면 둘을 이은 것이 상승 코사인이
    된다 — 그래서 ISI 가 0 이면서 동시에 정합 필터다. 이 책의 모든
    단일 반송파 링크가 이 쌍을 쓴다.

    t=0 과 t=±T/(4β) 에서 식이 0/0 이 되므로 극한값을 따로 넣는다.
    """
    n = span * sps
    out = []
    for i in range(n + 1):
        t = (i - n / 2.0) / sps
        if t == 0:
            v = 1.0 + beta * (4.0 / math.pi - 1.0)
        elif beta > 0 and abs(abs(t) - 1.0 / (4.0 * beta)) < 1e-12:
            v = (beta / math.sqrt(2.0)) * (
                (1.0 + 2.0 / math.pi) * math.sin(math.pi / (4.0 * beta))
                + (1.0 - 2.0 / math.pi)
                * math.cos(math.pi / (4.0 * beta)))
        else:
            num = (math.sin(math.pi * t * (1.0 - beta))
                   + 4.0 * beta * t
                   * math.cos(math.pi * t * (1.0 + beta)))
            den = math.pi * t * (1.0 - (4.0 * beta * t) ** 2)
            v = num / den
        out.append(v)
    e = math.sqrt(sum(v * v for v in out))
    return [v / e for v in out]

정의
Q(x) = 1√(2π) ∞∫x e−t²/2 dt
평균 0, 분산 1 인 정규분포가 x 를 넘을 확률.

def qfunc(x):
    """Q(x) = 1/√(2π) ∫_x^∞ e^{−t²/2} dt = ½ erfc(x/√2).

    math.erfc 가 표준 라이브러리에 있다. 급수를 손으로 짜지 않는 이유는
    erfc 가 꼬리(x > 5)에서도 상대 정확도를 지키기 때문이다 — 직접 짠
    급수는 거기서 자릿수를 잃는다.
    """
    return 0.5 * math.erfc(x / math.sqrt(2.0))

정리 (섀넌 1948) 대역폭 B, 신호 대 잡음비 γ 인 AWGN 채널에서 오류 확률을 원하는 만큼 작게 만들며 보낼 수 있는 최대 속도는

def budget(ptx_dbm, gtx_dbi, grx_dbi, path_loss_db, bw_hz, nf_db,
           required_snr_db, tx_loss_db=0.0, other_loss_db=0.0,
           temp_k=T0):
    """링크 버짓 한 판. 항을 이름표와 함께 돌려준다.

    이름표를 붙여 돌려주는 까닭: 여유가 모자랄 때 '어디서 잃었는지'
    를 봐야 고칠 수 있다. 숫자 하나만 돌려주면 그 정보가 사라진다.
    """
    eirp = eirp_dbm(ptx_dbm, gtx_dbi, tx_loss_db)
    prx = eirp - path_loss_db + grx_dbi - other_loss_db
    noise = noise_floor_dbm(bw_hz, nf_db, temp_k)
    snr = prx - noise
    return {
        'eirp_dbm': eirp,
        'path_loss_db': path_loss_db,
        'grx_dbi': grx_dbi,
        'other_loss_db': other_loss_db,
        'prx_dbm': prx,
        'noise_dbm': noise,
        'snr_db': snr,
        'required_snr_db': required_snr_db,
        'margin_db': snr - required_snr_db,
    }

1장

CRC — 깨졌는지 안다

고치지는 못하지만, 아는 것만으로 값이 있다

왜 검출이 정정보다 먼저인가

무선에서 "깨졌다" 를 아는 일은 곧 재전송의 방아쇠다. 아는 순간 다시 달라고 할 수 있고, 다시 받은 것을 앞의 것과 합칠 수도 있다(9부 HARQ). 그래서 CRC 는 부호 계층의 가장 바깥에 있다.

정정은 비싸다. 같은 잉여 비트로 검출은 훨씬 많은 오류를 잡는다 — 24비트 CRC 는 24비트 이하의 연집 오류를 전부 잡지만, 24비트로 정정할 수 있는 것은 몇 비트뿐이다.

def crc(bits, name):
    """시프트 레지스터로 구한 CRC. 초기값 0, 최종 반전 없음(3GPP 방식).

    구하는 값은 메시지 다항식에 D^L 을 곱해 생성 다항식으로 나눈
    나머지다. 시간 O(n).
    """
    if name not in CRC_POLYS:
        raise ValueError('모르는 CRC: %s' % name)
    length, poly = CRC_POLYS[name]
    mask = (1 << length) - 1
    reg = 0
    for b in bits:
        top = ((reg >> (length - 1)) & 1) ^ (b & 1)
        reg = (reg << 1) & mask
        if top:
            reg ^= poly
    return [(reg >> (length - 1 - i)) & 1 for i in range(length)]

def crc_polydiv(bits, name):
    """같은 값을 다항식 긴 나눗셈으로 — **다른 길로** 구한 검산용.

    시프트 레지스터 판이 틀려도 자기 자신과는 늘 짝이 맞는다. 정의
    그대로 나눠 보는 이쪽과 맞대어야 "맞다" 고 말할 수 있다.
    시간 O(n·L).
    """
    if name not in CRC_POLYS:
        raise ValueError('모르는 CRC: %s' % name)
    length, poly = CRC_POLYS[name]
    gen = [1] + [(poly >> (length - 1 - i)) & 1 for i in range(length)]
    work = [b & 1 for b in bits] + [0] * length
    for i in range(len(work) - length):
        if work[i]:
            for j, g in enumerate(gen):
                work[i + j] ^= g
    return work[-length:]

    def _viterbi(self, metric, steps, start=None, end=None):
        """공통 몸통.

        metric(step, state, u) 가 그 가지의 비용을 준다.
        """
        inf = float('inf')
        if start is None:
            cost = [0.0] * self.nstate
        else:
            cost = [inf] * self.nstate
            cost[start] = 0.0
        back = []
        for t in range(steps):
            nxt = [inf] * self.nstate
            bt = [(-1, 0)] * self.nstate
            for st in range(self.nstate):
                if cost[st] == inf:
                    continue
                for u in (0, 1):
                    c = cost[st] + metric(t, st, u)
                    ns = self.next[st][u]
                    if c < nxt[ns]:
                        nxt[ns] = c
                        bt[ns] = (st, u)
            cost = nxt
            back.append(bt)
        if end is None:
            last = min(range(self.nstate), key=lambda s: cost[s])
        else:
            last = end
        if cost[last] == inf:
            raise ValueError('복호할 수 있는 경로가 없다')
        msg = []
        st = last
        for t in range(steps - 1, -1, -1):
            prev, u = back[t][st]
            msg.append(u)
            st = prev
        msg.reverse()
        return msg, cost[last]

Q. CRC-24A 를 붙인 64비트 말에 2비트 오류를 던지면 2,016가지 모두 잡힌다. 그런데 "2비트 오류는 언제나 잡힌다" 는 말은 틀렸다고 한다. 무엇이 빠졌는가?

A. 블록 길이 조건이 빠졌다. 2비트 오류가 잡히려면 오류 패턴 Di+Dj = Di(1+Dj−i) 가 생성 다항식으로 나누어떨어지지 않아야 한다. 즉 1+Dm 이 g(D) 의 배수가 되는 가장 작은 m — 곧 다항식의 주기 — 보다 블록이 짧아야 한다.
CRC-24A 의 주기는 아주 길어서(수백만 비트) 실무의 블록 길이에서는 늘 잡힌다. 하지만 "언제나" 가 아니라 "이 길이에서는" 이다. 짧고 주기가 작은 다항식을 고르면 2비트 오류를 놓친다.

BCJR — 앞에서 한 번, 뒤에서 한 번

비터비는 가장 그럴듯한 경로를 찾는다. BCJR 은 비트마다 가장 그럴듯한 값을 찾는다 — 반복 복호에 넘길 연판정이 필요하기 때문이다.

LLR(ui) = ln Σu=0 α β γ Σu=1 α β γ

α 는 앞에서부터 쌓은 확률, β 는 뒤에서부터 쌓은 확률, γ 는 가지 하나의 확률이다.

def bcjr(la, lsys, lpar, maxlog=False):
    """한 구성 부호의 BCJR. 사후 LLR 목록을 돌려준다.

    la 는 앞 단계 복호기가 넘겨준 사전 정보(외재 정보)다. 길이는
    lsys·lpar 과 같아야 하고, 꼬리 구간에서는 0 이다 — 꼬리 비트에
    대해서는 상대 복호기가 아무 말도 해 줄 수 없기 때문이다.

    시간 O(T·8), 공간 O(T·8).
    """
    t = len(lsys)
    alpha = [[NEG] * NSTATE for _ in range(t + 1)]
    beta = [[NEG] * NSTATE for _ in range(t + 1)]
    alpha[0][0] = 0.0
    beta[t][0] = 0.0                     # 끝맺음한 부호라 끝은 0 상태다

    def gamma(i, s, u):
        ns, p = TRELLIS[s][u]
        gu = 1.0 - 2.0 * u
        gp = 1.0 - 2.0 * p
        return 0.5 * gu * (la[i] + lsys[i]) + 0.5 * gp * lpar[i]

    for i in range(t):
        for s in range(NSTATE):
            if alpha[i][s] <= NEG:
                continue
            for u in (0, 1):
                ns = TRELLIS[s][u][0]
                v = alpha[i][s] + gamma(i, s, u)
                alpha[i + 1][ns] = _maxstar(alpha[i + 1][ns], v, maxlog)

def _channel_llr(bits, ebn0_db, k, rnd):
    """BPSK·AWGN 을 지나온 채널 LLR. 양수면 0 쪽이 그럴듯하다는 뜻.

    Eb 는 **정보 비트당** 에너지다. 부호율이 R 이면 심볼당 에너지는
    R 배가 된다 — 이 한 줄을 빠뜨리면 터보 부호가 실제보다 3~5 dB
    좋아 보인다.
    """
    n = len(bits)
    rate = float(k) / n
    esn0 = 10.0 ** ((ebn0_db + 10.0 * math.log10(rate)) / 10.0)
    sigma2 = 1.0 / (2.0 * esn0)
    sd = math.sqrt(sigma2)
    out = []
    for b in bits:
        x = 1.0 - 2.0 * b                # 0 → +1, 1 → −1
        y = x + rnd.gauss(0.0, sd)
        out.append(2.0 * y / sigma2)
    return out

def _build_base(kb=10, mb=14, ninfo=4, zmax=16, seed=20260916):
    """기저 행렬을 규칙으로 짓는다 — 마법의 표를 손으로 적지 않는다.

    패리티 쪽은 계단(이중 대각선)이라 부호화가 앞먹임 한 번이면 끝나고,
    정보 쪽은 씨앗을 고정한 난수로 고르되 4-순환이 생기는 선택을
    물리치며 넣는다. 같은 씨앗이면 언제나 같은 행렬이 나온다.
    """
    rnd = random.Random(seed)
    rows = [[] for _ in range(mb)]
    pairs = set()          # (열a, 열b, 이동차) — 4-순환을 막는 열쇠

    def key_of(c0, s0, col, shift):
        if c0 < col:
            return (c0, col, (shift - s0) % zmax)
        return (col, c0, (s0 - shift) % zmax)

    def ok(r, col, shift):
        for c0, s0 in rows[r]:
            if key_of(c0, s0, col, shift) in pairs:
                return False
        return True

    def commit(r, col, shift):
        for c0, s0 in rows[r]:
            pairs.add(key_of(c0, s0, col, shift))
        rows[r].append((col, shift))

    for r in range(mb):
        # 정보 열 ninfo 개
        cols = rnd.sample(range(kb), ninfo)
        for c in sorted(cols):
            for _try in range(200):
                sh = rnd.randrange(zmax)
                if ok(r, c, sh):
                    commit(r, c, sh)
                    break
            else:
                raise RuntimeError('이동량을 못 골랐다')
        # 패리티 계단: 이 행의 새 패리티 열과 바로 앞 패리티 열
        if r > 0:
            commit(r, kb + r - 1, 0)
        commit(r, kb + r, 0)
    return Base(rows, kb + mb, kb)

class Encoder(object):
    """계단 구조를 이용한 앞먹임 부호기.

    패리티 열이 이중 대각선이라 검사식을 위에서 아래로 한 번 훑으면
    패리티가 하나씩 정해진다. 행렬을 뒤집을 필요가 없다 — 실물
    LDPC 부호기가 O(n) 인 까닭이 바로 이 구조다.
    """

    def __init__(self, h):
        self.h = h

    def encode(self, msg):
        h = self.h
        if len(msg) != h.k:
            raise ValueError('메시지는 %d 비트다: %d' % (h.k, len(msg)))
        cw = list(msg) + [0] * h.m
        z, kb = h.z, h.base.kb
        for r in range(h.base.mb):
            for i in range(z):
                ci = r * z + i
                s = 0
                for v in h.rows[ci]:
                    if v < (kb + r) * z:      # 아직 안 정한 열은 빼고
                        s ^= cw[v]
                cw[(kb + r) * z + i] = s
        return cw

def _check_msg(vals, minsum, alpha=0.75):
    """한 검사가 이웃들에게 보낼 말. vals 는 들어온 말들이다.

    합곱은 tanh 규칙, 최소합은 '부호는 곱, 크기는 최소' 다. 최소합은
    크기를 늘 크게 잡는 쪽으로 틀리므로 보통 0.7~0.8 을 곱해 눌러 준다.
    시간 O(d²) — d 가 6 안팎이라 이 책에서는 이 쪽이 읽기 좋다.
    """
    d = len(vals)
    out = [0.0] * d
    for i in range(d):
        if minsum:
            sgn = 1.0
            mag = float('inf')
            for j in range(d):
                if j == i:
                    continue
                v = vals[j]
                if v < 0:
                    sgn = -sgn
                mag = min(mag, abs(v))
            out[i] = alpha * sgn * mag
        else:
            prod = 1.0
            for j in range(d):
                if j == i:
                    continue
                t = math.tanh(vals[j] / 2.0)
                prod *= max(-_CLAMP, min(_CLAMP, t))
            prod = max(-_CLAMP, min(_CLAMP, prod))
            out[i] = 2.0 * math.atanh(prod)
    return out

SC 복호 — 앞에서부터 하나씩

비트를 앞에서부터 정하고, 정한 것을 뒤 계산에 그대로 쓴다. 그래서 한 번 틀리면 그 뒤가 줄줄이 무너진다.

py/wirelesslib/polar.py163–176되부름 한 판
def _sc(llr, frozen, offset, uhat):
    """SC 복호의 되부름 — 돌려주는 것은 그 부분나무의 x 영역 비트다."""
    n = len(llr)
    if n == 1:
        u = 0 if offset in frozen else (0 if llr[0] > 0 else 1)
        uhat[offset] = u
        return [u]
    h = n // 2
    a, b = llr[:h], llr[h:]
    lf = [_f(a[j], b[j]) for j in range(h)]
    x1 = _sc(lf, frozen, offset, uhat)
    lg = [_g(a[j], b[j], x1[j]) for j in range(h)]
    x2 = _sc(lg, frozen, offset + h, uhat)
    return [x1[j] ^ x2[j] for j in range(h)] + x2

설명용

FDMA — 가장 오래되고 가장 단순한

대역을 잘라 한 사람에게 하나씩 준다. 아날로그 시절에는 이것뿐이었다.

  • 장점 — 단말이 제 채널만 필터로 걸러 보면 된다. 동기가 필요 없다
  • 단점 — 채널 사이에 보호 대역이 필요하고, 안 쓰는 채널도 잡고 있다
  • AMPS — 30 kHz 씩 잘라 통화 하나. 미국 전체에 832 채널뿐이었다
이 "832 채널" 이 셀룰러가 필요했던 이유 그 자체다. 같은 채널을 멀리서 다시 쓰지 않으면 도시 하나에 832명이 한계다.
역사 근거

TDMA — 시간을 나눈다

같은 주파수를 여럿이 번갈아 쓴다. 디지털이라야 가능한 방식이다 — 말을 잠깐 모았다가 제 차례에 몰아 보내야 하기 때문이다.

  • 장점 — 단말이 제 슬롯에만 켜면 되므로 배터리가 오래 간다. 남는 시간에 이웃 셀을 잰다(핸드오버에 유리)
  • 단점 — 시각을 맞춰야 한다. 멀리 있는 단말은 미리 보내야 한다(타이밍 어드밴스)
  • GSM — 200 kHz 를 8슬롯으로. 통화 하나가 슬롯 하나다(6부)
규격 근거

CDMA — 모두가 동시에 떠든다

모두가 같은 시각에 같은 주파수로 보낸다. 대신 저마다 다른 부호로 신호를 넓게 퍼뜨린다. 받는 쪽은 제 부호로 다시 모아서 제 신호만 키운다.

처리 이득 = 10 log10 WR

잡음보다 낮게 묻힌 신호를 꺼내 쓸 수 있다는 것이 이 방식의 값이다. 대신 모두가 같은 세기로 도착해야 한다 — 전력 제어가 조건이 아니라 전제다(7부).

실행 검증

OFDMA — 시간·주파수 격자를 나눈다

부반송파 수천 개를 깔고, 시간·주파수 칸을 사람마다 나눠 준다. 사람마다 채널이 좋은 칸이 다르므로, 좋은 칸을 골라 주면 공짜 이득이 생긴다(다중 사용자 다이버시티).

이 유연함이 4G 의 얼굴 — 음성 하나에 고정 채널을 주던 시대에서, 밀리초마다 자원을 다시 나눠 주는 시대로 넘어간 것이 OFDMA 다(10부).
설명용

NOMA — 이름과 실제

전력을 달리해 같은 칸에 두 사람을 겹쳐 싣고, 센 쪽을 먼저 풀어 빼낸 뒤 약한 쪽을 푼다(연속 간섭 제거). 이론 용량은 직교 방식보다 크다.

얼랑 B — 막히면 버린다

B(0) = 1,   B(k) = A·B(k−1) k + A·B(k−1)
왜 점화식인가 원래 식에는 AN/N! 이 들어 있어 N 이 조금만 커져도 넘침이 난다. 점화식은 0 과 1 사이 값만 오간다 — 이 책의 구현이 점화식을 쓰는 이유다.

def erlang_b(a, n):
    """얼랑 B — 기다릴 수 없는 호가 막힐 확률.

        B(0) = 1,  B(k) = A·B(k−1) / (k + A·B(k−1))

    되부름 대신 이 점화식을 쓰는 까닭: 원래 식에는 A^N/N! 이 들어 있어
    N 이 조금만 커져도 넘침이 난다. 점화식은 0~1 사이 값만 오간다.
    시간 O(N).
    """
    if a < 0 or n < 0:
        raise ValueError('부하와 회선 수는 음수일 수 없다')
    b = 1.0
    for k in range(1, n + 1):
        b = a * b / (k + a * b)
    return b

def power_control_loop(target_db, steps, step_db=1.0, seed=1,
                       fade_db=6.0):
    """닫힌 고리 전력 제어. 매 걸음 한 비트만 올려/내려 보낸다.

    IS-95 는 이것을 초당 800번 돌렸다. 한 걸음이 1 dB 이므로 최대
    800 dB/s 를 따라갈 수 있고, 그래서 빠른 페이딩도 어느 정도 쫓는다.
    돌려주는 것은 걸음마다 기지국이 본 SINR [dB] 다.
    """
    rnd = random.Random(seed)
    tx = 0.0
    hist = []
    fade = 0.0
    for _ in range(steps):
        fade = 0.9 * fade + rnd.gauss(0.0, fade_db * 0.3)
        rx = tx + fade
        hist.append(rx)
        tx += -step_db if rx > target_db else step_db
    return hist

def cluster_sizes(maxi):
    """쓸 수 있는 클러스터 크기 N = i² + ij + j².

    아무 수나 되는 것이 아니다 — 육각 격자를 빈틈없이 덮으려면 이 꼴
    이어야 한다. 그래서 4 는 되고 5 는 안 된다.
    """
    out = set()
    for i in range(maxi + 1):
        for j in range(maxi + 1):
            n = i * i + i * j + j * j
            if n > 0:
                out.add(n)
    return sorted(out)

작은 i, j 를 훑어 나오는 값을 모아 정렬한다. 1, 3, 4, 7, 9, 12, 13, 16, 19, 21 … 5·6·8 이 없는 것을 눈으로 확인할 수 있다.

def sir_db(n, gamma, interferers=6):
    """같은 채널 간섭 대비 신호비.

        SIR = (D/R)^γ / i₀ = (√(3N))^γ / i₀

    첫 고리의 같은 채널 셀이 여섯이므로 i₀ = 6 이 기본이다. 섹터
    안테나를 쓰면 그중 일부만 보이므로 i₀ 가 준다(3섹터에서 2).
    N=7·γ=4·i₀=6 이 18.7 dB — 아날로그 AMPS 가 요구하던 18 dB 를
    막 넘는 값이고, 그래서 N=7 이 표준이 되었다.
    """
    if interferers < 1:
        raise ValueError('간섭원 수는 1 이상이어야 한다')
    return 10.0 * math.log10(reuse_ratio(n) ** gamma / interferers)

def offered_load(n, gos, hi=1e6, tol=1e-12):
    """차단률을 gos 로 맞추는 최대 부하 [얼랑]. 이분법으로 푼다.

    얼랑 B 는 A 에 대해 단조 증가하므로 이분법이 언제나 모인다.
    회선을 한 통에 모을수록 회선당 실어 나르는 양이 는다 —
    그 '트렁킹 이득' 을 이 함수로 잰다.
    """
    if not 0 < gos < 1:
        raise ValueError('차단률은 0 과 1 사이여야 한다')
    lo = 0.0
    while hi - lo > tol * max(1.0, hi):
        mid = (lo + hi) / 2.0
        if erlang_b(mid, n) < gos:
            lo = mid
        else:
            hi = mid
    return lo

얼랑 B 는 A 에 대해 단조 증가이므로 이분법이 반드시 수렴한다. 설계자가 실제로 묻는 것은 "차단률 2 % 를 지키려면 몇 얼랑까지 받을 수 있나" 이지 "이 부하의 차단률은 얼마인가" 가 아니다.

def ping_pong_count(hysteresis_db, seed=1, steps=2000, bias_db=0.0,
                    sigma_db=4.0):
    """히스테리시스를 걸었을 때 남는 핑퐁 핸드오프의 수.

    두 셀의 수신 세기가 비슷한 곳에서는 음영과 페이딩 때문에 순위가
    쉴 새 없이 바뀐다. 그때마다 넘기면 통화가 끊긴다. 그래서
    "지금 셀보다 H dB 이상 좋아야 넘긴다" 는 문턱을 둔다.

    bias_db 는 한쪽이 평균적으로 얼마나 센가다. 크게 주면 경계가
    아니라 셀 한가운데라는 뜻이라 핸드오프가 아예 일어나지 않는다.
    """
    rnd = random.Random(seed)
    cur = 0
    cnt = 0
    a = b = 0.0
    for _ in range(steps):
        a = 0.8 * a + rnd.gauss(0.0, sigma_db * 0.6) + 0.2 * bias_db
        b = 0.8 * b + rnd.gauss(0.0, sigma_db * 0.6)
        lv = [a, b]
        other = 1 - cur
        if lv[other] > lv[cur] + hysteresis_db:
            cur = other
            cnt += 1
    return cnt

씨앗을 고정한 난수로 음영을 흔들어 두 셀의 세기를 만들고, 문턱을 바꿔 가며 넘긴 횟수를 센다. 6장의 표가 이 함수의 출력이다.
